# devkit: правила сессий в самом репозитории

Ядро правил лежит здесь же (RULES.core.md) и подключено у пользователя
глобально, повторно оно себе не импортируется; полный текст с разбором в
RULES.md рядом, он читается по надобности. Для работы с задачами devkit
действует доска docs/TASKS.md (префикс DK) по тем же правилам, что у проектов:
ядро в RULES.board.core.md, полный текст в RULES.board.md. Ссылку на ядро доски
выписывает в тонкий файл харнеса генератор (`devkitctl doctor --fix`), руками её
тут держать не надо: AGENTS.md читают и инструменты без импортов.

Место новому файлу и язык нового инструмента выбираются правилом, а не на
глаз: раскладка каталогов и граница go/python/sh лежат в README.md, раздел
«Раскладка». Файл не по правилу это находка `devkitctl doctor`.

# Ядро правил доски

Доска `docs/TASKS.md`, правила `RULES.board.md`.

- Пункт очереди читать по ссылке в указанной версии. Найти ID, перед
  `taskctl show <ID>` вызвать `taskctl guard <ID>`. Черновик вести через
  `board-groom`. К исходникам идти после оформления и штатного взятия строки.
  Если версия, материал или состояние доски недоступны, назвать причину и остановиться.
- Доску менять через `taskctl`, ветки, слияние и выкат через `shipctl`.
  До `taskctl add` заполнить обязательные разделы `TASKFORM.md`. Сырое в `taskctl draft`.
- Новую идею человека, включая понятное поручение о новой возможности,
  сохранить черновиком и уточнить по `board-draft` до готовности SCQA.
  Спрашивай только о недостающем. Готовый SCQA покажи в ответе четырьмя частями.
  Без просьбы о груминге остановиться на черновике. Воспроизводимый баг и
  работа по согласованной задаче идут прежним порядком.
- Исполнитель и ревьювер по `agentctl pick <ID>` (ревью с `--role review`).
  Субагенту передать задачу, модель и определение из вердикта.
- ID задачи ставить в subject коммита.
- Коммит с `docs/TASKS.md`, `docs/TASKS-archive.md` или `docs/tasks/`
  пушить в origin сразу, без просьбы.
- Сценарий прогоняет отдельная сессия вне круга разработки, со свежим
  контекстом. Та же модель годится. Модель даёт `agentctl check <ID>`.
  Отметка через `agentctl stage <ID> проверка --by <модель>`.
  `taskctl close` отклонит прогон сессией участника круга.
- IP, доступы и инфраструктуру держать в гитигнорнутом `local-docs`.
  В коммитируемом тексте вместо адреса писать роль машины.

## Автономная работа

При `autonomous = true` обычный коммит в ветке задачи делай без вопроса.
Для повышения прав зови автопроверку. При отказе назови команду и причину.
Если пользователь явно не ограничил работу, пройди ворота, слей и выкати
через `shipctl`, проверь результат.
