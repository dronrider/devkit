# Ядро правил доски

Доска `docs/TASKS.md`, правила `RULES.board.md`.

- Пункт очереди читай в версии по ссылке. Найди ID. Перед `taskctl show <ID>`
  вызови `taskctl guard <ID>`. Черновики через `board-groom`. К исходникам
  после оформления и штатного взятия строки. Без версии, материала или
  статуса доски назови причину и остановись.
- Доска через `taskctl`, ветки, слияние и выкат через `shipctl`. Сырое в
  `taskctl draft`. До `taskctl add` заполни `TASKFORM.md`.
- Новую идею человека или поручение о новой возможности сохрани черновиком.
  Уточни по `board-draft` лишь недостающее, покажи готовый SCQA четырьмя
  частями. Без запроса груминга оставь черновик. Баг с воспроизведением и
  согласованная задача идут как прежде.
- Исполнитель и ревьювер из `agentctl pick <ID>` (ревью `--role review`).
  Субагенту дай задачу, модель и определение.
- ID в subject. Коммиты с `docs/TASKS.md`, `docs/TASKS-archive.md`
  или `docs/tasks/` сразу пушь в origin.
- Сценарий прогоняет отдельная сессия со свежим контекстом вне круга.
  Модель из `agentctl check <ID>`. До закрытия отметь
  `agentctl stage <ID> проверка --by <модель>`.
- IP, доступы, инфраструктура в `local-docs` (gitignore). Вместо адреса роль машины.

## Автономная работа

При `autonomous = true` обычный коммит в ветке задачи делай без вопроса.
Для повышения прав зови автопроверку. При отказе назови команду и причину.
Если пользователь явно не ограничил работу, пройди ворота, слей и выкати
через `shipctl`, проверь результат.
