# devkitctl: обвязка проекта

Подключение devkit к проекту размазано по трём ручным шагам (шаблон
CLAUDE.md, `taskctl init`, `git config core.hooksPath`), а сломанную обвязку
раньше никто не диагностировал. Утилита сводит это к двум командам; агент в
свежей сессии гоняет `doctor` и чинит по находкам, вместо чтения инструкций
по подключению. Нужен только python3, запуск прямо из devkit:

```
python3 ~/projects/devkit/devkitctl/devkitctl.py <команда>
```

## Команды

```
new --prefix XX [--name "..."] [--no-board] [-C dir]
doctor [--fix] [-C dir]
stats [-C dir]
```

`new` подключает проект: копирует шаблон `templates/CLAUDE.project.md` в
корень (плейсхолдеры заполняются, импорты пересчитываются под реальный путь
до devkit), выставляет `core.hooksPath` на хуки devkit (если у проекта уже
есть свои хуки, не трогает их и подсказывает симлинки), заводит доску через
`taskctl init` и болванку `.devkit/deploy.local` для shipctl (гитигнорит её,
`deploy` пустой, `autonomous = false`). Для проекта с внешним трекером
`--no-board`: доска и обвязка выката не создаются, а импорт `RULES.board.md`
из CLAUDE.md надо убрать руками, вписав трекер.

`doctor` проверяет обвязку существующего проекта и выходит с 1 при находках:

- CLAUDE.md на месте и его `@`-импорты разворачиваются (devkit склонирован);
- git-хуки devkit подключены (`core.hooksPath` либо симлинки);
- при наличии доски `taskctl lint` проходит;
- при наличии доски есть `.devkit/deploy.local` с непустой командой выката
  и он гитигнорнут (иначе адрес из команды утечёт в git);
- журнал запусков `.devkit/log` (его пишут taskctl, shipctl, regcheck и сам
  devkitctl) гитигнорнут, иначе замусорит status;
- локальные markdown-ссылки по всему репозиторию ведут на существующие файлы
  (обобщение проверки, которую lint делает для доски). Внутрь блоков кода
  проверка не заглядывает, как и в инлайн-код: ссылка в примере команды это
  текст, а не ссылка.

Отдельным разделом идёт машинный контур: он общий для всех проектов, поэтому
находки помечены словом «машина». Проверяется то, без чего конвейер тихо
работает наполовину:

- PostToolUse-хуки Claude Code прописаны в `~/.claude/settings.json` (символы,
  индекс памяти, чувствительное), там же SessionStart-хук `quota-refresh.sh`:
  без него снимок квоты сам не освежается и корректор pick рано или поздно
  остаётся с протухшим;
- уведомитель `notify.py` подключён сразу на два события, `Notification` и
  `SubagentStop`: пропажа любого проверяется отдельно, потому что без второго
  сессия молчит про отработавшего субагента, а без первого не зовёт, когда
  ждёт разрешения. Тут же проверяется, чем эти уведомления слать: бэкенд
  выбирает сам `notify.py` по платформе и PATH, и когда его нет (нет
  `notify-send` на Linux, необычная платформа), доктор называет это находкой
  с командой `notify.py --self-test`. Отдельная находка на macOS, где слать
  есть чем, но клик по баннеру уводит в Finder: `osascript` постит от имени
  Script Editor, переход в окно сессии даёт `terminal-notifier`, и находка
  предлагает её поставить. Поломкой это не считается, уведомления и без неё
  доходят;
- бинари `taskctl`, `shipctl`, `agentctl`, `regcheck` в PATH и не старее
  исходников devkit; свежесть меряется по mtime, поэтому из worktree ветки
  задачи она не проверяется и сборка не запускается: там mtime это момент
  выкладки, а машинный бинарь с непроверенной ветки уехал бы во все проекты
  сразу;
- определения субагентов `agents/*.md` (исполнители `exec-*`, ревьюверы
  `review-*`) лежат в `~/.claude/agents/` и совпадают с devkit; без них effort
  из вердикта pick применять нечем, и спавн молча уходит на дефолтного агента.
  Определением файл считается по frontmatter с `effort:`, соседняя проза вроде
  README на машину не уезжает. Эталон, как и у бинарей, это основной чекаут: из
  worktree ветки задачи определения только сверяются, а раскладка и перекладка
  ждут слияния;
- tmux в PATH, иначе `agentctl quota refresh` не снимет панель `/usage`;
- снимки квоты в `~/.devkit/quota/` есть и не протухли: порог 45 минут, тот же,
  по которому судит сам корректор, а на протухшем снимке pick теряет сдвиг
  вверх. Проверяется каждый файл директории, а не один: снимок теперь свой на
  харнес. Одиночный `~/.devkit/quota.local`, каким снимок был раньше, это
  находка про переезд: читатель его ещё понимает, но чинит расхождение `--fix`,
  а не пользователь. Лежат оба сразу, значит читается новый, а про старый
  доктор говорит и удалять его сам не берётся;
- профили харнесов `devkit/harness/*.toml` разбираются и проходят валидацию.
  Проверяются все, а не только активный: битый профиль находится до того, как
  кто-то на него переключится. Чинится это правкой в devkit, поэтому находка
  остаётся находкой и под `--fix`.

Валидатор профилей живёт в `devkitctl/harness.py` вместе с парсером
подмножества TOML. Парсер этот второй: тот же формат читает agentctl своим
кодом на Go (`tomllib` появился в python3.11, а devkitctl обещает голый
python3, тащить же в Go-утилиту первую внешнюю зависимость ради конфига из
строк и массивов не хочется). Расхождение двух реализаций ловится общими
фикстурами `harness/testdata`: на каждый вход там лежит ожидаемый отчёт, и
сверяются с ним обе стороны. Отчёт по любому файлу печатается и руками, это
удобная точка для глаза:

```sh
python3 devkitctl/harness.py harness/claude-code.toml
```

`doctor --fix` доводит обвязку уже подключённого проекта и машины до актуальной:
после `git pull` devkit это способ забрать новые её части одной командой, без
ручного заведения файлов. Большинство правок additive: подключает отвязанные
git-хуки, заводит болванку `.devkit/deploy.local` и строку в `.gitignore`,
собирает недостающие и устаревшие бинари (`go build` в `GOBIN`, иначе в
`GOPATH/bin`, иначе в `~/go/bin`) и кладёт определения субагентов в
`~/.claude/agents/`. Определение, разошедшееся с эталоном (устарело после
правки промптов в devkit либо кто-то поправил его прямо на машине), `--fix`
перекладывает: devkit источник правды, и правка обязана доехать до спавна
субагента сама, а не остаться находкой, которую надо чинить руками на каждой
машине. Перекладка не молчаливая, отчёт называет файл и что он разошёлся, так
что подправленное на машине видно в выводе, даже если его тут же перезаписали.
Заполненное иначе `--fix` не трогает (готовый `deploy=`, подправленный
CLAUDE.md), а неоднозначное оставляет находкой: битый импорт и ссылку правит
человек, пустой `deploy=` ждёт команды выката, хуки в `settings.json` чинятся
своим шагом, tmux и сам Go ставит пакетный менеджер, а снимок квоты снимается
командой `agentctl quota refresh`. Единственная неadditive правка это переезд
снимка квоты: одиночный `~/.devkit/quota.local` `--fix` перекладывает в
`~/.devkit/quota/claude-code.local` (снять его было нечем, кроме панели Claude
Code), и в отчёте называет оба пути. Файл при этом не пропадает, а меняет место;
если по новому пути снимок уже лежит, старый остаётся нетронутым и попадает в
находки. Собранный бинарь может проиграть в PATH
чужой копии, и это тоже находка, а не молчаливая пересборка на каждом прогоне.
Повторный прогон уже ничего не меняет.

`stats` собирает статистику по журналу запусков `.devkit/log`: выводит таблицу
с частотой каждой команды (утилита + субкоманда), долей ошибочных запусков
(код выхода != 0) и итоговой строкой. Битые строки в журнале молча пропускаются.
