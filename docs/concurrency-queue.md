## С чего продолжать

№001-004 покрыты кодом и адресными проверками. №005/DK-722 и №006/DK-1226
выполняются. Их исполнителям не назначается второй дубль. После исправления

Идти по порядку строк, пропуская покрытые и занятые результаты. Новые
№165, №166, №167, №164 стоят после №004 перед прежними №005-010.
Сначала проверяется пересечение файлов с живой работой DK-722 и DK-1226.
№170 и зависимая №168 стоят после №101, №163 после №128, №169 после №148. Номера и якоря
постоянны; исполняется порядок строк с обязательными зависимостями «После».

«Открыто» означает сохранившийся пробел реализации или результата работы.
«Частично» отделяет работающий механизм от остатка в той же строке.
«Нужен прогон» требует подтвердить симптом до назначения исправления.
«Покрыто в main» снимает повторную реализацию. Версии на чужих машинах
проверяются по №148-150 и новому сценарию №169.

не ждёт устойчивого делегата №102; проверка №108 идёт после ограничения
№103. Для №013 новый остаток относится к восстановлению многофайловой
записи после падения. Общая сериализация CLI уже реализована. Поэтому №014, №021, №025,
№027, №110, №117, №123, №124 и №133 больше не ждут нового результата
№013. Захват этапа №026 не ждёт интеграции всех писателей в №012.

## Как брать следующую задачу

1. Идти по порядку строк. Пропускать «Покрыто в main» и заблокированные
   работы. Из оставшихся брать первую с завершёнными предшественниками.
   Для «Нужен прогон» первым результатом служит воспроизведение на свежем коде.
   Исправление назначается после подтверждения причины.
2. Если у DK-задачи работает исполнитель или открыта человеческая развилка, не поднимать второго. Поручение
   остаётся у него; следующая независимая строка доступна другому исполнителю.
3. Для результата строки оформить одну задачу. Один черновик может быть
   источником разных результатов (DK-1513 для №165 и №166); каждой работе
   нужен отдельный ID доски. Дополнительные
   источники из [реестра](concurrency-drafts.md) добавляют сценарии к ней.
   Несколько источников в одной строке не означают несколько исправлений.
   Ссылка на черновик обозначает источник. Если его ID занят другой живой
   или архивной записью (например, DK-1457), не использовать `add --id`
   с этим номером. Зарегистрировать работу со свежим ID, сохранить исходный
   файл и обновить связь в очереди и реестре. Известные пересечения перечислены
   в плане полными путями; одноимённый архив не является этой работой.
4. У новой задачи название, границы и критерий уже заданы здесь. До изменения
   кода сохранить их карточкой через taskctl по TASKFORM.md. Номер очереди
   не является ID доски. Регистрация карточки входит в старт этой работы,
   отдельного повторного исследования или нарезки пакета не требуется.
5. Перед изменением повторить исходный сценарий на свежем коде. Если он
   исправлен другой задачей, записать SHA и проверку и перейти дальше.
   Архивный статус или запуск агента сами по себе не закрывают строку.
6. Одновременно брать только независимые строки без живого владельца и
   пересечения изменяемых файлов. При сомнении сохранять порядок номеров.

Зависимости проверены на отсутствие циклов. Каждый предшественник стоит
раньше зависимой задачи. Зависимости этой документации ещё не записаны
командами `taskctl dep`: создавать строки и связывать их следует при взятии,
после проверки текущих ID и владельцев. Этот документ задаёт очередь работ;
он не утверждает, что все новые строки уже существуют на доске.
