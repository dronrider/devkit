# Восстановление головы после отказа запуска

Если окно новой головы исчезло до первого хода, сначала прочитайте
`.devkit/task-<ID>.start.log` в дереве проекта. В нём остаются код выхода,
отказ подготовки и доступный хвост панели tmux. Ссылка на файл также
попадает в журнал инцидентов. Файл местный, права доступа 0600; он может
содержать текст терминала и не предназначен для публикации.

Проверьте путь к реально запущенному `taskctl` и его версию. Старая утилита,
которая не знает `guard`, останавливает запуск до обращения к модели.
Обновите devkit штатной командой `devkitctl update` и проверьте новый запуск.
Проверку материала отключать нельзя. Сетевой отказ или запрос авторизации
клиента устраняется по сохранённому сообщению, повторный запуск их не обходит.

При ротации оболочка получает шаблон идентичности из секции `head.session`
профиля. Новый UUID подставляется только в эту часть команды. Модель, имя
разговора и остальные аргументы сохраняются. Клиент, который назначает
идентичность самостоятельно, запускается без добавленных флагов.

Умерший клиент до регистрации оставляет ошибку с кодом выхода. Живой клиент,
адрес которого ещё не записан в реестре, продолжает первый ход без второго
заказа поверх него. Захват терминала и стандартные потоки клиента сохраняются.

Хвост ротации находится в `.devkit/task-<ID>.tail`. После отказа он остаётся
на месте. Первый заказ нового запуска содержит путь к непустому хвосту;
это действует и для печатного прохода. Новая голова сверяет хвост с текущей
карточкой и продолжает работу. Файл не удаляется подтверждением запуска.
