# DK-010: LLD квотного корректора вердикта pick

## Задача и ограничение

Вердикт `agentctl pick` считается только из метаданных задачи и не знает,
сколько осталось лимитов подписки. Расход выходит нерациональным: когда за
день до сброса не потрачено 80% дорогой модели, экономить на дешёвых
неразумно, а когда дорогая почти исчерпана, отдавать ей задачи неправильно.
Корректор сдвигает вердикт по лестнице моделей в обе стороны, опираясь на
остаток лимитов.

Ограничение, вокруг которого строится дизайн: остаток программно недоступен.
`/usage` только интерактивный, headless-эквивалента нет, расчёт серверный
(учитывает другие устройства и сессии), API-эндпоинта нет (проверено по докам
Claude Code, июль 2026). Локально остаток честно не воспроизвести, его можно
только снять с интерактивного интерфейса и записать.

## Откуда брать остаток

### Полуручной конфиг

Пользователь смотрит `/usage` и переписывает проценты с датами сброса в
гитигнорнутый файл, pick его читает. Данные честные (панель показывает
серверный расчёт, общий по всем устройствам), реализация тривиальная, чужих
контрактов ноль. Плата: нужны руки, снимок протухает. Протухание закрывается
правилами свежести в формуле (ниже), а не дисциплиной пользователя.

### Оценка по локальным транскриптам

Считать расход по `~/.claude/projects/*/*.jsonl`. Автоматично, но нечестно
дважды: транскрипты одной машины не видят другие устройства и сессии, а
размеры лимитов не публикуются, так что из потраченных токенов процент не
вывести. Получается не оценка, а ложная уверенность, и она хуже прочерка:
корректор начнёт сдвигать вердикты по выдуманному остатку. Отклонено, в том
числе как дефолт комбинированного варианта.

### Съём с интерактивных интерфейсов

Три способа снять остаток механически, все читают редко и только на чтение:

- pty-обвязка над самим `/usage`: поднять `claude` в одноразовой tmux-сессии,
  послать команду, забрать текст панели через `capture-pane`, распарсить.
  Авторизация уже есть, браузер не нужен. Ломается при редизайне панели,
  но ломается громко: парсер не находит ожидаемых строк и отказывает, не
  записав мусор;
- браузер к странице подписки claude.ai (Playwright с залогиненным профилем).
  Работает, но тащит тяжёлую зависимость ради пары чисел, а селекторы
  страницы хрупче текста панели. Отклонено;
- повторить недокументированный эндпоинт, которым `/usage` ходит за лимитами,
  под OAuth-токеном CLI. Механически самый чистый, но это чужой внутренний
  контракт без обещаний: протухает молча и в любой момент. Отклонено;
  вернуться, если эндпоинт задокументируют, тогда он вытеснит и pty-съёмщик.

### Выбор

Контрактом делается файл снимка: pick читает только его и ни в какую сеть и
tmux не ходит, детерминизм и скорость pick не меняются. Заполняется файл
двумя равноправными путями: руками после `/usage` (полуручной конфиг) и
командой `agentctl quota refresh` (pty-съёмщик поверх tmux), которая пишет
те же строки тем же форматом. Съёмщик это автоматизация заполнения, а не
второй источник: сломался парсер панели, значит refresh отказал, файл не
тронут, pick живёт по прежнему снимку или без сдвига.

Сравнение по хрупкости и цене поддержки, ради которого заводился разбор:

| Вариант | Хрупкость | Цена поддержки |
|---|---|---|
| файл руками | нулевая, формат свой | руки пользователя, протухание |
| транскрипты | средняя | высокая: реверс серверного расчёта, и всё равно нечестно |
| pty над /usage | средняя: текст панели, ломается громко | низкая: парсер плюс образцы вывода |
| браузер | высокая: селекторы страницы | высокая: браузерная обвязка |
| эндпоинт | высокая: протухает молча | низкая механически, но контракта нет |

## Файл снимка

`~/.devkit/quota.local`, уровень машины, не проекта: лимиты общие на
подписку, per-project копии в `.devkit/` протухали бы вразнобой и требовали
снимать одно и то же в каждом репозитории. Файл гитигнорить не нужно, он вне
репозиториев; чувствительного в нём нет, но и коммитить нечего.

Формат плоский `key = value`, как в `.devkit/deploy.local`:

```
taken = 2026-07-30T14:20
week_all = 34% сброс 2026-08-04T10:00
week_opus = 78% сброс 2026-08-04T10:00
```

`taken` это момент снятия, бакеты переписываются с панели: потраченный
процент и дата сброса. Пятичасовой сессионный бакет сознательно не пишется:
он протухает быстрее, чем живёт задача, снимок его не догонит. Набор ключей
не фиксирован жёстко: известные бакеты маппятся на ярусы таблицей в коде
(`week_all` держит haiku и sonnet, `week_opus` держит opus; DK-009 добавит
fable и, если панель заведёт ему отдельный бакет, строку в таблицу),
неизвестный ключ игнорируется с предупреждением в человеческой строке.

## Формула корректора

По каждому бакету считается темп расхода против равномерного:

```
remaining = 1 - used
time_left = (reset - now) / окно        # окно недельных бакетов: 7 суток
pace      = remaining / time_left
```

`pace > 1` значит остаток тратится медленнее равномерного темпа. Статус
бакета: профицит при `pace >= 2`, дефицит при `pace <= 0.5`, между ними
норма и сдвига нет. Зазор широкий сознательно: корректор должен срабатывать
на выраженный перекос (80% остатка за день до сброса даёт pace около 5.6,
почти исчерпанный бакет в середине окна около 0.1), а не дёргать вердикт
на каждом колебании.

Свежесть снимка асимметрична, потому что остаток внутри окна только тратится.
Дефицит от старения не рассасывается: снятый remaining это верхняя граница
текущего, и если даже он даёт дефицит, вывод верен до самого сброса. Профицит
же протухает: для сдвига вверх снимок должен быть не старше суток. Прошла
дата сброса, и бакет отбрасывается целиком: началось новое окно, про которое
снимок ничего не знает.

Правила сдвига, порядок значим:

1. Грумминговые вердикты (неопределённость >= 4, цена XL) не корректируются:
   «исполнять рано» это про порядок работы, расход тут ни при чём.
2. Дефицит бакета модели вердикта сдвигает на ярус вниз (opus -> sonnet,
   sonnet -> haiku). Ниже haiku некуда, остаётся предупреждение.
3. Иначе профицит бакета яруса выше сдвигает на ярус вверх (haiku -> sonnet
   при профиците week_all, sonnet -> opus при профиците week_opus).
4. Один шаг максимум, сдвиги не каскадятся. Дефицит проверяется первым:
   при конфликте экономия важнее дотраты.

Лестница ярусов в коде остаётся данными (упорядоченный список), корректор
двигает индекс: DK-009 вставит fable без правки формулы. Нет файла, битая
строка, протухший бакет: соответствующий бакет (или весь снимок)
отбрасывается, вердикт остаётся как сейчас. Отсутствие данных никогда не
ошибка pick.

## Вывод pick и запись --record

Первая строка остаётся машинно-читаемой и несёт итоговую модель. Сдвиг виден
во второй, человеческой строке:

```
model: sonnet
DK-012 (LLD, цена M, неопределённость 2): дизайн отдаётся сильной модели; корректор: дефицит week_opus, opus -> sonnet
```

Для LLD-вердикта, сдвинутого вниз, человеческая строка дополнительно советует
отложить дизайн до сброса, если он не горит: дизайн слабее из-за квоты это
долгий ущерб, а сброс близко. Решение остаётся за диспетчером, pick только
проговаривает.

Строка `--record` фиксирует и маппинг, и сдвиг, чтобы в файле задачи было
видно, чем вердикт объясняется:

```
- Исполнение: субагент sonnet по вердикту pick (маппинг opus, корректор: дефицит week_opus), 2026-07-30.
```

Без сдвига строка остаётся прежней, хвост про корректор не пишется.

## Команда quota

`agentctl quota` печатает распарсенный снимок: бакеты, возраст, pace и статус
каждого (профицит, норма, дефицит, протух). Это окно в решения корректора:
сдвиг в вердикте всегда можно объяснить, не лезя в файл руками.

`agentctl quota refresh` снимает панель `/usage` через tmux: одноразовая
сессия, `claude` из PATH, команда, ожидание отрисовки, `capture-pane`,
парсинг, запись файла, уборка сессии. Без tmux или без залогиненного claude
команда честно отказывает и файл не трогает.

## Тесты

- Юниты на парсер файла и формулу с инжектированными часами: пороги pace с
  обеих сторон, асимметрия свежести (старый дефицит валиден, старый профицит
  нет), протухший бакет, грумминговое исключение, конфликт дефицита с
  профицитом, края лестницы, отсутствие файла и битые строки.
- Парсер текста панели для refresh гоняется по сохранённым образцам вывода
  `/usage` (fixtures); редизайн панели ловится их обновлением, это принятая
  плата варианта. Сам tmux-цикл в CI не гоняется, обвязка тонкая.
- Интеграционный: pick с подложенным файлом снимка выдаёт сдвинутый вердикт
  и корректную строку --record.
