# DK-001: taskctl: машинно-читаемые зависимости blocks/blocked-by и lint инварианта зависимости

## Разбор

Сейчас зависимость между задачами живёт только прозой в причине блокировки
(«[блок: ждём DK-003]») или в тексте файла задачи. Машине она не видна: lint
не поймает задачу, взятую в работу раньше той, от которой она зависит, а
диспетчер не может дёшево спросить «что эта задача держит».

Решения по дизайну:

- Хранится одно направление, «задача A делается после B» (blocked-by).
  Обратное (blocks) вычисляется по доске, хранить обе стороны значит ловить
  их расхождение.
- Носитель это строка доски, а не файл задачи: зависимость нужна и
  однострочному бэклогу, которому файл не положен. Формат по образцу
  существующей пометки блокировки: суффикс заголовка `[после DK-003]`
  (несколько ID через запятую), отдельный regexp. Порядок суффиксов
  фиксирован: сначала `[после ...]`, потом `[блок: ...]`.
- Новая подкоманда `dep`: `dep add <ID> <DEP-ID>` (A после B),
  `dep rm <ID> <DEP-ID>`, `dep list [ID]` (без ID вся доска, обе стороны).
  `show <ID>` тоже печатает зависимости в обе стороны.
- `close <B>` снимает `[после B]` со всех строк доски той же операцией:
  закрытая зависимость выполнена, протухшие маркеры на доске не живут,
  в архив маркеры не попадают.
- Инварианты в lint: ID в маркере существует (доска или архив), не сам на
  себя, без дублей, без циклов; задача в In progress или Check с незакрытой
  зависимостью это ошибка (ей место в Backlog или Blocked). `move` в
  in-progress с незакрытой зависимостью падает с той же формулировкой
  (страховка до lint), `--force` не заводим.

## DoD

- Разбор и запись маркера `[после ...]` в board.go, нетронутые строки
  сохраняются байт в байт.
- Подкоманда `dep add/rm/list`, вывод зависимостей в `show`.
- Снятие маркера при `close`, страховка в `move`, инварианты в lint.
- Юнит-тесты на разбор, add/rm, close, move и каждый инвариант lint.
- Дока: taskctl/README.md (команда и формат), строка `dep` в перечне команд
  RULES.board.md.

## Сценарий проверки (агентский)

1. `cd $(mktemp -d) && git init -q . && taskctl init --prefix XR` и завести
   три задачи: `taskctl add --title "база" --type task --rank "0+3+0+0+0"`,
   так же «хвост» и «сбоку».
2. `taskctl dep add XR-002 XR-001` -> код 0, в строке XR-002 появился суффикс
   `[после XR-001]`; `taskctl dep list XR-001` показывает, что XR-001 держит
   XR-002.
3. `taskctl move XR-002 in-progress` -> код 1, в ошибке упомянута XR-001.
4. `taskctl dep add XR-001 XR-002` -> код 1 (цикл);
   `taskctl dep add XR-003 XR-009` -> код 1 (нет такой задачи).
5. Руками вписать в заголовок XR-003 суффикс `[после XR-001]` и перевести её
   строку в In progress (редактором), `taskctl lint` -> код 1, ошибка про
   незакрытую зависимость.
6. Вернуть XR-003 в Backlog, `taskctl close XR-001 --date 2026-07-29` -> у
   XR-002 и XR-003 суффикс снят, `taskctl lint` -> код 0.
