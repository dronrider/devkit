# DK-003: regcheck: проверка инлайновых тестов, когда правка и тест в одном файле

## Ход работы

- Исполнение: субагент sonnet по вердикту pick, 2026-07-29.
- Добавлен флаг `--inline` для файлов, где правка и тест живут в одном
  файле. На базу переносится не файл целиком, а только его тестовый
  регион: границы ищутся либо по явным маркерам `regcheck:test-begin` /
  `regcheck:test-end` (комментарий любого синтаксиса, работает для
  любого языка), либо по единственному блоку Rust
  `#[cfg(test)] mod ... { ... }` (совпадение фигурных скобок). Если
  регион не находится однозначно (несколько блоков, маркер без пары,
  несбалансированные скобки, региона нет вовсе), инструмент падает с
  объяснением, а не гадает: ложный зелёный хуже отказа. Автопоиск
  изменённых тестов (`isTestPath`) на инлайновые файлы не распространён,
  список `--inline` только явный.
- Раздел «Ограничения» в README про инлайновые тесты Rust убран,
  добавлен раздел «Инлайновые тесты» с описанием флага и эвристик.

## Сценарий проверки

Агентский, шаги ничего не меняют вне временных директорий.

1. Собрать `regcheck` из ветки:
   ```
   cd regcheck && go build -o /tmp/regcheck-check .
   ```
2. Развернуть во временной директории мини-репозиторий с инлайновым
   файлом `lib.rs`, где база багована (`CODE = "bug"`), а рабочее
   дерево одновременно чинит баг и добавляет инлайн-тест:
   ```sh
   WORK=$(mktemp -d) && cd "$WORK"
   git init -q -b main
   git config user.email t@t && git config user.name t
   printf 'const CODE: &str = "bug";\n' > lib.rs
   git add . && git commit -qm seed
   printf 'const CODE: &str = "fixed";\n\n#[cfg(test)]\nmod tests {\n    // проверяет CODE\n}\n' > lib.rs
   printf 'grep -q fixed lib.rs\n' > probe_test.sh
   /tmp/regcheck-check --inline lib.rs -- sh probe_test.sh
   ```
   Ожидаемый код возврата 0, в выводе строка:
   `тест краснеет на HEAD и проходит на текущем коде, регрессия закрыта (тесты: probe_test.sh, lib.rs)`
3. Негативный шаг: в другой временной директории тот же сценарий, но
   без тестового региона в файле (нет ни `#[cfg(test)]`, ни маркеров):
   ```sh
   WORK=$(mktemp -d) && cd "$WORK"
   git init -q -b main
   git config user.email t@t && git config user.name t
   printf 'const CODE: &str = "bug";\n' > lib.rs
   git add . && git commit -qm seed
   printf 'const CODE: &str = "fixed";\n' > lib.rs
   printf 'grep -q fixed lib.rs\n' > probe_test.sh
   /tmp/regcheck-check --inline lib.rs -- sh probe_test.sh
   ```
   Ожидаемый код возврата 1, в выводе строка:
   `ошибка: инлайновый файл lib.rs: не нашёл тестовый регион: нет #[cfg(test)] mod и нет маркеров regcheck:test-begin/regcheck:test-end вокруг тестов`

Оба шага прогнаны при разработке, вывод совпал с ожидаемым.

## Ревью

- check.go: оба маркера в одной строке считаются парой, регион схлопывается и перекрывает настоящий блок cfg(test); требовать begin строго раньше end: исправлено
- check.go / README: дописывание региона в конец базы может уронить компиляцию, и падение сборки засчитается за краснеющий тест; README про это молчит: исправлено
- check.go: файл, попавший и в tests, и в --inline, копируется целиком и правка утекает на базу, диагноз ложный; исключать inline из tests или падать на пересечении: исправлено
- check.go: однострочный cfg(test) mod tests не распознаётся, а текст ошибки утверждает, что блока нет вовсе: исправлено
- check.go: пересечение tests и inline сравнивается строкой, ./lib.rs против lib.rs обходит исключение: отклонено, кончается честной ошибкой, не ложным зелёным; пути от git всегда чистые, дыра только при разнобое ручных флагов
- README: совет посмотреть вывод глазами обещает больше, чем инструмент показывает, вывод базового прогона при успехе не печатается: отклонено, вкусовое, ручной прогон на базе остаётся доступным способом проверить глазами
