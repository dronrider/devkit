# DK-004: devkitctl doctor и shipctl merge: предупреждение про autonomous = true при пустом deploy

## Разбор

Сочетание `autonomous = true` с пустым `deploy=` в `.devkit/deploy.local` было
молчаливым: агент считает, что ему доверен весь конвейер, а merge при пустой
команде просто не запускает выкат. Теперь shipctl (status, merge, ship и
revert) и devkitctl doctor предупреждают, что надо вписать команду выката
либо снять autonomous.

## Ход работы

- Исполнение: субагент haiku по вердикту pick, 2026-07-29.
- Ветка dk-004: в `resolveDeploy` добавлено поле `warn` плана выката, его
  печатают status, merge (включая train-путь), ship и revert; `read_deploy` в
  devkitctl отдаёт ещё и autonomous, doctor даёт находку на конфликтное
  сочетание вместо старой про пустой deploy. Тесты в `config_test.go` и
  `test.sh`.

## Сценарий проверки (агентский)

Шаги выполняются с машины агента, прод не меняют.

1. Завести временный проект: git-репозиторий, доска через `taskctl init`
   (без неё status и блок deploy в doctor не работают), начальный коммит,
   `.devkit/deploy.local` из строки `autonomous = true`, без `deploy=`.
2. `shipctl status` (бинарь из `~/go/bin` после выката) в этом проекте.
   Ожидаемо: в выводе строка с предупреждением про autonomous при пустом deploy.
3. `python3 ~/projects/devkit/devkitctl/devkitctl.py doctor -C <проект>`.
   Ожидаемо: среди находок строка «autonomous = true при пустом deploy=...»,
   код возврата 1, старая находка про пустой deploy= не дублируется.
4. Дописать в конфиг `deploy = echo ok` и повторить шаг 2.
   Ожидаемо: предупреждения больше нет.
