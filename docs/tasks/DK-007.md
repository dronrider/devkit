# DK-007: agentctl: pick --record фиксирует модель исполнения в файле задачи

Какой моделью исполнялась задача, сейчас видно только в транскриптах сессий
(`~/.claude/projects/.../*.jsonl`), на доску это не попадает. Флаг `--record`
у pick дописывает вердикт строкой в раздел «Ход работы» файла задачи: диспетчер
зовёт `agentctl pick <ID> --record` при взятии задачи, и модель исполнения
остаётся там, куда смотрит пользователь. Это самоотчёт диспетчера, а не
доказательство; ground truth остаются транскрипты.

Решения:

- строка вида `- Исполнение: субагент <model> по вердикту pick, ГГГГ-ММ-ДД.`
  дописывается в конец раздела «## Ход работы»; если раздела нет, он
  добавляется в конец файла;
- каждый вызов с `--record` дописывает новую строку (история перезапусков),
  идемпотентности не нужно;
- грумминговый вердикт (неопределённость >= 4, цена XL) пишется словом
  «Грумминг» вместо «Исполнение»: работа по нему не начинается, запись не
  должна обещать исполнение, которого не было;
- нет файла задачи, значит ошибка с подсказкой `taskctl file <ID>`: pick
  зовётся при взятии в работу, а у взятой в работу задачи файл обязан быть;
- git agentctl не трогает: коммит и пуш строки остаются за диспетчером, как
  у любой правки файла задачи (п. 9 раздела «Трекинг задач»).

## DoD

- Флаг `--record` у pick: строка в «Ход работы», создание раздела, ошибка без
  файла задачи; вывод в stdout не меняется.
- Тесты: дозапись в существующий раздел, создание раздела, вторая строка при
  повторном вызове, ошибка без файла.
- Дока: agentctl/README.md (флаг и формат строки), п. 10 RULES.board.md
  (диспетчер зовёт pick с --record при взятии задачи).

## Сценарий проверки (агентский)

1. Собрать: `cd ~/projects/devkit/agentctl && go build -o ~/go/bin/agentctl .`;
   код возврата 0.
2. Во временном репозитории с доской завести задачу (`taskctl add --title a
   --type task --rank "0+1+1+0+0" --cost S`) и файл (`taskctl file T-001`).
   `agentctl pick T-001 --record` код 0; в `docs/tasks/T-001.md` появился
   раздел «## Ход работы» со строкой `- Исполнение: субагент haiku по
   вердикту pick, <сегодня>.`; повторный вызов дописывает вторую такую же
   строку.
3. Задача без файла (`taskctl add --title b ...`, файла нет):
   `agentctl pick T-002 --record` завершается ненулевым кодом, в ошибке
   упомянут `taskctl file`.
4. Задача с `--rank "25+5+5+0+3" --cost M` и файлом (`taskctl file T-003`):
   `agentctl pick T-003 --record` код 0, в файле строка `- Грумминг: субагент
   opus по вердикту pick, <сегодня>.`, слова «Исполнение» в ней нет.
5. `go test ./...` в `devkit/agentctl`: код возврата 0.
