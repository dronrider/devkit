# DK-009: agentctl: fable-ярус маппинга (LLD по цене, сложный код) и доменный override модели

Наблюдение пользователя: текущий маппинг не знает fable, а задачи
проектирования (дизайн, 3D-графика) и сложные LLD fable делает существенно
лучше opus. Верх маппинга сейчас opus, fable зарезервирован за диспетчером.

Что менять:

- сложность LLD на доске уже видна через цену: LLD ценой L/XL (сложное
  проектирование) -> fable, LLD ценой S/M -> opus;
- сверхсложный кодинг: цена L при неопределённости 3 -> opus (сейчас sonnet);
- доменные случаи (3D-графика, дизайн интерфейсов), которых в метаданных
  доски нет, закрываются явным override модели у задачи. Как записывать
  override, развилка: пометка в строке доски (метаданные живут в доске, но
  формат строки фиксирован) либо строка в файле задачи, которую читает pick.
  Решить при реализации, дока и lint соответственно.

Тесты на новые ветки маппинга и на override, README-таблица и п. 10
RULES.board.md обновляются той же веткой.

## Ход работы

- Исполнение: субагент sonnet по вердикту pick, 2026-07-30.
- Развилка по формату override решена в пользу строки в файле задачи, а не
  пометки в строке доски: формат строки доски фиксированный и его парсят три
  утилиты (agentctl, taskctl, shipctl), лишний столбец под редкий домен
  ломать не стоит. Валидация имени модели держится в pick, taskctl lint не
  трогается: lint проверяет инварианты доски, а файл задачи доска только
  индексирует.

## Сценарий проверки (агентский)

Проверяется выкаченный бинарь agentctl из PATH на одноразовой доске во
временной директории, прод ничего не меняет. Шаги:

```sh
d=$(mktemp -d) && mkdir -p "$d/docs/tasks"
cat > "$d/docs/TASKS.md" <<'EOF'
# t: задачи (префикс T)

## Backlog

| ID | Задача | Тип | P | R | Цена | Ссылка |
|---|---|---|---|---|---|---|
| T-001 | сложный дизайн | LLD | P1 | 20 (10+5+2+0+3) | L | - |
| T-002 | доменная задача | task | P2 | 10 (0+5+2+0+3) | M | - |
| T-003 | задача с опечаткой | task | P2 | 10 (0+5+2+0+3) | M | - |
EOF
agentctl -C "$d" pick T-001 | head -1        # жду: model: fable
printf '# T-002\n\nМодель: fable (3D-графика)\n' > "$d/docs/tasks/T-002.md"
agentctl -C "$d" pick T-002 | head -1        # жду: model: fable
printf '# T-003\n\nМодель: fabel\n' > "$d/docs/tasks/T-003.md"
agentctl -C "$d" pick T-003; echo "код: $?"  # жду: ошибка, код не 0
```

Итог: LLD ценой L даёт fable, override из файла задачи срабатывает,
опечатка в имени модели падает ошибкой, а не проваливается в маппинг.

## Ревью

- readOverride ищет строку «Модель:» по всему файлу: пример в code-fence сработает как настоящий override, при нескольких строках молча берётся первая; выбор «первая выигрывает» зафиксировать в README: исправлено
- нет теста на связку override и --record (метка «Исполнение», Groom=false) и теста «L с нечитаемым рангом остаётся sonnet», хотя README это обещает: исправлено
- кейс «LLD ценой S остаётся на opus» дублирует существующий «LLD сильнее дешевизны», одна из строк лишняя: исправлено
- LLD ценой L/XL с неопределённостью >= 4 уходит в fable без грумминга: LLD-правило выше грумминг-правила: отклонено, осознанно: LLD и есть работа по снятию неопределённости, приоритет LLD-правила прежний, поменялась только модель наверху
