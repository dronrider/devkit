# DK-012: agentctl: квотный корректор вердикта pick по снимку /usage

Реализация по принятому дизайну [DK-010](../lld/DK-010-quota-corrector.md),
дизайн там и не пересказывается. Состав: парсер файла снимка
`~/.devkit/quota.local`, формула корректора (pace, статусы, правила сдвига по
лестнице), сдвиг в выводе pick и в строке --record, команды `agentctl quota` и
`agentctl quota refresh` (pty-съёмщик поверх tmux), тесты по разделу «Тесты»
LLD, дока (`agentctl/README.md`, фраза в `RULES.board.md` п. 10).

Учесть DK-015 (уже в main): лестница моделей сдвинута, sonnet только на S с
неопределённостью 1 и с полом effort high, дефолт opus. Корректор двигает
итоговую модель вердикта по той же лестнице haiku -> sonnet -> opus -> fable
из LLD, пол sonnet применяется к результату сдвига так же, как к маппингу.

## Сценарий проверки

Агентский. После выката (пересборка бинарей в PATH):

1. `cd ~/projects/devkit/agentctl && go test ./...` завершается кодом 0.
2. Без файла `~/.devkit/quota.local` вывод `agentctl pick DK-012` не содержит
   слова «корректор» и совпадает с обычным маппингом (отсутствие данных не
   ошибка).
3. С подложенным во временный HOME снимком, где `week_opus` в дефиците
   (например, осталось 5% при половине окна), `pick` по задаче с вердиктом
   opus печатает сдвиг «opus -> sonnet» и хвост про корректор во второй
   человеческой строке.
4. `agentctl quota` на том же снимке печатает бакеты со статусами (дефицит),
   код возврата 0.

Шаги ничего не меняют на проде (временный HOME), итог проверяется по коду
возврата и строкам вывода.

## Ход работы

- Исполнение: субагент opus/medium по вердикту pick, 2026-07-30.
- Развилка: модель из override-строки файла задачи корректор не двигает.
  В LLD случай не оговорён, а ручное решение сильнее автоматики, иначе
  указанную руками модель пришлось бы отстаивать заново на каждый снимок.
  Пол effort у sonnet при этом применяется к итоговой модели, то есть уже
  после сдвига, и одинаково для маппинга и для override.
- Развилка: строка `--record` из LLD дополнена эффортом, который завёл DK-015,
  получилось «- Исполнение: субагент sonnet/high по вердикту pick (маппинг
  opus, корректор: дефицит week_opus), дата.». В LLD эффорта в примере нет, но
  он появился позже и описан в README, терять его на сдвинутых вердиктах
  незачем.
- Развилка: сдвиг вверх там, где у соседних ярусов набор трат одинаковый
  (haiku и sonnet, opus и fable), требует профицита всех бакетов яруса. В LLD
  прописана только пара haiku и sonnet через общий week_all, для opus и fable
  взято то же правило.
- Образец панели `/usage` в `agentctl/testdata` синтетический: точная разметка
  панели официально не описана (документированы состав данных и горячие
  клавиши, а не подписи строк), поэтому образцов два, с календарной датой
  сброса и с обратным отсчётом. При первом живом `agentctl quota refresh`
  образец стоит заменить реальным выводом `capture-pane`.
- Прогресс-бары в образцах панели набраны блоковыми символами, как их рисует
  клиент. Это тестовые данные, под исключение `check-symbols` они попадают
  осознанно.
