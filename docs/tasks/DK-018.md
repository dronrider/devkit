# DK-018: agentctl: строка --record всегда несёт состояние квоты, а не только сдвиг

`recordExecution` дописывает хвост про корректор только при сдвиге вердикта.
Когда сдвига не было, в файле задачи остаётся голое «Исполнение: субагент
opus/high по вердикту pick», и по нему не восстановить, на каких данных
решение принималось. Одинаково выглядят три разных случая:

- снимка нет, корректор выключен вовсе;
- снимок свежий, бакеты в норме, вердикт совпал с маппингом;
- снимок протух, поэтому профицит не применялся, хотя запас был.

Спросили ровно об этом, глядя на закрытую задачу в соседнем проекте: почему в
файле нет данных об использовании подписки, на основании которых выбрана
модель. Правило про наблюдаемость в `RULES.md` требует, чтобы бездействие
фичи было видно снаружи, а сейчас оно неотличимо от штатной работы.

Правка: строка исполнителя всегда несёт состояние квоты на момент решения.
Минимум это проценты бакетов, из которых тратит выбранный ярус, возраст
снимка и явное «снимка нет». Примерная форма (точную подобрать при
реализации, строка не должна расползтись на три экрана):

```text
- Исполнение: субагент opus/high по вердикту pick (квота: week_all 41%,
  снимок 1ч назад, сдвига нет), 2026-07-31.
- Исполнение: субагент sonnet/high по вердикту pick (маппинг opus, корректор:
  дефицит week_all 78%, снимок 20м назад, opus -> sonnet), 2026-07-31.
- Исполнение: субагент opus/high по вердикту pick (квота: снимка нет,
  корректор выключен), 2026-07-31.
```

Тем же заходом стоит подумать про человеческую строку вывода pick: сейчас она
про корректор тоже молчит, когда сдвига нет, и «снимка нет» там не печатается
(предупреждение появляется, только если файл есть и не читается). Обе поверхности
надо привести к одному поведению, иначе выключенный корректор снова окажется
невидимым.

Тесты: табличный юнит на форму строки для трёх случаев (нет снимка, норма,
сдвиг) плюс проверка, что повторный `--record` не задваивает данные.

Дока: `agentctl/README.md`, раздел про `--record` и пример строки.

Связь с соседями: DK-019 делает так, чтобы снимок вообще был свежим, здесь
фиксируется, что именно он показывал в момент решения. Порядок между ними
неважен, но обе трогают один и тот же вывод, так что вторая по счёту едет с
оглядкой на первую.

## Ход работы

- Исполнение: субагент opus/medium по вердикту pick (маппинг sonnet, корректор: профицит week_all), 2026-08-02.
- Состояние квоты собирается один раз (`quotaFactsOf` в `quota.go`) и уходит на
  обе поверхности: в человеческую строку вердикта и в строку `--record`. Форма
  вышла такой: `квота: week_all 41%, снимок 10м назад, сдвига нет`. Бакеты
  берутся не все подряд, а те, из которых платят исходный и итоговый ярусы:
  при сдвиге вниз причина лежит в бакете исходного, а знать надо и то, чем
  будет платить итоговый. Статус бакета печатается, только когда он не норма,
  иначе строка распухает ни на чём.
- Со сдвигом хвост про корректор остался прежним, состояние идёт вторым куском
  через точку с запятой и про сам сдвиг молчит: куда съехал ярус, уже сказано
  рядом. Грумминговый вердикт вместо «сдвига нет» говорит, что корректор его не
  двигает: там сдвига не было по другой причине, и путать эти два случая нельзя.
- В человеческой строке состояние не печатается там, где про снимок уже сказано
  предупреждением (нет снимка, нет момента снятия, часы разошлись, протух, файл
  не читается): предупреждение говорит то же самое и вдобавок несёт команду
  починки, а два хвоста подряд про одно читались бы как ошибка. В файл задачи
  предупреждения не идут вовсе, поэтому там состояние пишется всегда.
- Тесты: `TestRecordQuotaState` в `agentctl/pick_test.go` (сквозная таблица по
  строке записи: снимка нет, норма, сдвиг вниз, протухший снимок, подъём на max
  с двумя бакетами, плюс повторный `--record` без задвоения) и `TestQuotaFacts`
  в `agentctl/quota_test.go` (форма состояния там, куда сквозной pick не
  достаёт: сдвиг сверху вниз, бакета нет в снимке, снимок без момента снятия,
  снимок из будущего). Мутациями проверено, что тесты краснеют на: бакеты
  только итогового яруса, пропавшее «сдвига нет», неназванный протухший снимок,
  пропавший статус бакета, состояние не пишется в файл задачи, состояние
  дублирует предупреждение.
- Ревью: субагент sonnet/high по вердикту pick, 2026-08-02.

## Сценарий проверки (агентский)

Проверяется на синтетической доске во временном HOME: `pick --record` пишет в
живые файлы задач, и гонять его на боевой доске ради проверки нельзя.

```sh
S=$(mktemp -d)
mkdir -p "$S/home/.devkit/quota" "$S/repo/docs/tasks"
cat > "$S/repo/docs/TASKS.md" <<'EOF'
# demo: задачи (префикс T)

## In progress

| ID | Задача | Тип | P | R | Цена | Ссылка |
|---|---|---|---|---|---|---|
| T-002 | синтетическая задача | task | P2 | 34 (25+4+1+0+4) | M | - |

## Backlog

Нет.
EOF
printf '# T-002\n' > "$S/repo/docs/tasks/T-002.md"
cat > "$S/home/.devkit/harness.local" <<'EOF'
enabled = ["claude-code"]
default = "claude-code"

[claude-code]
mini = "haiku"
base = "sonnet"
pro = "opus"
max = "fable"
EOF
snap() { printf 'taken = %s\nweek_all = %s%% сброс %s\n' "$1" "$2" "$3" > "$S/home/.devkit/quota/claude-code.local"; }
run() { HOME="$S/home" DEVKIT_HOME=~/projects/devkit DEVKIT_HARNESS= agentctl pick T-002 --record -C "$S/repo" | tail -1; }

snap "$(date -v-10M '+%Y-%m-%dT%H:%M')" 41 "$(date -v+3d '+%Y-%m-%dT%H:%M')"; run
snap "$(date -v-10M '+%Y-%m-%dT%H:%M')" 95 "$(date -v+3d '+%Y-%m-%dT%H:%M')"; run
rm "$S/home/.devkit/quota/claude-code.local"; run

for p in 'квота: week_all 41%, снимок 10м назад, сдвига нет' \
         'корректор: дефицит week_all; квота: week_all 95% дефицит' \
         'квота: снимка нет, корректор выключен'; do
  grep -qF "$p" "$S/repo/docs/tasks/T-002.md" || { echo "нет строки: $p"; exit 1; }
done
echo "проверка пройдена"
```

Ожидаемый итог: последняя команда печатает «проверка пройдена», то есть в файле
синтетической задачи лежат три записи, и по каждой видно, на каких данных
принято решение. Вердикт по снимку в норме при этом сам говорит про квоту, а
вердикт без снимка, как и раньше, предупреждает и зовёт `agentctl quota
refresh`.

Прогон на сборке ветки (`go build -o "$B/agentctl" .` в `agentctl`, `$B` в
начало PATH):

```text
--- 1. снимок в норме
T-002 (task, цена M, неопределённость 1): задача для дешёвых моделей не подходит, по умолчанию идёт сильной; квота: week_all 41%, снимок 10м назад, сдвига нет
--- 2. дефицит
T-002 (task, цена M, неопределённость 1): задача для дешёвых моделей не подходит, по умолчанию идёт сильной, effort поднят до high: base дёшев, экономить глубину смысла нет; корректор: дефицит week_all, pro -> base; квота: week_all 95% дефицит, снимок 10м назад; сдвиг вниз на цене M и выше это заметная потеря качества в исполнении, а сброс близко, так что если не горит, лучше отложить
--- 3. снимка нет
T-002 (task, цена M, неопределённость 1): задача для дешёвых моделей не подходит, по умолчанию идёт сильной; снимка квоты нет (/tmp/.../home/.devkit/quota/claude-code.local), вердикт идёт без корректора; снять: agentctl quota refresh
--- файл задачи
# T-002
```
