# DK-022: agentctl: панель /usage сменила бакет opus на fable, парсер и лестница трат

Клиент обновился до 2.1.220, и панель `/usage` перестала показывать недельный
бакет Opus. Вместо него отдельным бакетом идёт Fable:

```text
Current week (all models)
[полоска]  41% used
Resets Aug 3 at 2:59pm (Europe/Moscow)

Current week (Fable)
[полоска]  70% used
Resets Aug 3 at 2:59pm (Europe/Moscow)
```

`parseUsagePanel` ищет секцию со словами «week» и «opus», не находит её и
отказывается писать снимок, поэтому `agentctl quota refresh` падает с текстом
«панель не узналась». На этот раз причина настоящая. Вдобавок секция Fable
попадает в ветку `week_all` (слово «week» есть, «opus» нет) и разбирается как
второе вхождение всех моделей; сейчас это спасает только порядок секций и
защита от повторной записи процента.

Что поменять:

- парсер узнаёт бакет Fable отдельной секцией и терпит отсутствие Opus.
  Старые снимки с `week_opus` должны читаться дальше: панель у разных версий
  клиента и тарифов отличается, а снимок пишется и руками;
- лестница трат `tierBuckets` пересобирается. Opus теперь виден только в
  бакете всех моделей, у Fable появился свой. Дефицит, двигающий вердикт с
  opus на sonnet, приходит из `week_all`, а `week_fable` держит только верхний
  ярус;
- следствие для корректора: между opus и sonnet бакеты больше не различаются,
  и сдвиг вниз с opus срабатывает ровно тогда же, когда с sonnet на haiku.
  Проверить, не сломало ли это смысл сдвига вверх (`extraBuckets` для перехода
  opus -> fable теперь возвращает `week_fable`, и это как раз тот случай,
  который дизайн DK-010 предусматривал словами «заведёт, и он добавится в
  таблицу»);
- образец новой панели кладётся в `agentctl/testdata` рядом с существующими,
  на нём же закрывается юнит парсера. Снять свежий образец можно так:

  ```sh
  tmux new-session -d -s probe -x 200 -y 60 claude && sleep 8 \
    && tmux send-keys -t probe -l "/usage" && sleep 1 \
    && tmux send-keys -t probe Enter && sleep 10 \
    && tmux capture-pane -p -t probe > /tmp/usage-pane.txt; tmux kill-session -t probe
  ```

Два наблюдения по той же панели, которые стоит учесть заодно.

Над бакетом всех моделей висит строка «+50% weekly limits promo through
Aug 19»: проценты считаются от увеличенного лимита, и в день окончания промо
знаменатель вернётся к обычному. В снимке это будет выглядеть как скачок
процента вверх без всякого расхода, и корректор честно съедет вниз. Ломать
из-за этого ничего не надо, но в README про такой скачок стоит предупредить.

Первым в панели идёт пятичасовое сессионное окно. В снимок оно по-прежнему не
пишется (протухает быстрее, чем живёт задача), и `panelSection` сбрасывает на
нём разбор в пустой ключ. При переделке парсера это поведение сохранить, а в
тесте на новом образце закрепить: секция сессии не должна затекать в бакет
всех моделей.

Дока: таблица «из каких бакетов тратит ярус» и пример снимка в
`agentctl/README.md`, плюс отличие от исходного дизайна в
`docs/lld/DK-010-quota-corrector.md`.

Заметка про порядок: DK-021 (читаемый отказ и сохранение неузнанной панели)
стоит делать раньше или в одной ветке. Ровно эта задача показала цену
отсутствия дампа: настоящую причину нашли, только сняв панель руками через
tmux.

## Сценарий проверки

Агентский. Выкат devkit это пересборка бинарей в `~/go/bin`, поэтому шаги
гоняют установленный `agentctl`. Единственное, что шаги меняют на машине, это
снимок `~/.devkit/quota.local` на шаге 2, и его перезапись свежими данными и
есть работа проверяемой команды.

1. Юниты: `cd ~/projects/devkit/agentctl && go test -count=1 ./...` завершается
   кодом 0. Парсер там гоняется по образцу живой панели 2.1.220 и по старым
   образцам с бакетом Opus.
2. Живая панель: `agentctl quota refresh` завершается кодом 0 и печатает
   строки `week_all:` и `week_fable:` с процентами и датой сброса. До правки
   команда падала кодом 1 с «панель /usage не узналась».
3. Чтение записанного: `agentctl quota` завершается кодом 0 и печатает те же
   два бакета со статусами, то есть снимок читается тем же форматом, каким
   записан.
4. Лестница трат на подложенном снимке, ничего настоящего не трогая:

   ```sh
   tmp=$(mktemp -d) && mkdir -p "$tmp/home/.devkit" "$tmp/repo/docs"
   printf '# проверка (префикс T)\n\n## In progress\n\n| ID | Задача | Тип | P | R | Цена | Ссылка |\n|--------|--------|-----|---|---|------|--------|\n| T-001 | проверка лестницы трат | task | P2 | 30 (25+3+1+0+1) | M | - |\n' > "$tmp/repo/docs/TASKS.md"
   r=$(date -v+3d '+%Y-%m-%dT%H:%M')
   snap() { printf 'taken = %s\nweek_all = %s%% сброс %s\n%s = %s%% сброс %s\n' "$(date '+%Y-%m-%dT%H:%M')" "$1" "$r" "$2" "$3" "$r" > "$tmp/home/.devkit/quota.local"; }
   snap 50 week_fable 5  && HOME="$tmp/home" agentctl -C "$tmp/repo" pick T-001
   snap 95 week_fable 50 && HOME="$tmp/home" agentctl -C "$tmp/repo" pick T-001
   snap 50 week_opus 95  && HOME="$tmp/home" agentctl quota && HOME="$tmp/home" agentctl -C "$tmp/repo" pick T-001
   ```

   Ждём три исхода подряд: профицит `week_fable` поднимает вердикт до
   `model: fable` с хвостом «корректор: профицит week_fable, opus -> fable»;
   дефицит `week_all` опускает до `model: sonnet` с хвостом «корректор:
   дефицит week_all, opus -> sonnet»; старый снимок с `week_opus` читается
   (в выводе `quota` он с процентом и статусом «дефицит»), но вердикт остаётся
   `model: opus` без хвоста корректора.

## Ход работы

- Исполнение: субагент opus/high по вердикту pick, 2026-07-30.
- Образец панели снят живьём с клиента 2.1.220 командой из постановки, экран
  входа не помешал: `agentctl/testdata/usage-panel-fable.txt` это настоящий
  вывод `capture-pane` целиком, с промо-строкой и подсказками внизу.
- Парсер: секция Fable узнаётся отдельным бакетом `week_fable`, обязательным
  остался только `week_all`. Заодно закрыты две дыры, которые новая панель
  открыла: за заголовок секции теперь считается только строка со словом
  «current» (иначе им притворяются промо «+50% weekly limits promo» и
  подсказка «w to week»), а процент берётся только со строки полоски («41%
  used»), иначе в бакет уезжает процент промо. Бакет без прочитанного
  процента стал отказом: молчаливый ноль читается как нетронутый бакет, то
  есть как профицит.
- Лестница трат пересобрана как в постановке: opus тратит только из
  `week_all`, у fable своя пара с `week_fable`. Сдвиг вниз с opus срабатывает
  теперь там же, где с sonnet на haiku, а вверх opus -> fable двигает профицит
  `week_fable` (`extraBuckets` возвращает ровно его). Ключ `week_opus` остался
  известным ради старых снимков: такой снимок читается без предупреждений и
  виден в `agentctl quota`, но вердикт больше не двигает. Это осознанная
  потеря для машин со старым клиентом, зафиксирована в LLD DK-010.
- По ходу нашлась вторая причина, по которой refresh падал, и без неё правка
  парсера пользователю не видна: команда набиралась, как только в панели
  появлялся хоть какой-то текст, то есть до строки ввода, и пропадала без
  следа, а refresh потом ждал панель, которую никто не открывал. Признаком
  готовности взята рамка строки ввода: слова подсказки под ней не годятся,
  клиент крутит их по очереди («? for shortcuts», «install gh for PR status»).
  Из свежего каталога (worktree задачи) старый refresh падал воспроизводимо,
  после правки три прогона подряд зелёные.
- Регрессия проверена механически: `regcheck --base main -- sh -c 'cd agentctl
  && go test ./...'` даёт «тест краснеет на main и проходит на текущем коде»,
  отдельно то же по `TestParseUsagePanel`, `TestCorrectModel` и
  `TestTierBuckets`.
