# DK-022: agentctl: панель /usage сменила бакет opus на fable, парсер и лестница трат

Клиент обновился до 2.1.220, и панель `/usage` перестала показывать недельный
бакет Opus. Вместо него отдельным бакетом идёт Fable:

```text
Current week (all models)
[полоска]  41% used
Resets Aug 3 at 2:59pm (Europe/Moscow)

Current week (Fable)
[полоска]  70% used
Resets Aug 3 at 2:59pm (Europe/Moscow)
```

`parseUsagePanel` ищет секцию со словами «week» и «opus», не находит её и
отказывается писать снимок, поэтому `agentctl quota refresh` падает с текстом
«панель не узналась». На этот раз причина настоящая. Вдобавок секция Fable
попадает в ветку `week_all` (слово «week» есть, «opus» нет) и разбирается как
второе вхождение всех моделей; сейчас это спасает только порядок секций и
защита от повторной записи процента.

Что поменять:

- парсер узнаёт бакет Fable отдельной секцией и терпит отсутствие Opus.
  Старые снимки с `week_opus` должны читаться дальше: панель у разных версий
  клиента и тарифов отличается, а снимок пишется и руками;
- лестница трат `tierBuckets` пересобирается. Opus теперь виден только в
  бакете всех моделей, у Fable появился свой. Дефицит, двигающий вердикт с
  opus на sonnet, приходит из `week_all`, а `week_fable` держит только верхний
  ярус;
- следствие для корректора: между opus и sonnet бакеты больше не различаются,
  и сдвиг вниз с opus срабатывает ровно тогда же, когда с sonnet на haiku.
  Проверить, не сломало ли это смысл сдвига вверх (`extraBuckets` для перехода
  opus -> fable теперь возвращает `week_fable`, и это как раз тот случай,
  который дизайн DK-010 предусматривал словами «заведёт, и он добавится в
  таблицу»);
- образец новой панели кладётся в `agentctl/testdata` рядом с существующими,
  на нём же закрывается юнит парсера. Снять свежий образец можно так:

  ```sh
  tmux new-session -d -s probe -x 200 -y 60 claude && sleep 8 \
    && tmux send-keys -t probe -l "/usage" && sleep 1 \
    && tmux send-keys -t probe Enter && sleep 10 \
    && tmux capture-pane -p -t probe > /tmp/usage-pane.txt; tmux kill-session -t probe
  ```

Два наблюдения по той же панели, которые стоит учесть заодно.

Над бакетом всех моделей висит строка «+50% weekly limits promo through
Aug 19»: проценты считаются от увеличенного лимита, и в день окончания промо
знаменатель вернётся к обычному. В снимке это будет выглядеть как скачок
процента вверх без всякого расхода, и корректор честно съедет вниз. Ломать
из-за этого ничего не надо, но в README про такой скачок стоит предупредить.

Первым в панели идёт пятичасовое сессионное окно. В снимок оно по-прежнему не
пишется (протухает быстрее, чем живёт задача), и `panelSection` сбрасывает на
нём разбор в пустой ключ. При переделке парсера это поведение сохранить, а в
тесте на новом образце закрепить: секция сессии не должна затекать в бакет
всех моделей.

Дока: таблица «из каких бакетов тратит ярус» и пример снимка в
`agentctl/README.md`, плюс отличие от исходного дизайна в
`docs/lld/DK-010-quota-corrector.md`.

Заметка про порядок: DK-021 (читаемый отказ и сохранение неузнанной панели)
стоит делать раньше или в одной ветке. Ровно эта задача показала цену
отсутствия дампа: настоящую причину нашли, только сняв панель руками через
tmux.

## Сценарий проверки

Агентский. Выкат devkit это пересборка бинарей в `~/go/bin`, поэтому шаги
гоняют установленный `agentctl`. Единственное, что шаги меняют на машине, это
снимок `~/.devkit/quota.local` на шаге 2, и его перезапись свежими данными и
есть работа проверяемой команды; остальные шаги живут во временных каталогах.

1. Юниты: `cd ~/projects/devkit/agentctl && go test -count=1 ./...` завершается
   кодом 0. Там же гоняются живые образцы: панель 2.1.220 целиком и её
   недорисованный кадр, старые панели с бакетом Opus, три экрана клиента
   (строка ввода, диалог доверия каталогу, мастер первого запуска).
2. Живая панель: `agentctl quota refresh` из каталога, которому клиент уже
   доверяет (например, `~/projects/devkit`), завершается кодом 0 и печатает
   обе строки, `week_all:` и `week_fable:`, с процентами и датой сброса. Важно
   именно «обе»: снимок с одним общим бакетом это отдельный дефект, панель
   приезжает не одним кадром, и дорогой бакет дорисовывается позже. До правки
   команда падала кодом 1 с «панель /usage не узналась».
3. Чтение записанного: `agentctl quota` завершается кодом 0 и печатает те же
   два бакета со статусами, то есть снимок читается тем же форматом, каким
   записан.
4. Отказы в чистом окружении, настройки клиента при этом не трогаются:

   ```sh
   before=$(shasum ~/.claude.json | cut -d' ' -f1)
   fresh=$(mktemp -d)/proj && mkdir -p "$fresh"
   (cd "$fresh" && agentctl quota refresh); echo "свежий каталог, код: $?"
   h=$(mktemp -d) && mkdir -p "$h/proj"
   (cd "$h/proj" && HOME="$h" agentctl quota refresh); echo "чистый HOME, код: $?"
   [ "$before" = "$(shasum ~/.claude.json | cut -d' ' -f1)" ] && echo "настройки клиента не тронуты"
   ```

   Ждём: из свежего каталога отказ кодом 1 со словами «доверие каталогу», из
   чистого HOME отказ кодом 1 со словами «мастер первого запуска», и последняя
   строка про нетронутые настройки. Сверка `~/.claude.json` тут не украшение:
   на этих экранах Enter подтверждает подсвеченный пункт, и совпадение
   контрольной суммы означает, что refresh в них ничего не нажал.
5. Лестница трат на подложенном снимке, ничего настоящего не трогая:

   ```sh
   tmp=$(mktemp -d) && mkdir -p "$tmp/home/.devkit" "$tmp/repo/docs"
   printf '# проверка (префикс T)\n\n## In progress\n\n| ID | Задача | Тип | P | R | Цена | Ссылка |\n|--------|--------|-----|---|---|------|--------|\n| T-001 | проверка лестницы трат | task | P2 | 30 (25+3+1+0+1) | M | - |\n' > "$tmp/repo/docs/TASKS.md"
   r=$(date -v+3d '+%Y-%m-%dT%H:%M')
   snap() { printf 'taken = %s\nweek_all = %s%% сброс %s\n%s = %s%% сброс %s\n' "$(date '+%Y-%m-%dT%H:%M')" "$1" "$r" "$2" "$3" "$r" > "$tmp/home/.devkit/quota.local"; }
   snap 5 week_fable 5   && HOME="$tmp/home" agentctl -C "$tmp/repo" pick T-001
   snap 50 week_fable 5  && HOME="$tmp/home" agentctl -C "$tmp/repo" pick T-001
   snap 95 week_fable 50 && HOME="$tmp/home" agentctl -C "$tmp/repo" pick T-001
   snap 50 week_opus 95  && HOME="$tmp/home" agentctl quota && HOME="$tmp/home" agentctl -C "$tmp/repo" pick T-001
   ```

   Ждём четыре исхода подряд. Профицит обоих бакетов поднимает вердикт до
   `model: fable` с хвостом «корректор: профицит week_all, week_fable,
   opus -> fable». Профицит одного `week_fable` при общем бакете в норме уже
   не поднимает: вердикт остаётся `model: opus` без хвоста корректора. Дефицит
   `week_all` опускает до `model: sonnet` с хвостом «корректор: дефицит
   week_all, opus -> sonnet». Старый снимок с `week_opus` читается, в выводе
   `quota` бакет идёт с процентом, статусом «дефицит» и пометкой «лестницу
   трат не задаёт», а вердикт остаётся `model: opus` без хвоста корректора.

## Ход работы

- Исполнение: субагент opus/high по вердикту pick, 2026-07-30.
- Образец панели снят живьём с клиента 2.1.220 командой из постановки, экран
  входа не помешал: `agentctl/testdata/usage-panel-fable.txt` это настоящий
  вывод `capture-pane` целиком, с промо-строкой и подсказками внизу.
- Парсер: секция Fable узнаётся отдельным бакетом `week_fable`, обязательным
  остался только `week_all`. Заодно закрыты две дыры, которые новая панель
  открыла: за заголовок секции теперь считается только строка со словом
  «current» (иначе им притворяются промо «+50% weekly limits promo» и
  подсказка «w to week»), а процент берётся только со строки полоски («41%
  used»), иначе в бакет уезжает процент промо. Бакет без прочитанного
  процента стал отказом: молчаливый ноль читается как нетронутый бакет, то
  есть как профицит.
- Лестница трат пересобрана как в постановке: opus тратит только из
  `week_all`, у fable своя пара с `week_fable`. Сдвиг вниз с opus срабатывает
  теперь там же, где с sonnet на haiku. Ключ `week_opus` остался известным
  ради старых снимков: такой снимок читается без предупреждений и виден в
  `agentctl quota`, но вердикт больше не двигает. Это осознанная потеря для
  машин со старым клиентом, зафиксирована в LLD DK-010.
- По ходу нашлась вторая причина, по которой refresh падал, и без неё правка
  парсера пользователю не видна: команда набиралась, как только в панели
  появлялся хоть какой-то текст, то есть до строки ввода, и пропадала без
  следа, а refresh потом ждал панель, которую никто не открывал. Из свежего
  каталога (worktree задачи) это воспроизводилось каждый раз.
- Регрессия проверена механически: `regcheck --base main -- sh -c 'cd agentctl
  && go test ./...'` даёт «тест краснеет на main и проходит на текущем коде»,
  отдельно то же по `TestParseUsagePanel`, `TestCorrectModel` и
  `TestTierBuckets`.

После ревью (исходы построчно в разделе «Ревью»):

- Признак строки ввода доведён до строгого. Первая правка считала готовностью
  любую сплошную линейку, а ею начинается и диалог доверия каталогу: команда
  уходила в модалку, Enter подтверждал подсвеченное «Yes, I trust this
  folder», то есть менял настройки пользователя, и только потом refresh врал
  отказом про неузнанную панель. Теперь строка ввода узнаётся рамкой (непустая
  строка между двумя линейками), диалог доверия и мастер первого запуска
  узнаются поимённо и дают отказ с подсказкой, что сделать руками, а Enter
  отправляется только после того, как набранное `/usage` видно в панели: на
  незнакомом экране он не нажмётся вовсе. Проверено на свежем каталоге и на
  чистом HOME, `~/.claude.json` при этом не меняется.
- Снимок больше не пишется по первому успешному разбору. Панель приезжает не
  одним кадром: съёмка с шагом 100 мс показала, что кадры со второго по пятый
  несут только `week_all` со строками про пересчёт, а дорогой бакет приходит
  примерно через полсекунды, и первый опрос (400 мс) попадал ровно в это окно.
  Теперь полная панель принимается сразу, а панель с одним общим бакетом
  должна продержаться три секунды: такая панель бывает и настоящей (свой
  тариф, своя версия клиента), поэтому отказом её считать нельзя.
- Подъём на ярус вверх требует профицита всех бакетов яруса выше, а не одного
  добавочного: иначе `opus -> fable` решался бы по одному `week_fable` при
  общем бакете у самой границы дефицита. `extraBuckets` за ненадобностью
  убран, отличие от правила 3 исходного дизайна записано в LLD DK-010.
- `agentctl quota` помечает бакет, из которого никакой ярус не тратит:
  «week_opus: ... дефицит (лестницу трат не задаёт, панель его больше не
  показывает)». Без пометки вывод обещал сдвиг, которого не будет.
- README предупреждает про промо на недельные лимиты: проценты панель считает
  от увеличенного лимита, и в день окончания промо та же трата станет большей
  долей без всякого расхода, а корректор честно съедет вниз.
- Живые образцы экранов клиента (строка ввода, диалог доверия, мастер первого
  запуска) и недорисованного кадра панели легли в `agentctl/testdata`, на них
  же держатся тесты. Краснота проверена возвратом прежнего признака:
  `TestPaneReady` падает на `pane-trust-dialog.txt`.

## Ревью

- refresh пишет неполный снимок: панель приезжает не одним кадром, секция Fable дорисовывается позже, и waitPane принимает первый успешный разбор, поэтому в снимок вероятно попадает один week_all без week_fable, молча и без предупреждения: исправлено, первый успешный разбор больше не пишется как есть: panelWaiter принимает панель с дорогим бакетом сразу, а одинокий week_all только если тот продержался usagePartialGrace (3s); закреплено юнитом TestPanelWaiter на живом недорисованном кадре usage-panel-partial.txt
- paneReady принимает за строку ввода любую сплошную линейку, поэтому на диалоге доверия каталогу и на мастере первого запуска refresh набирает /usage в модалку и жмёт Enter, молча подтверждая доверие каталогу, а затем врёт отказом про неузнанную панель: исправлено, признак строки ввода стал структурным (непустая строка между двумя сплошными линейками), диалог доверия и мастер первого запуска узнаются поимённо и дают человеческий отказ, а Enter теперь уходит только после того, как набранное /usage видно в панели; на свежем каталоге и чистом HOME refresh отказывает за секунду и ~/.claude.json не меняется (сверено по shasum)
- TestPaneReady собран из головы и проверяет только порог длины линейки: ни одного живого экрана клиента, который рамку содержит, но ввод не принимает, в наборе нет, поэтому тест зелёный и при дефекте выше: исправлено, тест переписан на живые образцы клиента 2.1.220: pane-ready.txt, pane-trust-dialog.txt, pane-first-run.txt в testdata; краснота проверена возвратом прежнего признака, тест падает на pane-trust-dialog.txt; отдельным юнитом TestPaneBlocker закрыты тексты отказов
- в README нет предупреждения про промо +50% weekly limits: проценты считаются от увеличенного лимита, и в день окончания промо процент скакнёт вверх без расхода, а корректор съедет вниз; требование постановки не закрыто: исправлено, в README добавлен абзац про промо: проценты меряются от увеличенного лимита, в день окончания промо та же трата станет большей долей без расхода, и корректор честно съедет вниз, поэтому снимок вокруг этой даты стоит переснять
- README описывает несуществующее поведение refresh фразой про ожидание строки ввода, описание надо согласовать с настоящим признаком готовности: исправлено, раздел про refresh в README переписан под то, что в коде: строка ввода узнаётся рамкой из двух линеек, Enter уходит только после эха набранного, панель с одним общим бакетом выдерживается три секунды; три осторожных места перечислены списком с причиной каждого
- agentctl quota печатает week_opus наравне с рабочими бакетами, хотя вердикт он больше не двигает: нужна пометка строкой, что бакет известен, но лестницу трат не задаёт: исправлено, quota печатает такой бакет с пометкой «лестницу трат не задаёт, панель его больше не показывает», пометка выбирается раньше пометки про старый профицит; закреплено подтестом TestCmdQuota, который заодно следит, что на рабочий бакет она не уезжает
- сдвиг opus -> fable смотрит только week_fable, поэтому подъём на верхний ярус возможен при week_all у самой границы дефицита: либо требовать профицит всей пары, либо зафиксировать выбор в LLD DK-010 и закрепить тестом: исправлено, выбран первый вариант: вверх двигает профицит всех бакетов, из которых будет тратить ярус выше, extraBuckets убран за ненадобностью; opus -> fable требует профицита week_all и week_fable сразу, для нижних пар это прежний week_all; закреплено кейсами про профицит обоих, про один только week_fable и про week_all у самой границы дефицита (74% в середине окна), отличие от дизайна записано в LLD DK-010
- поле кейса dear в quota_test.go по смыслу ключ бакета, читается как опечатка: исправлено, поле переименовано в key
