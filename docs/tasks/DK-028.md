# DK-028: devkitctl doctor: разбор taken берёт первую строку с = и молча принимает снимок из будущего

## Что происходит

Доктор мерит возраст снимка квоты по строке taken. Разбор в `quota_taken`
(tools/devkitctl/devkitctl.py) отвечает первой встреченной строкой taken: если
она не разобралась как время, функция сразу отдаёт None, даже когда ниже в
снимке лежит разобранная. Снимки заполняют и руками, writer agentctl кладёт их
тем же форматом, поэтому строк taken в файле бывает несколько, и читатели
расходятся: agentctl берёт последнюю (quota.go перезаписывает момент на каждой
строке taken), доктор первую.

Возраст check_quota сравнивает только с порогом протухания вверх. Снимок,
снятый «в будущем» после разошедшихся часов, даёт отрицательный возраст и
проходит молча. В pick такое предупреждение стоит («часы разошлись, ...
переснять: agentctl quota refresh»), у доктора его нет.

## Чего хотим

Доктор разбирает снимок как agentctl: последняя разобранная строка taken
выигрывает, неразобранная строка выше не глушит разобранную ниже. Снимок из
будущего становится находкой доктора словами про разошедшиеся часы и
переснятие, проверка протухания от этого не меняется.

## DoD

- Снимок с моментом снятия в будущем даёт находку доктора, тест держит.
- Снимок с несколькими строками taken разбирается последней разобранной,
  тест держит и неразобранную выше разобранной, и наоборот.

## Ранг

`0+2+0+5+1 = 8`, P3.

- Серьёзность 0: снаружи ничего не меняется, страдает только честность
  находок доктора.
- Ценность 2: снимок квоты пишет каждый refresh конвейера, расхождение
  читателей всплывает на первом же снимке с правкой руками.
- Неопределённость 0: правка локальна, поведение go-стороны задано кодом и
  тестом pick.
- Поправка на баг 5: молчаливый приём снимка из будущего подтверждён кодом
  check_quota.
- Рычаг 1: тот же разбор обслуживает порог протухания снимка.

## Сценарий проверки

Сценарий агентский, гоняется обкаткой из корня дерева и повторяется после
слияния. Поломку на старой механике не воспроизвести. Разбор и тест живут
в одном дереве. Краснота на старом коде доказана прогонами regcheck, след
в «Ходе работы». Шаги ниже показывают правленную механику на снимках-имитатах
во временном доме. Покрыты момент из будущего, пара строк taken в обе
стороны и нижняя разобранная строка, управляющая проверкой протухания.
Каждая строка блока это отдельный шаг под своим `sh -c`.

```sh
rm -rf /tmp/dk028 && mkdir -p /tmp/dk028/.devkit/quota && printf 'taken = 2030-01-01T00:00\nweek_all = 40%% сброс 2030-01-01T00:00\n' > /tmp/dk028/.devkit/quota/claude-code.local && HOME=/tmp/dk028 python3 tools/devkitctl/devkitctl.py doctor . | grep -F 'часы разошлись'
out=$(HOME=/tmp/dk028 python3 tools/devkitctl/devkitctl.py doctor . || true) && ! printf '%s\n' "$out" | grep -qF 'claude-code.local протух'
printf 'taken = вчера\ntaken = %s\nweek_all = 40%% сброс 2030-01-01T00:00\n' "$(date '+%Y-%m-%dT%H:%M')" > /tmp/dk028/.devkit/quota/claude-code.local && out=$(HOME=/tmp/dk028 python3 tools/devkitctl/devkitctl.py doctor . || true) && ! printf '%s\n' "$out" | grep -qF 'не разобран момент снятия' && ! printf '%s\n' "$out" | grep -qF 'claude-code.local'
printf 'taken = вчера\ntaken = %s\nweek_all = 40%% сброс 2030-01-01T00:00\n' "$(date -v-2H '+%Y-%m-%dT%H:%M')" > /tmp/dk028/.devkit/quota/claude-code.local && HOME=/tmp/dk028 python3 tools/devkitctl/devkitctl.py doctor . | grep -F 'claude-code.local протух (возраст'
printf 'taken = %s\ntaken = вчера\nweek_all = 40%% сброс 2030-01-01T00:00\n' "$(date '+%Y-%m-%dT%H:%M')" > /tmp/dk028/.devkit/quota/claude-code.local && out=$(HOME=/tmp/dk028 python3 tools/devkitctl/devkitctl.py doctor . || true) && ! printf '%s\n' "$out" | grep -qF 'claude-code.local' && rm -rf /tmp/dk028
```

Ожидание. Момент снятия в будущем даёт находку про разошедшиеся часы и не
считается протухшим. Из двух строк taken побеждает последняя разобранная.
Неразобранная сверху не глушит свежую снизу. Неразобранная снизу не отбирает
момент у свежей сверху. Возраст считается по нижней разобранной строке, даже
когда выше стоит неразобранная.
