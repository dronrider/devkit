# DK-032: подключение машины к devkit одной командой: хуки в settings.json и глобальные правила

Проявилось на DK-019, когда появился четвёртый хук Claude Code. Раскладка
проектного контура доведена до одной команды (`devkitctl new`, дальше
`doctor --fix`), а машинный контур на этом фоне остался наполовину ручным.
Пока devkit стоит на одной машине, это незаметно: всё прописано давно. Стоит
дать репозиторий второму человеку, и он получает обвязку, которая тихо
работает вполовину.

Что сейчас требует рук.

1. Хуки Claude Code в `~/.claude/settings.json`. Доктор их проверяет и находку
   печатает, но `--fix` не прописывает: считалось, что структура settings.json
   у каждого своя и лезть туда нельзя. Для трёх PostToolUse-хуков это стоило
   терпеть, для четвёртого уже нет. Сама правка ровно того класса, который
   `--fix` и делает: additive-слияние в массив по событию, дедупликация по
   строке команды, повторный прогон ничего не меняет. Чужие хуки при этом не
   трогаются, а разошедшуюся с devkit команду (свой путь, свои флаги) честнее
   оставить находкой, как это уже сделано для определений агентов.
2. Глобальные правила. `~/.claude/CLAUDE.md` с импортом `RULES.md` доктор не
   проверяет вовсе, хотя без него правила не подгружаются нигде, кроме
   подключённых проектов. Новый человек об этом узнает не из диагностики, а из
   README, если дочитает.

Что автоматике не по силам, остаётся находкой с командой: Go и tmux ставит
пакетный менеджер, снимок квоты снимается `agentctl quota refresh` (после
DK-019 его освежает хук, но первый снимок всё равно чей-то).

Открытые вопросы к реализации: писать в `settings.json` или в
`settings.local.json` (у Claude Code свои приоритеты слияния), и как вести
себя, когда файла нет вовсе.

Дока: `devkitctl/README.md` (что умеет `--fix`), `hooks/README.md` (сейчас там
JSON для ручной вставки, после правки он становится справкой, а не
инструкцией), корневой `README.md` (раздел про раскладку машинного контура).
