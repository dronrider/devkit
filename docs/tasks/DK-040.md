# DK-040: agentctl run: делегирование native/cli/none с ограничителем вложенности

## Ход работы

- Исполнение: субагент opus/medium по вердикту pick (квота: week_all 63%, снимок 43м назад, сдвига нет), 2026-08-08.

## Разбор

`pick` считает вердикт и на этом кончается: применяет его человек либо
диспетчер, а на харнесе без своего спавна применить некому вовсе. `run` это
недостающая половина. Печатает он ровно те же строки, что pick (вердикт
считается одним вызовом, второй раз резолвить харнес нельзя, иначе делегирование
ушло бы не туда, куда сказала строка `via`), а дальше работу забирает режим
`[delegate]` **харнеса назначения ступени**, а не активного: платит подпиской
тот, чьё имя стоит в `via`, ему и исполнять (DK-090, раздел «Делегирование: run
отдаёт работу харнесу назначения»).

Раскладка исходов такая:

| Режим харнеса назначения | Ступень домашняя | Ступень уехавшая |
|---|---|---|
| `native` | инструкция диспетчеру, выход 0 | отказ выходом 3 |
| `cli` | подпроцесс, код выхода наружу | подпроцесс, код выхода наружу |
| `none` | «делегировать нечем», выход 3 | то же самое |

Пара «уехавшая плюс native» отказная по построению: `native` значит, что спавн
субагента есть только внутри сессии самого инструмента, снаружи дёрнуть его
нечем. Код 3 у обоих отказов: скрипт поверх run не должен принять «нечем» за
сделанную работу, а от ошибок самого run (нет задачи, битый профиль, вложенный
запуск) отказ отличается тем, что те выходят единицей.

Ограничитель вложенности стоит первым, до чтения доски: подпроцесс это
полноценная сессия, она читает те же правила, а правила велят делегировать через
run, и без рубежа вышла бы воронка сессий, то есть потраченная подписка.
Подпроцессу ставятся `DEVKIT_RUN_DEPTH=1` и `DEVKIT_HARNESS` харнеса назначения
(детект по переменным родителя в гнезде сессий неоднозначен по построению, а для
второй подписки это буквально тот же клиент). Промпт вдобавок говорит
исполнителю, что он исполнитель, но текстовая просьба это не рубеж, рубеж это
переменная.

Снимок квоты освежается у харнеса-исполнителя, а не у активного, и отцепленно:
вердикт к этому моменту посчитан и напечатан, свежий снимок нужен сессии
подпроцесса и следующему запуску, а ждать съёма делегированию незачем. Замок
взят тот же, что у SessionStart-хука (`~/.devkit/quota-refresh.lock`): съём
поднимает клиента, старт которого дёргает тот же хук.

## Принятые решения

Развилки, которых нет ни в DK-033, ни в DK-090:

- **Рабочая директория приходит флагом `--workdir`, по умолчанию это корень
  проекта.** Дизайн говорит «рабочая директория задачи», а откуда run её берёт,
  не говорит. Искать worktree по имени ветки значит зашить соглашение shipctl в
  agentctl и развалиться на первом же чужом; путь дерева знает тот, кто дерево
  заводил, ему и передавать. Несуществующая директория это отказ до вердикта:
  подпроцесс, поднятый неизвестно где, хуже честной ошибки.
- **Прочерк в строке `via` это тот же отказ выходом 3.** Ненастроенная машина
  ярус не разворачивает, исполнителя вердикт не назвал, и делегировать
  действительно нечем. Ошибкой (единицей) это делать не стал: сам run исправен,
  и вердикт он печатает целиком, ярусная его половина от инструмента не зависит.
- **Нечисловое значение `DEVKIT_RUN_DEPTH` считается взведённым ограничителем**,
  а ноль и пустая строка его отсутствием. Молча пропустить непонятное значение
  тут дороже, чем отказать: цена ошибки это воронка сессий.
- **Подстановка плейсхолдеров идёт внутри элемента команды, незнакомая фигурная
  скобка остаётся как есть.** Подстановка внутри нужна ради `--model={model}`, а
  отказывать на незнакомой скобке нельзя: в аргументах чужого инструмента живут
  и JSON, и его собственные шаблоны.
- **Подпроцесс, убитый сигналом, отдаёт наружу код 1.** Кода выхода у него нет,
  а минус единица обернулась бы в 255 и читалась бы как чужой код возврата;
  причина при этом называется строкой в stderr.
- Ключ `bin` машинного слоя run не трогает: команду целиком объявляет шаблон
  профиля, и подмена нулевого аргумента без спроса профиля была бы вторым местом,
  где решается, чем поднимать инструмент. Понадобится, поедет вместе с профилем
  glm-code (DK-180).

Границы: ключи `home` и `env` машинного слоя с подстановкой в окружение
подпроцесса это DK-178, профиль glm-code это DK-180. Здесь окружение подпроцесса
это унаследованное плюс две переменные devkit.

## Сценарий проверки (агентский)

Контур синтетический: временный HOME, фейковый devkit с профилями харнесов и
настоящими определениями агентов, фейковая доска с одной задачей. Живого клиента
не поднимается ни разу, режим `cli` дёргает `/bin/sh` с echo, как советует
DK-033.

1. Собрать контур: `$H/devkit/kit/harness/` с тремя профилями (`fakecli` с
   `mode = "cli"` и командой-эхом, `fakenative` с `mode = "native"`, `fakenone` с
   `mode = "none"`), `$H/devkit/kit/agents/` копией из репозитория, `$H/.devkit/harness.local`
   с `enabled`, `default` и секцией маппинга, проект с `docs/TASKS.md` (строка
   DK-901, цена S, неопределённость 0) и пустым файлом задачи.
2. `HOME=$H DEVKIT_HOME=$H/devkit agentctl -C $P run DK-901 --workdir $P/work`
   при `default = "fakecli"`: жду вердикт, строку про подпроцесс, вывод самого
   подпроцесса с `depth=1`, `harness=fakecli` и рабочей директорией дерева, а в
   промпте первую строку настоящего определения `exec-low`.
3. То же с `DEVKIT_RUN_DEPTH=1`: жду отказ про вложенное делегирование и код 1,
   вердикт при этом не печатается вовсе.
4. `default = "fakenative"`: жду инструкцию диспетчеру спавнить субагента и код 0.
5. `default = "fakecli"`, но `mini = "fakenative:чужая"`: жду отказ про пару
   «уехавшая ступень плюс native» и код 3.
6. `default = "fakenone"`: жду «делегировать нечем» с именем харнеса и код 3.
7. Команда-эхо с `exit 7` и флаг `--record`: жду код возврата 7 наружу и строку
   исполнения словом «подпроцесс» в файле задачи.

### Обкатка 2026-08-08

Шаг 2, подпроцесс с окружением и промптом:

```text
model: дешёвая
effort: low
tier: mini
via: fakecli
DK-901 (task, цена S, неопределённость 0): совсем атомарная правка с очевидным подходом, дешёвой модели хватает; у харнеса fakecli секция [quota] пуста, снимать остаток нечем, вердикт идёт без корректора
делегирование: cli (харнес fakecli, профиль .../kit/harness/fakecli.toml), подпроцесс /bin/sh в .../proj/work
ЭТО ПОДПРОЦЕСС: модель=дешёвая effort=low depth=1 harness=fakecli
рабочая директория: .../proj/work
первая строка промпта: Ты исполнитель задачи доски `docs/TASKS.md`. Работаешь по правилам репозитория
код возврата: 0
```

Шаг 3, ограничитель (вердикт не напечатан, отказ пришёл до работы):

```text
ошибка: вложенное делегирование запрещено: эту сессию подняли через run (DEVKIT_RUN_DEPTH=1), и делегировать дальше нельзя, иначе выйдет воронка сессий; задачу DK-901 исполняй сам
код возврата: 1
```

Шаг 4, native дома:

```text
делегирование: native (харнес fakenative, профиль .../kit/harness/fakenative.toml)

```

Шаг 5, уехавшая ступень плюс native (в вердикте видно `via: fakenative` и хвост
про чужую подписку):

```text
делегировать нечем: ступень mini уезжает в fakenative, а он делегирует режимом native, то есть спавном субагента внутри своей же сессии, и снаружи дёрнуть его нечем; либо сменить назначение яруса в .../.devkit/harness.local, либо исполнять задачу сессией fakenative
код возврата: 3
```

Шаг 6, none:

```text
делегировать нечем: харнес fakenone объявил delegate.mode = "none" (профиль .../kit/harness/fakenone.toml), ни субагента, ни команды у него нет; задачу исполняет тот, кто это умеет
код возврата: 3
```

Шаг 7, код подпроцесса наружу и запись в файле задачи:

```text
код возврата: 7
- Исполнение: подпроцесс дешёвая/low по вердикту pick (квота: объявления нет, корректор выключен), 2026-08-08.
```

Тесты: `GOWORK=off go test ./...` в `tools/agentctl` зелёный (24с), новый файл
`run_test.go` держит подпроцесс с окружением, код возврата, три отказа, оба
ограничителя, замок съёма и подстановку плейсхолдеров.

Тест на команде вида ["/bin/sh", "-c", "kill -TERM $$"] воспроизводит её без труда (проверено руками: код 1 и строка в stderr совпадают с ожиданием). Добавить в run_test.go рядом с TestRunCLIExitCode.
