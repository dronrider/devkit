# DK-041: хуки: разбор входа по имени протокола, следы ходовых ассистентов в check-commit

Задача серии универсального кита, дизайн в
[DK-033](../lld/DK-033-universal-kit.md), раздел «Хуки и проверки текстов»
(состав задачи п. 6 плана работ, тесты и дока в своих разделах того же
документа). Профиль харнеса из DK-036 уже лежит в `harness/claude-code.toml`,
ключи `[hooks] protocol` и `memory_index` там описаны, читателя у них пока нет.

Что делает задача:

- заводит `hooks/hookio.py` таблицей разборщиков входа: функция на протокол,
  вход это stdin события, выход это фрагменты «путь, записанный текст» плюс
  канал ответа. Каждая проверка импортирует таблицу, своего разбора не носит;
- переводит `--hook` на аргумент с именем протокола (`--hook claude-code`).
  Голый `--hook` остаётся псевдонимом claude-code, иначе прописанные на машинах
  команды в settings.json сломаются об обновление devkit;
- `check-commit.py` перестаёт ловить следы одного ассистента: к
  `noreply@anthropic` добавляются адреса и подписи ходовых остальных, перечень
  снимается с их реальных коммитов при реализации;
- `check-memory.py` берёт путь индекса из `[hooks] memory_index`, а без ключа
  проверка не подключается: у инструмента без памяти находки про индекс это шум;
- `notify.py` берёт разбор входа из той же таблицы по имени протокола.

Тесты: `hooks/testdata/<протокол>/` с живьём снятыми JSON событий, `test.sh`
прогоняет каждый образец через каждую проверку, голый `--hook` эквивалентен
`--hook claude-code`. Протокол без образцов в таблицу не принимается.

Дока: `hooks/README.md`, раздел про `--hook <протокол>`, таблица разборщиков и
образцы.

## Ход работы

- Исполнение: субагент opus/medium по вердикту pick (маппинг sonnet, корректор: профицит week_all), 2026-08-02.
- Появился `hooks/hookio.py`: таблица разборщиков (протокол, разбор записи,
  разбор события сессии, канал ответа), имя протокола из аргумента `--hook`,
  чтение профиля харнеса ради `[hooks] memory_index`. Все четыре хука
  (`check-symbols`, `check-memory`, `check-sensitive`, `notify`) своего разбора
  больше не носят и берут вход оттуда.
- `check-commit.py` ловит след не одного ассистента: перечень `ASSISTANTS`
  снят с реальных коммитов на github (Claude Code, Codex двумя адресами,
  Cursor, aider, OpenHands, Devin, Copilot, Jules), родовые `co-authored-by` и
  `generated with` остались рядом.
- Образцы `hooks/testdata/claude-code/` сняты живьём: запись четырьмя
  инструментами, ввод пользователя, конец хода, субагент и запрос разрешения.
  Как они снимаются, описано в `hooks/testdata/README.md`.
- Тесты: юниты разбора в `hooks/hookio_test.py`, в `test.sh` прогон каждого
  образца через каждую проверку и через уведомитель, равенство голого `--hook`
  именованному, отказ на незнакомом протоколе, перечень подписей ассистентов и
  путь индекса памяти из профиля (свой `DEVKIT_HARNESS_DIR`). По правке
  прогнаны типовые мутации: выпавший ключ `content`, уехавший псевдоним голого
  `--hook`, код канала ответа, потерянный текст субагента, пропавшая ось ввода
  пользователя, зашитый мимо профиля путь индекса, снятая проверка на пустой
  ключ, выпавшие подписи Cursor и Copilot, снятый пропуск `testdata`, снятый
  фильтр путей доски. На каждой краснеет хотя бы один тест.
- Ветка отребейзена на main с DK-072, DK-018 и DK-056; правки разошлись по
  файлам, конфликтов не было. Появившийся с DK-072 `check-exec-bit.py` смотрит
  только семейство `test.sh`, так что новых файлов задачи он не касается и на
  них молчит; бит x выставлен `hookio_test.py` по соседнему `notify_test.py`,
  а `hookio.py` остался без него, как и другой импортируемый сосед
  `check-commit.py`.
- Отличия от дизайна выписаны в LLD, раздел «Отличия реализации от дизайна»:
  хвост пути вместо полного у `memory_index`, отказ на незнакомом протоколе,
  `DEVKIT_HARNESS_DIR`, снятие образцов двумя способами, `last_assistant_message`
  у конца хода и вставка пути при загрузке `notify.py` доктором.

## Проверка

Сценарий агентский: всё выполнимо с машины агента, итог виден по кодам возврата
и строкам вывода, на проде ничего не меняется. Прогоняется из основного чекаута
после слияния (`cd ~/projects/devkit`).

1. Самопроверки:

   ```sh
   sh hooks/test.sh          # хуки в порядке
   sh devkitctl/test.sh      # devkitctl в порядке
   ```

2. Прописанные на машинах команды не сломались: голый `--hook` работает как
   `--hook claude-code`, а незнакомое имя это отказ со строкой про разбор.

   ```sh
   dash=$(printf '\342\200\224')
   ev='{"tool_input":{"file_path":"x.md","new_string":"тире '"$dash"' тут"}}'
   printf '%s' "$ev" | python3 hooks/check-symbols.py --hook; echo "голый --hook: $?"
   printf '%s' "$ev" | python3 hooks/check-symbols.py --hook claude-code; echo "--hook claude-code: $?"
   printf '%s' "$ev" | python3 hooks/check-symbols.py --hook кодекс; echo "--hook кодекс: $?"
   python3 hooks/check-symbols.py --hook < hooks/testdata/claude-code/write-write.json; echo "живой образец: $?"
   ```

   Ожидание: первые два прогона печатают находку и дают 2, третий печатает
   `разбор входа протокола кодекс не заведён, известны: claude-code` и даёт 2,
   живой образец записи проходит нулём.

3. След чужого ассистента ловится:

   ```sh
   printf 'docs: правка от cursoragent@cursor.com\n' > /tmp/msg
   git log -n 100 --format=%s | python3 hooks/check-commit.py /tmp/msg; echo "check-commit: $?"
   ```

   Ожидание: строка `след ассистента в тексте коммита` и код 1.

4. Путь индекса памяти берётся из профиля, а без ключа проверка молчит:

   ```sh
   h=$(mktemp -d); printf '[hooks]\nprotocol = "claude-code"\n' > "$h/claude-code.toml"
   ev='{"tool_input":{"file_path":"/a/memory/MEMORY.md","new_string":"проза без указателя"}}'
   printf '%s' "$ev" | DEVKIT_HARNESS_DIR="$h" python3 hooks/check-memory.py --hook; echo "профиль без ключа: $?"
   printf '%s' "$ev" | python3 hooks/check-memory.py --hook; echo "живой профиль: $?"
   ```

   Ожидание: на профиле без `memory_index` код 0 и ни строчки, на живом профиле
   находка `индекс памяти пухнет` и код 2.

Прогон шагов 2-4 в дереве задачи, повторён после ребейза на main с DK-072:
