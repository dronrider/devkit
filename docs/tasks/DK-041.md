# DK-041: хуки: разбор входа по имени протокола, следы ходовых ассистентов в check-commit

Задача серии универсального кита, дизайн в
[DK-033](../lld/DK-033-universal-kit.md), раздел «Хуки и проверки текстов»
(состав задачи п. 6 плана работ, тесты и дока в своих разделах того же
документа). Профиль харнеса из DK-036 уже лежит в `harness/claude-code.toml`,
ключи `[hooks] protocol` и `memory_index` там описаны, читателя у них пока нет.

Что делает задача:

- заводит `hooks/hookio.py` таблицей разборщиков входа: функция на протокол,
  вход это stdin события, выход это фрагменты «путь, записанный текст» плюс
  канал ответа. Каждая проверка импортирует таблицу, своего разбора не носит;
- переводит `--hook` на аргумент с именем протокола (`--hook claude-code`).
  Голый `--hook` остаётся псевдонимом claude-code, иначе прописанные на машинах
  команды в settings.json сломаются об обновление devkit;
- `check-commit.py` перестаёт ловить следы одного ассистента: к
  `noreply@anthropic` добавляются адреса и подписи ходовых остальных, перечень
  снимается с их реальных коммитов при реализации;
- `check-memory.py` берёт путь индекса из `[hooks] memory_index`, а без ключа
  проверка не подключается: у инструмента без памяти находки про индекс это шум;
- `notify.py` берёт разбор входа из той же таблицы по имени протокола.

Тесты: `hooks/testdata/<протокол>/` с живьём снятыми JSON событий, `test.sh`
прогоняет каждый образец через каждую проверку, голый `--hook` эквивалентен
`--hook claude-code`. Протокол без образцов в таблицу не принимается.

Дока: `hooks/README.md`, раздел про `--hook <протокол>`, таблица разборщиков и
образцы.
