# DK-050: taskctl batch: отбор кандидатов пачки

Дизайн в [DK-048](../lld/DK-048-batch-dispatcher.md), раздел «Отбор кандидатов:
taskctl batch».

## Ход работы

- Исполнение: субагент opus/medium по вердикту pick, 2026-08-02.
- Команда `batch` живёт в `taskctl/batch.go`, отказы группируются по причине в
  порядке, в котором причина впервые встретилась при обходе бэклога сверху
  вниз. На доске devkit это даёт ровно тот порядок групп, что в примере LLD.
- Типовые мутации прогнаны руками, каждую ловит хотя бы один тест: порог
  неопределённости сдвинут до 2, лимит off-by-one, прочерк цены принят за S,
  прочерк ссылки принят за серию, перестановка каждой из пяти соседних пар
  проверок (тип/цена, цена/неопределённость, неопределённость/зависимость,
  зависимость/ссылка, ссылка/лимит), обход всей доски вместо Backlog,
  зависимость в архиве считается незакрытой, пустая пачка молчит.
- По замечанию ревью в фикстуру добавлена XR-114 с открытой зависимостью и
  ссылкой отобранной задачи разом: без неё пара «зависимость / ссылка» была
  единственной, чью перестановку тесты пропускали.
- Ревью: субагент sonnet/high по вердикту pick, 2026-08-02.

## Сценарий проверки

Агентский: все шаги выполнимы с машины агента, итог проверяется выводом команд,
живая доска только читается.

1. Собрать бинарь и завести синтетическую доску во временной директории:

   ```sh
   cd taskctl && go build -o /tmp/taskctl-dk050 .
   d=$(mktemp -d)/proj; mkdir -p "$d/docs"
   ```

   В `$d/docs/TASKS.md` положить доску с пустыми In progress и Check и таким
   Backlog (в `$d/docs/TASKS-archive.md` шапка архива без строк):

   ```text
   | XR-001 | Ждёт соседа [после XR-003] | task | P3 | 16 (0+10+1+0+5) | S | - |
   | XR-002 | Дизайн | LLD | P3 | 13 (0+8+0+0+5) | S | (LLD рядом) |
   | XR-003 | Годная первая | task | P3 | 11 (0+5+1+0+5) | M | [tasks/XR-003.md](tasks/XR-003.md) |
   | XR-004 | Из той же серии | bug | P3 | 10 (0+5+0+0+5) | S | [tasks/XR-003.md](tasks/XR-003.md) |
   | XR-005 | Годная вторая | task | P3 | 9 (0+3+1+0+5) | S | - |
   | XR-006 | Годная, но лишняя | task | P3 | 8 (0+3+0+0+5) | S | - |
   ```

2. `/tmp/taskctl-dk050 -C "$d" batch --limit 2`. Ожидается код 0 и ровно такой
   вывод (прогнано 2026-08-02):

   ```text
   batch: XR-003, XR-005
   взято: XR-003 (task, M, неопр. 1), XR-005 (task, S, неопр. 1)
   ждут незакрытых зависимостей: XR-001
   тип LLD: XR-002
   ссылка та же, что у отобранной: XR-004 (как у XR-003)
   лимит пачки 2 исчерпан: XR-006
   одно приложение и пересечение по файлам доска не видит: сверить кандидатов по файлам задач, вторая страховка это предупреждение shipctl merge --train
   ```

3. `/tmp/taskctl-dk050 batch` из корня devkit. Ожидается код 0, первая строка
   вида `batch: DK-...` (состав зависит от доски дня), последняя строка про то,
   чего доска не видит, и чистый `git status --porcelain docs/TASKS.md`: отбор
   доску не трогает. Прогон 2026-08-02 дал первые две строки:

   ```text
   batch: DK-041, DK-051, DK-018, DK-056, DK-070
   взято: DK-041 (task, S, неопр. 1), DK-051 (task, S, неопр. 1), DK-018 (task, S, неопр. 1), DK-056 (task, S, неопр. 1), DK-070 (bug, S, неопр. 1)
   ```

4. `cd taskctl && go test ./...` зелёный.

## Ревью

- Тесты не ловят перестановку соседних проверок «зависимость / ссылка» (LLD п.5-6): своп case в switch cmdBatch (проверка ссылки раньше проверки зависимости) проходит весь go test ./... без единого красного, хотя раздел «Тесты» LLD и ход работы задачи заявляют покрытие порядка проверок мутацией. Нужен фикстурный ряд с одновременно открытой зависимостью и дублирующей ссылкой, ожидающий группу «ждут незакрытых зависимостей» (не «ссылка та же»).: исправлено
