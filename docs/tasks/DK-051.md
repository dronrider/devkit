# DK-051: agentctl budget: размер пачки из остатка лимитов

Задача серии [DK-048](../lld/DK-048-batch-dispatcher.md), дизайн в разделе
«Размер пачки: agentctl budget». Пересказывать его тут не надо: там и формат
вывода, и таблица потолка по ответу корректора, и объяснение, почему пачка
считается через `correctModel` на opus, а не в процентах лимита.

Что делается:

- команда `agentctl budget` без аргументов. Первая строка машинная (`batch: N`),
  её значение уходит в `taskctl batch --limit`; вторая называет бакет, темп и
  причину потолка;
- потолок берётся из ответа корректора на модели `opus`, по таблице дизайна:
  сдвиг вниз даёт 1, подъём на fable даёт 3, «не двигает» на свежем профиците
  `week_all` даёт 5, остальное 3;
- без снимка потолок не роняется, но хвост строки говорит, чем его снять
  (`agentctl quota refresh`), как это делает `pick`.

Тесты по разделу «Тесты» дизайна: фикстуры снимка с инжектированными часами,
границы pace, свежий профицит одного `week_all` против профицита `week_all` и
`week_fable` сразу, дефицит, протухший профицит, снимка нет, бакет за датой
сброса, битая строка снимка. Краснеющего прогона у задачи нет (нового кода
старая версия не знает), поэтому вместо него типовые мутации из `RULES.md`.

Дока: раздел про `budget` в `agentctl/README.md` (таблица по ответу корректора,
почему через `correctModel`, поведение без снимка и на протухшем, почему не в
процентах). Правку `RULES.board.md` про размер пачки не трогать, она уедет
задачей скилла DK-054 вместе с остальной процедурой.

## Сценарий проверки

Агентский: все шаги выполнимы с машины агента, итог проверяется первой
строкой вывода и кодом возврата, окружение синтетическое (временный `HOME`,
синтетический снимок квоты, профили из репозитория через `DEVKIT_HOME`),
живой контур шаги не трогают. Прогнан до перевода в Check через `go run .` на
ветке; после выката те же шаги идут собранным бинарём `agentctl` из PATH.

Общая заготовка для шагов 1-4 (снимок пишет python3, времена берутся от
текущего момента, чтобы сценарий не протухал):

```sh
cd ~/projects/devkit/agentctl   # после выката шаг не нужен, agentctl уже в PATH
h=$(mktemp -d) && mkdir -p "$h/.devkit/quota"
export HOME="$h" DEVKIT_HOME=~/projects/devkit DEVKIT_HARNESS=claude-code
snap() { python3 -c '
import sys, datetime
taken, all_pct, all_left_h, max_pct, max_left_h = sys.argv[1:6]
now = datetime.datetime.now()
fmt = "%Y-%m-%dT%H:%M"
with open(sys.argv[6], "w") as f:
    f.write("taken = " + (now - datetime.timedelta(minutes=int(taken))).strftime(fmt) + "\n")
    f.write("week_all = " + all_pct + "% сброс " + (now + datetime.timedelta(hours=int(all_left_h))).strftime(fmt) + "\n")
    if max_pct != "-":
        f.write("week_max = " + max_pct + "% сброс " + (now + datetime.timedelta(hours=int(max_left_h))).strftime(fmt) + "\n")
' "$@" "$h/.devkit/quota/claude-code.local"; }
```

1. Профицит одного `week_all` на свежем снимке поднимает потолок до пяти:

   ```sh
   snap 10 5 24 - 0
   go run . budget   # после выката: agentctl budget
   ```

   Первая строка `batch: 5`, вторая содержит `профиците на свежем снимке`.
   Код 0.

2. Тот же снимок, но профицит подхватил и `week_max`: тут же корректор
   поднимает opus до fable, и потолок падает обратно до трёх, а не растёт:

   ```sh
   snap 10 5 24 5 24
   go run . budget
   ```

   Первая строка `batch: 3`, вторая содержит `поднимает opus до fable`. Код 0.

3. Дефицит `week_all` роняет потолок до одной задачи в пачке:

   ```sh
   snap 10 90 84 - 0
   go run . budget
   ```

   Первая строка `batch: 1`, вторая содержит `дефицит week_all`. Код 0.

4. Снимка нет вовсе: потолок не падает, а держит значение по умолчанию, и
   строка называет команду, которой снимок снять:

   ```sh
   rm -f "$h/.devkit/quota/claude-code.local"
   go run . budget
   ```

   Первая строка `batch: 3`, вторая содержит `снимка квоты нет` и
   `agentctl quota refresh`. Код 0.

Прогнано вручную при подготовке ветки, все четыре шага совпали с ожидаемым.
Дополнительно на ветке зелёные `cd agentctl && go test ./...` и
`go vet ./...`.
