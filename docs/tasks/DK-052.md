# DK-052: taskctl: рубеж доски из worktree и идемпотентный file

## Ход работы

- Исполнение: субагент sonnet/high по вердикту pick, 2026-08-02.

Дизайн из `docs/lld/DK-048-batch-dispatcher.md` (разделы «Доска в руках
диспетчера» и «Тесты») реализован без отступлений: рубеж (`boardGuard` в
новом `taskctl/worktree.go`) на `add`, `move`, `set`, `close`, `sort`, `dep
add`, `dep rm`, `file`, `init`; `review add`/`review resolve` разрешены
везде, но `review add` из worktree не чинит ссылку в строке доски, а
печатает подсказку; `file` стала идемпотентной и возвращается раньше
`c.apply` на холостом ходу. Рубеж считается по корню (`root`), который
taskctl уже нашёл через `-C`, не по текущей директории.
- Ревью: субагент sonnet/high по вердикту pick, 2026-08-02.

## Сценарий проверки

Агентский: все шаги выполнимы с машины агента, каждый итог проверяется
объективно (код возврата, конкретная строка вывода), ничего не меняется на
проде (весь сценарий во временной директории с временным `HOME` и
синтетической доской). Обкатан вживую при исполнении задачи.

```sh
BIN=/tmp/dk052-check/taskctl   # или go build -o "$BIN" . из taskctl/
WORK=/tmp/dk052-check/main
WT=/tmp/dk052-check/wt
export HOME=/tmp/dk052-check/home
export DEVKIT_NOTIFY_OFF=1
mkdir -p "$WORK" "$HOME"

cd "$WORK" && git init -q -b main && git config user.email t@t && git config user.name t
"$BIN" init --prefix XR --name "Проверка DK-052"
"$BIN" add --title "Задача рубежа" --type task --rank "0+1+1+0+1" --link "x"
git add -A && git commit -q -m init

git worktree add -q -b dk-052-check "$WT"

# 1) изменяющая команда из линкованного worktree отказывает, доска не тронута
cd "$WT" && "$BIN" move XR-001 in-progress; echo "exit=$?"
git -C "$WT" status --porcelain docs   # пусто

# 2) -C на основной чекаут из того же worktree проходит (путь shipctl merge)
"$BIN" -C "$WORK" move XR-001 in-progress; echo "exit=$?"

# 3) review add из worktree пишет только файл задачи
"$BIN" review add XR-001 "проверка рубежа из worktree"
grep XR-001 "$WT/docs/TASKS.md"   # ссылка в строке не поменялась

# 4) идемпотентный file, в том числе с -m/--push
cd "$WORK"
"$BIN" file XR-001                                  # создаёт файл и ссылку
"$BIN" file XR-001; echo "exit=$?"                   # "уже есть и файл, и ссылка", exit=0
HEAD1=$(git rev-parse HEAD)
"$BIN" file XR-001 -m "docs(tasks): XR-001 файл" --push; echo "exit=$?"
[ "$(git rev-parse HEAD)" = "$HEAD1" ] && echo "коммит не создан"
```

Ожидаемый итог по шагам:

1. `move` из `$WT` падает с `exit=1` и текстом «...это линкованный worktree,
   доску правит только диспетчер в основном чекауте...»; `git status
   --porcelain docs` в `$WT` пустой.
2. `-C "$WORK" move` из процесса с cwd в `$WT` завершается `exit=0` строкой
   `XR-001: backlog -> in-progress`.
3. `review add` из `$WT` завершается успехом, пишет файл `docs/tasks/XR-001.md`
   в `$WT` и сообщением «...ссылку на docs/tasks/XR-001.md поправь в
   основном чекауте: taskctl file XR-001»; строка `XR-001` в `$WT/docs/TASKS.md`
   ссылку не меняет (там же, где до этого, «x»).
4. Первый `file` в `$WORK` создаёт файл и ссылку; второй вызов подряд (и без
   флагов, и с `-m`/`--push`) завершается `exit=0` строкой «у XR-001 уже
   есть и файл, и ссылка на него» и не создаёт нового коммита (`HEAD` до и
   после вызова с `-m`/`--push` совпадает).
