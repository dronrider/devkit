# DK-054: скилл board-batch, раскладка скиллов и ключ test в devkitctl

## Ход работы

- Исполнение: субагент opus/medium по вердикту pick, 2026-08-02.

Дизайн из `docs/lld/DK-048-batch-dispatcher.md` (разделы «Скилл board-batch» и
«Команда тестов») реализован тремя кусками. Первый это сам скилл новой
директорией `skills/board-batch/SKILL.md`: frontmatter с именем и описанием,
процедура из 11 шагов с точными командами, ветки процедуры, второй вход со
списком задач вручную и команда тестов из `.devkit/deploy.local`. Второй это
раскладка скиллов в devkitctl (`check_skills` рядом с `check_agent_defs`, тот же
канал доставки, тот же рубеж основного чекаута): не разложенный скилл и скилл,
разошедшийся с devkit, это находки доктора, а `--fix` кладёт и перекладывает.
Скиллом считается директория с `SKILL.md`, соседняя проза в `skills/` на машину
не уезжает. Третий это ключ `test`: болванка `devkitctl new` получает пустой
`test =`, `read_deploy` отдаёт его третьим значением, а пустой ключ ловится
находкой, как ловится пустой `deploy`. Разбор ключа в shipctl остался от DK-053
нетронутым.

Отступлений от дизайна нет.

Мутации, на которых обязан краснеть хоть один тест, прогнаны скриптом, каждая
поймана: раскладка скиллов по `*.md` вместо `*/SKILL.md` (посторонний markdown
уезжает как скилл), расхождение скилла с devkit не проверяется, `--fix` кладёт
скилл и из worktree ветки задачи, пустой `test=` перестал быть находкой, в
болванке нет ключа `test`, находка про `test` печатается при заполненном ключе,
`check_skills` не позван из машинного контура.
- Ревью: субагент sonnet/high по вердикту pick, 2026-08-02.

## Сценарий проверки

Агентский: все шаги выполнимы с машины агента, каждый итог проверяется
объективно (код возврата, конкретная строка вывода), на проде ничего не
меняется. Весь прогон идёт во временной директории с временным `HOME`, потому
что раскладка скиллов пишет в `~/.claude`, и живой `HOME` трогать нельзя.

```sh
BASE=/tmp/dk054-check
DK=${DK:-$HOME/projects/devkit}
WORK=$BASE/proj
export HOME=$BASE/home
rm -rf "$BASE"; mkdir -p "$HOME" "$WORK"
DKCTL=$DK/devkitctl/devkitctl.py
doc() { python3 "$DKCTL" doctor "$@" -C "$WORK" 2>/dev/null; }
skill=$HOME/.claude/skills/board-batch/SKILL.md

cd "$WORK"
git init -q -b main && git config user.email t@t && git config user.name t

echo "=== шаг 1: болванка выката с пустым test ==="
python3 "$DKCTL" new --prefix XX -C "$WORK" >/dev/null; echo "exit=$?"
grep -nE '^(deploy|test) =$' .devkit/deploy.local

echo "=== шаг 2: doctor на пустой машине ==="
doc | grep -E 'нет скилла|пустой test=' | cut -c1-100
[ -e "$HOME/.claude/skills" ] || echo "скиллов на машине нет"

echo "=== шаг 3: doctor --fix раскладывает скилл ==="
doc --fix | grep -E 'скилл board-batch положен|пустой test=' | cut -c1-100
diff -q "$skill" "$DK/skills/board-batch/SKILL.md" >/dev/null && echo "скилл совпал с devkit"

echo "=== шаг 4: расхождение с devkit ==="
printf '\nправка на машине\n' >> "$skill"
doc | grep -E 'скилл .*SKILL.md разошёлся' | cut -c1-100
grep -q 'правка на машине' "$skill" && echo "doctor без --fix скилл не тронул"
doc --fix | grep -E 'починено: скилл .*разошёлся' | cut -c1-100
grep -q 'правка на машине' "$skill" || echo "--fix переложил скилл из devkit"

echo "=== шаг 5: повторный --fix ничего не меняет ==="
doc --fix | grep -q 'починено' || echo "чинить нечего"

echo "=== шаг 6: вписанная команда тестов снимает находку ==="
printf 'deploy = true\ntest = go test ./...\nautonomous = false\n' > .devkit/deploy.local
doc | grep -q 'пустой test=' || echo "находки про пустой test больше нет"
```

Ожидаемый итог по шагам:

1. `new` проходит с `exit=0`, и в болванке есть обе пустые строки, `deploy =` и
   `test =`.
2. Доктор на пустой машине печатает находку «нет скилла
   .../board-batch/SKILL.md» и находку про пустой `test=`, а директории
   `~/.claude/skills` ещё нет вовсе (печатается «скиллов на машине нет»).
3. `--fix` отчитывается строкой «починено: скилл board-batch положен в ...»,
   разложенный файл совпадает с devkit побайтно, а находка про пустой `test=`
   остаётся: команду тестов `--fix` не выдумывает.
4. Правка скилла на машине становится находкой «скилл ... разошёлся с devkit»,
   без `--fix` файл не тронут (печатается «doctor без --fix скилл не тронул»), а
   с `--fix` перекладывается из devkit с отчётом (печатается «--fix переложил
   скилл из devkit»).
5. Повторный `--fix` ничего не чинит, строк «починено» в выводе нет
   (печатается «чинить нечего»).
6. С вписанной командой тестов находка про пустой `test=` уходит (печатается
   «находки про пустой test больше нет»).

Реальный прогон до выката (2026-08-02). Скилл до слияния лежит только на ветке,
поэтому `DK` был выставлен на копию дерева ветки, а после выката переменная не
задаётся и берётся `~/projects/devkit`:
