# DK-062: уведомления по важности: громкий повод против фонового, событие Stop

Уведомитель шлёт все поводы одинаково, и канал забит тем, что срочности не
несёт. За сутки в `~/.devkit/notify.log` 84 строки `subagent_stop`, одна
`idle_prompt` и ни одной `permission_prompt`. Баннеры идут лентой, каждый
висит в центре уведомлений отдельной строкой, и момент, когда сессия правда
ждёт человека, тонет среди отчётов о том, что очередной субагент дописал своё.
Уведомитель ради этого момента и заводился (DK-034), а получилось наоборот:
поток есть, а сигнала в нём нет.

Второй перекос в наборе поводов. Конец хода главной сессии не подключён
сознательно (DK-034, п. 2 согласованного): считалось, что момент «пользователь
отвлёкся» посчитает сам харнес и пришлёт `idle_prompt` через минуту простоя. По
журналу видно, что не присылает: одна строка за сутки на десятки завершённых
ходов. Пользователь узнаёт о готовности сессии, только когда сам заглянет в
окно.

## Что согласовано с пользователем

1. Поводов два сорта. Громкий зовёт подключиться, приходит со звуком и своим
   баннером. Фоновый рассказывает о ходе работы, приходит молча и схлопывается,
   чтобы не копить ленту.
2. Громкие: сессия упёрлась в вопрос (`permission_prompt`,
   `agent_needs_input`, `elicitation_dialog`), главная сессия закончила ход,
   задача доехала до Check, работа встала на блокере. Последние два шлёт не
   харнес, а `taskctl` с `shipctl`, и это отдельная задача DK-063; здесь под
   них готовится способ позвать уведомитель громко из чего угодно.
3. Фоновые: субагент отработал (`SubagentStop`). Насовсем гасить их не надо,
   они интересны, просто вторичны.

## Решение

1. Уровень появляется у повода и доезжает до бэкенда. Событие харнеса
   раскладывается в уровень внутри `parse_event`, внешний вызов задаёт его
   флагом (`--quiet` понижает; без флага зовущий скрипт считается громким,
   старые вызовы `notify.py "заголовок" "текст"` от этого не меняются).
2. Как уровень выглядит на баннере, решает бэкенд. `terminal-notifier`:
   громкий со звуком, фоновый молча и с `-group` по сессии, тогда новый
   баннер сессии вытесняет её же предыдущий, а не ложится под него.
   `osascript`: звук у громкого, группировки нет вовсе. `notify-send`:
   срочность плюс схлопывание по сессии. Своя команда из
   `DEVKIT_NOTIFY_BACKEND` уровня не понимает и получает заголовок с телом
   как раньше.
3. Конец хода. Подключается событие `Stop`, но с порогом: ход короче
   `DEVKIT_NOTIFY_TURN_MIN` (по умолчанию минута) уведомления не даёт, потому
   что пользователь эти секунды смотрит в то же окно и звать его некуда.
   Длительность хода считается от последнего ввода пользователя, метку кладёт
   хук на `UserPromptSubmit` в то же состояние в `~/.devkit/notify/`. Метки
   нет (сессия поднялась до правки настроек, ход первый), значит порог не
   срабатывает и уведомление уходит.
4. `Stop` и `idle_prompt` это один и тот же повод «сессия ждёт тебя»,
   поэтому троттлинг у них общий: один ключ и окно шире минуты, иначе
   пришедший следом `idle_prompt` продублирует баннер конца хода.
5. В журнал пишется уровень: жалоба «важное не отличается от фонового»
   разбирается по строке, а не на глаз.
6. Профиль харнеса. В `harness/claude-code.toml` добавляются оси событий под
   конец хода и ввод пользователя, вместе с ними список известных событий в
   `devkitctl/harness.py` и `agentctl/harness.go` (у второго тест сверяет
   строку событий целиком). Раскладку `settings.json` пока делает пользователь
   руками, поэтому README показывает готовый кусок конфига.

## Что затрагивается

- `hooks/notify.py`, тесты `hooks/notify_test.py`.
- `hooks/README.md`, раздел «Уведомления о сессии»: сейчас там сказано, что
  `Stop` не подключается вовсе, и объяснено почему. Решение поменялось, значит
  меняется и текст, вместе с примером `settings.json` и разбором журнала.
- `harness/claude-code.toml`, `devkitctl/harness.py`, `agentctl/harness.go`,
  таблица `events` в `docs/lld/DK-033-universal-kit.md`.
- `~/.claude/settings.json` пользователя: новые хуки на `Stop` и
  `UserPromptSubmit`. Файл вне репозитория, правится в конце работы.

## Кусок для ~/.claude/settings.json

Раскладывает его диспетчер после ревью, сам исполнитель настройки не трогает.
К уже стоящему хуку `Notification` (матчер прежний) добавляются три события:

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          { "type": "command", "command": "python3 ~/projects/devkit/hooks/notify.py --hook claude-code" }
        ]
      }
    ],
    "SubagentStop": [
      {
        "hooks": [
          { "type": "command", "command": "python3 ~/projects/devkit/hooks/notify.py --hook claude-code" }
        ]
      }
    ],
    "UserPromptSubmit": [
      {
        "hooks": [
          { "type": "command", "command": "python3 ~/projects/devkit/hooks/notify.py --hook claude-code" }
        ]
      }
    ]
  }
}
```

`SubagentStop` там уже стоит с DK-034, новые тут `Stop` и `UserPromptSubmit`.
Второй ничего не шлёт, он кладёт метку начала хода, без которой порог
длительности не работает и конец хода звонит на каждый короткий ответ.

## Сценарий проверки

Агентский, кроме шага 6. Стабом не проверяются только звук и схлопывание
баннеров, всё остальное видно по аргументам отправителя и по журналу.

1. Тесты: `python3 hooks/notify_test.py` кодом 0 (50 тестов), `sh hooks/test.sh`
   печатает «хуки в порядке», `sh devkitctl/test.sh` печатает «devkitctl в
   порядке», `cd agentctl && go test ./...` печатает `ok`.

2. Уровень доезжает до отправителя и до журнала. Стаб зовётся именно
   `terminal-notifier`: по имени бэкенда уведомитель решает, что тот понимает.

```sh
h=$(mktemp -d); d=$(mktemp -d)
printf '#!/bin/sh\nprintf "%%s\\n" "$*" >> %s/args\n' "$d" > "$d/terminal-notifier"
chmod +x "$d/terminal-notifier"
ev() { printf '{"hook_event_name":"%s","notification_type":"%s","session_id":"%s","cwd":"/p/devkit-dk-062","message":"проба","agent_type":"exec-low","last_assistant_message":"готово"}' "$1" "$2" "$3"; }
hook() { HOME="$h" DEVKIT_NOTIFY_BACKEND="$d/terminal-notifier" python3 hooks/notify.py --hook claude-code; }
ev Notification permission_prompt s-loud | hook
ev SubagentStop "" s-bg | hook
cat "$d/args"; grep -o 'повод [a-z_]* уровень [а-я]*' "$h/.devkit/notify.log"
```

   Ожидается `-sound default` у громкого и `-group devkit-s-bg` без звука у
   фонового, в журнале «повод permission\_prompt уровень громкий» и «повод
   subagent\_stop уровень фоновый».

3. Порог длительности хода: короткий ход молчит, длинный (тут порогом ноль) и
   ход без метки уведомляют.

```sh
: > "$d/args"
ev UserPromptSubmit "" s-turn | hook
ev Stop "" s-turn | hook
wc -l < "$d/args"; grep -c 'пропуск: ход короче 60с' "$h/.devkit/notify.log"
ev Stop "" s-turn | HOME="$h" DEVKIT_NOTIFY_BACKEND="$d/terminal-notifier" \
  DEVKIT_NOTIFY_TURN_MIN=0 python3 hooks/notify.py --hook claude-code
ev Stop "" s-fresh | hook
cat "$d/args"
```

   Ожидается ноль баннеров на коротком ходе и одна строка пропуска в журнале, а
   дальше два баннера «ход закончен» (порог снят, метки нет).

4. Конец хода и `idle_prompt` это один повод: второй баннер не повторяется.

```sh
: > "$d/args"
ev Stop "" s-wait | hook
ev Notification idle_prompt s-wait | hook
wc -l < "$d/args"
grep -c 'повод idle_prompt уровень громкий бэкенд - цель - пропуск: повтор в окне 180с' "$h/.devkit/notify.log"
```

   Ожидается один баннер и одна строка пропуска по окну.

5. Доктор называет неподключённые события (временный HOME, чтобы не смотреть на
   настоящие настройки):

```sh
HOME="$h" python3 devkitctl/devkitctl.py doctor 2>&1 | grep 'notify.py не подключён'
```

   Ожидается находка про `Notification, Stop, SubagentStop, UserPromptSubmit`.
   На настоящей машине после правки настроек эта находка пропадает.

6. Пользовательский шаг, после того как диспетчер разложил хуки. Поработать
   сессией: дождаться конца длинного хода (звук и баннер «ход закончен»),
   посмотреть на пачку отработавших субагентов (баннеры приходят молча и
   держатся одной строкой в центре уведомлений, а не лентой), убедиться, что на
   коротком ответе звонка нет.

## Ход работы

- Исполнение: субагент opus/medium по вердикту pick, 2026-08-02.
- Ключи отправителей сверены с самой утилитой, а не по памяти: у
  `terminal-notifier` `-sound default` («Use 'default' for the default
  notification sound») и `-group ID` («Old notifications with the same ID will
  be removed»), у `osascript` строка `sound name "default"` принимается кодом
  0. Расхождений с решением не нашлось.
- Сверх постановки правится `devkitctl doctor`: он проверял подключение
  уведомителя на двух событиях, теперь на четырёх. Без этого хук на `Stop` и
  `UserPromptSubmit` не разложился бы молча на второй машине, а порог
  длительности хода тихо не работал бы вовсе.
- Мутации, на каждой краснеет хоть один тест: уровень субагента поднят до
  громкого, окно ожидания сведено к обычному, граница порога хода сдвинута на
  `<=`, метка начала хода не кладётся, общий ключ ожидания снят, звук у
  громкого убран, проверка порога выключена, порог по умолчанию другой, `Stop`
  не разбирается, уровень не пишется в журнал. Первые три и ещё три ловят
  юниты, побочные эффекты хука (метка, пропуск по порогу, строка журнала)
  ловит прогон `hooks/test.sh`.
