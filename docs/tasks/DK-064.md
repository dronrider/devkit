# DK-064: конец хода зовёт по фокусу окна, а не по длительности

Уведомление о конце хода не приходит там, где оно и нужно. Пользователь завёл
новый чат, задал вопрос не по задаче, отошёл, и баннера не дождался. В журнале
видно, что хук отработал и сам себя погасил:

```
12:53:07 сессия c8b6f4e4 повод turn_done уровень громкий бэкенд - цель - пропуск: ход короче 60с
```

Порог длительности хода из DK-062 стоит на догадке: раз ответ занял меньше
минуты, человек эти секунды смотрит в то же окно. Догадка неверная.
Длительность хода про то, сколько работала машина, а звать или молчать зависит
от того, где в это время человек, и одно из другого не выводится. Короткий
вопрос перед тем, как отойти, это ровно тот случай, где догадка промахивается,
и он не редкий.

## Что даёт машина

`System Events` отвечает и на «какое приложение сейчас впереди», и на «как
зовётся его переднее окно»:

```
$ osascript -e 'tell application "System Events" to get name of first application process whose frontmost is true'
Code
$ osascript -e 'tell application "System Events" to tell (first application process whose frontmost is true) to get name of front window'
Investigate task priorit... - devkit
```

В заголовке окна VS Code стоит имя рабочего дерева, а дерево сессии уведомитель
уже знает: он собирает по нему цель перехода по клику. Значит «смотришь ли ты
сейчас на эту сессию» это не догадка, а факт. Вызов стоит около 180 мс, для
конца хода терпимо.

## Решение

1. Порог длительности хода уходит вместе с меткой на `UserPromptSubmit` и
   переменной `DEVKIT_NOTIFY_TURN_MIN`, вместо него решает фокус: окно сессии
   впереди значит молчим, всё остальное значит зовём, хоть через три секунды.
   Хук на `UserPromptSubmit` остаётся, он снимает отметку ожидания (DK-062), но
   метку начала хода больше не кладёт.
2. Правило применяется только к концу хода. Запрос разрешения и вопрос агента
   зовут всегда: они редкие, сессия на них стоит намертво, а повторного события
   от харнеса может и не быть. Фоновых поводов проверка фокуса не касается
   вовсе, лишние 180 мс на каждого субагента ни к чему.
3. Сессия узнаётся по рабочему дереву в заголовке окна. Совпадением считается
   заголовок, который кончается именем дерева сессии (у VS Code это хвост после
   разделителя), иначе окно чужое. Несколько чатов в одном окне редактора друг
   от друга не отличить, и это осознанная грубость: сессии в одном дереве
   считаются одной, зато промах уходит в сторону лишнего баннера, а не тишины.
4. Фокус не определился (не macOS, нет разрешения на управление компьютером,
   `osascript` ответил ошибкой или пусто) значит зовём. Тишина здесь хуже
   лишнего баннера: она неотличима от штатной работы, а разрешение выдают не на
   всякой машине. Отказ пишется в журнал, чтобы «звонит всегда» разбиралось по
   строке.
5. Определение фокуса живёт отдельной функцией с подменяемым способом опроса:
   тесты гоняются без живого `System Events`, а на не-macOS оно просто не
   заводится. Переменной (`DEVKIT_NOTIFY_FOCUS=off`) проверка выключается
   целиком, тогда конец хода зовёт всегда.
6. В журнал пишется, почему промолчали: «пропуск: окно сессии в фокусе». Строки
   про короткий ход исчезают вместе с порогом.

## Что затрагивается

- `hooks/notify.py`, тесты `hooks/notify_test.py`, сквозные шаги `hooks/test.sh`
  (там есть блоки про порог длительности, они переписываются под фокус).
- `hooks/README.md`: раздел «Уведомления о сессии» описывает порог и метку
  начала хода, обе уходят.
- Файл задачи DK-062 в архиве не переписывается, история решения остаётся как
  была; на смену правила ссылается эта задача.

## Сценарий проверки

Агентский, кроме шага 6: заглянуть в окно глазами подменой нельзя. Опрос фокуса
на шагах 2-5 идёт через стаб `osascript` в PATH, HOME временный, настоящий
`~/.devkit` не трогается. Обвязка одна на все шаги:

```sh
h=$(mktemp -d); d=$(mktemp -d)
printf '#!/bin/sh\nprintf "%%s\\n" "$*" >> %s/args\n' "$d" > "$d/terminal-notifier"
chmod +x "$d/terminal-notifier"
mkdir -p "$d/bin"
cat > "$d/bin/osascript" <<EOF
#!/bin/sh
printf 'спросили\n' >> "$d/asked"
[ -s "$d/title" ] || exit 1
read -r t < "$d/title" && printf '%s\n' "\$t"
EOF
chmod +x "$d/bin/osascript"
ev() { printf '{"hook_event_name":"%s","notification_type":"%s","session_id":"%s","cwd":"/p/devkit-dk-064","message":"проба","agent_type":"exec-low","last_assistant_message":"готово"}' "$1" "$2" "$3"; }
hook() { HOME="$h" PATH="$d/bin:$PATH" DEVKIT_NOTIFY_BACKEND="$d/terminal-notifier" python3 hooks/notify.py --hook claude-code; }
```

1. Тесты из корня worktree: `python3 hooks/notify_test.py` кодом 0 (63 теста),
   `sh hooks/test.sh` печатает «хуки в порядке», `sh devkitctl/test.sh` печатает
   «devkitctl в порядке». Краснота регрессионного теста на старом коде:

```sh
regcheck --base main -- python3 hooks/notify_test.py \
  TestHookFocus.test_short_turn_rings_from_someone_elses_window
```

2. Окно сессии впереди, значит молчим, и в журнале сказано почему.

```sh
: > "$d/args"
printf 'notify.py - devkit-dk-064\n' > "$d/title"
ev Stop "" s-here | hook
echo "баннеров: $(wc -l < "$d/args" | tr -d ' ')"
grep -c 'пропуск: окно сессии в фокусе' "$h/.devkit/notify.log"
```

   Ожидается ноль баннеров и одна строка пропуска.

3. Впереди окно самого проекта, а сессия сидит в дереве задачи: это разные
   окна, и конец хода зовёт.

```sh
printf 'TASKS.md - devkit\n' > "$d/title"
ev Stop "" s-away | hook
cat "$d/args"
```

   Ожидается баннер «devkit-dk-064: ход закончен».

4. Опрос не ответил (нет разрешения, не macOS), значит зовём и пишем отказ в
   журнал; `DEVKIT_NOTIFY_FOCUS=off` зовёт, не спрашивая никого.

```sh
: > "$d/args"; : > "$d/title"; : > "$d/asked"
ev Stop "" s-blind | hook
echo "баннеров: $(wc -l < "$d/args" | tr -d ' ')"
grep -c 'фокус не определился, зовём' "$h/.devkit/notify.log"
: > "$d/args"; : > "$d/asked"
printf 'notify.py - devkit-dk-064\n' > "$d/title"
ev Stop "" s-off | HOME="$h" PATH="$d/bin:$PATH" DEVKIT_NOTIFY_BACKEND="$d/terminal-notifier" \
  DEVKIT_NOTIFY_FOCUS=off python3 hooks/notify.py --hook claude-code
echo "баннеров: $(wc -l < "$d/args" | tr -d ' '), опросов: $(wc -l < "$d/asked" | tr -d ' ')"
```

   Ожидается по баннеру в каждом случае, строка отказа в журнале и ноль опросов
   при выключенной проверке.

5. Мимо конца хода фокус не спрашивается вовсе: лишний опрос на каждого
   субагента это его 180 мс на пустом месте.

```sh
: > "$d/args"; : > "$d/asked"
ev Notification permission_prompt s-perm | hook
ev SubagentStop "" s-sub | hook
echo "баннеров: $(wc -l < "$d/args" | tr -d ' '), опросов: $(wc -l < "$d/asked" | tr -d ' ')"
rm -rf "$h" "$d"
```

   Ожидается два баннера и ноль опросов.

6. Пользовательский шаг, после выката. Задать сессии короткий вопрос, сразу
   переключиться в другое окно и дождаться ответа: баннер «ход закончен» должен
   прийти, хотя ход занял секунды. Тот же короткий вопрос, не уходя из окна
   сессии, баннера давать не должен, а в `~/.devkit/notify.log` на него ляжет
   строка «пропуск: окно сессии в фокусе».

## Ход работы

- Исполнение: субагент opus/high по вердикту pick, 2026-08-02.
- Опрос сделан одним вызовом `osascript`: имя переднего приложения (первая
  команда из постановки) для сравнения не нужно, заголовка окна хватает, а
  второй вызов стоил бы ещё 180 мс на каждом конце хода.
- Живой `osascript` ищется через PATH, а не через проверку платформы: на
  не-macOS его там нет, и проверка выключается сама, зато сквозной прогон
  подставляет стаб той же дорогой и не зависит от машины.
- Заголовок VS Code разделяет части длинным тире, а не дефисом (снято живьём,
  см. прогон), поэтому хвост сверяется по границе слова, а не по строке с
  дефисом. Тем же правилом `devkit` перестаёт совпадать с `devkit-dk-064`.
- Дерева сессии нет (`cwd` не собрался ни из транскрипта, ни из события),
  значит опроса не делаем вовсе: сравнивать заголовок не с чем, и повод
  считается неопределившимся, то есть зовём.
- Сверх списка «Что затрагивается» правятся `devkitctl/README.md` с
  `devkitctl/test.sh` (находка доктора про `UserPromptSubmit` объяснялась
  порогом длительности) и таблица событий в `docs/lld/DK-033-universal-kit.md`
  (там же). Сама находка доктора не меняется: хук на четырёх событиях остаётся.
- Мутации, на каждой краснеет хоть один прогон: срок опроса снят, хвост
  заголовка сверяется без границы слова, неудачный опрос считается взглядом в
  окно сессии, пропуск по фокусу не пишется в журнал, опрос всегда отвечает
  пусто, проверка пустого дерева снята, фокус спрашивается на любом поводе,
  проверка фокуса снята совсем, выключатель не читается, ненулевой код
  `osascript` считается ответом, ввод пользователя не снимает отметку ожидания.
  Первые десять ловят юниты, последнюю только `hooks/test.sh`.
