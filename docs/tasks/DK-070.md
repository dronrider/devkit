# DK-070: mergedShas читает файл задачи построчно и не знает про ограждённые блоки: процитированный раздел «Выкат» становится настоящей записью

Вылезло сразу на DK-065, при первом же прогоне её сценария после выката. В файл
задачи вкладывается реальный вывод (RULES.board.md, «Трекинг задач» п. 6), а в
выводе стоял заголовок `## Выкат` и строка записи из синтетического
репозитория. `mergedShas` (`shipctl/record.go`) идёт по строкам файла и про
ограждённые блоки не знает, поэтому процитированное принял бы за свою запись:
пришлось сдвигать вывод на два пробела и оговаривать это прозой.

Сам по себе чужой sha безвреден, он просто не найдётся в логе. Опасен обратный
случай: файл задачи цитирует чужую запись (разбор соседней задачи, кусок
истории), sha из неё в логе есть, и очередь выката посчитает выкаченной не ту
задачу. Того же поля `openReviewNotes` в `shipctl/board.go`: он тоже ищет
`## Ревью` построчно, и процитированное замечание без исхода отобьёт слияние.

Что сделать: разбирая файл задачи, пропускать содержимое ограждённых блоков
(``` и ~~~), общим хелпером для обоих читателей. Тест на файл, где раздел
процитирован внутри блока.

## Ход работы

- Исполнение: субагент opus/medium по вердикту pick (маппинг sonnet, корректор: профицит week_all), 2026-08-02.
- Общий хелпер лёг в `shipctl/taskdoc.go`: `fenceMask` помечает строки внутри
  ограждённого блока вместе с самими ограждениями, `sectionLines` отдаёт
  строки раздела мимо блоков. Через него пошли `mergedShas` и
  `openReviewNotes`, а `appendToSection` ищет по маске начало и конец своего
  раздела: иначе строка записи уехала бы внутрь процитированного вывода.
- Тот же построчный разбор живёт в `taskctl/review.go` (`loadReview`) и в
  `agentctl/pick.go` (`recordExecution`). Там он опаснее, чем читатели
  shipctl: `review resolve N` перепишет строку внутри блока, а запись
  исполнителя встанет в процитированный «Ход работы». Хелпер лежит в модуле
  shipctl, на два соседних модуля его так просто не растянуть, поэтому в этой
  задаче они не трогались и просятся отдельной строкой на доску.
- Регрессия закрыта regcheck на тестах `shipctl/record_test.go`:

  ```
  regcheck --base main -- go test -C shipctl ./ -run 'TestMergedShasSkipsFenced|TestAppendToSectionSkipsFenced|TestMergeIgnoresFencedReviewNote'
  тест краснеет на main и проходит на текущем коде, регрессия закрыта (тесты: shipctl/record_test.go)
  ```
