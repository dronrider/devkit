# DK-070: mergedShas читает файл задачи построчно и не знает про ограждённые блоки: процитированный раздел «Выкат» становится настоящей записью

Вылезло сразу на DK-065, при первом же прогоне её сценария после выката. В файл
задачи вкладывается реальный вывод (RULES.board.md, «Трекинг задач» п. 6), а в
выводе стоял заголовок `## Выкат` и строка записи из синтетического
репозитория. `mergedShas` (`shipctl/record.go`) идёт по строкам файла и про
ограждённые блоки не знает, поэтому процитированное принял бы за свою запись:
пришлось сдвигать вывод на два пробела и оговаривать это прозой.

Сам по себе чужой sha безвреден, он просто не найдётся в логе. Опасен обратный
случай: файл задачи цитирует чужую запись (разбор соседней задачи, кусок
истории), sha из неё в логе есть, и очередь выката посчитает выкаченной не ту
задачу. Того же поля `openReviewNotes` в `shipctl/board.go`: он тоже ищет
`## Ревью` построчно, и процитированное замечание без исхода отобьёт слияние.

Что сделать: разбирая файл задачи, пропускать содержимое ограждённых блоков
(``` и ~~~), общим хелпером для обоих читателей. Тест на файл, где раздел
процитирован внутри блока.
