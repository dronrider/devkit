# DK-072: devkitctl/test.sh без бита x, локальный прогон как в доке падает

`devkitctl/README.md` показывает прогон тестов строкой `devkitctl/test.sh`, но
у файла нет прав на исполнение (`-rw-r--r--`), и команда из доки падает с
`permission denied`. Соседний `hooks/test.sh` бит x несёт, так что перепутать
легко: скрипт выглядит рабочим ровно до запуска.

Правка: вернуть биту x место (`git update-index --chmod=+x` либо `chmod +x` с
коммитом режима) и закрыть регресс тестом. Проверять надо не один файл, а всё
семейство: любой `*/test.sh` в репозитории обязан быть исполняемым, иначе через
полгода тот же дефект вылезет на новой утилите. Тест должен краснеть на дереве
до правки режима.

Дока правки не требует, команда в `devkitctl/README.md` написана верно, она
просто не работала.

## Ход работы

- Исполнение: субагент sonnet/high по вердикту pick (маппинг haiku, корректор: профицит week_all), 2026-08-02.
- Бит вернулся через `chmod +x devkitctl/test.sh` + `git add`: режим объекта
  git это часть дерева, обычный `chmod` без стадии на индекс не влияет
  (проверено вручную, `git ls-files -s` до `add` всё ещё показывал `100644`).
- Регресс закрыт не про один файл, а про всё семейство `test.sh`: новый
  `hooks/check-exec-bit.py` смотрит `git ls-files -s` по репозитории (корень и
  любая вложенность) и находит любой `test.sh` без режима `100755`. Юнит-фикстура
  на синтетическом репозитории лежит в `hooks/test.sh` (ловит бит без x и в
  корне, и во вложенной директории, молчит на исполняемом и на постороннем
  `.sh` рядом), а сам регресс закрывает прогон чекера на живом репозитории:
  `regcheck --base main --tests hooks/check-exec-bit.py -- python3
  hooks/check-exec-bit.py` краснеет на `main` (там `devkitctl/test.sh` ещё без
  бита) и проходит на текущем коде.
- CI (`.github/workflows/ci.yml`) гоняет чекер на каждый push отдельным шагом,
  README и `hooks/README.md` описывают новый прогон.

## Сценарий проверки (агентский)

Шаги воспроизводят исходный баг и проверяют регресс на всём семействе, все
выполнимы с машины агента без выката (правка это состояние самого git-дерева).

1. `devkitctl/test.sh` (прямой вызов строкой из `devkitctl/README.md`).
   Раньше падал `permission denied`, код возврата 126; теперь код 0,
   последняя строка `devkitctl в порядке`.
2. `python3 hooks/check-exec-bit.py` - код 0, вывод пустой (любой `test.sh`
   в репозитории несёт бит x в git-индексе).
3. `git ls-files -s -- 'test.sh' '**/test.sh'` - оба пути (`devkitctl/test.sh`,
   `hooks/test.sh`) показывают режим `100755`.
4. `sh hooks/test.sh` - код 0, последняя строка `хуки в порядке` (новая
   фикстура `check-exec-bit.py` внутри проходит вместе с остальными).

Прогнано агентом при закрытии задачи, реальный вывод:

```
$ devkitctl/test.sh
devkitctl в порядке
$ echo $?
0
$ python3 hooks/check-exec-bit.py; echo $?
0
$ git ls-files -s -- 'test.sh' '**/test.sh'
100755 2e4296aa9b9cbf1e69c805545fc5183b8a9f4846 0	devkitctl/test.sh
100755 c61d2f19fe2de412629a8ece61b7e16e756c2b97 0	hooks/test.sh
$ sh hooks/test.sh
хуки в порядке
```
