# DK-080: taskctl add --id: флаг -m падает, когда черновик не закоммичен (pathspec на удалённый файл)

## Из черновика DK-159 (записан 2026-08-06)

### Разбор на грумминге 2026-08-07

Воспроизведено на временном репозитории с синтетической доской: незакоммиченный
черновик, `taskctl add --id ... -m` падает той же ошибкой pathspec, строка и
перенос файла остаются в индексе без коммита. Причина в коде найдена:
`promoteDraft` переносит файл через `gitMv`, у которого на неотслеживаемом
файле `git mv` отбивается и срабатывает запасной `os.Rename`, а `add --id`
кладёт путь черновика в pathspec коммита безусловно (`ops.go`, сборка `paths`
после `promoteDraft`). `apply` отфильтровывает несуществующие пути только для
`git add`, в `git commit -- <paths>` едут все. Для `draft drop` и
`draft attach` тот же класс уже закрыт хелпером `removeDraft` (`groom.go`):
он пробует `git rm`, на отказе удаляет обычным `rm` и путь в коммит не кладёт.
Кандидат из черновика подтверждается: в `add --id` путь черновика должен
попадать в pathspec только когда перенос прошёл через `git mv`, то есть
`gitMv` (или `promoteDraft`) должен отвечать, знает ли git про исходный путь,
по образцу `removeDraft`.

### Черновик

taskctl add --id падает на коммите, когда черновик не был закоммичен. Оформление DK-158: файл черновика завели командой draft (она его не коммитит), потом переписали разбором, потом позвали add --id ... -m ... --push. Строка на доске завелась, файл переехал в docs/tasks/DK-158.md и попал в индекс, а команда упала: error: pathspec 'docs/tasks/drafts/DK-158.md' did not match any file(s) known to git, exit status 1. Коммита и пуша не случилось, работа осталась в индексе, доводить пришлось руками. Кандидат: в pathspec коммита класть путь черновика только тогда, когда git про него знает (git ls-files --error-unmatch либо проверка перед сборкой списка). Смежно с DK-116 (файл черновика всплыл в рабочем дереве после оформления) и DK-119 (коммит доски, собранный руками, отбивает pre-push): у всех трёх предмет один, стык оформления черновика с гитом.

## Из черновика DK-274 (записан 2026-08-12)

### Черновик

taskctl add по неотслеженному черновику падает на git commit: pathspec drafts/<ID>.md не находится, строка и перенос файла успевают, коммит остаётся руками. Живой случай: оформление DK-270 2026-08-12, черновик лежал в накопителе незакоммиченным

## Ход работы

Фикс по образцу `removeDraft` (groom.go): класс бага для `draft drop` и
`draft attach` уже закрыт хелпером, который возвращает `(staged, error)` и
кладёт путь черновика в pathspec коммита только когда `git rm` прошёл, то есть
когда git знал исходный путь. Для `add --id` сделано симметрично:

- `gitMv` (ops.go) теперь возвращает `(staged bool, error)`, где `staged=true`
  значит «перенос шёл через git mv, git знал исходный путь». На неотслеживаемом
  файле git mv отбивается, срабатывает запасной rename, возвращается
  `staged=false`.
- `promoteDraft` (draft.go) несёт этот флаг выше, расширяя возврат до
  `(promoted, staged, error)`.
- `cmdAdd` кладёт путь `docs/tasks/drafts/<ID>.md` в pathspec коммита только
  когда `staged`: на неотслеживаемом черновике этого пути в коммите нет, файл
  задачи едет как вновь добавленный через `git add`.
- `cmdClose` (архивация) при звуке новой сигнатуры `gitMv` отбрасывает флаг:
  файл задачи там всегда tracked, поведение не меняется.

Регрессионный тест `TestAddPromotesUntrackedDraft` (draft_test.go) возвращает
красноту на старом коде с точной ошибкой из баг-репорта (`error: pathspec
'docs/tasks/drafts/XR-008.md' did not match any file(s) known to git`) и зелён
на исправленном: untracked черновик, `cmdAdd` с `-m`, файл переехал, коммит
состоялся, в `git show` исходного пути `drafts/` нет. Существующий
`TestDraftPromotedByAdd` бага не ловил: `setup` без `git init` и пустой
`CommitOpts{}` выходили из `apply` по `Msg == ""` до pathspec. Новый тест
поднимает git-репозиторий через `gitSetup` и подставляет `-m`, как живой вызов.

Дока едет той же правкой: README taskctl в абзаце про оформление `add --id`
дописывает стык «черновик не в git»: `git mv` на неотслеживаемом файле
отбивается, и pathspec коммита этого пути не несёт.
- Ревью: подпроцесс glm-5.2/high по вердикту pick (квота: объявления нет, корректор выключен), 2026-08-12.

## Сценарий проверки (агентский)

Условие бага это неотслеживаемый (untracked) черновик, и шаг 3 проходит именно
тот путь, что до фикса ронял коммит ошибкой pathspec. Шаги идут во временном
окружении, живую доску не трогают, итог каждого шага проверяется командой.
Прогон ниже на собранном из ветки бинарнике, на проде он повторится на
обновлённом после выката taskctl.

1. Временное окружение: `d=$(mktemp -d)`, `git init -q "$d"`,
   `HOME="$d/h" taskctl init --prefix XR -C "$d"`, `git -C "$d" commit -q -am init`.
   Ожидается: `taskctl -C "$d" list` отвечает без ошибки.
2. Неотслеживаемый черновик: `taskctl -C "$d" draft "зерно бага"`. Ожидается:
   `git -C "$d" status --porcelain --untracked-files=all` выводит
   `?? docs/tasks/drafts/XR-001.md`, то есть draft без `-m` не коммитит и
   черновик именно untracked.
3. Условие бага: `taskctl -C "$d" add --id XR-001 --title "Тест DK-080" --type bug --rank "25+2+1+5+0" -m "docs(tasks): проверка DK-080"`. До фикса падало с `error: pathspec 'docs/tasks/drafts/XR-001.md' did not match any file(s) known to git`; ожидается exit 0 и строка про перенос черновика.
4. Итог коммита: `git -C "$d" status --porcelain` пуст, `git -C "$d" log --oneline -1`
   держит коммит «docs(tasks): проверка DK-080», `docs/tasks/drafts/XR-001.md`
   исчез, `docs/tasks/XR-001.md` на месте.
5. Дополнение «как раньше и не сломалось»: tracked-черновик оформляется тем же
   путём, и переименование едет в pathspec. Завести и закоммитить черновик
   (`taskctl -C "$d" draft "второй"`, `git -C "$d" commit -q -am draft`), затем
   `add --id XR-002 ...` теми же флагами. Ожидается exit 0, а в
   `git -C "$d" show --name-status HEAD` есть строка
   `R100 docs/tasks/drafts/XR-002.md docs/tasks/XR-002.md`.

Обкатка до выката, 2026-08-12, на собранном из ветки taskctl:

```
шаг 2: ?? docs/tasks/drafts/XR-001.md
шаг 3: XR-001 заведена в backlog: P2, R=33, черновик перенесён
       в docs/tasks/XR-001.md, коммит 9dd0c9f
       exit=0
шаг 4: git status --porcelain пуст
       git log --oneline -1 = 9dd0c9f docs(tasks): проверка DK-080
       docs/tasks/drafts/ пуст, docs/tasks/XR-001.md на месте
шаг 5: XR-002 заведена в backlog: P2, R=33, черновик перенесён
       в docs/tasks/XR-002.md, коммит 7131e20
       exit=0
       git show --name-status HEAD:
         R100 docs/tasks/drafts/XR-002.md docs/tasks/XR-002.md
```

До фикса шаг 3 падал с точной ошибкой из баг-репорта, что сверяет
регрессионный тест `TestAddPromotesUntrackedDraft` (draft_test.go).
