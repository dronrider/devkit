# DK-086: Хуки корп-контура: обёртка чужих хуков и рубеж следов devkit

Задача серии корп-контура по принятому LLD
[DK-074](../lld/DK-074-corp-contour.md), раздел «Хуки: чужой сосед и рубеж
следов» (строки 382-410). Идёт после закрытой DK-081. Раскладывает обёртку по
`.git/hooks` корп-клона подключение `devkitctl corp` (DK-085), и оно же ловит
перезаписанную обёртку диагностикой; здесь строится сама обёртка и состав
проверок, чтобы DK-085 не писал её второй раз.

## Что делать

`core.hooksPath` в корп-клоне не годится: он выключает `.git/hooks` целиком, а
там живут чужие хуки проекта, и молча отключённый линтер компании это поломка
чужого процесса. Симлинки не лучше, их перетирает чужой инсталлер.

1. Обёртка-цепочка: файл devkit с маркером в первой строке, который прогоняет
   проверки devkit, а затем зовёт чужой хук, если тот был. Чужой хук при
   подключении переезжает в соседнее имя `<hook>.chained`, обёртка зовёт
   именно его. Ненулевой код любой стороны валит коммит, ни одна сторона
   молча не проглатывается.
2. Маркер первой строки это опознание своего файла. Чужой инсталлер,
   перезаписавший обёртку, ловится по пропавшему маркеру; починка это
   повторный `--fix`, который снова развернёт цепочку. Саму находку и `--fix`
   строит DK-085, здесь нужен маркер, по которому это возможно, и функция
   развёртывания цепочки, годная для повторного прогона.
3. Состав проверок в корп-контуре. Остаются как есть символы
   (`check-symbols`), следы ассистентов и формат сообщения (`check-commit`),
   чувствительное в staged-диффе: в корпе первые два важнее домашнего, цена
   прокола выше.
4. Добавляется рубеж следов devkit: локальный ID доски (префикс берётся из
   шапки доски боковой директории) и путь боковой директории не должны попасть
   ни в дифф, ни в сообщение коммита. Перечень расширяем списком слов в
   контуре, но по умолчанию короткий: широкие эвристики дают ложные
   срабатывания, а рубеж, который врёт, отключают.
5. Включается всё это признаком корп-контура из DK-081 (редирект
   `devkit.local`), заново разбирать git-конфиг не надо. Без редиректа
   корп-проверки молчат, и домашние проекты не замечают ничего.
6. Рубеж чувствительного для самой доски переезжает вместе с доской: боковая
   директория это свой git-репозиторий, и его pre-commit это обычные хуки
   devkit с `core.hooksPath`, корп-специфичного там нет.

Раскладка обёртки по клону, переезд чужого хука в `.chained` при подключении,
exclude-строка и находки doctor это DK-085. Здесь код обёртки, состав проверок
и рубеж следов.

## Дока

## Сценарий проверки

Агентский.

Юниты по разделу «Тесты» LLD: обёртка зовёт и проверки devkit, и чужой хук;
отказ каждой стороны валит коммит; рубеж следов ловит локальный ID и путь
боковой директории и в диффе, и в сообщении коммита; без редиректа
`devkit.local` корп-проверки молчат и домашние проекты не трогаются. Мутации,
которые тесты обязаны ловить: чужой хук не позван, его ненулевой код проглочен,
рубеж смотрит только в дифф или только в сообщение, префикс ID взят не из шапки
боковой доски, корп-проверки включились без редиректа.

Живая проверка на временном репозитории вне рабочих деревьев: клон с чужим
pre-commit, развёрнутая обёртка, коммит с локальным ID в сообщении обязан
упасть, чистый коммит пройти, чужой хук обязан отработать в обоих случаях. В
файл задачи вкладывается реальный вывод.

Прогон общего тест-набора из `.devkit/deploy.local` (ключ `test`) с кодом 0,
`hooks/test.sh` в его составе.
