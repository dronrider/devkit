# DK-093: agentctl: гейт бюджета цели (spend) и потолок яруса в pick (--goal)

Первая задача серии автономного цикла из
[DK-079](../lld/DK-079-autonomous-loop.md). Дизайн лежит там, раздел «Контракт
лимитов»; здесь ход работы и сценарий проверки.

## Что сделано

- `agentctl spend --goal <файл цели>` считает расход цели против её бюджета и
  печатает машинную строку `gate: ok` либо `gate: over`, а за ней человеческую
  с числами по каждому бакету. Кодом возврата гейт не отвечает: `over` это
  штатный ответ команды, и ненулевой код спутался бы с ошибкой постановки.
- Лимиты читаются из раздела «Бюджет» файла цели (`бюджет: week_all <= 25`,
  необязательная строка `ярус: pro`), расход считается по цепочке снимков из
  раздела «Журнал» плюс текущий снимок квоты. Отрицательная дельта значит сброс
  окна, и расходом берётся значение нового окна целиком. Флаг `--record`
  дописывает текущий снимок в конец «Журнала», так что следующий виток читает
  его как предыдущую точку цепочки и расход не удваивается.
- Отказом отвечает только ошибка постановки: незнакомый харнесу бакет,
  нечитаемая строка `бюджет:` или `ярус:`, раздел вовсе без лимитов, ненайденный
  файл цели. Всё остальное (нет снимка, снимок протух, битая строка журнала,
  пустая секция `[quota]` у харнеса) гейт не роняет, но говорит вслух хвостом
  строки: расход по неполной цепочке занижен, и молчать про это нельзя.
- Потолок яруса применяет сам pick, флагом `--goal`. Режет он последним шагом
  ярусной оси, после override и корректора, и только вниз; effort не трогает, а
  пол base считается по итоговому ярусу. Грумминговый вердикт ниже pro не
  режется: нарезка цели дешёвой моделью выйдет плохой, и весь бюджет уедет на
  переделку. Причина среза идёт и в человеческую строку, и в запись `--record`
  вместе с исходным маппингом.
- Место записи в раздел файла вынесено в общую `insertIntoSection`: строку
  исполнения в «Ход работы» и снимок витка в «Журнал» пишут одинаково.
- Дока: `agentctl/README.md`, раздел «Гейт бюджета цели (spend)» с подразделом
  про `--goal` у pick. `README.md` devkit и `RULES.board.md` правят соседние
  задачи серии.

## Сценарий проверки (агентский)

Живой проект, живая доска и настоящий снимок квоты не трогаются: всё на
синтетической цели во временном дереве со своим `HOME`.

```sh
sh docs/tasks/DK-093-check.sh
```

Шаги и ожидаемый итог:

1. `spend` по цели с бюджетом `week_all <= 25`, снимком витка на 10% в журнале
   и живым снимком на 22% печатает `gate: ok` и «потрачено 12 из 25»;
2. `spend --record` дописывает строку снимка в «Журнал», раздел «Итог» остаётся
   как был, а повторный прогон печатает те же 12 пунктов, а не 24;
3. `pick T-002 --goal ...` при потолке `base` даёт `tier: base` с причиной
   «потолок цели: base, pro -> base», в файле задачи появляется запись с
   исходным маппингом, а тот же pick без `--goal` остаётся на `tier: pro`;
4. потолок бюджета опущен до 10, и `spend` печатает `gate: over` с «бюджет цели
   исчерпан по week_all»;
5. незнакомый бакет в строке бюджета это отказ с ненулевым кодом, а не гейт по
   остальным строкам.

Скрипт печатает «шаг N: ok» по каждому шагу и завершается нулевым кодом.

До сдачи обкатан на бинарях ветки (`DEVKIT=<клон ветки> sh
docs/tasks/DK-093-check.sh`, бинарь собирается во временный каталог и подменяет
PATH): все пять шагов дали ожидаемый вывод, код возврата 0. На выкаченном
сегодня бинаре тот же скрипт падает на первом шаге («неизвестная команда
spend», код 2), то есть сценарий проверяет именно эту правку. После выката он
гоняется без `DEVKIT`, тогда agentctl берётся из PATH.

## Ход работы

- Исполнение: субагент opus/medium по вердикту pick (квота: week_all 2%, снимок 4м назад, сдвига нет), 2026-08-03.
- Ветка `dk-093` в своём worktree, коммиты серией: код agentctl, дока, файл
  задачи со сценарием.
- Тесты: `agentctl/goal_test.go` (разбор бюджета и журнала, границы раздела,
  пошаговые дельты со сбросом окна, обе стороны границы гейта, отсутствие и
  протухание снимка, битая строка журнала, отказы постановки, `--record` в свой
  раздел и повторный счёт, CLI и справка, таблица потолка, потолок на сквозном
  пути pick вместе с override и корректором, запись `--record` с причиной
  среза). Полный прогон devkit (`go test` по четырём модулям, `hooks/test.sh`,
  `devkitctl/test.sh`) зелёный.
- Мутации по разделу «Тесты» дизайна прогнаны по одной, каждая красит хоть один
  тест: перепутанный знак дельты, потерянный сброс окна, сдвинутая граница
  `gate`, `--record` в чужой раздел, потолок применён до корректора, override
  принят сильнее потолка, грумминг срезан ниже pro, потолок подтягивает низкий
  вердикт вверх. Типовые мутации из `RULES.md` тем же порядком: пропавший
  побочный эффект записи, пустой возврат `spendOf`, снятые проверки на пустой
  бюджет и на незнакомый бакет, не та ветка на протухшем снимке. Одна проверка
  пережила мутацию, потому что была недостижима (снимок журнала без единого
  бакета до неё не доходит, разбор падает раньше), и убрана как мёртвая.
