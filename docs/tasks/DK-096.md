# DK-096: оболочка goal-run: tmux-цикл витков, замок, защита от воронки, уведомления

## Ход работы

- Исполнение: субагент opus/medium по вердикту pick (квота: week_all 4%, снимок 30м назад, сдвига нет), 2026-08-04.
- Оболочка легла `skills/goal-loop/goal-run.sh` рядом со скиллом. Витки идут
  одноразовыми headless-сессиями (`claude -p "продолжай цель <ID> по скиллу
  goal-loop"`), следующую поднимает только маркер `continue`. Без флагов цикл
  уходит в tmux-сессию `goal-<ID>` тем же способом, каким съёмщик панели
  `/usage` поднимает клиента, а `--foreground` держит витки в этом же процессе,
  и на нём же стоят тесты.
- Маркер разбирается ровно так, как обещает раздел «Маркеры выхода»: последняя
  непустая строка ответа сравнивается целиком, поэтому ограда примера и
  «маркер: continue» прозой за маркер не сходят. Ответ без маркера и упавшая
  сессия это авария витка, цикл на ней встаёт с кодом 1.
- Замок вышел не `flock`: на macOS его в системе нет вовсе. Вместо него
  директория `.devkit/goal-<ID>.lock` с pid владельца внутри, как в
  `hooks/quota-refresh.sh`: `mkdir` атомарен, мёртвый владелец виден по
  `kill -0`, и брошенный замок снимается сам, а не запирает цель до ручной
  уборки.
- Счётчик воронки считает витки, которые ответили `continue` и не дописали в
  «Журнал» ни строки; строки снимков квоты за запись не считаются, их гейт
  бюджета дописывает и пустому витку. Маркер `stuck` цикл останавливает сразу,
  как любой другой маркер кроме `continue`, поэтому трём `stuck` подряд взяться
  неоткуда. Отличия от дизайна записаны в LLD DK-079, подраздел «Оболочка
  goal-run», и в самом скилле.
- Стартовать оболочка отказывается там же, где отказывает постановка: нет
  доски, нет файла цели, в `.devkit/deploy.local` не стоит `autonomous = true`.
  Коды возврата разводят исходы: 0 стоп по маркеру, 1 стоп самой оболочки
  (авария витка, воронка), 2 ошибка вызова или окружения, 3 цикл уже идёт.
- Тесты `skills/goal-loop/test.sh`: настоящих сессий не поднимается ни одной,
  витки играет заглушка вместо `claude` со своим сценарием на стенд, у стенда
  свои проект, доска, цель и `HOME`. Покрыты цикл до `done`, каждый из пяти
  маркеров, воронка с порогом и сбросом счётчика, снимок квоты не за
  продвижение, замок с живым и с брошенным владельцем, аварии витка, отказы
  старта и ветка tmux со своей заглушкой. У заглушки стоит потолок в десять
  витков: сломанная оболочка иначе крутила бы стенд вечно, и провал выглядел бы
  зависшим прогоном.
- Мутации, на каждой краснеет хоть один тест: маркер `continue` принят за стоп
  (10 провалов), порог воронки на единицу больше (2), замок не берётся (6),
  строка снимка считается продвижением (2), стоп без уведомителя (6).
- Команда тестов devkit целиком зелёная, тесты оболочки подключены ключом
  `test` в `.devkit/deploy.local`, шагом в CI и строкой в README.

## Сценарий проверки

Агентский. Каждый шаг выполним с машины агента, итог проверяется командой, а не
глазом. Прод не трогается: настоящих сессий `claude` оболочка тут не поднимает
ни одной, витки играет заглушка в своём PATH, цель и доска синтетические, а
`HOME` временный, так что уведомитель пишет свой журнал в песочницу.

Скрипт целиком, звать из корня клона (`sh scenario.sh <путь к клону>`):

```sh
#!/bin/sh
# Сценарий проверки DK-096: оболочка goal-run. Настоящих сессий claude не
# поднимается ни одной, витки играет заглушка в своём PATH; живая доска и прод
# не трогаются, всё идёт на синтетической цели во временном HOME.
set -eu
repo=${1:-$PWD}
run="$repo/skills/goal-loop/goal-run.sh"
sand=$(mktemp -d)
HOME="$sand/home"
export HOME
mkdir -p "$HOME"

ok() { echo "OK: $1"; }
bad() { echo "FAIL: $1"; exit 1; }

stand() { # синтетический проект с целью DK-100 в $1
    mkdir -p "$1/.devkit" "$1/docs/tasks"
    printf '# Доска\n\n## In progress\n' > "$1/docs/TASKS.md"
    printf '# DK-100: Цель: синтетическая\n\n## Бюджет\n\nбюджет: week_all <= 10\n\n## Журнал\n' \
        > "$1/docs/tasks/DK-100.md"
    printf 'deploy = true\nautonomous = true\n' > "$1/.devkit/deploy.local"
}

echo "== 1. самопроверка оболочки =="
sh "$repo/skills/goal-loop/test.sh" | tee "$sand/test.out"
grep -qx 'оболочка цели в порядке' "$sand/test.out" || bad "тесты оболочки не прошли"
ok "тесты оболочки зелёные"

echo "== 2. символы клавиатурные =="
python3 "$repo/hooks/check-symbols.py" "$run" "$repo/skills/goal-loop/test.sh" \
    "$repo/skills/goal-loop/SKILL.md" "$repo/docs/tasks/DK-096.md"
ok "запрещённых символов нет"

echo "== 3. цикл до маркера done: витки, журнал оболочки, снятый замок =="
p="$sand/done"
stand "$p"
mkdir -p "$sand/bin"
cat > "$sand/bin/claude" <<'EOF'
#!/bin/sh
n=$(cat "$STAND/n" 2>/dev/null || echo 0); n=$((n + 1)); printf '%s\n' "$n" > "$STAND/n"
printf -- '- виток %s, задача цели закрыта\n' "$n" >> "$STAND/done/docs/tasks/DK-100.md"
[ "$n" -lt 3 ] && { printf 'marker: continue\n'; exit 0; }
printf 'marker: done\n'
EOF
chmod +x "$sand/bin/claude"
STAND=$sand; export STAND
PATH="$sand/bin:$PATH"; export PATH
"$run" DK-100 -C "$p" --foreground
log="$p/.devkit/goal-DK-100.log"
grep -q 'виток 1 маркер continue код 0' "$log" || bad "маркер continue не поднял следующий виток"
grep -q 'виток 3 маркер done код 0' "$log" || bad "цикл не дошёл до done"
grep -q 'остановлен: done' "$log" || bad "журнал оболочки не назвал, чем цикл кончился"
grep -q 'уровень громкий' "$HOME/.devkit/notify.log" || bad "стоп прошёл без громкого уведомления"
if [ -d "$p/.devkit/goal-DK-100.lock" ]; then bad "замок остался после цикла"; fi
ok "три витка, журнал с маркерами, громкое уведомление, замок снят"

echo "== 4. воронка: витки говорят continue и не пишут в «Журнал» =="
p="$sand/funnel"
stand "$p"
cat > "$sand/bin/claude" <<'EOF'
#!/bin/sh
n=$(cat "$STAND/fn" 2>/dev/null || echo 0); n=$((n + 1)); printf '%s\n' "$n" > "$STAND/fn"
[ "$n" -le 5 ] || { printf 'marker: done\n'; exit 0; }
printf 'marker: continue\n'
EOF
chmod +x "$sand/bin/claude"
code=0
"$run" DK-100 -C "$p" --foreground || code=$?
[ "$code" -eq 1 ] || bad "воронка вернула $code вместо 1"
[ "$(cat "$sand/fn")" -eq 3 ] || bad "воронка остановила цикл на витке $(cat "$sand/fn"), а порог три"
grep -q 'остановлен: воронка' "$p/.devkit/goal-DK-100.log" || bad "воронка не названа в журнале"
ok "стоп ровно на третьем пустом витке, код 1"

echo "== 5. замок: вторая оболочка той же цели отказывает =="
p="$sand/lock"
stand "$p"
cat > "$sand/bin/claude" <<EOF
#!/bin/sh
"$run" DK-100 -C "$p" --foreground > "\$STAND/second.out" 2>&1
printf 'код %s\n' "\$?" >> "\$STAND/second.out"
printf 'marker: done\n'
EOF
chmod +x "$sand/bin/claude"
"$run" DK-100 -C "$p" --foreground > /dev/null
cat "$sand/second.out"
grep -q 'уже идёт' "$sand/second.out" || bad "вторая оболочка не отказала"
grep -qx 'код 3' "$sand/second.out" || bad "отказ второй оболочки вернул не 3"
ok "идущий цикл заперт, вторая оболочка отказала кодом 3"

echo "== 6. отказ на старте при autonomous = false =="
p="$sand/manual"
stand "$p"
printf 'deploy = true\nautonomous = false\n' > "$p/.devkit/deploy.local"
code=0
"$run" DK-100 -C "$p" --foreground || code=$?
[ "$code" -eq 2 ] || bad "оболочка пошла при autonomous = false, код $code"
ok "цикл без выката не стартует, код 2"

echo "== 7. оболочка названа в доке =="
grep -q '## Оболочка goal-run' "$repo/skills/goal-loop/SKILL.md" || bad "скилл не описывает оболочку"
grep -q 'goal-run.sh' "$repo/README.md" || bad "README не называет оболочку"
grep -q 'skills/goal-loop/test.sh' "$repo/README.md" || bad "README не называет прогон тестов оболочки"
grep -q 'skills/goal-loop/test.sh' "$repo/.github/workflows/ci.yml" || bad "тесты оболочки не в CI"
ok "скилл, README и CI знают про оболочку"

rm -rf "$sand"
echo "СЦЕНАРИЙ ПРОЙДЕН"
```

Ожидаемый итог: каждый шаг печатает свой `OK:`, последняя строка «СЦЕНАРИЙ
ПРОЙДЕН», код возврата 0. Уведомитель на синтетике честно молчит и говорит,
почему: корень проекта лежит под `TMPDIR`, и живой баннер про песочницу был бы
ложным, а сам вызов виден строкой в его журнале.
