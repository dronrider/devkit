# DK-097: скилл live-core: порог, канал через порядок devkit, границы

## Ход работы

- Исполнение: субагент opus/medium по вердикту pick (квота: week_all 2%, снимок 4м назад, сдвига нет), 2026-08-03.
- Скилл написан по разделу «Правка ядра по ходу цели: live-core» в
  `docs/lld/DK-079-autonomous-loop.md`, форма и тон по соседнему `board-batch`.
- Дизайн уточнён в двух местах, оба всплыли при обкатке команд:
  - скиллы из клона сразу не действуют. На машину они уезжают копией в
    `~/.claude/skills`, кладёт её `devkitctl doctor --fix` из основного
    чекаута, а из worktree ветки задачи доктор класть отказывается нарочно.
    Из клона сразу работают только хуки и файлы правил, они зовутся по пути;
  - у `taskctl` флаг `-C` общий и разбирается до подкоманды, поэтому черновик
    заводится как `taskctl -C ~/projects/devkit draft "..."`. Форма из LLD
    (`taskctl draft -C ...`) увела бы черновик на доску проекта.
  Обе правки внесены в LLD там же, плюс «строка на его доске» заменена на
  «строки у мелочи нет»: по `RULES.board.md` мелочь идёт в main без строки.
- Дока: README devkit, состав `skills/` пополнен `live-core`.

## Сценарий проверки

Агентский. Скрипт `docs/tasks/DK-097-check.sh` гоняет машинные шаги скилла на
синтетическом окружении: временный HOME, временный клон devkit, пустой проект.
Живой `~/.claude`, живая доска devkit и бинари в PATH не трогаются, шестой шаг
нарочно возвращает настоящий HOME и работает в чекауте (уведомитель молчит из
временной директории, и в клоне тесты хуков упали бы не по делу).

```bash
sh docs/tasks/DK-097-check.sh
```

Ожидание: код 0 и шесть шагов подряд. Скилл на месте и без неклавиатурных
символов; `doctor --fix` кладёт `live-core` на машину; из worktree ветки задачи
не кладёт и говорит почему; черновик по `-C` уходит на доску devkit, а у
проекта накопителя не появляется; пересобранный бинарь выигрывает в PATH;
полный прогон тестов devkit зелёный.
