# DK-100: Дерево контекста: тонкий резидентный корень, правила скиллами и хуками

## Что происходит

Замер расхода claude-code за 5.07-3.08 (по jsonl-журналам сессий, скрипты
остались в сессии от 3.08): 7,67 млрд токенов, $8 693 в пересчёте на ставки
API. Чтение кеша это 96,5% объёма и 54% денег ($4 717), запись кеша на часовом
TTL ещё 26% ($2 264). Контекст одного запроса: медиана 128k токенов, среднее
182k, p90 394k; запросы с контекстом от 200k (30% штук) несут 61% объёма,
сабагенты 30%.

Резидентная цепочка devkit (CLAUDE.md со всеми импортами: RULES.md,
RULES.board.md, AGENTS.md, MEMORY.md) весит ~53k символов, порядка 20k токенов,
и едет в каждом из 42 тысяч запросов месяца: ~0,85 млрд токенов только на
постоянный хвост. Смежная
DK-029 предлагает порог на вес этой части в doctor; порог охраняет от роста,
но сам вес не снижает.

## Чего хотим

Контекст грузится деревом, а не целиком. Корень тонкий: критический список
строк на тридцать плюс указатели. Остальное по требованию:

- RULES.board.md уезжает в скилл, который грузится при работе с доской;
- стилевые правила по возможности переезжают из прозы в хуки-энфорсеры
  (check-symbols уже так работает: правило действует, контекст не занимает);
- вопрос уровня «какая погода» в проектной директории не тянет весь свод
  правил.

## Развилки дизайна

- Состав критического ядра: что перестаёт работать, если правила нет в
  контексте, а хука на него нет. Потерю послушания мерить, а не предполагать.
- Харнессы без механизма скиллов: им генератор вклеивает правила в AGENTS.md
  между маркерами, тонкий корень оставит их без правил вовсе. Видимо, для них
  вклейка остаётся полной, дерево только для Claude Code.
- Резать префикс на живой сессии нельзя: инвалидация превращает чтение (0.1x
  ставки ввода) в перезапись (1.25-2x), а cw1h уже вторая статья расхода.
  Дерево должно менять то, что грузится на старте сессии, а не середину.
- Границы эффекта: пол не срезается (системный промпт харнесса и схемы тулов),
  а главный вклад в объём даёт не резидент, а история сессий (жирные tool
  results, длинные сессии без /clear); дизайн должен назвать, что из этого
  берёт на себя devkit (правила чтения? определения exec-агентов?), а что
  остаётся дисциплиной.
- Стык с DK-029: порог doctor логично считать уже по новому тонкому корню.

## DoD

- LLD в docs/lld/ с решением по каждой развилке выше;
- посчитан ожидаемый эффект в токенах на запрос и в долях месячного объёма;
- план миграции генератора (devkitctl doctor --fix) и скиллов, разбитый на
  задачи доски.

## Ход работы

- Исполнение: субагент opus/xhigh по вердикту pick (квота: week_all 4%, снимок 1м назад, сдвига нет), 2026-08-03.
- Ревью: субагент opus/xhigh по вердикту pick (квота: week_all 4%, снимок 20м назад, сдвига нет), 2026-08-04.
- Дизайн написан: [LLD дерева контекста](../lld/DK-100-context-tree.md), пять
  развилок постановки сняты, эффект посчитан, разбивка на семь задач,
  2026-08-04.
- Вес резидента замерен, а не взят с потолка: headless-прогоны `claude -p` в
  пустой директории и в директории с импортом одного файла правил дают цену
  файла в токенах (`RULES.md` 5 006, `RULES.board.md` 7 078), отсюда
  коэффициент 2,45 символа на токен. Сверено с первым запросом живой сессии
  из журнала (42 918 токенов на старте) и с разбором журналов за окно
  постановки. Две поправки к вводным: «53k символов» это байты (символов
  32 108), а цепочка правил весит ~13,1 тысячи токенов, не 20; зато два
  кармана постановка не считала вовсе (описания определений `agents/` и
  описания скиллов), с ними резидент devkit это 14,3 тысячи, 2026-08-04.
- Цена перезаписи префикса подтверждена замером по журналу: в сессии из 102
  запросов префикс переписывался дважды, второй раз на 350 903 токена по
  истечении часового TTL. Отсюда запрет дизайна на механизмы, правящие голову
  контекста посреди сессии, 2026-08-04.

## Сценарий проверки

Сценарий пользовательский: выката нет, дизайн читает пользователь. Проверить
по [LLD](../lld/DK-100-context-tree.md):

1. Каждая из пяти развилок постановки снята явным решением с причиной: состав
   критического ядра (таблица правил с механизацией и тем, что теряется без
   текста, плюс стенд `obeycheck`, которым потеря послушания меряется, а не
   предполагается), харнесы без скиллов (вклейка остаётся полной, глубину
   выбирает новая секция `[skills]` профиля, а не код по имени инструмента),
   запрет на смену состава посреди сессии (три утверждения и подпись
   перезаписи в журнале, по которой это проверяется), границы эффекта (пол
   ~27,9 тысячи токенов, доля резидента в среднем запросе ~6%, что берёт на
   себя devkit и что остаётся дисциплиной), стык с DK-029 (что мерить, откуда
   порог, второй порог на тело скилла).
2. Цифры эффекта прослеживаются до замера, а не до предположения: раздел
   «Сколько весит резидент» называет способ замера каждого куска, а раздел
   «Ожидаемый эффект» называет мягкие места оценки.
3. Разбивка исполнима: у каждой задачи заголовок, тип, разбивка ранга по
   шкалам `RANKING.md`, цена и предпосылки; инвариант зависимости соблюдён
   (ранг предпосылки не ниже зависимой), стенд послушания стоит первым, потому
   что без него разрез принимается на глаз.
4. Затрагиваемая долгоживущая дока перечислена по разделу «Документация
   изменений» `RULES.md`.

Задача проходит, когда дизайн принят пользователем; серия реализации заводится
на доске отдельным шагом после приёмки.
