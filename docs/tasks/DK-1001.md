# DK-1001: Пакет dashboard красит на -count 3 целиком, врозь зелёный

## Что происходит

`GOWORK=off go test -C tools/dashboard -count 3 ./...` красит двумя тестами.
`TestDraftGroomDeathSaid` (`chatdeath_test.go:235`) говорит «смерть разбора не
легла в журнал задачи». `TestBindsWithoutTheLog` (`registry_test.go:367`)
говорит «пустой реестр» и показывает чужие записи внутри. По одному оба теста
зелёные и при `-count 3`, это проверено отдельным прогоном только этой пары.
Красит связка «весь пакет плюс несколько повторов в одном процессе». Сосед по
пакету оставляет состояние, не убранное между повторами, а не эти два теста
держат его сами на себе.

Найдено по ходу DK-998, обкаткой сценария проверки в свежем дереве.
`taskctl rehearse` там гонял пакет `-count 3`, и находка не про предмет
DK-998, там правка только `cache_test.go`. Сценарий DK-998 переписан на три
отдельных запуска вместо `-count 3` внутри одного.

## Чего хотим

Полный прогон пакета `tools/dashboard` с `-count` больше единицы не красит.
Либо повторяемый тест убирает за собой глобальное состояние, либо у него
находится причина, почему делить его с соседями по процессу нельзя, и она
решена явно (пакетный `TestMain` со сбросом состояния между повторами,
например).

## DoD

- `GOWORK=off go test -C tools/dashboard -count 3 ./...` зелёный;
- причина красноты найдена и названа: общее состояние, гонка или порядок
  тестов.

## Ранг

`0+0+3+5+2 = 10`, P3.

- серьёзность 0. Обычный прогон (`-count 1`, отдельные запуски) не красит;
- ценность 0. Пользователь ничего не замечает;
- неопределённость 3. Кто из соседей по пакету оставляет состояние, не
  найдено, разбор только начат;
- поправка на баг +5;
- рычаг 2. Мешает тому, кто прогонит пакет повтором в одном процессе, как
  обкатка DK-998.

## Ход работы

- Найдено по ходу DK-998. `taskctl rehearse` погнал сценарий с
  `-count 3 ./...`, упали `TestDraftGroomDeathSaid` и
  `TestBindsWithoutTheLog`. Прогон одной этой пары с `-count 3` в изоляции
  зелёный, красит только связка с остальным пакетом.
- Причина нашлась в стенде запуска. `TestRunStartKeepsSessionBesidesUserCheck`
  поднимал голову задачи без подмены машинного дома (`useHeadHome`), и подъём
  писал строку реестра в запасной дом всего прогона, общий для повторов
  `-count`. На повторе `TestBindsWithoutTheLog` видела чужие записи.
  `TestDraftGroomDeathSaid` отдавала смерть разбора прежнему жильцу имени
  `task-XR-005`: адресата смерти `chatDeathSay` ищет по реестрам обоих домов,
  и чужая запись оказалась свежее. На `-count 1` связка зелёная только
  порядком файлов, писатель живёт в `runs_test.go`, жертвы раньше него по
  алфавиту.
- Починено подменой дома в самом стенде, а пустота запасного дома стала
  рубежом. `TestMain` роняет прогон с найденными строками, тест-сторож
  `TestBindsSecondHomeStaysEmpty` краснеет на писателе в одном прогоне с ним.
  Краснота сторожа на старом коде доказана regcheck (`--tests` везёт
  `tasks_test.go` целиком, правка стенда остаётся в `runs_test.go`).
- Полный набор тестов прогнан с `-count 3` четырьмя частями по именам. Одна
  команда целиком не влезает в потолок прогона одного захода, три повтора
  пакета занимают около 23 минут. Точечная связка «писатель, обе жертвы,
  сторож» зелёная на `-count 3` в одном процессе.
- Сторож прозы: docs/tasks/DK-1001.md, средняя длина предложения 20,6 при
  пороге 19, оставлено: длинные строки сценария это команды sh-блока.
- Сторож прозы: docs/tasks/DK-1001.md, предложений длиннее 25 слов 42,9 при
  пороге 30, оставлено: то же, команды прогона не режутся.
- Сторож прозы: docs/tasks/DK-1001.md, двоеточие в середине фразы 13,9 на
  1000 слов при пороге 11, оставлено: двоеточия ходят в командах шагов.

## Сценарий проверки

Агентский, стоит на воспроизведении. На коде до правки сторож краснеет, на
текущем полный прогон с повторами зелёный.

1. Краснота на коде до правки: regcheck везёт сторож из `tasks_test.go` на
   базу, тест краснеет там и проходит на текущем коде:

```sh
GOWORK=off regcheck --base 118a2ac98 --tests tools/dashboard/tasks_test.go -- go test -C tools/dashboard -count 1 ./...
```

2. Полный прогон пакета тремя повторами одним процессом. Три повтора это
   около 23 минут, срок теста в шаге поднят явно:

```sh
GOWORK=off go test -C tools/dashboard -count 3 -timeout 40m ./...
```

3. Как раньше и не сломалось: одиночный прогон пакета зелёный:

```sh
GOWORK=off go test -C tools/dashboard -count 1 ./...
```
