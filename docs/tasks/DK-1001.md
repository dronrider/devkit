# DK-1001: Пакет dashboard красит на -count 3 целиком, врозь зелёный

## Что происходит

`GOWORK=off go test -C tools/dashboard -count 3 ./...` красит двумя тестами.
`TestDraftGroomDeathSaid` (`chatdeath_test.go:235`) говорит «смерть разбора не
легла в журнал задачи». `TestBindsWithoutTheLog` (`registry_test.go:367`)
говорит «пустой реестр» и показывает чужие записи внутри. По одному оба теста
зелёные и при `-count 3`, это проверено отдельным прогоном только этой пары.
Красит связка «весь пакет плюс несколько повторов в одном процессе». Сосед по
пакету оставляет состояние, не убранное между повторами, а не эти два теста
держат его сами на себе.

Найдено по ходу DK-998, обкаткой сценария проверки в свежем дереве.
`taskctl rehearse` там гонял пакет `-count 3`, и находка не про предмет
DK-998, там правка только `cache_test.go`. Сценарий DK-998 переписан на три
отдельных запуска вместо `-count 3` внутри одного.

## Чего хотим

Полный прогон пакета `tools/dashboard` с `-count` больше единицы не красит.
Либо повторяемый тест убирает за собой глобальное состояние, либо у него
находится причина, почему делить его с соседями по процессу нельзя, и она
решена явно (пакетный `TestMain` со сбросом состояния между повторами,
например).

## Ранг

`0+0+3+5+2 = 10`, P3.

- серьёзность 0. Обычный прогон (`-count 1`, отдельные запуски) не красит;
- ценность 0. Пользователь ничего не замечает;
- неопределённость 3. Кто из соседей по пакету оставляет состояние, не
  найдено, разбор только начат;
- поправка на баг +5;
- рычаг 2. Мешает тому, кто прогонит пакет повтором в одном процессе, как
  обкатка DK-998.
