# DK-1009: Чат цели идёт дорогой задачи: сессия первой репликой, запуск лестницей носителей

## Что происходит

2026-09-15 пользователь зашёл в чат цели с её формы в дашборде. Цикл цели не шёл. Панель открыла разговор с плашкой «Цикл цели не идёт» и кнопкой «Поднять виток». Реплика из поля ввода легла строкой во «Входящие» файла цели. Ответа не было.

Так устроен код панели в static/app.js. Адрес цели без выбранного чата панель считает разговором с headless-оболочкой goal-run. Реплика уходит ручкой POST /goals/<ID>/message мимо сессии. Дорогу проложили правки DK-287, DK-319 и DK-938. У задачи та же панель без живой сессии поднимает новую первой репликой, и агент отвечает. Кнопка «Поднять виток» зовёт POST /runs и поднимает оболочку goal-run. У цели нет выбора носителя. README дашборда описывает это в разделе про подписку у кнопки запуска.

DK-971 закрыта 2026-09-14 и решена словом пользователя. Виток остаётся понятием одной оболочки goal-run. В живом чате витка нет вовсе. Сессия ведёт цель до стоп-маркера, ход держит hooks/goal-hold.py. В разделе «Цикл в чате» скилла goal-loop живой чат назван основным входом, а оболочка входом без чата. Дверь чата цели в дашборде осталась из мира до DK-971.

Пользователь пишет в чат цели и не получает ответа. Собеседника за дверью нет. Строка остаётся без ответа. Прогон оболочки никто не поднимал. Плашка с кнопкой подменяет разговор служебным щитком.

Слово пользователя 2026-09-15. Плашек подобных в чате быть не должно вовсе. Механика выполнения у задачи и цели одна. Разница между ними в объёме и в автономности. Цель это цепочка задач, и в её режиме агент сам выбирает шаги и заводит задачи.

## Чего хотим

Чат цели с формы и со строки доски ведёт себя ровно как чат задачи. Живая сессия цели открывается. Без неё первую реплику получает свежая сессия с привязкой к цели и отвечает. В чате нет плашек над полем ввода и кнопок подъёма. «Продолжай цель» в этом чате запускает цикл по goal-loop прямо в сессии, по решению DK-971.

## Границы

Носитель разговора цели не меняется, это DK-439, и она идёт после этой
строки. Раздел «Входящие» файла цели, отметки `.devkit/goal-<ID>.mail` и
подхват `hooks/chat-in.py` остаются за headless-путём. Лежащие строки живых
целей (DK-909 несёт непрочитанную) не трогаются. Сами плашки и кнопку
«Поднять виток» из панели снимает DK-957, эта строка идёт после неё. Условий,
посильных только человеку, не нашёл. Правка живёт в статике дашборда, его
go-сервере, тестах, README и пересмотрах LLD, доступов и секретов ей не нужно.

## DoD

- Дверь чата цели с формы цели и со строки доски идёт дорогой задачи. Живой
  разговор по цели открывается. Без него первая реплика поднимает сессию с
  привязкой к цели через `POST /chats`, и она отвечает. Открытие панели без
  реплики сессию не поднимает.
- При живой headless-оболочке `goal-run` дверь открывает её транскрипт, реплика
  доезжает подхватом, вторая сессия рядом не поднимается, пока жив замок.
- Цели не отказано в имени разговора и в реплике в сессию. Ветки
  `isGoalTitle` в `sessionChatName` и `handleTaskMessagePost` сняты, ручка
  `/goals/{id}/message` остаётся только у headless-пути до DK-439.
- Кнопка запуска цели идёт лестницей носителей `taskctl run`, как у задачи.
  Ступень чата поднимает сессию с заказом «продолжай цель <ID>», headless-ступень
  поднимает `goal-run`. Отказ «у цели выбора нет» снят с ручки и из README.
- Тест `TestStaticGoalChatReplyToInbox` переписан под новый инвариант, новый
  стенд держит подъём сессии первой репликой, браузерный стенд
  `TestBrowserGoalChatOpensLoop` зелёный.
- README дашборда описывает одну дверь чата для задачи и цели. LLD DK-430
  (решение 6) и DK-136 (раздел «Что видит человек») получают пересмотр с датой
  и ссылкой на эту строку.

цели. У стоящего цикла первая реплика поднимает сессию через `POST /chats`.
