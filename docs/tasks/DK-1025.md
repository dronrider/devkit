# DK-1025: Стенд по правилу ядра гоняет раскладку без ядра

## Что происходит

Генератор `tools/devkitctl/rules.py --layout full` кладёт в раскладку
RULES.md и RULES.board.md, а RULES.core.md не кладёт. Строка импорта ядра
из глобальной точки снимается с пометкой «текст уже в раскладке». Причина в
том, что карта `deep` считает имя ядра покрытым полным текстом. Замечено 16
сентября 2026 года на прогонах по DK-1022. RULES.md разбирает правила, а
сами правила лежат в ядре. В пункте про мимикрию он так и пишет: «само
правило стоит в ядре». Из пятнадцати предложений раздела «Мимикрия» ядра
десяти в RULES.md нет, в том числе фразы «перед письмом взять выборку
скиллом prose». В RULES.md поводом для prose названы комментарии, MR и LLD,
без README и черновика. Раскладка глубины core ядро везёт домашним
импортом, `home/projects/devkit/RULES.core.md`. На живой машине в контексте
оба файла, ядро глобальной точкой и полный текст тонким файлом проекта.

Все замеры на раскладке full шли без фразы ядра. Отметка DK-808 по
`15-mimicry-readme` 5/5 на base, прогоны DK-1022 на mini. Результат стенда
про правила ядра на full на живую машину не переносится. Пара «full против
core» меряет разбор без ядра против ядра.

### Что нашёл разбор

Разбор сверен 2026-09-16 на прогоне генератора по
`tools/obeycheck/testdata/project`. Full кладёт RULES.md и RULES.board.md,
строку ядра снимает. Core везёт ядро домашним импортом, и фраза «взять
выборку из корпуса эталонов скиллом prose» лежит только в core. Оба
включённых харнеса объявляют `discovery = "auto"`, и генератор выводит из
этого глубину core. На живой машине в контексте ядро и
RULES.board.core.md, а RULES.md не лежит вовсе. Фраза ситуации про «оба
файла на машине» этим снимается. Харнеса глубины full сегодня нет.

Состав full без ядра это решение DK-104 («ядро и полный текст никогда не
лежат в контексте вместе»). Сценарий проверки той задачи включает строку
`[ ! -f full/RULES.core.md ]`, а тест `test_global_point_naming_the_core_directly`
в `tools/devkitctl/rules_test.py` проверяет то же. Гипотеза черновика это
пересмотр DK-104.

Скилл `prompt-test`, раздел «Раскладки», требует пару full для любой правки
промпта. Отметка `obeycheck --task` при предмете, которого нет в
раскладке-кандидате, пишет предупреждение и всё равно ложится зачтённой.
DK-996 несёт две такие отметки по 27-work-plan, DK-808 симметричную по
RULES.md на core. Отметок по сценариям с предметом в ядре 13, в двух файлах
задач, DK-808 и DK-996. У сценария 18-comment-typology предмет есть только
в RULES.md, на core он непроверяем.

Соседи: DK-408 (контрольная ветка без правил), DK-663 (ядро у субагента),
DK-877 (full без страниц корня), DK-815 (карман ядра у doctor) не дубли.
DK-1022 это запись, из которой черновик вырос.

## Чего хотим

Генератор остаётся по DK-104. Full везёт разбор без ядра, а живая машина
глубины core меряется раскладкой core. Скилл prompt-test выбирает глубину
пары по предмету сценария. Обе раскладки для страницы ядра собираются как
core, а full остаётся сценарию, чей предмет целиком лежит в полном тексте.
У трёх смешанных сценариев предмет из RULES.md снимается, правило на машине
читают из ядра. Отметка `obeycheck --task` с предметом, которого в
раскладке-кандидате нет, не пишется. В строке вывода генератора на full
вместо «текст уже в раскладке» стоит причина снятия ядра.

## Границы

- Состав раскладки full не меняется, решение DK-104 в силе; гипотеза «full
  как машина глубины full» не делается.
- Прошлые отметки не перепроверяются, развилка «отметки».
- Контрольная ветка без правил остаётся черновику DK-408.

## Сценарий проверки

Первый шаг воспроизводит поломку. До правки строка вывода генератора на full
говорила «текст уже в раскладке», а ядра в раскладке не было. Глобальная
точка собирается во временном HOME, как на живой машине.

```sh
mkdir -p "$HOME/.claude" "$HOME/nested-devkit"
cp RULES.core.md "$HOME/nested-devkit/RULES.core.md"
printf '<!-- devkit:generated body=stub -->\nстенд\n\n@~/nested-devkit/RULES.core.md\n' > "$HOME/.claude/CLAUDE.md"
python3 tools/devkitctl/rules.py --layout full "$HOME/rules-full" tools/obeycheck/testdata/project | grep 'RULES.core.md снят, ядро на глубине full не едет (DK-104), вместо него RULES.md'
test "$(python3 tools/devkitctl/rules.py --layout core "$HOME/rules-core" tools/obeycheck/testdata/project | grep -c снят)" = 0
grep -rq 'взять выборку из корпуса эталонов скиллом' "$HOME/rules-core"
test "$(grep -rl 'взять выборку из корпуса эталонов скиллом' "$HOME/rules-full" | wc -l)" = 0
! obeycheck --task DK-1025 --only 15-mimicry-readme -k 3 --base пусто "$HOME/rules-full" "$HOME/rules-core" > "$HOME/refuse.txt" 2>&1
grep 'след не пишется' "$HOME/refuse.txt"
git diff --quiet -- docs/tasks/DK-1025.md
test "$(obeycheck --list | grep -c 'RULES.md «')" = 1
grep -q 'layout core ../rules-with' kit/skills/prompt-test/SKILL.md
```

Ожидание. Генератор на full называет причину снятия ядра, на core ничего не
снимает. Фраза ядра о выборке скиллом prose лежит только в раскладке core.
Стенд с `--task` на раскладке full отказывает до первой сессии. Предмет в
RULES.md остался у одного сценария, 18-comment-typology. Пример скилла
собирает пару core.
