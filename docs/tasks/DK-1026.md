# DK-1026: стенд devkitctl падает: .git/objects песочницы исчезает под обходом

## Что происходит

16 сентября 2026 года полный прогон тестов на `shipctl merge DK-1023` упал на
компоненте devkitctl: 31 ошибка из 838 тестов. Отдельный прогон
`python3 -m unittest discover` в `tools/devkitctl` на main дал 27 ошибок.
Все ошибки в `tearDown` (`testenv.py:701`). Отпечаток `fingerprint()`
обходит `self.dk.rglob("*")` (`testenv.py:659`) и падает с
`FileNotFoundError` на каталоге `<песочница>/devkit/.git/objects/XX`. Каталог
`.git` отпечаток выбрасывает после обхода, а не до него. Класс
`drain_test.DrainReportTest` поодиночке проходит, в полном прогоне даёт три
ошибки. Утром того же дня полный прогон проходил, DK-1018 закрыта.

Ворота слияния красные у любой задачи, пока стенд падает. DK-1023 и DK-603
стоят в In progress с чистым ревью. Кто удаляет каталоги объектов во время
обхода, пока неизвестно, разбор идёт.

### Разбор 2026-09-16

Каталоги удаляет сам git. `git commit` в `Sandbox.__init__` (`testenv.py`,
строки 462-465) порождает отсоединённый `git maintenance run --auto --detach`,
тот зовёт `git repack -d --cruft --write-midx`, и через секунду после возврата
`commit` все 256 каталогов `objects/XX` сгребаются в пак. Срабатывание зависит
от числа россыпных объектов в каталоге `objects/17`, у песочницы их около
пяти, и репак стартует почти всегда. Событие снаружи: 12 сентября обновились
Command Line Tools, git в них 2.54.0. Правок кода за падением нет, последняя
правка `testenv.py` это 2c309797 от 13 сентября.

Вторая половина причины в обходе. `fingerprint` (`testenv.py:659`) ходит
`rglob("*")`, а `.git` выбрасывает фильтром по результату, не по обходу, и
`scandir` заходит в каталог, которого уже нет.

Настройка `gc.auto 0` на этом git не помогает, репак идёт через maintenance.
Помогает только `maintenance.auto false`.

Воспроизведение без слияния: `cd tools/devkitctl && GOWORK=off python3 -m
unittest -q describe_test`, три прогона подряд дают 12, 3 и 5 ошибок из 16.

## Чего хотим

Полный прогон тестов devkitctl на main зелёный, отпечаток песочницы не зависит
от того, что git делает внутри `.git`.

## Развилки

Кто переупаковывает `.git` песочницы во время `tearDown`: отсоединённый gc
самого git, команда devkitctl или процесс соседнего теста? Чинить обход
отпечатка, чтобы он не заходил в `.git`, или настройку git песочницы?

## DoD

- `fingerprint` в `testenv.py` не заходит в `.git` и `__pycache__`: обход
  `os.walk` с отсечкой каталогов вместо фильтра по результату `rglob`. Набор
  путей в отпечатке тот же, что и раньше.
- `git_init` песочницы ставит `maintenance.auto false`: репак песочнице не
  нужен, и он же не мешает другим обходам.
- `describe_test` и пара `harness_test layout_test` зелёные три прогона
  подряд. Краснота: старый обход на том же наборе падает.
- Полный прогон компонента devkitctl зелёный.
