# DK-1046: Службы и выкат находят go в PATH сами

## Что происходит

2026-09-18, выкат поезда DK-1043. `shipctl ship` упал строкой «go в PATH нет,
собирать нечем». Go на машине стоит в `/usr/local/go/bin`. Этого каталога нет
в PATH сессии. Нет его и в ключе `EnvironmentVariables` plist службы
`ru.devkit.dashboard`, откуда выкат поднимается тиком. С прописанным
`PATH=/usr/local/go/bin:$PATH` тот же `shipctl ship` прошёл с первого раза.

Правка второго круга DK-1043 пролежала слитой на main с 10:16 до 11:14 и на
прод не попала. Тиковый `shipctl ship --drain` каждые пять минут молчал нулём.
Сценарий проверки этого тоже не поймал. Агентская часть гоняет тесты рабочего
дерева и прода не трогает. Приёмка успела отметить smoke на сборке без правки.

## Чего хотим

Выкат проходит без ручного PATH на любой машине, где Go стоит мимо
`/usr/local/bin`. Нехватку Go видно диагностикой заранее.

сессии самого доктора, живое окружение службы это тема открытой DK-848.

## Из черновика DK-1030 «Сессия, поднятая заново, не находит go в PATH» (записан 2026-09-17)

### Черновик

#### Ситуация

Наблюдение соседней сессии в другом проекте, 16 сентября 2026 года. После
подъёма заново в PATH сессии нет `/usr/local/go/bin`, сборка и тесты go
падают на «command not found». Чем сессия поднималась, дашбордом, tmux или
`--resume` из терминала, не уточнено. На доске DK-587 про devkitctl из PATH
и DK-1014 про claude в Bash субагента, про PATH самой сессии записи нет.
Дашборд под launchd живёт с системным PATH и дописывает его только под
taskctl и tmux (`tools/dashboard/board.go`, комментарии у строк 37 и 615).

#### Осложнение

Агент в такой сессии либо чинит окружение вместо задачи, либо пишет
исключение для тестов. Тест, не прогнанный из-за PATH, неотличим от
пропущенного.

#### Вопрос

Уточнить у соседней сессии вход, которым её подняли. Какой PATH у
tmux-сервера, поднятого из launchd, и наследует ли его сессия. Брать PATH
при спавне из профиля пользователя (login shell) или дописывать известные
каталоги тулчейнов.

#### Гипотеза

Сессия, поднятая любым входом, видит тот же PATH, что терминал пользователя,
а расхождение это находка `devkitctl doctor`.

#### Приписка 2026-09-17, пачка мелких задач

Симптом у regcheck: без go в PATH он отвечает «тест не проходит на текущем коде» и кладёт пустой файл вывода, а «command not found» не виден нигде. У shipctl merge то же: раннер параллельных тестов падает трейсом FileNotFoundError на go. Обход у обоих один, PATH=/usr/local/go/bin:$PATH перед вызовом.

#### Приписка 2026-09-17: повтор на DK-1022

Исполнитель и ревьювер DK-1022 звали каждый go test и shipctl merge с явным PATH=/usr/local/go/bin, тот же симптом у обоих.

#### Приписка 2026-09-18

Четвёртый случай, уже на выкате. Автоматика конвейера (разлив поезда по тику, 03:17) запустила `shipctl ship`, команда выката `devkitctl build` отказала «go в PATH нет: собирать нечем», ship упал, `taskctl fail` пометил голову поезда DK-1025 провалом проверки, и очередь встала целиком. Сборка руками с /usr/local/go/bin в PATH прошла, прод цел, признак снят `taskctl fail --clear`. Окружение тика не совпадает с окружением человека, и go туда не попадает.
