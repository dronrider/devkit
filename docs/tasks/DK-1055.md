# DK-1055: obeycheck --task пишет след в дерево, названное --devkit

## Что происходит

2026-09-18, DK-464. Исполнитель в дереве задачи позвал `obeycheck --task DK-464 --devkit <дерево задачи> ...` без смены каталога. Утилита нашла корень через `git rev-parse --show-toplevel` от cwd процесса и записала след прогона в docs/tasks/DK-464.md основного чекаута. Исполнитель заметил по выводу и откатил файл, обходится это связкой `cd <дерево> && obeycheck ...`.

Субагентам основной чекаут запрещён, а cwd между вызовами оболочки у них сбрасывается в него же. След стенда уезжает не в ту ветку, ворота слияния его не видят, а в основном чекауте остаётся незакоммиченная правка файла задачи, которую ловит следующий `shipctl`.

## Чего хотим

След прогона ложится в дерево, названное `--devkit`, а без ключа утилита говорит, в какой файл пишет, до прогона моделей.

## Границы

Корень в `tools/obeycheck/main.go`: `taskFile` получает точку вместо корня, уже вычисленного из `--devkit`. Поиск от cwd задуман осознанно (комментарий у `taskFile`, зеркало `logRun`), поэтому случай, когда в дереве `--devkit` файла задачи нет, остаётся: утилита берёт дерево текущего каталога и называет путь. Соседние черновики DK-907 и DK-921 про то, что стенд видит с машины, сюда не входят. Условий, посильных только человеку, обход не нашёл: искал в коде obeycheck и в сценариях.

## Развилки

- «запасной»: где искать файл задачи, когда в дереве --devkit его нет?
  - решает: исполнитель
  - рекомендация: сперва дерево --devkit, потом дерево cwd, путь называется до прогона
  - вариант: только дерево --devkit, без запасного пути
  - источник: код tools/obeycheck/main.go и tasknote.go

## DoD

- С ключом `--devkit` след ложится в `docs/tasks/<ID>.md` названного дерева, cwd на это не влияет.
- Путь файла следа печатается до прогона моделей. Когда задачи нет ни в одном дереве, отказ приходит тоже до прогона.
- Тест на случай, когда `--devkit` и cwd это разные деревья, краснеет на старом коде, это проверено прогоном regcheck.
- README стенда и скилл prompt-test больше не советуют связку `cd <дерево> && obeycheck`.
