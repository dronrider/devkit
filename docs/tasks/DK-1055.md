# DK-1055: obeycheck --task пишет след в дерево, названное --devkit

## Что происходит

2026-09-18, DK-464. Исполнитель в дереве задачи позвал `obeycheck --task DK-464 --devkit <дерево задачи> ...` без смены каталога. Утилита нашла корень через `git rev-parse --show-toplevel` от cwd процесса и записала след прогона в docs/tasks/DK-464.md основного чекаута. Исполнитель заметил по выводу и откатил файл, обходится это связкой `cd <дерево> && obeycheck ...`.

Субагентам основной чекаут запрещён, а cwd между вызовами оболочки у них сбрасывается в него же. След стенда уезжает не в ту ветку, ворота слияния его не видят, а в основном чекауте остаётся незакоммиченная правка файла задачи, которую ловит следующий `shipctl`.

## Чего хотим

След прогона ложится в дерево, названное `--devkit`, а без ключа утилита говорит, в какой файл пишет, до прогона моделей.

## Границы

Корень в `tools/obeycheck/main.go`: `taskFile` получает точку вместо корня, уже вычисленного из `--devkit`. Поиск от cwd задуман осознанно (комментарий у `taskFile`, зеркало `logRun`), поэтому случай, когда в дереве `--devkit` файла задачи нет, остаётся: утилита берёт дерево текущего каталога и называет путь. Соседние черновики DK-907 и DK-921 про то, что стенд видит с машины, сюда не входят. Условий, посильных только человеку, обход не нашёл: искал в коде obeycheck и в сценариях.

## Развилки

- «запасной» (решена): где искать файл задачи, когда в дереве --devkit его нет?
  - решает: исполнитель
  - рекомендация: сперва дерево --devkit, потом дерево cwd, путь называется до прогона
  - вариант: только дерево --devkit, без запасного пути
  - источник: код tools/obeycheck/main.go и tasknote.go
  - решено агентом 2026-09-19: сперва дерево --devkit, потом дерево cwd тем же путём, каким стенд ищет журнал прогонов; путь до прогона моделей печатается сразу после разрешения

## DoD

- С ключом `--devkit` след ложится в `docs/tasks/<ID>.md` названного дерева, cwd на это не влияет.
- Путь файла следа печатается до прогона моделей. Когда задачи нет ни в одном дереве, отказ приходит тоже до прогона.
- Тест на случай, когда `--devkit` и cwd это разные деревья, краснеет на старом коде, это проверено прогоном regcheck.
- README стенда и скилл prompt-test больше не советуют связку `cd <дерево> && obeycheck`.

## Сценарий проверки

Первый шаг воспроизводит исходную поломку из «Что происходит». Команда
`--devkit <дерево>` зовётся из чужого каталога, без `cd` в дерево задачи.
Дерево `--devkit` держит синтетический файл задачи и текст предмета. Дерево
cwd пустое. Раскладка-кандидат без текста предмета доводит стенд до отказа
раньше первой сессии, и текст отказа называет дерево, в котором нашёлся файл
задачи.

```sh
mkdir -p "$HOME/devkit-tree/docs/tasks" "$HOME/cwd-tree" "$HOME/scen" "$HOME/layout" "$HOME/bin"
git -C "$HOME/devkit-tree" init -q
git -C "$HOME/cwd-tree" init -q
printf '# Ядро правил\n\n## Тесты обязательны\n\nЛюбая правка кода едет вместе с тестами.\n' > "$HOME/devkit-tree/RULES.core.md"
printf '# DK-0001\n\n## Проверка\n\nШаги гоняются из корня чекаута.\n' > "$HOME/devkit-tree/docs/tasks/DK-0001.md"
cp tools/obeycheck/testdata/scenarios/press.md "$HOME/scen/press.md"
GOWORK=off go -C tools/obeycheck build -o "$HOME/bin/obeycheck" .
(cd "$HOME/cwd-tree" && "$HOME/bin/obeycheck" --devkit "$HOME/devkit-tree" --scenarios "$HOME/scen" --only press --task DK-0001 -k 3 --base пусто --agent-cmd false --no-preflight "$HOME/layout" "$HOME/layout" > "$HOME/out.txt" 2>&1); echo "код=$?"
cat "$HOME/out.txt"
grep -q 'текст предмета RULES.core.md «Тесты обязательны»' "$HOME/out.txt"
! grep -q 'а текущая директория не в репозитории' "$HOME/out.txt"
! grep -q 'нет ни в дереве --devkit' "$HOME/out.txt"
cat "$HOME/devkit-tree/docs/tasks/DK-0001.md"
```

Ожидание. Код возврата 2. Пустая раскладка-кандидат не несёт текста предмета
«Тесты обязательны», и стенд отказывает раньше первой сессии. Текст отказа
называет этот предмет, не репозиторий cwd. Файл задачи нашёлся в дереве
`--devkit`, хотя команда позвана из другого каталога. Файл
`docs/tasks/DK-0001.md` в дереве `--devkit` остаётся без следа прогона.
Отказ до сессии ничего не пишет.

Регрессия проверена прогоном `regcheck` с базой до правки:

```sh
regcheck -C tools/obeycheck --base 7231aad36089794e107ea7b145a8ba32c1dcc641 --tests tools/obeycheck/tasknote_bin_test.go -- go test -run TestTaskFileWritesToDevkitTreeNotCwd ./...
```
