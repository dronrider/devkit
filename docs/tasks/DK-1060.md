# DK-1060: shipctl двигает метку выката при включённой подписи тегов

## Что происходит

2026-09-19 18:09, слияние DK-1055. В 17:41 в глобальном git-конфиге машины появились `commit.gpgsign true`, `tag.gpgsign true` и `gpg.format ssh`. `shipctl merge` слил и запушил задачу, а на перестановке метки выката упал: «git tag: exit status 128 (fatal: no tag message?)». Подписанный тег аннотированный и требует сообщения, а `tools/shipctl/ops.go` зовёт `git tag -f deployed <sha>` без него (четыре вызова). Тег `deployed` и доска не сдвинулись, `shipctl status` видит DK-1055 поездом, ждущим выката.

С включённой подписью тегов не проходит ни один `merge` и ни один `ship`, конвейер стоит на каждой задаче. Обойти можно только правкой чужого git-конфига.

## Чего хотим

`shipctl merge` и `shipctl ship` двигают метку выката при любой настройке подписи в git, и конвейер без человека на ней не встаёт.

## Границы

Номер DK-1060 утилита выдала повторно: прежний черновик с этим номером приписан к DK-1058 разделом «Из черновика DK-1060», к этой задаче он не относится. Глобальный git-конфиг машины задача не трогает и настройку подписи не обходит для коммитов: без подписи ставится только служебная метка выката, как она ставится сегодня. Читатели метки (`hasTag`, диапазон `deployed..main` в ops.go и advice.go, `deployedIn`, `pushTag`) аннотированности не боятся, правка нужна только на записи, это четыре вызова в `tools/shipctl/ops.go`. Тесты shipctl заводят временные репозитории без подмены HOME и сами ставят тег `deployed` (ops_test.go), на машине с подписью они краснеют при обычном `go test`. Коммиты утилит (`commitBoard`, `taskctl` с ключом `-m`) под подписью работают, пока в ssh-агенте есть ключ, и этот случай сюда не входит. Условий, посильных только человеку, обход не нашёл: искал в tools/shipctl, internal/freshtree, архиве DK-274 и DK-306.

## Развилки

Служебная метка ставится без подписи (`--no-sign`, поведение как сегодня) либо аннотированным тегом с сообщением, который подпишется по настройке пользователя и на каждой перестановке потребует ключ?

- «метка»: как ставить служебную метку выката при включённой подписи тегов?
  - решает: исполнитель
  - рекомендация: git tag --no-sign -f: лёгкий неподписанный тег, поведение как сегодня, конвейер без человека не встаёт на запросе ключа
  - вариант: git update-ref refs/tags/deployed, прямая ссылка мимо любой политики подписи
  - вариант: аннотированный тег с сообщением, подпишется по настройке и на каждой перестановке потребует ключ в ssh-агенте
  - источник: код tools/shipctl/ops.go (вызовы git tag, hasTag, pushTag), tools/shipctl/ops_test.go
  - решено агентом 2026-09-19: git tag --no-sign -f: --no-sign введён в git 2.9 вместе с самим tag.gpgsign (одна и та же серия), значит машина, где включена подпись тегов, всегда несёт и флаг. Версию сужает не сильнее, чем сама причина бага, равносильный -c tag.gpgSign=false не понадобился.

## DoD

- `shipctl merge`, `shipctl ship` и откат двигают метку выката при `tag.gpgsign true` в git-конфиге, конвейер на ней не встаёт.
- Без подписи тегов поведение прежнее, метка остаётся лёгким тегом и по-прежнему уходит в origin.
- Регрессионный тест включает подпись тегов в конфиге временного репозитория, краснеет на старом коде и проходит на новом, это проверено прогоном regcheck.
- Тесты shipctl и соседних пакетов, которые ставят теги и коммиты во временных репозиториях, не зависят от подписи в глобальном конфиге машины.
- README shipctl говорит одной фразой, что служебная метка ставится без подписи и почему.

## Сценарий проверки

Первый шаг воспроизводит исходную поломку из «Что происходит». Во временном
репозитории с локально включённой подписью тегов голый `git tag -f` падает на
«no tag message?». Так падал `shipctl` на боевой машине. Дальше шаги проверяют
выбранный по развилке «метка» приём (`--no-sign`) на живом git. Последний шаг
гонит регрессионный тест `TestDeployTagUnderGPGSign` через `regcheck` с базой
на коммите до правки этой задачи.

```sh
rm -rf "$HOME/dk1060-scenario"
git init -q -b main "$HOME/dk1060-scenario"
git -C "$HOME/dk1060-scenario" config user.email t@example.com
git -C "$HOME/dk1060-scenario" config user.name t
git -C "$HOME/dk1060-scenario" config commit.gpgsign false
git -C "$HOME/dk1060-scenario" config tag.gpgsign true
printf 'a\n' > "$HOME/dk1060-scenario/a.txt"
git -C "$HOME/dk1060-scenario" add a.txt
git -C "$HOME/dk1060-scenario" commit -qm seed
git -C "$HOME/dk1060-scenario" tag -f deployed HEAD 2>"$HOME/dk1060-scenario-err.txt"; echo "код=$?"
grep -q 'no tag message' "$HOME/dk1060-scenario-err.txt"
git -C "$HOME/dk1060-scenario" tag --no-sign -f deployed HEAD
git -C "$HOME/dk1060-scenario" rev-parse --verify deployed
rm -rf "$HOME/dk1060-scenario" "$HOME/dk1060-scenario-err.txt"
regcheck -C tools/shipctl --base 5bd2c3dc4e5869e1ba75a0e7656255df3c378f4f -- go test ./... -run TestDeployTagUnderGPGSign
```
