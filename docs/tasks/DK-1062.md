# DK-1062: poc_chatwarm.mjs не завершается, живой polling списка чатов держит node

## Что происходит

Тест `TestStaticChatListWarmOnReturn` в `tools/dashboard/chat_test.go` зовёт
`testdata/poc_chatwarm.mjs` через `exec.Command(node, ...).CombinedOutput()`.
Скрипт печатает успешный результат, доходит до конца и вызывает
`sandbox.closeChat()` с `sandbox.closeAgentLive()`. Node-процесс после этого не
завершается сам. Прямой прогон `node testdata/poc_chatwarm.mjs static/app.js`
подтверждает: вывод печатается сразу, а процесс висит до `SIGTERM` внешнего
`timeout`.

Открытый в тесте список чатов заводит настоящий `setTimeout`-таймер
(`{ realTimers: true }` у `makeSandbox`) для перечитки состава. Ни
`closeChat()`, ни `closeAgentLive()` этот конкретный таймер не трогают, узел
ждёт его вечно. `CombinedOutput()` у Go-теста ждёт `EOF` от процесса и виснет
вместе с ним до потолка `go test` пакета. Найдена при слиянии DK-881: полный
прогон `go:dashboard` падал таймаутом почти на каждой попытке, изолированный
запуск теста воспроизвёл зависание за несколько секунд.

Соседние скрипты с тем же `realTimers: true` уже несут обход. `poc_bench_task.mjs`
и `poc_bench_swap.mjs` заканчиваются явным `process.exit(0)` с комментарием
про живые опросы, держащие цикл событий узла.

## Чего хотим

`poc_chatwarm.mjs` завершается сам сразу после печати результата. Тест
`TestStaticChatListWarmOnReturn` проходит за секунды.

## DoD

- `poc_chatwarm.mjs` вызывает `process.exit(0)` последней строкой, по тому же
  образцу, что `poc_bench_task.mjs` и `poc_bench_swap.mjs`.
- Прямой `node testdata/poc_chatwarm.mjs static/app.js` завершается сам, без
  внешнего `timeout`.
- `go test -run TestStaticChatListWarmOnReturn` в `tools/dashboard` проходит
  за разумное время (секунды), не упирается в потолок пакета.
