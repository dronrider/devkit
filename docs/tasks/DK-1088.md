# DK-1088: Привязка сессии к цели пишется в реестр чатов при старте цикла, срез считает «фон» после конца цикла

## Что происходит

Довесок цели DK-909 (`docs/tasks/DK-909.md`), развилка «починка фона», решение человека 2026-09-21. Проверяющий на строке цели в Check нашёл расхождение по третьей строке DoD. Свод `taskctl spend --from --to` относит ход головной сессии к статье «фон» по носителю сессии, а носитель для цикла цели берётся из живой записи `~/.devkit/goals`. Запись уходит с концом цикла. За 20 сентября 155k токенов вывода захода по цели легли в строку «вне статей», хотя днём раньше, при живом цикле, тот же срез печатал статью «фон».

## Чего хотим

Привязка сессии к цели живёт долго. Старт цикла (оболочка `goal-run` и заход из чата по «продолжай цель») пишет её в реестр чатов `~/.devkit/sessions.log` полем носителя. DK-913 так же пишет виток и безголовый заход из переменных окружения. Срез за прошлый день печатает статью «фон» так же, как за живой цикл. Запись `~/.devkit/goals` остаётся рабочим состоянием цикла, и источником свода она больше не служит.

## Границы

- Статьи и их порядок признаков это DK-913, здесь только источник признака цикла.
- Запись `~/.devkit/goals` и её срок жизни не меняются.

## Развилки

- «кто пишет»: какая точка кладёт носителя в реестр?
  - решает: исполнитель
  - рекомендация: хук старта сессии `hooks/session-task.py` при привязке к цели (строка доски с файлом цели, `DEVKIT_GOAL_SHELL` либо реплика «продолжай цель») и `goal-run.py` при подъёме витка; реестр получает носителя «цикл цели <ID>», свод читает его раньше живой записи

## DoD

- На временном репозитории сессия, привязанная к цели при старте цикла, получает в реестре чатов носителя с ID цели без живой записи `~/.devkit/goals`.
- Срез `taskctl spend --from --to` за день, когда цикл уже кончился, печатает статью «фон» по этой сессии, а не «вне статей».
- Тест бага краснеет на старом коде и проходит на новом (`regcheck`).

## Ранг

`50+6+1+5+4 = 66`, P1.

- Серьёзность 50: третья строка DoD цели DK-909 не сходится на следующий день после цикла.
- Ценность 6: статья «фон» это половина расхода машины по замеру 20 сентября.
- Неопределённость 1: подход назван развилкой цели, открыта одна точка записи.
- Поправка на баг 5: регресс механики DK-913 во времени.
- Рычаг 4: свод расхода стоит на этом признаке.

Цена S: одна запись в реестр и одно чтение в своде.

Вид приёмки agent.

## Ход работы

Развилку «кто пишет» закрыл рекомендацией. Носителя кладёт хук старта сессии,
а `goal-run.py` называет ему цель переменной `DEVKIT_GOAL_SHELL`, которую и так
ставил витку. Своей записи в реестр оболочке не понадобилось.

Хук узнаёт цикл двумя дорогами. У витка ID цели стоит в переменной, а у захода
из чата задача приезжает заказом `DEVKIT_TASK`. Цикл виден по тому, что файл
задачи это запись цели. Разбор взят готовый, тот же, каким открывается этап
«постановка» (`record_kind`). Оболочка без ID цели в переменной осталась витком
без номера, как было до правки.

Свод читает носителя реестра раньше живой записи `~/.devkit/goals`. Запись
никуда не делась, она по-прежнему рабочее состояние цикла и по-прежнему
читается вторым признаком.

Тест бага лежит своим файлом `tools/taskctl/spendgoal_test.go`. Соседи по
`spenditem_test.go` зовут новую `spendCarrierGoal`, и перенос всего файла на
старый код рассыпался сборкой. Краснота при этом ничего не доказывает.

Живой срез за 2026-09-20 после правки не печатает статью «фон» по сессии
ba9845cd, и это ожидаемо. Носитель пишется на рождении сессии, а
строка рождения того захода легла в реестр вчера, без поля. Правка работает
вперёд, и срез сходится с первым циклом, поднятым после неё.

Пометки сторожа прозы и обходы:

- Сторож прозы: хвост «а не» в файле задачи снят перестройкой фразы в «Чего
  хотим», в DoD оборот оставлен: он и есть формулировка критерия.
- Коммит `docs(sessions)` правит один комментарий к полю `Bind.Carrier`, тесту
  тут взяться неоткуда, и ворота тестов обойдены `DEVKIT_NO_TESTS=1` осознанно.

## Ревью

Уровень 3 до aad7d82: до aad7d82a: триаж критичности, дифф трогает critical_paths hooks и tools/taskctl (носитель сессии и свод расхода), это и есть путь DoD

- Вердикт: без замечаний до aad7d82. уровень 3 до aad7d82a: живой путь по DoD прогнан руками (spend period и hook recognition на синтетическом стенде, совпало с записью), regcheck подтвердил красноту на 47ec03d4a и зелень на dk-1088 для tools/taskctl/spendgoal_test.go и hooks/session_task_test.py::GoalLoopCarrier, go test ./... в tools/taskctl и internal/sessions зелёные (GOWORK=off), python3 -m unittest hooks.session_task_test зелёный (51/51). Сверено: разбор main..dk-1088 включал дрейф main (DK-1084/DK-908/DK-999), реальный дифф от 47ec03d4a содержит только заявленные 9 файлов. Совместимость реестра: internal/sessions.ParseLine уже умеет многословные значения полей, дашборд Carrier не читает, единственный потребитель строкового совпадения (spenditem.go carrier) обновлён в этом же диффе первым порядком проверки. Признак цикла из чата это record_kind(root, task) равный «цели» по DEVKIT_TASK, ровно по дизайну развилки DK-909 (строка доски с файлом цели это один из трёх перечисленных сигналов), поэтому он размечает циклом любой чат на строке цели, а не только «продолжай цель»: соответствует принятой рекомендации, не постановке вопреки. DEVKIT_GOAL_SHELL кладёт goal-run.py (self.id, реальный ID). DoD «работает вперёд» без добора старых строк реестра назван в «Ход работы» как осознанное ограничение, в границах задачи добор не входит
