# DK-1113: Цель: обкатка, ревью и закрытие без повторных прогонов

## Что происходит

Неделя 14-21 сентября: 251 коммит обкаток и smoke на 77 закрытых задач, у DK-971 и DK-689 по девять. Отметка обкатки протухает от коммита слияния и чужих коммитов доски (`onlyTaskDocSince` прощает только файл самой задачи). 39 из 75 ревью уровня 3, кругов 94, из 90 замечаний половина про форму, а не код. Ворота close требуют прогон другой моделью, и прогон повторяется: DK-881 sonnet -> opus, DK-909 sonnet -> haiku при цене XL. Первый прогон стенда obeycheck у пяти задач не различал редакции.

### Проверено грумингом 2026-09-21

Актуальность на месте. Послабление `onlyTaskDocSince` (`tools/taskctl/gate.go:388`) прощает после отметки обкатки только цепочку коммитов, где тронут ровно один путь, `docs/tasks/<ID>.md` самой задачи. Коммит слияния даёт другой путь. Чужой коммит доски тоже. Отметка в обоих случаях гаснет. Ворот `closeVerifyGate` (`gate.go:225`) сверяет имя прогонявшего с именем исполнителя разработки. Про ярус в нём нет ничего. Дешёвый прогон на дорогой задаче проходит молча, лишь бы имена не совпали.

Уровень ревью стоит из скилла (`kit/skills/review/SKILL.md:84`). Два «да» триажа критичности дают третий уровень сразу. Оба вопроса считаются совпадением путей диффа с `critical_paths`, до чтения самого диффа. Сторожа формы перед спавном ревьювера нет вовсе. Хуки `hooks/check-symbols.py` и соседние стоят на записи через Write и Edit. Правка через sed и heredoc идёт мимо них. У стенда `obeycheck` отдельного вердикта про неразличённые редакции нет. Есть «зелёный на обеих» и «не хуже» (`tools/obeycheck/verdict.go:73`), и при пустой базе они не засчитываются.

Счёт недели сверил по истории. С 14 по 21 сентября в main легло 258 коммитов со словами про обкатку и smoke. Сводка `taskctl review stats` даёт 101 ревью третьего уровня против 52 второго. Медиана ходов у третьего 43, у второго 22.

Дубля на доске нет. Из семи открытых целей ни одна не про число прогонов на задачу. Ближе всех DK-183 про след ревью и два круга. Её предмет это промты и шкала замечаний, состав ещё не нарезан. Соседние цели того же разбора недели это DK-1112 про доставку правки до main, DK-1114 про журналы и учёт и DK-1115 про сторожей и субагентов.

Каждая задача платит два-три лишних прогона тестов и коммита доски, ревью тратит круги на то, что ловит grep, приёмку XL закрывает дешёвая модель.

## Чего хотим

На задачу приходится не больше одного коммита обкатки при пустом диффе кода, один прогон проверки, уровень 3 ревью только с причиной по содержанию диффа, машинные проверки формы до спавна ревьювера. Задачи цели: DK-1116 ярус проверки из pick, DK-1095 DoD цели после перевода в Check, DK-1096 вердикт стенда «не различает редакции», DK-1097 триаж критичности по содержанию, DK-1098 сторож формы до ревью, DK-1111 зелёная отметка только при настоящем прогоне. Из накопителя: DK-741, DK-989, DK-1085, DK-1039, DK-1027, DK-1047, DK-838, DK-1005, DK-668, DK-700.

## Границы

Вне цели остаётся всё, что чинит форму в момент записи. Хуки на Write и Edit и отказ утилит доски по одной претензии за ход это черновик DK-1109 из цели DK-1112. Там же остаётся прогон тестов по тронутым компонентам (DK-1090), он меряется временем доставки до main. Промты ревью, шкала «блокер, замечание, вкус» и чеклист одной копией остаются за целью DK-183. В её файл уходит строка про то, что триаж критичности и машинные проверки формы уехали сюда. Тесты, которые краснеют под нагрузкой сами по себе, это цель DK-1084.
