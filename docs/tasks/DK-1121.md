# DK-1121: Команды разбора не делают чат работой строки, кнопка запуска остаётся

## Что происходит

2026-09-22, груминг DK-879 из свободного чата дашборда (chat-5). После `taskctl set DK-879` реестр `~/.devkit/sessions.log` получил строку с источником «работа». Строка доски пришла с полями run: chat, run_busy: true. Вместо кнопки «Выполнить» у строки стоял «Стоп». В перечне touchCmds в tools/taskctl/touch.go работой числятся add, move, close, ask, fail, set, file, review, dep и progress. В комментарии к taskChats в tools/dashboard/chats.go сказано обратное: груминг, привязка рукой и разговор о задаче строку не присваивают. Привязку снял ручкой POST /api/projects/{p}/sessions/{sid}/task с пустой задачей. Поля run у строки после этого пропали. Разбор воспроизвёл предмет на синтетической доске во временном репозитории с подменным HOME. Команда `taskctl set XX-1 --cost M` из сессии харнеса положила в реестр строку «источник работа повод taskctl set XX-1».

Каждый груминг из чата зовёт add и set. Разговор становится работой над строкой. Пока чат жив, у строки «Стоп» вместо запуска, и кнопкой конвейер не поднять. После смерти чата кнопка становится «Продолжить» и ведёт в разговор разбора, исполнителя она не поднимает. Такое случается на каждой задаче, оформленной из чата; оформление с экрана черновика этого не задевает.

## Чего хотим

Задача, оформленная или поправленная из чата, стоит в Backlog с кнопкой «Выполнить», а чат разбора в списке чатов остаётся разговором о задаче без признака работы.

## Границы

Задача не заводит записи «снята» ни на снятых командах, ни на своей команде отвязки. У сужённого перечня привязка не появляется вовсе. В реестре сегодня нет ни одной строки, за которой привязку записали старые чаты разбора. `grep «источник работа» ~/.devkit/sessions.log` пуст на 501 строке с 14 сентября. Разовая чистка не требуется. Задача не трогает подхват строки, уже стоящей в In progress. Повторный `move` отбивается ошибкой «уже в in-progress», а `agentctl` ставит привязку такой сессии своим перечнем.

Условий, посильных только человеку, не нашёл. Доступов, секретов и необратимых шагов наружу работа не просит. Проверка идёт на временном репозитории и на своём же реестре.

## Из черновика DK-1042 «Оформление черновика делает сессию груминга работой строки» (записан 2026-09-17)

### Черновик

#### Ситуация

17.09.2026 сессия чата доски разобрала черновик DK-1041 и оформила его
командой `taskctl add --id DK-1041 ... --push`. После этого на форме задачи
в дашборде вместо кнопки «Выполнить» стоял «Стоп» (замечание пользователя).
В реестре `~/.devkit/sessions.log` появилась запись сессии по DK-1041 с
источником «работа» и поводом `taskctl add --id`. Команда `add` входит в
`touchCmds` (`tools/taskctl/touch.go`), и оформление строки записалось как
работа над ней. Дашборд по `rowOurRun` показывает «Стоп» строке, чью работу
ведёт живой разговор.

#### Осложнение

Строку, только что заведённую грумингом, с дашборда нельзя запустить, пока
жива сессия груминга, а «Стоп» на ней снял бы разговор с человеком, а не
работу по задаче. Слово «работа» у сессии, которая задачу не делает,
противоречит DK-430.11: живой разговор это третье состояние строки, а не
работа.

#### Вопрос

Считать ли `add` работой вовсе, или только `add` без `--id`. Заведение
строки из черновика это конец разбора, исполнение начинается позже. Нужна ли
сессии команда отвязки руками для таких случаев.

#### Гипотеза

После `taskctl add --id` строка на дашборде показывает «Выполнить», а сессия
груминга остаётся разговором без признака работы.
