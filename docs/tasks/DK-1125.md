# DK-1125: Итоги прогона по компонентам ложатся в журнал, слияния от чужой красноты считаются командой

Цель: [tasks/DK-1084.md](tasks/DK-1084.md)

## Что происходит

Запись `shipctl` хранит принадлежность коммитов. Итогов прогона `test` в ней нет.
Журнала слияний, отбитых чужой краснотой, нет вовсе, и число это сегодня
считается ручным разбором файлов задач.

Исполнитель видит красный компонент и не знает, своя это краснота или чужая.
В DK-764 записаны четыре отбитых слияния за сутки, в DK-1038 три за одну пачку,
в DK-1000 два лишних прогона по пять минут на одно слияние. Разбор чужого
компонента по DK-845 занял субагента на десять минут ради вывода «не наше».

Третья строка DoD цели DK-1084 требует счёта таких слияний с нулём после выката.
Такого счёта нет.

## Чего хотим

Итог прогона `test` по компонентам ложится в журнал при каждом слиянии. Команда
печатает число слияний, отбитых компонентом вне диффа задачи, за названный срок.
По этому числу видно, падает ли чужая краснота после выката бюджета машины.

## DoD

- `shipctl merge` пишет итог прогона по компонентам: имя компонента, исход,
  длительность, состав диффа задачи.
- Команда печатает число слияний, отбитых компонентом вне диффа задачи, за
  названный срок.
- Прогон на стенде показывает оба исхода: отбой своей краснотой и отбой чужой.
  Первый в счёт не идёт, второй идёт.
- Журнал переживает откат и повторное слияние той же задачи.

## Ранг

`25+6+1+0+4 = 36`, P2 по своим слагаемым. С наследованием от цели DK-1084 ранг
строки 65.

- Серьёзность 25. Ручная работа с дешёвым обходом. Исполнитель разбирает чужой
  компонент глазами и по диффу.
- Ценность 6. Регулярная операция слияния идёт каждый день, и разбор красноты
  входит в неё.
- Неопределённость 1. Форма записи выбирается по месту, опора это раздел «Выкат»
  файла задачи.
- Поправка на баг 0. Строка заводит механику.
- Рычаг 4. Журнал измеряет эффект бюджета машины и удешевляет каждое следующее
  слияние.

Цена M, правка `shipctl` вместе с тестами и командой счёта. Вид приёмки
агентский, барьеров из шести не названо. Журнал и вывод команды читаются с машины
агента.

## Ход работы

- Заведена нарезкой цели DK-1084, 2026-09-22. Третья строка DoD цели держится
  этой задачей.
- Вычитка: 1 файл, 2 правки, 0 пометок, 2026-09-22.
- Разработка, 2026-09-23. Журнал лёг машинным файлом `.devkit/test-runs.log`
  (JSON построчно, гитигнорнут, живёт по образцу `.devkit/log`). Запись идёт
  из `cmdMerge` сразу после прогона `test`, красного в том числе, до отказа
  слияния. Разбор по компонентам берётся построчно из вывода самой команды
  `test`. Формат общий, `<имя> <секунды>s ok|FAIL`, его же печатает
  `tools/devkitctl/parallel.py`. Команда без такого разбора заводит один
  синтетический компонент на весь прогон. «Своя» и «чужая» краснота
  различаются эвристикой: имя провалившегося компонента ищется сегментом
  пути в диффе задачи. Раскладка `deploy.<имя>.paths` тут не судья, она не
  обязана быть заведена. Команда `shipctl foreign-fails --since <срок>`
  (24h, 30m, дни и недели 7d, 2w) читает журнал. Она считает слияния, где ни
  один упавший компонент диффа не коснулся.
- Разработка, 2026-09-23: тестовый фикстурный репозиторий `setup()`
  (tools/shipctl/ops_test.go) не игнорировал `.devkit/test-runs.log`.
  `git add .` во втором коммите фикстуры ловил журнал и ломал следующий
  checkout внутри `merge`. Тот же риск несёт любой проект без записи в
  `.gitignore`. Запись `.devkit/test-runs.log` добавлена в общий список
  `MACHINE_IGNORE_ENTRIES` (tools/devkitctl/devkitctl.py) рядом с cmdout и
  ship.lock. `devkitctl new`/`corp` и `doctor --fix` раскладывают её сами,
  находка у доктора тоже есть. Тест `test_16_machine_ignore_paths`
  (tools/devkitctl/devkitctl_test.py) расширен проверкой новой записи.
- Тесты: `go test ./...` пакета tools/shipctl (полный прогон, GOWORK=off),
  `python3 -m unittest devkitctl_test.DeployTest` (16 тестов). Оба зелёные.

## Сценарий проверки

Агентский.

1. `cd tools/shipctl`, затем `GOWORK=off go build ./...`. Сборка проходит без
   ошибок, свежий бинарь понимает подкоманду `foreign-fails --since <срок>`.
2. `GOWORK=off go test ./... -run 'TestMergeForeignFailsOwnRedNotCounted|TestMergeForeignFailsForeignRedCounted|TestJournalSurvivesRevertAndRemerge' -v`.
   Три теста зелёные. Первый держит красный компонент внутри диффа задачи, и
   `foreignFails` после него возвращает 0. Второй держит красный компонент вне
   диффа, и `foreignFails` возвращает 1 (оба исхода DoD, третий пункт). Третий
   проверяет, что после `cmdRevert` и второго `cmdMerge` той же задачи в
   журнале остаются обе записи (четвёртый пункт DoD).
3. `GOWORK=off go test ./...` пакета tools/shipctl целиком, зелёный: новый
   журнал не ломает существующие сценарии merge, revert, ship и train.
4. `PYTHONPATH=. python3 -m unittest devkitctl_test.DeployTest.test_16_machine_ignore_paths -v`
   из `tools/devkitctl`, зелёный: `devkitctl new`/`doctor --fix` раскладывают
   `.devkit/test-runs.log` в `.gitignore` проекта.
