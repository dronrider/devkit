# DK-1132: Юнит рендера ленты вырезает из статики все нужные функции, go:dashboard зелёный

Цель: [tasks/DK-1084.md](tasks/DK-1084.md)

## Что происходит

Юниты рендера markdown гоняют саму статику. Помощник
`mdSource` в `tools/dashboard/messages_test.go:897` вырезает из `static/app.js`
три константы и восемь функций по именам, склеивает их в `md.mjs` и пускает под
node с игрушечным DOM.

Коммит 766c5b400 (DK-1120) добавил в статику `inlineCodeSpan`, и `mdInline`
теперь зовёт её на каждом куске кода в обратных кавычках. В список вырезки
функция не попала, так что собранный модуль падает под node на
`ReferenceError: inlineCodeSpan is not defined`. От этого красные
`TestMarkdownEscapesInjection` и `TestMarkdownBlocks`.

Цена красноты больше самих тестов. Раннер `tools/devkitctl/parallel.py` встаёт
на первом упавшем компоненте, `go:dashboard` в его порядке первый, и прогон
`test` из `.devkit/deploy.local` красный всегда. Слить сейчас нельзя ничего.
Поймал я это замером DK-1122 2026-09-22: из четырёх полных прогонов на `-j 3`,
`4`, `5` и `8` три умерли на `go:dashboard` через 534, 569 и 563 секунды.
Нагрузка тут ни при чём, `ReferenceError` детерминированный.

Одним именем в списке дело не кончится. `inlineCodeSpan` зовёт `codeLinkify` и
`copyBtn`, а `copyBtn` собирает кнопку через `icon`, `setAttribute`,
`addEventListener`, `classList`, `window.navigator` и `setTimeout`. Игрушечный
DOM теста (`messages_test.go:938`) ничего из этого не умеет, и вырезки одних
имён не хватит.

## Чего хотим

Собранный из статики модуль знает все функции, которые рендер зовёт на самом
деле, а игрушечный DOM держит кнопку копирования. Ожидания юнитов знают, что
код в обратных кавычках приезжает обёрткой с кнопкой. Компонент `go:dashboard`
зелёный, прогон слияния доходит до конца.

Расхождение списка вырезки с тем, что зовёт рендер, слышно раньше слияния, и
говорит о нём внятная строка теста.
