# DK-1143: Сборка плана из шаблона: два входа, слот и «без шаблона»

## Что происходит

Файл набора появляется строкой DK-1142, но читать его пока некому. План сессии
собирает агент из головы, и обязательные этапы задачи в нём либо есть, либо
нет. LLD DK-972 (`docs/lld/DK-972-plan-templates.md`) закрывает это решениями 4
(шаблон выбирается по типу задачи, по суффиксу строки или по флагу, а иначе
план идёт «без шаблона»), 5 (свои пункты агента ложатся в слот, обязательные
держит движок) и 6 (у каждого встроенного этапа названо слово следа).

## Чего хотим

`agentctl plan set` собирает план из шаблона по решениям 4 и 5. Появляется
пакет `internal/trace` по решению 6, и проверяющие следов переезжают в него из
кода ворот без изменения поведения. `plan done` спрашивает след и печатает «на
слове агента» там, где следа у этапа нет. В шапке файла плана стоит имя
шаблона, суффикс `[план: имя]` ставит команда `taskctl plan`, а дашборд
печатает имя шаблона и «без шаблона» у кольца задачи и в блоке «План агента».

Тесты: сборка по типу, по суффиксу, по флагу и без всего сразу; слот со своими
пунктами; повторный `set` не теряет этапы; `done` на этапе со следом без следа
отказывает, а без задачи закрывает этап словом.

## Границы

Ворота `taskctl` и `shipctl` читают шаблон строками DK-1144 и DK-1145, здесь их
поведение не трогается. Редактор набора в дашборде это DK-1149.

## DoD

Исполнитель задачи типа task после `plan set` видит в плане вычитку, ревью,
сценарий и проверку, и ставить их своей рукой ему не приходится.

## Ранг

`50+8+1+0+4 = 63`, P1.

- Серьёзность 50: обязательные этапы держатся на памяти агента, и пропуск
  всплывает уже на воротах слияния.
- Ценность 8: план собирается сам, а `internal/trace` становится опорой ворот.
- Неопределённость 1: входы и слот решены LLD, открыты детали печати.
- Поправка на баг 0: новая работа.
- Рычаг 4: на `internal/trace` опираются обе строки ворот и редактор в дашборде.

## Сценарий проверки

Вид приёмки агентский, шаги гоняются прогонами тестов из корня дерева.

1. Сборка по типу, суффиксу, флагу и «без шаблона». Шаг, прогнать `devkitctl
   test tools/agentctl -run TestPlanSetFrom`. Итог, зелёные тесты FromType,
   FromSuffix, FromSuffixMissing, FlagAndUnknown и NoTemplate. Шаблон
   выбирается тремя путями, суффикс с чужим именем и пустой набор без
   шаблона отказывают словами.
2. Слот и повторный set. Шаг, прогнать `devkitctl test tools/agentctl -run
   'TestPlanSetSlotEmptyAndDup|TestPlanSetRepeatCarriesStages'`. Итог, зелёные тесты.
   Свои пункты занимают слот этапа, дубль имени этапа не удваивается, а
   повторный set переносит состояния и не теряет обязательные этапы.
3. Закрытие по следу. Шаг, прогнать `devkitctl test tools/agentctl -run
   TestPlanDone`. Итог, зелёные тесты TraceRefuses и ByWord. Done на этапе со следом
   без следа отказывает, слово закрывается печатью «на слове агента», а след
   файла задачи без задачи закрывается словом.
4. Словарь следов. Шаг, прогнать `devkitctl test internal -run
   'TestDictionary|TestTaskBound|TestCheck|TestRegcheckLogged|TestPathsTouched|TestPathMatch'`.
   Итог, зелёные тесты. Словарь знает свои слова, диспетчер Check расходится по
   трём исходам, разбор журнала regcheck и маски путей работают.
5. Суффикс доски. Шаг, прогнать `devkitctl test tools/taskctl -run
   'TestPlanSetAndOff|TestPlanSetKeepsOtherTails|TestPlanUnknownName|TestLintPlanNames'`.
   Итог, зелёные тесты. Суффикс ставится между взводом и приёмкой, чужое имя
   отказывает, находка линта зовёт поправить.
6. Шапка в дашборде. Шаг, прогнать `devkitctl test tools/dashboard -run
   'TestPlanFileShape|TestPlanFileTellsAboutBrokenFile'`. Итог, зелёные тесты. Файл
   плана с шапкой и старый массив читаются, посторонний объект остаётся
   жалобой.
