# DK-1156: Флаг человеческого скилла у goal-start запирает постановку цели из чата

## Что происходит

DK-808 поставила goal-start, board-team и live-core флаг disable-model-invocation: true ради веса резидента. 2026-09-24 в чате задачи пользователь словами велел завести цель на строки нарезки DK-972. Вызов скилла инструментом Skill отбит харнесом: скилл заперт для модели, и порядок его нельзя воспроизводить другим путём.

Команда человека в чате не считается вызовом. Постановка цели требует от пользователя набрать /goal-start руками, хотя разговор уже идёт и бюджет назван. Диспетчер в панели дашборда и виток цели так цель завести не могут вовсе. Черновик DK-808 этот риск называл открытым вопросом.

## Чего хотим

Флаг остаётся у board-team и live-core, где вход и правда только ручной. У goal-start он снимается, сценарий DK-808 правится на два флага. Разговор постановки идёт скиллом interview, как и сейчас.

## Развилки

Снять флаг у goal-start и заплатить строкой описания в реестре, либо оставить флаг и вынести машинную часть постановки (строка, файл цели, бюджет) в команду taskctl goal add, которую зовёт любой вход?

- «кейсы»: какие пользовательские кейсы у DK-1156? рекомендую сбалансированный: узкий не держит приёмку стендом, а кейсы (4) и (5) широкого это отдельные решения, машинное ядро команды уже на две трети в add --id
  - решает: человек
  - рекомендация: сбалансированный состав, 3 кейса: (1) пользователь в чате велит завести цель словами, сессия ведёт постановку скиллом goal-start без ручного слэша; (2) реестр сессий не тяжелеет: описание goal-start в реестре одна строка, тело остаётся внерезидентным; (3) стенд 49-goal-budget-fit зелёный на снятом флаге, вызов гейтится описанием
  - вариант: узкий состав, 1 кейс: (1) постановка цели из чата идёт без ручного /goal-start
  - вариант: широкий состав, 5 кейсов: (1) постановка из чата скиллом без слэша; (2) описание в реестре не растёт сверх строки, стенд 49 зелёный; (3) диспетчерский чат DK-1253 заводит цель тем же входом; (4) машинная команда taskctl goal add заведена для входов без скиллов; (5) след входа постановки фиксируется в журнале цели
  - решено человеком 2026-10-28: сбалансированный состав, 3 кейса: (1) пользователь в чате велит завести цель словами, сессия ведёт постановку скиллом goal-start без ручного слэша; (2) реестр сессий не тяжелеет: описание goal-start в реестре одна строка, тело остаётся внерезидентным; (3) стенд 49-goal-budget-fit зелёный на снятом флаге, вызов гейтится описанием
- «путь»: снимать ли флаг у goal-start или выносить машинную часть постановки в команду taskctl goal add?
  - решает: исполнитель
  - рекомендация: снять флаг у одного goal-start и не заводить команду: её машинное ядро уже на две трети в add --id, разговор живёт в interview, а плата снятия одна строка описания
  - источник: код kit/skills/goal-start/SKILL.md:62-72, дока tools/taskctl/README.md:478-484

## DoD

Флаг disable-model-invocation снят у goal-start и оставлен у board-team и
live-core. Пользователь в чате велит завести цель, сессия зовёт Skill
goal-start и ведёт постановку до строки и файла цели. Стенд 49-goal-budget-fit
зелёный на снятом флаге, описание скилла честно гейтит вызов. Команда taskctl
goal add этой строкой не заводится.

## Ранг

`25+3+1+0+3 = 32`, P2.

25+3+1+0+3 = 32, S.

- Серьёзность 25: постановка цели из чата и панели требует ручного слэша, диспетчер завести цель не может вовсе.
- Ценность 3: постановка редкая операция, польза приходится на каждый её заход.
- Неопределённость 1: путь снятия флага оцифрован, открыта только приёмка стендом.
- Поправка на баг 0: тип task, вход расширяется после сознательного решения DK-808.
- Рычаг 3: диспетчерскому чату DK-1253 достаётся тот же вход постановки.

## Что дал разбор

Обход 2026-10-28 подтверждает механику и оцифровывает цену. DK-808 выросла из
черновика DK-554: все скиллы сидели в реестре с описаниями, реестр грузится в
каждую сессию, и тройка goal-start, board-team, live-core получила флаг ради
веса (archive/2026/DK-808.md:231-263). Открытым вопросом DK-808 называла вызов
из goal-loop, и он закрыт фактом: goal-start из кода не зовёт никто, оболочка
goal-run.py сама отказывается заводить цель (:371). Прямого вопроса про
постановку из чата слов в DK-808 нет.

Плата снятия ровно одна строка. В контекст каждой сессии едет только name с
description, тело скилла не резидентно (README devkitctl:2392-2413,
weigh.py:130). Описание goal-start занимает 417 символов, около 170 токенов.
Скилл не менялся с инцидента: git log по kit/skills/goal-start/ с 2026-09-24
пуст.

Посылка «порядок нельзя воспроизводить другим путём» не держится. Стенд
49-goal-budget-fit уже ведёт постановку моделью, которая читает файл скилла
напрямую (tools/obeycheck/scenarios/49-goal-budget-fit.md:57-58). Разговорная
часть и вовсе не заперта: interview зовут четыре входа, и флага у него нет.
Живых следов вызова goal-start в журналах нет ни одного. После запирания
поставлены минимум три цели: DK-1253, DK-1114, DK-1198, и след входа постановки
нигде не фиксируется.

Команды taskctl goal add нет, и её машинное ядро уже на две трети существует.
Строка и файл цели кладутся командой add --id (SKILL.md:62-72), разговор идёт
interview, остались бы заготовка пяти разделов файла цели и вызов agentctl
fit. Тёзок по предмету нет на доске, в архиве и в накопителе. Стык нашёлся
один: диспетчерский чат DK-1253 это второй вход, которому нужен вход
постановки. Условий, посильных только человеку, не нашёл.
