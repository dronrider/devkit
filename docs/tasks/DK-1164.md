# DK-1164: Ревьювер идёт ярусом исполнителя, спуск на ступень снят

## Что происходит

Вердикт `agentctl pick --role review` опускает ревьювера на ступень ниже
исполнителя (`tools/agentctl/pick.go`, `reviewShift`): задачу на pro ревьюит
base. Правило пришло из DK-023 (2026-07-31) с доводом, что ревьюверу нужна
внимательность на диффе, а не калибр автора, и что выигрыш по квоте невелик.
Замера у довода не было.

Пилот DK-1159 (2026-09-25) дал замер. Ревью DK-685 по процессу шло на sonnet
с effort high и нашло одну мелочь. Слепой ревьювер на opus на том же диффе
нашёл два серьёзных дефекта (ложный отказ у «Исключение: сценарий» и
необновлённый предикат `closable.go`), а на соседнем диффе той же задачи
без ревью поймал блокирующую поломку `taskctl close`. Ревью оказалось
единственным этапом, который отделил «сливать нельзя» от «сливать после
правок», и на нём экономить ярус дороже, чем на чём угодно другом.

## Чего хотим

Ревьювер получает ярус исполнителя. Пол base и особые случаи (грумминговый
вердикт, LLD) остаются как есть. Вердикт по-прежнему объясняет причину
строкой, README agentctl описывает таблицу без строки со спуском.

## DoD

- `agentctl pick <ID> --role review` у задачи на pro даёт pro, у задачи на max
  даёт max, у mini и base даёт base. Причина в вердикте называет правило.
- Тесты `pick_test.go` на спуск переписаны под новое правило и краснеют на
  старом коде, краснота сверена `regcheck`.
- Раздел «Роль ревьювера» в `tools/agentctl/README.md` и п. 10 раздела
  «Трекинг задач» в `RULES.board.md` согласованы с кодом.

## Ранг

`25+7+1+0+4 = 37`, P2.

- Серьёзность 25: рубеж ревью стоит, но пропускает серьёзные дефекты, обход
  есть (позвать ярус выше руками).
- Ценность 7: ревью идёт у каждой задачи с веткой.
- Неопределённость 1: правка одной функции, развилок нет.
- Баг 0: поведение задумано, а не сломано.
- Рычаг 4: меняется качество ворот перед каждым слиянием.

Цена S. Вид приёмки агентский: вердикт печатается командой на синтетической
доске.

## Сценарий проверки

Сценарий агентский, `agentctl` собирается из свежего дерева, установленного
бинаря не требует. Первый шаг кладёт синтетическую доску во временный
каталог с четырьмя строками (пример pro, mini, base, override на max) и
сверяет ярус ревьювера по каждой. Второй шаг проверяет, что причина у не
опускаемого яруса называет новое правило, а не старый спуск.

```sh
d=$(mktemp -d) && GOWORK=off go -C tools/agentctl build -o "$d/agentctl" . && mkdir -p "$d/board/docs/tasks" && printf '%s\n' "# synthetic: задачи (префикс T)" "" "## In progress" "" "| ID | Задача | Тип | P | R | Цена | Ссылка |" "|---|---|---|---|---|---|---|" "| T-100 | ревью на pro | task | P2 | 34 (25+4+1+0+4) | L | - |" "" "## Backlog" "" "| ID | Задача | Тип | P | R | Цена | Ссылка |" "|---|---|---|---|---|---|---|" "| T-101 | ревью на mini | task | P3 | 5 (0+3+0+0+2) | S | - |" "| T-102 | ревью на base | task | P3 | 6 (0+3+1+0+2) | S | - |" "| T-103 | ревью на max override | task | P3 | 6 (0+3+1+0+2) | S | - |" "" "## Blocked" "" "Нет." > "$d/board/docs/TASKS.md" && printf 'Модель: fable (проверка override)\n' > "$d/board/docs/tasks/T-103.md" && home=$(mktemp -d) && export HOME="$home" DEVKIT_HARNESS="" && t100=$("$d/agentctl" -C "$d/board" pick T-100 --role review | sed -n '3p') && t101=$("$d/agentctl" -C "$d/board" pick T-101 --role review | sed -n '3p') && t102=$("$d/agentctl" -C "$d/board" pick T-102 --role review | sed -n '3p') && t103=$("$d/agentctl" -C "$d/board" pick T-103 --role review | sed -n '3p') && echo "pro=$t100 mini=$t101 base=$t102 max=$t103" && [ "$t100" = "tier: pro" ] && [ "$t101" = "tier: base" ] && [ "$t102" = "tier: base" ] && [ "$t103" = "tier: max" ]
```

Ожидание: `pro=tier: pro mini=tier: base base=tier: base max=tier: max` и
зелёный шаг. На pro и на override max ревьювер держит ярус исполнителя, mini
подтягивается до пола base, base остаётся на полу.
