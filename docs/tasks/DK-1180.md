# DK-1180: Ревью, интервью и определения агентов сверяют правку с docs/ARCHITECTURE.md и docs/STYLEGUIDE.md

Цель: [tasks/DK-1178.md](tasks/DK-1178.md)

## Что происходит

Скилл `review` фильтрует расхождение правки с кодом как вкус. Правило
«вкусовщина не пишется» стоит, а адреса правила у ревьювера нет, потому что
проектные правила приходят одним каналом, ключом `checks` из
`.devkit/review.conf`. Определения исполнителей `kit/agents/exec-*.md` и
ревьюверов `review-*.md` ни архитектуры, ни стайлгайда не упоминают, обходчик
`interview` приносит развилки с источниками «код|дока|доска|возражение» без
слоя архитектуры. Корень разобран в файле цели DK-1178.

## Чего хотим

Тексты по решениям LLD DK-1179.

- `RULES.core.md` получает один абзац про якоря и расхождение, разбор идёт в
  `RULES.md`; бюджет ядра держится, доктор находок веса резидента (DK-190) не
  ставит.
- Скилл `review` получает вопрос второго уровня про границы архитектуры и
  соглашения стайлгайда с адресом правила, а расхождение с кодом без
  записанного правила пишет развилкой «кандидат в стандарт» через
  `taskctl decide` с рекомендацией «как в коде»; блока и молчания в этом
  случае нет.
- Определения exec-* и review-* получают строку чтения `docs/ARCHITECTURE.md`
  и `docs/STYLEGUIDE.md` до правки, когда файлы есть.
- Обходчик `interview` получает источник «архитектура» для слоя, который
  задача трогает.
- Стенд `obeycheck` получает сценарий, где дифф расходится с кодом без
  записанного правила, и правка прогоняется по скиллу `prompt-test` со
  следом в файле задачи.

проектам не пишется. Стиль прозы и символов (RULES.md, «Код и тексты») не
трогается.
