# DK-119: коммит доски, собранный руками, отбивает pre-push

записан 2026-08-05

Правило доски требует пушить коммит `docs/TASKS.md`, `docs/TASKS-archive.md` и
`docs/tasks/` сразу и без просьбы, а `pre-push` такой пуш отбивает, потому что
сессия агентская. Разрешение хуку ставят `taskctl` и `shipctl`, когда пушат
сами (DK-106), а у ручного коммита такого канала нет, и остаётся
`DEVKIT_PUSH_OK=1`, то есть ровно тот обход, ради запрета которого хук и
заводился.

## Что происходит

Под правку файла задачи флаги `-m` и `--push` не подходят: они есть только у
изменяющих доску команд, а строка журнала цели, постановка задачи и вывод
прогнанного сценария пишутся в файл руками.

Виток цели DK-109 упёрся в это дважды. Цель DK-128 (2026-08-05) упёрлась семь
раз подряд: постановка цели, нарезка, правка DoD, дорезка, постановка каждой
задачи и запись каждого витка это ручной коммит `docs/tasks/`, и каждый пуш
пришлось звать через `DEVKIT_PUSH_OK=1`. Отбой выглядит так:

```text
что делать: остановиться на локальном коммите и сказать, что ветка готова к пушу
коммит доски пушится сразу, но своим путём: taskctl ... --push и shipctl ... --push
error: failed to push some refs
```

Совет хука тут неисполним: у ручного коммита доски своего пути нет.

## Чего хотим

Канал, которым правка доски пушится законно, без переменной-обхода. Развилка,
и обе стороны названы черновиком:

- команда `taskctl`, которая коммитит и пушит произвольную правку доски и
  файлов задач. Уже, чем кажется, зато вписывается в нынешний рубеж «доску
  правит утилита»;
- хук учится пропускать пуш, где в диффе только `docs/TASKS.md`,
  `docs/TASKS-archive.md` и `docs/tasks/`. Шире и потому опаснее, зато чинит
  случай целиком, включая правку файла задачи из дерева.

## DoD

Правка файла задачи, сделанная руками, коммитится и пушится одним понятным
шагом, без `DEVKIT_PUSH_OK`. Пуш, где в диффе есть что-то кроме доски,
по-прежнему отбивается. Проверяется на временном репозитории с обоими случаями.

## Решение развилки

Выбран второй путь: `pre-push` пропускает пуш, где в диффе только
`docs/TASKS.md`, `docs/TASKS-archive.md` и `docs/tasks/`. Причины:

- рубеж и правило перестают противоречить друг другу в самой точке
  принуждения: правило требует пушить коммит доски сразу, и хук теперь кодирует
  ровно его, а не приближение «пуш делает только утилита». Команда taskctl
  закрыла бы один сценарий, а ручной `git push` законного досочного коммита
  отбивался бы и дальше;
- шаг для агента не новый: обычные `git commit` и `git push`, без команды,
  которую надо помнить, и без переменной-обхода. DoD «одним понятным шагом»
  закрывается штатным гитом;
- отбой смешанного пуша живёт там же, где калитка: диффом диапазона проверяется
  любой пуш, как бы коммит ни собирали, тогда как команде taskctl эту проверку
  пришлось бы дублировать у себя;
- узость калитки удерживается разбором строк stdin: пропускается только
  движение вперёд от известного ремоута, а новая ветка, удаление, дивергенция и
  неизвестный sha отбиваются как раньше.

## Сценарий проверки

Агентский, на временном репозитории с bare-ремоутом и настоящим `git push`;
хук берётся из дерева задачи. Оба случая DoD:

```sh
tmp=$(mktemp -d)
git init -q --bare "$tmp/origin"
git clone -q "$tmp/origin" "$tmp/work" && cd "$tmp/work"
git config user.name t && git config user.email t@t
mkdir -p docs/tasks tools
printf '| доска |\n' > docs/TASKS.md
printf '# DK-001\n' > docs/tasks/DK-001.md
printf 'код\n' > tools/app.txt
git add -A && git commit -q -m "база"
env -u CLAUDECODE -u CLAUDE_CODE_ENTRYPOINT -u CURSOR_AGENT git push -q -u origin HEAD
cp <дерево задачи>/hooks/pre-push .git/hooks/pre-push

# случай 1: в диффе только доска, пуш из сессии агента проходит
printf '# DK-001\nход работы\n' > docs/tasks/DK-001.md
git commit -q -am "DK-001 ход работы"
CLAUDECODE=1 git push -q && echo "OK: пуш прошёл без DEVKIT_PUSH_OK"

# случай 2: в диффе доска и код, пуш отбивается
printf '# DK-001\nход работы 2\n' > docs/tasks/DK-001.md
printf 'код 2\n' > tools/app.txt
git commit -q -am "DK-001 доска и код"
CLAUDECODE=1 git push -q || echo "OK: смешанный пуш отбит"
```

Дальше юниты и краснота из дерева задачи:

```sh
python3 hooks/pre_push_test.py
regcheck --base main --tests hooks/pre_push_test.py -- python3 hooks/pre_push_test.py
```

## Ревью

- Дыра в калитке: hooks/pre-push:27 зовёт git diff --name-only без --no-renames, а определение переименований включено по умолчанию, и для переименования выводится только путь назначения. Коммит, который переносит tools/app.txt в docs/tasks/app.md, виден калитке как досочный и уходит в ремоут, удаляя файл кода (проверено живым пушем в bare-репозиторий: после пуша в origin остались только docs/TASKS.md и docs/tasks/app.md). Заодно поведение рубежа зависит от diff.renames в конфиге пользователя. Лечится флагом --no-renames в строке 27, нужен тест на перенос кода в docs/tasks/.
- Стухла дока скилла: kit/skills/board-groom/SKILL.md:116 говорит «результат разбора обязан пережить сессию, а ручной пуш docs/tasks/ отбивает pre-push». После калитки это неправда, а скилл читается агентом на каждом разборе черновиков. Тот же довод в tools/taskctl/README.md исполнитель пометил отпавшим, скилл пропущен.
- Стухший комментарий в коде: tools/taskctl/groom.go:17 объясняет, почему исходы разбора сделаны командой, доводом «ручная правка docs/tasks/ упирается в pre-push и учит обходу DEVKIT_PUSH_OK=1». Довод отпал той же правкой, комментарий надо оговорить.
- Ещё два места про рубеж говорят старое: tools/shipctl/README.md:575 («самовольный git push в той же сессии рубеж всё равно не пропустит») и kit/skills/board-ship/SKILL.md:50 («pre-push из devkit отбивает пуш, запущенный из сессии агента»). Досочный пуш теперь проходит и без утилиты, обе фразы стоит оговорить одной вставкой.
