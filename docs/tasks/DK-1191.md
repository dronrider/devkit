# DK-1191: Подъём чата после ответа на вопрос возвращает привязку к задаче

## Что происходит

Разговор по задаче, запаркованной вопросом, после ответа человека живёт как
свободный чат. В заголовке панели нет чипа с номером задачи, строка доски не
видит за собой работу, и записи в реестре сессий стоят с пустой задачей. На
DK-920 это выглядело так.

1. Конвейер поднял сессию окном `task-DK-920`, в реестр легла запись «заказ»
   с задачей.
2. Сессия запарковала строку на вопросе командой `taskctl move DK-920 blocked`.
   Перевод из in-progress считается концом работы по строке, и `taskctl`
   записал «снята DK-920». По правилу DK-716 у запаркованной строки не висит
   «Стоп». Окно закрылось через минуту.
3. Человек ответил с дашборда. Дашборд вернул строку в работу от своего
   имени, а реплику положил в чат без ведущей сессии.
4. Реплика подняла старую сессию резюмом. Задачу подъём берёт из тронутых
   записей реестра, а там DK-920 снята, и запасная дорога по суффиксу
   бокового дерева пуста, работа шла в основном дереве. Чат поднялся окном
   `chat-4`, в реестр легла запись «заказ» с пустой задачей.
5. Сессия позвала `taskctl move DK-920 in-progress`, получила отказ «уже в
   in-progress», а отказавшая команда реестр не трогает (DK-1003). Записи
   «работа» так и не появилось, хотя дальше сессия вела задачу до слияния.

Чип задачи в панели строится по последней записи сессии в реестре
(`bindTask` в `tools/dashboard/registry.go`), у неё задача пустая, и панель
подписывает разговор как свободный.

## Чего хотим

Ответ на вопрос задачи продолжает работу по той же строке, и подъём разговора
это знает. Реплика адресована задаче, и её ID едет в подъём резюмом. Запись
реестра при таком подъёме несёт задачу, окно tmux зовётся по задаче, чип в
заголовке панели кликабелен. Снятая парковкой привязка возвращается ответом,
потому что ответ и есть продолжение работы. Возврат строки в in-progress,
сделанный дашбордом за сессию, оставляет за поднятой сессией запись о работе.
Без неё строка после ответа стоит без «Стопа» и с кнопкой запуска поверх
идущей работы.

## Границы

Правится дорога подъёма резюмом в `tools/dashboard/chats.go` и то, как
запись реестра ложится при возврате строки в работу ответом. Критерий работы в
`internal/sessions` (слова «работа», «дерево», «снята») не меняется, как и
правило DK-716 о снятии привязки при парковке.

## DoD

- Резюм по реплике, адресованной задаче, кладёт запись реестра с этой задачей
  и поднимает окно tmux с именем по задаче.
- Возврат строки в in-progress ответом человека оставляет за поднятой сессией
  запись «работа», и строка доски показывает её как ведущую.
- Тесты воспроизводят цепочку DK-920 (запись «снята», ответ, подъём резюмом),
  после чего у сессии есть задача и работа. Тест падает на старом коде,
  краснота сверена `regcheck`.
- Раздел README дашборда про подъём резюмом называет, откуда берётся задача.

## Ранг

- Серьёзность 25: чат по задаче виден свободным, работа строки не показана,
  обход есть, открыть задачу с доски руками.
- Ценность 4: связь чата и строки это то, ради чего панель существует, и
  сбой заметен каждым ответом на вопрос.
- Неопределённость 1: место правки и причина найдены по журналу.
- Баг +5: привязка терялась там, где раньше держалась.
- Рычаг 2: своя польза, меньше ручного разбора «где работа по строке».

## Ход работы

- Правка легла в снятие парковки (`unparkAsk` в `tools/dashboard/wake.go`).
  Ждущую сессию называет поле «сессия» признака `.ask`. Спрашивается оно до
  снятия признака. Возврат строки в In progress оставляет за этой сессией
  запись реестра с источником «работа». Строка доски видит её ведущей.
- Подъём резюмом берёт задачу из тронутых записей, как и раньше. Возвращённая
  привязка это ровно то, чего ему не хватало.
- Второй дороги в `chats.go` не появилось. Задача там так и берётся реестром и
  суффиксом дерева. Угадывание по имени окна снято на DK-716.
- Запись ложится на ждущую сессию. Работу продолжает она, её поднимает резюмом
  реплика человека. Сессия, поднятая взамен, пишет свой след сама. Умерший
  разговор с записью работы строку не занимает. Работы собираются по живому
  окну и свежему транскрипту.
- Возврат, не прошедший до конца, работы за сессией не оставляет. Строка стоит
  припаркованной тем же вопросом, и подъём повторит тик сторожка. На этом
  отказе (`git push`) встала цепочка DK-920. Третий тест держит край.
- Круг ревью нашёл вторую дорогу ответа. Клавишный ответ живой сессии сводит
  строку через `settleAsk`, а признак там снят первым же ходом. Адрес ждущей
  сессии пришлось протащить параметром до `unparkAsk`. Четвёртый тест держит
  эту дорогу. Признак без сессии уходит своей строкой журнала.

## Сценарий проверки

Прогон после слияния в main, окружение синтетическое, временный `HOME` с
реестром сессий и записью «снята», сборка дашборда из main.

```sh
GOWORK=off go test -C /Users/rider/projects/devkit/tools/dashboard -v -run 'TestAnswerReturnsWorkToWaitingSession|TestAnswerKeepsWorkOffWhenUnparkFailed|TestChatResumeAfterAnswerCarriesTask|TestKeysAnswerReturnsWorkToLiveSession' -count=1 ./...
```

Ожидаются четыре зелёных теста цепочки. Запись «работа» за ждущей сессией, её
отсутствие при непройденном возврате строки, подъём резюмом окном `chat-XR-7-1`
с задачей в записи реестра и та же запись после клавишного ответа живой сессии.
