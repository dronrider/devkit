# DK-1218: Очередь слияний живёт в devkit, merge ждёт замок, а отбитая чужой краснотой ветка встаёт в хвост

Цель: [tasks/DK-1084.md](tasks/DK-1084.md)

## Что происходит

Строка оформлена из приписки DK-1212 к цели, записанной 2026-09-28. В тот день восемь готовых веток сливались весь день. Замок `.devkit/ship.lock` берётся через `flock` без ожидания (`tools/shipctl/lock.go:114`). Занятый замок даёт мгновенный отказ, и `shipctl merge` не повторяет попытку сам. Поезд `--train` копит уже слитые задачи, очереди на само слияние нет. Пометка `own: false` в `.devkit/test-runs.log` остаётся наблюдением, повтора от неё не бывает.

Диспетчеры закрывали дыру сами. За 28 сентября две сессии написали три одноразовых цикла в scratchpad. Первый, `merge-queue.sh`, вёл файл очереди под nohup. Второй, `ship-loop.sh`, повторял `shipctl ship` раз в десять секунд. Третий, `merge-when-calm.sh`, ждал спада load average. Очередь работала пять часов, отбитую ветку выкидывала из файла независимо от причины отказа, и повторные заходы диспетчер добавлял руками.

Атрибуция красноты тоже неверна. Падение HiddenTabQuiet или «WaitDelay expired» под нагрузкой журнал пишет как `own: true` у любой ветки, тронувшей `tools/dashboard`. Дифф пересекается с компонентом, и нагрузочное падение считается краснотой автора.

## Чего хотим

Очередь слияний это механика devkit.

- `shipctl merge` при занятом замке ждёт его, печатая держателя и время ожидания, и завершается с ошибкой только по явному сроку. Ключ отказа без ожидания остаётся для скриптов.
- Очередь готовых веток живёт вне сессии. Тик `devkitctl watch` берёт готовые к слиянию задачи по порядку ранга и зовёт `shipctl merge --train` по одной, рядом с `ship --drain`. Готовность читается теми же проверками, что у `shipctl ready`.
- Ветка, отбитая чужой краснотой, встаёт в хвост очереди сама, с потолком повторов. Отказ по своей красноте, конфликту ребейза или проверкам выводит задачу из очереди с записью в файл задачи.
- Признак нагрузочного падения. Падение теста из семейства стенного времени или с «WaitDelay expired» в выводе считается чужим независимо от пересечения диффа с компонентом.

Снаружи видно так. `shipctl status` печатает очередь слияний с позицией каждой ветки и числом повторов. Раздел «Ход работы» задачи получает этап «ждёт очереди» на каждый заход с причиной прошлого отказа.
