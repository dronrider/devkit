# DK-1219: Потолок параллельных прогонов накрывает прямой go test и unittest

Цель: [tasks/DK-1084.md](tasks/DK-1084.md)

## Что происходит

DK-1162 поставила потолок числа одновременных полных прогонов. Это замок `~/.devkit/parallel-slots` с одним слотом по умолчанию, лишний запуск ждёт. Замок берёт `parallel.py`. Исполнитель, проверяющий свою правку, зовёт `go test -C <дерево>/tools/taskctl ./...` или `python3 -m unittest` напрямую, и такой прогон замок не проверяет. 2026-09-28 в 19:45 под замком шёл `shipctl merge DK-1204`, а рядом третья сессия гоняла `go test` по дереву dk-1205 с потолком 9 минут. Load average в эти минуты держался на 76-89 при десяти ядрах.

## Чего хотим

Прямой прогон тестов из дерева задачи встаёт в ту же очередь слотов, что и полный прогон. Вход один. Обёртка `devkitctl test <путь>` берёт слот, при занятом слоте печатает строку ожидания и зовёт `go test` или `unittest` по типу каталога с тем же бюджетом параллельности и приоритетом, что у `parallel.py`. Скиллы исполнителя и стандарт тестов зовут обёртку вместо голых команд. Голый `go test` в дереве задачи становится находкой хука. PreToolUse на Bash печатает замену.

Снаружи видно так. Обёртка печатает строку ожидания слота, а в `.devkit/test-runs.log` записываются частичные прогоны с полем `scope`.

Слот и формула бюджета лежат в tools/devkitctl/parallel.py, и обёртка зовёт их у соседнего модуля, без нового бинаря и без второй копии формулы. Отвергнуто: своя утилита testctl (ещё один бинарь в PATH и своя сборка ради двух вызовов) и ключ parallel.py --only (частичный прогон это не срез компонентов полного, у него своя область и своя запись журнала).
- «форма находки хука»: Чем хук отвечает на голый go test в дереве проекта?
  - решает: исполнитель
  - рекомендация: отказ с готовой заменой, как у рубежа связки cd (DK-770): подсказка без отказа потолка не держит, агент прочитает её и повторит голую команду
  - вариант: отказ с готовой заменой
  - вариант: подсказка без отказа
  - вариант: молчаливая подмена команды
  - оставлена агентом 2026-09-29: Отказ с готовой заменой, как у рубежа связки cd (DK-770). Подсказка без отказа потолка не держит: агент прочитает её и повторит ту же голую команду, а полка нагрузки вернётся. Молчаливая подмена команды отвергнута дважды: хук харнеса правит не саму команду, а только отвечает на неё, и подмена скрыла бы от агента, чем прогон отличается от заказанного. Находка срабатывает в дереве, подключённом к devkit (каталог .devkit выше по дереву), у голой команды без обёртки regcheck, devkitctl или parallel.py.

## Ход работы

- Вычитка: 3 файла, 9 правок, 2 пометки, 2026-09-28.
- Разработка, 2026-09-29. Обёртка легла модулем `tools/devkitctl/testrun.py` и
  подкомандой `devkitctl test <путь>`. Слот, бюджет и приоритет берутся у
  соседнего `parallel.py`, второй копии формулы нет. У `full_run_slot` появилась
  метка строки ожидания, умолчание оставило прежнюю строку полного прогона.
- Раннер выбирается по каталогу. `go.mod` это go-модуль, свой `suite.py` это
  собственный раннер каталога, файлы `*_test.py` это `unittest discover`.
  Названный именем хвост (модуль, класс, метод) уходит `unittest` напрямую. Ни
  перебор, ни `suite.py` имени не принимают, а длинный прогон дробится этим же
  хвостом.
- Журнал. Запись частичного прогона несёт поле `scope`. На стороне go у
  `testRunRecord` появилось то же поле, и счётчик чужой красноты
  (`foreignFails`) записи с непустым `scope` не считает. Красный частичный
  прогон это штатный шаг автора, слияния он не отбивал.
- `regcheck` получил признак упавшего теста у обёртки (`failMarkers`).
  Стандарт зовёт обёртку из-под `regcheck`, и без своей строки её ненулевой код
  шёл бы краснотой без разбора, включая отказ на каталоге без тестов.
- Правило въехало в ядро одной фразой. На скиллах и определениях исполнителя
  стенд дал 3 из 5 против 0 из 5, разница незначима. С фразой в ядре 5 из 5
  против 0 из 5, вердикт «польза».
- Сторож прозы: hooks/README.md, средняя длина предложения 19,3 при пороге 19,
  оставлено: перестройка фраз раздела просадила остальные метрики, а файл и без
  правки стоял над порогом предупреждения.

## Сценарий проверки

Предмет: обёртка частичного прогона и рубеж на прямую команду.

1. Обёртка гонит пакет go-модуля, печатает бюджет и строку итога.

```sh
devkitctl test ~/projects/devkit/tools/secretctl
```

Ждём строку «бюджет параллельности: ядра=<N> доля прогона=<N> приоритет=nice 19»
и строку итога «go:secretctl (tools/secretctl) <секунды>s ok», код возврата 0.

2. Запись частичного прогона легла в журнал с областью.

```sh
tail -1 ~/projects/devkit/.devkit/test-runs.log | python3 -c "import json,sys; r=json.load(sys.stdin); print(r['scope'], r['ok'], r['components'][0]['name'])"
```

Ждём «tools/secretctl True go:secretctl».

3. Каталог без тестов это отказ с перечнем признаков.

```sh
devkitctl test ~/projects/devkit/docs; test $? -eq 2
```

Ждём строку «нет ни go.mod, ни suite.py, ни файлов *_test.py» и код 2.

4. Рубеж отбивает прямую команду и печатает замену.

```sh
python3 ~/projects/devkit/hooks/check-bare-test.py "go test -C ~/projects/devkit/tools/taskctl ./... -run TestBoardMove"; test $? -eq 1
```

Ждём первой строкой «Прямой go test отбит рубежом DK-1219, повтори ход этой
командой: devkitctl test /Users/rider/projects/devkit/tools/taskctl -run TestBoardMove».

5. Прогон под обёрткой рубеж пропускает.

```sh
python3 ~/projects/devkit/hooks/check-bare-test.py "regcheck -- go test ./..."
```

Ждём пустой вывод и код 0.

6. Рубеж подключён к харнесу машины.

```sh
devkitctl doctor --fix 2>&1 | grep -c check-bare-test
```

Ждём число больше нуля: либо строка подключения хука, либо его отсутствие
находкой.
