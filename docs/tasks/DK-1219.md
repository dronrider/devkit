# DK-1219: Потолок параллельных прогонов накрывает прямой go test и unittest

Цель: [tasks/DK-1084.md](tasks/DK-1084.md)

## Что происходит

DK-1162 поставила потолок числа одновременных полных прогонов. Это замок `~/.devkit/parallel-slots` с одним слотом по умолчанию, лишний запуск ждёт. Замок берёт `parallel.py`. Исполнитель, проверяющий свою правку, зовёт `go test -C <дерево>/tools/taskctl ./...` или `python3 -m unittest` напрямую, и такой прогон замок не проверяет. 2026-09-28 в 19:45 под замком шёл `shipctl merge DK-1204`, а рядом третья сессия гоняла `go test` по дереву dk-1205 с потолком 9 минут. Load average в эти минуты держался на 76-89 при десяти ядрах.

## Чего хотим

Прямой прогон тестов из дерева задачи встаёт в ту же очередь слотов, что и полный прогон. Вход один. Обёртка `devkitctl test <путь>` берёт слот, при занятом слоте печатает строку ожидания и зовёт `go test` или `unittest` по типу каталога с тем же бюджетом параллельности и приоритетом, что у `parallel.py`. Скиллы исполнителя и стандарт тестов зовут обёртку вместо голых команд. Голый `go test` в дереве задачи становится находкой хука. PreToolUse на Bash печатает замену.

Снаружи видно так. Обёртка печатает строку ожидания слота, а в `.devkit/test-runs.log` записываются частичные прогоны с полем `scope`.

## Сценарий проверки

Предмет: обёртка частичного прогона и рубеж на прямую команду. Шаги идут из
корня чекаута относительными путями: обкатка гоняет их в свежем дереве с
подменным домом, и `~/projects/devkit` там указывает в пустоту.

1. Обёртка гонит пакет go-модуля, печатает бюджет и строку итога.

```sh
python3 tools/devkitctl/devkitctl.py test tools/secretctl
```

Ждём строку «бюджет параллельности: ядра=<N> доля прогона=<N> приоритет=nice 19»
и строку итога «go:secretctl (tools/secretctl) <секунды>s ok», код возврата 0.

2. Запись частичного прогона легла в журнал с областью.

```sh
mkdir -p .devkit && python3 tools/devkitctl/devkitctl.py test tools/secretctl > /dev/null && tail -1 .devkit/test-runs.log | python3 -c "import json,sys; r=json.load(sys.stdin); print(r['scope'], r['ok'], r['components'][0]['name'])"
```

Ждём «tools/secretctl True go:secretctl».

3. Каталог без тестов это отказ с перечнем признаков.

```sh
python3 tools/devkitctl/devkitctl.py test docs; test $? -eq 2
```

Ждём строку «нет ни go.mod, ни suite.py, ни файлов *_test.py» и код 2.

4. Рубеж отбивает прямую команду и печатает замену с каталогом.

```sh
mkdir -p .devkit && python3 hooks/check-bare-test.py "go test -C tools/taskctl ./... -run TestBoardMove"; test $? -eq 1
```

Ждём первой строкой «Прямой go test отбит рубежом DK-1219, повтори ход этой
командой: devkitctl test <корень>/tools/taskctl -run TestBoardMove».

5. Обёртка-префикс с ключами команду не прячет, а прогон под чужим первым
словом рубеж пропускает.

```sh
mkdir -p .devkit && python3 hooks/check-bare-test.py "nice -n 19 go test ./..."; test $? -eq 1
mkdir -p .devkit && python3 hooks/check-bare-test.py "regcheck -- go test ./..."; test $? -eq 0
```

Ждём отказ на первой команде и пустой вывод с кодом 0 на второй.

6. Пример прямой команды внутри heredoc рубеж пропускает.

```sh
mkdir -p .devkit && printf 'cat > doc.md <<EOF\ngo test ./... -run TestX\nEOF\n' | python3 hooks/check-bare-test.py --stdin; test $? -eq 0
```

Ждём пустой вывод и код 0.

7. Рубеж стоит в раскладке хуков харнеса.

```sh
python3 -c "import sys; sys.path.insert(0, 'tools/devkitctl'); import devkitctl as d; print(sum(1 for e, m, c in d.HOOK_LAYOUT if 'check-bare-test' in c), 'check-bare-test.py' in d.PRE_SCRIPTS, 'check-bare-test.py' in d.PRE_GAPS)"
```

Ждём «1 True True».
