# DK-123: shipctl start в корп-контуре зовёт merge, которого там нет

Найдено прогоном сценария DK-087 на живом корп-стенде. `shipctl start` в
корп-контуре заканчивает строкой «по готовности: shipctl merge <ID>», а `merge`
там отказывает: слияние ведёт MR-флоу компании. Первый же шаг пользователя в
подключённом проекте зовёт команду, которая ему откажет.

Подсказка в корп-контуре должна называть настоящий следующий шаг: `trackctl
submit`, пуш ветки, MR. Текст этого шага уже есть в отказе `merge`
([shipctl/corp.go](../../shipctl/corp.go)), сочинять его заново не надо.

## Ход работы

- Разработка: субагент sonnet/high по вердикту pick (маппинг haiku, корректор: профицит week_all; квота: week_all 28% профицит, снимок 16м назад), 2026-09-17 00:27-02:27.
- Текст ручного пути вынесен константой `corpNextSteps` в `shipctl/corp.go` и
  используется и отказом `merge`/`ship`/`revert`, и подсказкой на конце
  `shipctl start`: в привязанном контуре последняя строка отчёта `start`
  теперь называет `trackctl submit`, пуш ветки и MR вместо `shipctl merge
  <ID>`, которого там нет. Вне контура подсказка не менялась. Добавлен тест
  `TestCorpStartHintsRealNextStep` (`shipctl/corp_pipeline_test.go`): падает
  на коде до правки (отчёт `start` называл `shipctl merge`) и проходит после.
  Дописана строка в `shipctl/README.md`, раздел «Корп-контур».

## Сценарий проверки

Агентский. Тесты пакета конвейера корп-контура, окружение синтетическое
(временный git-репозиторий и боковая директория с фикстурой привязки, живой
корп-стенд не трогается).

```sh
PATH=/usr/local/go/bin:$PATH go test ./tools/shipctl/... -run 'TestCorpStartHintsRealNextStep|TestCorpMergeShipRevertRefuse' -v
```

Ожидается `PASS` по обоим тестам и `ok` для пакета `tools/shipctl`: отчёт
`shipctl start` в привязанном контуре не содержит подстроку `shipctl merge`, а
называет `trackctl submit`, и это тот же текст, каким `merge` в том же
контуре отказывает.
