# DK-1246: просмотр блока decide --chat не паркует задачу чужой сессией

## Что происходит

2026-09-30 10:04, консультационная сессия по DK-1233 (заголовок чата «DK-1233 один вариант ответа») прогнала `taskctl decide DK-1233 --chat` через Bash ради диагностики. Команда переписала признак `.devkit/chat/task-DK-1233.ask` на ID этой сессии (tools/taskctl/ask.go, WriteAsk с askSession), позвала уведомитель и поставила этап «ждёт человека» второй раз. В run-файле задачи две строки «ждёт человека»: 00:42 от захода ветки и 10:04 от консультации.

Блок вопроса появился в ленте чужого чата, человек принял его за новый вопрос. Команда, которую зовут посмотреть блок, имеет побочное действие парковки, и любой диагностический вызов утаскивает ожидание задачи с сессии-исполнителя.

## Чего хотим

Просмотр блока из сторонней сессии ожидание задачи не двигает. Реестр в выборе адресата бьёт окружение, признак переписывает только сессия-держатель. Чужой диагностический вызов повторный этап «ждёт человека» не ставит.

## Развилки

Разделить печать и парковку флагом, или парковать только сессию, у которой задача взята в работу, или признак с чужой сессии не перезаписывать?

Обход назвал механизм. askSession выбирает адресата в порядке ключ, затем переменная окружения DEVKIT_TMUX, затем реестр (tools/taskctl/ask.go:158-171). Окружение консультационной сессии победило реестр. LLD DK-430.2 называет живого адресатом сессию реестра, держатель клавиатуры тут ни при чём. Для диагностики хватает готового обхода. `env -u DEVKIT_TMUX taskctl decide <ID> --chat` не трогает признак.

- «адресат»: как просмотр блока из сторонней сессии перестаёт парковать задачу?
  - решает: исполнитель
  - рекомендация: реестр бьёт окружение в выборе адресата askSession, чужой вызов признак не переписывает
  - вариант: флаг печати без парковки у decide --chat
  - источник: код, tools/taskctl/ask.go:42-51 и :158-171, internal/chat/chat.go:439-447, архитектура LLD DK-430.2, сосед DK-756.4

## DoD

Диагностический вызов `decide --chat` из сторонней сессии не переписывает признак и не добавляет строку «Ждёт человека» в run-файл. Уведомитель не зовётся повторно. Ответ человека уходит адресату из реестра, в чат вызвавшего он не попадает.
