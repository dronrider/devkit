# DK-1262: Тикет трекера входит на доску черновиком и проходит груминг

## Что происходит

Разбор 2026-09-30 по жалобе контрибьютора: задача из Jira сделана агентом
заметно хуже обычной, скиллы груминга и постановки в заходе не звались.
Сверка по коду показала, что вход тикета в работу описан без груминга:
`trackctl take <KEY>` без зеркальной строки на доске идёт дальше и только
печатает «зеркальной строки с ключом нет, считать эстимейт не из чего»
(`tools/trackctl/cmd.go:130-163`); `RULES.local.md` строкой 7 говорит, что в
корп-контуре доска не ведётся, а пунктом 8 задаёт порядок take -> код ->
submit без шага заведения строки; LLD DK-074 требует, чтобы ранг и цену
зеркальной строке проставлял локальный грумминг, но кто заводит саму строку,
не говорит нигде. Единственная команда, которая делает строку из тикета,
это `trackctl review`, и она же одна копирует постановку тикета в файл
(`fillReviewFile` в `review.go`). Стенд obeycheck сценария на вход из трекера
не имеет.

Тикет уходит в код мимо груминга, pick и всех ворот доски, и ни одна команда
этого не отбивает: расхождение видит только `trackctl sync` постфактум. В
корп-контуре путь работы отличается от домашнего, и всё, что лежит в скиллах
доски, до такой задачи не доезжает. Итог видел контрибьютор: работа сдана
плохо, а причина в устройстве входа, а не в заходе.

## Чего хотим

Вход на доску один для обоих контуров: тикет становится черновиком с
постановкой и ссылкой, груминг оформляет его строкой со ссылкой на тикет,
и она же служит зеркальной. `trackctl take` без зеркальной строки
отказывает и печатает команду заведения черновика. `RULES.local.md` вместо
«доска не ведётся» описывает порядок тикет -> черновик -> груминг -> take.
Сценарий obeycheck держит этот вход.

## Границы

Фейковый адаптер трекера в боевой сборке и сценарий obeycheck на вход тикета
остаются за границей: стенду нужен адаптер без сети, это отдельная строка.
Условий, посильных только человеку, до старта не нашёл: токен Jira и контур
у пользователя стоят, проверка на второй машине идёт приёмкой.

## DoD

- `trackctl draft <KEY>` кладёт тикет черновиком: заголовок из summary,
  постановка тикета в «Ситуацию», ссылка на тикет в тексте, уровень разбора
  из аргумента. Без токена и без контура команда отказывает словами.
- Груминг оформляет такой черновик строкой обычным порядком, а ссылка на
  тикет встаёт в ячейку доски (`taskctl set --link` в порядке скилла
  `board-groom` либо тем же `add --id`), и `trackctl issue`, `take`, `sync`
  видят строку зеркальной.
- `trackctl take <KEY>` без зеркальной строки отказывает и печатает команду
  `trackctl draft <KEY>`; с зеркальной строкой поведение прежнее.
- В devkit лежит коммитимый образец `RULES.local.example.md` с порядком
  «тикет -> черновик -> груминг -> take» вместо фразы «доска не ведётся», а
  `devkitctl doctor` называет находкой локальный файл, у которого нет
  раздела образца по маркеру.
- LLD DK-074, раздел «Граница доски и тикета», получает приписку: постановка
  тикета копируется в черновик и файл задачи, решение DK-756 распространяется
  на вход исполнения.
- README `trackctl` и скилл `board-groom` описывают вход тикета шагами первого
  запуска; тесты на `draft`, отказ `take` и находку доктора.

Ожидания по шагам:

1. Раскладка синтетического окружения: доска без строк, контур с недостижимым
   адресом, привязка с ключом `ABC`. Своего вывода у шага нет.
2. `take` без зеркальной строки отказывает и называет команду заведения
   черновика. Отказ приходит до разговора с трекером, поэтому недостижимый
   адрес на шаг не влияет.
3. `draft` без уровня разбора отказывает и называет допустимые уровни.
4. `draft` с уровнем идёт в трекер и отказывает словами про отсутствующий
   токен. Черновика при этом не появляется.
5. `devkitctl doctor` называет находкой локальный `RULES.local.md` этой машины,
   у которого нет раздела «Вход тикета на доску». Чинится находка переносом
   раздела из коммитимого образца `RULES.local.example.md`.

Шаги пользователя (в корп-клоне, на живом тикете):

1. `trackctl draft <живой KEY> --prio mid` кладёт черновик. Ожидание: файл

2. Груминг оформляет черновик строкой, ссылка на тикет уезжает в ячейку

   `trackctl sync` видят строку зеркальной.
3. `trackctl take <KEY>`. Ожидание: тикет уходит в In Progress с исполнителем
   и оценкой из цены строки, как прежде.

- Исключение: стенд (вход тикета стенд не прогоняет, адаптера трекера без
