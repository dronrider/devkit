# DK-1266: sessions.go дашборда разбит, планы субагентов отдельным модулем

## Что происходит

sessions.go это второй гигант каталога: 3591 строка, шесть тем. Обход корней
и файлов транскриптов, разбор reply JSONL (parseReplies и_contentTexts),
пиры (peerKind), SSE-стриминг (streamSession), планы субагентов (planStamp
-> planOrdered, около 1000 строк отдельной подсистемы), занятость (busyNow).
Пропорция с sessions_test.go (3029 строк, 74 теста) честная, но сам файл
мешает: подсистема планов и разбор реплик тянут на отдельные модули.

## Чего хотим

Домен реестра собирается в пакет sessions. Планы субагентов и разбор реплик
лежат в нём отдельными файлами, наружу смотрят явные точки входа. Обход
транскриптов, пиры, стриминг и занятость остаются в sessions.go или
расходятся по темам, если разрез ложится естественно. Поведение наружу не
меняется.

## DoD

- Домен реестра собран в пакет sessions с явными точками входа.
- Ни один файл пакета не больше ~700 строк.
- Тесты переложены по конвенции из DK-1264.
- Смоук и тесты проходят.

## Ранг

`25+5+1+0+3 = 34`, P2.

- Серьёзность 25: правка реестра читается в гиганте.
- Ценность 5: реестр сессий это вход во все экраны ленты.
- Неопределённость 1: разрез назван обзором.
- Рычаг 3: разблокирует правки планов и стриминга.
