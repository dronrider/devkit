# DK-130: board-groom: исследование черновика до оформления, режимы захода и тест скилла

Задача цели DK-128 (`docs/tasks/DK-128.md`), последняя перед разбором самого
накопителя. Скилл сегодня описывает оформление и начинается с уже принятого
решения «оформляем»: признака зрелости черновика в процедуре нет, актуальность
не проверяет никто, заходов два, один ID либо весь накопитель.

Механика исходов приехала на DK-132: у `taskctl draft` есть `defer`, `attach`,
`drop`, дата записи и пометка в списках. Эта задача переписывает процедуру под
них. Решения и доводы в `docs/lld/DK-129-groom-process.md`, состав работы в его
разделах «Разбивка на задачи» и «Затрагиваемая документация».

## Что сделать

- переписать `skills/board-groom/SKILL.md` по решениям 1, 3 и 5: фаза разбора
  до фазы диалога, трое ворот критерия готовности с их исходами, ранг вслух с
  причиной по каждому слагаемому, смягчённый шаг про цену, поиск дубля в том
  числе по накопителю, три входа (ID, список ID, весь накопитель), граница по
  числу черновиков с вопросами за заход, четыре исхода разбора с командой под
  каждый, право отдать проверку актуальности субагенту;
- сторож процедуры в `skills/test.sh` рядом с теми, что стоят по `goal-loop` и
  `goal-start`: три входа и четыре исхода;
- по строке про ранг вслух с причиной в `skills/board-task/SKILL.md` (п. 3
  раздела «Новая задача») и `skills/goal-loop/SKILL.md` (шаг 3), решение 6;
- фраза про четыре исхода черновика и оформление по критерию в `RULES.board.md`,
  п. 5 раздела «Трекинг задач». Ядро `RULES.board.core.md` не трогается;
- строка про `board-groom` в `README.md` devkit: скилл перестаёт быть только
  оформлением.

## Границы

Накопитель не разбирается, это DK-131: живые черновики в `docs/tasks/drafts/`
не помечаются, не приписываются и не удаляются. Код `taskctl` не трогается,
он приехал на DK-132.

## DoD

Процедура скилла описывает разбор до оформления, три входа и четыре исхода;
`sh skills/test.sh` печатает `ok` и сторожит это машинно; названные документы
знают про новый порядок.

## Сценарий проверки

Агентский: `sh skills/test.sh` печатает `ok`; сторож краснеет, если из
`SKILL.md` убрать раздел про входы или про исходы (проверяется мутацией);
`python3 hooks/check-symbols.py` по тронутым файлам проходит; `taskctl lint`
зелёный.
