# DK-1312: Длинный заход с простоями не платит мегатокены за перезапись префикса

## Что происходит

Цифра: 1615 запросов из 125559 переписали префикс, суммарно записано 361M токенов кусками по ~900k.
Пример: поток 8257b5e0 на запросе 2103 из 2772 записал 943821 токен, чтение кэша упало с 940279 до нуля; десятки таких перезаписей приходятся на один поток.
Мера: порог ротации по числу ходов и объёму префикса с отметкой ротации в журнале сессий.

Обход показал другую причину. Перезапись приходится не на рост префикса, а на
простой с истечением TTL кэша. Из 1613 событий перезаписи 1449 идут после
простоя больше пяти минут и пишут 320.9M из 361M токенов. Любой простой от
тридцати секунд закрывает 96.8% перезаписи. На гистограмме зазоров по основным
потокам видна подпись часового TTL, о нём же записано в DK-100 и DK-108.
Ротация из меры черновика лечит следствие. Порог уменьшает цену перезаписи
коротким префиксом, 361M доходит до ~200M при пороге 500k и до ~60M при 150k.
Причину ротация не снимает. Прямой обход причины это дешёвое чтение кэша в
простое, в devkit его нет. Готовая механика ротации уже есть в agentctl rotate,
порог она меряет токенами. DK-662 держит ту же ротацию с отметкой журнала,
DK-849 пользу ротации на prompt-test не доказал. Смена модели в потоке и правка
головы харнесом дают ещё по 1.6% токенов перезаписи. Счёт разошёлся. В черновике
1615 запросов, в обходе 1613 событий на 584 потоках, сумма записей одна.

## Чего хотим

Длинный заход с простоями не платит мегатокены за перезапись префикса. Работа
механики с префиксом видна снаружи строкой журнала сессий, молчание за работу
не считается. Падение записи по квоте меряется тем же обходом, каким считали
361M.

## Границы

Готовая механика ротации уже есть в agentctl rotate, DK-662 держит ротацию с
отметкой журнала, DK-849 её пользу на prompt-test не доказал. Сценарий проверки
пишет исполнитель. Условий, посильных только человеку, не нашёл.

## DoD

Перезапись префикса после простоя не платит мегатокенами захода. Доля записи
префикса в расходе падает и считается тем же обходом, каким считали 361M. Работа
механики с префиксом видна снаружи строкой журнала сессий, молчание за работу не
считается. Строка ротации с отметкой журнала бронируется один раз общей механикой
agentctl rotate. В записи DK-662 стоит одна строка про границу.

## Ранг

`25+8+2+0+4 = 39`, P2.

Серьёзность 25. Конвейер идёт, но длинные заходы платят лишнюю квоту. Суммарно
это 361M токенов записи префикса и десятки перезаписей на поток. На человека
работа не встаёт, обход дешёвый, порог ротации уже есть готовой механикой.

Ценность 8. Каждый виток и пачка дешевле по квоте, если длинный заход не платит
за перезапись префикса. Масштаб меньше DK-662: та отдавала больше половины
недельной квоты.

Неопределённость 2. Кейсы, предмет и стык закрыты ответами, обе меры записаны в
DoD. Открыта деталь механики, развилка «мера порога» оставлена исполнителю.
Задача идёт с диспетчером в цикле.

Поправка на баг 0. TTL это устройство провайдера, ротации не было, ломаться
было нечему. Нарушение DK-100 в правке головы малой доли и в предмет не тянет.

Рычаг 4. Каждый длинный заход дешевле по квоте, тот же рычаг, что у DK-662.
