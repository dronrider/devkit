# DK-1319: доктор находит дом харнеса без переменной отключения классификатора

## Что происходит

Клиент через сторонний шлюз на первом чувствительном вызове показывает
диалог о смене оплаты классификатора auto-режима и ждёт Enter, снаружи чат
выглядит зависшим. Переменная env CLAUDE_CODE_AUTO_MODE_SERVER=0 в доме
харнеса отключает серверные проверки классификатора, и диалог не появляется
вовсе. Дома харнесов (~/.devkit/claude-glm, claude-routerai, claude-mimo)
ведутся руками, и за переменной никто не следит. Её вписали в glm 01.10
после первого зависания, а 07.10 чат routerai простоял на диалоге полчаса,
потому что дом жил без защиты; в mimo той же причиной отбивались
чувствительные вызовы до конца дня. Клиент называет переменную временной,
и будущая версия может её убрать, тогда защита пропадёт молча у всех домов
сразу.

## Чего хотим

Дом харнеса без переменной становится находкой devkitctl doctor, в находке
имя дома и имя переменной. Дома харнесов доктор уже смотрит, там лежит
находка симлинка из DK-193, и новая проверка ложится туда же. Чинит ли
находка дом сам ключом --fix, решает исполнитель по устройству доктора.

## DoD

На стенде с домом без переменной doctor печатает находку с именем дома. На
стенде с переменной во всех домах doctor завершается без этой находки.

## Ранг

`25+3+1+0+2 = 33`, P2.

- Серьёзность 25: чат стоит и выглядит умершим, обход есть, но требует диагноза с нуля.
- Ценность 3: страховка от тихой потери защиты.
- Неопределённость 1: место проверки видно по находке симлинка.
- Поправка на баг 0: новая работа.
- Рычаг 2: находка бережёт поднятые чаты всех подписок разом.

## Ход работы

Проверка легла в `check_sub_catalog` рядом с подстановками алиасов: это тот
место, где доктор уже читает `settings.json` каждого дома харнеса из ключа
`home` машинного слоя. Дом без `CLAUDE_CODE_AUTO_MODE_SERVER=0` даёт находку
с путём конфига (в нём имя дома) и именем переменной, `--fix` прописывает
значение сам из основного чекаута, как у подстановок. Стенды с «заполненным»
конфигом (testenv.alt_sub, тест 15 MachineContour) дополнены переменной:
заполненное состояние теперь включает её. Тесты: AltSubDirTest (находка,
фикс, чужое значение, рубеж worktree), MachineContourTest.test_19 на уровне
доктора. README девкитконтрола дополнен, вычитка пройдена. Прогон зелёный:
AltSubDirTest, WindowCopyTest, MachineContourTest, SecondSubscriptionLayoutTest
и CodexLayoutTest под обёрткой devkitctl test, краснота на старом коде
доказана regcheck. Живой прогон доктора на этой машине по всем четырём домам
молчит: переменную в них уже вписали руками, и находка не сверкает ложняком.

Замечание ревью о копии окна закрыто правкой. Переменная прописана в want
check_window_copy известным значением «0», без зеркала машинного слоя. Ключ
`--fix` раскладывает её в копию вместе с ключами подписки и подстановками
алиасов. Тест test_auto_off_rides_to_the_window_copy держит находку и фикс.
Краснота на старом коде доказана regcheck. Сюита devkitctl зелёная, 1273
теста. Коммит 01fd5b758. Вычитка дельты README и этого абзаца пройдена,
правок ноль.

## Сценарий проверки

Прогон идёт из корня свежего дерева. HOME у обкатки временный. Стенд второй
подписки заводится в нём сам и после шагов не живёт. Доктор зовётся питоном
из дерева, установленная на машине копия ещё не несёт правки задачи. Путь
--fix в сценарии не гоняется: из worktree непроверенной ветки ключ писать
переменную отказывается, зелёность этого пути держит сюита AltSubDirTest.
Токен и адрес в стенде подставные.

1. Стенд машинного слоя без переменной. Вторая подписка объявлена в
harness.local, в её конфиге ключи болванки и ни CLAUDE_CODE_AUTO_MODE_SERVER.

```sh
mkdir -p "$HOME/.devkit/claude-glm" && printf 'enabled = ["claude-code"]\n\n[glm-code]\nhome = "~/.devkit/claude-glm"\n' > "$HOME/.devkit/harness.local" && printf '{"env": {"ANTHROPIC_BASE_URL": "https://gateway.example/anthropic", "ANTHROPIC_AUTH_TOKEN": "токен-стенда", "ANTHROPIC_MODEL": "модель-стенда"}}\n' > "$HOME/.devkit/claude-glm/settings.json" && chmod 700 "$HOME/.devkit/claude-glm" && chmod 600 "$HOME/.devkit/claude-glm/settings.json"
```

2. Доктор по стенду находит дом без защиты. Жду ровно одну строку про
переменную, в ней путь конфига с именем дома claude-glm и само имя
CLAUDE_CODE_AUTO_MODE_SERVER.

```sh
python3 tools/devkitctl/devkitctl.py doctor | grep "CLAUDE_CODE_AUTO_MODE_SERVER" | grep "claude-glm"
```

3. Значение вписано в стенд, как его вписывал бы --fix из основного чекаута.

```sh
printf '{"env": {"ANTHROPIC_BASE_URL": "https://gateway.example/anthropic", "ANTHROPIC_AUTH_TOKEN": "токен-стенда", "ANTHROPIC_MODEL": "модель-стенда", "CLAUDE_CODE_AUTO_MODE_SERVER": "0"}}\n' > "$HOME/.devkit/claude-glm/settings.json"
```

4. Стенд с переменной во всех домах чист. Повторный доктор о переменной
молчит, остальные находки стенда остаются и ожидаемы. Код доктора на
шумных находках ненулевой, поэтому его вывод отделяется точкой с запятой,
а не склейкой через &&.

```sh
python3 tools/devkitctl/devkitctl.py doctor > doctor-after.out; ! grep -q "CLAUDE_CODE_AUTO_MODE_SERVER" doctor-after.out && rm doctor-after.out
```
