# DK-1319: доктор находит дом харнеса без переменной отключения классификатора

## Что происходит

Клиент через сторонний шлюз на первом чувствительном вызове показывает
диалог о смене оплаты классификатора auto-режима и ждёт Enter, снаружи чат
выглядит зависшим. Переменная env CLAUDE_CODE_AUTO_MODE_SERVER=0 в доме
харнеса отключает серверные проверки классификатора, и диалог не появляется
вовсе. Дома харнесов (~/.devkit/claude-glm, claude-routerai, claude-mimo)
ведутся руками, и за переменной никто не следит. Её вписали в glm 01.10
после первого зависания, а 07.10 чат routerai простоял на диалоге полчаса,
потому что дом жил без защиты; в mimo той же причиной отбивались
чувствительные вызовы до конца дня. Клиент называет переменную временной,
и будущая версия может её убрать, тогда защита пропадёт молча у всех домов
сразу.

## Чего хотим

Дом харнеса без переменной становится находкой devkitctl doctor, в находке
имя дома и имя переменной. Дома харнесов доктор уже смотрит, там лежит
находка симлинка из DK-193, и новая проверка ложится туда же. Чинит ли
находка дом сам ключом --fix, решает исполнитель по устройству доктора.

## DoD

На стенде с домом без переменной doctor печатает находку с именем дома. На
стенде с переменной во всех домах doctor завершается без этой находки.

## Ранг

`25+3+1+0+2 = 33`, P2.

- Серьёзность 25: чат стоит и выглядит умершим, обход есть, но требует диагноза с нуля.
- Ценность 3: страховка от тихой потери защиты.
- Неопределённость 1: место проверки видно по находке симлинка.
- Поправка на баг 0: новая работа.
- Рычаг 2: находка бережёт поднятые чаты всех подписок разом.
