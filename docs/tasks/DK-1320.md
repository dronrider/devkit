# DK-1320: черновик мимо taskctl draft ловится до коммита

## Что происходит

Разбор 07.10 по транскриптам нашёл механику. Сессия перед записью
долгоживущего текста берёт выборку корпуса жанра task, как требует хук
прозы, а фрагмент корпуса оформлен шапкой «## постановка (task)» с полями
«источник» и «роль». Правило мимикрии велит писать как корпус, и сессия
копирует форму фрагмента в сам файл. Так 5-6 октября легли DK-1300,
DK-1302, DK-1303 и DK-1305, номер сессия назначала сама через taskctl id
или grep по доске. У таких файлов нет заголовка-исхода и приоритета,
накопитель показывает сырую первую строку, и черновик выпадает из очереди
разбора. Рубежа на пути нет. Хуки записи проверяют символы, прозу и
секреты, но не форму черновика, lint сверяет разделы файлов задач, доктор
черновики не смотрит. Ошибочная форма прошла запись, коммит и пуш четыре
раза. Смежный дефект механики черновиков лежит в DK-925.

## Чего хотим

Файл черновика не по форме TASKFORM ловится до коммита. Носитель рубежа
открыт. Либо находка lint или доктора по первой строке файла (не «# DK-N:
заголовок», нет строки «записан» или «приоритет»), либо отказ хука на
запись в docs/tasks/drafts/ с отсылкой к taskctl draft. Выбирает исполнитель
по устройству линта и хуков.

## DoD

На стенде файл в docs/tasks/drafts/ с первой строкой не «# DK-N: заголовок»
даёт находку или отказ до коммита. Черновик, записанный taskctl draft,
проходит рубеж чисто.

## Ранг

Серьёзность 25, черновики выпадают из очереди груминга и находка повторяется
с каждой партией дежурства, обход есть, но требует разбора с нуля. Ценность
3, чинит вход в доску для всех будущих черновиков. Поправки на баг нет.
Неопределённость 2, носитель рубежа это открытая развилка из двух зрелых
вариантов. Рычаг 2, находка бережёт весь поток разбора накопителя.
