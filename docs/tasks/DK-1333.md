# DK-1333: Незапушенный код main роняет слияние через фикстный тест линты

## Что происходит

Ночью 2026-10-09 в 02:19 слияние DK-1312 ушло из очереди с формулировкой
«краснота в диффе задачи: go:obeycheck». Красный тест это
TestFixtureProjectPassesLint в tools/obeycheck/env_test.go. Линта фикстуры
нашла «main впереди origin/main на 3 коммита с кодом». За полминуты до
слияния сессия закоммитила три код-коммита на локальный main без пуша. Тик
тут же пошёл сливать задачу.

Прогон идёт в свежем дереве, его заводит freshtree.Make командой
`git worktree add --detach`. Worktree делит рефы с основным чекаутом, из
дерева видны локальный main и origin/main носителя. Фикстура при этом не
самодостаточна, `taskctl -C фикстура lint` поднимается в репозиторий вокруг
себя. Правило mainAheadFinds (DK-602, tools/taskctl/mainahead.go) видит
опережение и пишет находку линты. Утром коммиты переложили и запушили.
Повод красноты исчез, а строка осталась снятой и ждала рук.

## Чего хотим

Слияние не краснеет от git-состояния основного чекаута машины. Прогон в
свежем дереве судит код ветки, про пуш main у автора сессии ему знать
незачем.

## DoD

- локальный main с незапушенными код-коммитами не роняет слияние чужой
  задачи: TestFixtureProjectPassesLint в свежем дереве зелёный
- правило DK-602 в живом репозитории работает как раньше и забытый пуш
  находит
