# DK-1335: Судья живости читает реестр ~/.claude/sessions, а сессии пишутся в каталог подписки

## Что происходит

Открытые этапы работы печатают в подсказке «сессии нет, брошена». Строки на
доске красные, хотя рабочие сессии живы. Текст собирает `taskctl`. Этап берёт
список сессий задачи и прогоняет их через `peers.Judge`
(`tools/taskctl/stagenote.go`). Карта для судьбы собирается `peers.Load`, и
каталог для неё задаёт `peers.Dir`. Путь там жёсткий `~/.claude/sessions`
(`internal/peers/peers.go`). Клиент пишет файл реестра в
`$CLAUDE_CONFIG_DIR/sessions`. Это каталог подписки, например
`~/.devkit/claude-mimo/sessions` или соседний конфиг-каталог. Каталог
`~/.claude/sessions` остаётся пустым. Судья не находит ни одной записи и
возвращает `Gone`. Фронт дашборда видит строку «сессии нет, брошена» и ставит
класс `k-gone` (`tools/dashboard/static/app.js`), и от этого строка красная.

Проверено на четырёх строках секции In progress. Запись сессии каждой из них
лежит в каталоге подписки. pid живые, рабочие tmux-окна на месте. Работа идёт,
чтение реестра падает.

Есть отдельная особенность, в эту задачу она не входит. Запись живости
обновляется касаниями. У долгого хода касание перерастает рубеж простоя.
После починки пути часть строк покажет «сессия молчит N минут». Зелёное
«сессия жива» они получат от свежих касаний.

## Чего хотим

`peers.Load` перебирает каталоги, где реально лежат записи. Это каталог своей
подписки из `CLAUDE_CONFIG_DIR`, соседние конфиг-каталоги
`~/.devkit/claude-*/sessions` и старый `~/.claude/sessions`. По ним судья
находит живые сессии. Открытый этап работы получает `Gone` лишь когда сессий
действительно нет. Дашборд читает тот же пакет и чинится вместе с ним.

## DoD

Сценарий. Запись сессии этапа лежит в `$CLAUDE_CONFIG_DIR/sessions`. Каталог
`~/.claude/sessions` пуст, pid жив. `taskctl show` по задаче с открытым этапом
работы печатает «сессия жива» либо «сессия молчит». На «сессии нет, брошена»
не переходит. Строка на доске не красная. Тест на сбор каталогов реестра
падает на старом коде и проходит на исправленном. Прогон идёт через
`regcheck`.
