# DK-134: taskctl: -m съедает следующий флаг как сообщение, пуш молча пропадает

записан 2026-08-05

Флаг `-m` у изменяющих команд `taskctl` объявлен через `flag.StringVar`, и когда
значение после него не передано, парсер берёт значением следующий аргумент,
даже если тот сам флаг. Вызов `taskctl add ... -m --push` из-за этого коммитит
с сообщением `--push`, а сам `--push` остаётся невыставленным, и команда
рапортует про коммит как про удачу. Тихо портится сообщение коммита доски и
молча пропадает пуш, доска после этого отстаёт от origin.

## Что происходит

Прогон на синтетической доске 2026-08-07, симптом жив:

```text
$ taskctl add --id TT-001 --title "проверка" ... -m --push
TT-001 заведена в backlog: P3, R=6, коммит ab0b736
$ git log --oneline -1
ab0b736 --push
```

Обход у пользователя есть: передать `-m` его значение. Семейство то же, что у
DK-099 (разбор аргументов taskctl), но правка там другая: DK-099 читает
позиционные аргументы из `fs.Args()` после `Parse`, а здесь `Parse` съедает
`--push` штатно, и до позиционных аргументов дело не доходит.

## Чего хотим

Отказ до коммита, когда значение `-m` начинается с дефиса: такое сообщение это
почти наверняка проглоченный флаг, а не текст коммита. Флаги вешает
`commitFlags` на все изменяющие команды разом, поэтому проверка в одном месте
закрывает всё семейство вызовов.

## DoD

Вызов с `-m`, за которым идёт флаг, отказывает с внятным сообщением и ничего
не коммитит. Рабочие формы (`-m "сообщение"`, `-m "сообщение" --push`) не
задеты. Тест на отказ падает на старом коде и проходит на исправленном
(regcheck), тесты на рабочие формы держат их от регресса.

## Ход работы

2026-08-11, pick: модель glm-5.2, effort high, ярус base, via glm-code;
исполняет glm-сессия.

Правка легла туда, куда обещал разбор: в `CommitOpts.validate`
(tools/taskctl/ops.go). `validate` зовётся первой строкой во всех изменяющих
командах (`cmdMove`, `cmdClose`, `cmdFile`, `cmdAdd`, `cmdReviewAdd` и др.),
до чтения доски и любой записи на диск, поэтому одна проверка закрывает всё
семейство вызовов сразу и не оставляет доску изменённой, но не закоммиченной.
Отбивка срабатывает, когда `Msg` начинается с дефиса: `flag.StringVar` берёт
значением `-m` следующий аргумент, даже если тот сам флаг, поэтому вызов
`... -m --push` даёт `Msg` ровно `--push`, что и ловится.

Тесты в tools/taskctl/commit_test.go:

- `TestCommitMsgRejectsFlagValue` гоняет отбивку через `cmdMove` с
  `Msg "--push"`: команда возвращает ошибку, HEAD не сдвинулся, файл доски не
  изменился;
- `TestCommitOptsValidate` таблично перебирает границы: дефис в середине
  текста (`docs: -Werror потушен`) проходит, в начале (`--push`, `-x`)
  отбивается, `--push` без `-m` отбивается отдельно, рабочая форма с пушем
  проходит.

regcheck: тесты краснеют на `main` и проходят на правке, регрессия закрыта.

## Сценарий проверки (агентский)

Окружение синтетическое: временный каталог как git-репо с доской, живой прод
не трогается. До начала HEAD пустого репо запоминается, возврат проверяется
кодом и grep-ом по stderr, а не на глаз.

```text
S=$(mktemp -d)
git -C "$S" init -q -b main
git -C "$S" config user.email t@t && git -C "$S" config user.name t
taskctl -C "$S" init --prefix TT
git -C "$S" add -A && git -C "$S" commit -q -m init
HEAD0=$(git -C "$S" rev-parse HEAD)

# 1. Воспроизведение симптома: -m, за которым идёт флаг, должен отказать.
taskctl -C "$S" add --id TT-001 --title проверка --type task --rank 0+0+0+0+0 -m --push
#    жду: код возврата ненулевой, stderr содержит «начинается с дефиса»,
#    нового коммита нет (HEAD == HEAD0), рабочий каталог чист.
test $? -ne 0 || echo FAIL: должен был отказать
git -C "$S" rev-parse --verify -q HEAD >/dev/null && test "$(git -C "$S" rev-parse HEAD)" = "$HEAD0"

# 2. Рабочая форма: -m "сообщение" коммитит с темой сообщения.
taskctl -C "$S" add --id TT-002 --title проверка --type task --rank 0+0+0+0+0 -m "docs(tasks): TT-002 заведена"
#    жду: код возврата 0, тема последнего коммита «docs(tasks): TT-002 заведена».
test "$(git -C "$S" log -1 --pretty=%s)" = "docs(tasks): TT-002 заведена"
```

Первый шаг на неотфиксированном коде коммитил бы с темой `--push` и рапортовал
про удачу; на исправленном отказывает до коммита.
