# DK-1356: board-task: шаг board-debt не зовётся при сдаче поездом и тиком сторожка

## Что происходит

Скилл board-debt выкатился в DK-624 (код слит 2026-09-30, у пользователя с
2026-10-05). Шаг вызова стоит в board-task, и зовут его при сдаче задачи в
Check до отчёта диспетчеру. Наблюдение за применением 2026-10-11 показало,
что после 7 октября вызовов нет ни одного при закрытых за эти дни около
десяти задачах, включая кодовые (DK-1309, DK-1328, DK-1321, DK-1312,
DK-1335, DK-1300, DK-1351).

Три вызова, которые были 2026-10-07, пришли из разных сессий, и все три из
ручных заходов исполнителя. Сдачи по маршруту конвейера, похоже, шаг не
проходят. Строку в Check переводит тик сторожка или поезд выката. В этих
маршрутах скилл никто не зовёт. Вторая половина той же беды видна на DK-839.
Вызов был, но сессия оборвалась на разборе, decide не заведён, хвост потерян
вместе с окном. Возвраты хвостов разбирал DK-1317, хотя там речь шла об
обрыве после взятия. Тут скилл не начинается.

Долг лежит. Запас Backlog с меткой [долг] на 2026-10-11 равен 26 строкам,
за неделю погашена одна (DK-1176).

## Чего хотим

Шаг долга срабатывает на каждой сдаче в Check, какой бы маршрут ни перевёл
строку. Рука исполнителя, тик сторожка и поезд ведут себя одинаково. Если
пересечений с диффом нет, это тоже видно. Короткая отметка в файле задачи
говорит, что разбор был, а пустого результата не нашлось. Хвост
прерванного разбора не теряется молча.

## Развилки

- «разбор»: кто разбирает хвост долга, если строку в Check увёл конвейер и сессии исполнителя уже нет?
  - решает: человек
  - рекомендация: проверяющий по заказу checkrun: подъём проверяющего уже поднимает выкат и тик, шаг долга ложится в его заказ на всех конвейерных сдачах, ручной маршрут у исполнителя не меняется
  - вариант: только исполнитель: заказ долга не несёт, хвост на конвейере гасят ворота close
  - вариант: машинный суд: пересечение считает taskctl по разделу «Выкат», закрытая отметка пишется без сессии
  - источник: доска docs/tasks/archive/2026/DK-624.md
  - решено человеком 2026-10-12: проверяющий по заказу checkrun: подъём проверяющего уже поднимает выкат и тик, шаг долга ложится в его заказ на всех конвейерных сдачах, ручной маршрут у исполнителя не меняется
- «дренаж»: чем закрытие строки страхует незакрытый хвост долга?
  - решает: исполнитель
  - рекомендация: ворота close по образцу closeForkGate: открытая отметка долга не даёт закрыть строку и называет команду закрытия хвоста
  - вариант: только видимость: хвост виден в «Ходе работы», ворота close отметку не читают
  - вариант: эскалация тиком: незакрытая отметка заводит запись дежурному по образцу DUTY_MARK
  - источник: код tools/taskctl/gate.go
  - решено агентом 2026-10-12: ворота close по образцу closeForkGate: открытая отметка долга не даёт закрыть строку и называет команду закрытия хвоста

## Сценарий проверки

Агентская часть. Синтетическая доска живёт во временном каталоге с
временным HOME. Бинарь taskctl собирается из чекаута, утилита зовётся с
`-C` на синтетический проект. Первый шаг воспроизводит баг на коде до
правки. Каждый шаг собран в одну строку через `&&`. Обкатка гоняет строки
блока по одной своим `sh -c`. Переменная, названная строкой выше, до
следующей строки не доживает.

Шаги пишут один и тот же файл задачи синтетической доски. Его содержимое
показано ниже блоком `text`. Заголовки блока несут отступ в три пробела. Без
него ограждение сценария принимает их за забытый конец блока. Шаг снимает
отступ и кладёт файл в `docs/tasks/XR-001.md` каталога прогона.

```text
# XR-001: Правка справки

   ## DoD

- отметка долга проверена

   ## Сценарий проверки

1. Синтетический шаг, реального вывода не требует.

- Исключение: обкатка (синтетическая доска)

   ## Проверка

- Синтетическая проверка, реального вывода не требует.
```

1. Старый код не оставлял следа долга. taskctl собирается с родителя коммита
   правки. Строка XR-001 проводится в Check по синтетической доске. В файле
   задачи считается отметка долга.

   ```sh
   base=$(git log --format=%H --grep=DK-1356 -- tools/taskctl/debt.go | tail -1); old=$(mktemp -d); git worktree add -q --detach "$old/tree" "$base^" && GOWORK=off go -C "$old/tree/tools/taskctl" build -o "$old/tc" . && mkdir -p "$old/proj" "$old/home" && HOME="$old/home" "$old/tc" -C "$old/proj" init --prefix XR --here >/dev/null && HOME="$old/home" "$old/tc" -C "$old/proj" add --title "Правка справки" --type task --rank "25+5+1+5+4" --cost S --accept agent >/dev/null && awk '/^```text$/{f=1;next} /^```$/{if(f)exit} f{sub(/^ +/,"");print}' docs/tasks/DK-1356.md > "$old/proj/docs/tasks/XR-001.md" && HOME="$old/home" "$old/tc" -C "$old/proj" move XR-001 in-progress >/dev/null && HOME="$old/home" "$old/tc" -C "$old/proj" move XR-001 check >/dev/null && sed -n '/^## Check/,/^## Backlog/p' "$old/proj/docs/TASKS.md" | grep -q XR-001 && n=$(grep -c 'Долг: жду разбора у диффа' "$old/proj/docs/tasks/XR-001.md" || true) && echo "отметок долга: $n" && test "$n" = 0; rc=$?; git worktree remove --force "$old/tree" >/dev/null 2>&1; exit $rc
   ```

   Ожидаемый итог: «отметок долга: 0». Сдача в Check следа разбора не
   оставляла. Маршрут перевода был безразличен молчанием.

2. Выкаченный код открывает отметку сам, тем же переводом.

   ```sh
   bin=$(mktemp -d); mkdir -p "$bin/proj" "$bin/home" && GOWORK=off go -C tools/taskctl build -o "$bin/tc" . && HOME="$bin/home" "$bin/tc" -C "$bin/proj" init --prefix XR --here >/dev/null && HOME="$bin/home" "$bin/tc" -C "$bin/proj" add --title "Правка справки" --type task --rank "25+5+1+5+4" --cost S --accept agent >/dev/null && awk '/^```text$/{f=1;next} /^```$/{if(f)exit} f{sub(/^ +/,"");print}' docs/tasks/DK-1356.md > "$bin/proj/docs/tasks/XR-001.md" && HOME="$bin/home" "$bin/tc" -C "$bin/proj" move XR-001 in-progress >/dev/null && HOME="$bin/home" "$bin/tc" -C "$bin/proj" move XR-001 check >/dev/null && grep 'Долг: жду разбора у диффа' "$bin/proj/docs/tasks/XR-001.md"
   ```

   Ожидаемый итог это строка «Долг: жду разбора у диффа, <дата>» из раздела
   «Ход работы». Какой бы маршрут ни перевёл строку, отметку открыл сам
   перевод.

3. Ворота close держат открытую отметку и называют команду. Закрытие хвоста
   отпускает строку в архив.

   ```sh
   bin=$(mktemp -d); mkdir -p "$bin/proj" "$bin/home" && GOWORK=off go -C tools/taskctl build -o "$bin/tc" . && HOME="$bin/home" "$bin/tc" -C "$bin/proj" init --prefix XR --here >/dev/null && HOME="$bin/home" "$bin/tc" -C "$bin/proj" add --title "Правка справки" --type task --rank "25+5+1+5+4" --cost S --accept agent >/dev/null && awk '/^```text$/{f=1;next} /^```$/{if(f)exit} f{sub(/^ +/,"");print}' docs/tasks/DK-1356.md > "$bin/proj/docs/tasks/XR-001.md" && HOME="$bin/home" "$bin/tc" -C "$bin/proj" move XR-001 in-progress >/dev/null && HOME="$bin/home" "$bin/tc" -C "$bin/proj" move XR-001 check >/dev/null && HOME="$bin/home" "$bin/tc" -C "$bin/proj" close XR-001 2>&1 | grep 'taskctl debt-done XR-001' && HOME="$bin/home" "$bin/tc" -C "$bin/proj" debt-done XR-001 "пересечений нет" >/dev/null && HOME="$bin/home" "$bin/tc" -C "$bin/proj" close XR-001 >/dev/null && grep 'Долг: разобран, пересечений нет' "$bin/proj/docs/tasks/archive/$(date +%Y)/XR-001.md"
   ```

   Ожидаемый итог такой. Отказ close называет `taskctl debt-done XR-001`.
   После закрытия хвоста close проходит. Архивный файл несёт строку разбора
   с итогом.

4. Краснота теста заказа проверяющего.

   ```sh
   base=$(git log --format=%H --grep=DK-1356 -- internal/checkrun/checkrun.go | tail -1); GOWORK=off regcheck -C internal --tests internal/checkrun/checkrun_test.go --base "$base^" -- go test ./... -run TestOrderCarriesDebtStep
   ```

   Ожидаемый итог это строка «тест краснеет на `<коммит>^` и проходит на
   текущем коде, регрессия закрыта». Тест проверяет заказ: шаг долга с
   командой закрытия отметки стоит у любого вида приёмки.

У новых тестов утилиты regcheck неприменим. Они зовут `cmdDebtDone` и
`taskform.DebtHeld`, которых в базе нет. База с тестами не собирается.
Краснота утилиты доказана шагом 1 на старом бинаре.
