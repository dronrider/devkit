# DK-1359: Профиль Codex подключает правила и навыки devkit

## Что происходит

В kit/harness есть профили Claude Code и дополнительных подписок. Codex установлен, но agentctl не определяет сессию и не разворачивает уровень в модель. Codex читает AGENTS.md и не раскрывает импорты вида @{path}.

## Чего хотим

Добавить профиль kit/harness/codex.toml средствами существующего формата. Подключённый проект получает правила и навыки через автоматику devkit. Объём задачи ограничен профилем, его тестами и инструкцией подключения.

## DoD

- Детект использует непустую CODEX_THREAD_ID. CODEX_HOME не подходит для детекта сессии, эта переменная задаёт каталог настроек и в текущей сессии отсутствует.
- Правила вклеиваются в AGENTS.md через mode = "embed". Навыки раскладываются в каталог, который обнаруживается установленным Codex. Проверить текущий контракт клиента перед выбором пути.
- Делегирование идёт командой codex exec с {prompt}, {model}, {effort}. Подтвердить флаги по установленному codex exec --help. Сохранить sandbox workspace-write, не добавлять обходы разрешений.
- Предложения моделей опираются на установленный клиент. В машинном config.toml сейчас model = "gpt-6.1-sol". Непроверенные имена моделей не добавлять. Различные усилия задаёт {effort}.
- Секции hooks и quota пустые. Поддержку протокола Claude Code и его съёмщика Codex не приписывать.
- Если добавляется секция head, её аргументы проверены help клиента. Для интерактивной головы без хука конца хода предпочесть отсутствие секции и описать ограничение.
- Оба парсера принимают профиль без предупреждений. Тесты проверяют детект, команду делегирования и раскладку правил и навыков на временном HOME и пустом проекте.
- Типовые мутации профиля обнаруживаются тестами. Прогоны идут через devkitctl test.
- В tools/agentctl/README.md есть короткая инструкция включения codex в harness.local, вызова doctor --fix и проверки agentctl harness.
