# DK-1359: Профиль Codex подключает правила и навыки devkit

## Что происходит

В kit/harness есть профили Claude Code и дополнительных подписок. Codex установлен, но agentctl не определяет сессию и не разворачивает уровень в модель. Codex читает AGENTS.md и не раскрывает импорты вида @{path}.

## Чего хотим

Добавить профиль kit/harness/codex.toml средствами существующего формата. Подключённый проект получает правила и навыки через автоматику devkit. Объём задачи ограничен профилем, его тестами и инструкцией подключения.

## DoD

- Детект использует непустую CODEX_THREAD_ID. CODEX_HOME не подходит для детекта сессии, эта переменная задаёт каталог настроек и в текущей сессии отсутствует.
- Правила вклеиваются в AGENTS.md через mode = "embed". Навыки раскладываются в каталог, который обнаруживается установленным Codex. Проверить текущий контракт клиента перед выбором пути.
- Делегирование идёт командой codex exec с {prompt}, {model}, {effort}. Подтвердить флаги по установленному codex exec --help. Сохранить sandbox workspace-write, не добавлять обходы разрешений.
- Предложения моделей опираются на установленный клиент. В машинном config.toml сейчас model = "gpt-6.1-sol". Непроверенные имена моделей не добавлять. Различные усилия задаёт {effort}.
- Секции hooks и quota пустые. Поддержку протокола Claude Code и его съёмщика Codex не приписывать.
- Если добавляется секция head, её аргументы проверены help клиента. Для интерактивной головы без хука конца хода предпочесть отсутствие секции и описать ограничение.
- Оба парсера принимают профиль без предупреждений. Тесты проверяют детект, команду делегирования и раскладку правил и навыков на временном HOME и пустом проекте.
- Типовые мутации профиля обнаруживаются тестами. Прогоны идут через devkitctl test.
- В tools/agentctl/README.md есть короткая инструкция включения codex в harness.local, вызова doctor --fix и проверки agentctl harness.

## Ранг

25+7+2+0+3 = 37. Серьёзность 25, подключение сейчас делается вручную. Ценность 7, появляется поддержка ещё одного клиента. Неопределённость 2, стык правил и навыков надо проверить прогоном. Поправка на баг 0, это новая возможность. Рычаг 3, профиль подключает Codex к существующим инструментам. Цена M.

## Сценарий проверки

Сценарий агентский. Гоняется командой taskctl rehearse из корня дерева, в его
свежем worktree и с временным HOME. Клиент Codex проверяющему не нужен,
раскладка ходит файлами. Раскладку правил и навыков на временном HOME и пустом
проекте гоняет стендовый тест. На worktree ветки задачи doctor машинное
хозяйство на машину не кладёт, и живой вызов doctor --fix в свежем дереве
всегда красный от его машинных находок. Проектная половина сценария живая,
это новый пустой проект и детект в сессии Codex. Пустой проект стоит без доски,
поэтому глубина правил у Codex core и тело вклейки в нём пустое. Маркеры стоят,
а текст правил подъезжает в проекте с доской. Автор правки не выполняет
приёмочный прогон.

1. Бинарь агентов собирается из свежего дерева.

```sh
GOWORK=off go -C tools/agentctl build -o /tmp/agentctl-dk1359 .
```

Сборка выходит кодом 0.

2. Раскладка правил и навыков на временном HOME и пустом проекте.

```sh
python3 tools/devkitctl/devkitctl_test.py CodexLayoutTest.test_01_fix_lays_rules_and_skills
```

Стенд печатает «OK». Фикс на песочном доме ставит вклейку в AGENTS.md нового
проекта, тело вклейки на проекте без доски пустое, навыки лежат в каталоге,
который Codex сканирует сам, и навыки первого харнеса на месте.

3. Повторный doctor не меняет разложенное.

```sh
python3 tools/devkitctl/devkitctl_test.py CodexLayoutTest.test_02_repeated_fix_changes_nothing
```

Стенд печатает «OK»: повторный --fix молчит и не переписывает файлы.

4. Пустой git-проект подключается, codex включается в машинном слое песочного
   HOME.

```sh
proj=${TMPDIR:-/tmp}/dk1359-proj && rm -rf "$proj" && mkdir -p "$proj" && git -C "$proj" init -q && python3 tools/devkitctl/devkitctl.py new --no-board -C "$proj" >/dev/null && mkdir -p "$HOME/.devkit" && printf 'enabled = ["claude-code", "codex"]\ndefault = "claude-code"\n' > "$HOME/.devkit/harness.local"
```

Шаг выходит кодом 0.

5. В сессии Codex детект называет codex. Переменные чужих сессий вокруг
   снимаются явно, детект судит только CODEX_THREAD_ID.

```sh
proj=${TMPDIR:-/tmp}/dk1359-proj && DEVKIT_HARNESS= CLAUDECODE= DEVKIT_HOME="$PWD" CODEX_THREAD_ID=01a14473-e714-7fa0-b2fd-a2e1d18cbff9 /tmp/agentctl-dk1359 harness -C "$proj" | grep -q "харнес: codex"
```

Полная строка «харнес: codex (детект по переменной CODEX_THREAD_ID)».
