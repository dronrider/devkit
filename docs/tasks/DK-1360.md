# DK-1360: agentctl check: без ступени выше проверяющий спускается вниз

## Что происходит

11 октября закрытие DK-1351 упёрлось в отказ `agentctl check`. Разработку
вела модель верхнего яруса (`mimo-v2.6-pro`), проверяющий по правилу берётся
ступенью выше с другой моделью, а выше в раскладке машины ступени нет. Отказ
прямо предложил поднять другой моделью руками. Задача была готова. Код слит,
ревью пройдено, обкатка зелёная, и всё это держалось на ручном обходе.

Инвариант правила один. Сценарий прогоняет не автор правки, и для
независимости хватает другой модели. Прогон сценария механический, шаги и
ожидаемый вывод записаны заранее, большая модель здесь ничего не добавляет.
Лестница при этом заканчивается, и подъём всегда невозможен у задач яруса
max и у любого яруса, чья модель совпала с верхней ступенью (на маппинге
`mimo` pro и max это одна модель). Добавление новой модели над верхом тупик
только сдвигает. У задачи, взятой уже новой верхней моделью, он повторится.

## Чего хотим

Когда модели яруса вела разработку, а ступени выше с другой моделью нет,
проверяющий спускается ступенью вниз, к ближайшей модели, отличной от
разработчика. Тупик исчезает у любой лестницы, где различие есть хоть на
одной ступени. Отказ остаётся одному случаю, когда во всей лестнице подписки
одна модель на всех ярусах. Там остаётся ручной прогон и прежний текст
отказа.

## DoD

- `internal/checkrun.Choose` после неудачного подъёма ищет модель ниже по
  лестнице и отдаёт спуск с признаком (From это ярус вердикта, Tier ступень
  ниже), как сейчас отдаёт подъём.
- Отказ остаётся только лестнице из одной модели, и текст отказа называет
  именно её.
- Тесты держат спуск на верхней ступени (верха больше нет, вниз модель
  есть), отказ по одно-модельной лестнице, прежние случаи подъёма и работы
  без совпадения целы.
- `RULES.board.md` (п. 6 раздела «Трекинг задач») и справка `agentctl`
  носят ту же механику. Подъём, затем спуск, другой модели для
  независимости хватает.
- regcheck держит красноту теста спуска на текущем коде и зелёность после
  правки.

## Ранг

- Серьёзность 25: доска не стоит целиком, но закрытие каждой задачи
  верхнего яруса ложится ручную работу. Сценарий прогоняет чужой моделью
  сам, проверку отмечаешь тоже сам. Обход дешёвый, но ручной, и каждый раз
  на глазах диспетчера.
- Ценность 6: закрытие pro-задач снова идёт штатным порядком, операция
  ежедневная, диспетчеру не нужен ручной танец с stage и моделью.
- Неопределённость 1: направление согласовано с человеком 11 октября,
  спуск вниз; открытых развилок нет.
- Поправка на баг 0: отказ работает как задумано, дыра в правиле про
  верхнюю ступень, регрессом это не является.
- Рычаг 4: каждая следующая задача верхнего яруса закрывается без обхода,
  механика проверки дешевеет на все строки доски.

## Обход до правки

Пока правка не слита, тупик обходится руками, конвейер не стоит:

1. Сценарий прогоняет субагент с моделью, отличной от разработчика (для
   верха `mimo` это flash). Диспетчер спавнит его сам, вердикт `agentctl
   check` в этот раз не нужен.
2. Прогон отмечается `agentctl stage <ID> проверка --by <модель>`, той
   самой моделью, что гоняла.
3. Дальше `taskctl close <ID>` проходит. Ворота сверяют прогонявшего с
   разработчиком, имена разные.

## Сценарий проверки

1. Спуск на верхней ступени. Шаг, прогнать
   `go test ./internal/checkrun/ -count=1 -run TestChooseStepsDownAtTop`.
   Итог, тест зелёный. Лестница с верхней моделью, совпавшей с
   разработчиком, отдаёт ближайшую ступень ниже с другой моделью. На коде
   без спуска тест красный, краснота подтверждена regcheck.
2. Отказ одно-модельной лестницы. Шаг, прогнать
   `go test ./internal/checkrun/ -count=1 -run TestChooseRefusesOneModel`.
   Итог, тест зелёный. Лестница, где одна модель на всех ступенях, даёт
   отказ с текстом про одну модель.
3. Прежние случаи целы. Шаг, прогнать `go test ./internal/checkrun/
   -count=1`. Итог, пакет зелёный. Подъём на коллизии и работа без
   совпадения не тронуты.
4. Инструмент не сломан. Шаг, прогнать `devkitctl test tools/agentctl`.
   Итог, пакет зелёный.

Команды шагов, по строке на шаг.

```sh
go test ./internal/checkrun/ -count=1 -run TestChooseStepsDownAtTop
go test ./internal/checkrun/ -count=1 -run TestChooseRefusesOneModel
go test ./internal/checkrun/ -count=1
devkitctl test tools/agentctl
```
