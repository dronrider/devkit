# DK-1360: Независимая проверка допускает ту же модель в отдельной сессии

## Что происходит

11 октября закрытие DK-1351 упёрлось в отказ `agentctl check`. Разработку
вела модель верхнего яруса, а другой модели выше в раскладке не было.
Первоначальная постановка предлагала искать проверяющего ступенью ниже.

26 октября тот же тупик остановил очередь после выката DK-994. Разработку
вёл glm-5.3. Обе разрешённые автоматике подписки используют эту модель на
ярусах base, pro и max. `agentctl check` завершается с отказом, smoke не появляется,
следующий выкат запрещён. Routerai оставлена для ручного использования.

Правило «сценарий прогоняет не автор правки» сейчас проверяется сравнением
имён моделей. Отдельная сессия той же модели тоже получает отказ.
По согласованию с пользователем независимую проверку может выполнять
другой агент той же модели со свежим контекстом. Поиск другой модели
ступенью выше или ниже больше не является решением этой задачи.

## Чего хотим

Проверку выполняет отдельная сессия, которая не участвовала в разработке
или доработке задачи. Модель выбирается по достаточности для сценария и
разрешениям подписки. Совпадение моделей проверяющего и разработчика разрешено.

Проверяющий получает постановку, DoD, сценарий и фактическое состояние
выката. История рассуждений автора ему не передаётся. Результаты прогона
и личность проверяющего сохраняются в записи задачи.

## Границы

Меняются выбор и учёт проверяющего, запуск проверки и условия закрытия.
Общие правила восстановления зависших голов остаются отдельной работой.
Допуск подписок к автоматическим задачам сохраняется. Ради проверки
нельзя автоматически включать routerai или другую запрещённую подписку.

## DoD

- Исполнители разработки и доработки записываются по устойчивому ID сессии
  или агента. Имя модели хранится отдельно. Учитываются все авторы текущего
  круга, включая возобновлённые сессии и вложенных исполнителей.
- Проверяющий поднимается в отдельной сессии со свежим контекстом.
  Совпадение с любым автором текущего круга блокирует самостоятельную
  приёмку. Новое окно, смена модели или повторный запуск не должны стирать
  связь возобновлённой сессии с автором.
- `agentctl check`, общий выбор в `internal/checkrun`, shipctl и dashboard
  допускают ту же модель в отдельной сессии. При выборе сохраняются
  требования яруса, машинный допуск подписки и проверка владельца `via`.
- Этап проверки и smoke связываются с фактической сессией проверяющего и
  последним выкатом. `taskctl close` сверяет участников текущего круга.
  Одного ручного `--by <модель>` недостаточно для доказательства независимости.
- Для старых записей без ID участников определён переходный порядок.
  Недостающие сведения явно диагностируются. Совпадение или различие имён
  моделей не выдаётся за доказанную независимость; фиктивные ID не создаются.
- Правила доски, скиллы сдачи и справки команд описывают один порядок.
  Удалено обязательное требование другой модели. Пользователь видит причину
  отказа, когда независимость или разрешение запуска подтвердить нельзя.
- Регрессии покрывают запуск и закрытие разными сессиями одной модели,
  запрет самопроверки, возобновление автора, несколько авторов, старые записи
  без ID и запрет автоматического выбора недопущенной подписки.
  Краснота на прежнем коде и зелёность исправления подтверждены regcheck.

## Ранг

25+6+2+0+4, цена M. Отказ после выката блокирует следующую задачу,
ручная независимая приёмка остаётся обходом. Неопределённость повышена до 2:
нужно согласовать учёт участников между оболочками и переход старых записей.

## Приёмка

Вид агентский. Проверки выполняются на временных проектах и конфигурациях.
Сценарий использует подставные команды клиентов, платных вызовов моделей нет.

## Сценарий проверки

1. Закрытие после разработки, слияния и выката: прогон той же моделью из
   чужой сессии принимается, а сессией автора выкаченного кода и вторым
   автором круга отбит с точной причиной.

   ```sh
   devkitctl test tools/taskctl -run 'TestClosePassesForeignVerifyRun|TestCloseRefusesSameSessionVerifyRun|TestCloseRefusesAuthorOfShippedCode'
   ```

2. Старая запись только с именами моделей даёт явную диагностику, без
   выдуманных ID и подмены имени.

   ```sh
   devkitctl test tools/taskctl -run 'TestCloseRefusesNamelessCircle|TestCloseVerifyGateRefusesWhenVerifierWroteTheCode'
   ```

3. Отбор проверяющего держит ярус и допуск подписки: routerai и запрещённый
   владелец `via` не запускаются, точный ярус соседней лестницы дешевле
   ступени вверх.

   ```sh
   devkitctl test tools/agentctl -run 'TestCmdCheckKeepsTierOnSameDevModel|TestCmdCheckKeepsTierOnForeignDevModel|TestCmdCheckTakesNextLadderOnMissingTierModel'
   devkitctl test internal -run 'TestChooseKeepsSameModelAsDeveloper|TestChooseAvailableTakesNextLadderWithoutLoweringTier'
   ```

4. Подъём проверки конвейером живёт на активном харнесе и той же модели.

   ```sh
   devkitctl test tools/shipctl -run 'TestCheckRunStaysOnActiveHarnessWithSameModel|TestMergeRaisesCheckerOnAuthorModel'
   devkitctl test tools/dashboard -run 'TestCheckRunRaisesDeveloperModel'
   ```

5. Целевые прогоны затронутых компонентов, жду код 0. Полный прогон
   internal остаётся за живым деревом: обкатка приносит в шаг указатели
   тулчейнов настоящего дома, и freshtree краснеет на своей механике, яма
   обкатки известна по DK-1399.

   ```sh
   devkitctl test tools/taskctl
   devkitctl test tools/shipctl
   ```
