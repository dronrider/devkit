# DK-1364: голова без имени харнеса берёт default машинного слоя, а не хардкод

## Что происходит

2026-10-12 в окно 12:33-17:42 цель DK-1326 шла на подписке mimo, а сессии
голов задач сидели на подписке glm. Транскрипты голов DK-1317, DK-1326,
DK-1362 и DK-662 лежат в каталоге ~/.devkit/claude-glm, панели их окон несут
DEVKIT_HARNESS=claude-code рядом с CLAUDE_CONFIG_DIR=/Users/rider/.devkit/claude-glm.
Отдельного запуска на glm никто не делал, расход виден в снимке квоты glm
за эти часы.

Воспроизведение. Тик goal-watch поднимает голову командой `taskctl run <ID>`
без флага --harness, переменной DEVKIT_HARNESS в окружении launchd-агента нет.
Порядок taskhead.HarnessName заканчивается константой
DefaultHarness = "claude-code" (internal/taskhead/profile.go). Машинный слой
~/.devkit/harness.local с default = "mimo" в этот порядок не входит, и
пятьшагов разрешения из agentctl в подъёме головы не участвуют.

Ожидание. Голова без имени поднимается на подписке по умолчанию машинного
слоя, и пары окружения подписки кладёт ей обвязка agentctl exec.

Вышло. Два звенья, и они независимы. Профиль claude-code поднимает клиента
голым (`kit/harness/claude-code.toml`, [head] client), обвязки exec у него нет,
и некому положить пары каталога конфигурации. Панель наследует глобальное
окружение tmux-сервера, а в нём CLAUDE_CONFIG_DIR каталога подписки glm
(`tmux showenv -g`): сервер заведён сессией дашборда, и каталог остался в нём
с тех пор. Чистка head_env в task-run.py снимает CLAUDE_CODE_* и метки
печатного режима, CLAUDE_CONFIG_DIR она не трогает. Голый claude стартует
с чужим каталогом конфигурации. Сессия подписана claude-code, списывается она
на квоту glm.

Тот же хардкод лежит в оболочке. DEFAULT_HARNESS = "claude-code" в
kit/skills/board-task/task-run.py выбирает профиль там, где DEVKIT_HARNESS
нет, и та же строка читает потолок ожидания подписки.

## Чего хотим

HarnessName при пустых имени и переменной берёт default из машинного слоя.
Источник один на всю машину, `agentctl harness --json`, поле default.
Утилита сводит слои конфигурации сама, чтение harness.local оболочкой
означало бы третью копию разбора. Без agentctl в PATH остаётся прежний
claude-code.

task-run.py держит тот же порядок для профиля клиента и потолка ожидания.
Источник у него тот же.

Голый клиент головы не видит чужого CLAUDE_CONFIG_DIR. Переменная
добавляется в FOREIGN_ENV, чистку которой уже делает head_env. Свой каталог
конфигурации подписке кладёт agentctl exec поверх очищенного окружения,
поэтому чистка безопасна для всех профилей.

## Границы

Чаты и генератор launchd-агента остаются в DK-1271, единая обвязка для всех
подписок. Здесь эта половина не правится.

Порядок HarnessName «имя, переменная, default» не меняется. Шаг детекта
по окружению из agentctl в подъём головы не переносится, у поднятой головы
имя уже назначено.

## DoD

`taskctl run <ID>` без --harness и без DEVKIT_HARNESS на машине с default=mimo
поднимает голову с DEVKIT_HARNESS=mimo в окружении оболочки.

Голый клиент головы, поднятой из окружения с чужим CLAUDE_CONFIG_DIR,
стартует без этой переменной.

Тесты обоих звеньев падают на старом коде и проходят на исправленном.
Полный прогон regcheck зелёный.
