# DK-1364: голова без имени харнеса берёт default машинного слоя, а не зашитое значение

## Что происходит

2026-10-12 в окно 12:33-17:42 цель DK-1326 шла на подписке mimo, а сессии
голов задач сидели на подписке glm. Транскрипты голов DK-1317, DK-1326,
DK-1362 и DK-662 лежат в каталоге ~/.devkit/claude-glm. В панелях их окон
заданы DEVKIT_HARNESS=claude-code и
CLAUDE_CONFIG_DIR=/Users/rider/.devkit/claude-glm. Отдельного запуска на glm
никто не делал, расход виден в снимке квоты glm за эти часы.

Воспроизведение. Тик goal-watch поднимает голову командой `taskctl run <ID>`
без флага --harness, в окружении launchd-агента нет переменной DEVKIT_HARNESS.
Порядок taskhead.HarnessName заканчивается константой
DefaultHarness = "claude-code" (internal/taskhead/profile.go). Машинный слой
~/.devkit/harness.local с default = "mimo" в этот порядок не входит, и
пятьшагов разрешения из agentctl в подъёме головы не участвуют.

Ожидание. Голова без имени поднимается на подписке по умолчанию машинного
слоя, и пары окружения подписки кладёт ей обвязка agentctl exec.

Вышло. Два звенья, и они независимы. Профиль claude-code поднимает клиента
голым (`kit/harness/claude-code.toml`, [head] client), обвязки exec нет,
пары каталога конфигурации не кладутся. Панель наследует глобальное
окружение tmux-сервера, а в нём CLAUDE_CONFIG_DIR каталога подписки glm
(`tmux showenv -g`). Сервер заведён сессией дашборда, и каталог остался в нём
с тех пор. Чистка head_env в task-run.py снимает CLAUDE_CODE_* и метки
печатного режима. CLAUDE_CONFIG_DIR она не трогает. Голый claude стартует
с чужим каталогом конфигурации. Сессия подписана claude-code, списывается
на квоту glm.

То же зашитое значение лежит в оболочке. По DEFAULT_HARNESS = "claude-code"
в kit/skills/board-task/task-run.py выбирается профиль там, где нет
DEVKIT_HARNESS, и потолок ожидания подписки берётся из той же строки.

## Чего хотим

HarnessName при пустых имени и переменной берёт default из машинного слоя.
Источник один на всю машину, `agentctl harness --json`, поле default.
Утилита сводит слои конфигурации сама. Чтение harness.local оболочкой
означало бы третью копию разбора. Без agentctl в PATH остаётся прежний
claude-code.

В task-run.py тот же порядок для профиля клиента и потолка ожидания.
Источник тот же.

Голый клиент головы стартует без чужого CLAUDE_CONFIG_DIR. Переменная
добавляется в FOREIGN_ENV, чистку которой делает head_env. Свой каталог
конфигурации подписке кладёт agentctl exec поверх очищенного окружения.
Чистка безопасна для всех профилей.

## Границы

Чаты и генератор launchd-агента остаются в DK-1271 как единая обвязка для

по окружению из agentctl в подъём головы не переносится. У поднятой головы
имя назначено.
