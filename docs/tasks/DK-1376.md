# DK-1376: Слияние встаёт на незакоммиченной болванке файла задачи

## Что происходит

`taskctl add` заводит файл задачи docs/tasks/<ID>.md вместе со строкой доски.
В коммит доски уезжает только docs/TASKS.md. Файл задачи остаётся
незакоммиченным в основном чекауте. Ветка задачи несёт свой вариант того же
файла. На последнем шаге ff-слияние git встаёт отказом. Незакоммичный файл
мешает перезаписать его версию из ветки.

На DK-1374 так встали два полных прогона тестов. Каждый кончался зелёным
набором и падал только на слиянии. Диагноз пришлось ставить по кешу cmdout.
Пока болванку не убрали руками, очередь выката стояла. Выкат прошёл лишь после
ручной уборки чужого каркаса.

## Чего хотим

Коммит доски везёт файл задачи вместе со строкой. Другой путь закрывает merge.
Он принимает незакоммиченную болванку за мусор предусловий и убирает её сам.
Механизм работает без человека. Ручная уборка перед слиянием перекладывает
раскладку на диспетчера. Находка не повторяется. Тест на пару «taskctl add
плюс ветка с файлом задачи» гоняет слияние до конца.

## DoD

- `taskctl add` коммитит файл задачи вместе со строкой доски, либо `shipctl
  merge` проходит по незакоммиченной болванке без отказа git.
- Побеждавший механизм закрыт тестом. Если второй остаётся, его поведение
  названо в README конвейера.
- Слияние задачи с файлом в ветке доезжает до выката без ручной уборки в
  основном чекауте.

## Ранг

- Серьёзность 25: слияние встаёт на ровном месте у любой задачи с файлом в
  ветке. Обход есть, но он ручной и стоит полного прогона тестов зря.
- Ценность 6: через merge-гейт проходит каждая задача доски с веткой.
- Неопределённость 1: предмет и конец ясны, открыта только развилка, с какой
  стороны править.
- Поправка на баг 5: обвязка подвела на боевом конвейере, отказ выглядел как
  падение тестов.
- Рычаг 3: экономия времени всех последующих слияний своего потока.
