# DK-1380: Вопрос из чужого проекта доезжает разговору без галочек

## Что происходит

Вопрос человеку по задаче чужого проекта ложится признаком ожидания в дерево
этой задачи, а разговор, из которого спросили, галочек не получает вовсе.

Механика такая. `runAsk` (tools/taskctl/ask.go) пишет признак в основной
чекаут дерева задачи под именем разговора `task-<ID>` и кладёт туда сессию
спросившего. Панель ищет вопросы разговору сканом `handedAsks`
(tools/dashboard/waiting.go) через `askScan`, а тот читает только
`.devkit/chat/` своего проекта. Совпадение по сессии работает, пока сессия и
задача живут в одном проекте. Конвейер спрашивает из окна `task-<ID>`, и
признак лежит в том же дереве, что и разговор.

Живой случай 14.10, DK-1379. Чат диспетчера поднялся в проекте xr-proxy, а
вопрос по развилке «снятие» задан командой `taskctl decide DK-1379 --chat` из
этого чата. Задача стоит на доске devkit, и признак ушёл в
`devkit/.devkit/chat/task-DK-1379.ask` с сессией разговора xr-proxy. Скан
xr-proxy признаков не нашёл, разговор остался без галочек. В проекте devkit
галочки встали бы только в разговоре самой задачи по совпадению имени, а
человек сидел в чате диспетчера. Вопрос дошёл до него текстом реплики, ответ
возможен разве что словами в ленту.

Половина механики при этом работает. Уведомитель зовёт человека по задаче,
парковка строки стоит, свободный ответ доходит до ждущей сессии подхватом. Не
хватает видимой части вопроса в том разговоре, где сидит человек, и выбор
варианта галочкой закрыт целиком.

## Чего хотим

Разговор, из которого спросили по чужой задаче, показывает вопрос с галочками
и дописывает строки вариантов наравне с разговором своего проекта. Скан
вопросов охватывает деревья всех проектов машины, либо признак дублируется в
дерево разговора. Ответ человека уезжает ждущей сессии прежним порядком.

панели живёт во временном доме с двумя синтетическими проектами. Первые два
шага повторяют живой случай DK-1379, когда сессия одного проекта спрашивает
по задаче другого, а разговор спрашивающего получает вопрос с вариантами.
Третий шаг проверяет ответ репликой и снятие признака в дереве задачи,
четвёртый порядок вопросов через деревья, пятый прежние дороги своего
проекта.


Ожидание: `ok` на каждом шаге. Пульс разговора спрашивающего показывает
ожидание с задачей чужого проекта и строками вариантов, ручка `/ask` собирает
виджет с вариантами, ответ репликой ложится во вход дерева задачи и снимает
признак там же, а разговор своего дерева при этом не получает лишнего входа.
Вопросы из разных деревьев встают по времени файла, и прежние дороги своего
проекта работают как раньше.
