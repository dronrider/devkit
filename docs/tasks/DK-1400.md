# DK-1400: Застой строки конвейер знает, но человеку не называет

## Что происходит

Самоход конвейера прав сделан из тихих повторов. Тик молчит после второго
одинакового отказа и ждёт смены состояния строки, память в ~/.devkit/watch.checkrun.
Сторож подъёма DK-510 поднимает упавший ход, а прогон, поднятый и не начавшийся,
не трогает. Статус печатает «следующий шаг», но его никто не смотрит. Итог ночи
17.10: пять слитых строк висели в Check без smoke часами, прогоны,
поднятые в 12:30, лежали без исполнения до вечера, и ни одно уведомление об
этом не ушло. Пользователь видит на доске ряд без движения и не отличает
застой от работы.

## Чего хотим

Застой называется человеку сам, без дознания. Строка Check без smoke дольше
названного окна и прогон, поднятый дольше окна без первого хода, уходят
уведомлением с причиной и названием следующего шага. Повтор не чаще раза на
окно за один и тот же случай, как у service-alert. Механика не спорит с тишиной
повторов: тишина остаётся для шума, эскалация работает по сроку.

## DoD

- Строка Check без отметки smoke дольше окна (например, 4 часа) уходит человеку
  уведомлением с ID, сроком и названием следующего шага.
- Прогон без первого хода дольше окна уходит тем же уведомлением.
- Один и тот же случай зовёт не чаще раза на окно, шум не растёт.
- Тест сторожка на стенде из заглушек: случай есть, уведомление ушло, повтор
  в окне подавлен, после окна ушёл снова.

## Ранг

25+4+3+0+3 = 35: застой различим только дознанием, обход дешёвый (статус), но
пользователь не должен им заниматься. Поведение дополняется, дефекта одного
места нет.
