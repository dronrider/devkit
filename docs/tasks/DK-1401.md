# DK-1401: Прогон, поднятый в мёртвый харнес по старому снимку квоты, умирает молча

## Что происходит

17.10 в 12:30 тик поднял прогоны проверки для DK-1359, DK-1390, DK-1396, DK-499
и DK-828 в харнес mimo. Подписка mimo к тому дню мертва, снимок квоты по ней
не обновлялся, и назначение поехало по протухшим данным. Прогоны до вечера не
исполнялись. В записях runs стоит «ждёт человека | проверка после выката»
без первого хода и без срока. Вечером тот же pick по свежему снимку называет
glm-5.3 и glm-code. Поднятые утром прогоны никто не переименовал и не
перезаказал. DK-510 поднимает упавший ход. Прогон без первого хода не упавший
ход, его сторож не видит. Итог: хвост конвейера стоит часами, причина видна
только дознанием runs и chat-in.log.

## Чего хотим

Прогон исполняется той моделью, которую называет свежий снимок квоты на момент
хода. Подъём по протухшему снимку не поедет в мёртвый харнес. Снимок старше
срока годности не участвует в назначении, а прогон без первого хода дольше
короткого окна перезаказывается по свежему pick. Отказ харнеса при попытке
хода пишется в файл задачи строкой хода работы.

## DoD

- Назначение модели для прогона берёт снимок квоты свежее срока годности.
  Протухший снимок не участвует, назначение отказывает с причиной.
- Прогон без первого хода дольше окна (например, 30 минут) перезаказывается по
  свежему pick автоматически, одна попытка на окно.
- Отказ харнеса при попытке хода ложится строкой в «Ход работы» файла задачи.
- Тест стенда: мёртвый харнес в снимке, прогон перезаказан на живой, повтор
  подавлен в окне.
