# DK-1370: Снятие ложной отметки стенда утилитой доски

## Что происходит

В файлах задач остаются ложные строки отметок стенда. Прогон, который не
состоялся, оставил запись с пустым списком сценариев (предмет e3b0c442 у
DK-662). Снять её нечем. Строку держит check-machine-lines.py и руками её
не выкинуть. Вызов DropStandRecord вне штатной записи стенда считается
обходом. Мусор копится, и читающий файл верит записи, которой не было.

## Чего хотим

У утилиты доски появился легальный путь снять отметку стенда по требованию
задачи. Команда одна, запись идёт внешним процессом и строка уходит
целиком. Ложная отметка DK-662 снимается первым прогоном.

## DoD

- У taskctl есть команда снятия отметки стенда, запись идёт внешним
  процессом и рубеж Edit|Write её не видит.
- Ложная отметка стенда DK-662 с предметом e3b0c442 снята этой командой.
- Команда покрыта тестом.
- В README механики доски путь записан строкой с примером.

## Ранг

`25+3+2+5+2 = 37`, P2.

- Серьёзность 25. Файл мусорит ложной записью, воротам она безвредна
  (пустой список сценариев не матчится), но читающий ей верит. Если не
  делать, следы копятся и каждый разбирает их глазами. Серьёзность не
  дотягивает до 50, работа не блокируется.
- Ценность 3. Порядок в машинных строках, меньше ложных следов в файлах
  задач.
- Неопределённость 2. Механика снятия уже собрана в DropStandRecord, надо
  дать ей команду доски и записать путь.
- Поправка на баг 5. Ложная запись это дефект данных, и задача его
  закрывает.
- Рычаг 2. Чистка понадобится каждой задаче, где стенд лёг не так.
