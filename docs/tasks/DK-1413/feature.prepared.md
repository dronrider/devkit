# DK-1370: Пробная копия обычной фичи

## Проблема и результат

Ложная отметка стенда DK-662 с предметом e3b0c442 и пустыми сценариями
осталась после пропущенного прогона. Её требуется снять штатной командой
taskctl во внешнем процессе, документировать путь и проверить его тестом.
Исходная постановка DK-1370 задаёт этот результат. Выдержки старого
помощника, его тестов и самой ложной отметки даны общими материалами.

## Требования и проверки

| Требование | Работа | Проверка и свидетельство |
|---|---|---|
| R1. taskctl снимает выбранную запись внешним процессом, README содержит пример | W2 | V1. Запуск команды на временном файле, затем пример из README; сохранить команду и результат |
| R2. Удалены отметка и её предупреждение/вывод; соседние записи и проза сохранены | W2 | V2. Прежние случаи DropStandRecord и целевой случай с чужой записью, предупреждением и прозой |
| R3. Выбор не захватывает другую базу или набор сценариев | W1, W2 | V2. Две соседние записи с разным ключом; после удаления остаётся нужная соседняя |
| R4. Снята реальная ложная запись DK-662 с пустыми сценариями без ослабления признания валидных стендов | W1, W2, W3 | V3. Сначала сохранённая строка на временной копии; потом вызов на DK-662, diff удаляет только целевую запись |

## Неизвестное и готовность

U1. Не выбран способ точного адресования записи при пустом списке сценариев.
Имя и синтаксис команды тоже открыты. W1 должен дать один проверяемый
контракт выбора и исходы для отсутствующего/неоднозначного совпадения.
Человеческий результат удаления чужих записей здесь не придумывается.
U2. standScenarios возвращает false на пустом списке; DropStandRecord
вызывает StandMarks. Применимость помощника к ложной строке ещё надо
проверить. До реализации нужен тест на сохранённой строке. Если решение
потребует изменить, какие стенды считаются валидными, надо вернуть вопрос.

Готово исследование W1. W2 и W3 зависят от его результата и не объявлены
готовыми к старту. Исходный результат DK-1370 не расширяется до общей чистки
машинных строк, нового хранения следов или принятия пустого стенда.

## Поручения и передача

W1 получает эту копию и общие материалы. Результат: точный выбор целевой
записи, ответы U1/U2 и примеры сохранности для R3/R4. Это вход W2.
W2 получает W1, делает команду, тесты V1/V2 и документацию. Он отвечает за
совместимость удаления и чтения валидных отметок. W3 получает проверенную
команду W2, снимает реальную ложную запись и сохраняет V3. W3 собирает общий
результат по R1-R4. Параллельно W2 и W3 не стартуют.

В файле задачи W ссылаются на изменения и V в существующих свидетельствах.
Шаги agentctl принадлежат сессии. При передаче записываются коммит,
готовые части, оставшиеся работы и результаты проверок; отметка шага
сессии сама по себе W не закрывает.
