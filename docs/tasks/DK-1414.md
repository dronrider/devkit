# DK-1414: Дашборд сам догоняет доску проекта из origin

## Что происходит

2026-10-21 в проекте xr-proxy задача XR-309 заведена и запушена другой машиной (62fa3936 в origin/main). На этой машине доска её не показывала, пока сессия не догнала чекаут руками git pull --ff-only. Доску дашборд берёт подпроцессом taskctl list --json (projectBoard в tools/dashboard/cache.go), сеть в чтении не ходит нигде, позиция записана в tools/taskctl/catchup.go. На старте сессии хук фетчит только чекаут devkit (hooks/devkit-catchup.sh), чекауты проектов не фетчит никто.

Актуальность снята тем же днём на живом случае. git rev-list main...origin/main дал «0 1». taskctl show XR-309 до pull отвечал «нет ни на доске, ни в архиве, ни в черновиках».

Класс DK-1069, две машины над одной доской: правки доски чужой машины невидимы, пока кто-то не вспомнит про pull. Человек смотрит на витрину, видит устаревший список и узнаёт о чужой строке на конфликте слияния. DK-1069 решает, что видно по уже сфетченным данным, но само догонение оставлено человеку.

## Чего хотим

Правки доски, запушенные другой машиной, видны в дашборде без ручного git: строки и файлы задач приезжают сами, локальная работа не затирается.

## Границы

Сеть в чтении taskctl не появляется. Позиция catchup.go остаётся в силе. Догон делает только fetch и fast-forward. Незакоммиченные файлы он не трогает. Rebase и merge не запускает. Свежий origin/main после дога попутно правит пометку stale у CLI, это принятый побочный эффект.

## DoD

Стенд из двух клонов с общим origin и доской docs/TASKS.md. У второго клона живёт дашборд с коротким интервалом дога. Все проверки агентские, судят коды возврата и строки вывода.

1. Пуш доски из первого клона. В втором клоне ручного git нет. Следующий тик дашборда отдаёт новую строку в taskctl list --json, main и origin/main совпадают.
2. Во втором клоне лежит незакоммиченная правка. Тик не меняет файлы дерева. Витрина держит пометку, что доска позади origin. После чистки дерева доска дотягивается следующим тиком.
3. В первом клоне свежий пуш, во втором локальный коммит на main. Догон отказывается на расхождении. Коммит остаётся на месте, пометка стоит.
4. Origin недоступен. Тик пишет в лог и живёт дальше. Доска отдаётся прежняя, витрина не падает.
5. Интервал дога читается из конфига дашборда. Стенд ставит его коротким.

## Сценарий проверки

Стенд двух клонов с общим origin собирают сами тесты пакета. Фикстура
mkCatchupEnv поднимает bare origin, проект дашборда «второй машины» и первый
клон. Пуш доски идёт из первого клона, интервал круга в тесте тика стоит
коротким. Прогоняет не автор правки, шаги агентские и судят код возврата.

1. Краснота на коде до правки. Тесты механики зовут новые символы и на базе
не собираются. Поведенческая краснота доказана на ключе конфига, до правки
`catchup_interval` ронял старт как незнакомый, и круг догона не поднимался
вовсе. На закоммиченной ветке базой берётся main.

```sh
GOWORK=off regcheck --tests tools/dashboard/catchup_config_test.go -- go test -C tools/dashboard -count 1 -run TestLoadConfigCatchupKeyKnown ./...
```

2. Точки DoD поимённо, шаг закрывает все пять пунктов. Пуш доезжает кругом
без ручного git (TestBoardCatchupFastForward). Грязное дерево держит файлы и
пометку (TestBoardCatchupDirtyTreeKeepsFiles). Расхождение отказывает и
хранит местный коммит (TestBoardCatchupDivergedRefuses). Недоступный origin
не роняет витрину (TestBoardCatchupOriginGoneKeepsServing). Тик читает
интервал из конфига (TestBoardCatchupKeeperTick). Ssh берётся из
core.sshCommand репозитория (TestRemoteGitEnvPrefersRepoSSH).

```sh
devkitctl test tools/dashboard -run 'TestBoardCatchup|TestRemoteGitEnv|TestLoadConfigCatchup' -count 1
```

3. Пакет дашборда целиком, проверка на то, что раньше не сломалось.

```sh
devkitctl test tools/dashboard -count 1
```
