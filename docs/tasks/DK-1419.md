# DK-1419: regcheck молча валится на команде одной строкой и чужом go.work

## Что происходит

Вызов regcheck из README не работает как написано, нашлось по ходу DK-1337
дважды за день.

Исполнитель споткнулся первым: команда после «--», собранная одной строкой,
молча падает с пустым выводом. Помогла передача команды argv по частям:
«regcheck -- go test ...» вместо «regcheck -- 'go test ...'».

Ревьювер нашёл второе: в монорепозитории с go.work прогон из README
(`regcheck -C tools/taskctl -- go test ./...`) падает без GOWORK=off с
«directory tools/taskctl is contained in a module that is not one of the
workspace modules», а с GOWORK=off go test от cmdout-каталога не находит
go.mod. Рабочий вариант это обёртка «-- sh -c 'cd tools/taskctl && go test .'».

Проверено на грумминге 2026-10-24 по коду. Разбор в tools/regcheck/main.go (строки 41-49) берёт всё после «--» как argv без оболочки. Запуск в tools/regcheck/check.go (runCmd, строки 31-36) зовёт exec.Command с первым словом как именем файла. GOWORK нигде не глушится. Тот же предмет записан черновиками DK-1436, DK-607, DK-634, DK-729 и DK-651.

### Черновик

#### Ситуация

#### Вопрос

## Из черновика DK-607 «regcheck молча валит команду с присваиванием среды после -- и выдаёт ложную красноту»

### Что происходит

Команда тестов с префиксом среды, например `PATH=$HOME/.cargo/bin:$PATH
cargo test --workspace`, после `--` в regcheck падает с пустым выводом,
и утилита отчитывается «тест не проходит на текущем коде». Причина в способе
запуска: argv уходит в exec целиком, а присваивание среды это синтаксис
оболочки, исполняемого файла с таким именем нет. Пустой вывод при этом
не отличен от честного падения тестов, и читатель верит красноте.

### Чего хотим

Regcheck либо запускает команду через оболочку, либо называет причину
пустого вывода («команда не нашлась») и не считает её краснотой тестов.
Шаблон команды из .devkit/deploy.local с PATH= заработал бы без правки
на вызывающей стороне.
