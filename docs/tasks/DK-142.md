# DK-142: раннер тестов хуков на python вместо hooks/test.sh

Задача цели [DK-135](DK-135.md). Правило языка принято в
[DK-139](archive/2026/DK-139.md): `hooks/test.sh` (956 строк) правило относит к
сложному, и на sh ему места нет.

## Задача

Переписать раннер `hooks/test.sh` на python по правилу «Раскладка»
`README.md`: тест лежит рядом со своим кодом файлом `<модуль>_test.py`, прогон
`python3 -m unittest discover -p '*_test.py'` из `hooks/`, внешних
зависимостей нет (стандартная библиотека, `unittest`). Половина работы уже
сделана и служит образцом: `hooks/hookio_test.py` и `hooks/notify_test.py`
живут рядом с кодом, а `test.sh` их зовёт и сверх того гоняет каждую проверку
на каждом образце.

Требование DK-139 к обеим задачам про раннеры: python-тесты обязаны покрывать
то же, что покрывал sh. Сначала снять список проверок раннера (имена функций и
ветки `case`), после переписывания сверить один к одному, расхождение
объяснить в файле задачи. Особое внимание проверкам, которые гоняют хук как
процесс с подсунутым stdin и смотрят на код возврата: они и есть суть раннера.

Файлы `check-*.py` берут каждый свой `<модуль>_test.py`; хук без своего модуля
(точки входа `pre-commit`, `commit-msg`, `pre-push` на sh, они по правилу
остаются) проверяется оттуда, откуда его зовут по существу.

Точки, которые звали старый раннер, правятся тем же коммитом: `.github/
workflows/ci.yml`, перечень локальных прогонов в конце `README.md`, команды
внутри `kit/skills/live-core/SKILL.md`. Гитигнорнутый `.devkit/deploy.local`
правит диспетчер, туда не лезть.

## Сценарий проверки

Агентский.

1. Перечень проверок sh-раннера и перечень python-тестов сходятся один к
   одному, расхождение объяснено в «Ходе работы».
2. `python3 -m unittest discover -p '*_test.py'` из директории инструмента
   зелёный, sh-раннера в дереве больше нет.
3. Остальные прогоны CI зелёные: шесть `go test ./...`, оставшиеся sh-прогоны,
   `check-exec-bit.py`, `check-symbols.py`.
4. Перечень локальных прогонов в конце `README.md` называет новую команду, а не
   мёртвый `sh .../test.sh`.
