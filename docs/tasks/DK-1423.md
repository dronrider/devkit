# DK-1423: Тест check-traces проходит с .devkit в глобальном gitignore

## Что происходит

При полной проверке DK-1413 2026-10-23 упал
`hooks/check_traces_test.py::TestRigInTheIndex.test_link_in_the_index_is_refused`.
Тот же тест падает на чистом main c00a99b5c. Наблюдение и контрольные
прогоны переданы диспетчером; подтверждена одна машина, частота неизвестна.

В Git-настройках этой машины core.excludesFile указывает на глобальный
ignore со строкой .devkit. Фикстура создаёт ссылку .devkit, затем выполняет
self.add('.'). Git пропускает ссылку, и проверяемый хук её не получает.
Ожидались код 1 и сообщение об обвязке devkit в индексе. Получен код 0.
Выполнение теста не доходит до проверки сообщения и остальных утверждений.

Без GIT_CONFIG_* переопределений точечный devkitctl test падает.
С GIT_CONFIG_COUNT=1, GIT_CONFIG_KEY_0=core.excludesFile и
GIT_CONFIG_VALUE_0=/dev/null тот же тест проходит. Это контроль причины
и временный обход для процесса. Пользовательские настройки не менялись.
Фикстура TracesCase в hooks/check_traces_test.py не изолирует глобальный
Git ignore; определение переменных перед запуском не исправляет фикстуру.

## Чего хотим

Тест с git add . проверяет отказ хука на действительно добавленной ссылке.
Его результат одинаков при наличии и отсутствии .devkit в глобальном
ignore внешнего тестового окружения. Изоляция задаётся в фикстуре.
Для обычного devkitctl test не нужны ручные переопределения Git-настроек.

## Сценарий проверки

Сценарий предназначен для будущей проверки исправления. Сейчас он не
запускался при заведении задачи. Команды выполняются из корня devkit.
Каждый шаг создаёт временный HOME; настоящие настройки не меняются.

1. Синтетический внешний глобальный ignore содержит .devkit. Точечный
   тест на старой фикстуре падает с 0 вместо ожидаемого 1, после исправления
   проходит без внешнего отключения ignore.

```sh
case_home=$(mktemp -d) && trap 'rm -rf "$case_home"' EXIT && printf '%s\n' '.devkit' > "$case_home/ignore" && printf '[core]\nexcludesFile = %s/ignore\n' "$case_home" > "$case_home/.gitconfig" && env -u GIT_CONFIG -u GIT_CONFIG_COUNT -u GIT_CONFIG_KEY_0 -u GIT_CONFIG_VALUE_0 -u GIT_CONFIG_GLOBAL -u GIT_CONFIG_SYSTEM HOME="$case_home" XDG_CONFIG_HOME="$case_home/xdg" GIT_CONFIG_NOSYSTEM=1 devkitctl test "$PWD/hooks" check_traces_test.TestRigInTheIndex.test_link_in_the_index_is_refused check_traces_test
```

2. В чистом временном HOME весь модуль сохраняет прежние результаты.

```sh
case_home=$(mktemp -d) && trap 'rm -rf "$case_home"' EXIT && env -u GIT_CONFIG -u GIT_CONFIG_COUNT -u GIT_CONFIG_KEY_0 -u GIT_CONFIG_VALUE_0 -u GIT_CONFIG_GLOBAL -u GIT_CONFIG_SYSTEM HOME="$case_home" XDG_CONFIG_HOME="$case_home/xdg" GIT_CONFIG_NOSYSTEM=1 devkitctl test "$PWD/hooks" check_traces_test
```

Ожидание после исправления: обе команды завершаются 0, ссылка в первом
случае проверяется в индексе, сообщения хука и остальные утверждения
модуля сохранены. Вывод и регрессионное доказательство сохраняются при
будущем исполнении. Шаги не являются изменением машинных настроек.
