# DK-1424: close не требует smoke при слиянии документации без выката

## Что происходит

2026-10-23 при закрытии DK-1413 на main d1f92423b команда taskctl close
завершилась с отказом:
«в «Выкате» есть слияние, а отметки smoke на последний выкат нет».
Следующая штатная команда shipctl smoke DK-1413 тоже завершилась с отказом:
«нет непроверенного выката: очередь она не держит, и отметка ей не нужна».
Оба результата переданы диспетчером, подтверждён один случай.

DK-1413 содержит только docs/, слита trainmerge без deploy и опубликована.
Свежая независимая проверка завершилась успешно. Выполнены пять шагов,
обкатка 2/2 и проверки подмен 8/8. Строка остаётся в Check. Результат
доставлен, но штатно закрыть проверенную агентскую документацию не
получается даже вручную.

В tools/taskctl/gate.go closeSmokeGate требует SmokeCovers при любой
записи MergedShas. В tools/shipctl/record.go cmdSmoke проверяет checkQueue
и не ставит отметку задаче, у которой нет непроверенного выката. Запись
слияния документации ошибочно приравнена к выкату при закрытии. Ложный
smoke и удаление записи слияния не являются допустимым обходом.

## Чего хотим

Проверенная агентская задача только с документацией закрывается после
слияния и публикации без deploy и без отметки smoke. Запись слияния
сохраняется. Проверки close и smoke одинаково различают слияние и
непроверенный выкат. Закрытие настоящего выката без действующей отметки smoke
по-прежнему запрещено.

## Границы

- Исправляется условие необходимости smoke при закрытии. Остальные
  требования приёмки и проверки результата сохраняются.
- Отметки задним числом, удаление свидетельств слияния и принудительный
  обход проверок не входят в решение. Поведение тестируется на временных
  репозиториях и файлах задач.
- DK-1363 и черновик DK-1133 касаются противоположного дефекта, при
  котором настоящий выкат закрывается без smoke. Их защитное поведение
  надо сохранить.
  Дубля открытой задачи или черновика для слияния документации не найдено.
- Регресс и распространённость по другим задачам не установлены.
  DK-1413 остаётся в Check до будущего исправления инструмента.

## DoD

- Синтетическая агентская задача в Check со слиянием только docs/ без deploy
  закрывается штатным taskctl close после выполненной независимой проверки.
  Отметка smoke не создаётся, запись слияния и свидетельства проверки
  сохраняются.
- Для настоящего непроверенного выката close завершается отказом и
  оставляет строку в Check. Действующий smoke после последнего выката
  разрешает закрытие при выполнении остальных условий. Отметка прошлого
  круга новый выкат не покрывает.
- shipctl smoke для невыкатной документации по-прежнему сообщает, что
  отметка не нужна. Исправление не превращает этот отказ в ложную запись.
- Тест исходного конфликта падает на старом условии closeSmokeGate и
  проходит после исправления; regcheck подтверждает результат. Контроль
  настоящего выката и прежних условий закрытия проходит.

## Сценарий проверки

Сценарий предназначен для будущего исправления. При регистрации он не
запускался. Все изменения выполняются в синтетических репозиториях с
временным HOME, проверяются только временные строки доски.

1. Создать агентскую строку в Check с независимой проверкой и записью
   слияния только docs/ через trainmerge, без deploy. На старом коде
   taskctl close требует smoke; shipctl smoke сообщает, что непроверенного
   выката нет. Это воспроизводит исходный конфликт.
2. После исправления на том же случае taskctl close закрывает строку,
   сохраняя запись слияния и вывод проверки. Отметка smoke отсутствует.
3. Создать отдельную строку с настоящим непроверенным выкатом. Close
   должен завершиться с отказом, строка остаётся в Check. После реального
   выполнения сценария и штатной отметки smoke закрытие разрешено.
4. Добавить новый выкат после старой отметки smoke. Закрытие снова
   запрещено до проверки и отметки текущего выката. Случай без записи
   слияния сохраняет прежнее поведение.

Сохранить команды, вывод и изменения временной доски для каждого случая.
Запуск regcheck должен подтвердить красноту первого случая на старом
условии и зелень после исправления. Боевые строки, настройки машины и
историю опубликованной DK-1413 для воспроизведения не менять.
