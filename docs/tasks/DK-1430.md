# DK-1430: Список чатов строится строками записей

Цель: [tasks/DK-1253.md](tasks/DK-1253.md)

## Что происходит

Список чатов дашборда показывает разговоры и конвейеры самостоятельными
строками, и одна работа стоит в нём дважды: строкой конвейера и разговором
записи. Заголовок разговора называет первая реплика, ID записи в нём нет,
фильтра основных чатов нет, принадлежность чата к цели не видна.

## Чего хотим

Носитель, служащий отрезком основного чата, отдельной строкой списка больше
не стоит, его история стоит в основной строке записи (решение 6 LLD DK-1422).
Снятие назначения возвращает разговору собственную строку. Это единственный
пересмотр DK-430 в списке, склейка решения 15 остаётся ключом внутри отрезка.

Строку основного чата строят на лету, у разговора её не хранят. В строке
стоят `DK-NNN: Заголовок записи`, метка вида записи (цель, задача, черновик)
по правилу DK-816, стадия и состояние отдельно. Переименование записи меняет
строку без правки разговора. Фильтры называются «Все», «Основные»
и «Обсуждения». Обсуждение по `DK-NNN` это разговор с касанием записи,
не служащий отрезком, свободные разговоры входят туда же. Сортировка
по последнему сообщению считается по всей склейке отрезков. Принадлежность
цели берётся из связей доски, переход из задачи в чат цели это навигация.
Прежние адреса продолжают открывать то, что называли: hash с sid открывает
сессию, адрес конвейера его разговор. Поля `run_chat` и `talk_chat` читает
«Работа агентов», кнопка строки их больше не читает.

## Границы

Реализуется решение 6 LLD DK-1422. Журнал назначений заводит DK-1427.
Подписи ролей и этапов на отрезках относятся к DK-871, сессии исполнителей
и ревьюверов остаются отдельными разговорами. Разбор «обсуждение по DK-NNN»
для старых разговоров без назначения остаётся миграции DK-1432.

## DoD

- В общем списке одна строка основного чата с ID, заголовком и видом записи,
  стадия и состояние показаны отдельно.
- Переименование записи обновляет строку, фильтры «Все», «Основные»
  и «Обсуждения» работают, принадлежность чата к цели видна.
- Носитель назначения не стоит отдельной строкой, после снятия назначения
  возвращается собственной строкой.
- Дополнительные обсуждения не меняют назначение основного чата, сессии
  агентов доступны внутри работы.
- Прежние ссылки открывают прежнюю переписку.
- Тесты закрывают построение строки, фильтры, сортировку по склейке
  и обратную совместимость адресов.

## Ход работы

Строки записей строит сама ручка списка (chatMainRows в mainchat.go). Журнал
назначений собирает разговоры записи в одну строку. Заголовок, вид, стадию и
цель строка берёт из доски, архива и накопителя. Ветку `?tmux=` слияние не
встречает, поиск по имени окна находит носителя прежним перечнем.

Носитель держится в ответе только по ключу keep и пометкой `carrier`. Панель,
стоящая на адресе записи, находит им ленту и незачатую заготовку оформления.
Снятие назначения гасит строку записи, носителю возвращается собственная.
Сортировка и состояние берутся от свежейшего отрезка склейки.

Клиент рисует фильтры «Все», «Основные», «Обсуждения» кнопкой по образцу
архива. Чип цели в строке открывается навигацией. Кнопка строки читает адрес
записи, без выбора run_chat. Адрес цели разрешается в виток до чтения
списка. Скрытый виток тогда уезжает в ответе флагом удержания, и шапка
панели берёт заголовок витка (DK-938). Экран задачи теперь отдаёт панели
живые работы проекта. Без них кнопка формы цели оставляла панель без чата.
