# DK-1431: Решения цели доезжают задачам через основные чаты

Цель: [tasks/DK-1253.md](tasks/DK-1253.md)

## Что происходит

У цели нет своего разговора с задачами: сессии витков регистрируются
в реестре с пустой задачей (DK-1214), кнопка цели не находит их переписку.
Изменение требований цели доезжает задачам правкой файлов, подтверждения
получения нет, и диспетчер задачи продолжает работать по устаревшему
поручению. Вопрос из чата задачи диспетчеру цели передать нечем.

## Чего хотим

У цели свой основной чат и диспетчер. Носителя цели подтверждают записями
витков (замок цели, реестр целей), лента собирает витки отрезками, вход
остановленной цели лежит в «Входящих» файла цели (LLD DK-1422, стык
с DK-1214). Диспетчер цели отвечает за общий результат, состав задач
и зависимости, диспетчер задачи доводит её до приёмки.

Переходы работают в обе стороны: из чата цели доступны чаты задач, из чата
задачи доступен чат цели, назначения при этом независимы. Вопрос, затрагивающий
состав цели, соседние задачи или общий подход, диспетчер задачи передаёт
диспетчеру цели, решение человека запрашивается в чате цели с контекстом.
Прямой вопрос в чате задачи получает ответ в том же чате. Изменение
требований цели доставляется диспетчерам затронутых задач с подтверждением
получения и пересмотром выданных поручений. Транспорт назван LLD. Строка
во вход записи идёт безадресно, ответ приходит адресно голове носителя.

## Границы

Реализуется «Цель и её задачи» постановки DK-1253 и стык LLD DK-1422
с DK-1214. Журнал назначений заводит DK-1427, доставка во вход записи
и адресность по голове идут от DK-1428. Привязка сессии витка к строке цели
при старте остаётся предмету DK-1214, назначение цели на неё не опирается.
Подписи отрезков ленты относятся к DK-871.

## DoD

- У цели и её задач отдельные основные чаты, переходы работают в обе
  стороны, лента цели показывает витки отрезками.
- Решение цели доставляется затронутой задаче с подтверждением получения
  и пересмотром поручения.
- Прямой вопрос в чате задачи получает ответ в том же чате, вопрос
  о составе цели уходит диспетчеру цели и возвращается решением с контекстом.
- Тесты закрывают сборку ленты цели из витков, доставку с подтверждением
  и адресность ответа.

## Ранг

`50+8+3+0+3 = 64`, с поправкой M+1 ранг 65, P1. Ранг совпадает с рангом
цели.

- Серьёзность 50. Без доставки решений цикл цели требует человека на каждом
  изменении состава, автономия обещана.
- Ценность 8. Каждый виток цели становится автономнее, поручения не
  расползаются с требованиями.
- Неопределённость 3. Правка проходит границу витка цели, конвейера задачи
  и дашборда.
- Поправка на баг 0. Новая связь.
- Рычаг 3. Подтверждения и пересмотр поручений разгружают следующие циклы
  цели.

## Приёмка

Вид агентский. Барьеров из закрытого списка нет: доставка и подтверждение
проверяются тестами на изолированных данных, переходы проверяются заходом
в живой дашборд.

## Сценарий проверки

Вид приёмки агентский. Прогоны идут в свежем дереве с временным HOME,
пользовательские пути проходятся заходом в дашборд.

1. Пакеты правки зелёные вместе с тестами доставки и ленты цели.

   ```sh
   devkitctl test tools/dashboard
   ```

2. Заход в дашборд: открыть чат цели, пройти в чат задачи и обратно, сверить
   независимость назначений.
3. Изменить требование в цели и проверить доставку и подтверждение в задаче.
   Затем задать прямой вопрос в чате задачи и получить ответ там же.
