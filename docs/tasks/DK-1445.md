# DK-1445: Выбор отдельных сценариев работает в текстовом чате

## Что происходит

[Дизайн DK-1318](../lld/DK-1318-grooming-scenarios.md), Решения 1, 3, 4 и 5,
задаёт один список сценариев с устойчивыми ID и переход старых составов.
2026-10-24 пользователь разрешил нарезку по дополненному дизайну.
Текущий internal/taskform.Lineup хранит Width и []string и перенумеровывает
состав. Fork.Choices включает Hint первым вариантом. decideAnswer разбирает
только нерешённые развилки, --open скрывает решённые; снимка раскладки нет.

Одной замены парсера недостаточно. Нужны создание и чтение нового списка,
выбор нескольких сценариев, пересмотр ответа, продолжение и защита от ответа
на изменённый блок. Старые решения должны сохранить смысл.

## Чего хотим

В текстовом чате пользователь видит карточки с источниками и один список,
меняет отдельные пункты и сохраняет выбранное устойчивыми ID. Рекомендация
набора находится в голове вопроса и не становится ещё одним вариантом. Разбираются
несколько позиций/ID, «плюс» и «минус» по опубликованному договору.
При повторном ответе сохраняются история и новый выбор. После перерыва
видны выбранное, открытые вопросы и зависимые решения для сверки.
Устаревший блок не применяется молча. Прямо заданный состав повторно
не спрашивается; агентская рекомендация согласием не считается.

W1 выполняется до кода. В ней фиксируются грамматика новой формы,
представление ID, рекомендация набора, договор ответа, снимок раскладки,
его срок действия, исход пустого выбора и поведение устаревшего ответа.
Контракт пока не выбран. Исполнитель сверяет варианты с действующей
архитектурой; важный открытый выбор передаётся человеку до зависимой W2.
Само наличие этой карточки не объявляет код готовым к старту.
Пустота не означает молчаливого согласия с рекомендованным набором;
её продуктовый исход согласуется в W1 до реализации и воспроизводится
в CLI и UI одним способом.

W2 объединяет разбор, запись и вывод taskctl. W3 использует работающий
контракт в interview и обновляет документацию. У этой вертикали нет
жёстких предпосылок из остальных карточек. Пересечения файлов требуют
согласования изменений, но не образуют искусственного ребра.

Производный ранг с M+1 равен 92. Основанием повышения стала правка строки

в этом заходе не проводилась.

- Серьёзность 75. Сохранено значение поздней правки очереди, которой
  текстовый выбор поднят в P0. Доказанного отсутствия обхода в карточке нет.
- Ценность 9. Сохранена оценка из той же правки. Один список с понятным
  содержанием и продолжением относится к выбранным пользователем СЦ-1/СЦ-6.
- Неопределённость 3. Не определены новая грамматика и снимок раскладки;
  связаны форма, парсер, применение повторного ответа и вывод.
- Поправка на баг 0. Вводится новая форма выбора с переходом, а не
  восстановление доказанно существовавшего множественного выбора.
- Рычаг 4. Появляются повторно используемые механика формы и CLI с тестами
  и договором для панели; последующие задачи получают устойчивый выбор.

## Сценарий проверки

Приёмка агентская после доставки CLI и правил; это будущие шаги.
В W1 исполнитель фиксирует точные команды создания нового списка и ответа,
вывод которых становится примером договора. До Check команды подготовки

   выбранный перечень ID; следующий ID свободен, рекомендация не стала пунктом.
2. Сохранить первый блок, изменить список и ответить по старым номерам.
   Ожидание: конкретное расхождение до применения; выбранное не поменялось
   молча. По актуальному блоку выбор применим. Проверить номер вне списка
   и пустой выбор: наблюдается исход опубликованного договора W1,
   рекомендуемый набор молча не подставляется.
3. Ответить на решённый выбор второй раз, затем вызвать --open новым
   процессом. Ожидание: прежнее решение в истории, новый состав и незакрытый
   остаток видны; зависимые решения перечислены для сверки.
4. Прочитать старый решённый состав и ответить на старый открытый;
   повторить обычный одиночный вопрос. Ожидание: прежние решения и смысл
   ответа сохранены, лишнего обязательного повторения состава нет.
5. На раскладках поставленного и прежнего interview выполнить изменённые
   42-interview-cases-narrow и 43-interview-cases-wide, затем сохранённый
   43-interview-decide-block. Сохранить реальные выводы и ревизию договора
   для задачи панели. Один повтор unit-тестов не заменяет эту приёмку.
