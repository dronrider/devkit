# DK-1451: Конвейер передаёт проверку и отличает занятость от отказа

## Что происходит

Авторская голова держит замок в Check и ждёт собственной проверки. Дежурный считает занятый замок провалом запуска и после трёх тиков зовёт человека с причиной старого отказа. В очередь попадают ветки, где пока есть только постановка. Живой клиент без начатого хода остаётся незаметен полчаса.

## Чего хотим

Освобождать замок для независимой проверки, сохраняя живые подзадачи. Занятость должна оставаться ожиданием. Ветка с одной постановкой должна дозревать вне очереди слияния. Запуск без единого начатого хода должен получать раннюю диагностику без остановки клиента.

## DoD

- Голова разработки сдаёт agent и mixed в Check без smoke, в том числе во время машинного ожидания. Проверяющий и голова с живыми подзадачами продолжают работу.
- Код 3 от taskctl run не тратит попытку дежурного и не занимает подпись. Отчёт различает прежний исход и нынешний отказ запуска. Неотправленное уведомление повторяется.
- Ветка без новых коммитов, кроме доски, не участвует в слиянии. Отказ ревью готового кода остаётся отказом.
- Через две минуты без единого начатого хода пишется одна диагностика возможного запроса доверия, авторизации или неисправного хука. По таймауту клиент не останавливается.
- Регрессии проходят на исправлении и падают на прежнем коде через regcheck.

## Сценарий проверки

Агентский. Команды выполняются в свежем дереве без живой доски и внешних вызовов.

1. Выполнить `python3 -m unittest discover -s /Users/rider/projects/devkit/kit/skills/board-task -p task_run_test.py`. Ожидается код 0, сценарии передачи проверки и ожидания зелёные.
2. Выполнить `python3 -m unittest discover -s /Users/rider/projects/devkit/tools/devkitctl -p duty_test.py`. Ожидается код 0, занятость не расходует попытки, доставка повторяется.
3. Выполнить `env GOWORK=off go -C /Users/rider/projects/devkit/tools/shipctl test ./... -run TestQueue -count=1`. Ожидается код 0, ветки с одной постановкой пропускаются, сбои готового кода видны.
