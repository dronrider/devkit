# DK-1460: Эскалация дежурному пишет в файл задачи без коммита и блокирует слияние

## Что происходит

Сторожок дописывает эскалации в раздел «Ход работы» файла задачи без
коммита. Следующее слияние останавливается на собственной записи.
Повторы копятся до ручного коммита. Это воспроизведено на DK-1605 и
DK-1606 6-7 ноября. В основном чекауте накопилось по три новых
служебных строки, рабочие деревья веток чистые. Первоначальная причина
отказа под этими повторами сохраняется, сценарий проверки отсутствует.

В watch.task_record() запись выполняется через path.write_text().
Коммит отложен до следующей правки доски. Но слияние той же задачи
требует чистоты этого файла через requireCleanScoped(). В существующем
журнале hooks/incidents.py есть запись остановки, счётчик повторов и
исход; дежурный этот журнал читает.

Дубль не создаётся. Основной источник DK-1460; связанные наблюдения
сохранены в DK-1535, DK-1592 и DK-1621. Их старые гипотезы про
автоматический коммит в решение не вошли. Пользователь 7 ноября
согласовал перенос оперативных эскалаций в существующий журнал
инцидентов. Предмет этой задачи ограничен самоблокировкой. Сценарии
DK-1605/1606 и прежние записи их файлов доводятся отдельно.

Условий, посильных только человеку, при просмотре кода и связанных
записей не найдено. Проверки используют синтетический репозиторий,
временный HOME и тестовый журнал. Реальные чаты и внешняя модель для
стенда не нужны.

## Чего хотим

Сторожок сохраняет оперативную эскалацию в существующем журнале
инцидентов и передаёт её дежурному. Его запись не меняет коммитимые
файлы и не создаёт новую причину отказа слияния. Пользовательские
незакоммиченные изменения сохраняются и по-прежнему препятствуют
слиянию затронутых файлов.

## DoD

- Повторные тики, включая смену даты, оставляют один инцидент одной
  остановки со счётчиком повторов. Инциденты с разными причинами и
  корнями не склеиваются.
- После эскалации чистый синтетический репозиторий остаётся чистым.
  Когда исходное препятствие снято, повтор слияния не останавливается
  на служебной записи сторожка.
- Дежурный получает новый инцидент существующим механизмом.
  Исторические эскалации в файлах задач продолжают читаться. После
  возобновления повторное возникновение сбоя создаёт новую остановку.
- Предварительные пользовательские изменения сохраняются побайтно.
  Проверка чистоты дерева не ослаблена. Отказ записи журнала явно
  сообщается, ошибка не скрывается ложной отметкой успешной эскалации.
- Регрессионный тест падает на старом коде и проходит после правки,
  что подтверждено regcheck. Адресные тесты записи, повторов и передачи
  дежурному зелёные. README описывает актуальный носитель эскалаций.

дереве незакоммиченное по файлам задачи, сначала закоммить»), retry не
мог пройти, дежурный разбирал и коммитил журнал руками. То же копилось
у DK-1432: строка эскалации лежала незакоммиченной.

Дополнение от 26.10.2026. Механизм подтвердился в полный рост: слияние
DK-489 дошло до круга 474, каждый отказ дописывал эскалацию в файл
задачи, грязная строка отбивала следующий круг по вороту дерева, и цикл
жил сам. Журнал уходил коммитом трижды за сутки (дважды дежурным утром,
затем разбором в 14:12), и только после чистого коммита круг перестал
отбиваться по дереву.

Первоначальная гипотеза черновика: записи этапа и эскалаций ложатся
коммитом доски сразу за записью, либо merge поглощает журнальную грязь
файла своей задачи. Отвергнута согласованием 7 ноября: оперативные
эскалации переезжают в журнал инцидентов, автоматический коммит не
выбирается.

## Сценарий проверки

Приёмка агентская на установленной версии после выката. Отдельного скрипта
стенда нет. Каждый python-стенд возводится самим тестом во временном каталоге,
с синтетическим git-репозиторием, временным HOME и временным журналом
инцидентов. Настоящие журналы, очереди и чаты машина проверки не трогает.
Команды идут из корня свежего дерева установленного devkit, не из старой
ветки задачи. Первый аргумент это каталог, второй модуль, класс или метод.

```sh
devkitctl test hooks incidents_test
devkitctl test tools/devkitctl watch_test.EscalationJournalTest
devkitctl test tools/devkitctl duty_test
devkitctl test tools/devkitctl lift_test.DutyCase
```
