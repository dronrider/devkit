# DK-1466: Часовое условие взвода с аргументом времени и уведомлениями браузера

Цель: [tasks/DK-1198.md](tasks/DK-1198.md)

## Что происходит

У взвода рёбер порядка нет аргумента времени, решение DK-933.6 отложило его. Напоминаний по времени у дашборда нет, отложенный черновик возвращается без даты, браузер молчит о сроках.

## Чего хотим

Взвод принимает часовое условие аргументом `--at`. Сторожок срабатывает в срок, напоминание ложится в журнал уведомителя. Отложенный черновик возвращается к названной дате, браузерное уведомление приходит с настройкой часа и числа дней до срока.

## Сценарий проверки

Проверка идёт на синтетическом дереве без участия человека, исход судит
прогон.

1. Дерево заводится чистым клоном devkit в `~/.devkit/scenario/DK-1466`. На
   доске три строки Backlog. Первая несёт ребро после закрытой задачи и
   часовой взвод, вторая взвод с прошедшим часом, третья обойдётся без
   взвода.
2. Часовой взвод держит строку до часа. Команда `taskctl -C <дерево> arm XR-A
   --at "завтра в два"` пишет суффикс `[взвод: <дата> 02:00]`. До срока
   `taskctl -C <дерево> wake --quiet` строку не поднимает и отказа не пишет.
   В проверке взвод ставится на минуту вперёд, после тика wake поднимает
   строку в Долг. Итог: до часа строка стоит в Backlog, после часа уезжает
   в Долг.
3. Отложенный черновик возвращается к дате. Команда `taskctl -C <дерево>
   draft defer XR-B --until <сегодня> "причина"` кладёт пометку с датой
   возврата, в тот же день пометка снимается. Итог: в `draft list --json` до
   дня возврата есть `deferred`, в день возврата поля нет.
4. Напоминание лежит в журнале уведомителя. На синтетической доске стоит
   строка со сроком `[срок: <сегодня>]`. Круг хранителя кладёт строку с
   поводом `task_due`. В бою круг живёт в демоне с ключами remind_hour и
   remind_days из `~/.devkit/dashboard.local`, на стенде его показывает
   прогон `devkitctl test tools/dashboard -run TestDueRemind`. Итог: у
   строки журнала стоят `повод task_due`, `задача <ID>` и `проект <имя>`.
5. Регрессия закрыта на базе. Прогон `regcheck --base main -- devkitctl
   test tools/devkitctl watch_test board_test` краснит все новые тесты на
   main и зелёнит на ветке. Итог: выход 0.
