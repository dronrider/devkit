# DK-1470: Контроль задачи проверкой за N дней до срока и кнопкой дожать

Цель: [tasks/DK-1198.md](tasks/DK-1198.md)

## Что происходит

Просроченная задача всплывает только взглядом по доске. Проверить работы к дате некому, напомнить исполнителю нечем, инспектора нет.

## Чего хотим

В карточке задачи появляется контроль, взять на карандаш. Напоминание, если контроль не выполнен к дате, прогон проверки работ агентом, напоминание исполнителю, назначение инспектора. Проверка стартует по сторожку за N дней до срока, проверяющий агент кладёт черновик вида «Риски срыва сроков по DK-123», уведомитель доносит. Напоминание тому, от кого ждут, пишет модель по шаблону в канал участника. Просроченный контроль виден на главной кнопкой «дожать». Риски срыва кладутся черновиком, отдельных строк контроль не заводит, потолки вопросов и деревьев DK-400 соблюдаются.

## Развилки

- «контроль-потолки»: контроль задачи против потолков вопросов и деревьев DK-400, как укладывается?
  - решает: исполнитель
  - рекомендация: контроль живёт внутри потолков DK-400, риски срыва кладутся черновиком, вопросов не выше двух на цель, сторожок за N дней до срока не плодит деревья
  - решено исполнителем 2026-10-28: контроль живёт внутри потолков DK-400: инспектор кладёт риски срыва черновиком и не заводит строк и деревьев, вопросов человеку не больше двух на цель и только штатным инструментом ожидания, подъём один на строку в день, поэтому деревьев и лишних вопросов сторожок не плодит; слова потолков вшиты в заказ инспектора (ControlOrder), и скиллы доски разводят по ним работу сессии без человека

## DoD

Контроль задачи стартует проверкой за N дней до срока, проверяющий агент кладёт черновик рисков, напоминание исполнителю уходит, всё живёт внутри потолков DK-400.

## Сценарий проверки

База кода до правки это 34c052b86. Тесты с новыми символами на базе не
собираются, их краснота regcheck не доказывает. Разбор лежит в «Ходе
работы».

1. Контрольный круг тика сторожка. Подъём идёт один раз на строку в день,
   повтор отказа зовёт человека один раз. Тишина вне окна не пишет журнал,
   суффикс контроля разбирается после маркера зависимости:

```sh
regcheck -C tools/devkitctl --base 34c052b86 --tests tools/devkitctl/watch_test.py,tools/devkitctl/board_test.py -- python3 -m unittest watch_test.ControlTickTest board_test.DepFindingsTest
```

   Ждём выход 0 и слова «регрессия закрыта».

2. Поле контроля доезжает от `taskctl set --control` до экрана задачи строкой
   доски. Сторож полей видит его в ответе list --json:

```sh
GOWORK=off regcheck -C tools/dashboard --base 34c052b86 --tests tools/dashboard/rowfields_test.go -- go test . -run TestBoardRowCarriesEveryJSONField -count=1
```

   Ждём выход 0 и слова «регрессия закрыта».

3. Отбор и подъём инспектора контроля по модулям:

```sh
devkitctl test internal -run "TestOfAndSuffix|TestControlNeed|TestInspectorChoice|TestControlOrder|TestControlRun"
devkitctl test tools/shipctl -run TestControlRun
devkitctl test tools/dashboard -run "TestControlRun|TestTaskPress|TestBoardRowCarriesEveryJSONField"
```

   Ждём три зелёных прогона. В заказе инспектора есть черновик рисков,
   напоминание исполнителю, потолки DK-400 и дожим просрочки. Строка вне
   окна и строка без контроля подъёмом не кончаются. Кнопка дожать зовёт ту
   же дорогу, строке без контроля ручка отказывает словами.
