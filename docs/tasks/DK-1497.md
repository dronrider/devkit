# DK-1497: Заголовок чата в списке дашборда становится «1» на реплике с нумерацией

## Что происходит

Разговор по цели DK-1198 открыт репликой из шести нумерованных пунктов. Первый
пункт начинался словами «1. Нашёл баг». В списке чатов дашборда разговор
получил заголовок «1». Харнес glm-code-2 записал в транскрипт осмысленный
заголовок «Баги главной страницы». Живой случай, сессия 9cf1c43a от 2026-10-28.

Разбор 2026-10-28 подтвердил механику прогоном: файл сессии занял 1562517 байт,
запись ai-title легла на смещении 415985. Обход уточнил корень: первая реплика
человека лежит на 19692 байта, а ai-title харнес пишет после первого витка
целиком, за тринадцатью записями вложений и служебных строк. Допущение DK-879
«сразу после первой реплики, до первого ответа модели» описывает кодовый
Claude Code и в подписке glm не держится.

Дашборд читает шапку транскрипта окном в 256 КБ (readSessionHead,
metaScanLimit, tools/dashboard/sessions.go). Харнес кладёт запись ai-title
после результатов инструментов первого хода. В живом случае запись легла на
смещении 415985, за окном. Список остался без ai-title и собрал заголовок
эвристикой первого предложения (titleTrim, tools/dashboard/chats.go). Эвристика
режет строку по первому знаку из «.?!». Реплика с нумерацией отдала заголовком
голую цифру.

Цифра вытесняет и запасной заголовок. Без эвристики фронтенд подписывает чат
строкой «чат <id8>» (static/app.js), а «1» занимает это место. Лестница
заголовка одна на всех потребителей (список чатов, раздел «Агенты»,
уведомления, доска). Правка читателя шапки достаёт их разом. Обход именем при
подъёме случая не закрывает этого. Дашборд называет только головы,
поднятые сам, а свободный чат из терминала остаётся без имени.

## Чего хотим

Чинится парой правок. Список дочитывает ai-title хвостом файла. titleTrim не
возвращает заголовок из одних цифр, нумерация в начале реплики обрезается.

Разбор снял способ «хвостом файла». Модельный хвост в 256 КБ в живом случае
лёг после записи и её не покрывает. Желаемый исход тот же, пользователь его и
ждёт. Список показывает заголовок из ai-title, эвристика не отдаёт заголовок
из одних цифр. Способ доставки записи лёг развилками ниже.

## Границы

- Запись custom-title читается тем же окном и пишется при /rename когда угодно,
  той же дальностью страдает, но живых жалоб нет. Вторым проходом она не
  достаётся и остаётся как есть.
- Место записи ai-title в харнесе glm-code-2 не двигается. Харнес внешний.
- Условий, посильных только человеку, не нашёл. Правка живёт в коде дашборда
  этого репозитория, проверяется синтетическим транскриптом и живым файлом
  сессии на этой машине.
