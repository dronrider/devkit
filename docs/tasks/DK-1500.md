# DK-1500: Архивация ломает ссылку на файл-спутник задачи

## Что происходит

При закрытии `taskctl close` задачи, в файле которой вне код-блока есть
ссылка на свой файл-спутник `docs/tasks/<ID>-...`, архивный файл получает
битую ссылку. У DK-1446 такой ссылкой был сценарий проверки.

Для воспроизведения нужна задача со спутником, на который ссылается файл
задачи. Закрытие уносит оба файла в `docs/tasks/archive/<год>/`. Ссылка
должна разрешаться в тот же архивный каталог. Вместо этого она смотрит на
прежний путь `docs/tasks/<ID>-...`, которого после закрытия нет.

Причина в порядке шагов закрытия. `rewriteLinksInFile` (tools/taskctl/ops.go)
переписывает ссылки относительно старого места файлов. Затем
`moveTaskSatellites` увозит спутники в архив, а `rewriteSatelliteRefs`
правит только текстовые вхождения `docs/tasks/<ID>-` внутри код-блоков.
Ссылка вне код-блока остаётся с путём `../../<ID>-...` на опустевшее место.
Замечено 2026-10-29 при проверке закрытия DK-1446. В самом архивном файле
DK-1446 ссылка починена руками.

## Чего хотим

Ссылки архивного файла задачи разрешаются после закрытия. Ссылка на
собственный спутник ведёт в архивный каталог так же, как команды в
код-блоках.

## DoD

- В архивном файле закрытой задачи со спутником нет ссылок, которые не
  разрешаются из его каталога.

## Ранг

`25+2+1+5+2 = 35`, P2.

- Серьёзность 25: запись закрытой задачи носит битую ссылку на сценарий
  проверки.
- Ценность 2: чистая починка статус-кво.
- Неопределённость 1: корень найден заранее.
- Поправка на баг 5: дефект переписывателя, а не новая работа.
- Рычаг 2: у каждой следующей закрытой задачи со спутником ссылки остаются
  целыми.
