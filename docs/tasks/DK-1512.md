# DK-1512: Конвейер сохраняет хвост и причину отказа при пересоздании головы

## Что происходит

Ротация из task-run.py повторно использует команду клиента с прежним
session-id. После записи хвоста оболочка снимает старую голову и запускает
ту же команду. Пустой ответ wait_session считается живым процессом без
адреса, даже если клиент уже завершился. Следующий подъём не получает
сохранённый хвост. В черновике DK-1512 есть три эпизода этого отказа.

Вечернее дополнение 30 октября описывает иной ранний выход новых голов
DK-722 и DK-1226 со свежим session-id. Его причина ещё не установлена.
На машине исполнителя отдельно подтверждена несовместимость версий:
установленный taskctl не знает guard, который новая оболочка вызывает
до запуска клиента. Этот факт не объявляется причиной удалённых эпизодов.

Воспроизведение не требует модели. Подставной клиент отказывает при
повторном ID или сразу завершается с сообщением в stderr. Ожидается
новая идентичность при ротации, сохранённая диагностика раннего выхода
и доставка хвоста при следующем восстановлении. Сейчас повторяется
старый ID, умерший процесс получает исход «без адреса», вывод может
исчезнуть вместе с окном, а хвост не входит в обычный первый заказ.

## Чего хотим

Ротация продолжает задачу в новой сессии с сохранённым хвостом.
Ранний отказ головы оставляет проверяемый исход, код возврата и местный
журнал до исчезновения окна. Восстановление после отказа не теряет хвост.

## Границы

Сохраняются терминал интерактивного клиента и проверки материала перед
запуском. Их запрещено обходить при старой или недоступной утилите.
Вечерний отказ сначала диагностируется по фактической команде и выводу.
Исправления DONE и неизвестной живости реестра остаются №165 и №166
очереди; длительные команды DK-722 и владение целью DK-1226 сюда не входят.
Условий, посильных только человеку, не найдено. Стенд использует временные
проекты и подставные клиенты, платных обращений к модели нет.

## DoD

- Повторный запуск после ротации получает новую идентичность из контракта
  профиля. Заказ и модель сохраняются, прежняя сессия не возобновляется
  случайно. Клиент без явного session-id остаётся поддержан.
- Ранний выход до регистрации отличается от живого процесса без адреса.
  Сохраняются код возврата, этап отказа и доступная диагностика, включая
  отказ проверки материала. Терминальный режим клиента не ломается.
- Сохранённый хвост включается в первый заказ восстановления после
  оборванной ротации. Повтор не теряет и не удаляет его до передачи.
- Отказ старой утилиты guard виден до расхода модели; проверка материала
  остаётся обязательной. Факт несовместимости содержит путь утилиты и
  способ штатного обновления, без автоматического обхода защиты.
- Регрессии со свежим/повторным ID, умершим/живым незарегистрированным
  клиентом и восстановлением хвоста проходят на изолированном стенде.
  Исходная краснота проверена regcheck.

## Ранг

`50+7+2+5+4 = 68`, P1.

50+7+2+5+4 = 68, P1, цена M.

- Серьёзность 50. Повторное создание головы останавливает выполнение задачи.
- Ценность 7. Восстановление сохраняет результат работы и следующий шаг.
- Неопределённость 2. Ротация воспроизводится по коду; вечерний ранний выход
  требует сохранения фактической диагностики.
- Поправка на баг 5. Заявленный переход ротации не доводится до нового хода.
- Рычаг 4. Один механизм используется головами разных задач.
