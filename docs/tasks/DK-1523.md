# DK-1523: Чат задачи в поднимающей вкладке пуст при разрешённом жильце

## Что происходит

Пользователь запустил задачу DK-1417 кнопкой доски и открыл её чат. Сервер
уже разрешает ключ окна конвейера в разговор жильца: ручка отвечает
идентификатором сессии и именем окна отдельным полем. Вкладка, помнящая свой
подъём, при этом показывает плашку «сессия поднимается», запертое поле и
пустую ленту, хотя жилец окна жив и пишет ходы. Так панель стоит до истечения
памяти подъёма, её потолок 15 минут.

Ветка сверки в static/app.js, строка 9859, проводит поле окна только в
условие плашки. Совпадение памяти с именем окна ставит плашку, но разговор
жильца не открывается. Поле окна приехало из DK-1521 вместе с серверным
разрешением, а открытие ленты под плашкой осталось недовезённым.

## Чего хотим

Разрешённый ответ открывает ленту жильца и в поднимающей вкладке. Разговор,
рождённый этим подъёмом, узнаётся сверкой рождения с моментом памяти подъёма
и снимает память. Плашка уходит, ввод открывается. Прежний жилец того же окна
держит плашку и замок над открытой лентой, реплика в него ушла бы вторым
агентом рядом с поднимающимся. Неразрешённый ключ работает как раньше, плашка
стоит без ленты.

## DoD

1. Поднимающая вкладка после разрешения ключа показывает ленту жильца.
2. Жилец, рождённый подъёмом, снимает плашку и замок ввода; прежний жилец
   держит их над лентой.
3. Неразрешённый ключ держит плашку без ленты, поведение прежнее.
4. Стенд жильца расширен обоими исходами и краснеет на коде до правки
   (regcheck).

## Ранг

`25+5+1+5+2 = 38`, P2.

- Серьёзность 25: поднимающая вкладка показывает пустой чат при живой работе
  окна, обход это повторное открытие чата из списка.
- Ценность 5: лента работы возвращается на главную поверхность панели.
- Неопределённость 1: подход ясен, правка локальна во фронте.
- Поправка на баг 5: недовезённая половина DK-1521.
- Рычаг 2: та же сверка рождения обслуживает подъёмы записи и цели.

## Сценарий проверки

Агентский, исполняется с машины агента, прод не меняет. Стенд жильца окна
testdata/poc_chatresident.mjs расширяется двумя фазами подъёмной вкладки.

1. В фазе «выросший жилец» память подъёма свежая, у окна жилец с транскриптом,
   рождение жильца не старее момента памяти. Открытие чата задачи видит ленту
   жильца, плашки нет, ввод открыт.
2. В фазе «прежний жилец» носитель тот же, но рождение жильца старее момента
   памяти подъёма. Лента жильца открыта, плашка стоит, ввод заперт.
3. `GOWORK=off regcheck -C tools/dashboard --base main -- go test ./... -run
   'TestStaticChatResident'` краснеет на базе и зелёный на ветке.
