# DK-156: Цель: автономный цикл не стоит молча и переживает обрывы

записан 2026-08-06

## Цель

Инцидент 2026-08-06 (чат «Выполни цель XR-266» в xr-proxy, разбор в DK-153):
сессия цикла дважды молча простояла часами, зависнув на ожидании выката без
Docker, и оба раза цикл поднимал пользователь вопросом в чат. Независимо от
зависаний ход цикла убивает обрыв соединения («API Error: Connection closed
mid-response», пойман живьём в devkit тем же днём), и в живом чате после него
витки никто не поднимает. Цель собирает комплекс: вставший цикл слышен, а
продолжение после стопа не требует ручного набора команд.

Разведка грумминга:

- DK-153 (сторожок: простой дольше порога зовёт громко) и DK-154 (shipctl:
  вставший deploy проваливается по пределу, ожидание фона через Monitor)
  заведены тем же днём и становятся задачами цели при нарезке;
- восстановления после стопа сегодня нет нигде: goal-loop говорит «продолжение
  это новый чат той же фразой либо оболочка», обвязка goal-run чинит обрыв
  «повторным запуском той же командой», и то и другое руками, хотя состояние
  цикла целиком на диске и продолжение механическое;
- кандидат третьей задачей нарезки: перезапуск вставшего витка тем, кто
  заметил стоп, с ограничителем попыток, чтобы не зациклить сломанный виток;
- смежная DK-117 (след хода витка по ходу, а не по концу) даёт сторожку
  готовый критерий движения, связь учесть при нарезке.

Границы:

- перезапуск не маскирует поломку: провал прода, `wait-human` и исчерпанный
  бюджет остаются стопами с громким зовом, перезапуск положен только стопу
  без вердикта (обрыв, зависание, убитая сессия);
- бюджет цели и потолок яруса ставятся на постановке, черновик их не задаёт.

DoD, агентский:

1. Стендовый прогон воспроизводит инцидент без молчаливого простоя: виток,
   подвешенный на вечной команде, замечен не позже порога, и уведомитель
   позван громким поводом; проверяется строкой уведомления в прогоне, а не
   глазом.
2. Deploy-команда, не кончившаяся за предел, даёт провал выката с громким
   уведомлением, а не вечное ожидание; проверяется кодом возврата shipctl и
   строкой провала.
3. Стоп цикла без вердикта (убитая сессия, обрыв соединения) кончается
   перезапуском: сам с ограничителем попыток либо одной командой, названной в
   уведомлении. Стендовый прогон убивает сессию витка и видит перезапуск, а
   исчерпанные попытки кончаются громким стопом, не тихим зацикливанием.
4. Граница держится: провал прода, `wait-human` и `over` перезапуска не
   получают, на стенде такой стоп остаётся стопом с громким зовом.
5. Прогон `test` из `.devkit/deploy.local` зелёный, поведение осело в
   долгоживущих доках (README затронутых утилит, скиллы цикла).

## Задачи цели

Нарезано первым витком 2026-08-07, три задачи в таком порядке:

1. DK-153, сторожок цикла цели: простой дольше порога зовёт громко. Цена M,
   ранг 63, зависимостей нет. Идёт первой: она даёт обнаружение стопа, на
   которое встаёт всё остальное, и закрывает первый пункт DoD.
2. DK-169, goal-run: стоп без вердикта перезапускает виток, попытки ограничены,
   продолжение одной командой. Цена M, ранг 38, после DK-153. Закрывает третий
   и четвёртый пункты DoD, включая границу «стоп с вердиктом перезапуска не
   получает».
3. DK-154, shipctl: вставший deploy проваливается по пределу, ожидание фона
   через Monitor. Цена M, ранг 34, зависимостей нет. Закрывает второй пункт
   DoD, ехать может когда угодно, стоит третьей по рангу.

Решения нарезки:

- перезапуск отделён от сторожка, а не склеен с ним: сторожок с носителем,
  порогом и тестами сам по себе цена M, вместе с правкой оболочки и уведомлений
  вышло бы L, а крупнее M склеивать нельзя. Зависимость между ними настоящая:
  перезапуск делает тот, кто заметил стоп, второго механизма обнаружения рядом
  заводить незачем;
- DK-117 (наблюдаемость витков из чата) в состав цели не вошла. Критерий
  движения сторожок берёт из `.devkit/log`, куда каждая утилита devkit пишет
  строку с меткой времени при любом входе, хоть из чата, хоть под оболочкой, а
  гейт бюджета в начале витка гарантирует такую строку не реже витка. След хода
  из DK-117 дал бы критерий тоньше, но при пороге в десятки минут он не нужен, и
  ждать чужую задачу цель не будет. Разбор в DK-153;
- пятый пункт DoD (зелёный `test`, дока в README и скиллах) отдельной строкой не
  заводится: тесты и дока едут вместе с правкой в каждой из трёх задач по общим
  правилам, отдельная строка тут только оплатила бы лишний круг конвейера.

## Итог

Цель достигнута 2026-08-07, три задачи закрыты за два рабочих витка, прод
живой после каждой. Прогон DoD:

1. Вставший цикл замечен и слышен: стендовый прогон в проверке DK-153 (простой
   3 часа при пороге 45 минут дал громкий зов с именем цели, живой цикл тих),
   на машине поднят launchd-агент ru.devkit.goal-watch с проверкой раз в 5
   минут, doctor находок по сторожку не даёт.
2. Вечная deploy-команда кончается провалом: прогон в проверке DK-154 (sleep
   600 при пределе 5s убит за 5 секунд кодом 1, текст называет команду и ключ
   deploy_timeout, умолчание 30 минут в README), штатный выкат не задет.
3. Стоп без вердикта кончается перезапуском: прогон в проверке DK-169 (обрыв
   дважды, третий виток done, код 0; вечный обрыв упирается в три попытки и
   встаёт громко), команду продолжения целиком сторожок кладёт в баннер.
4. Граница держится: wait-human перезапуска не получил (счётчик 1, код 0),
   терминальные маркеры и проваленный прод останавливают цикл как раньше
   (тест test_each_terminal_marker_stops_on_first_turn).
5. Полный прогон ключа test зелёный на каждом слиянии, поведение осело в
   README shipctl и devkitctl, LLD DK-079 и скилле goal-loop.

Живая проверка комплекса случилась по ходу самой цели: сессия исполнителя
DK-169 оборвалась на ENOTFOUND и была поднята с места обрыва.

Потрачено по бакетам за цикл: week_all 7 пп из 20, week_max 8 пп из 8
(потолок задели впритык, но не пробили). Незакрытых задач и деревьев не
осталось.
