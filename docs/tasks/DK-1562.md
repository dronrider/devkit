# DK-1562: Тест taskctl зависает в голом окружении из-за headless-подъёма головы

## Что происходит

Очередь слияний машины заперта наглухо. С переменными грума краснеет agentctl,
без них зависает taskctl. DK-1546 снята с очереди с причиной и ждёт починки.

## Чего хотим

Подъём headless-головы не проверяет, есть ли кому подниматься. В голом
окружении нет ни сессии харнеса, ни реестра чатов, а taskctl draft всё равно
спавнит оболочку и ждёт принятия замка. Поднятию нужно отступать без спавна,
когда окружение не несёт адреса сессии и записи ожидания.

## DoD

Слияние любой ветки на этой машине проходит шаг тестов в свежем дереве.
Прогон go:taskctl без CLAUDE-переменных и с пустым домом зелёный,
репродукция из «Ситуации» проходит, очередь слияний снова сливает ветки.

  прогона очереди остался не пойман, решение от него не зависит: лестница
  обязана отступать без спавна.
- 2026-11-03, правка. Headless-ступень лестницы в internal/taskhead/raise.go
  получила стража носителя carried(). Спавн оболочки без окна стоит только
  при явном заказе. Это приставка зовущего (все подъёмы дашборда, DK-935),
  заказ словами (--order, --reply) или обход записи ожидания. Обход ставит
  новое поле Request.Waited, его заполняет taskctl wake. Голову тоже видно
  без окна, когда у зовущего есть адрес сессии CLAUDE_CODE_SESSION_ID или у
  задачи есть окно в реестре чатов. Без носителя лестница говорит строку
  отступа и уходит к зову человека, подпроцесс оболочки не заводится. Окно
  tmux страж не трогает, окно видит сам человек. Заказ несут все конвейерные
  зовущие. Дашборд ставит приставку, лифт и сторожок идут с ключами --reply
  и --order (lift.py), обход ждущих с флагом Waited.
- 2026-11-03, тесты. Регрессия TestHeadlessBacksOffWithoutCarrier лежит в
  internal/taskhead/carrier_test.go отдельным файлом. Голый запрос без tmux,
