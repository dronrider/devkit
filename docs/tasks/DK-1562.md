# DK-1562: Тест taskctl зависает в голом окружении из-за headless-подъёма головы

## Что происходит

Очередь слияний машины заперта наглухо. С переменными грума agentctl краснеет,
без них taskctl зависает. DK-1546 снята с очереди с причиной и ждёт починки.

## Чего хотим

Подъём headless-головы не проверяет, есть ли кому подниматься. В голом
окружении нет ни сессии харнеса, ни реестра чатов, а taskctl draft всё равно
спавнит оболочку и ждёт принятия замка. Поднятию нужно отступать без спавна,
когда в окружении нет адреса сессии и записи ожидания.

## DoD

Слияние любой ветки на этой машине проходит шаг тестов в свежем дереве.
Прогон go:taskctl без CLAUDE-переменных и с пустым домом зелёный,
регрессионный тест TestHeadlessBacksOffWithoutCarrier зелёный, очередь
слияний снова сливает ветки.

## Ранг

`50+8+3+0+4 = 65`, P1.

- Серьёзность 50. Очередь слияний машины заперта, ни одна ветка не сливается.
- Ценность 8. Каждое слияние любой задачи на этой машине.
- Неопределённость 3. Место спавна найдено (raise.go, headlessCmd), повод
  подъёма из sandbox-команды draft неясен.
- Поправка на баг 0. Дефект main, не следствие чужой правки.
- Рычаг 4. Конвейер держит все строки доски разом.

## Приёмка

- вид agent. Регрессионный тест TestHeadlessBacksOffWithoutCarrier ловит
  спавн оболочки без носителя, ручной взгляд не нужен.

## Ход работы

- Из черновика DK-1562 «Тест taskctl зависает в голом окружении из-за headless-подъёма головы»: записан 2026-11-02, оформлен 2026-11-02. Тип task, источник thought.
- 2026-11-03, диагностика. Подъём taskhead.Raise достижим из taskctl двумя
  дорогами. Первая `taskctl run`, вторая обход ждущих: `taskctl close` ->
  wakeNote -> cmdWake -> raiseHead -> cmdRun. Третьей нет, проверено грепом
  по всем ссылкам taskhead в tools/taskctl. На пути `taskctl draft` и
  вложенного `taskctl show` нет вызова подъёма. Ребёнок /bin/sh в стеке
  внешнего draft это скорее git-обёртка самого теста. Шелл headlessCmd
  требует непустую приставку Prefix, а её ставит один дашборд.
  Воспроизвести красноту из интерактивной сессии не вышло ни в одной
  конфигурации. Снимал CLAUDE-переменные, ANTHROPIC-*, DEVKIT_*, делал
  пустой дом, урезал PATH до набора демона, брал свежее дерево с bin
  впереди PATH. Тест везде зелёный, спавнов головы нет. По журналу очереди
  красные прогоны go:taskctl длятся 727-795с при 25с зелёных. Это шестьсот
  секунд go-таймаута плюс сборка, пакет зависал целиком. Точный триггер
  прогона очереди остался не пойман, решение от него не зависит. Лестница
  обязана отступать без спавна.
- 2026-11-03, правка. Headless-ступень лестницы в internal/taskhead/raise.go
  получила стража носителя carried(). Спавн оболочки без окна стоит только
  при явном заказе или когда голову видно. Заказ это метка Request.Wanted,
  её ставит вход команды run (tools/taskctl/run.go) на каждый вызов cmdRun.
  Руками, скриптом или обходом ждущих команду зовут осознанно. Поэтому
  простой run поднимает headless и без tmux, как прежде. Ещё заказ это
  приставка зовущего (все подъёмы дашборда, DK-935) и заказ словами
  (--order, --reply). Голову видно, когда у зовущего есть адрес сессии
  CLAUDE_CODE_SESSION_ID или у задачи есть окно в реестре чатов. Прямой
  вызов библиотеки без метки и без носителя получает отступ. Лестница
  печатает строку отступа и уходит к зову человека, подпроцесс оболочки не
  заводится. Страж не трогает окно tmux, окно видит сам человек. Первая
  версия стража резала спавн и для голого cmdRun, три теста run падали.
  Тесты кодируют обязанность простого run поднимать headless без tmux.
  Метку заказа ставит сам вход команды.
- 2026-11-03, тесты. Регрессия TestHeadlessBacksOffWithoutCarrier лежит в
  internal/taskhead/carrier_test.go отдельным файлом. Тест подаёт голый
  запрос без tmux и проверяет, что голова не поднята, runner.log не создан
  и отступ назван строкой. Тест гасит адрес сессии машины, стенд
  воспроизводит голое окружение. regcheck с этим файлом краснеет на main
  и зелёный на правке.
  Существующие тесты headless-ступени (TestNoTmuxGoesHeadless,
  TestWindowFailureFallsToHeadless, TestHeadlessDropsCallerWindow) переведены
  на явный заказ Wanted, добавлен TestHeadlessCarriedByExplicitOrder. Отбор
  лестницы в internal зелёный, 28с.
- 2026-11-03, прогоны. Полный go:internal зелёный, 51с. Полный go:taskctl
  в голом окружении зелёный, 285с. Первый голый прогон того же кода упал
  на clitx-обёртках при высокой нагрузке машины. Тесты BoardGuard и
  MoveRejects вкладывают show в git-обёртку PATH процесса. Фоновые
  параллельные тесты зовут git в эту же обёртку, и под перегрузом вложенный
  show не успевает за потолок 6с внешней команды. Попавший в обёртку
  wake-тест висит до общего таймаута пакета. Повтор без перегруза зелёный,
  дифф задачи ни при чём. Похоже, это и есть причина красноты очереди,
  машина очереди всегда под грузом слияний. Живой полный прогон прошёл по
  всем тестам, FAIL поставил один runsguard, в настоящий реестр runs
  писала живая голова DK-919. Это шум окружения.
- Вычитка: 2 файла, 18 правок, 3 пометки, 2026-11-03.

## Ревью

Уровень 3 до 2dd1126: неопределённость 3, дифф трогает tools/taskctl и механизм подъёма головы, от которого зависит очередь слияний

- [возврат: правила, 2026-11-03] не блокирует: internal/taskhead/carrier_test.go, TestHeadlessBacksOffWithoutCarrier гасит из окружения зовущего только CLAUDE_CODE_SESSION_ID, а связка DEVKIT_GROOM_SOURCE и DEVKIT_GROOM_MODE режет подъём ещё раньше лестницы (GuardGroomRun в Raise, DK-1545): в любой сессии грумера или диспетчера тест падает посторонней ошибкой «источник разбора DK-1531 не прочитан» вместо проверки носителя. Воспроизведено прогоном на ветке и на main, у существующих Raise-тестов та же хрупкость, очередь слияний переменных не несёт, поэтому не блокирует. Погаси обе переменные рядом с гашением адреса сессии, и стенд перестанет зависеть от машины.: исправлено, переменные погашены в carrier_test.go рядом с адресом сессии, коммит 1064fafa8, краснота воспроизведена и снята прогоном

## Сценарий проверки

Команды выполняются из корня свежего дерева devkit. Каждый шаг гасит
CLAUDE-переменные зовущего и подставляет временный HOME, а кеш сборки и
модулей берёт из машины, чтобы прогон не качал зависимости заново.

1. Регрессионный тест в голом окружении проходит и называет отступ без
   носителя.

```sh
cache=$(go env GOCACHE) && mod=$(go env GOMODCACHE) && case_home=$(mktemp -d) && trap 'rm -rf "$case_home"' EXIT && env -u CLAUDE_CODE_SESSION_ID -u CLAUDE_CONFIG_DIR -u DEVKIT_GROOM_SOURCE -u DEVKIT_GROOM_MODE HOME="$case_home" GOCACHE="$cache" GOMODCACHE="$mod" GOWORK=off devkitctl test "$PWD/internal" -run TestHeadlessBacksOffWithoutCarrier -count=1
```

2. Полный go:taskctl в том же окружении зелёный и не зависает.

```sh
cache=$(go env GOCACHE) && mod=$(go env GOMODCACHE) && case_home=$(mktemp -d) && trap 'rm -rf "$case_home"' EXIT && env -u CLAUDE_CODE_SESSION_ID -u CLAUDE_CONFIG_DIR -u DEVKIT_GROOM_SOURCE -u DEVKIT_GROOM_MODE HOME="$case_home" GOCACHE="$cache" GOMODCACHE="$mod" GOWORK=off devkitctl test "$PWD/tools/taskctl"
```

первого шага есть `ok github.com/dronrider/devkit/internal/taskhead`, во
втором go:taskctl без FAIL. Шаги машинных настроек не меняют.
