# DK-1576: Вложенный спавн субагента теряет тип определения

## Что происходит

Исполнитель DK-1570 поднял вычитчика по определению proofread из своей сессии. Хук спавна записал этого субагента этапом «разработка» с определением exec-high, и ворота плана на пункте «вычитка» не закрылись: в событии харнеса agent_type приехал от родительского захода, тип определения proofread потерялся по дороге. Этап «вычитка» руками не ставится, `agentctl stage` отказывает, пункт плана остался открытым при сделанной работе. Обход встал записью препятствия в «Ход работы», след этапа в пакете runs потерян.

## Чего хотим

Субагент, поднятый из субагента, приезжает в событии харнеса с типом своего определения. Хук спавна ставит по нему свой этап, proofread даёт «вычитку», и ворота планов закрываются обычным done без форса.

## DoD

Спавн proofread из exec-сессии записывает этап «вычитка» в пакет runs и «Ход работы». План с пунктом вычитки закрывается done без форса. Тест на событие вложенного спавна едет с правкой.

## Ранг

`25+3+1+5+2 = 36`, P2.

- Серьёзность 25: этапы записей задач врут, ворота планов встают и обходятся форсом, след учёта портится.
- Ценность 3: путь вложенного спавна редкий, но каждая такая задача ловит отказ на пустом месте.
- Неопределённость 1: диагноз назван, правка узкая, открыто где теряется тип в событии.
- Поправка на баг 5: это дефект механики, у фичи здесь предмета нет.
- Рычаг 2: один хук, чинит учёт этапов у всех вложенных спавнов.

## Приёмка

- вид: agent
- Сценарий: тест события вложенного спавна зелёный, done пункта вычитки закрывается без форса на синтетической задаче.
