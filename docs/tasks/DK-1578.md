# DK-1578: Ворота плана читают след этапа в основном чекауте

## Что происходит

Ревьювер DK-1570 работал в дереве задачи и записал след ревью в файл задачи ветки. `agentctl plan done` на этапе «ревью» пункт не закрыл: ворота этапа читают docs/tasks/DK-1570.md основного чекаута, где раздела «Ревью» нет. Пункт плана остался открытым при сделанной работе, форс ворот не снимает, а отказ называет основную копию файла. Тот же отказ словил исполнитель DK-1570 на этапе вычитки по соседней причине (DK-1576).

## Чего хотим

Ворота plan done берут след этапа там, где работа шла. Копия файла задачи живёт в дереве задачи до слияния, и смотреть воротам надо её: у основной копии раздела на этот момент нет. По какому ключу ворота находят дерево (путь рядом с проектом по имени ветки, запись `shipctl status` или явный -C), решает исполнитель.

## DoD

plan done по этапу, чей след лежит в файле задачи ветки worktree, закрывается без форса. Ворота не путают две копии файла: след из основной копии и след из копии дерева различаются, и берётся тот, что свежее по работе задачи. Тест на ворота с двумя копиями едет с правкой.

## Ранг

`25+3+2+5+2 = 37`, P2.

- Серьёзность 25: пункт плана висит открытым при сделанной работе, след учёта не сходится, обход ручной.
- Ценность 3: ревью и вычитка идут субагентами в дереве задачи, каждый круг ловит отказ.
- Неопределённость 2: открыто, по какому ключу ворота находят дерево задачи.
- Поправка на баг 5: это дефект механики.
- Рычаг 2: одни ворота, чинят закрытие планов у всякой задачи с деревом.

## Приёмка

- вид: agent
- Сценарий: done этапа со следом только в копии дерева закрывается без форса на синтетической доске с worktree, и тест двух копий зелёный.
