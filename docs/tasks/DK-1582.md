# DK-1582: Запуск облачного чата не оставляет процессы после проверки

## Что происходит

На рабочей машине 3 ноября обнаружены 416 осиротевших cloud-start guardian
от smoke-проверок dashboard. После окончания стенда его fake tmux удалён,
ack отсутствует, а оболочка раз в секунду повторяет опрос без конечного
исхода. Установленный код 4fb2f5702ccf совпадает с main 8c015e705795 в этих
местах. Утечка изолированно воспроизведена точным shell-кодом cloudstart.go.
Нормальный ack завершает процесс, удаление fake tmux оставляет его живым.

Результаты исследования и критерии №171 и №172 опубликованы в
https://github.com/dronrider/devkit/blob/codex/concurrency-refresh-20261030/docs/concurrency-incident-20261103.md.

## Чего хотим

Запуск различает создание терминала и принятие резерва клиентом. Неизвестная
живость получает ограниченный опрос, сохранённое состояние с владельцем и
диагностику. Резерв остаётся защищённым до ack или доказанной смерти клиента.
Стенд по любому исходу завершает только собственные процессы, ждёт их выхода
и закрытия резервов до удаления фикстур. Повторные прогоны не накапливают
guardian.

## Границы

Работа покрывает №171 и №172. Общая политика нагрузочных повторов №173 и
расследование остановок чатов №174 сюда не входят. Нет изменений квот,
подписок, порога простоя или массового завершения чатов. Простое освобождение
резерва по тайм-ауту запрещено: клиент может ещё работать. По подтверждению
исправления отдельно допускается адресная очистка только синтетических
остатков из снимка с повторной сверкой PID, команды и удалённой фикстуры.

## DoD

- Ack передаёт резерв без разрыва; guardian завершается, рабочий клиент жив.
- Смерть клиента до ack освобождает резерв с причиной. Выход родителя сам
  по себе не снимает резерв, принадлежащий ещё живому запуску.
- Временный сбой опроса не снимает живой чат. Постоянная неизвестная живость
  не создаёт бесконечный частый опрос; состояние и владелец резерва наблюдаемы.
- Smoke поддерживает реальный контракт ack/живости. Успех, ошибка, отмена
  и тайм-аут не оставляют процессов и открытых резервов своего стенда;
  удаление фикстуры происходит после завершения процессов. --keep сохраняет
  материалы без живых циклов.
- Регрессия удаления fake tmux до ack падает на исходном коде и проходит
  после исправления, проверка через regcheck. Серия изолированных запусков
  не накапливает процессы. Боевые сессии и модельные API не используются.
- README описывает состояния запуска, диагностику и порядок завершения стенда.

- Серьёзность 50: очередь слияний простаивает при сотнях оставшихся процессов.

- Рычаг 4: один путь запуска применяется в нескольких входах чата и цели.

## Сценарий проверки

На установленном после выката дереве выполнить адресные тесты cloudstart
и проверку отсутствия остатка smoke без модельных вызовов. Точные команды
будут дополнены вместе с исполняемыми регрессиями до обкатки.
