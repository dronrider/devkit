# DK-1593: Ссылка архива не разбирается, отложенная реплика закрытой задачи не находится

## Что происходит

Ревью DK-1591 нашло мёртвую ветку в holdFile дашборда. parseArchiveRows
кладёт в Link всю шестую ячейку строки архива вместе с markdown-обёрткой и
хэшами коммитов (tools/dashboard/goal.go, формат ячейки виден в
docs/TASKS-archive.md). Stat по такому пути всегда падает, и для закрытой
задачи holdFile всегда отвечает «файла нет». Реплика в мёртвое окно закрытой
задачи снимается без записи. Файл задачи при этом лежит в
docs/tasks/archive/<год>/, и записать в него можно.

## Чего хотим

Ссылка архива разбирается до пути файла, holdFile находит файл закрытой
задачи. Отложенная реплика ложится в раздел «Входящие» этого файла с
коммитом от корня репозитория.

## DoD

Тест закрывает архивную ветку holdFile: строка архива в живом формате, файл
в docs/tasks/archive. Отложенная реплика находится в файле, коммит называет
путь от корня. Тест красный на старом коде, regcheck это держит.

## Ранг

`0+2+1+0+1 = 4`, P3.

- Серьёзность 0: реплика не теряется, остаётся строкой журнала и звоном
  человеку, но в файл задачи не ложится.
- Ценность 2: закрытые задачи получают реплики редко.
- Неопределённость 1: место и формат известны, открыт только разбор ячейки.
- Поправка на баг 0: баг подтверждён чтением кода, не воспроизведением.
- Рычаг 1: разбор ссылки пригодится другим читателям архива.
