# DK-1605: Повторное продолжение задачи поднимает второй процесс того же SID

Цель: блокер проверки DK-1253, воспроизведено DK-1433

## Что происходит

При сквозной проверке DK-1433 на установленном b110be669 повторное продолжение
запустило два процесса одного разговора. После смены модели и возобновления
через say у синтетической XR-010 уже было живое окно chat-XR-010-1.
Обычный POST /tasks/XR-010/continue вернул way=resume и chat-XR-010-2.
Оба процесса одновременно работали с одним --resume SID. Для обоих
сохранены полные SessionStart с указанием транскрипта того же SID.
Ожидалось продолжение в живом окне. Два исполнителя одного разговора могут параллельно менять одни файлы и повторять работу.

handleTaskContinue получает каноническое имя окна, но перед liftChat проверяет
только сокет. Профиль клиента допускает работу без peer-сокета. Дорога say
для такого профиля уже умеет найти живое окно с проверкой владельца.
Подтверждение и снимки процессов сохранены в
/private/tmp/dk1433-final-run/proof/G2-duplicate-FAIL.json;
разбор кода в /private/tmp/dk1253-g2-continue-diagnosis.md.

## Чего хотим

Продолжать живой основной чат через существующий безопасный канал.
Новый процесс нужен после смерти прежнего носителя. Живой процесс цели
не получает дополнительной подгоняющей реплики. Сохраняются проверки
владельца окна и конфликта peer, а также существующие отказы доставки.

Это блокер проверки цели DK-1253. DK-1138 касается разделения ленты после
снятия и нового подъёма окна; здесь два процесса одновременно обслуживают
один SID. Постановка DK-1138 и принятые по ней решения не меняются.
Условий, посильных только человеку, не найдено. Работа идёт на синтетическом
профиле без обращения к внешней модели и без новых доступов.

## DoD

- После say/resume и последовательного continue остаётся один живой процесс
  того же SID и окна. Контрольная реплика приходит только ему.
- Проверка живого окна сохраняет защиту от чужого владельца и конфликта peer.
  Обычная ошибка доставки не запускает рядом новый процесс; умерший носитель
  по-прежнему возобновляется штатным способом.
- Живая цель не получает лишнюю подгоняющую реплику. Дорога через сокет
  и обработка отсутствия подтверждения не ухудшены.
- Поведенческий regcheck падает на старой версии и проходит после правки.
  Отдельная сессия повторяет сценарий на установленном бинаре с настоящими
  tmux-окнами и квитанциями. README описывает выбор живого канала.

## Ранг

`50+5+2+5+3 = 65`, P1.

- Серьёзность 50: два исполнителя одного разговора могут одновременно менять
  рабочее дерево и дублировать работу.
- Ценность 5: затронуто продолжение возобновлённого чата без peer-сокета.
- Неопределённость 2: причина и поддерживаемый канал найдены, нужно сохранить
  проверки владельца и ошибки доставки.
- Поправка на баг 5: два живых процесса подтверждены установленным прогоном.
- Рычаг 3: один путь продолжения обслуживает задачи и цели.
