# DK-1623: Накопитель дашборда забивает канал сотнями запросов

## Что происходит

HAR пользователя от 2026-11-06 содержит 994 запроса. Из них 933 приходятся на чтение prepared. Экран накопителя renderDrafts в tools/dashboard/static/app.js делает Promise.all по всем 466 черновикам. Две волны по 466 запросов стартовали в 17:54:34 и 17:55:27. Вторую волну вызвало восстановление связи lostAgain -> refresh -> renderDrafts. Запрос projects стоял до отправки 34,29 с, waiting 32,66 с, resources 39,19 с. Получены 35 ответов 502 с Too many open files (os error 24) от посредника. Открытие согласования занимает десятки секунд. Ожидается постоянное число запросов при любом количестве черновиков.

Обход появился в DK-1469, DK-1564 сохранила его при замене proposals на prepared. В DK-1564 есть отдельные изменения формы и подтверждения. Здесь требуется отдельная срочная правка производительности без их переписывания.

## Чего хотим

Восстановить работу накопителя и открытия подготовленной задачи сейчас. Сервер отдаёт общий состав подготовленных задач одним ответом. При открытии и обновлении списка нет сетевых запросов по каждому черновику. Решение может быть небольшим временным шагом до последующей оптимизации серверного чтения.

## Развилки

Открытых человеческих развилок нет. Пользователь 2026-11-06 поручил оформить находки и временно восстановить работоспособность дашборда. Конкретный способ общего чтения выбирает исполнитель по действующему источнику prepared. Ограничение параллельности 466 запросов пользователь отверг как сохранение ошибочной логики. Скрывать подготовленные задачи и отключать подтверждение не требуется.
