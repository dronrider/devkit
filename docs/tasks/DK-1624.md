# DK-1624: Проверена переносимость чатов между Claude и Codex

## Что происходит

В чате можно менять модель и подписку с сохранением разговора. Текущий перенос использует совместимые транскрипты Claude Code. У Codex есть профиль для разовых поручений, но работа с ним через app-server ещё не подключена. Не проверено, можно ли передать историю из Claude в Codex и вернуть результат обратно без потери доступного пользователю контекста. Предмет согласован в разговоре 2026-11-06.

## Чего хотим

Провести ограниченный эксперимент Claude -> Codex -> Claude на отдельном проекте. Зафиксировать переносимые данные, ограничения и способ продолжения разговора. По результатам предложить следующий шаг интеграции. Отрицательный результат считается результатом задачи, если ограничение воспроизводится и сохранены подтверждения.

## Границы

Работа идёт на синтетической истории и временном проекте. Рабочие чаты пользователя и настройки дашборда не меняются. Используется локальный codex app-server с существующим входом через подписку ChatGPT. Нужны сообщения обеих ролей, вызовы инструментов и их результаты, команда и правка файла. Отдельно проверяются длинная история, сжатая история при доступной поддержке и восстановление после перезапуска процесса.

Полная интеграция в интерфейс, конвейер задач, новый постоянный журнал и общий переносчик всех форматов в эту задачу не входят. Недоступное внутреннее состояние моделей не объявляется перенесённым. Сводка вместо исходных сообщений отмечается как потеря подробностей.

## Наблюдение о потоковом вводе инструментов

Диспетчер проверил обратную пару: assistant.message.content с text и tool_use(id,name=Bash,input.command), затем user.message.content с tool_result(tool_use_id,content,is_error=false), затем конечный user-вопрос. Поэтому успешное чтение одного assistant и пары tool_use/tool_result не доказывает тихий импорт полного разговора. Нужно считать дополнительные turn, фактические новые tool_use и их побочные эффекты. Повтор полного разговора через stream-json может запускать генерации на каждом историческом user. Тип assistant во входе принят установленным клиентом, но его гарантии в публичной документации отдельно не найдены: не называть этот тип документированным supported API только из-за наличия флага stream-json.
