# DK-1624: Проверена переносимость чатов между Claude и Codex

## Что происходит

В чате можно менять модель и подписку с сохранением разговора. Текущий перенос использует совместимые транскрипты Claude Code. У Codex есть профиль для разовых поручений, но работа с ним через app-server ещё не подключена. Не проверено, можно ли передать историю из Claude в Codex и вернуть результат обратно без потери доступного пользователю контекста. Предмет согласован в разговоре 2026-11-06.

## Чего хотим

Провести ограниченный эксперимент Claude -> Codex -> Claude на отдельном проекте. Зафиксировать переносимые данные, ограничения и способ продолжения разговора. По результатам предложить следующий шаг интеграции. Отрицательный результат считается результатом задачи, если ограничение воспроизводится и сохранены подтверждения.

## Границы

Работа идёт на синтетической истории и временном проекте. Рабочие чаты пользователя и настройки дашборда не меняются. Используется локальный codex app-server с существующим входом через подписку ChatGPT. Нужны сообщения обеих ролей, вызовы инструментов и их результаты, команда и правка файла. Отдельно проверяются длинная история, сжатая история при доступной поддержке и восстановление после перезапуска процесса.

Полная интеграция в интерфейс, конвейер задач, новый постоянный журнал и общий переносчик всех форматов в эту задачу не входят. Недоступное внутреннее состояние моделей не объявляется перенесённым. Сводка вместо исходных сообщений отмечается как потеря подробностей.

## DoD

1. Есть повторяемый сценарий с командами запуска, версиями клиентов и синтетическими исходными данными.
2. Проведены оба перехода Claude -> Codex и Codex -> Claude. Новый исполнитель подтверждает факты из прежних сообщений и результатов инструментов, которых нет в последней реплике и текущих файлах.
3. История инструментов проверяется отдельно от текстовых сообщений. Есть команда, вывод команды и правка файла. Сохранены причины отказов либо подтверждение продолжения на принимающей стороне.
4. Проверены длинный вывод инструмента с маркерами в начале, середине и конце, отсутствие дублей после повторного импорта и восстановление после перезапуска app-server. Длина и пределы эксперимента указаны числами.

7. Есть вывод о варианте реализации и объёме следующего шага. Результат не обещает бесшовного переключения, если эксперимент этого не подтвердил.

## Порядок эксперимента

Реализовать только переносимый проверочный сценарий и отчёт по ограничениям. Рабочая машина и её штатные настройки остаются за диспетчером. Диспетчер выполнит подготовленный сценарий там и вернёт обезличенный результат. Не менять настройки дашборда, не обновлять Codex, не открывать журналы чужих чатов и не читать секреты. Не пушить и не сливать ветку из исполнительского процесса. Хуки не обходить.

Начать с доступного протокола установленного Codex 0.163.0, а не предположений из актуального сайта. Диспетчер проверил активный ChatGPT-вход и команду app-server. Сгенерированную схему он предоставит в local-docs. Клиент Claude Code используется как формат истории; текущий реальный модельный провайдер можно взять из действующей подписки GLM, поэтому не путать клиент Claude с обязательной моделью Anthropic. Работа только в новом временном проекте с синтетическими сообщениями.

Код эксперимента, тесты преобразования и результат должны соответствовать раскладке README. Для одноразовых сценариев проверки допустимо место в docs по существующему правилу; если выбран модуль инструмента, соблюсти его язык. Сначала подготовить сценарий и автономные тесты, сообщить путь и команду диспетчеру отдельной короткой строкой stdout, затем заняться документацией. Нужен структурированный JSON-результат, а полные сырые журналы оставить вне git в каталоге конкретного запуска. В репозиторий не копировать auth/config клиента, пути пользовательских домов, адреса машины и приватные журналы.

Критически важно не подменять эксперимент сводкой. Проверить передачу ролей и аргументов/результатов инструментов, причинно-следственные связи, исторические факты, которые не восстанавливаются из текущих файлов. В обратном направлении сначала выяснить поддержанный механизм Claude Code; запись в транскрипт руками допустима только как явно названная экспериментальная гипотеза в отдельном каталоге клиента с проверкой формата. Потерянные reasoning/signature и служебные инструкции учитывать отдельно. Не вызывать команды и инструменты из импортированной истории повторно.
