# DK-1626: Полка ждущих повторяет машинный обход для каждого проекта

## Что происходит

waitshelf.go waitShelf последовательно вызывает projectWaits для шести проектов. Для каждого проекта через waitLookup вызывается waitScan. Один ответ повторно читает тот же машинный реестр, журнал уведомлений и окна tmux шесть раз. В прогретом стенде шесть waitScan заняли 74-81 мс из 80-85 мс всего обработчика. Холодные доски добавили ещё около 0,9 с последовательного чтения пяти соседних проектов. В HAR до лавины waiting отвечал за 251-1054 мс.

## Чего хотим

Машинная часть ожиданий собирается один раз на ответ waiting. Полка сохраняет проектные вопросы, парковки и вопросы без строки доски.

## Развилки

Открытых человеческих развилок нет. Пользователь 2026-11-06 поручил оформить все находки исследования тяжёлых ручек. Доступы и необратимые шаги от человека для реализации и проверки не требуются. Реализацию выбирает исполнитель в пределах описанного поведения.

## DoD

- Количество машинных waitScan и widgetWaits на ответ постоянно при увеличении числа проектов.
- Полка сохраняет порядок ожиданий, живые вопросы без строки и отбрасывает закрытые задачи и архивированные разговоры.
- Холодное чтение соседней доски не требует полей, не используемых полкой; выбранное поведение при ошибке одного проекта описано.
- Регрессия проверена regcheck на нескольких проектах; документация обновлена.
