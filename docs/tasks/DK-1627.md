# DK-1627: Одновременные запросы повторяют поиск проектов

## Что происходит

cache.go projects проверяет scanTTL под замком, но выполняет scanProjects вне него без общей записи обновления. После истечения пяти секунд несколько запросов независимо проверяют все worktree через git. На машине шесть проектов и 37 кандидатов. Один холодный проход запускает 37 процессов git и занимает 71-99 мс. Два одновременных прохода в отдельном стенде запустили 74 процесса git и заняли 159 мс. projects вызывается также из findProject и resources.

## Чего хотим

Читатели используют один обновляющийся список проектов. Одновременное истечение scanTTL не умножает обход каталогов и процессы git.

## Развилки

Открытых человеческих развилок нет. Пользователь 2026-11-06 поручил оформить все находки исследования тяжёлых ручек. Доступы и необратимые шаги от человека для реализации и проверки не требуются. Реализацию выбирает исполнитель в пределах описанного поведения.

## DoD

- Несколько одновременных запросов после истечения срока хранения в памяти запускают один обход кандидатов.
- Добавление и удаление проекта, смена корней и создание worktree обнаруживаются в установленный срок.
- Сохранены ошибки обхода и последнее подтверждённое состояние при отказе git. Паника не оставляет вечного ожидания.
- Счётчик обходов проверен regcheck; поведение памяти описано в README.

## Приёмка

- вид: agent
- Результат проверяется на синтетических данных автоматическими проверками. Данные настоящих разговоров и решения пользователя при проверке не меняются.

## Сценарий проверки

1. Создать несколько основных проектов и боковых деревьев.
2. Одновременно вызвать projects из нескольких запросов на пустой и просроченной памяти; посчитать git и обходы.
3. Изменить набор проектов и проверить новый список, затем отказ git и повторный успешный обход.
