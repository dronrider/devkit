# DK-1630: Смена экрана оставляет ненужные запросы и подпроцессы

## Что происходит

Браузерная функция api не принимает AbortSignal. Переход между экранами не отменяет прежние fetch. Серверный runProcEnv создаёт timeout от context.Background на 30 с, taskctlDo не принимает контекст HTTP. Работа по закрытому экрану может продолжаться и конкурировать с работой нового экрана. HAR подтверждает большие очереди, но объём работы после конкретного ухода не измерен. Ошибки ERR_CERT_VERIFIER_CHANGED не считать отменами экрана.

## Чего хотим

Ненужная работа прекращается после ухода с экрана и обрыва клиента. Общий расчёт сохраняется, пока его ждут другие читатели.

## Развилки

Открытых человеческих развилок нет. Пользователь 2026-11-06 поручил оформить все находки исследования тяжёлых ручек. Доступы и необратимые шаги от человека для реализации и проверки не требуются. Реализацию выбирает исполнитель в пределах описанного поведения.

## DoD

- Запросы ушедшего экрана отменяются, поздний ответ не перерисовывает новый экран.
- Отмена последнего читателя останавливает относящийся только к нему подпроцесс чтения в ограниченное время.
- Общий расчёт не отменяется при отмене одного из оставшихся читателей; запись решений и подтверждения защищена от неоднозначного повтора.
- Синтетический медленный подпроцесс и смена экрана проверяются regcheck. Область применения отмены описана в README.
