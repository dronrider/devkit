# DK-1646: Журнал обновления квот публикуется частично

## Что происходит

8 ноября штатные слияния DK-1570 и DK-1564 остановились на проверке полноты журнала quota-refresh. В test_journal_entry_never_seen_half_written прочитана строка `---\n` без конечного «код возврата». Хук и тест в обеих ветках совпадают с main. Повторные зеленые запуски причину отказа не устраняют.

Для воспроизведения достаточно запустить исходный хук с подставными agentctl, tmux и claude и задержать писателя после первой строки. Ожидается, что читатель увидит только полную запись. Сейчас сначала появляется отбивка, а тело записи дописывается позже.

Причина подтверждена на системном Bash 3.2. Один printf с готовой короткой записью вызывает несколько write, первый из них пишет четыре байта `---\n`. Пауза после этого write воспроизвела исходный отказ за один адресный прогон. В тесте полноты awaited не используется. Разбор и синтетическая трасса сохранены в /private/tmp/DK1564-quota-log-diagnosis.md и /private/tmp/DK1564-quota-log-trace/.

## Чего хотим

Читатель quota-refresh.log получает предыдущий полный журнал или следующий полный журнал. Новая запись готовится вместе с прежними записями в соседнем временном файле под существующим замком quota-refresh. Обрезка выполняется до атомарной замены журнала через os.replace. Размер истории остается ограниченным прежними настройками.

При отказе подготовки, обрезки или замены прежний журнал сохраняется. В quota-refresh.error рядом с журналом сохраняется короткое название этапа отказа без содержимого refresh. После успешной записи этот след очищается. При недоступном для записи каталоге сохранение отдельного файла ошибки также невозможно; прежний журнал в этом случае не изменяется.

## Границы

Правка касается записи журнала в hooks/quota-refresh.sh, его тестов и описания в hooks/README.md. Правила выбора харнеса, подписки, настройки окружения и сам съем квоты остаются за пределами задачи. Все проверки используют подставные команды и временный HOME.

## DoD

- При задержке между частями записи каждый непустой снимок опубликованного журнала содержит завершенные записи с конечным «код возврата». Утверждение исходного теста о полноте каждого прочитанного снимка сохраняется.
- Пока готовится второй запуск, читатель видит прежнюю полную запись. После замены видны обе записи; последовательные допущенные писатели не теряют историю друг друга. Запуск при занятом замке по-прежнему не начинает второй съем.
- Ограничение роста применяется до публикации. Читателю недоступен промежуточный необрезанный файл; прежние значения предела и числа строк сохраняются.
- Отказ записи или замены оставляет прежний журнал целым и явный след ошибки. Временные файлы этого запуска убираются до снятия замка; чужие файлы не удаляются. Замок освобождается, последующий успешный запуск возможен.
- Проверка установленного хука воспроизводит задержку писателя на фактическом пути /Users/rider/projects/devkit/hooks/quota-refresh.sh вместе с вызываемым им /Users/rider/projects/devkit/hooks/quota_journal.py. Настоящий съем квоты и сетевые обращения при этом не выполняются.
