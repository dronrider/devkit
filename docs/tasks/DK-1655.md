# DK-1655: Реплика нового чата задачи уходит в старый разговор

## Что происходит

Живой случай вечера 2026-11-08, машина с дашбордом, задача DK-1570. Факты
ниже проверены по журналам демона и сессий.

Как воспроизвести. У задачи есть разговор и живая сессия-носитель, строка
стоит в ожидании. На экране чатов заводится новый чат с этой задачей, в
форме выбраны задача и модель. Дашборд отвечает «чат заведён: сессию
поднимется первой репликой». Дальше в панель заготовки пишется первая
реплика и отправляется.

Ожидался подъём сессии, реплика и ответ в ленте нового чата. Вышло
иначе. Реплика уехала во вход разговора задачи и досталась прежнему
носителю, старому чату. Заготовка осталась пустой, поле grown у записи
не появилось. Отправка со стороны выглядит потерянной, ответ лёг в ленту
старого чата.

Корень в развилке chatWay файла static/app.js. Дорога задачи
(chatWaitsTask) стоит раньше ветки подъёма «new». Условие дороги смотрит
на живость входа самой панели, а у заготовки входа нет никогда. Любая
ждущая строка задачи уводит первую реплику ручкой /tasks/<ID>/message во
вход task-<ID>.in. Хозяина входа назначает носитель разговора. Панель, из
которой писали, на выбор не влияет. Обещание «сессию поднимет первая
реплика» молча нарушается.

Следы случая. dashboard.log, 20:53 «заведён чат blank-141c9a8b, задача
DK-1570», 20:55 «реплика задаче DK-1570 легла в чат task-DK-1570». Журнал
~/.devkit/chat-in.log, доставка старой сессии 20:58. Ответ стоит в её
транскрипте 20:59.

## Чего хотим

Первая реплика из незачатого чата с задачей поднимает сессию этого чата,
как обещает заведение. Реплика и ответ идут в ленте заготовки, запись
получает поле grown.

Дорога задачи остаётся себе для панелей без свежей заготовки. Строка
ждёт, разговор у записи не заводился, ответ уходит безадресной строкой во
вход.

Если какая-то дорога перебивает подъём, панель говорит об этом словами до
отправки. Молчаливых развилок у поля ввода не остаётся.

## Границы

Отметки доставки, индикаторы и видимость работы в ленте чинит DK-1615,
эта задача доставку не трогает. Мёртвые заготовки, зависшие в списке
после случая, убираются руками. Условий, посильных только человеку, у
задачи нет.

## Сценарий проверки

Свежее дерево, временный HOME, дашборд на синтетической доске. Браузерные
шаги идут порядком существующих тестов tools/dashboard
(chat_choice_browser.mjs и соседние).

1. Строка задачи стоит с вопросом, у записи есть разговор с мёртвой
   сессией-носителем.
2. Завести чат с этой задачей ручкой заведения. Ответ содержит «сессию
   поднимет первая реплика».
3. Браузером открыть панель заготовки, ввести реплику и отправить.
4. У записи заготовки появилось поле grown, файл
   .devkit/chat/task-<ID>.in пуст, реплика видна в ленте заготовки.

До правки шаг 4 красный. Поля grown нет, реплика лежит во входе задачи.
