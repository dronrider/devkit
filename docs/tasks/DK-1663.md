# DK-1663: Развилка с переносом вопроса держит старт задачи

## Что происходит

У DK-1650 две развилки из четырёх записаны вопросом с переносом. Первая
строка головы кончается словами «...строки без», продолжение «распакованного
дерева?» лежит ниже с отступом. shipctl start завершается ошибкой
и печатает эти развилки как человеческие, хотя под вопросом в файле стоит
«решает: исполнитель». taskctl decide --leave отчитывается «оставлена
исполнителю», а перечень вслед за этим печатает «открыта, держит старт»
без перемены.

Разбор блока развилки обрывается на продолжении вопроса. Цикл ParseForks в
internal/taskform/forks.go после головы ждёт подстроки с маркером.
Прозаическое продолжение не имеет маркера, и чтение стопится. Подстроки
«решает» и «рекомендация» под продолжением не читаются вовсе, поле Who
остаётся дефолтным «человек». HoldingForks держит старт, а с ним закрытие:
ворота читают один разбор. Соседние две развилки той же записи попали
вопросом в одну строку и распознались верно.

Письмо в такой блок тоже ломается. AppendToFork ставит след сразу после
первой строки головы и режет вопрос пополам. decideSetWho находит поле
«решает» ниже разрыва и переписывает его в то же значение, наверх ничего не
поднимая. Руками голову не поправить, её сторожит рубеж машинных строк.
Утилиты смены вопроса у развилки нет.

## Чего хотим

Разбор блока развилки понимает продолжение с отступом как продолжение
вопроса и читает подстроки под ним. Ворота старта и закрытия берут Who из
поля. AppendToFork и decideSetWho вставляют свои строки после целого блока
и не трогают прозу вопроса.

## DoD

На файле с двухстрочным вопросом развилки HoldingForks возвращает поле
«решает» из подстроки. decide --leave дописывает след после блока без
разрыва вопроса. Повторный shipctl start проходит. Тест падает на старом
коде и проходит на исправленном (regcheck).

## Ранг

`25+6+1+5+2 = 39`, P2.

- Серьёзность 25: задача с такой развилкой не стартует и не закрывается,
  обход руками запрещён сторожем машинных строк, утилиты смены вопроса нет.
- Ценность 6: живой прецедент DK-1650 стоит без движения, форма допускает
  перенос прозой и не отвергает его на записи.
- Неопределённость 1: разбор локализован в трёх функциях одного файла,
  подход записан.
- Поправка на баг 5: ворота держат старт там, где постановка оставила
  развилку исполнителю.
- Рычаг 2: снятый блок открывает работу с развилками, записанными
  переносом.

## Сценарий проверки

Вид агентский. Запись DK-9901 для обкатки заводит сам шаг в свежем дереве,
доска не трогается. Первый шаг воспроизводит ситуацию DK-1650 и пишет блок
развилок вида:

```markdown
- «источники»: откуда отбор читает метки готовности строки без
  распакованного дерева?
  - рекомендация: из двух источников: распакованный файл и git show
    ветки, иначе кандидат без дерева молча выглядит неготовым
  - решает: исполнитель
- «метки»: какие проверки едут в отбор кандидатов без
  живого дерева?
  - рекомендация: файл задачи и открытые замечания
```

У первой развилки вопрос перенесён на вторую строку, поле «решает» стоит
под переносом. У соседней вопрос тоже перенесён, поля нет. После правки
первая названа оставленной исполнителю, соседняя, как раньше, держит старт.

```sh
printf '# DK-9901: запись обкатки разбора развилок\n\n## Развилки\n\n- «источники»: откуда отбор читает метки готовности строки без\n  распакованного дерева?\n  - рекомендация: из двух источников: распакованный файл и git show\n    ветки, иначе кандидат без дерева молча выглядит неготовым\n  - решает: исполнитель\n- «метки»: какие проверки едут в отбор кандидатов без\n  живого дерева?\n  - рекомендация: файл задачи и открытые замечания\n' > docs/tasks/DK-9901.md
taskctl decide DK-9901
taskctl decide DK-9901 | grep -q '«источники» (оставлена исполнителю): откуда отбор читает метки готовности строки без распакованного дерева?'
taskctl decide DK-9901 | grep -q '«метки» (открыта, держит старт)'
```

Второй шаг передаёт исполнителю развилку без поля «решает». Поле встаёт
