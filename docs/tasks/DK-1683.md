# DK-1683: Guardian cloud-start не паркуется при пропаже бинар tmux

## Что происходит

Тест MissingTmux в tools/dashboard/cloudstart_test.go (строка 362) стабильно красный на main. Тест подменяет tmux пустой заглушкой, поднимает резерв guardian, удаляет бинар и ждёт парковки «unknown;». Guardian остаётся в цикле ожидания ack со state «terminal-created; awaiting-ack». Обе пробы по исчезнувшему бинару падают с «no such file», а выход из цикла разобран только для «no server running» (tools/dashboard/cloudstart.go, строки 101-107). Консервативный разбор проб приехал правкой DK-1582 от 03.11, до неё тест выходил из цикла по первой неудачной пробе.

Краснота держит слияния всей доски. Ворота merge гоняют компоненты в свежем дереве и останавливаются по первому провалу. С 03.11 компонент go:dashboard в свежих деревьях не прогонялся, ближайшие слияния были бескодовыми или падали раньше по devkitctl, и первым до него дошёл merge DK-1655 10.11.

## Чего хотим

Guardian выходит из цикла ожидания ack и паркуется «unknown;» тем же порядком, каким выходит при отсутствующем сервере. Неопытная проба по исчезнувшему бинару перестаёт держать цикл. Тест зелёный на main.

## DoD

Тест зелёный на main. Регчек подтверждает красноту на коде до правки и зелёный после неё. Слияние с правкой проходит компонент go:dashboard целиком, очередь слияний двигается.
