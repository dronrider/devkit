# DK-1689: два прогона переносимого ревью

## Результат

Выполнены ровно два тестовых прогона gpt-6.1-sol, medium. Повторов,
субагентов и модельного судьи не было. Оба ревьювера получили одинаковые
код, общие и проектные правила, а также один нейтральный промпт.
Отличался только REQUEST.md. Ожидаемые ответы им не передавались;
рабочий проект и его код в эти прогоны не входили.

| Проверка | Только цель | Цель и вариант реализации |
|---|---|---|
| Публичное locale недоступно без правки кода | Найдено | Найдено |
| Ненужные counters ломают отчёт только с профилем | Найдено | Найдено |
| Обязательный type с единственным значением | Назван избыточным, блокирует | Признан проверкой контракта получателя |
| Обоснованные ограничения и контрольные решения | Сохранены | Сохранены |
| Аудит правил | 57 строк, архитектура violated | 57 строк, архитектура violated |

Оба дополнительно обнаружили коллизию числового и строкового имени при
сериализации JSON, а также нечувствительность авторского check.py
к отключению валидации. По коду и воспроизведениям эти находки подтверждены.
Тестируемый код не изменён. Чистый вердикт для дефектного проекта
не выставлялся; audit-check отказал на violated.

## Что показывает различие по type

Первый ревьювер показывает, что type повторяет сведения SOURCES
и не проверяет фактическое значение. Второй явно рассматривает поле,
но оправдывает его согласованностью с контрактом получателя. Он отмечает,
что типизированное описание является вариантом решения, а не обоснованием
любого ограничения.

Требование строкового и числового JSON само по себе не устанавливает
необходимость обязательного поля type в описании. Его польза как проверки
ожидаемого контракта возможна, но отдельное требование на такую декларацию
в этом проекте не установлено. Поэтому здесь зафиксированы рассуждения
и разные оценки, а не единый доказанный вердикт о необходимости поля.
Само различие выводов не доказывает ошибку второго ревьювера.
Этот вопрос нельзя засчитать как автоматически найденный дефект либо
как полностью обоснованное отсутствие проблемы. Полного зачёта всей
архитектурной проверки по этой паре не объявляем.
