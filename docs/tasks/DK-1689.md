# DK-1689: Ревью проверяет обоснование решения независимо от его описания

## Что происходит

При разборе реального примера ревью сначала замечает избыточность конфигурации, затем снимает архитектурный вопрос из-за упоминания механизма в постановке. Соответствие выбранному способу подменяет проверку необходимости этого способа. Существующие сценарии не сравнивают одинаковый код с разной формулировкой постановки.

## Чего хотим

Подключённый к разным проектам review отличает цель пользователя, обязательный внешний контракт и предложенный способ реализации. Для настройки прослеживаются независимый выбор, доступные данные, потребитель и необходимые загрузки. Реальный проект используется для выявления класса ошибок; его код и данные в devkit не копируются.

## Границы

Скилл review и его справочники, переносимые учебные проекты и сценарии obeycheck. Без изменения кода рабочего проекта и схемы аудита. После подготовки примера пользователь отдельно разрешил два тестовых прогона на gpt-6.1-sol без повторов и модельного судьи. Машинная полнота отчёта не объявляется доказательством правильности архитектуры.

Пользователь уточнил предмет работы: улучшать devkit для разных проектов. Новые модельные прогоны требуют отдельного согласования после подготовки проверяемого результата.
