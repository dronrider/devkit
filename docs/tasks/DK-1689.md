# DK-1689: Ревью проверяет обоснование решения независимо от его описания

## Что происходит

При разборе реального примера ревью сначала замечает избыточность конфигурации, затем снимает архитектурный вопрос из-за упоминания механизма в постановке. Соответствие выбранному способу подменяет проверку необходимости этого способа. Существующие сценарии не сравнивают одинаковый код с разной формулировкой постановки.

## Чего хотим

Подключённый к разным проектам review отличает цель пользователя, обязательный внешний контракт и предложенный способ реализации. Для настройки прослеживаются независимый выбор, доступные данные, потребитель и необходимые загрузки. Реальный проект используется для выявления класса ошибок; его код и данные в devkit не копируются.

## Границы

Скилл review и его справочники, переносимые учебные проекты и сценарии obeycheck. Без изменения кода рабочего проекта и схемы аудита. После подготовки примера пользователь отдельно разрешил два тестовых прогона на gpt-6.1-sol без повторов и модельного судьи. Машинная полнота отчёта не объявляется доказательством правильности архитектуры.

## Развилки

Пользователь уточнил предмет работы: улучшать devkit для разных проектов. Новые модельные прогоны требуют отдельного согласования после подготовки проверяемого результата.

## DoD

- Процедура проверяет обоснованность способа реализации даже при его упоминании в постановке; обязательный контракт учитывается явно.
- Есть один обезличенный проект и два варианта постановки с одинаковым кодом. Ожидаемые ответы проверяют переносимость проверки, избыточные настройки и ненужные загрузки, а также допустимые ограничения.
- Локальные проверки подтверждают фактические дефекты примера и корректность контрпримеров; ответы не попадают во вход ревьювера.
- Документация различает проверку учебного проекта и проверку поведения агента. Улучшение поведения без отдельного прогона не заявляется.

## Ранг

`50+7+2+5+4 = 68`, P1.

- Серьёзность 50: архитектурное ревью подменяется соответствием описанию реализации.
- Ценность 7: общий путь ревью разных проектов.
- Неопределённость 2: известен сбой решения, эффект поправки требует поведенческой проверки.
- Поправка на баг 5: пропуск воспроизведён в текущем разборе.

Подготовить оба варианта во временных каталогах по командам самих сценариев.
Проверить check.py, хеши файлов и отсутствие ожидаемых ответов во входе.
Прочитать сохранённые результаты двух разрешённых запусков без новых вызовов.

```python
import hashlib
import json
import os
from pathlib import Path
import re
import subprocess
import sys
import tempfile

root = Path.cwd()
evidence = json.loads((root / "docs/tasks/DK-1689.local-evidence.json").read_text())
listing = subprocess.check_output(["obeycheck", "--list"], text=True)
prepared = []
for record in evidence["scenario_preparations"]:
    scenario = record["scenario"]
    assert scenario in listing, scenario
    source = (root / "tools/obeycheck/scenarios" / (scenario + ".md")).read_text()
    commands = re.search(r"## Подготовка\s+```sh\n(.*?)```", source, re.S).group(1)
    with tempfile.TemporaryDirectory(prefix="dk1689-check-") as directory:
        target = Path(directory)
        def run(*args):
            subprocess.run(args, cwd=target, check=True)
        run("git", "init", "-q")
        run("git", "config", "user.name", "Stand")
        run("git", "config", "user.email", "stand@example.invalid")
        (target / "tool.py").write_text("pass\n")
        run("git", "add", "tool.py")
        run("git", "-c", "core.hooksPath=/dev/null", "commit", "-qm", "seed")
        env = dict(os.environ, OBEY_DEVKIT=str(root), PYTHONDONTWRITEBYTECODE="1")
        subprocess.run(["sh", "-ec", commands], cwd=target, env=env, check=True)
        files = {str(path.relative_to(target)): hashlib.sha256(path.read_bytes()).hexdigest()
                 for path in target.rglob("*") if path.is_file() and ".git" not in path.parts}
        assert files == record["files"], (scenario, files)
        assert not any("oracle" in name or "witness" in name for name in files)
        run(sys.executable, "check.py")
        prepared.append(files)
assert {name for name in prepared[0] if prepared[0][name] != prepared[1][name]} == {"REQUEST.md"}
results = json.loads((root / "docs/tasks/DK-1689.behavior-results.json").read_text())
assert results["model_runs"] == 2 and results["judge_model"] is None
assert results["only_project_input_difference"] == ["REQUEST.md"]
for result in results["runs"]:
    json.loads((root / "docs/tasks" / result["evidence"]).read_text())
    assert (root / "docs/tasks" / result["event_log"]).stat().st_size > 0
    assessment = result["assessment"]
    assert assessment["public_field_scope_defect_detected"]
    assert assessment["unused_load_defect_detected"]
    assert assessment["control_false_positives"] == []
    assert assessment["all_rule_rows"] == 57
    print(result["scenario"], assessment["type_result"], assessment["type_reason"])
assert {result["assessment"]["type_result"] for result in results["runs"]} == {"violated", "checked"}
print((root / "docs/tasks/DK-1689.behavior-results.md").read_text())
```
