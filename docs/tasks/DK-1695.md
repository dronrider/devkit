# DK-1695: В чате дашборда доступен Codex с переносом разговора

## Что происходит

В дашборде можно менять модель и подписку в одном разговоре. Для существующих клиентов переносится история Claude Code. Работа с Codex через app-server к этому пути не подключена. Профиль разовых поручений Codex существует, но продолжить в нём тот же чат дашборда нельзя.

В DK-1624 проверен перенос Claude -> Codex -> Claude на синтетической истории. Прямой импорт через app-server работает и переживает перезапуск, но повторный импорт создаёт дубли. Импортированные элементы доступны модели и отсутствуют в ленте API Codex. Обратное потоковое воспроизведение теряет отдельные факты инструментов. Проверенная альтернатива использует внутренний журнал Claude и обычный resume; она зависит от версии клиента. Код и отчёт прототипа сохранены в ветке dk-1624, слияние ещё не завершено.

Пользователь 2026-11-11 поручил запустить основную реализацию через taskhead на glm-code-2.

## Чего хотим

Выбирать Codex в существующем чате дашборда, работать через подписку ChatGPT и переключаться обратно к профилю Claude Code. Сообщения, аргументы инструментов и их результаты должны оставаться в доступной истории одного разговора.

## Границы

Существующие рабочие чаты и подписки сохраняются. Используется штатный вход Codex; новый API-ключ не нужен. Полное скрытое состояние моделей, reasoning и служебные инструкции разных клиентов не считаются переносимой историей.

Работа касается профиля Codex, адаптера app-server, отображения событий и переходов между клиентами. Перестройка всей доски и внедрение других провайдеров не входят в предмет. Перед переносом существующей истории нужен обратимый путь и отказ без повреждения исходного чата. Формат внутреннего журнала проверяется по установленной версии клиента; несовместимость показывается пользователю.

## DoD

1. Codex доступен в существующем выборе профиля и модели чата. Запуск идёт через app-server и действующую подписку ChatGPT. Отсутствие клиента или входа объясняется в интерфейсе.
2. Из интерфейса можно отправить запрос, увидеть поток ответа, вызовы инструментов, результаты и завершение. Ошибка процесса, отказ сервера и отмена не оставляют чат в вечном ожидании. Подтверждения опасных действий следуют действующей политике доступа.
3. Переход Claude -> Codex -> Claude сохраняет один разговор, роли, видимый текст, аргументы и результаты инструментов. На принимающей стороне подтверждаются независимые факты из истории, отсутствующие в последнем вопросе и текущих файлах.
4. Дашборд сохраняет доступную пользователю историю независимо от полноты ленты Codex. Повторное переключение, отправка и восстановление процесса не дублируют сообщения и импортированные элементы. Старые вызовы инструментов не исполняются повторно.
5. После перезапуска повторный вход в чат открывает тот же разговор. Связь логического чата с сеансами клиентов хранится явно; пользовательская история не привязана к одному провайдеру.
6. Ошибочный или несовместимый перенос не повреждает исходную историю. Потери и ограничения видны пользователю; скрытой замены истории кратким пересказом нет.
7. Основные пути покрыты автономными проверками на подменённых клиентах. Живой прогон на отдельном синтетическом проекте подтверждает полный переход в обе стороны, работу команды и правки файла без повторного исполнения старых действий.
8. Подключение и обновление профиля выполняются штатной автоматикой devkit. README содержит первый запуск и действующие ограничения. После выката Codex доступен в чате на рабочей машине.

## Ранг

`25+7+3+0+4 = 39`, P2.

- Серьёзность 25: нужная пользователю подписка недоступна в существующем чате; обход требует отдельного клиента.
- Ценность 7: позволяет работать с Codex и текущими подписками в одном разговоре.
- Неопределённость 3: перенос проверен прототипом, но транспорт, восстановление и отображение ещё нужно встроить в рабочий чат.
- Поправка на баг 0: добавляется новая возможность.
- Рычаг 4: адаптер и явная связь сеансов позволят подключать клиентов с разными протоколами истории.

## Приёмка

- вид: agent
- Проверки выполняются на синтетической истории в отдельном проекте. Есть действующий вход клиента. Прогон интерфейса, отмены и восстановления проверяется автоматизированно; отдельного согласования нового дизайна не требуется.

## Сценарий проверки

1. После выката выбрать Codex в новом синтетическом чате и получить поток ответа. Выполнить команду и правку файла в тестовом проекте, проверить отображение результата.
2. Передать историю Claude -> Codex -> Claude и спросить независимые факты из старого текста, аргументов и длинного результата инструмента. Значений нет в последнем вопросе и файлах получателя.
3. Повторить переключение, отменить запрос и восстановить процесс. Проверить единую ленту, отсутствие дублей и повторного исполнения старых команд.
4. Подставить недоступный app-server и несовместимый журнал. Проверить видимую причину отказа и сохранность исходной истории. Исполнитель добавляет исполнимые команды и ожидаемые результаты до обкатки.

## Вход исполнителю

Работа запускается одним taskhead на glm-code-2 по прямому поручению пользователя. Предпосылка DK-1624 ещё находится на слиянии. Сначала довести её штатную обкатку, слияние и отдельную приёмку, используя существующую ветку и результаты. Затем реализовать эту задачу в собственном дереве. Не повторять исследование прототипа целиком. Блокеры очереди проверять штатными командами; тесты, хуки и очередь не обходить, чужие задачи не откатывать.

Выбор исполнителей делать в контуре glm-code-2. Основной код делегировать через действующий профиль этой подписки, ревью и отдельную приёмку провести по правилам проекта. Не менять глобальную подписку по умолчанию. Перед началом проверить актуальный клиент и его локальную схему app-server; прототип относится к Codex 0.163.0 и Claude Code 2.1.312.

Сначала изучить текущие harnesses.go, chatlift.go, перенос и хранение истории в tools/dashboard и профиль kit/harness/codex.toml. Сохранить штатный выбор профилей и текущие ограничения доступа. Живые вызовы моделей использовать для проверки границ протокола и итоговой приёмки; основную отладку вести на автономных подменах. Секреты и закрытые чаты не читать, действующий вход использовать только через штатный клиент.
