# DK-1695: В дашборде работает профиль Codex

## Что происходит

В дашборде нет рабочего профиля Codex для обычного чата. Пользователь хочет подключить его через подписку ChatGPT. В DK-1624 уже проверены основные возможности протокола, но дальнейшая доводка прототипа не нужна для подключения профиля.

Пользователь 2026-11-11 уточнил приоритет: «Прототип задрачивать не стоит. Нужно завершить подключение профиля, а всё остальное потом».

## Чего хотим

Выбрать профиль Codex в дашборде, открыть его чат и работать с ним через действующую подписку. Довести этот путь до рабочей машины пользователя.

## Границы

Первый рабочий профиль использует app-server и штатный вход Codex. Текущие профили и рабочие чаты сохраняются. Смена клиента с переносом старой истории отложена; при неподдерживаемом переходе исходный разговор сохраняется, а ограничение видно до продолжения.

Закрытие, повторная обкатка и слияние DK-1624 не являются предпосылкой. Не запускать её taskhead и не расходовать подписку на повторное исследование. Из прототипа можно использовать уже известные результаты по мере надобности.

## DoD

1. Профиль Codex доступен в штатном выборе профилей и моделей дашборда. Для нового чата используется app-server и действующий вход через подписку ChatGPT.
2. Пользователь отправляет запрос, получает поток ответа, видит вызовы инструментов, их результаты и завершение. Codex может выполнить команду и изменить файл в отдельном тестовом проекте согласно действующей политике доступа.
3. Отмена, завершение и ошибка процесса не оставляют чат в вечном ожидании. При отсутствии клиента или входа видна конкретная причина.
4. Текущие профили и существующие чаты продолжают работать. Неподдерживаемый перенос истории не приводит к её потере или скрытому началу пустого разговора.
5. Есть необходимые автономные проверки адаптера и один ограниченный живой прогон рабочего профиля на синтетическом проекте. README описывает первый запуск. Подключение раскладывается штатной автоматикой, профиль проверен после выката на рабочей машине.

## Сценарий проверки

Живой прогон идёт на рабочем дашборде машины с включённым профилем Codex
(раздел «Первый запуск Codex» в README дашборда) и установленным клиентом
`codex` со штатным входом. Синтетический проект создаётся во временном
каталоге под первым корнем дашборда и убирается последним шагом. Временный
дом нужен только стенду недоступного клиента, живым шагам он не нужен.
Шаги идут подряд в одном шелле, окружение задано переменными первого блока.

1. Вход в дашборд и синтетический проект.

```sh
set -eu
DASH=http://127.0.0.1:7112
WORK=$(mktemp -d)
TOKEN=$(awk -F' = ' '/^token/{print $2}' "$HOME/.devkit/dashboard.local")
curl -sS -c "$WORK/cookies" -X POST "$DASH/api/login" -d "{\"token\":\"$TOKEN\"}"
ROOT=$(grep '^root' "$HOME/.devkit/dashboard.local" | head -1 | cut -d= -f2 | tr -d ' ' | sed "s|^~|$HOME|")
SYN=$(mktemp -d "$ROOT/dk1695-check.XXXXXX")
mkdir -p "$SYN/docs/tasks"
printf '# XR-169500\n\nСинтетическая задача проверки профиля Codex.\n' > "$SYN/docs/tasks/XR-169500.md"
printf '# Доска\n\n- [ ] XR-169500 синтетическая задача\n' > "$SYN/docs/TASKS.md"
P=$(basename "$SYN")
```

Вход отвечает `{"ok":true}`, синтетический проект создан в корне дашборда.

2. Проект и подписка видны серверу.

```sh
curl -sS -b "$WORK/cookies" "$DASH/api/projects" | grep -q "\"$P\""
curl -sS -b "$WORK/cookies" "$DASH/api/harnesses" > "$WORK/harnesses.json"
MODEL=$(python3 -c "
import json
hs = json.load(open('$WORK/harnesses.json'))['harnesses']
h = [x for x in hs if x.get('protocol') == 'codex'][0]
ms = h.get('models') or []
m = [x for x in ms if x['tier'] == 'base'] or ms
print(m[0]['model'])")
test -n "$MODEL"
```

Синтетический проект назван в списке, подписка codex пришла с ключом
protocol и лестницей моделей, `MODEL` это её ступень base.

3. Первый чат Codex и ответ в ленте.

```sh
SID=$(curl -sS -b "$WORK/cookies" -X POST "$DASH/api/projects/$P/chats" \
  -d "{\"id\":\"XR-169500\",\"text\":\"Ответь одним словом, работает ли ты.\",\"model\":\"$MODEL\",\"harness\":\"codex\"}" \
  | python3 -c "import json,sys; d=json.load(sys.stdin); assert d.get('way')=='appserver', d; print(d['session'])")
test "$(printf '%s' "$SID" | cut -c1-2)" = "as"
for i in $(seq 1 60); do
  FEED=$(curl -sS -b "$WORK/cookies" "$DASH/api/projects/$P/sessions/$SID")
  printf '%s' "$FEED" | grep -q '"role":"assistant"' && break
  sleep 3
done
printf '%s' "$FEED" | grep -q '"role":"assistant"'
```

Подъём отвечает `way=appserver` и адресом сессии на `as`, за три минуты в
ленте появляется ответ клиента.

4. Команда и правка файла в синтетическом проекте.

```sh
printf 'было\n' > "$SYN/marker.txt"
curl -sS -b "$WORK/cookies" -X POST "$DASH/api/projects/$P/chats/$SID/say" \
  -d '{"text":"Выполни команду ls и допиши её итог одной строкой в конец файла marker.txt в текущем каталоге, затем прочитай marker.txt и приведи его содержимое целиком.","msg_id":"m-cmd"}' > /dev/null
for i in $(seq 1 60); do
  ST=$(curl -sS -b "$WORK/cookies" "$DASH/api/projects/$P/chats/$SID/status")
  printf '%s' "$ST" | grep -q '"busy":false' && break
  sleep 3
done
printf '%s' "$ST" | grep -q '"busy":false'
FEED=$(curl -sS -b "$WORK/cookies" "$DASH/api/projects/$P/sessions/$SID")
printf '%s' "$FEED" | grep -q '"role":"tool"'
test "$(wc -l < "$SYN/marker.txt" | tr -d ' ')" -ge 2
```

Ход завершается за три минуты, в ленте стоит запись вызова команды, файл
marker.txt вырос строкой итога.

5. Отмена долгого запроса.

```sh
curl -sS -b "$WORK/cookies" -X POST "$DASH/api/projects/$P/chats/$SID/say" \
  -d '{"text":"Расскажи подробно об устройстве файловых систем, много абзацев подряд.","msg_id":"m-long"}' > /dev/null
sleep 2
STOP=$(curl -sS -b "$WORK/cookies" -X POST "$DASH/api/projects/$P/chats/$SID/stop" -d '{}')
printf '%s' "$STOP" | grep -q '"way":"stopped"\|"way":"killed"'
for i in $(seq 1 10); do
  ST=$(curl -sS -b "$WORK/cookies" "$DASH/api/projects/$P/chats/$SID/status")
  printf '%s' "$ST" | grep -q '"busy":false' && break
  sleep 1
done
printf '%s' "$ST" | grep -q '"busy":false'
```

Стоп отвечает `stopped` либо `killed`, за десять секунд ход перестаёт
идти, чат не остаётся в вечном ожидании.

6. Обычная работа профиля Claude.

```sh
NEW=$(curl -sS -b "$WORK/cookies" -X POST "$DASH/api/projects/$P/chats" \
  -d '{"id":"XR-169500","text":"Ответь одним словом, на связи ли ты."}')
printf '%s' "$NEW" | grep -q '"way":"new"'
for i in $(seq 1 30); do
  LIST=$(curl -sS -b "$WORK/cookies" "$DASH/api/projects/$P/chats?tmux=chat-XR-169500-1")
  CSID=$(printf '%s' "$LIST" | python3 -c "import json,sys; rows=json.load(sys.stdin)['chats']; print(rows[0]['id'] if rows else '')")
  test -n "$CSID" && break
  sleep 2
done
for i in $(seq 1 100); do
  FEED=$(curl -sS -b "$WORK/cookies" "$DASH/api/projects/$P/sessions/$CSID")
  printf '%s' "$FEED" | grep -q '"role":"assistant"' && break
  sleep 3
done
printf '%s' "$FEED" | grep -q '"role":"assistant"'
```

Подъём без пары модель/подписка идёт дорогой tmux и отвечает `way=new`.
Сессия `chat-XR-169500-1` появляется в списке чатов, ответ клиента приходит
в ленту за пять минут. Прежний путь живых чатов не сломан чужим профилем.

7. Ошибка недоступного клиента на изолированном стенде.

```sh
STAND=$(mktemp -d)
TREE=$HOME/projects/devkit-dk-1695
mkdir -p "$STAND/home/.devkit" "$STAND/root/proj/docs/tasks"
printf '# XR-169500\n\nСинтетическая задача стенда.\n' > "$STAND/root/proj/docs/tasks/XR-169500.md"
printf '# Доска\n' > "$STAND/root/proj/docs/TASKS.md"
printf '#!/bin/sh\necho "нет входа" >&2\nexit 1\n' > "$STAND/home/bin-client"
chmod +x "$STAND/home/bin-client"
printf 'enabled = ["codex"]\n\n[codex]\nbin = "%s/home/bin-client"\n' "$STAND" > "$STAND/home/.devkit/harness.local"
PORT=$(python3 -c "import socket; s=socket.socket(); s.bind(('127.0.0.1',0)); print(s.getsockname()[1]); s.close()")
printf 'root = %s/root\naddr = 127.0.0.1\nport = %s\ntoken = stand-token\n' "$STAND" "$PORT" > "$STAND/home/.devkit/dashboard.local"
chmod 600 "$STAND/home/.devkit/dashboard.local"
env -u DEVKIT_TASK HOME="$STAND/home" DEVKIT_DASH_HOME="$STAND/home" DEVKIT_HOME="$TREE" dashboard serve > "$WORK/stand.log" 2>&1 &
STANDPID=$!
for i in $(seq 1 30); do
  curl -sS "http://127.0.0.1:$PORT/healthz" > /dev/null 2>&1 && break
  sleep 1
done
curl -sS -c "$WORK/stand-cookies" -X POST "http://127.0.0.1:$PORT/api/login" -d '{"token":"stand-token"}'
SMODEL=$(curl -sS -b "$WORK/stand-cookies" "http://127.0.0.1:$PORT/api/harnesses" | python3 -c "
import json,sys
h = [x for x in json.load(sys.stdin)['harnesses'] if x.get('protocol') == 'codex'][0]
print((h.get('models') or [])[0]['model'])")
ERR=$(curl -sS -b "$WORK/stand-cookies" -X POST "http://127.0.0.1:$PORT/api/projects/proj/chats" \
  -d "{\"id\":\"XR-169500\",\"text\":\"Ответь одним словом.\",\"model\":\"$SMODEL\",\"harness\":\"codex\"}")
printf '%s' "$ERR" | grep -q 'нет входа'

```

Стенд поднимает свой дашборд на свободном порту с подпиской codex, чей
клиент это заглушка, падающая с причиной в stderr. Дашборд читает свой
конфиг по `HOME`, а подписки и клиентов поднимает под домом
`DEVKIT_DASH_HOME`. Без ключа дом берётся от uid машины, и стенд увидел бы
настоящий `~/.devkit/harness.local`. Профиль codex с лестницей моделей
agentctl берёт из `TREE`, дерева ветки. Стенд поднимается бинарями этой
ветки из `PATH`. `DEVKIT_TASK` снимается. Сессия проверки несёт свою задачу,
и exec не прошёл бы её сторож записи до заглушки. Конфиг стенда получает
права 600 явно. При umask 022 служба не стартует с более широкими правами.
Реплика отвечает 502 со словами причины заглушки вместо ожидания без
ответа.

Прогон 2026-11-12 шёл живьём на собранных из ветки бинарях, umask 022.
Конфиг стенда получил права 644, служба поднялась после явного chmod 600.
Вход ответил `{"ok":true}`. Ручка подписок показала codex с заглушкой стенда
в качестве bin и лестницей моделей из дерева ветки, выборка дала gpt-6-luna.
Реплика чата ответила HTTP 502, в теле отказа стоят слова заглушки.

```sh

SMODEL=gpt-6-luna
{"error":"чат не поднялся: клиент не поднялся: процесс умер, не ответив на initialize: поток вывода закрылся: EOF; exec: харнес codex, команда /.../home/bin-client, каталог /.../root/proj
нет входа (...)"}
HTTP 502
```

Каталоги подъёма и журналы легли в дом стенда, настоящий `~/.devkit` машины
остался нетронутым.
