# DK-1700: Тест хука пуша красный после контракта аудита ревью

## Что происходит

Ворота слияния прогоняют стенд hooks, и с 10 ноября он красный. В свежем
дереве main падает test_mixed_range_with_legit_id_passes. Воспроизвожу
командой `devkitctl test hooks pre_push_test.TestBoardGateWithShipctl -v`,
вывод даёт failures=1 и отказ `returncode 1 != 0`. Ожидался зелёный класс.
Вышло: тест вешает на HEAD заметку «Уровень 1 до ...», а после DK-1675
(70c8c4a39) калитка ждёт в заметке строку «Ярлык:» и готовый отчёт аудита по
ярлыку. `shipctl push --check-only` отказывает, хук возвращает 1. Краснота
держит ворота слияния у всех задач доски: выкат DK-1689 стоит восемнадцать
часов, слияние DK-1695 отказало два раза.

## Чего хотим

Стенд hooks снова зелёный на main. Предмет теста прежний, код-коммит с ID
задачи не из Backlog проходит вместе с доской в одном диапазоне. Судить его
будем первым пушем ветки задачи в автономном режиме с origin. Калитка там
зовёт разбор диапазона от origin/main, и смешанный диапазон разбирается тем
же rangeVerdict. Заметка с аудитом остаётся предметом go-стенда
tools/shipctl, этот контракт уже покрыт тестами TestPushAudit* из DK-1675.

## Границы

- Контракты калитки и аудита не меняются, правка лежит только в тесте.
- Заметочный стек аудита в python-стенд не тащится. Хук запускает в PATH один
  shipctl, аудита без taskctl не собрать, а повторять разбор reviewaudit на
  python было бы вторым экземпляром контракта.

## DoD

В свежем дереве main прогон класса TestBoardGateWithShipctl зелёный.
Очередной shipctl merge доезжает до своих ворот, не спотыкаясь о красный
стенд.

## Ранг

`50+5+0+5+4 = 64`, P1.

- Серьёзность 50: красный стенд держит ворота слияния. Ни одна задача доски
  не сливается, выкат стоит.
- Ценность 5: слияния возвращаются, польза видна каждой задаче доски.
- Неопределённость 0: причина найдена воспроизведением, фикс написан и
  проверен прогоном класса во временном дереве.
- Поправка на баг 5: регрессия от DK-1675 подтверждена живым прогоном.
- Рычаг 4: зелёный стенд это живой цикл разработки, каждая следующая задача
  проходит слияние дешевле.
