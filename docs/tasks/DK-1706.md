# DK-1706: В дашборде виден остаток квоты Codex

## Что происходит

13 ноября 2026 пользователь заметил, что у работающего профиля Codex в дашборде нет остатка подписки. В kit/harness/codex.toml раздел quota пуст. Протокол установленного Codex 0.163.0 поддерживает account/rateLimits/read и account/rateLimits/updated. Доступны usedPercent, windowDurationMins и resetsAt для окон лимита.

## Чего хотим

У Codex в общем индикаторе подписок видны остаток и время сброса для доступных окон, включая недельное. Данные обновляются существующим сборщиком, в том числе без активного чата. Источник использует штатный app-server и существующий вход через ChatGPT.

## Границы

Задача касается квоты профиля Codex. Перенос истории между харнесами и расширение прототипа остаются вне этой работы. Не запускать модельные ходы ради чтения квоты, не выводить токены или данные учётной записи. Основной чекаут содержит чужие неотслеживаемые файлы; коммитить только явно перечисленные файлы этой задачи.

## DoD

- После штатного обновления снимка Codex отображается общим индикатором квот с фактическим остатком и временем сброса каждого поддерживаемого окна.
- Запрос работает без активного чата. Сборщик ограничивает время ожидания и завершает созданный процесс app-server.
- Недоступный клиент, отсутствие входа и неполный ответ дают диагностируемое состояние без выдуманного нулевого или полного остатка.
- Изолированные проверки покрывают разбор окон, выбор нужного лимита из нескольких бакетов и отказ источника; живой запрос подтверждает работу без модельного хода.

## Ранг

`25+4+1+0+1 = 31`, P2.

- Серьёзность 25: остаток одного профиля не виден, для обхода можно проверить его в клиенте Codex.
- Ценность 4: при выборе Codex пользователь видит доступную квоту рядом с остальными подписками.
- Неопределённость 1: источник подтверждён протоколом, остаётся связать его с общим форматом.
- Поправка на баг 0: добавляется отсутствующий источник квоты.
- Рычаг 1: общий снимок становится доступен существующим потребителям квоты.
