# DK-1711: Груминг на Sol завершается до первого хода

## Что происходит

14 ноября пользователь выбрал Sol кнопкой груминга черновика и запустил разбор. Работы в чате не видно. Журнал дашборда подтверждает запуск груминга DK-1536 через профиль codex в 16:24:43. Через секунду клиент завершился, не начав хода и не зарегистрировавшись. Подготовленных результатов нет. Временный каталог опекуна уже удалён, точная причина завершения пока неизвестна.

## Чего хотим

Груминг черновика запускается на выбранной модели Sol через профиль Codex. Начало работы и её состояние видны в дашборде. При отказе запуска пользователь получает конкретную причину.

## Границы

Восстановить запрошенный пользователем груминг DK-1536 после исправления причины. Сохранить выбор Sol, исходный черновик и порядок согласования результатов. Подготовленные задачи не применять без подтверждения пользователя. Перенос истории между клиентами сюда не входит. Чужие неотслеживаемые файлы не трогать.

## DoD

- Повторный запуск груминга на Sol начинает ход, который виден в чате черновика.
- Выбор модели и профиля сохраняется, скрытого переключения на другую подписку нет.
- Отказ клиента до первого хода диагностируется и доступен пользователю.
- Исправление покрыто тестом с проверкой красноты на прежнем коде и проверено на обновлённом дашборде.

## Ранг

`25+5+2+5+2 = 39`, P2.

- Серьёзность 25: выбранный запуск не работает, пользователь может выбрать другой профиль.
- Ценность 5: выбранная модель начинает разбор черновика из дашборда.
- Неопределённость 2: завершение клиента подтверждено, точная причина ещё не установлена.
- Поправка на баг 5: действие запуска завершается без хода и результата.
- Рычаг 2: тот же вход используется для следующих запусков груминга.

## Приёмка

- вид: agent
- Проверены доступ, секрет, необратимость, согласие, событие и глаза. Условий, посильных только человеку, не найдено. Пользователь уже разрешил запуск груминга на Sol. Применение его результатов остаётся отдельным подтверждением.

## Ход работы

- Причина подтверждена кодом и установленным клиентом. handleDraftGroom всегда вызывал groomCmd с флагами Claude. Команда `codex --permission-mode auto --model gpt-6.1-sol --name 'DK-1711 диагностика' 'Не выполнять ход'` завершилась кодом 2 и `unexpected argument '--permission-mode' found` до первого хода.
- Для чужого протокола груминг использует существующий app-server. Выбор модели, глубины, режима и исходного дерева сохраняется. agentctl exec получает DEVKIT_TASK, DEVKIT_GROOM_SOURCE и DEVKIT_GROOM_MODE. Занятость видна среди работ, второй запуск не проходит, панель открывает ленту сразу. Причина раннего отказа клиента сохраняется в ленте.
- Живой повтор DK-1536 оставлен диспетчеру после выката. Материал DK-1536 исполнитель не читал. app-server сохраняет workspace-write и approvalPolicy=never. Для реальной приёмки нужно подтвердить исполнение taskctl guard и сохранение prepared-результата в общей .git; возможный запрет записи песочницей остаётся риском, одного подъёма app-server для приёмки недостаточно.
- Адресный прогон `devkitctl test tools/dashboard -run '^(TestApp|TestDraftGroom|TestStaticGroomSewsPanel|TestLiveWorks)'` прошёл. regcheck на базе 2fc7cf565 подтвердил красноту TestDraftGroomAppServer и перехода панели на прежнем коде. Полный набор проекта не запускался.
- Препятствие devkit: agentctl plan done не закрыл разведку из-за отсутствия этапа development от native Codex hook spawn. Отметка не подделывалась, работа продолжена по явному поручению диспетчера.
- Вычитку окончательного текста выполняет ревьювер свежим контекстом.

## Сценарий проверки

На изолированном стенде проверить оба режима груминга, сохранение выбранной
модели и глубины, начало хода, окружение источника, видимость работы,
блокировку повторного запуска, причину раннего выхода и переход панели в чат.

```sh
devkitctl test tools/dashboard -run '^(TestDraftGroomAppServer|TestStaticGroomSewsPanel|TestAppChat|TestDraftGroom)'
```

После выката выполнить `taskctl guard DK-1536` и повторить запрошенный
груминг DK-1536 на Sol кнопкой дашборда. Убедиться, что в разговоре выбран
профиль codex и модель gpt-6.1-sol, появился ход с исполнением taskctl guard,
а prepared-результат сохранён и ожидает согласия человека. При запрете
песочницы записать точную причину из ленты. Результаты без согласия не применять.
