# DK-1711: Груминг на Sol завершается до первого хода

## Что происходит

14 ноября пользователь выбрал Sol кнопкой груминга черновика и запустил разбор. Работы в чате не видно. Журнал дашборда подтверждает запуск груминга DK-1536 через профиль codex в 16:24:43. Через секунду клиент завершился, не начав хода и не зарегистрировавшись. Подготовленных результатов нет. Временный каталог опекуна уже удалён, точная причина завершения пока неизвестна.

## Чего хотим

Груминг черновика запускается на выбранной модели Sol через профиль Codex. Начало работы и её состояние видны в дашборде. При отказе запуска пользователь получает конкретную причину.

## Границы

Восстановить запрошенный пользователем груминг DK-1536 после исправления причины. Сохранить выбор Sol, исходный черновик и порядок согласования результатов. Подготовленные задачи не применять без подтверждения пользователя. Перенос истории между клиентами сюда не входит. Чужие неотслеживаемые файлы не трогать.

## Ход работы

- Причина подтверждена кодом и установленным клиентом. handleDraftGroom всегда вызывал groomCmd с флагами Claude. Команда `codex --permission-mode auto --model gpt-6.1-sol --name 'DK-1711 диагностика' 'Не выполнять ход'` завершилась кодом 2 и `unexpected argument '--permission-mode' found` до первого хода.
- Для чужого протокола груминг использует существующий app-server. Выбор модели, глубины, режима и исходного дерева сохраняется. agentctl exec получает DEVKIT_TASK, DEVKIT_GROOM_SOURCE и DEVKIT_GROOM_MODE. Занятость видна среди работ, второй запуск не проходит, панель открывает ленту сразу. Причина раннего отказа клиента сохраняется в ленте.
- Живой повтор DK-1536 оставлен диспетчеру после выката. Материал DK-1536 исполнитель не читал. app-server сохраняет workspace-write и approvalPolicy=never. Для реальной приёмки нужно подтвердить исполнение taskctl guard и сохранение prepared-результата в общей .git; возможный запрет записи песочницей остаётся риском, одного подъёма app-server для приёмки недостаточно.
- Адресный прогон `devkitctl test tools/dashboard -run '^(TestApp|TestDraftGroom|TestStaticGroomSewsPanel|TestLiveWorks)'` прошёл. regcheck на базе 2fc7cf565 подтвердил красноту TestDraftGroomAppServer и перехода панели на прежнем коде. Полный набор проекта не запускался.
- Препятствие devkit: agentctl plan done не закрыл разведку из-за отсутствия этапа development от native Codex hook spawn. Отметка не подделывалась, работа продолжена по явному поручению диспетчера.
- После замечаний 1-2 подготовлен согласованный пользователем режим только для груминга. thread/start и thread/resume используют workspace-write, on-request и auto_review. До первого хода проверяется ответ клиента с фактической политикой. Явный отказ или игнорирование reviewer завершают запуск с причиной в панели. Обычные чаты сохраняют never.
- Нейтральный DEVKIT_CHAT_SESSION_ID связывает план agentctl и вопросы taskctl с адресом as-разговора. Флаги --sid/--session остаются старше окружения. Переменные CLAUDE и имя tmux для Codex не подделываются.
- Интеграционный TestAppGroomPreparedAgreement использует настоящий taskctl: prepared save/ask, GET as/ask, комментарий, подтверждение из чата и с формы, создание задачи add, отказ занятого хода, повтор по сохранённой квитанции и продолжение той же нити с прежними model/harness/mode/tree/effort. Потерянной доставки в терминальный вход нет.
- Адресные тесты TestAppGroom, TestAppChat, TestPreparedFormConfirmReachesAsker, TestGroomConsent, TestAsk и TestPlan прошли. regcheck на e1a12793d подтвердил красноту новых тестов dashboard, taskctl и agentctl. Реальный guard/prepared с auto_review проверяет независимый ревьювер на временном проекте до слияния; DK-1536 повторяется после выката.
- Вычитку окончательного текста выполняет ревьювер свежим контекстом.

## Ревью

Уровень 2 до e1a1279: Проверены протокол запуска, контекст груминга и согласование; два блокирующих отказа подтверждены probe.

- [возврат: реализация, 2026-11-14] Блокирует: appchat.go:224-227 запускает groom thread с workspace-write и approvalPolicy=never. Штатный taskctl guard DK-1536 из command/exec этой нити завершается exit 1: chmod common .git/devkit/draft-tx operation not permitted (живой app-server probe диспетчера 2026-11-14). Sol начинает ход, но обязательный первый guard и сохранение prepared-результата остаются недоступны, пользовательский сценарий не исправлен. Источник: ARCH-005/011/012 и DoD задачи. Нужен поддерживаемый протокол запроса эскалации и проверки доступа с сохранением sandbox и guard; проверить guard и подготовку результата через реальный app-server до принятия.
- [возврат: реализация, 2026-11-14] Блокирует: appSpawn (appchat.go:181-188) сохраняет GroomSource/Mode/Tree, но не связывает вопросы taskctl ask с as-сессией. taskctl askSession читает только CLAUDE_CODE_SESSION_ID; в Codex draft вопрос без Session, а waiting.go:askForChat проверяет binds[asID].Task, которого нет. Изолированный API probe на e1a12793d: POST foreign groom XR-77, chat.WriteAsk(Task=XR-77, Session пустой), GET /chats/as.../ask возвращает «вопросов агента за ним нет» без ask. Пользователь не видит структурированный вопрос согласования и прежний run-порядок не сохранён. Источник: ARCH-007/022 и docs/ARCHITECTURE.md, инвариант PreparedQuestion. Связать app-server разговор, вопросы и delivery штатным контрактом, добавить тест полного цикла prepared ask -> показ -> согласие -> продолжение с сохранением модели/mode/tree.

профиль codex и модель gpt-6.1-sol, появился ход с исполнением taskctl guard,
