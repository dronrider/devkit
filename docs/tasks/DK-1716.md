# DK-1716: Задача на Sol не запускается из-за отсутствия секции head

## Что происходит

15 ноября 2026 года пользователь выбрал Sol в меню на форме задачи и нажал «Выполнить». Вместо начала работы получил ошибку: «в профиле kit/harness/codex.toml нет секции [head]: чем поднимать голову задачи, не сказано». В профиле есть делегирование через Codex CLI и протокол codex для чатов, но секции [head] нет. Груминг на Sol уже работает через app-server. Причину выбора неподходящего пути запуска задачи нужно подтвердить.

## Чего хотим

Кнопка «Выполнить» запускает работу по задаче с выбранной моделью Sol и профилем Codex. Начало работы и причина возможного отказа видны в чате задачи. Выбор модели и глубины сохраняется.

## Границы

Исправляется запуск задачи на Codex, без переноса истории между клиентами и развития остального прототипа. Не запускать заново пользовательскую задачу до проверки отсутствия живого исполнителя. Незавершённую работу другого клиента не дублировать.

## Сценарий проверки

После выката запустить из основного чекаута devkit. Первая команда проверяет
исходный путь кнопки «Выполнить» на выкаченном бинаре. Без переменной
`DEVKIT_DASHBOARD_BIN` берётся установленный `dashboard` из PATH. Бинарь
копируется без пересборки, его путь и SHA-256 печатаются в выводе. Временные
HOME, машинный дом, проект, утилиты доски и клиент подменяются стендом.
Реальная модель не вызывается; используется безопасная задача XR-002.

```sh
probe_binary="${DEVKIT_DASHBOARD_BIN:-$(command -v dashboard)}" && test -x "$probe_binary" && DEVKIT_DASHBOARD_BIN="$probe_binary" devkitctl test tools/dashboard -run '^TestAppTaskInstalledArtifact$' -count=1 -v
```

Ожидается код 0 и строка `artifact: HTTP start, task binding, model/effort,
duplicate refusal and stop passed`. Прогон требует HTTP 200 при запуске,
выбранные модель Codex и глубину high в клиенте, запись задачи XR-002 и ID
нити в чате, HTTP 409 у второго запуска, HTTP 200 у остановки и снятый общий
замок. Старый бинарь завершится ошибкой запуска про отсутствующую `[head]`.

Для обкатки до выката передать `DEVKIT_DASHBOARD_BIN` с путём к отдельно
собранному бинарю проверяемого коммита. После выката переменную убрать и
повторить команду в свежей сессии. Пользовательскую UI-задачу и текущую
DK-1716 этим сценарием не запускать.
