# DK-1720: Первая реплика нового чата задачи уходит в старый разговор

## Что происходит

17 ноября 2026 пользователь создал новый чат DK-1570 и отправил «Нужно довести задачу до завершения. Я согласовал макеты где подписка отображалась свёрнутой, но дальше работа не двинулась. Продолжай».

Ожидался запуск нового чата с полной первой репликой и подтверждением доставки. Реплика осталась на экране недоставленной, хотя индикатор этапов задачи заработал.

В dashboard.log в 19:07:06 записана отправка команды «Продолжай выполнение DK-1570» старой живой голове. Новый чат blank-757fd674-9507-4330-baee-4d4af9776691 остался заготовкой. Полный текст есть в журнале said задачи. В транскрипте старого разговора есть только команда «Продолжай выполнение DK-1570». Полный текст пользователя модели не доставлен; клиент старой подписки остался на повторе HTTP 429 из-за исчерпанного баланса. Индикатор задачи не доказывает доставку в выбранный чат.

## Чего хотим

Первая реплика нового чата задачи запускает выбранный чат и поступает его исполнителю целиком. Доставка и индикатор работы согласованы с фактическим адресатом. Ошибка запуска сохраняет реплику для безопасного повтора.

## Границы

Проверяем создание нового чата задачи при существующем живом или ожидающем чате той же задачи. Саму реализацию выбора подписок DK-1570 эта задача не меняет.

## DoD

- Новый чат задачи получает первую реплику целиком при наличии другого живого чата той же задачи. Старый чат от этой отправки не возобновляется.
- Тест проверяет выбранный адресат, текст и подтверждение доставки. Ошибка запуска не выдаётся за доставку, повтор не дублирует успешно принятую реплику.
- Сохранены штатные ответы из существующего чата и со страницы задачи. Регрессия воспроизводится на старой версии и проходит на исправленной.
- Для инцидента DK-1570 выяснены фактический адресат и состояние реплики. Повторная отправка допускается после проверки отсутствия успешной доставки.

## Ранг

`50+4+2+5+2 = 63`, P1.

- Серьёзность 50. Работа запускается в другом чате; выбранный пользователем новый разговор не начинается.
- Ценность 4. Создание чата задачи входит в регулярную работу через дашборд.
- Неопределённость 2. Ошибочный маршрут подтверждён журналом, требуется проверить границы запуска и подтверждения.
- Поправка на баг 5. Пользовательский инцидент подтверждён состоянием заготовки и журналом сервера.
- Рычаг 2. Исправление восстанавливает последующие первые отправки чатов задач.

## Приёмка

- вид: agent
- Синтетический проект и тестовый отправитель проверяют запуск, точный текст и адресат. Живой чат читается через API без повторной отправки пользовательского текста.

## Условия

Условий, посильных только человеку, не найдено. Журналы, реплика и состояние чатов доступны локально. Исправление и выкат разрешены текущим запросом и autonomous проекта.

## Ход работы

- Маршрут ожидания задачи перехватывал первую реплику нового чата. Новый
  адрес теперь сохраняется при старом живом, ожидающем и кончившемся чате.
- Принятый терминальный запуск хранит отпечаток заказа. Повтор возвращает
  прежний адрес, другая реплика получает HTTP 409. Отказ до запуска сохраняет
  черновик и допускает новую попытку.
- `regcheck --base HEAD -- devkitctl test tools/dashboard -run TestTaskBlank -count=1`
  подтвердил падение тестов на старом коде и успех на исправленном.
- Пять мутаций маршрута, адреса, отпечатка, повтора и замка запуска дали
  красные тесты. После каждого прогона исходники восстановлены.

## Сценарий проверки

1. В свежем дереве с временным HOME прогнать стенды панели и API:

```sh
devkitctl test tools/dashboard -run 'TestTaskBlank|TestChatBlank|TestStaticTaskReplyWithoutLead' -count=1
```

Панель запускает выбранный новый чат при старом живом, ожидающем или
кончившемся разговоре. Проверяются точный многострочный текст, задача,
адрес заготовки, модель и подписка. Ошибка сохраняет реплику без отметки
доставки, успех переносит её в новый разговор. API сохраняет черновик
при отказе и принимает повтор одного запуска без второго клиента.
Две разные параллельные реплики дают один запуск и один явный HTTP 409.
Повтор после смерти клиента и после появления grown не запускает дубль.
Штатные ответы из существующего чата и со страницы задачи остаются на своих дорогах.

2. После выката только чтением API и журнала проверить восстановление DK-1570.
Новый разговор должен быть связан с исходной заготовкой, моделью
`glm-5.3-flash` и подпиской `glm-code-2`. В его транскрипте должна быть полная
исходная реплика из раздела «Что происходит». В старом разговоре остаётся
только ошибочная команда продолжения. Во входе задачи не должно остаться
безадресной копии исходной реплики. Проверяющий не отправляет новых реплик
и не меняет состояния живых чатов.
