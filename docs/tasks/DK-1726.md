# DK-1726: Чат задачи меняет привязку и теряет новые реплики

## Что происходит

18 ноября пользователь открыл чат «Свёрнутая подписка в макетах», созданный
для DK-1570. В заголовке появилась задача DK-1725. Новые сообщения не
появляются в ленте. Ответа нет.

Ожидается продолжение того же разговора по DK-1570 с сохранением отправленных
реплик. Локальный API возвращает для сессии c99eba5f-e410-424f-ab39-8d85e2975d20
tasks и leads в порядке DK-1725, DK-1570. Запись запуска по-прежнему содержит
task=DK-1570, окно chat-DK-1570-2, модель glm-5.3-flash и подписку glm-code-2.
Клиент числится live и idle. Последняя запись нативного журнала датирована
18 ноября 02:45 по Москве. В ней исполнитель ждёт ревью исправления DK-1725,
которое понадобилось при доводке DK-1570. Судьба новых реплик пока не установлена.

DK-1720 уже устранил неверный маршрут первой реплики заготовки. Здесь речь
об установленном разговоре после работы над побочной задачей. DK-1615 содержит
общий переход к отметкам доставки, а этот инцидент требует установить и
устранить конкретную причину смены привязки и недоступности разговора.

## Чего хотим

Чат, созданный для DK-1570, сохраняет эту основную привязку, пока пользователь
её не сменит. Работа исполнителя над препятствием не подменяет адрес разговора.
Новые реплики сохраняются и попадают выбранному собеседнику. Лента показывает
отправленный текст, подтверждённое состояние доставки и ответ.

## Границы

В задачу входит восстановление пострадавшего чата и проверка судьбы
отправленных реплик. До повтора сообщения нужна сверка с нативным журналом
и очередями. Реализацию меню подписок DK-1570 и исправление стенда DK-1725
ведут их исполнители. Общий редизайн отметок из DK-1615 сюда не входит.

## DoD

- Основной задачей чата «Свёрнутая подписка в макетах» снова отображается DK-1570.
- После работы над побочной задачей основная привязка сохраняется в API и панели.
- Установлена судьба последних сообщений пользователя; сохранённые реплики
  восстановлены без повторной доставки уже полученных.
- Отправленная реплика и ответ доступны в той же ленте после обновления страницы.
- Сценарий покрывает живой простаивающий клиент и работу над второй задачей.

## Ранг

`50+7+2+5+3 = 67`, P1.

- Серьёзность 50: чат задачи теряет назначение и перестаёт давать продолжить работу.
- Ценность 7: переписка с исполнителем используется при каждой доводке задачи.
- Неопределённость 2: адрес и расхождение привязок установлены. Причину доставки нужно проверить.
- Поправка на баг 5: пользователь сообщил повторный сбой, API подтвердил неверный порядок задач.
- Рычаг 3: исправление защищает разговоры при работе над связанными препятствиями.
