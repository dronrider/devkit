# DK-1736: Sol и Astra 6.2 заменяют прежние версии в новом выборе

## Что происходит

18 ноября 2026 пользователь отклонил результат DK-1730. Новые Sol и Astra
были добавлены рядом с прежними версиями, хотя пользователь ожидал замену
актуального выбора на 6.2. Он уточнил: прежние версии нужны только для
отображения в существующих чатах.

При открытии нового выбора сейчас предлагаются прежние Sol и Astra вместе
с 6.2. Ожидался выбор актуальных версий с сохранением подписи старой модели
у существующего чата. Добавление вариантов в DK-1730 не выполнило этот заказ.

## Чего хотим

В новом выборе моделей Sol и Astra представлены версиями 6.2. Прежние
версии этих семейств отображаются у чатов, где они уже сохранены.
Существующая запись чата сохраняет свой идентификатор модели.
При смене модели у старого чата предлагаются актуальные варианты.
Для нового запуска используются выбранные актуальные идентификаторы.

Условий, посильных только человеку, при сверке уточнения и способа выката
не нашёл. Другие семейства моделей этой заменой не затрагиваются.

## DoD

- Новый выбор и выбор при смене модели предлагают `gpt-6.2-sol` и
  `gpt-6.2-astra`; прежние версии Sol и Astra там отсутствуют.
- У существующего чата с прежней моделью видна сохранённая версия, запись
  чата сама по себе не переписывается.
- Возврат на прежнюю версию через новый выбор недоступен.
- Новый чат и новый запуск используют выбранную версию 6.2, в том числе
  при прежних машинных настройках, которые могли оставить старые варианты.
- Приёмка на поставленном дашборде проверяет новый выбор, подпись старого
  чата и передачу точного ID после смены на 6.2.

## Сценарий проверки

1. Во временном HOME включить Codex, задать прежние `pro = "gpt-6.1-sol"`,
   `max = "gpt-6-astra"` и добавить обе прежние версии в машинный `chat`.
   Установленный `agentctl harness --json` должен сохранить эти назначения.
   Они используются фоновыми агентами и этой правкой не меняются.
2. Поднять установленный дашборд с тем же HOME и синтетическим проектом.
   Подменить только клиент app-server, записывающий полученный `model`.
   GET списка чатов должен предложить Sol/Astra 6.2 с прежними ярусами,
   подпиской, глубиной и признаком модели по умолчанию. Terra и Luna
   сохраняют свои ID. Прямые POST нового
   чата, незачатой записи и смены модели с любым из четырёх прежних ID
   должны дать HTTP 409, в том числе при пустой подписке.
3. Открыть существующий чат с `gpt-6.1-sol`. Прежний ID виден в поле модели,
   но в открытом меню смены доступны только актуальные версии.
   Прочитать список повторно и сверить файл записи. ID остаётся прежним.
   POST реплики до смены должен дать HTTP 409 без отправки хода клиенту.
4. Выбрать `gpt-6.2-sol`, затем `gpt-6.2-astra`. После каждой смены отправить
   реплику. Запись чата и запрос клиента должны содержать выбранный точный
   ID, а лента должна сохранить историю и разделитель смены.
   Снова выбрать прежний ID прямым POST должно быть невозможно.
5. В браузере сохранить предпочтение `gpt-6.1-sol` и создать новый чат при
   другой подписке по умолчанию. Выбор и POST должны содержать
   `gpt-6.2-sol` с прежней подпиской. Повторить для Astra.
   Автоматический прогон интерфейса и ручных HTTP-входов:

```sh
devkitctl test tools/dashboard -run 'Test(ChatLegacy|ChatModelPreference|ChatModelCatalog|AppChatCatalog)'
```
