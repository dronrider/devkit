# DK-1738: Отказ модели Codex не виден в ленте чата

## Что происходит

19 ноября 2026 года пользователь дважды отправил сообщение в чат DK-585 на
модели gpt-6.2-sol. Codex завершил оба хода с ошибкой model_not_found,
но в дашборде остались только реплики пользователя. Чат выглядел молчащим.
Отказ подтверждён журналом клиента, а отсутствие ответа подтверждено файлом ленты.

В appNote файла tools/dashboard/appchat.go поле turn.error читается строкой.
Клиент передаёт объект с полями message и codexErrorInfo. Ошибка разбора JSON
игнорируется. Для воспроизведения достаточно завершить ход подставного
клиента с таким объектом. Ожидается сообщение об отказе в ленте; сейчас его нет.

## Чего хотим

Человек видит причину неудачного хода в том же разговоре и может повторить
отправку после устранения причины. История и выбранная модель сохраняются.

## Границы

Задача касается отображения отказа. Выбор модели, обновление CLI и поиск
профиля из старого рабочего дерева разбираются отдельно.

## DoD

- Объект turn.error с message отображается в ленте как отказ клиента.
- Строковый error прежнего формата сохраняет читаемое сообщение.
- Успешный ход и error=null не создают сообщения об отказе.
- После отказа занятость чата снимается, повторная реплика принимается.
- Регрессионный тест падает до исправления и проходит после него.

## Ревью

Уровень 2 до 634fed6: Проверены путь уведомления, совместимость форматов и повтор; обнаружена потеря принадлежности дочернего отказа

- [возврат: реализация, 2026-11-19] блокирует: tools/dashboard/appchat.go:580 записывает ошибку любого turn/completed без Sub. Если дочерняя нить завершится с объектом error.message, её отказ показывается как отказ родительского хода, хотя busy родителя остаётся true; соседние item-события помечаются Sub по threadId. Сохраните принадлежность отказа дочерней нити и проверьте уведомление child с error.message при работающем родителе и обычный родительский отказ.

- По замечанию ревью отказ дочерней нити отмечается её threadId, занятость родительского хода сохраняется. Родительский отказ остаётся без Sub. `regcheck --base HEAD -- devkitctl test tools/dashboard -run 'TestAppFeedTurnError|TestAppFeedChildTurnError|TestAppChatTurnFailureRetry'`: дочерний тест краснеет на прежнем коде и проходит с исправлением. Это проверка регрессии бага; типовые мутации не запускались.

## Сценарий проверки

1. В стенде app-server отправить реплику и вернуть turn/completed со
   status=failed и error={"message":"model_not_found","codexErrorInfo":"other"}.
   В HTTP-ленте того же разговора есть сообщение отказа с model_not_found.
2. Повторная реплика после отказа принимается. ID разговора и модель сохранены.
3. Успешный ход, null и строковый error проверены отдельными случаями.
