# DK-1740: Один разговор в Codex и дашборде

## Что происходит

После перезапуска дашборд пытается продолжить разговор отдельным процессом.
Если разговор уже открыт в настольном Codex, попытка завершается ошибкой
`already has an active writer`. Пользователь не может отправить реплику из
дашборда. Это произошло с DK-585 19 ноября 2026 года.

На стенде дашборд и Codex CLI подключились к одному процессу через Unix-сокет.
Оба клиента по очереди отправили реплики в одну нить до и после перезапуска
дашборда. Ответы видны в обоих клиентах. Сами реплики из Codex в дашборде
не видны. Обработчик ленты пропускает события `userMessage`.

## Чего хотим

В настольном Codex и дашборде открыта одна нить. Из любого окна можно написать
и увидеть вопрос и ответ в обоих. Перезапуск дашборда не требует переключать
клиент или вручную освобождать нить.

## Границы

Проверка на отдельном разговоре. DK-585 не запускать. Общий локальный сервер
используется для совместимых интерактивных чатов Codex. Политика песочницы,
рабочий каталог и авторизация сохраняются. Другие поставщики и автоматические
запуски сохраняют свой способ работы.

## DoD

- Дашборд ведёт интерактивный разговор на общем локальном сервере Codex.
  После перезапуска разговор продолжается с прежним `threadId`.
- В ленте видны реплики из обоих клиентов и ответы. После переподключения
  восстанавливаются пропущенные сообщения. Если реплика уже видна в ленте
  после отправки, событие от сервера не добавляет её повторно.
- При недоступном сервере или занятом ходе интерфейс показывает причину.
  Повтор сообщения с неподтверждённым исходом не создаёт второй ход.
- Есть тесты протокола и ленты. В README описаны запуск и условия работы.
- Живая проверка с настольным Codex и отдельным экземпляром дашборда
  подтверждает отправку и историю в обоих направлениях до и после рестарта.

## Ранг

`50+7+2+0+3 = 62`, P1.

- Серьёзность 50: при переходе между окнами работа в чате останавливается.
- Ценность 7: один разговор нужен при регулярном переходе между окнами.

- Поправка на баг 0: это поддержка совместной работы двух клиентов.
- Рычаг 3: общий способ пригодится для интерактивных чатов Codex.

## Сценарий проверки

Проверить поставляемый бинарник на синтетической доске. Команда заканчивается
строкой `dashboard smoke: ok`.

```sh
DEVKIT_HOME="$PWD" dashboard smoke
```

Продолжить на отдельном стенде с общим сервером Codex.

1. Запустить проверяемый бинарник дашборда на локальном порту с отдельным
   каталогом состояния и пустой тестовой доской. Создать чат Codex без задачи,
   отправить уникальную реплику и дождаться ответа.
2. Открыть ту же нить в настольном Codex и отправить вторую уникальную
   реплику. В обоих окнах видны обе реплики и ответы.
3. Перезапустить только тестовый дашборд. Во время его остановки отправить
   реплику из Codex. После запуска дашборд покажет её и ответ. Отправить
   ещё одну реплику из дашборда. Она и ответ видны в Codex.
4. Сверить `threadId` и число записей в ленте. Убедиться, что каждая реплика
   и каждый ответ видны по одному разу. Исходная рабочая доска и DK-585
   в проверке не задействованы.
5. Создать отдельный чат прежним бинарником дашборда, получить ответ и
   остановить экземпляр. Открыть эту нить в Codex. Запустить новый бинарник
   с тем же тестовым состоянием и продолжить чат из дашборда. Перезапустить
   его и повторить отправку. ID нити совпадает, а в ленте каждая реплика
   и каждый ответ встречаются один раз.
