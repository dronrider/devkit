# DK-1744: Запуск задач предлагает прежний Sol и блокирует реплики в чате

## Что происходит

20 ноября пользователь запустил DK-1741 кнопкой «Выполнить». В выборе была
Sol 6.1 и не было Sol 6.2. Работающий чат выполнял задачу, но следующая
реплика получила отказ с требованием выбрать gpt-6.2-sol. Сообщение не ушло.
Ожидался доступный актуальный выбор при запуске и возможность продолжить
тот же разговор без потери переписки и контекста.

DK-1736 обновила только выбор обычного чата. Назначения pro/max для запуска
задач остались прежними, а проверка устаревшей модели применяется и к таким
чатам. Пользователь обновил Codex и просит актуальные Sol/Astra 6.2 во всех
местах выбора. Доступность моделей нужно проверить заново.

## Чего хотим

Новый запуск чата, задачи и агента предлагает и использует Sol/Astra 6.2.
Старые машинные назначения не возвращают прежние версии в доступный выбор.
Прежний ID в существующем разговоре остаётся честной записью истории.
Явный переход чата задачи на 6.2 сохраняет переписку, привязку к задаче и
контекст Codex. Действующий ответ не обрывается выбором модели.

## Границы

DK-1741 ведёт девять изменений поведения панели, включая меню живого Codex.
Здесь исправляется согласованность каталога и запуска и проверяется переход
со старой модели. Пересечение с пунктом 8 DK-1741 нужно сверить перед правкой.
Пользовательский чат DK-1741 диагностируется без отправки служебных реплик,
остановки работы и ручной перезаписи его файлов.

## DoD

- Все места выбора Sol/Astra для нового чата и кнопки «Выполнить» показывают
  только 6.2. Сервер передаёт выбранный точный ID клиенту.
- Стандартный профиль Codex и совместимость с прежними машинными
  назначениями дают актуальные модели при новом запуске задачи и агента.
- Уровни мышления и подписка сохраняются. Terra и Luna не меняются.
- Переход существующего чата задачи на 6.2 проверен с прежней историей,
  контекстом Codex и привязкой к задаче. Если текущая реализация теряет
  внутреннюю нить, она исправлена; видимая история не выдаётся за полный
  контекст модели.
- Для DK-1741 дан ответ о безопасном переходе по фактическому состоянию.
- Проверены регрессия, установленный дашборд и актуальный клиент Codex.

## Ранг

`50+8+3+5+2 = 68`, P1.

- Серьёзность 50: сообщение в действующий чат задачи не отправляется.
- Ценность 8: сломан ежедневный запуск и продолжение задач.
- Неопределённость 3: нужно согласовать каталог, запуск и нить Codex.
- Поправка на баг 5: отказ воспроизведён пользователем.
- Рычаг 2: последующие запуски используют единый актуальный выбор.

## Ход работы

- Диагноз: профиль Codex и машинная лестница сохраняли прежние назначения
  pro/max, тогда как проверка чата уже требовала актуальный ID. Смена модели
  очищала Thread и снимала процесс, сохраняя видимую ленту без контекста Codex.
- В DK-1744 исправляются каталог, рабочие назначения и безопасная смена
  модели в той же подписке Codex. Из DK-1741 согласован перенос двух условий
  панели: живому Codex разрешён выбор, выбор не шлёт stop и служебный say.
  DK-1741 сохраняет остальные изменения меню, работу с turn ID,
  уведомления плана и остальные изменения панели. Её незакоммиченный diff
  прочитан только для сверки пересечений; пользовательский чат не менялся.
- Явная смена сохраняет нить, текущий ход, глубину и привязку к задаче. Новый
  выбор применяется следующим turn/start, включая автоматический проход,
  и при thread/resume. Рабочий чат задачи сохраняет подписку. У обычного
  чата смена подписки во время старта или хода получает отказ, после
  конца хода создаёт новую нить; перенос её внутреннего контекста не заявлен.
  Ошибка resume не подменяется новым thread/start.
- Происхождение рабочего разговора отделено от выбранной модели: сохранённые
  ID запуска, корень, PID, подписка и ID чата подтверждают прежний запуск.
  Для старой записи с одним PID перед сменой проверяются прежняя модель и
  назначение чата. Историческая модель taskstate не переписывается.
- Прежний ID в записи чата остаётся до явного выбора. Legacy /say получает
  409 с полем refused. Текст сохраняется в панели после обновления страницы
  и не повторяется автоматически. Текущий ответ старой модели
  при этом не прерывается.
- Препятствие devkit: taskctl guard/show не могут создать git/devkit/draft-tx
  в песочнице вложенного исполнителя; guard/show успешно выполнены
  диспетчером, постановка прочитана из файла задачи. Agentctl plan без SID
  отказал; план создан диспетчером с SID текущей сессии и меткой DK-1744.
  Devkitctl test отказал на ~/.devkit/parallel-slots/slot-0.lock; прогоны
  выполняет диспетчер штатной обёрткой, прямых go test нет.
- Свежий ревьювер выявил гонки смены подписки с открыванием хода и стартом
  процесса, а также откат выбранной модели полными снимками записи.
  Смена и открывание сериализованы замками appMu/c.mu, отсоединённый клиент
  не принимает новый ход. Горячие записи меняют только свои поля под файловым
  замком: просмотр, архив, глубина и нить, состояние и происхождение запуска.
  Отметка выбора записывается ролью mark в саму ленту Codex, видна через API
  и после обновления страницы, называет применение к следующему ходу.
- Вычитка: 3 файла, 3 правки, 1 пометка, 2026-11-20.
- Вычитка README дашборда: 1 файл, 0 правок, 2 пометки, 2026-11-20.

## Проверка

- Диспетчер: Codex 0.170.0, оба настоящих `exec --model gpt-6.2-sol` и
  `exec --model gpt-6.2-astra` вернули OK и код 0. Живой пользовательский чат
  для проб не использовался.
- Схема установленного клиента: `TurnStartParams.model` переопределяет модель
  текущего и последующих ходов; `ThreadResumeParams.model` задаёт настройки
  возобновляемой нити. Схема снята клиентом в
  `/private/tmp/dk1744-codex-schema/v2/` и прочитана до завершения правки.
- Диспетчер: `python3 /private/tmp/dk1744-real-context.py`, код 0. В отдельной
  ephemeral-нити первый ход Sol 6.1 запомнил случайное контрольное слово;
  следующие ходы Sol 6.2 и Astra 6.2 воспроизвели его в том же thread ID,
  без инструментов и без служебных реплик в пользовательский чат.
- Диспетчер: `gtimeout 360 python3 /private/tmp/dk1744-real-context.py --resume`,
  код 0. Отдельная постоянная нить Sol 6.1 сохранила случайное контрольное
  слово. После перезапуска app-server `thread/resume` с Sol 6.2 продолжил
  тот же ID, Sol 6.2 и следующий Astra 6.2 воспроизвели прежнее слово.
  Тестовая нить затем архивирована. Пользовательский чат не использовался.
- Первые узкие прогоны через `devkitctl test` зелёные: agentctl
  TestProfileCodex, TestCmdHarnessJSONProfileChatModels,
  TestLegacyAssignmentsUseCurrentModels; dashboard TestAppChatModelSwitch,
  TestAppChatModelSwitchKeepsCodexContext,
  TestChatModelCatalogProjectsLegacyAssignments,
  TestChatModelCatalogUpdatesOperationalTask,
  TestChatLegacyModelPreservedUntilExplicitChange. Полный набор и regcheck
  дополняются после последних тестов происхождения и отказа доставки.
