# DK-1744: Запуск задач предлагает прежний Sol и блокирует реплики в чате

## Что происходит

20 ноября пользователь запустил DK-1741 кнопкой «Выполнить». В выборе была
Sol 6.1 и не было Sol 6.2. Работающий чат выполнял задачу, но следующая
реплика получила отказ с требованием выбрать gpt-6.2-sol. Сообщение не ушло.
Ожидался доступный актуальный выбор при запуске и возможность продолжить
тот же разговор без потери переписки и контекста.

DK-1736 обновила только выбор обычного чата. Назначения pro/max для запуска
задач остались прежними, а проверка устаревшей модели применяется и к таким
чатам. Пользователь обновил Codex и просит актуальные Sol/Astra 6.2 во всех
местах выбора. Доступность моделей нужно проверить заново.

## Чего хотим

Новый запуск чата, задачи и агента предлагает и использует Sol/Astra 6.2.
Старые машинные назначения не возвращают прежние версии в доступный выбор.
Прежний ID в существующем разговоре остаётся честной записью истории.
Явный переход чата задачи на 6.2 сохраняет переписку, привязку к задаче и
контекст Codex. Действующий ответ не обрывается выбором модели.

## Границы

DK-1741 ведёт девять изменений поведения панели, включая меню живого Codex.
Здесь исправляется согласованность каталога и запуска и проверяется переход
со старой модели. Пересечение с пунктом 8 DK-1741 нужно сверить перед правкой.

- Диагноз: профиль Codex и машинная лестница сохраняли прежние назначения
  pro/max, тогда как проверка чата уже требовала актуальный ID. Смена модели

- В DK-1744 исправляются каталог, рабочие назначения и безопасная смена
  модели в той же подписке Codex. Из пункта 8 DK-1741 перенесены два условия
  панели: живому Codex разрешён выбор, выбор не шлёт stop и служебный say.
  DK-1741 сохраняет остальные изменения меню, работу с turn ID,
  уведомления плана и другие изменения панели. Её незакоммиченный diff
  прочитан только для сверки пересечений; пользовательский чат не менялся.
- По просьбе пользователя указание выбирать исполнителей Sol 6.2 отправлено
  диспетчеру DK-1741 через штатный вход задачи. Там же оставлены сведения о
  пересечении правок. HTTP подтвердил запись трёх сообщений в очередь;
  подтверждения их чтения пока нет. Позже отдельным сообщением уточнено,
  что панель должна выбирать путь по наличию protocol, без литерала имени.
- Явная смена сохраняет нить, текущий ход, глубину и привязку к задаче. Новый
  выбор применяется следующим turn/start, включая автоматический проход,
  и при thread/resume. Рабочий чат задачи сохраняет подписку. У обычного
  чата смена подписки во время старта или хода получает отказ, после
  конца хода создаёт новую нить; перенос её внутреннего контекста не заявлен.
  Ошибка resume не подменяется новым thread/start.
- Происхождение рабочего разговора отделено от выбранной модели: сохранённые
  ID запуска, корень, PID, подписка и ID чата подтверждают прежний запуск.
  Для старой записи с одним PID перед сменой проверяются прежняя модель и
  назначение чата. Историческая модель taskstate не переписывается.
- Прежний ID в записи чата остаётся до явного выбора. Legacy /say получает
