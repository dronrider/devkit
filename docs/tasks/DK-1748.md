# DK-1748: Дашборд проверяет ход Codex при долгой тишине

## Что происходит

20 ноября дашборд остановил ход DK-1746. Последняя команда основного
хода завершилась за 19 секунд до таймаута. Codex записал прерывание хода.
В ветке DK-1746 дашборд уже отсчитывает срок от последнего события хода.
После 30 минут тишины он всё ещё останавливает app-server сразу. Долгая
команда может всё это время работать без вывода.

## Чего хотим

Конвейер ждёт до 30 минут с последнего события текущего хода. Когда
срок истекает, дашборд запрашивает у Codex состояние той же нити и хода.
Подтверждённая работа даёт новое окно ожидания. Если Codex уже завершил
ход, конвейер принимает подтверждённый исход и продолжает штатно.

## DoD

- Событие текущего хода продлевает ожидание. Чужой ход срок не меняет.
- При тишине дашборд запрашивает состояние Codex перед остановкой.
  Ответ о продолжающемся ходе продлевает ожидание, в том числе пока
  команда идёт без вывода или Codex ждёт решения пользователя.
- Если уведомление о конце хода пропущено, дашборд принимает исход из
  ответа Codex. Если проверить ход не удалось и свежих событий нет,
  пользователю видна причина остановки. Явный стоп сохраняет силу.
- Стенд с управляемым временем воспроизводит активный ход, долгую
  команду без вывода, пропущенное завершение и отказ проверки состояния.

## Ранг

`25+7+3+5+4 = 44`, P2.

- Серьёзность 25: прерванную работу можно запустить снова, теряется время хода.
- Ценность 7: длинная команда может закончиться в том же рабочем чате.
- Неопределённость 3: решение дашборда опирается на ответ app-server.
- Поправка на баг 5: прерывание активного хода подтверждено журналом.
- Рычаг 4: проверка защищает долгие проходы всего конвейера Codex.

## Ход работы

- Регрессия воспроизведена на стенде после возврата прежней остановки
  по таймеру. `TestAppTaskSilenceProbe/running` упал до запроса состояния.
  После восстановления правки профильные тесты прошли.

## Сценарий проверки

Запустить стенд app-server с управляемым временем. Дать основному ходу
проработать дольше 30 минут и прислать событие перед прежним сроком
остановки. Ход завершается, события другой нити и другого хода отсчёт
не продлевают.

На 30-й минуте тишины стенд отвечает, что ход ещё идёт. Конвейер ждёт.
При следующей проверке стенд возвращает завершённый ход без уведомления
`turn/completed`. Конвейер принимает исход. Если запрос проверки
завершился ошибкой, но за время проверки пришло свежее событие, ход продолжает работу.
При ошибке без новых событий конвейер сообщает причину остановки.

```sh
devkitctl test tools/dashboard -run '^TestAppTaskSilence(Timer|Probe.*)$' -count=1 -v
```
