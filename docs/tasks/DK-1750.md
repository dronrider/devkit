# DK-1750: shipctl check-run запускает отдельную приёмку в Codex

## Что происходит

20 ноября 2026 года `shipctl check-run DK-1748` завершился ошибкой.
Для приёмки требовалась свежая сессия Codex. При попытке запустить
проверяющего через `taskctl run` потребовалась секция `[head]`.
В профиле Codex такой секции нет. Сценарий удалось выполнить из отдельной
сессии Codex, запущенной вручную.

## Чего хотим

`shipctl check-run` запускает проверяющего в свежей сессии Codex, если
этот харнес указан в вердикте `agentctl check`. Проверяющий получает заказ
приёмки. Модель и усилие берутся из вердикта. Валидатор аудита проверяет
связь записей с кодом и принимает корректные доказательства этого ревью.

## DoD

- Профиля Codex без секции `[head]` достаточно для запуска через
  `shipctl check-run`.
- При закрытии задачи сессия проверяющего определяется по её собственному ID.
- Путь запуска для харнесов с секцией `[head]` продолжает работать.
- Валидатор принимает доказанное чтение окружения, связанную запись поля,
  чтение глобального значения в аргументе и точный составной путь файла.
  Чужое поле, недостижимое чтение и подменённый путь отклоняются.
