# DK-1750: shipctl check-run запускает отдельную приёмку в Codex

## Что происходит

20 ноября 2026 года `shipctl check-run DK-1748` завершился ошибкой.
Для приёмки требовалась свежая сессия Codex. При попытке запустить
проверяющего через `taskctl run` потребовалась секция `[head]`.
В профиле Codex такой секции нет. Сценарий удалось выполнить из отдельной
сессии Codex, запущенной вручную.

## Чего хотим

`shipctl check-run` запускает проверяющего в свежей сессии Codex, если
этот харнес указан в вердикте `agentctl check`. Проверяющий получает заказ
приёмки. Модель и усилие берутся из вердикта. Валидатор аудита проверяет
связь записей с кодом и принимает корректные доказательства этого ревью.

## DoD

- Профиля Codex без секции `[head]` достаточно для запуска через
  `shipctl check-run`.
- При закрытии задачи сессия проверяющего определяется по её собственному ID.
- Путь запуска для харнесов с секцией `[head]` продолжает работать.
- Валидатор принимает доказанное чтение окружения, связанную запись поля,
  чтение глобального значения в аргументе и точный составной путь файла.
  Чужое поле, недостижимое чтение и подменённый путь отклоняются.

## Ранг

`50+6+2+5+0 = 63`, P1.

- Серьёзность 50. Автоматическая приёмка останавливается. Для обхода нужно
  вручную запустить и учесть сессию.
- Ценность 6. Задета регулярная приёмка задач, для которых выбран Codex.
- Неопределённость 2. Причина найдена. Нужно проверить контракт запуска.
- Поправка на баг 5. Отказ воспроизведён командой на выкаченной сборке.
- Рычаг 0. Работа восстанавливает существующий сценарий приёмки.

## Ход работы

- Вычитка: 1 файл, 5 правок, 0 пометок, 2026-11-21.
- Запуск Codex вынесен в отдельный процесс с замком задачи и журналом. Отметка
  проверки получает ID потока Codex. Дальше нужны ревью и живой прогон после
  выката.

## Ревью

Уровень 2 до 002cbf2: Проверка отдельной сессии, стыка JSON, замка, остановки и независимости проверяющего

Проверить живым процессом: после «Стоп» группа завершена, замок снят и повторный автоматический запуск не происходит.: исправлено, Worker завершает группу и освобождает замок; dashboard ждёт освобождения, тестирует также отказ по сроку.

- [возврат: реализация, 2026-11-21] блокирует: проверяющий запускается без DEVKIT_CHAT_SESSION_ID, CLAUDE_CODE_SESSION_ID и DEVKIT_TMUX (checkcodex.go:154), а agentctl plan выбирает только эти переменные или явный --sid (tools/agentctl/plan.go:95-110) и не читает CODEX_THREAD_ID. ## Проверка

- Исключение: стенд (в work-plan уточнено описание переменных адреса. Порядок ведения плана остался прежним).

- `regcheck --base main --tests tools/shipctl/checkrun_test.go -- devkitctl test tools/shipctl -run '^TestCheckRunCodexEntry$' -v` подтвердил красный прогон на `main` и зелёный на исправлении. Тест запускает собранный `shipctl check-run --json`.
- `regcheck --base 0267dc92e --tests tools/shipctl/checkcodex_test.go -- devkitctl test tools/shipctl -run '^TestCodexCheckWorkerReportsLateLogFailure$' -v` подтвердил отказ старого кода и исправление. Тест разрывает журнал после подтверждения старта и проверяет сообщение системному журналу и завершение хода.
- `regcheck` для `TestCodexCheckWorkerStopsDescendant` подтвердил красный прогон на 7df2dd2a1 и зелёный на исправлении в 45a5da246. Тест проверяет завершение дочернего процесса, который игнорирует SIGTERM.
- Временное отключение ожидания замка дало код 200 вместо 503 в `TestRunStopCodexCheckerReportsUnreleasedLock`. После восстановления ожидания тест прошёл.

- Три изолированные мутации дали ожидаемый FAIL. Удаление ID Codex поймал
  `TestOwnCodexSession`, запись в чужой замок поймал
  `TestCodexCheckWorkerDoesNotDuplicate`, а подтверждение на `thread.started`
  без `turn.started` поймал `TestCodexCheckWorkerFailsBeforeTurn`.
- `regcheck` для `TestNameAssignmentRejectsUnrelatedFieldConsumer`
  дал красный прогон на e95588634 и зелёный после исправления. Собранный
  `taskctl` принял настоящее доказательство `planResolve` из этого ревью.

- `regcheck` на a3fad1ebf подтвердил прежний отказ для `fmt.Fprintf`.
  После исправления `taskctl` принял записи `logRun` и `appendRunLog`.
  Тест отклоняет чужой дескриптор и затенённый пакет `fmt`.
