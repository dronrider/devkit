# DK-1751: taskctl отклоняет доказательства операций Go и Python

## Что происходит

На снимке DK-1746 `c664f1328` проверка `STYLE-001` оставляет 24
цели без полного доказательства. Ещё три записи о чтении полей она отклоняет.
В Go вызывающий читает обновлённое поле через указатель или в следующем
вызове. В Python проверка записи попадает в разборщик Go. Результаты
вызовов Python, которые затем читаются, тоже требуют отдельной проверки.

Из-за этих отказов слияние восстановления чатов не проходит. Каждый
новый формат, добавленный в ветку DK-1746, попадает в тот же аудит.

## Чего хотим

Выпустить доработку `taskctl` отдельно. Для реальных примеров из DK-1746
сверять место записи, путь значения и потребителя по исходнику. При
отказе выводить место и причину, которую можно проверить по коду.

## Границы

Эта ветка меняет аудит и его тесты. Код восстановления и отчёт DK-1746
едут своей веткой после установки валидатора. Обязательные проверки
`meaning`, `result` и `writes` действуют в обоих случаях.
Для запуска, доступа и выката действуют штатные настройки devkit.

## DoD

- Оставшиеся 27 целей DK-1746 сгруппированы по фактическим причинам.
  Примеры, для которых нужен валидатор, воспроизводятся из тестов.
- Проверка Go подтверждает видимую связь записи с потребителем того же
  объекта. Подмена экземпляра, перезапись и недостижимое чтение дают отказ.
- Проверка Python подтверждает фактическую файловую цель, запись через
  дескриптор и используемое возвращаемое значение на примерах из
  восстановления. Подмена цели, переменной или вызываемой функции даёт отказ.
- Установленный `taskctl` проверяет контрольный набор из исходников Go и
  Python. Повтор на снимке DK-1746 показывает, какие записи приняты и по
  каким требуется правка доказательства или исходника.

`50+7+3+5+4 = 69`, P1.

- Серьёзность 50: обязательный аудит задерживает выкат восстановления чатов.
- Ценность 7: проверка позволяет оформить доказательства для рабочей ветки.
- Неопределённость 3: известны фактические места Go и Python, нужно проверить связь между вызовами.
- Поправка на баг 5: отказы воспроизводятся в штатном `taskctl`.
- Рычаг 4: те же формы понадобятся следующим задачам с правками Go и Python.

## Сценарий проверки

1. Прогнать проверку доказательств на Go и Python. У валидных примеров
   проходит запись о чтении того же поля, файловом назначении и
   результате вызова. Подмена экземпляра, пути, функции и недостижимое
   использование дают отказ.
2. Прогнать проверку записи вердикта через штатный вход `taskctl`.

```sh
devkitctl test internal -v -run '^(TestNamePython|TestNameAssignment|TestNameCallback|TestNameChain|TestReviewNameReachability|TestNameSystemFlock|TestNameHTTPJSON)'
devkitctl test tools/taskctl -v -run '^TestReviewCleanNewRoundCLI$'
```

3. После выката сверить версию установленного `taskctl`. В отдельном
   дереве DK-1746 повторить `taskctl review audit-record` с контрольными
   записями Go и Python. `audit-progress` должен показать, сколько целей
   закрыто и какие записи ещё требуют подтверждения.
