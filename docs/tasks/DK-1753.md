# DK-1753: Отчёт аудита сбрасывает обкатку задачи

## Что происходит

22 ноября `shipctl merge DK-1746` отклонил обкатку `cd4efa04f29a` на коммите `7ab8c8419`. Между ними изменились карточка и отчёт аудита DK-1746. Обкатка заново пишет карточку, а машинная проверка подписей требует, чтобы проверенное дерево совпадало с выпускаемым за пределами файла аудита. Задача застряла между двумя проверками.

## Чего хотим

Отчёт аудита текущей задачи можно зафиксировать после обкатки. Шлюз слияния сохраняет отметку свежести и отдельно проверяет сам отчёт. Изменённый сценарий проверяется по своему отпечатку.

## DoD

- Шлюз принимает отметку, когда после прогона появился отчёт `docs/tasks/<ID>.review-audit.json` этой задачи и записи доски. Контрольные случаи проверяют изменение исходника, сценария, JSON-фикстуры и отчёта другой задачи.
- Регрессионный тест воспроизводит отказ на прежнем коде. После выката штатный `shipctl` содержит исправленный шлюз.

## Ранг

`50+8+1+5+4 = 68`, P1.

- Серьёзность 50: слияние восстановления чатов Codex остановилось.
- Ценность 8: можно выпустить проверенный кандидат с подписанными наблюдениями.
- Неопределённость 1: причина найдена, два варианта шлюза проверены на `7ab8c8419`.
- Поправка на баг 5: отказ воспроизведён на опубликованной ветке.
- Рычаг 4: любой подписанный аудит после обкатки проходит тот же шлюз.

- Вердикт: без замечаний до 301e27b. Проверены архитектура, точный путь своего отчёта, контроль чужого отчёта и JSON-фикстуры, отдельный audit gate, регрессии и две мутации; audit-check --coverage пройден на 301e27b. Унаследованное послабление Markdown-файлов доски вне согласованной области.

## Сценарий проверки

1. Прогнать тесты свежести обкатки в чистом дереве. Тест с отчётом проверяемой задачи должен пройти. Контрольные тесты должны подтвердить отказ для других изменений.

```sh
devkitctl test internal -v -run '^TestFresh'

```

2. После выката сверить версию установленного `shipctl` с тегом `deployed` и повторить контрольную проверку.
