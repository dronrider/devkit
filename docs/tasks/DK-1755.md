# DK-1755: Доска тормозит при обновлении активных работ

## Что происходит

На живом дашборде 24 ноября 2026 года открытие и обновление доски
сопровождалось всплеском CPU до 190% и примерно 5 ГиБ резидентной памяти.
Для списка активных работ доска вызывает общий список app-server-чатов.
Один обход разбирает 35 лент объёмом 156 МиБ. Список проектов запускает
такой обход для каждой доски. Из метаданных разговора видны проект, задача
и тип работы. Состояние работы берётся у живого процесса и из замка.

## Чего хотим

Доска и список проектов собирают активные app-server-работы по состоянию
процессов и метаданным. Длинная история чата не замедляет этот запрос.

## DoD

- Доска показывает активные задачи и груминг своего проекта с прежними
  полями. Закрытые и чужие разговоры в список активной работы не попадают.
- Сбор активных работ обходится без открытия файлов ленты. Регрессионный
  тест фиксирует это на запросе доски.
- Для одного набора данных есть замеры времени ответа, процессорного
  времени и памяти до и после исправления.

## Ранг

`25+7+1+5+4 = 42`, P2.

- Серьёзность 25: доска отвечает, но регулярные обновления задерживаются.
- Ценность 7: доску открывают и обновляют в течение всего рабочего дня.
- Неопределённость 1: путь чтения найден, нужно проверить видимость работ.
- Поправка на баг 5: повторное чтение воспроизведено на живых данных.
- Рычаг 4: устраняется расход процессора и памяти у общих ручек дашборда.

## Ревью

Уровень 2 до a02d5ac: проверка штатных входов, выбора и порядка работ, снимка реестров и доступа к лентам

- Вердикт: без замечаний до a02d5ac. Сверены штатная выдача доски и общий путь списка проектов, поля, порядок и отбор живых работ, снимок реестров и отсутствие открытий лент. Regcheck красный на базе и зелёный на вершине, тест обнаружил восемь мутаций. Замеры HTTP 200 сверены с кодом стенда.

## Сценарий проверки

1. Запросить доску проекта с активной задачей, грумингом и старыми чатами.
   На исходном коде запрос открывает файлы лент. После правки тест проходит
   и в ответе остаются задача и груминг своего проекта с нужными полями.

   ```sh
   python3 tools/devkitctl/devkitctl.py test tools/dashboard -run '^TestBoardAppWorksWithoutFeedReads$' -v
   ```

2. Прогнать сквозную проверку бинаря дашборда на синтетическом проекте.
   Ожидаемый результат — `dashboard smoke: ok`. После выката сверить
   коммит запущенного дашборда по `/healthz` с установленным бинарём.

   ```sh
   DEVKIT_HOME="$PWD" dashboard smoke
   ```
