# DK-1757: Пульс повторно разбирает реестр сессий

## Что происходит

Обработчик `/pulse` обновляет кольцо задачи или открытого разговора.
В живом профиле 24 ноября 2026 года виден повторный разбор реестра сессий
при построении списка чатов. Обработчик собирает до 80 записей, а внутри
цикла для каждого чата снова читает и разбирает реестр целиком.

## Чего хотим

Обработчик `/pulse` один раз читает и разбирает реестр сессий за запрос.
Сведения о привязках и ожиданиях в ответе берутся из одного снимка.

## DoD

- Запросы пульса по задаче и по открытой сессии получают прежние состояния,
  порядок и привязки. Следующий запрос видит свежую запись реестра.
- Регрессионный тест на обработчике подтверждает один снимок реестра
  на запрос. Старый код воспроизводит повторное чтение.
- Для одинаковой нагрузки сняты время ответа, процессорное время и
  пиковая резидентная память до и после правки.

## Ранг

`25+6+2+5+3 = 41`, P2.

- Серьёзность 25: повторный разбор тормозит работающий экран.
- Ценность 6: пульс регулярно опрашивается при открытом чате.
- Неопределённость 2: нужно найти все обращения к реестру из обработчика.
- Поправка на баг 5: повторный разбор подтверждён профилем живого процесса.
- Рычаг 3: снижается нагрузка регулярного опроса на общий сервер.

## Ход работы

## Ревью

Уровень 2 до ccdbf11: Проверка HTTP-контракта, общего снимка и порядка строк двух журналов на базе 774c8b9a2 и вершине ccdbf11ce.

- Вердикт: без замечаний до ccdbf11. Проверены пульс по задаче, по сессии и с обоими параметрами, привязки и вопросы из одного снимка, равные метки журналов двух домов и свежесть следующего запроса. regcheck и обкатка ccdbf11ce прошли. Мутация выбора ручной привязки упала на HTTP-проверке. Замеры на идентичной нагрузке записаны в разделе «Проверка».

## Сценарий проверки

1. Запросить пульс по задаче, по сессии и с обоими параметрами.
   На исходном коде стенд фиксирует три или четыре чтения из каждого дома.
   После правки запрос читает файл каждого дома один раз. Тест проверяет
   порядок привязок, адресное ожидание и видимость свежей записи в
   следующем запросе.

   ```sh
   python3 tools/devkitctl/devkitctl.py test tools/dashboard -run '^TestPulse' -v
   ```

2. Выполнить сквозную проверку дашборда на синтетическом проекте.
   Ожидаемый результат — `dashboard smoke: ok`. После выката сверить
   коммит запущенного дашборда по `/healthz` с установленным бинарём.

   ```sh
   DEVKIT_HOME="$PWD" dashboard smoke
   ```

процессах с `GOMAXPROCS=2`. Каждый запрос получил HTTP 200, восемь
агентов задачи и состояние `working` открытого разговора.
