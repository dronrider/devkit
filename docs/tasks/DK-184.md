# DK-184: Скилл proofread для вычитки прозы с парами, словарём и сторожевым корпусом

записан 2026-08-12, первая задача реализации серии DK-173

## Постановка

Первая задача реализации принятого LLD `docs/lld/DK-173-agent-prose.md`.
Материал для пар и типологии лежит в исходном разборе
`docs/tasks/DK-173.md`: 16 примеров с комментариями пользователя и
выведенная из них типология из восьми повторяющихся проблем. Открытые
вопросы LLD решены пользователем 2026-08-08: словарь (а), «ярус» меняется
на «уровень» (б), эталон стиля при споре это норма жанра (а).

Создаётся новый скилл `kit/skills/proofread/`:

- `SKILL.md` с процедурой вычитки. На входе список файлов, вычитку гонит
  субагент со свежим контекстом, не тот, что писал текст, по тому же
  доводу, по которому ревью не отдают автору кода. Модель sonnet: haiku
  не вытягивает суждение о прозе, opus для страницы избыточен. На выходе
  правки формы прямо в файлах и короткий список помеченного, но не
  исправленного: спорные слова, кандидаты в словарь.
- Пары «плохо/хорошо» по восьми пунктам типологии из DK-173, по паре на
  пункт. Одна копия, в доку не дублируются.
- Словарь devkit: поезд, виток, лестница, накопитель, сторожок, заход,
  ворота, рубеж, дорезка. Вычитка помечает слово, которого нет ни в
  словаре, ни в общем техническом русском. Пополняет словарь
  пользователь.
- `corpus.md` со сторожевым прогоном: 16 фраз из DK-173. На плохой
  половине вычитка обязана дать находку по каждому пункту типологии, на
  эталонной, переписанные DK-089, DK-117 и DK-165 после калибровки,
  пройти почти без замечаний. Пороги вида «не меньше 14 находок из 16» и
  «не больше двух ложных на эталоне» фиксируются первым прогоном при
  реализации и записываются в сценарий проверки. Вычитка
  недетерминирована, требовать всех 16 из 16 значит сделать прогон
  плавающим.

Границы вычитки записаны в самом скилле: правится форма, а факты, числа,
ID задач, команды, пути и термины словаря не трогаются. Изменение смысла
при вычитке это порча, а не редактура.

Правки в долгоживущей доке:

- `RULES.core.md`, раздел «Мимикрия»: одна строка, долгоживущий текст
  перед коммитом проходит вычитку скиллом `proofread`;
- `RULES.md`, разбор мимикрии: ссылка на скилл и фраза про одну копию
  пар;
- `README.md` devkit, список скиллов: строка про `proofread`.

Формат следа отработки живёт в самом скилле и пишется в раздел «Ход
работы» файла, к которому относится текст: «Вычитка: 2 файла, 5 правок,
1 пометка, ГГГГ-ММ-ДД». Строка пишется и при нуле правок, иначе чистый
текст неотличим от пропущенного вызова.

В эту задачу не входят точки вызова, правка `board-ship`, определения
`review-*` и `exec-xhigh`, `board-groom`, нарезка `goal-loop`, и заход по
написанному. То и то отдельные задачи серии [DK-185], [DK-186], [DK-187],
они идут после этого скилла.

## DoD

Скилл `proofread` лежит в `kit/skills/`, вызывается списком файлов и
правит форму по типологии DK-173, не трогая факты, команды и термины
словаря. Сторожевой прогон по `corpus.md` держит порог, зафиксированный
первым прогоном и записанный в сценарии проверки. В `RULES.core.md`,
`RULES.md` и `README.md` лежат соответственно строка про вычитку, ссылка
на скилл и пункт списка скиллов. Тест по стандарту devkit на сторожевом
корпусе; сценарий проверки пишет исполнитель.
