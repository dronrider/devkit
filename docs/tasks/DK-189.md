# DK-189: Секция харнеса без ярусов глушит предложение маппинга из профиля

записан 2026-08-08

## Что происходит

Окно запускатора (сессия с DEVKIT_HARNESS=glm-code) получало от pick вердикт
с model: - и via: -. Машинная секция [glm-code] несла одну обвязку (home,
env), что законно по DK-177, но предложение маппинга `map_*` из профиля
включается только когда машинного конфига нет вовсе (mergeLayers в
tools/agentctl/harness.go, ветка mdoc == nil) и только для claude-code.
Активный харнес с секцией-обвязкой остаётся без лестницы, хотя его профиль
несёт полный `map_*`.

Хинт при этом обманчив: «харнес glm-code не настроен, маппинга ярусов нет;
вписать секцию [glm-code] в ~/.devkit/harness.local», хотя секция стоит, не
хватает ярусов.

Воспроизведено на грумминге 2026-08-08: синтетический harness.local, где
[glm-code] несёт один home, и `agentctl harness` под DEVKIT_HARNESS=glm-code
печатает «маппинг ярусов: не задан, харнес ненастроен; вписать секцию
[glm-code]». На машине обойдено явными ярусами в [glm-code] по предложению
профиля. Найдено в первом живом окне shipctl code (IRC-097).

## Чего хотим

Секция без ярусов не выключает предложение профиля для активного харнеса:
маппинг `map_*` разворачивается предложением с пометкой Suggested, как при
отсутствии машинного конфига, либо хинт называет недостающие ключи вместо
совета вписать уже стоящую секцию. Какая половина едет в правку (предложение,
честный хинт или обе) решается на исполнении.

## DoD

- На машинном конфиге, где секция активного харнеса стоит без ярусов, вердикт
  pick не остаётся с прочерками: либо модель развёрнута предложением профиля
  и `agentctl harness` называет источник маппинга, либо хинт перечисляет
  недостающие ключи ярусов.
- Регрессионный тест падает на старом коде, проверено прогоном regcheck.
