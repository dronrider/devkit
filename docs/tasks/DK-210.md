# DK-210: doctor --fix сам переносит рукописный CLAUDE.md в AGENTS.md

записан 2026-08-09

## Что происходит

Проект, подключённый до переезда на AGENTS.md, несёт рукописный CLAUDE.md со
старой дорогой `@../devkit/RULES*.md`, которая до контекста не доезжает.
Доктор это видит, но сам не чинит: печатает подсказку про `git mv CLAUDE.md
AGENTS.md`, правку импортов руками и повторный `--fix` (rules.py:1028,
README devkitctl, раздел про поведение доктора). На раскатке DK-204
(2026-08-09) эти три ручных шага повторялись на каждом из трёх проектов
(goonies, it-road-course, xr-proxy), и все три файла разбирались без остатка.
Осторожность оправдана только для файла с неопознанными строками вроде
корп-импорта `@../devkit/RULES.local.md`: такие у восьми корп-клонов, и им
отказ нужен по-прежнему.

## Чего хотим

`doctor --fix` переносит рукописный CLAUDE.md в AGENTS.md сам, когда файл
разбирается без остатка: каждая строка либо известный импорт devkit
(`@../devkit/RULES*.md` и подобные, генератор выпишет их заново через
ссылку), либо проза, едущая в AGENTS.md как есть. Перенос идёт через git
(история файла сохраняется), следом обычная генерация тонкого файла.
Неопознанная строка, как и файл вне индекса (корп-клон со спрятанным
CLAUDE.md), это отказ с сегодняшней подсказкой.

## DoD

На синтетическом проекте с рукописным CLAUDE.md из известных импортов и
прозы один прогон `doctor --fix` оставляет AGENTS.md с прозой, генерённый
тонкий CLAUDE.md со ссылкой и молчащего доктора. Файл с неопознанной строкой
не тронут, находка с подсказкой на месте. Оба случая покрыты тестами, README
devkitctl описывает границу переноса.
