# DK-215: LLD дашборда: границы сервер-клиент, API, аутентификация, раскладка кода

записан 2026-08-09

Задача цели DK-112 ([DK-112.md](DK-112.md)), первая строка нарезки.

## Чего хотим

Дизайн дашборда до кода, документом `docs/lld/DK-112-dashboard.md`. Крупное
постановка цели уже решила: Go-сервер с вшитой статикой компонентом devkit,
источник правды это доска и taskctl/agentctl/shipctl, своей базы нет, канал
вынесен в решение выката, признак проекта `docs/TASKS.md`. LLD снимает
развилки уровнем ниже и по каждой кончается решением с причиной, а не веером
вариантов: это задача проектирования внутри цели, выбор делается здесь, а
исполнителям остаются детали реализации.

Развилки, которые LLD обязан закрыть:

- граница сервер-клиент: что считает сервер, что рисует клиент, из чего
  собирается вшитая статика без внешних зависимостей;
- состав API под все экраны цели: проекты и доска, запуск и стоп, живой
  статус (журнал витка, транскрипт, tmux), переписка через состояние цели,
  правка строки и файла задачи, зависимости, лента уведомлений;
- аутентификация: механизм входа, где живёт секрет, как он попадает на машину
  и что происходит при утечке; дашборд исполняет код на машине и сетевому
  периметру не доверяет ни при каком канале;
- как сервер берёт данные: подпроцессы taskctl/agentctl/shipctl против чтения
  файлов напрямую, и где граница между этими способами;
- раскладка кода по README «Раскладка»: имя инструмента в `tools/`, язык go,
  место статики и способ её вшивания;
- конфиг дашборда: формат списка корней поиска проектов и где он лежит;
  переезд списка в машинный конфиг при появлении DK-042 постановкой уже
  решён, LLD выбирает только форму до переезда;
- запуск на машине и выкат: кто держит процесс, как правка доезжает командой
  deploy и чем работа видна снаружи (журнал, health-эндпоинт).

## Сценарий проверки

Пользовательский: дизайн проверяется чтением. Прочитать
`docs/lld/DK-112-dashboard.md` и убедиться, что по каждой развилке из списка
выше стоит решение с причиной, вееров вариантов нет, а решения не расходятся
с постановкой цели. Стоп плановый и стоит в начале серии, в хвост его не
увести: без решений LLD не стартует ни одна строка состава. Посиделка
совмещается с проверкой экранов DK-216.
