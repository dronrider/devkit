# DK-217: Каркас дашборда: сервер с аутентификацией и доска проектов на чтение [после DK-215, DK-216]

записан 2026-08-09

Задача цели DK-112 ([DK-112.md](DK-112.md)).

## Чего хотим

Первый живой срез дашборда: Go-сервер с вшитой статикой по раскладке из
DK-215, вход по своей аутентификации, доска на чтение. Сервер читает список
корней из конфига, проектом считает каталог с `docs/TASKS.md`, доску и
статусы берёт через taskctl тем способом, который назвал LLD, своей базы нет.
Экран доски по макету DK-216: задачи и цели со статусами нескольких проектов,
видно, что сейчас в работе. Правок доски в этом срезе нет.

Состав:

- инструмент в `tools/` под именем из LLD, go, статика вшита в бинарь;
- вход по механизму из LLD, без входа не отдаётся ни одной строки данных;
- API на чтение: список проектов, доска проекта со статусами и текущими
  работами;
- экран доски под телефон и ноутбук;
- конфиг корней, запуск процесса и выкат по решению LLD; нехватку раскладки
  называет диагностика, а не молчание.

После слияния и выката дашборд стоит на машине и отвечает из домашней сети с
телефона: наблюдение за агентами работает само по себе, и цикл может встать
на любой следующей строке без полуфабриката на проде.

## Ранг

`25+8+3+0+4 = 40`, P2.

- Серьёзность 25 (Major). Первая половина основного сценария цели: доска
  видна без машины. Обход есть, сидеть за машиной, поэтому Major, а не
  Critical.
- Ценность 8. «Видно, над чем агенты работают прямо сейчас» это первый пункт
  цели, ради наблюдения она и затевается.
- Неопределённость 3. Подход решён LLD, но правка пересекает границу
  сервер-клиент, порог RANKING.md: развилки стыка видны живым прогоном, а не
  чтением исходников.
- Поправка на баг 0. Новая работа.
- Рычаг 4. Сервер, вход, статика и конфиг это каркас, на котором едут все
  следующие срезы, каждая задача серии дешевле.

## Сценарий проверки

Агентский.

1. Собранный дашборд поднимается на свободном порту с конфигом, где корень
   поиска указывает на временный каталог с синтетическим проектом (фикстурная
   `docs/TASKS.md`); окружение задаётся явно, живая доска не участвует.
2. Запрос без входа получает отказ (код по решению LLD: 401 или редирект на
   вход), в теле нет ни одной строки доски.
3. После входа API проектов отдаёт синтетический проект, API доски отдаёт его
   задачи со статусами, коды 200, строки сверяются с фикстурой командой.
4. Экран доски отдаётся тем же сервером из вшитой статики, в HTML нет ссылок
   на внешние хосты (греп по ответу).
5. На проде без правок: GET к стоящему на машине дашборду после входа отдаёт
   живую доску devkit, шаги ничего не меняют.
