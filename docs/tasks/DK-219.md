# DK-219: Живой статус агента в дашборде: журнал витка, транскрипт, tmux [после DK-217]

записан 2026-08-09

Задача цели DK-112 ([DK-112.md](DK-112.md)).

## Чего хотим

Экран живого статуса агента: чем он занят прямо сейчас. Источники решены
целью: журнал витка `.devkit/goal-<ID>.log` (после DK-117 он наполняется по
ходу, а не по концу), транскрипт сессии
`~/.claude/projects/<проект>/<сессия>.jsonl`, tmux-сессии. Сервер читает их с
диска и отдаёт хвост журнала, реплики транскрипта и список сессий, экран по
макету DK-216. Транскриптное API дальше переиспользует переписка DK-220.

## Ранг

`25+8+3+0+2 = 38`, P2.

- Серьёзность 25 (Major). Что делает агент, сегодня видно только с машины;
  обход есть, трение основного сценария наблюдения заметное.
- Ценность 8. Честная оценка 7: по живому статусу решается, вмешиваться или
  ждать, но доска со статусами уже стоит соседней задачей, это углубление. До
  8 слагаемое подтянуто инвариантом зависимости под переписку DK-220 (38),
  которая без транскриптного API не начинается.
- Неопределённость 3. Граница сервер-клиент и чужие форматы на входе: jsonl
  транскрипта, журнал оболочки, вывод tmux.
- Поправка на баг 0. Новая работа.
- Рычаг 2. Транскриптное API переиспользует переписка DK-220, небольшая своя
  польза вперёд.

## Сценарий проверки

Агентский.

1. В подставном HOME лежат фикстуры: журнал витка, транскрипт jsonl с парой
   реплик, tmux-сессия поднята с известным именем.
2. API журнала отдаёт хвост фикстурного журнала, строки сверяются командой.
3. API транскрипта отдаёт последние реплики, ход агента и его ответы, поле в
   поле с фикстурой.
4. API tmux называет поднятую сессию.
5. Экран живого статуса отдаётся из вшитой статики и зовёт только свои API,
   внешних хостов в статике нет (греп).

## Ход работы

- Исполнение: субагент fable/high по вердикту pick (маппинг opus, корректор: профицит week_all, week_max; квота: week_all 95% профицит, week_max 83% профицит, снимок 0м назад), 2026-08-10.
- Ветка dk-219 подтянута fast-forward до main (уехал вперёд на серию DK-119),
  до первого коммита задачи.
- Три ручки живого статуса: хвост журнала цикла с SSE-дострением
  (`/goals/{id}/log`, опрос файла раз в секунду по LLD), сессии и лента
  реплик транскрипта (`/sessions`, `/sessions/{sid}` с `?before=` и
  `?stream=1`), список tmux-сессий и снимок пейна (`/api/tmux`,
  `/api/tmux/{name}`). Разбор jsonl общим куском parseReplies под
  переиспользование перепиской DK-220.
- Каталог транскриптов кодируется как у Claude Code: дефисом заменяется любой
  символ кроме букв и цифр, а не только слэш; ветки субагентов (isSidechain)
  и служебные записи в ленту не попадают, размышления сворачиваются в пометку
  без текста. Уточнения записаны в LLD.
- Живой tmux 3.7b на цель `=имя` без двоеточия отвечает «can't find pane»:
  capture-pane ждёт цель-пейн, точное имя сессии передаётся как `=имя:`.
  Поймано прогоном сценария на настоящем tmux, фикстурный тест сверяет
  аргументы вызова.
- Экран «03 Агент» в вшитой статике: хэш `#проект/agent/DK-NNN`, переходы с
  карточек живых работ доски и кнопкой с экрана задачи; на ноутбуке журнал и
  транскрипт рядом, tmux полосой внизу, на телефоне те же панели табами.
  Потоки и таймер снимка закрываются при уходе с экрана. Пустоты названы
  словами: журнала нет, транскриптов нет, tmux-сессия не найдена.
