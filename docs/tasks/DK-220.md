# DK-220: Переписка с агентом через состояние цели [после DK-219]

записан 2026-08-09

Задача цели DK-112 ([DK-112.md](DK-112.md)).

## Чего хотим

Переписка так, как решила цель: ход и ответы читаются из транскрипта сессии
(API из DK-219), а сообщение человека дашборд кладёт в состояние цели, откуда
его берёт следующий виток. Писать в идущий процесс цель не берётся, механики
для этого в devkit нет, двусторонний живой чат остаётся черновиком DK-136.

В задачу входит и сторона витка: goal-loop читает сообщение из состояния цели
и отдаёт его витку, формулировка держится тестами скилла. Формат и место
записи назвал LLD DK-215. Экран переписки по макету DK-216, с честной
надписью, что сообщение уйдёт следующему витку.

## Ранг

`25+8+3+0+2 = 38`, P2.

- Серьёзность 25 (Major). Ответ на wait-human сегодня требует сесть за
  машину; обход есть, но это трение ровно того сценария, ради которого цель
  затевалась.
- Ценность 8. Шаг DoD «отправить сообщение агенту и увидеть его подхваченным»
  и главный смысл управления с любого устройства: цель спрашивает, человек
  отвечает откуда угодно.
- Неопределённость 3. Граница сервер-клиент плюс стык с goal-loop: формат
  сообщения, порядок чтения витком, гонка с идущей записью состояния.
- Поправка на баг 0. Новая работа.
- Рычаг 2. Механика «сообщение в состоянии цели» пригодится и вне дашборда,
  ответ витку можно будет класть любым инструментом; польза своя и небольшая.

## Сценарий проверки

Агентский.

1. На синтетической цели (временный HOME, фикстурный файл цели) отправка
   сообщения через API отвечает 200, текст лежит в состоянии цели ровно в том
   месте и формате, которые читает виток; сверка файлом.
2. Тесты goal-loop держат формулировку про чтение сообщения из состояния
   цели, прогон зелёный.
3. Экран переписки показывает ход из фикстурного транскрипта и отправленное
   сообщение с пометкой, что оно уйдёт следующему витку.
4. Сквозной подхват живым витком проверяет smoke DK-222, здесь прод не
   трогается.
