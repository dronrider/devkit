# DK-221: Правка задачи и цели с дашборда, зависимости в обе стороны [после DK-217]

записан 2026-08-09

Задача цели DK-112 ([DK-112.md](DK-112.md)).

## Чего хотим

Правка задачи и цели с дашборда: заголовок, слагаемые ранга, цена, файл
задачи. Зависимости видны наглядно и в обе стороны: кого ждёт строка и кто
ждёт её. Правки идут через taskctl (`set`, `dep`), а не мимо него: доска
остаётся источником правды, порядок строк выводится из ранга по RANKING.md,
произвольного перетаскивания мимо ранга нет. Экран задачи по макету DK-216.

## Ранг

`25+5+3+0+2 = 35`, P2.

- Серьёзность 25 (Major). Груминг и переранжировка без этой задачи требуют
  сесть за машину; обход дешёвый и очевидный, но трение сидит в заявленном
  сценарии полного управления.
- Ценность 5. Ощутимое удобство: бэклог разбирается с телефона. Наблюдение и
  запуск к этому моменту закрыты соседними строками, это углубление, а не
  ядро цели.
- Неопределённость 3. Граница сервер-клиент, свои развилки на стыке с доской:
  конкуренция с параллельной правкой доски идущим циклом, чем отбивается
  кривая разбивка ранга.
- Поправка на баг 0. Новая работа.
- Рычаг 2. Разобранный по дороге бэклог ускоряет следующий состав работ,
  польза своя и небольшая.

## Сценарий проверки

Агентский.

1. На синтетической доске правка заголовка, разбивки ранга и цены через API
   отвечает 200, строка изменена (`taskctl show`), сумма R и бакет P
   пересчитаны.
2. После правки ранга порядок в ответе API доски отсортирован по рангу;
   запроса «поставить строку на место N» у API нет.
3. API зависимостей на фикстуре с цепочкой A -> B -> C называет для B обе
   стороны: ждёт A, держит C.
4. Правка файла задачи через API доезжает до `docs/tasks/<ID>.md` фикстуры и
   видна повторным чтением.
