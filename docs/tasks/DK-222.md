# DK-222: Лента уведомлений дашборда и smoke агентской части DoD [после DK-218, DK-220]

записан 2026-08-09

Задача цели DK-112 ([DK-112.md](DK-112.md)).

## Чего хотим

Живая лента уведомлений в дашборде: стоп агента, wait-human, завершение
задачи. События сервер берёт из тех же источников, что живой статус (какие
именно, решил LLD DK-215), лента обновляется без перезагрузки страницы. Канал
наружу остаётся в пределах выбранного доступа, новых каналов задача не
заводит.

Второй частью едет сквозной smoke агентской части DoD цели: скрипт через API
дашборда получает доску со статусами и текущими работами, запускает задачу и
останавливает её, отправляет сообщение и видит его подхваченным следующим
витком, ловит уведомление о стопе и печатает «dashboard smoke: ok». Отдельной
строкой smoke не оплачивал бы круг конвейера, а уведомления это последний
кусок, которого он ждёт; дальше он остаётся сторожем дашборда.

## Ранг

`25+7+3+0+3 = 38`, P2.

- Серьёзность 25 (Major). Стоп агента и wait-human без уведомления это
  молчание: о стоящем цикле пользователь узнаёт, сев за машину. Обход есть,
  трение заметное.
- Ценность 7. Последний экран DoD; без ленты управление между заходами в
  дашборд слепое.
- Неопределённость 3. Граница сервер-клиент плюс живая доставка событий:
  источник, поток без перезагрузки; что вылезет, покажет прогон.
- Поправка на баг 0. Новая работа.
- Рычаг 3. Smoke закрывает агентскую часть DoD и дальше сторожит каждую
  правку дашборда, проверка следующих задач дешевле.

## Сценарий проверки

Агентский. Прогон smoke на синтетическом проекте (временный HOME, свой
корень, фикстурная цель): доска -> запуск -> сообщение -> стоп -> уведомление
о стопе в ленте; скрипт печатает «dashboard smoke: ok» и выходит 0. Отдельным
шагом лента получает событие без перезагрузки страницы, доставка проверяется
командой по потоку, а не глазами. Живая доска в шагах не участвует, прод не
меняется.
