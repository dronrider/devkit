# DK-223: Заход извне и проверка дашборда с телефона [после DK-219, DK-222]

записан 2026-08-09

Задача цели DK-112 ([DK-112.md](DK-112.md)), замыкающая строка серии.

## Чего хотим

Последний шаг цели: дашборд открывается с телефона извне домашней сети, и
пользователь проходит экраны доски, живого статуса, переписки и уведомлений.
Канал это решение выката, а не архитектуры: заход извне даёт браузерный вход
xr-proxy (XR-252 на доске XR), дома хватает адреса машины в своей сети. В
задаче само подключение дашборда за канал (конфигом выката, без правок
архитектуры) и пользовательская проверка по DoD.

Внешняя предпосылка: XR-252 живёт на чужой доске, и это единственное место
цели, зависящее от неё. Пока XR-252 не закрыта, задачу не брать; взятая и
упёршаяся в канал строка уходит в Blocked по правилам доски. Сам дашборд
каналонезависим и ведётся параллельно, этой строки он не ждёт.

## Ранг

`25+6+3+0+0 = 34`, P2.

- Серьёзность 25 (Major). Обещание цели «с любого устройства» без захода
  извне выполняется только дома; обход есть (домашняя сеть, машина), полоса
  Major.
- Ценность 6. Ощутимое: дашборд начинает работать из любой точки, а не
  только из своей сети.
- Неопределённость 3. Стык с чужим каналом: xr-proxy, VPS, браузерный вход.
  Развилки сидят на границе и видны живым прогоном.
- Поправка на баг 0. Новая работа.
- Рычаг 0. Замыкающий шаг, дальше ничего не разблокирует.

## Сценарий проверки

Пользовательский, ровно DoD цели: с телефона вне домашней сети (мобильная
сеть, VPN выключен) открыть адрес дашборда через браузерный вход xr-proxy,
войти по аутентификации дашборда, пройти экраны доски, живого статуса,
переписки и уведомлений; каждый экран живой и показывает данные машины. На
этой проверке цикл штатно останавливается и зовёт человека.

## Ход работы

- Исполнение: субагент opus/high по вердикту pick (квота: week_all 4%, week_max 4%, снимок 0м назад, сдвига нет), 2026-08-10.
- Разобран канал: XR-252 это дизайн, работает реализация XR-262..XR-264.
  Наружу сервис выставляется публикацией агента шар xr-proxy
  (`xr-share expose add --name <имя> --upstream 127.0.0.1:7112`), соединение до
  VPS держит сам агент изнутри, фронт входа проксирует по имени публикации в
  поддомене. Со стороны devkit подключению не нужно ни строки конфига: адрес
  апстрима живёт в конфиге агента xr-proxy.
- Найдено на стыке и починено правкой: посредник переписывает `Host` на адрес
  апстрима, а внешнее имя кладёт в `X-Forwarded-Host`, и сверка `Origin`
  дашборда сходиться переставала. За каналом это отказ не в правках, а в самом
  входе: `POST /api/login` отвечал бы «чужой Origin», и с телефона дальше
  страницы логина было бы не пройти. `externalHost` берёт имя из
  `X-Forwarded-Host`, тесты `TestLoginOriginForwardedHost`,
  `TestLoginForeignOriginBehindProxy` и `TestExternalHost`; краснота на старом
  коде проверена regcheck.
- Проверено живьём на машинном конце: сервер с ветки поднят на временном доме,
  запрос с набором заголовков посредника (`Host: 127.0.0.1:<порт>`,
  `X-Forwarded-Host: dash.entry.example`, `Origin: https://dash.entry.example`)
  проходит вход с кодом 200 и кукой, а тот же запрос с `Origin` чужой страницы
  получает 403. Прогон дашборда целиком зелёный.
- Дока: раздел «Заход извне» в `tools/dashboard/README.md` (цепочка ролями
  машин, шаги подключения, две команды проверки живости через `secretctl`),
  абзац следствия в LLD.
- Осталось человеку, и без этих прав канал не поднять: поставить на машину
  агент шар xr-proxy с `--features relay`, привязать его к хабу рег-токеном из
  админки и поднять автозапуском (нужен root), завести публикацию на 7112,
  выпустить на VPS RU сертификат на имя публикации и добавить правило фронта.
  Дальше положить в хранилище `secretctl` имена `DASHBOARD_ENTRY` (адрес входа)
  и `DASHBOARD_ENTRY_PASSWORD` (пароль владельца), прогнать обе команды
  проверки из README и пройти сценарий с телефона.
- Ревью: субагент sonnet/high по вердикту pick (квота: week_all 4%, week_max 4%, снимок 18м назад, сдвига нет), 2026-08-10.
