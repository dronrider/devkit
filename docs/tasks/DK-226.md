# DK-226: secretctl: имена агенту, значение в подпроцесс через два бэкенда

Задача цели DK-207. Принцип цели переворачивает работу с секретами: модель
оперирует именами, а значение в момент исполнения подставляет утилита.
secretctl и есть эта утилита. Образец для неё trackctl, где token_env и
token_file уже подставляют токен в HTTP-вызов, не показывая значение агенту
(`tools/trackctl/contour.go:171-187`), и ошибка там называет имя переменной, а
не значение (`contour.go:176`).

## Что делается

Go-утилита в `tools/secretctl/`, собирается выкатом devkit автоматически по
`go.mod` (`tools/devkitctl/build.py:46-48`). CLI строится по `flag.NewFlagSet`
на подкоманду, как в trackctl (`tools/trackctl/main.go:111-151`). Две команды:

- `secretctl names` перечисляет имена секретов хранилища, по одному на строку,
  без значений;
- `secretctl exec <имя> -- <команда> [аргументы...]` запускает команду в
  подпроцессе, подставив значение секрета в его окружение: имя переменной
  окружения равно имени секрета. Значение в stdout самой secretctl не попадает.

Команды, печатающей значение секрета в stdout, у утилиты нет. Это закреплено
тестом: обходом всех подкоманд с запросом значения ни одна не выводит его в
свой stdout.

Бэкенда два, выбор по окружению: macOS Keychain через `security` CLI (образца в
trackctl нет, делается с нуля), когда Keychain доступен; файлы с правами 0600 в
любом другом случае, формат по образцу token_file.

## DoD

- `go build ./tools/secretctl/...` проходит;
- `go test ./tools/secretctl/...` проходит, в их числе тест «обход подкоманд не
  печатает значение в stdout» и тест «exec подставляет значение в env
  подпроцесса»;
- `secretctl names` перечисляет имена, `secretctl exec` подставляет значение в
  переменную окружения подпроцесса (подтверждается подпроцессом, который
  печатает свою переменную окружения).

## Сценарий проверки

Агентский.

    go test ./tools/secretctl/...

Тесты прошли; среди них exec подставляет значение в env подпроцесса, names
печатает только имена, обход подкоманд с запросом значения не выводит его в
stdout.

    devkitctl build

secretctl входит в собранный тарболл утилит.

## Развилки

Выбор между `security` CLI и go-keychain берёт исполнитель. Критерий: работает
на голой macOS без сторонних зависимостей, поскольку devkit держит принцип
запуска на пустой машине. Формат файлового хранилища и правило «имя секрета
равно имени env-переменной» зафиксированы выше, отступать от них нельзя: на них
держатся задачи переезда (DK-227) и чистки allow-правил (DK-229).
