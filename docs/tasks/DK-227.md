# DK-227: Значения секретов переезжают из access.local.md в secretctl

Задача цели DK-207, после утилиты DK-226. Сегодня доступы лежат одним открытым
файлом `~/.claude/access.local.md`, который агент читает целиком, и значения
оказываются в контексте. Формат Markdown, значения в прозе и блоках кода:
Telegram-бот token и chat_id, Jira PAT, Confluence PAT, GitLab PAT, GitHub PAT,
z.ai API key, плюс около десятка инфраструктурных адресов и IP.

## Что делается

Значения секретов переезжают в хранилище secretctl, файл остаётся с именами
секретов и служебной прозой (адреса машин, роли, команды), значений там нет.
Переезд идёт через `secretctl exec`, который подставляет значение, либо
одноразовым мигратором, оформленным как скрипт в `local-docs` (в коммит он не
едет, как и сами значения). Имена секретов в хранилище берутся такими, чтобы
имя переменной окружения читалось естественно (`JIRA_PAT`, `CONFLUENCE_PAT`,
`GITLAB_PAT`, `GITHUB_PAT`, `ZAI_API_KEY`, токен и chat_id Telegram).

IP-адреса и имена машин пограничны: `check-sensitive` ловит их как секрет, но
они не токены. Переезд их в secretctl или маскировка в файле на усмотрение
исполнителя, критерий один: греп `check-sensitive` по файлу молчит.

## DoD

`python3 hooks/check-sensitive.py ~/.claude/access.local.md` выходит нулём: в
файле остались имена секретов и проза, значений нет. То, что значения живы и
доступны через `secretctl exec`, проверяется подстановкой в тестовую команду.

## Сценарий проверки

Агентский.

    python3 ~/projects/devkit/hooks/check-sensitive.py ~/.claude/access.local.md
    => exit 0

Значения токенов отсутствуют, имена и проза на месте. Значения доступны через
secretctl, проверкой подстановки в env тестовой команды.

## Развилки

Если `check-sensitive` к моменту задачи ещё не расширен скоупом паттерном
корп-доменов (DK-230), это на прогон не влияет: прямой вызов проверяет любой
файл, скоуп доски тут ни при чём. Состав секретов и их имена уточняются по
файлу доступов на момент исполнения.

## Ревью

- Процесс миграции: на первичном зонде access.local.md редуктор пропустил три значения (GitLab PAT без префикса, z.ai-ключ, chat_id), их фрагменты ушли в контекст исполнителя. В отчёт значения не выводились, финальное состояние (значения переехали из файла в хранилище) эту утечку закрывает, но постановка цели DK-207 «секреты не попадают в контекст» в процессе нарушена. Исход: правки в ветке не требует, утечка закрыта финальным состоянием. Рекомендация вперёд: миграция секретов идёт без чтения значений инструментами модели вообще, парсер-мигратор запускается и работает в подпроцессе, чей вывод с контекстом не пересекаются; а редуктор зонда режет любое backtick-значение и длинную alnum-цепочку, а не только паттерны check-sensitive.: отклонено, процессное замечание без правки ветки; рекомендация принята, фиксируется в журнале цели DK-207, отдельная задача по усилению редуктора зонда и подходу миграции заводится отдельно
