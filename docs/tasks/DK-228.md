# DK-228: Рубеж чтения секретов: permissions.deny и PreToolUse-хук на Bash

Задача цели DK-207, после утилиты DK-226. Защита односторонняя: `check-sensitive`
режет секрет на записи в коммит, а чтение файла доступов через `Read` или
`cat` не закрыто ничем, и значение уезжает в контекст модели в обратном
направлении. После DK-226 у агента есть secretctl, поэтому рубить чтение можно,
не оставляя его без средства получить значение.

## Что делается

Два слоя на одних и тех же путях:

- `permissions.deny` в `~/.claude/settings.json` режет инструмент `Read` на
  `~/.claude/access.local.md`, каталог `local-docs`, приватные ключи (`~/.ssh`)
  и файловое хранилище secretctl. Сегодня ключ `deny` в настройках отсутствует,
  его надо завести;
- `PreToolUse`-хук режет чтение тех же путей через `Bash`, перехватывая
  `cat`, `grep`, `less`, `head`, `tail` и подобное в `tool_input.command`.
  PreToolUse-хуков сегодня нет вообще: генератор `HOOK_LAYOUT` знает только
  PostToolUse (`tools/devkitctl/devkitctl.py:145-156`), а `hooks/hookio.py`
  разбирает только write-события Edit/Write/Notebook. Разбор `Bash`-команды и
  матчинг путей в ней делаются с нуля.

Хук пишется на python в `hooks/`, по каркасу `check-symbols.py` и
`check-sensitive.py` (те же три режима вызова, `Reply(2)` для блокировки,
`hookio.py:108`). Генератор `HOOK_LAYOUT` расширяется веткой PreToolUse и
установкой (пример установки PostToolUse в `devkitctl.py:938-953`).

## DoD

- в `permissions.deny` стоят правила `Read` на файл доступов, `local-docs`,
  приватные ключи и хранилище secretctl, греп настроек их находит;
- `PreToolUse`-хук подключён в `~/.claude/settings.json` и в `HOOK_LAYOUT`,
  прогон хука на `cat ~/.claude/access.local.md` блокирует операцию (exit 2);
- установка и работа хука проверены прогоном `devkitctl doctor` без находок по
  этой части.

## Сценарий проверки

Агентский. Попытка чтения файла доступов через `Read` отклоняется настройкой
deny, через `cat ~/.claude/access.local.md` отклоняется PreToolUse-хуком
(exit 2). Значение при этом доступно через `secretctl exec`, что и подтверждает
связку: рубится только прямой доступ к значениям, не работа с секретом вообще.

    python3 ~/projects/devkit/hooks/<хук>.py --hook < sample-bash-event.json
    => exit 2, команда с путём к файлу доступов блокируется

Регресс-тест на хук пишется по образцу `check_sensitive_test.py`: подаёт
`--hook` с событием чтения секретного пути, ждёт exit 2; подаёт событие с
нейтральной командой, ждёт проход.

## Развилки

Матчинг путей в `Bash`-команде ненадёжен по природе: подстановки, переменные,
кавычки, пайпы. Берётся надёжный минимум: разворот `~`, сравнение с эталонными
путями и их префиксами, без попыток интерпретировать shell полностью. Как
делят ответственность deny (инструмент `Read`) и хук (чтение через `Bash`)
зафиксировано выше: deny режет свой инструмент, хук прикрывает обход через
shell.
