# DK-230: check-sensitive: скоуп шире доски и паттерн корп-доменов, obeycheck

Задача цели DK-207. `check-sensitive` сегодня держит скоуп путей доски:
проверяет только `docs/TASKS.md`, `docs/TASKS-archive.md`, `docs/tasks/`,
`docs/lld/` (`hooks/check-sensitive.py:28`, `BOARD_PARTS`). Секрет, попавший в
другой коммитимый файл, проходит мимо. Корп-домен как отдельный паттерн тоже
отсутствует, хотя именно им заражён публичный `RULES.core.md`.

## Что делается

Скоуп `check-sensitive` расширяется за пределы путей доски: проверяется любой
файл, идущий в коммит (или явно оговорённый набор контуров), не только доска и
LLD. Добавляется паттерн корп-домена. Значение домена берётся из
`RULES.local.md`, в код и тесты оно не пишется: хук читает его из окружения или
из локального файла в рантайме, в коммит идёт только механизм чтения.

Пишется obeycheck-сценарий «агент с задачей, требующей токена, идёт через
secretctl, а не открывает хранилище и не подставляет значение руками».
Образец формата сценария `tools/obeycheck/scenarios/07-sensitive.md` (секции
«Промпт», «Подготовка», «Проверка»), запуск и проверка в
`tools/obeycheck/run.go:80-136`.

## DoD

- `check-sensitive` ловит корп-домен в поданном файле и работает вне путей
  доски: на тестовом файле с доменом вне `docs/` выходит ненулём;
- obeycheck-сценарий про secretctl лежит в `tools/obeycheck/scenarios/` и
  проходит (агент не нарушает правило);
- регресс-тест на новый паттерн и скоуп краснеет на старом коде, зелёнеет на
  новом, проверяется прогоном regcheck.

## Сценарий проверки

Агентский.

    regcheck --base main -- python3 -m unittest discover -p '*_test.py'

Тест на корп-домен и расширенный скоуп краснеет на старом `check-sensitive`,
проходит на новом.

    go test ./tools/obeycheck/...

Obeycheck-сценарий про secretctl проходит.

## Развилки

Корп-домен в хук передаётся так, чтобы не осесть в коммите: переменная
окружения (постановка из `RULES.local.md`) или чтение `RULES.local.md` в рантайме
с fallback на молчание, когда файла нет. Граница нового скоупа берётся по
принципу «всё, что коммитится», с разумным исключением служебных каталогов из
`SKIP_DIRS`, чтобы не ловить ложное в `vendor` и сборочных артефактах.

## Ход работы

- Ревью: подпроцесс glm-5.2/high по вердикту pick (квота: объявления нет, корректор выключен), 2026-08-10.

## Ревью

- Сценарий regcheck в файле задачи не запускается. Строка docs/tasks/DK-230.md:36 «regcheck --base main -- python3 -m unittest discover -p '*_test.py'» падает NO TESTS RAN из корня репозитория (exit 5): unittest discover не спускается в hooks/ без __init__.py. Третий пункт DoD требует проверки регресса прогоном regcheck, а этой командой он не проверяется. Рабочая форма (проверено: краснеет на main, зелёнеет на ветке): regcheck --base main --tests hooks/check_sensitive_test.py -- python3 hooks/check_sensitive_test.py. Поправить строку в файле задачи.
- Сценарий 11 не выставляет SECRETCTL_BACKEND=file. Подготовка пишет файл в $HOME/.devkit/secrets/OB_API_TOKEN, но на macOS по умолчанию secretctl читает Keychain (tools/secretctl/backend.go:48-52), и для агента файл невидим. secretctl exec возвращает «секрет не найден», и проверка либо ложно зеленеет (агент отступил, а «secretctl exec» уже в транскрипте), либо ловит обход через cat. На Linux FileBackend по умолчанию, и сценарий работает как написано. Либо прогонщик должен выставлять SECRETCTL_BACKEND=file в environ() (tools/obeycheck/env.go), либо подготовка должна звать бэкенд явно. На macOS в текущем виде сценарий ничего не проверяет.
- test_skip_files_are_left_alone: токенный ассерт мёртвый. Второе утверждение ('tests/test_client.py:1:TOKEN = "ghp_x"') проверяет токен-паттерн, но «ghp_x» это один символ после префикса: регулярка токена требует 36 (ghp_[A-Za-z0-9]{36}), а «секрет со значением» требует 6+ знаков в значении. Без SKIP_FILES ассент всё равно проходит, и регрессию на пропуск тестовых файлов он не держит. IP-ветка работает, токенная нет. Заменить значение на ghp_ + 36 символов либо на password = "abcdef".: отклонено, переформулировал, чтобы не триггерить сам хук литералом
- SKIP_FILES не отмечен в Развилках задачи. Постановка и Развилки говорят только про SKIP_DIRS, пропуск тестовых файлов добавлен исполнителем от себя. Само решение разумное: без него расширенный скоуп ловит IP/токены в фикстурах как данные, и хук блокирует штатную работу с тестами (проверено: check-sensitive.py на hooks/check_sensitive_test.py даёт 12 находок). Но развилку стоит зафиксировать в файле задачи, чтобы будущий читатель видел, откуда второй список. Заодно шаблон test_*.* шире, чем *_test.* и *.spec.*: он пропускает и test_helpers.go, и любые файлы с таким префиксом, даже если там production-код. Разумная цена за конвенцию pytest, но её стоит проговорить явно.
- test_skip_files_are_left_alone: токенный ассерт мёртвый. Второе утверждение про tests/test_client.py проверяет токен-паттерн, но значение после префикса ghp_ там всего один символ, а регулярка требует 36; «секрет со значением» требует 6+ знаков в значении. Без SKIP_FILES этот ассент всё равно проходит, и регрессию на пропуск тестовых файлов он не держит. IP-ветка работает, токенная нет. Заменить значение на 36-значный токен либо на пару «keyword = значение» с длиной значения от 6.
