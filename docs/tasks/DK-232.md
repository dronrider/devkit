# DK-232: Корп-домен вычищен из дерева и истории, force-push пользователя

Задача цели DK-207, после DK-230. Корп-домен закоммичен в публичный
`RULES.core.md` вопреки собственному правилу: строка 96 упоминает хост
`gitlab.<корп-домен>` в условии корп-контура. Дерево содержит домен ровно в
этом одном файле, историю внёс один коммит.

## Что делается

Корп-домен вычищается из рабочего дерева: `RULES.core.md:96` переформулируется
без домена, ролью машины («корп-репозиторий», «корп-контур»), как того требует
правило из `RULES.md`. История переписывается так, чтобы домен исчез из всех
коммитов: `git filter-repo --replace-text` (предпочтительно) с маской по домену.
Сила переписывания истории в том, что публичный origin после force-push
перестаёт хранить домен у себя.

Force-push переписанной истории в публичный origin делает пользователь: это
точка, где цикл встаёт и зовёт человека.

## DoD

- греп по корп-домену молчит в рабочем дереве devkit;
- `git log --all -S '<корп-домен>'` молчит по всей истории;
- `RULES.core.md:96` переформулирована без домена.

Значение корп-домена берётся из `RULES.local.md`, в файл задачи и в коммит оно
не пишется.

## Сценарий проверки

Греп по домену молчит и в дереве, и в истории. Пользовательская часть: после
переписывания истории пользователь делает force-push в origin, после чего
греп по домену молчит и на remote.

    grep -rn '<корп-домен>' .
    => пусто
    git log --all -S '<корп-домен>' --oneline
    => пусто

## Развилки

Инструмент переписывания `git filter-repo`; если его нет, ставится через pip
или берётся эквивалент. Переписывание затрагивает все ветки и теги, поэтому
согласуется с открытыми worktree и ветками: перед прогоном активные деревья
очищаются, после force-push обновляются. Ротация утёкших токенов сознательно за
рамками цели и остаётся за пользователем, в «Итог» цели пишется напоминание.
