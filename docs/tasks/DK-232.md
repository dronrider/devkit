# DK-232: Корп-домен вычищен из дерева и истории, force-push пользователя

Задача цели DK-207, после DK-230. Корп-домен закоммичен в публичный
`RULES.core.md` вопреки собственному правилу: строка 96 упоминает хост
`gitlab.<корп-домен>` в условии корп-контура. Дерево содержит домен ровно в
этом одном файле, историю внёс один коммит.

## Что делается

Корп-домен вычищается из рабочего дерева: `RULES.core.md:96` переформулируется
без домена, ролью машины («корп-репозиторий», «корп-контур»), как того требует
правило из `RULES.md`. История переписывается так, чтобы домен исчез из всех
коммитов: `git filter-repo --replace-text` (предпочтительно) с маской по домену.
Сила переписывания истории в том, что публичный origin после force-push
перестаёт хранить домен у себя.

Force-push переписанной истории в публичный origin делает пользователь: это
точка, где цикл встаёт и зовёт человека.

## DoD

- греп по корп-домену молчит в рабочем дереве devkit;
- `git log --all -S '<корп-домен>'` молчит по всей истории;
- `RULES.core.md:96` переформулирована без домена.

Значение корп-домена берётся из `RULES.local.md`, в файл задачи и в коммит оно
не пишется.

## Сценарий проверки

Греп по домену молчит и в дереве, и в истории. Пользовательская часть: после
переписывания истории пользователь делает force-push в origin, после чего
греп по домену молчит и на remote.

    grep -rn '<корп-домен>' .
    => пусто
    git log --all -S '<корп-домен>' --oneline
    => пусто

## Переписывание истории (точка пользователя)

Дерево вычищено на этапе 1 (RULES.core.md без домена, греп молчит). История
переписывается `git filter-repo`, и это пользовательская точка: прогон делает
человек после остановки параллельных сессий. Ассистент filter-repo не гоняет,
потому что на машине активны другие циклы, работающие с этим репозиторием:
переписывание всей истории ломает их рабочие деревья и ветки.

Файл замен лежит в `/tmp/dk-232-replace-text.txt` (вне репо, не коммитится, в
нём домен, поэтому файл секретный). Домен в него подставляется из env
`DEVKIT_CORP_DOMAIN` или ключа `corp_domain` из `RULES.local.md`, литерала
домена в коммите нет. Формат `filter-repo --replace-text`, по строке на замену,
длинное (хост) идёт раньше короткого (домен), чтобы перекрытие не оставило
остатка:

    gitlab.<корп-домен>==>корп-origin
    <корп-домен>==>корп-контур

Пересоздать файл при потере (значение берётся из env/RULES.local.md, не из
этого файла):

    DOMAIN="${DEVKIT_CORP_DOMAIN:-$(... ключ corp_domain из RULES.local.md ...)}"
    { echo "gitlab.${DOMAIN}==>корп-origin"; echo "${DOMAIN}==>корп-контур"; \
    } > /tmp/dk-232-replace-text.txt

Порядок прогона в основном дереве devkit (не в worktree). `filter-repo`
после прогона удаляет remote `origin`, поэтому адрес сохраняется до запуска
и возвращается после:

    OLD_ORIGIN=$(git remote get-url origin)
    git filter-repo --replace-text /tmp/dk-232-replace-text.txt --force
    git remote add origin "$OLD_ORIGIN"

При потере сохранённого значения (новый клон) адрес origin берётся из
`access.local.md` (там роль машины, а не литерал в коммите); домен для файла
замен по-прежнему из `DEVKIT_CORP_DOMAIN` или ключа `corp_domain` из
`RULES.local.md`. Затем force-push всех веток и тегов:

    git push --force origin --all
    git push --force origin --tags

Перед прогоном остановить параллельные сессии и очистить worktree, после
force-push обновить деревья (`git fetch --all`, перепривязка веток). После
прогона `git log --all -S '<корп-домен>' --oneline` молчит по всей истории.

## Развилки

Инструмент переписывания `git filter-repo`; если его нет, ставится через pip
или берётся эквивалент. Переписывание затрагивает все ветки и теги, поэтому
согласуется с открытыми worktree и ветками: перед прогоном активные деревья
очищаются, после force-push обновляются. Ротация утёкших токенов сознательно за
рамками цели и остаётся за пользователем, в «Итог» цели пишется напоминание.
