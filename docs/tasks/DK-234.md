# DK-234: Цель в Backlog при идущих витках это находка

записан 2026-08-10

## Что происходит

По goal-loop цель переводится в работу первым витком, при нарезке, но шаг
держится только на прозе скилла: DK-207 набрал журнал (нарезка, два закрытых
задачи), а строка простояла в Backlog, пока расхождение не заметили глазами.
Автоматики нет ни с одной стороны: гейт витка (`agentctl spend --goal`,
tools/agentctl/goal.go) считает только бюджет и статусом строки не
интересуется, у `devkitctl doctor` проверок про цели нет вовсе. Проверено
грепом по обоим инструментам 2026-08-10.

## Чего хотим

Проверку, которая ловит расхождение сама: цель с записями в «Журнале» либо с
заведёнными строками в «Задачах цели», чья строка на доске стоит в Backlog,
это находка. Где ей жить (doctor, гейт витка или `taskctl lint`) и что считать
признаком идущей работы, выбирает исполнитель.

## DoD

Расхождение статуса цели с её журналом видно без глаз человека: находку
печатает команда, которая и так зовётся по ходу цикла, и на состоянии, снятом
с DK-207 (строка в Backlog, в журнале витки), она срабатывает. Тесты по
стандарту devkit.
