# DK-241: Подключение дашборда за канал одной командой

записана 2026-08-10

## Чего хотим

Заход извне (DK-223) подключается сегодня набором ручных шагов из README
дашборда: поставить xr-share установщиком хаба, завести публикацию, положить
два секрета с маркерами, прогнать две команды проверки. Живой прогон показал
и ловушки: значение секрета тянет в историю консоли, маркер Keychain легко
забыть, а установщик хаба может поставить бинарь без нужной подкоманды
(протухший share-dist, черновик XR-277 на доске XR).

Хотим одну короткую команду (подкоманда dashboard или шаг devkitctl, решить
по раскладке), которая проводит всё подключение целиком:

- ставит или обновляет xr-share, если его нет или он не знает expose;
  рег-токен спрашивается скрыто или берётся флагом;
- заводит публикацию с именем из аргумента и апстримом на порт дашборда из
  его конфига;
- спрашивает скрыто пароль владельца и кладёт оба секрета вместе с маркерами
  (DK-239 про secretctl set смежен: появится он, командой пользоваться тут);
- прогоняет обе проверки канала из README и печатает итог словами;
- идемпотентна: повторный запуск на подключённой машине отвечает «уже
  стоит», а не падает на первом занятом имени.

Root-шаги (бинарь, служба, expose) идут через sudo внутри команды, это
честно называется до запроса пароля.

Предпосылка вне доски: свежесть share-dist хаба (черновик XR-277 на доске
XR). До его закрытия команда обязана хотя бы распознать бинарь без expose и
назвать лекарство, а не падать на unrecognized subcommand.

## Ранг

`0+4+2+0+1 = 7`, P3.

- Серьёзность 0 (Minor). Удобство: обход есть и записан в README, подключение
  делается раз на машину.
- Ценность 4. Ощутимое улучшение, которое пользователь попросил сам после
  живого прохода по ручным шагам.
- Неопределённость 2. Шаги известны, развилки в деталях: интерактив против
  флагов, границы идемпотентности, распознавание протухшего бинаря.
- Поправка на баг 0. Новая работа.
- Рычаг 1. Каждая следующая машина и переустановка подключаются быстрее.

## Сценарий проверки

Агентский. На синтетическом окружении (временный HOME, фейковые install.sh,
xr-share, security и фронт): прогон команды с нуля проходит все шаги и
печатает итог; повторный прогон отвечает «уже стоит» и ничего не ломает;
бинарь без expose распознаётся с названным лекарством; секрета в истории и в
выводе нет (греп по журналу прогона). Живой конец канала в сценарии не
участвует.
