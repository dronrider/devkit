# DK-242: Экраны дашборда открываются секунды: профилировать и убрать ожидание из стартовой и карточки задачи

записана 2026-08-11, замечания 2 и 4 пользовательской проверки цели DK-112

## Чего хотим

Стартовая страница открывается несколько секунд, карточка задачи тоже.
Вероятный корень один: каждый запрос гоняет подпроцессы (обход корней с git
rev-parse на каталог-кандидат, taskctl list --json на проект, dep list на
карточке) без какого-либо кэша, и телефон ждёт весь конвейер. Профилировать,
корень назвать в ходе работы числами (сколько ест скан, сколько taskctl) и
убрать ожидание: кэш с коротким сроком, параллельный опрос проектов,
ленивый рендер, решить по замеру. Порог: стартовая и карточка открываются
без заметной паузы по ощущению на телефоне, числом в ходе работы.

## Ранг

`25+7+3+0+1 = 36`, P2.

- Серьёзность 25 (Major). Каждый заход в основной сценарий начинается с
  ожидания; пользоваться можно, потому Major, а не выше.
- Ценность 7. Ощутимое улучшение, названо пользователем прямо.
- Неопределённость 3. Корень не подтверждён замером, подход выбирается после
  профилирования.
- Поправка на баг 0. Так собрано изначально, регресса нет.
- Рычаг 1. Быстрый отклик делает приятнее каждый следующий экран серии.

## Сценарий проверки

Агентский. На синтетическом окружении с четырьмя проектами замерить время
ответа /api/projects и карточки задачи до и после; после правки ответ
укладывается в названный в ходе работы порог (сотни миллисекунд, не
секунды), замер печатается командой. Повторный запрос дешевле первого, если
решением стал кэш.
