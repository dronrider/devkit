# DK-245: Заведение задачи и черновика с дашборда

записана 2026-08-11, замечание 12 пользовательской проверки цели DK-112

## Чего хотим

С дашборда нельзя завести ни задачу, ни черновик, а мобильный сценарий этого
просит: мысль приходит вне машины. Кнопка «Новая задача» была на макете
DK-216 и убрана ревью сознательно, потому что цель DK-112 заведение не
называла; теперь это отдельная строка с собственным решением.

Состав: ручка и форма заведения через taskctl (add с рангом или draft для
сырой мысли, обе строго подпроцессом), выбор типа и цены, слагаемые ранга с
подсказками из RANKING.md, коммит доски тем же порядком, что у правок.
Черновик как путь по умолчанию для телефона: полная строка требует ранга, а
ранг с телефона считать неудобно.

## Ранг

`25+6+2+0+1 = 34`, P2.

- Серьёзность 25 (Major). Половина мобильного управления доской отсутствует,
  обход это сидеть за машиной.
- Ценность 6. Ощутимое расширение, попрошено пользователем после живого
  прохода.
- Неопределённость 2. Механика ясна (taskctl add и draft готовы), развилки в
  форме: черновик против полной строки, ранг на телефоне.
- Поправка на баг 0. Новая работа.
- Рычаг 1. Черновики с телефона кормят грумминг и остальную доску.

## Сценарий проверки

Агентский: на синтетическом проекте POST заведения черновика кладёт файл в
docs/tasks/drafts/ с текстом и коммитом (сверка файлом), заведение полной
строки с рангом даёт строку через taskctl add, кривой ранг отбивается
словами утилиты, без входа 401. Взгляд формы глазами за пользователем.

## Ход работы

- Исполнение: субагент opus/medium по вердикту pick (квота: week_all 8%, week_max 9%, снимок 0м назад, сдвига нет), 2026-08-11.
- Ручек две: `POST /api/projects/{p}/drafts` пишет черновик через `taskctl draft`,
  `POST /api/projects/{p}/tasks` заводит строку через `taskctl add` и по флагу
  `file` дописывает файл задачи (`taskctl file`). Обе коммитят доску через
  commitDocs, ID берётся из ответа утилиты: нумерация сквозная, и своей у
  сервера быть не может.
- Текст черновика едет утилите на вход подпроцесса, а не аргументом: аргументом
  его сначала разбирает flag (мысль с дефиса), потом страж подкоманд taskctl
  (мысль из одного слова латиницей вроде «fix»), и оба раза запись теряется. Ради
  этого в дашборде появился runProcIn, а рядом taskctlDoIn.
- Экран `#проект/new` с кнопкой на доске и на главной: черновик первым полем,
  полная строка разворотом. Слагаемые ранга взяты из того же RANK_PARTS, что у
  экрана задачи, поправка на баг сверяется с типом теми же словами, что в PATCH
  (bugPartRefusal на сервере). Поля переживают перечитывание по фокусу окна,
  кнопки гаснут на время запроса.
- Краснота: `regcheck --base main --tests tools/dashboard/newtask_test.go`,
  тест краснеет на main и проходит на ветке.
- По замечанию ревью добавлен TestDraftTextLimit: текст за пределом отбивается
  400 со словами про предел, накопитель и коммит доски остаются нетронутыми, а
  длинная запись в пределе доезжает до файла целиком. Краснота мутацией: со
  снятым MaxBytesReader ручка отвечает 200 и тест падает.
- Ревью: субагент sonnet/high по вердикту pick (квота: week_all 8%, week_max 9%, снимок 0м назад, сдвига нет), 2026-08-11.
