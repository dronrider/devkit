# DK-250: Действия задачи по статусу: выполнить, продолжить, закрыть со своими промптами конвейеру

записана 2026-08-11, замечание 2 второй пользовательской проверки цели DK-112

## Чего хотим

Кнопка «В работу» одна на все строки, а действие зависит от статуса и вида
строки. По статусу задачи дашборд предлагает своё:

- Backlog: «Выполнить», промпт конвейеру «Выполни DK-NNN»;
- In progress: «Продолжить», для цели «Продолжай выполнение цели DK-NNN»,
  для задачи «Продолжай выполнение DK-NNN»;
- Check: «Закрыть», промпт «Закрой DK-NNN» (агентский сценарий агент гоняет
  и закрывает, пользовательский честно скажет, что ждёт человека);
- у живой работы остаётся «Стоп».

Промпт собирает сервер (ручка runs уже различает цель и задачу), кнопки на
строке доски и на экране задачи берут действие из статуса. Тексты промптов
держатся тестами, чтобы не разъехались со скиллами.

## Ранг

`25+6+2+0+1 = 34`, P2.

- Серьёзность 25 (Major). Одна кнопка на все статусы путает и шлёт конвейеру
  не тот заказ.
- Ценность 6. Управление становится осмысленным по месту.
- Неопределённость 2. Механика запуска готова, развилки в текстах промптов.
- Поправка на баг 0. Новая работа.
- Рычаг 1. Те же действия пригодятся черновикам (груминг DK-251).

## Сценарий проверки

Агентский: на синтетическом проекте строка каждого статуса получает своё
действие (ответ API и разметка), запуск из Backlog поднимает сессию с
промптом «Выполни ...», из In progress «Продолжай ...», из Check «Закрой ...»
(промпт виден в аргументах фикстурного tmux), у цели своя формулировка.

## Ход работы

- Исполнение: субагент opus/medium по вердикту pick (квота: week_all 22%, week_max 24%, снимок 0м назад, сдвига нет), 2026-08-11.
- Сервер: `runPrompt(sect, id)` в `runs.go` собирает промпт headless-сессии по
  секции строки (backlog «Выполни», in-progress «Продолжай выполнение», check
  «Закрой»); секция берётся из `row.Sect`, который `parseBoardRows` уже
  проставляет по ответу taskctl, ручку менять не пришлось. У цели заказ
  остался один: и «выполнить», и «продолжить» это следующий виток, а промпт
  витка сочиняет оболочка `goal-run.py`, и лезть в её слова из дашборда нечем.
- Клиент: `actionLabel(sect)` даёт подпись кнопке на строке доски и на полосе
  действий задачи (полоса вынесена из `renderTask` в `taskActions`, рядом
  `taskActionHint` про место работы). Заблокированная маркером `[после ...]`
  задача действия не получает: кнопка стоит погашенной, причину говорит
  подсказка.
- Тесты: `TestRunStartTaskPromptBySection` гоняет запуск из трёх статусов и
  сверяет промпт в аргументах фикстурного tmux, `TestStaticActionLabelBySection`
  и `TestStaticTaskActionBySection` держат подписи и погашенную кнопку.
  Краснота: `regcheck --base main --tests tools/dashboard/runs_test.go,
  tools/dashboard/board_test.go,tools/dashboard/tasks_test.go`, тесты краснеют
  на main. Полный прогон `GOWORK=off go test -count=1 ./...` в tools/dashboard
  зелёный.
- Ревью: субагент sonnet/high по вердикту pick (квота: week_all 25%, week_max 29%, снимок 0м назад, сдвига нет), 2026-08-12.
