# DK-251: Состав цели сабтасками, единая форма задача-черновик и раздел черновиков с оформлением

записана 2026-08-11, замечания 11, 14, 15 второй пользовательской проверки цели DK-112

## Чего хотим

- Экран цели показывает состав как сабтаски в трекерах: список задач цели со
  статусами и судьбой (источник это раздел «Задачи цели» файла цели плюс
  строки доски и архива), а не пустой блок зависимостей;
- заведение единой формой с переключателем задача-черновик: поля как у
  правки задачи (черновику текст и заголовок), несохранённое нельзя взять в
  работу, черновику доступен только груминг;
- раздел «Черновики» в проекте рядом с бэклогом: список из
  docs/tasks/drafts/ (taskctl draft list), просмотр текста, действие
  «Оформить» поднимает сессию груминга конвейером (промпт по механике
  DK-250), после которого строка оказывается в Backlog.

## Ранг

`25+6+2+0+1 = 34`, P2.

- Серьёзность 25 (Major). Состав цели невидим, черновики недостижимы с
  телефона: половина мобильного цикла работы с доской отсутствует.
- Ценность 6. Прямые просьбы пользователя.
- Неопределённость 2. Источники данных известны, развилки в форме.
- Поправка на баг 0. Новая работа.
- Рычаг 1. Груминг с телефона кормит всю доску.

## Сценарий проверки

Агентский: на синтетической цели с задачами состав отдаётся API и рендерится
списком со статусами; черновики видны разделом, текст читается; «Оформить»
поднимает сессию с грумминговым промптом (фикстурный tmux); форма заведения
переключается задача-черновик и не даёт взять несохранённое в работу.

## Ход работы

- Исполнение: субагент opus/medium по вердикту pick (квота: week_all 34%, week_max 40%, снимок 0м назад, сдвига нет), 2026-08-12.
- Состав цели читается из раздела «Задачи цели» файла цели, своего реестра у
  цели не заводится. Задачей цели считается ID, который открывает элемент
  списка либо назван с метаданными в скобках, включая перечисление через
  запятую перед общими скобками: на живом DK-112 это правило берёт всю нарезку
  и не берёт соседей («ждёт XR-252», «остаётся черновиком DK-136 вне цели»).
- Статус закрытой задачи берётся из `docs/TASKS-archive.md` разбором таблицы, а
  не командой утилиты: своего `--json` у архива нет, а `taskctl show` по каждой
  закрытой задаче поднимал бы подпроцесс на строку состава.
- `taskctl draft list --json` добавлен отдельным коммитом до дашборда: машинного
  вида у накопителя не было, а разбирать печать грепом хрупко.
- Сессия груминга поднимается под именем `task-<ID>`: грумминг кончается
  строкой доски с тем же ID, работа видна в общем списке работ проекта, и стоп
  ей достаётся тот же самый.
- Слово в текстах экранов оставлено в написании «груминг»: написание макета
  («грумминг») держит запрет теста `TestStaticAgentPaneWords`, язык экранов
  правился раньше и разъезжаться с ним из-за одной формы незачем.
- Прогон smoke получил шаг «состав цели сабтасками» с фикстурным архивом: без
  него закрытая половина состава осталась бы непроверенной снаружи.
- Ревью: субагент sonnet/high по вердикту pick (квота: week_all 34%, week_max 40%, снимок 0м назад, сдвига нет), 2026-08-12.

У остальных изменяющих ручек (tasks, newtask, messages, runs) есть парный тест 401-без-входа/403-чужой-Origin, у groom его нет

Дата закрытия из архива нигде не сверяется со значением фикстуры
