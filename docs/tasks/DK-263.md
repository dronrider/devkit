# DK-263: Интерактивные сессии агентов видны в работах: живость по mtime транскрипта, включая окна боковых деревьев

записана 2026-08-11, вопрос пользователя при проверке цели DK-112

## Чего хотим

Дашборд узнаёт живые работы по tmux-сессиям и реестру целей, и интерактивное
окно агента (VSCode, вторая подписка GLM в боковом дереве devkit-glm)
невидимо: ни tmux, ни записи в реестре. Первый пункт цели «видно, над чем
агенты работают прямо сейчас» для таких окон не выполняется.

Источник живости есть: транскрипт идущей сессии дописывается каждым ходом.
Показать в работах проекта интерактивные сессии, чей транскрипт обновлялся
недавно (порог решить, минуты), с заголовком задачи по привязке DK-252,
подписью «интерактивная сессия» и без кнопки остановки (снимать нечего,
сессию ведёт человек в окне). Каталоги боковых деревьев (devkit-glm,
devkit-dk-NNN) уже входят в выборку сессий, работы из них относятся к
родному проекту. Порог и решение записать в LLD.

## Ранг

`25+6+2+0+1 = 34`, P2.

- Серьёзность 25 (Major). Половина реальной работы на машине (интерактивные
  окна) невидима, наблюдение неполно.
- Ценность 6. Прямой вопрос пользователя, дыра в первом пункте цели.
- Неопределённость 2. Источник ясен, развилки в пороге живости и виде
  карточки.
- Поправка на баг 0. Оба источника работ собраны как задумано.
- Рычаг 1. Живость сессий пригодится экрану «Агенты» (DK-256).

## Сценарий проверки

Агентский: фикстурная сессия со свежим mtime и привязкой к задаче видна в
работах с подписью и без кнопки остановки; протухшая по порогу не видна;
tmux-работы не задваиваются (сессия конвейера и его транскрипт это одна
работа). Живая проверка: окно соседней подписки с идущей работой появляется
в работах проекта devkit руками диспетчера.
