# DK-270: dashboard: ручка message шьёт путь цели жёстко, журнал идёт по ссылке строки

записан 2026-08-11, оформлен 2026-08-12

## Что происходит

`goalFile` в `tools/dashboard/messages.go` собирает путь файла цели жёсткой
склейкой `docs/tasks/<ID>.md`, а `goalDocPath` в `tools/dashboard/journal.go`
сначала идёт по ссылке строки доски (разбор `linkPath` из DK-255) и лишь при
битой ссылке откатывается на обычное место. У цели, чья ссылка ведёт на живой
файл не на обычном месте, концы расходятся: сообщение из дашборда ляжет в
`docs/tasks/<ID>.md`, а виток и экран прочитают файл по ссылке; если файла на
обычном месте нет вовсе, ручка ответит 404 «класть сообщение некуда» при
журнале, который экран показывает. Сегодня расхождения нет: все цели доски
ссылаются на `tasks/<ID>.md`, дефект латентный, обход дешёвый, держать файл
цели на обычном месте.

## Чего хотим

Оба конца берут путь одним разбором: `goalFile` ходит через тот же
`goalDocPath`, жёсткой склейки пути в ручке message не остаётся.

## DoD

Сообщение цели, чья ссылка строки ведёт на файл не на обычном месте, ложится в
тот файл, который читают журнал и экран; держит это тест с нестандартной
ссылкой в строке доски.

## Ранг

`0+2+1+5+2 = 10`, P3.

- Серьёзность 0 (Minor). Дефект латентный: все нынешние цели ссылаются на
  обычное место, расхождения на живой доске нет, обход дешёвый и очевидный.
- Ценность 2. Небольшая страховка целостности чата целей: пользователь заметит
  только на цели с нестандартной ссылкой.
- Неопределённость 1. Подход назван в черновике, общий разбор уже есть
  (`goalDocPath`), осталось позвать его из второго конца.
- Поправка на баг 5. Несостыковка двух ручек это дефект, а не новая работа.
- Рычаг 2. Общий разбор ссылки убирает грабли у будущих правок чата целей
  (DK-136, DK-112).
