# DK-280: dashboard: разговор законченной работы не открыть ни с задачи, ни с чата

записан 2026-08-12, оформлен 2026-08-12

## Что происходит

Посмотреть, что агент делал по задаче, можно только пока работа идёт. Кнопка
«Живой статус» на экране задачи стоит у живой работы, «Чат с агентом» только у
цели (`taskActions`, `tools/dashboard/static/app.js`), а ручка
`/sessions?task=` читает шапки лишь у 50 свежих транскриптов проекта
(`headScanMax`, `tools/dashboard/sessions.go`) при 224 файлах в каталоге
devkit. После конвейера DK-208 карточка работы пропала, и разобраться, что
случилось с задачей, стало неоткуда: ни в дашборде, ни в окне IDE, при том что
транскрипт лежит на диске и задачу свою называет первой репликой. Поймано на
приёмке цели DK-112 2026-08-12.

## Чего хотим

Разговор ищется по ID задачи, а не по живости работы: переход к сессиям стоит
на экране любой задачи, поиск идёт по всем транскриптам проекта, а законченный
разговор открывается на чтение, без поля ввода.

## DoD

С экрана задачи, чья работа кончилась вчера, открывается её разговор; держат
это тест поиска сессии за окном `headScanMax` и тест экрана задачи, где
переход к сессиям есть и без живой работы.

## Ранг

`25+8+2+0+2 = 37`, P2.

- Серьёзность 25 (Major). Разбор законченной работы упирается в тупик, обход
  дорогой: читать `~/.claude/projects/*.jsonl` руками с ноутбука.
- Ценность 8. Ради наблюдения за работой агентов дашборд и затевался, а с
  телефона другого пути к транскрипту нет вовсе.
- Неопределённость 2. Подход понятен, развилки в деталях: чем ограничить поиск
  по каталогу, чтобы экран не ждал, и как показывать несколько сессий одной
  задачи.
- Поправка на баг 0. Так было с самого начала, это новая работа.
- Рычаг 2. Поиск сессии по ID пригодится ленте и будущему живому чату (DK-136).
