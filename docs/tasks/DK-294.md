# DK-294: dashboard: разговор живой сессии без узнанной задачи не открыть

записан 2026-08-13, оформлен нарезкой цели DK-327 2026-08-14

## Что происходит

В полосе живых работ вверху экрана сессия, чью задачу узнать не удалось, стоит
карточкой с подписью «задача не распознана», и карточка эта мёртвая: экран агента
открывается по ID задачи, а его-то и нет. Поймано на приёмке DK-280: два окна
начаты вольным вопросом без номера задачи, и посмотреть, чем они заняты,
неоткуда, при том что транскрипт лежит на диске и сервер про него знает (в ответе
`/api/projects` у такой работы заполнено поле `session`).

После DK-280 разговор ищется по ID задачи, и напрашивается второй вход, по id
сессии: полоса живых работ ведёт на экран агента прямо по `session`, а экран,
открытый так, шапку берёт из первой реплики вместо строки доски. Заодно
закрывается тот же случай для тех, кто вообще работает без доски.

Развилка, которую надо снять: экран агента сейчас завязан на ID задачи и
маршрутом (`#project/agent/<id>`), и журнал с tmux он ищет по нему же. Либо
маршрут учится принимать id сессии, либо заводится отдельный экран разговора.

## Чего хотим

Разговор живой сессии открывается с полосы работ в один нажим, даже когда задача
не узнана.

## DoD

- Экран агента открывается по id сессии, а не только по ID задачи: полоса живых
  работ ведёт на разговор прямо по `session`.
- Шапка такого экрана берётся из первой реплики и честно показывает, что задача
  не узнана; журнал и tmux там не изображаются пустыми, а названы отсутствующими.
- Развилка снята решением, а не веером: выбор между маршрутом с id сессии и
  отдельным экраном назван в ходе работы с причиной, отвергнутый вариант тоже.
- Тест ручки и юнит статики под node на маршрут, оба падают на старом коде.
- Список сессий задачи с переключателем берётся у DK-290, второй такой список не
  заводится.
- Поведение описано в README дашборда.

## Ранг

`25+5+3+0+1 = 34`, P2.

- Серьёзность 25 (Major). Транскрипт лежит на диске и виден серверу, а
  посмотреть его с экрана неоткуда. Обход дешёвый и очевидный: открыть то же окно
  на машине.
- Ценность 5. Второй сценарий цели DK-327 в части нераспознанных сессий, и заодно
  случай тех, кто работает без доски вовсе.
- Неопределённость 3. Правка едет через границу сервер-клиент, а маршрут экрана
  завязан на ID задачи, по которому ищутся и журнал, и tmux.
- Поправка на баг 0. Второго входа не было никогда, это работа, которой не было.
- Рычаг 1. На этот вход опирается разбор карточки нераспознанной сессии (черновик
  DK-291): что показывать в карточке, видно только на живых сессиях, куда можно
  зайти.

## Итог

Экран агента открывается вторым входом, по id сессии
(`#проект/session/<id сессии>`). Карточка живой работы, чью задачу узнать не
удалось, ведёт туда с полосы живых работ полем `session`, а на экране «Агенты»
у той же работы стоит кнопка «Разговор»: до этого обе стояли мёртвыми, экран
агента открывался по ID задачи, а его-то у такой сессии и нет. Тем же входом
открывается разговор тех, кто работает без доски вовсе.

Ручка разговора (`GET /api/projects/{p}/sessions/{sid}`) отдаёт вместе с лентой
шапку `head`: id, время последней записи, ветку, боковое дерево, первую реплику
и задачу с подписью, чем она узнана. Экран берёт из неё заголовок: строки доски
у захода по сессии нет, и брать его больше неоткуда. В шапке стоят имя файла
транскрипта с веткой, признак живости и подпись про задачу, узнанную либо
нераспознанную; у узнанной рядом кнопка «Экран задачи». Журнал и tmux пустыми
не изображаются: оба ищутся по ID задачи, и в панелях стоят слова о том, почему
их тут нет, разные для узнанной и неузнанной задачи. Вкладка по умолчанию на
телефоне «Лог витка».

Список сессий задачи с переключателем остался один, взят у DK-290: заход по
сессии зовёт ту же ленту (`openTranscript`) одним выбранным разговором, второго
списка не завелось.

Тесты: ручка на узнанной и неузнанной сессии (шапка поле в поле, подпись
«задача не распознана»), стенд `testdata/screen_keep.mjs` на маршрут (карточка
полосы ведёт по id сессии, экран собирается, заголовок из первой реплики,
журнал с tmux названы словами, поток ленты идёт по этой сессии). Оба падают на
старом коде, `regcheck --base main` зелёный. Поведение описано в README
дашборда (API, экран агента, экран агентов).

Не входило: что показывать в карточке нераспознанной сессии (черновик DK-291,
теперь есть где его посмотреть), доставка сообщения в идущую сессию (DK-136).

## Сценарий проверки

1. `cd tools/dashboard && GOWORK=off go test ./...` зелёный.
2. `node testdata/screen_keep.mjs static/app.js` печатает строку про разговор
   нераспознанной сессии, открытый с полосы работ по id сессии.
3. `regcheck --base main -- sh -c 'cd tools/dashboard && GOWORK=off exec go test
   ./... -run "TestSessionHeadNamesTask|TestScreenKeepsPlaceOnRefresh"'`
   говорит, что тесты краснеют на main.
4. Живьём: открыть окно агента вольным вопросом без номера задачи и подождать
   ход. В полосе живых работ дашборда появляется карточка «интерактивная
   сессия» с подписью «задача не распознана».
5. Нажать на неё: адрес становится `#проект/session/<id сессии>`, в шапке стоит
   первая реплика этого окна, имя файла транскрипта с веткой и подпись «задача
   не распознана», в ленте идёт разговор и дописывается следующим ходом.
6. В панели журнала и в полосе tmux того же экрана стоят слова о том, что оба
   ищутся по ID задачи, а задачу разговора узнать не удалось; пустыми они не
   стоят.
7. Открыть тем же входом сессию с узнанной задачей (`#проект/session/<id>` из
   списка `GET /api/projects/<проект>/sessions`): в шапке названа задача и чем
   она узнана, кнопка «Экран задачи» ведёт на `#проект/agent/<ID>`.
