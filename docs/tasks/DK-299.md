## Сценарий проверки

Часть проверок агентские (машина гоняет сама), часть глазная (формулировки
примеров обходов из LLD выбраны на месте по материалу раздела «Прогон по
архиву», и их убедительность судит ревью).

### Агентское

1. `ACCEPTANCE.md` лежит в корне и проходит `devkitctl doctor --layout`
   без находки про лишний файл:

   ```sh
   python3 tools/devkitctl/devkitctl.py doctor --layout
   ```

   Ожидание: «раскладка в порядке».

2. Белый список раскладки и перечень README совпадают, сторож `readme_gaps`
   молчит:

   ```sh
   cd tools/devkitctl && python3 -m unittest layout_test -v
   ```

   Ожидание: 20 тестов ок, включая `test_all_fifteen_entries_are_named` и
   `test_lists_match`.

3. В `ACCEPTANCE.md` ровно шесть барьеров и у каждого блока обходов, а
   распределение числа обходов (3/4/4/3/1/3) совпадает с LLD «Решение 1»:

   ```sh
   grep -c '^| глаза\|^| доступ\|^| необратимость\|^| секрет\|^| согласие\|^| событие' ACCEPTANCE.md
   ```

   Ожидание: 6 (строка заголовка таблицы). Число обходов сверяется по тексту
   под таблицей и по примерам перебора (DK-064 глаза 3, DK-232 необратимость
   4, DK-272 событие 3, DK-223 доступ 4).

4. Названные ссылки из правил и скиллов реально ведут на `ACCEPTANCE.md`, и
   файл лежит по тем же путям, что и `RANKING.md`:

   ```sh
   grep -l 'ACCEPTANCE.md' RULES.board.md README.md \
     kit/skills/board-groom/SKILL.md kit/skills/board-task/SKILL.md \
     kit/skills/board-ship/SKILL.md kit/skills/goal-loop/SKILL.md \
     kit/skills/goal-start/SKILL.md kit/skills/board-batch/SKILL.md \
     kit/agents/review-low.md kit/agents/review-medium.md \
     kit/agents/review-high.md kit/agents/review-xhigh.md
   test -f ACCEPTANCE.md && echo ok
   ```

   Ожидание: 12 файлов в выдаче `grep -l` и `ok`.

5. Символы чистые по всему изменённому набору:

   ```sh
   python3 ~/projects/devkit/hooks/check-symbols.py \
     ACCEPTANCE.md RULES.board.md README.md \
   ```

   ```sh
   python3 kit/skills/check-skills.py
   ```

   Ожидание: «ok: скиллы, проверено 10».

7. Прогон критериев по выборке даёт те же виды, что в LLD «Прогон по архиву».
   Берутся строки архива с суффиксом `[приёмка: ...]` (заведённые после DK-298)
   и файлы задач с разделом «Приёмка»; для каждой считается вид по шести
   барьерам `ACCEPTANCE.md` и сверяется с записанным. На момент DK-299 архив
   ещё не накопил задач с суффиксом (DK-298 вкодился одновременно), поэтому
   счёт пока пуст, и шаг этот проверяет готовность процедуры, а не число. Когда
   появятся строки `[приёмка: ...]`, та же команда даст наполнение:

   ```sh
   grep -c '\[приёмка:' docs/TASKS-archive.md || true
   ```

   Ожидание на момент работы: 0 (архив ещё не накопил). Контрольный счёт
   отложен до наполнения архива, как и сказано в LLD «Решение 6».
