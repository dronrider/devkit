# DK-300: Рубеж против фиктивного агентского сценария: вопрос ревью и ворота close

Постановка из LLD [DK-292](../lld/DK-292-check-kind.md), раздел «Рубеж против
фиктивного агентского сценария». Перевёрнутое умолчание (вид `agent` без
суффикса) держится на том, что ошибка в дешёвую сторону видна, и это надо
обеспечить механизмами, а не обещанием. Опасен один случай: вид `agent`, а
сценарий собран из повтора тестов ветки, прогон зелё всегда, задача закрывается
сама, молчание неотличимо от работы (DK-243, DK-284 в архиве).

Рубеж держат двое: ревью (человек судит содержание) и ворота `close` (машина
судит наличие).

## Ход работы

- Исполнение: подпроцесс glm-5.2/medium по вердикту pick (квота: объявления нет, корректор выключен), 2026-08-14.
- Источник дизайна: `docs/lld/DK-292-check-kind.md`, разделы «Рубеж против
  фиктивного агентского сценария» и «Ворота и пересмотр по ходу работы».

### Ворота close (машина)

`taskctl close <ID>` у задачи с видом `agent` требует вложенного вывода прогона
в файле задачи. Проверяется наличие, а не честность: пустое закрытие агентской
задачи становится невозможным, и это ровно та работа, которую машина может
сделать, не берясь судить содержание. Правило вкладывать реальный вывод есть и
сегодня (`RULES.board.md`, п. 6 раздела «Трекинг задач»), но воротами оно не
подкреплено.

Чем считать вложенный вывод, формулируется на месте (неопределённость 2 LLD):
надёжный и машинно-ловимый признак это непустой раздел `## Проверка` в файле
задачи. Именно туда диспетчер вкладывает реальный вывод прогона (как вкладывал
в DK-299 и DK-302), и ворота проверяют наличие непустого раздела у агентского
вида. Вывод у задачи без выката (дока, находка диагностики) идёт после коммита
в main и вкладывается тем же порядком, ворота работают и там.

Исключений из ворот нет: агентского LLD не бывает (решение 1 LLD), единственный
случай, у которого прогона нет по построению, снят вместе с ним.

### Вопрос ревью (человек)

Ревью обязательно перед слиянием и в автономном режиме тоже, и правило
«сценарий проверяется по содержанию, а не по пометке» в нём уже есть. Оно
получает проверяемый вопрос:

- у задачи с видом `agent` в сценарии обязан быть хотя бы один шаг, который
  прогоняется после выката и не является повтором тестов ветки;
- у задачи с не агентским видом в разделе «Приёмка» обязан стоять перебор
  обходов по форме решения 1, где у каждого обхода из строки барьера есть исход.

Нет такого шага значит сценарий переписывается, и понижать вид тут нельзя, пока
обход исполним. Замечание ревью держит слияние само (`shipctl merge` отказывает
при открытом замечании), то есть рубеж стоит на уже работающем механизме.

Правки текста: `kit/skills/board-ship/SKILL.md` (вопрос ревью про шаг после
выката и про перебор обходов) и `kit/agents/review-{low,medium,high,xhigh}.md`
(тот же проверяемый вопрос в определение ревьювера).

### Не входит

Обязательность флага `--accept` у `taskctl add` это отдельная строка DK-301
(дашборд): пока все три входа не научились слать флаг, обязательность не
включается. DK-300 ворота и вопрос ревью ставит, обязательность не трогает, и
переходный режим (`add` без `--accept` печатает предупреждение) остаётся как в
DK-298.
- Ревью: подпроцесс glm-5.2/high по вердикту pick (квота: объявления нет, корректор выключен), 2026-08-14.

## Сценарий проверки

Агентский. Ворота close и правки текста покрываются go-тестами taskctl и
самопроверкой скиллов.

1. Ворота close отказывают агентской задаче без непустого раздела «Проверка» и
   пропускают с ним:

   ```
   cd tools/taskctl && GOWORK=off go test -run 'TestClose' ./...
   ```

   Ожидание: `ok`. Тест покрывает обе ветки: агентский вид без вывода отказ,
   агентский вид с непустым разделом «Проверка» проходит, не агентский вид
   воротами close не трогается (его держат ворота move check из DK-298).

2. Вопрос ревью про шаг после выката стоит в board-ship и в определениях
   ревьюверов:

   ```
   grep -l 'после выката\|повтор.*тестов ветки\|перебор обходов' \
     kit/skills/board-ship/SKILL.md kit/agents/review-*.md | wc -l
   ```

   Ожидание: не меньше 5 файлов (board-ship и четыре ревью-агента).

3. Самопроверка скиллов и агентов зелёная:

   ```
   python3 kit/skills/check-skills.py
   ```

   Ожидание: «ok: скиллы, проверено 10» (правки в телах скиллов и агентов под
   правилами).

4. Полный прогон модуля taskctl:

   ```
   cd tools/taskctl && GOWORK=off go test ./...
   ```

   Ожидание: `ok`, ни одного провала.

5. Символы чистые по изменённому набору:

   ```
   python3 ~/projects/devkit/hooks/check-symbols.py \
     kit/skills/board-ship/SKILL.md kit/agents/review-low.md \
     kit/agents/review-medium.md kit/agents/review-high.md \
     kit/agents/review-xhigh.md tools/taskctl/*.go
   ```

   Ожидание: exit 0.
