# DK-301: Дашборд заводит задачу с видом приёмки, флаг add становится обязательным

Постановка из LLD [DK-292](../lld/DK-292-check-kind.md), раздел «Входы заведения
строки». Обязательный флаг `--accept` у `taskctl add` бьёт по всем, кто зовёт
команду, а зовут её три входа. Два из них (сессия агента, постановка цели) уже
шлют флаг с DK-299; третий это дашборд, и им же обязательность включается:
флаг становится обязательным не раньше, чем его научились слать все три входа.

## Ход работы

- Исполнение: подпроцесс glm-5.2/medium по вердикту pick (квота: объявления нет, корректор выключен), 2026-08-14.
- Источник дизайна: `docs/lld/DK-292-check-kind.md`, разделы «Входы заведения
  строки» и «Дашборд» разбивки.

### Дашборд: форма и ручка шлют вид

Форма «Новая задача» собирает аргументы в `tools/dashboard/newtask.go`
(`[]string{"add", "--title", ..., "--type", ..., "--rank", ...}`), и сейчас она
флаг не шлёт. Форма получает:

- выбор вида тремя значениями (agent/mixed/user), по умолчанию agent;
- при не агентском виде выбор барьера из шести списком;
- поле причины непригодности обхода (строка, её потом читает ревьювер).

Свободного текста для вида на телефоне не заводится: два тапа по закрытому
списку это ровно та работа, которую там можно сделать всерьёз. Ручка
`POST /api/projects/{p}/tasks` (`tools/dashboard/server.go`, `handleTaskCreate`)
шлёт `--accept` и, когда нужно, `--barrier`. Статика обоих форм-факторов
получает новое поле.

Как показать шесть барьеров на узком экране, решается формой на месте
(неопределённость 2 LLD), а не этим LLD: выбор из шести на телефоне это либо
свёрнутый список, либо разбор по шагам, исполнитель берёт читаемый вариант.

### Обязательность флага включается

Как только дашборд (третий вход) шлёт флаг, все три входа готовы, и
обязательность включается: `taskctl add` без `--accept` отказывает (сегодня
печатает предупреждение, DK-298), `--accept user` и `--accept mixed` без
`--barrier <ключ>` отказывают тоже. Это DoD цели DK-308, пункт 1 и пункт 5.

Правка одна: в `tools/taskctl` воротах `add` предупреждение сменяется отказом.
Скиллы груминга, нарезки цели и постановки уже шлют флаг (DK-299), их править не
надо.

### Не входит

Ворота `close` и вопрос ревью это DK-300; критерии вида и `ACCEPTANCE.md` это
DK-299; отбор пачки и совет после выката это DK-302. DK-301 только дашборд и
переключатель обязательности.

## Сценарий проверки

Агентский. Правки покрываются go-тестами дашборда и taskctl.

1. Форма и ручка шлют вид и барьер: тест `tools/dashboard/newtask_test.go`
   покрывает агентский (по умолчанию, без суффикса), смешанный и
   пользовательский вид с барьером и причиной.

   ```
   cd tools/dashboard && GOWORK=off go test -run 'TestNewTask|TestTaskCreate' ./...
   ```

   Ожидание: `ok`.

2. Обязательность флага: `taskctl add` без `--accept` отказывает, `--accept
   user` без `--barrier` отказывает, `--accept agent` заводит без суффикса.

   ```
   cd tools/taskctl && GOWORK=off go test -run 'TestAdd' ./...
   ```

   Ожидание: `ok`. На старом коде (предупреждение вместо отказа) проверка
   отказа падала.

3. Полные прогоны модулей:

   ```
   cd tools/dashboard && GOWORK=off go test ./...
   cd tools/taskctl && GOWORK=off go test ./...
   ```

   Ожидание: оба `ok`.

4. Символы чистые по изменённому набору:

   ```
   python3 ~/projects/devkit/hooks/check-symbols.py \
     tools/dashboard/newtask.go tools/dashboard/server.go \
     tools/dashboard/newtask_test.go tools/taskctl/*.go
   ```

   Ожидание: exit 0.
