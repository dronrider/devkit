# DK-303: Открытые строки доски получают вид приёмки по критериям

Проход по открытым строкам доски (Backlog, In progress, Check) и назначение им
вида приёмки по критериям `ACCEPTANCE.md`. Источник: LLD
[DK-292](../lld/DK-292-check-kind.md), строка «Открытые строки» разбивки и
раздел «Решение 6».

Вид `agent` это умолчание и пишется без суффикса (LLD, решение 3; `--accept
agent` заводит строку без суффикса, DoD цели DK-308 п. 1). Значит проход не
ставит суффикс каждой строке: agent по умолчанию уже стоит. Работа в том, чтобы
найти строки, которые по шести барьерам `ACCEPTANCE.md` заслуживают mixed или
user, и назначить им вид с разделом «Приёмка». Остальные остаются agent.

## Ход работы

- Исполнение: диспетчер в основном чекауте (правка доски, кода и worktree нет).
- Источник дизайна: `docs/lld/DK-292-check-kind.md`, разделы «Открытые строки»
  разбивки, «Решение 1» (шесть барьеров) и `ACCEPTANCE.md`.

### Процедура

Пройти каждую открытую строку по шести барьерам `ACCEPTANCE.md`. Назначить
`taskctl set <ID> --accept agent|mixed|user` и, при не агентском виде,
`--barrier <ключ>`. Вид agent суффикса не получает, поэтому правка трогает
только те строки, чей вид не агентский:

- **LLD, тип LLD.** По умолчанию user, барьер «согласие»: приёмка LLD это
  согласие с решением, обхода нет (`ACCEPTANCE.md`, особый случай «согласие»).
  Смешанного вида у LLD не бывает.
- **Глаза, доступ, необратимость, секрет, событие.** Барьер засчитывается, когда
  в файле задачи названа причина, по которой не годится каждый обход его строки.
  Разрез по шагам: барьер в одном шаге делает вид смешанным, целиком user.

Уже стоящие суффиксы (на момент работы: DK-328, DK-316, DK-324) не трогать, их
проставила груммингом параллельная сессия цели DK-327.

### Число строк

На 2026-08-13 открытых 63 (LLD); на момент работы с учётом нарезки цели DK-327
их около 85. Часть чужих строк дашборда (DK-289, DK-290, DK-297, DK-305,
DK-310..DK-313, DK-319, DK-325, DK-326) может заслуживать mixed по барьеру
«глаза» или «событие»: вид им назначает своя сессия, но если файла задачи и
сценария ещё нет, назначение откладывается до груминга.

## Сценарий проверки

Агентский. Проверяется распределение видов и отсутствие строк, у которых вид в
файле задачи расходится со строкой доски; сводку печатает DK-304.

1. Открытые не агентские строки имеют раздел «Приёмка» с перебором обходов, и
   число строк перебора равно числу обходов названного барьера:

   ```
   taskctl lint
   ```

   Ожидание: зелёный, инварианты доски и архива соблюдены.

2. Строк без назначенного вида нет (агентские без суффикса считаются
   назначенными по умолчанию, не агентские с суффиксом и разделом «Приёмка»
   назначенными явно):

   ```
   taskctl kinds
   ```

   Ожидание: сводка по видам, строк без вида ноль. Команда это DK-304, до него
   проверка grepом: не агентских без раздела «Приёмка» нет.
