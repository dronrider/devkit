# DK-304: taskctl kinds: сводка по видам приёмки, расхождениям и пересмотрам

Команда `taskctl kinds` печатает сводку по видам приёмки из того, что уже лежит
на диске: строки доски, файлы задач и архивные строки. Отдельной ручной сверки
«раз в месяц» не заводится, счёт идёт по закрытым за период и по живой доске.
Источник: LLD [DK-292](../lld/DK-292-check-kind.md), раздел «Решение 6».

## Ход работы

- Исполнение: подпроцесс glm-5.2 по вердикту pick (квота: объявления нет, корректор выключен).
- Источник дизайна: `docs/lld/DK-292-check-kind.md`, раздел «Решение 6».

### Четыре счёта

`taskctl kinds` печатает четыре счёта, и данные для всех уже есть на диске,
новых записей заводить не надо (суффикс приёмки переживает `close` наравне с
`[блок: ...]`, раздел «Приёмка» уезжает в архив с файлом задачи).

1. **Распределение по видам** (`agent`, `mixed`, `user`): доля ждущего человека
   становится числом, а не ощущением.
2. **Ошибка в дорогую сторону**: строка `user` или `mixed`, у которой в файле
   нет раздела «Приёмка» с ключом барьера. Задача простояла без названной
   причины. Этот счёт ловит и живая доска: `taskctl lint` печатает такую строку
   находкой.
3. **Ошибка в дешёвую сторону**, три следа. Первый: вид `agent`, вернувшийся из
   Check провалом (`taskctl fail`), агент прогнал сценарий, а прод сломан.
   Второй, важнее: понижение вида на ревью ветки, рубеж решения 4 поймал
   фиктивный агентский сценарий до выката. Растущий второй при нулевом первом
   это работающий рубеж, а не отсутствие ошибок. Третий это класс без рубежа:
   агентские задачи, закрытые без раздела «Выкат» и без единого замечания
   ревью, то есть мелочь мимо ветки; растущее число повод посмотреть выборочно,
   а не находка.
4. **Пересмотры**: сколько видов менялось по ходу работы и в какую сторону.
   Понижений много значит, груминг систематически не видит барьера, чинится
   правкой таблицы; повышений много значит, назначающий не знает про обходы,
   чинится примерами в `ACCEPTANCE.md`.

### Оговорка и формат

Считать имеет смысл только задачи, заведённые после правки: у 140 закрытых вид
в строке никогда не стоял, выводить его из прозы задним числом нельзя. Сводка
это отчёт, а не ворота: чинится по ней текст критериев, решает человек.

Формат вывода открыт (неопределённость 1 LLD): исполнитель берет читаемый,
счёты названы явно. DoD цели DK-308 п. 7: `kinds` печатает сводку и ноль строк
без вида.
- Исполнение: подпроцесс glm-5.3/high по вердикту pick (квота: объявления нет, корректор выключен), 2026-08-15.

## Сценарий проверки

Агентский. Правки покрываются go-тестами taskctl.

1. Команда печатает четыре счёта и ноль строк без вида:

   ```
   cd tools/taskctl && GOWORK=off go test -run 'TestKinds' ./...
   ```

   Ожидание: `ok`. Тест гоняет kinds по фикстуре с известным распределением и
   утверждает все четыре счёта.

2. Полный прогон модуля:

   ```
   cd tools/taskctl && GOWORK=off go test ./...
   ```

   Ожидание: `ok`.

3. Символы чистые по изменённому набору:

   ```
   python3 ~/projects/devkit/hooks/check-symbols.py tools/taskctl/*.go
   ```

   Ожидание: exit 0.
