# DK-316: dashboard: перерисовка дёргает экран, позиция скролла и чат прыгают

записан 2026-08-13, оформлен нарезкой цели DK-327 2026-08-14

## Что происходит

На списках задач и черновиков позиция пролистывания сбивается при каждом
обновлении, а чат с агентом дёргается на приходе событий. При нажатии
«Продолжить» или «Закрыть» экран прыгает, нажатие выглядит несостоявшимся, и
человек жмёт второй раз. Базовая беда одна: `refresh()` висит на focus окна и на
hashchange и пересобирает экран целиком (`static/app.js`, около строки 2985).
`renderBoard`, `renderDrafts` и лента чата строят DOM заново, и позиция скролла
теряется. Спокойное обновление сделано только форме задачи: `renderTask` при
несохранённой правке вешает плашку вместо перерисовки.

Размер материала: в `static/app.js` три тысячи строк и тринадцать функций
`render*`, из них экран пересобирает не меньше пяти на каждый возврат в браузер.
Поймано пользователем на приёмке 2026-08-13 поимённо: прыжок экрана при нажатии
кнопок, дёргающийся чат, сбитая позиция списка черновиков.

## Чего хотим

Общий слой перерисовки для экранов, а не заплатка на каждый: изменившиеся узлы
обновляются, позиция пролистывания и фокус переживают обновление, а нажатие
кнопки не сдвигает экран.

## DoD

- Слой частичной перерисовки закрывает списки задач и черновиков и ленту чата,
  то есть места, названные приёмкой; целиком экран на обновлении не
  пересобирается.
- Позиция пролистывания и фокус переживают обновление по focus окна и по приходу
  события: юнит статики под node с игрушечным DOM сверяет их до и после
  перерисовки и падает на старом коде.
- Нажатие кнопки действия не сдвигает экран: узел строки обновляется на месте.
- Поведение описано в README дашборда, раздел про перерисовку.

- Ценность 8. Сквозное требование шестнадцатого сценария цели DK-327: пока экран

- Неопределённость 3. Подход понятен (частичная перерисовка вместо полной), а

- Поправка на баг 5. Дефект поведения экрана, а не отсутствующая работа:

Инвариант зависимости: строка держит DK-317 (43), DK-289 (43) и DK-305 (37), её

## Приёмка

- вид: mixed
- барьер «глаза»: сквозное требование сценария 16, экран не прыгает и позицию
  пролистывания не теряет
  - утверждённый макет: не годится, предмет тут не раскладка, а поведение экрана
    на обновлении, и макета на такое не бывает;
  - headless-браузер с замером: годится для чисел, позиция пролистывания и число
    пересобранных узлов замеряются и уходят агенту;
  - тест по разметке и стилям: годится для правил, а дёрганье экрана под рукой им
    не ловится.

## Итог

В `static/app.js` завёлся общий слой частичной перерисовки: `sync` обновляет
детей коробки по описаниям с ключом и отпечатком, `viewSnap` с `viewBack`
снимают и возвращают место (прокрутку списка, фокус с кареткой, якорь сдвига
раскладки). На слое держатся доска, накопитель черновиков, полоса живых работ
и лента чата, то есть все места, названные приёмкой.

Что изменилось с экрана:

- обновление по фокусу окна не трогает узлы, у которых отпечаток тот же:
  прокрутка, фокус на кнопке и раскрытый текст черновика остаются на месте;
- нажатие кнопки строки не сдвигает экран. Строка результата (`.actmsg`)
  появляется над списком, и раньше он уезжал на её высоту вниз; теперь
  `sayResult` берёт снимок до слов и возвращает картинку по якорю;
- разговор собирается один раз на заход. Экранная развилка `refresh` разошлась
  надвое: `refresh` снимает и возвращает место, `paint` собирает экран. Живые
  потоки закрываются при уходе с экрана, а не на каждом обновлении, поэтому
  перечитанная доска больше не рвёт поток событий чата и не собирает ленту
  заново; на экране чата обновление меняет только шапку и кнопку стопа.

Экран, который собирается целиком (задача, лента, главная, «Агенты», форма
заведения), тем же снимком держит хотя бы позицию пролистывания. Переход это
другой экран, и он открывается сверху.

Тесты: стенд `testdata/screen_keep.mjs` поднимает статику в node с игрушечным
DOM, где опустевшая коробка сбрасывает прокрутку, а снятый с дерева узел
теряет фокус. После обновления стенд смотрит прокрутку, фокус, раскрытую
запись, набранное в поле чата и число открытых потоков. Go-тест
`TestScreenKeepsPlaceOnRefresh` зовёт его. Четыре старых проверки текста статики
поправлены под новые имена (`paint` вместо `refresh` у развилки экранов,
`sync(box, items)` вместо `box.replaceChildren()` в ленте чата).

## Сценарий проверки

Смешанный. Агентская часть гоняется командами из корня чекаута, барьер «глаза»
остаётся человеку.

1. Регрессия закрыта, на старом коде стенд краснеет:

   ```sh
   regcheck --base main \
     --tests tools/dashboard/board_test.go,tools/dashboard/testdata/screen_keep.mjs \
     -- bash -c 'cd tools/dashboard && GOWORK=off go test -run TestScreenKeepsPlaceOnRefresh .'
   ```

   Ожидание: «тест краснеет на main и проходит на текущем коде».

2. Стенд частичной перерисовки проходит сам по себе, и видно, что он проверял:

   ```sh
   cd tools/dashboard && node testdata/screen_keep.mjs static/app.js
   ```

   Ожидание: строка «частичная перерисовка: доска, черновики и лента чата
   держат место и фокус», код возврата 0.

3. Остальной дашборд не сломан:

   ```sh
   cd tools/dashboard && GOWORK=off go test ./...
   ```

   Ожидание: `ok`.

Пользовательская часть, барьер «глаза»: открыть доску с телефона или ноутбука,
пролистать список вниз, переключиться на другое окно и вернуться. Список стоит
на том же месте, чат при обновлении не дёргается, а нажатие «Продолжить» или
«Закрыть» не сдвигает экран, и повторно жать не хочется.
