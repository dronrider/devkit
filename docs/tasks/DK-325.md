# DK-325: dashboard: поиск задач по доске и архиву

записан 2026-08-13, оформлен нарезкой цели DK-327 2026-08-14

## Что происходит

Поиска на дашборде нет: ни поля, ни фильтра по тексту (единственный фильтр в
ленте по типу события, `static/app.js`), задача находится глазами по доске, из
ленты либо прямым хэшем. С ростом доски (за семьдесят строк в Backlog плюс архив)
глазами уже не находится.

Где полю стоять и как выглядит выдача, решает макет DK-328: пользователь назвал
предварительные изменения в дизайне частью работы.

## Чего хотим

Поиск по ID, заголовку и тексту файла задачи, по живой доске и по архиву, с
телефона и из браузера.

## DoD

- Поиск ищет по ID, заголовку и тексту файла задачи, по живой доске и по архиву;
  место поля и вид выдачи по макету DK-328.
- Поиск живёт ручкой на сервере, клиент не подменяет её чтением всей доски.
- Работает с телефона: поле не съедает экран, выдача листается.
- Тест ручки на выдачу, на пустой запрос и на архив, юнит статики под node на
  поле, шаг смока на поиск по синтетической доске и синтетическому архиву.
- Поведение описано в README дашборда.

## Ранг

`25+7+3+0+2 = 37`, P2.

- Серьёзность 25 (Major). За семьдесят строк в Backlog плюс архив, и задача
  находится глазами. Обход дешёвый и очевидный: открыть файл доски или зайти
  прямым хэшем, если номер помнишь.
- Ценность 7. Десятый сценарий цели DK-327, и с ростом доски это ежедневный шаг,
  а не редкий.
- Неопределённость 3. Правка едет через границу сервер-клиент, а в архиве сотни
  файлов задач, и цена запроса по ним видна на прогоне, а не в исходниках.
- Поправка на баг 0. Поиска не было никогда.
- Рычаг 2. Своя польза: находить задачу быстрее приходится в каждой второй
  сессии.

## Итог

Поиск задач живёт ручкой `GET /api/projects/{p}/search?q=`
(`tools/dashboard/search.go`) и своим экраном выдачи `#проект/find/<запрос>`.
Реализовано по принятому LLD DK-328, решение 2.

Что делает сервер. Индекса он не заводит вовсе: доску берёт из своего кэша,
накопитель у `taskctl draft list --json`, архив разбирает файлом тем же
`archiveRows`, что и состав цели, а текст ищет обходом `docs/tasks` вместе с
подкаталогами `archive/<год>` и `drafts`. Инвалидация индекса стоила бы дороже
обхода сотни мелких файлов из горячего кэша файловой системы, а удерживают цену
потолки выдачи (короче двух символов запрос не ищется вовсе, в группе до
двадцати строк, в текстовой до тридцати, остаток едет числом в `more`) и
задержка ввода на клиенте. Отвечает ручка четырьмя группами в постоянном
порядке, и строка выдачи у них одного вида: разница между группами это
заполненные поля, поэтому у архивной строки ранга и цены нет не по забывчивости
клиента, а потому что в архиве этих колонок не существует. Задача, нашедшаяся
по номеру или заголовку, в текстовую группу второй строкой не попадает. Запрос,
похожий на номер, поднимает точное попадание первой строкой, и `324`, `dk-324`
и `DK324` считаются одним номером: держать в голове префикс своей доски
человеку не надо. Ищется всё подстрокой, а не выражением, поэтому набранная с
телефона скобка или звёздочка не оборачивается отказом.

Что видно с экрана. На ноутбуке поле стоит в шапке доски слева от
колокольчика, и косая черта ставит в него курсор. На телефоне шапка тесная, там
же стоит лупа рядом с колокольчиком, а поле во всю ширину открывается на самом
экране выдачи и сразу ждёт набора. Выдача занимает свой экран, а не выпадает
списком под полем: запрос в адресе делает её ссылкой и переживает кнопку
«назад», а на телефоне выпадающий список дрался бы с клавиатурой за нижнюю
половину экрана. Совпадения подсвечены везде, включая заголовки и цитаты из
текста задач, урезанная группа подписана хвостом («ещё 7 совпадений, уточните
запрос»), а пустые случаи говорят словами сервера, чего ждёт короткий запрос и
где искали, если не нашлось ничего. Набранное уходит одним запросом по
задержке в четверть секунды, поле между буквами не пересобирается и курсора не
теряет, а ответ на прежний запрос поверх свежей выдачи не рисуется.

## Сценарий проверки (агентский)

1. `cd tools/dashboard && GOWORK=off go test ./...`: полный модуль зелёный.
   Ручку держат тесты `search_test.go` (состав групп, цитаты с местом файла,
   поиск по номеру, короткий запрос, ненайденное, спецсимволы, потолки,
   дверь входа).
2. `cd tools/dashboard && node testdata/screen_keep.mjs static/app.js`: стенд
   печатает свою строку и выходит нулём. Там же проверен поиск: выдача
   собирается своим экраном, архивная строка идёт без ранга, совпадения
   подсвечены в заголовке и в цитате, набор уходит одним запросом, поле держит
   курсор, запоздавший ответ не рисуется поверх свежего, а в поиск ведут косая
   черта и лупа шапки.
3. `regcheck --base main --tests tools/dashboard/search_test.go,tools/dashboard/board_test.go,tools/dashboard/testdata/screen_keep.mjs -- sh -c 'cd tools/dashboard && GOWORK=off go test -run "TestSearch|TestScreenKeepsPlaceOnRefresh|TestStaticBoardNarrowRow" ./...'`
   из корня дерева задачи: тесты краснеют на main и проходят на текущем коде.
4. `cd tools/dashboard && GOWORK=off go run . smoke`: сквозной прогон вторым
   шагом ищет по живой доске, по архиву и по тексту файла задачи на
   синтетическом проекте.

Итог проверяется кодами возврата команд, не на глаз.

Пользовательская часть, без глаз не проверить: на живом дашборде набрать в поле
шапки номер задачи и слово из текста постановки, пройти по строке выдачи на
экран задачи, нажать косую черту вне поля ввода и убедиться, что курсор встал в
поиск; с телефона открыть поиск лупой и проверить, что поле не съедает экран, а
выдача листается.

## Ревью

- Отказ taskctl draft list остаётся при своей группе и не роняет весь поиск, это заявлено ключевым решением (Итог, README): доска и архив читаются мимо утилиты. Ручное воспроизведение подтверждает поведение (разогретый кэш доски + PATH без taskctl: board и archive остались, drafts.Note заполнилась причиной), но search_test.go этот путь не проверяет ни одним тестом, хотя нужный приём (t.Setenv("PATH", t.TempDir())) уже есть в server_test.go. Правка без теста на заявленное поведение это незакрытая правка (RULES.core, «Тесты обязательны»). Исправлено: TestSearchDraftsFailureStaysInGroup в search_test.go греет кэш доски первым запросом, убирает taskctl из PATH и сверяет, что доска с архивом отвечают по-прежнему, а причина стоит в группе черновиков; краснота проверена мутацией (отказ группы, поднятый до отказа всей ручки, роняет тест).
