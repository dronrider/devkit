# DK-325: dashboard: поиск задач по доске и архиву

записан 2026-08-13, оформлен нарезкой цели DK-327 2026-08-14

## Что происходит

Поиска на дашборде нет: ни поля, ни фильтра по тексту (единственный фильтр в
ленте по типу события, `static/app.js`), задача находится глазами по доске, из
ленты либо прямым хэшем. С ростом доски (за семьдесят строк в Backlog плюс архив)
глазами уже не находится.

Где полю стоять и как выглядит выдача, решает макет DK-328: пользователь назвал
предварительные изменения в дизайне частью работы.

## Чего хотим

Поиск по ID, заголовку и тексту файла задачи, по живой доске и по архиву, с
телефона и из браузера.

## DoD

- Поиск ищет по ID, заголовку и тексту файла задачи, по живой доске и по архиву;
  место поля и вид выдачи по макету DK-328.
- Поиск живёт ручкой на сервере, клиент не подменяет её чтением всей доски.
- Работает с телефона: поле не съедает экран, выдача листается.
- Тест ручки на выдачу, на пустой запрос и на архив, юнит статики под node на
  поле, шаг смока на поиск по синтетической доске и синтетическому архиву.
- Поведение описано в README дашборда.

## Ранг

`25+7+3+0+2 = 37`, P2.

- Серьёзность 25 (Major). За семьдесят строк в Backlog плюс архив, и задача
  находится глазами. Обход дешёвый и очевидный: открыть файл доски или зайти
  прямым хэшем, если номер помнишь.
- Ценность 7. Десятый сценарий цели DK-327, и с ростом доски это ежедневный шаг,
  а не редкий.

  файлов задач, и цена запроса по ним видна на прогоне, а не в исходниках.
- Поправка на баг 0. Поиска не было никогда.
- Рычаг 2. Своя польза: находить задачу быстрее приходится в каждой второй
  сессии.
