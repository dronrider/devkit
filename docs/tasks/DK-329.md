# DK-329: taskctl add с --link и не агентской приёмкой затирает текст черновика

записан 2026-08-14

## Черновик

Заведение строки по черновику с --accept mixed|user и --link теряет текст
черновика.

## Что происходит

promoteDraft (`tools/taskctl/ops.go`, строка 303) переносит
`docs/tasks/drafts/<ID>.md` в `docs/tasks/<ID>.md`, но при заданном --link
переменная taskFile остаётся пустой: заполняющая её ветка (строки 309-318)
работает только без ссылки. Дальше ветка заведения файла с разделом
«Приёмка» (строка 323) срабатывает по условию `taskFile == ""`, и
os.WriteFile (строка 330) кладёт поверх перенесённого текста скелет из
заголовка и пустого раздела. Потеря тихая: команда отчитывается «черновик
перенесён» и выходит с нулём.

Проверено 2026-08-16 прогоном на синтетической доске во временном
репозитории: `add --id ... --accept user --barrier глаза --link
tasks/<цель>.md` оставил в `docs/tasks/<ID>.md` четыре строки скелета, текст
черновика пропал. Вариант без --link безопасен: taskFile заполняется
найденным файлом, скелет не пишется.

Поймано вживую на нарезке цели DK-327 (2026-08-14): потерялись тексты
DK-316 и DK-324, восстановлены из контекста сессии. Не агентский вид
приёмки со ссылкой на файл цели это штатный виток нарезки (у LLD-строк вид
user), значит без правки риск повторяется на каждой следующей цели.

## Чего хотим

Заведение строки из черновика не теряет текст ни в какой комбинации флагов.
Перед записью скелета проверяется существование файла: раздел «Приёмка»
дописывается к перенесённому черновику, а не переписывает его. Срабатывание
ветки не зависит от того, задан ли --link.

## DoD

- `taskctl add --id` по черновику с `--accept user` (или `mixed`),
  `--barrier` и `--link` оставляет в `docs/tasks/<ID>.md` текст черновика и
  дописывает к нему раздел «Приёмка»;
- прогон на синтетической доске, как в проверке выше, идёт в тест
  `tools/taskctl` и падает на старом коде;
- без --link поведение прежнее: текст цел, скелет не пишется.

Вычитка: 1 файл, 4 правки, 2 пометки, 2026-08-16.

## Сценарий проверки

Агентский, целиком машинный. Проверяется выкаченный бинарь taskctl из PATH
на одноразовой доске во временном репозитории, прод не меняется. Первый шаг
повторяет исходный виток нарезки цели, на котором текст и терялся.

Завести доску и цель нарезки:

```sh
tmp=$(mktemp -d)
mkdir -p "$tmp/docs/tasks"
git -C "$tmp" init -q -b main
git -C "$tmp" config user.email t@t && git -C "$tmp" config user.name t
taskctl -C "$tmp" init --prefix T --name "песочница"
git -C "$tmp" add docs && git -C "$tmp" commit -qm init
taskctl -C "$tmp" add --id T-001 --title "Цель" --type LLD --rank "25+0+2+0+3" --accept agent --link tasks/T-001.md
printf '# T-001: Цель\n\nНарезка на строки.\n' > "$tmp/docs/tasks/T-001.md"
```

1. Исходный баг: оформление черновика со ссылкой на файл цели и не агентской
   приёмкой, как в нарезке DK-327.

   ```sh
   taskctl -C "$tmp" draft "строка цели: текст черновика"
   taskctl -C "$tmp" add --id T-002 --title "Строка из черновика" --type task --rank "0+1+1+0+1" --accept user --barrier глаза --link tasks/T-001.md
   cat "$tmp/docs/tasks/T-002.md"
   taskctl -C "$tmp" show T-002
   ```

   Ожидание на исправленном: команда выходит с нулём и печатает «черновик
   перенесён», в файле стоит текст черновика (раздел «Черновик») и дописан
   раздел «Приёмка» с видом user и барьером «глаза», ссылка строки ведёт на
   tasks/T-001.md. На баге вместо текста черновика в файле оставались четыре
   строки скелета.

2. Та же комбинация без --link: текст цел, скелет не пишется, раздел
   дописан, ссылка строки ведёт на файл самой задачи.

   ```sh
   taskctl -C "$tmp" draft "второй черновик без ссылки"
   taskctl -C "$tmp" add --id T-003 --title "Без ссылки" --type task --rank "0+1+1+0+1" --accept mixed --barrier глаза
   cat "$tmp/docs/tasks/T-003.md"
   taskctl -C "$tmp" show T-003
   ```

3. Без черновика поведение прежнее: заводится скелет из заголовка и раздела
   «Приёмка».

   ```sh
   taskctl -C "$tmp" add --id T-004 --title "Без черновика" --type task --rank "0+1+1+0+1" --accept user --barrier глаза
   cat "$tmp/docs/tasks/T-004.md"
   ```

4. `taskctl -C "$tmp" lint` молчит: доска и файлы задач после шагов 1-3 в
   порядке.

5. Тесты: `go test .` в tools/taskctl зелёный, а
   `regcheck --base main -- go test ./tools/taskctl -run TestAddNonAgentAppendsAcceptance -count=1`
   докладывает «тест краснеет на main и проходит на текущем коде».
