# DK-330: Подсказка taskctl add и set не называет --accept и --barrier

## Что происходит

После DK-298 у `taskctl add` появились флаги вида приёмки: `--accept` без
него команда отказывает, а `--barrier` обязателен для `mixed` и `user`. Шапка
`usageText` (`tools/taskctl/main.go`) перечисляет прежний набор `add`:
`--title`, `--type`, `--rank`, `--cost`, `--link`, `--status`, `--id`,
`--reason`; про `--accept` и `--barrier` там ни слова. То же у `set`: флаг
`--accept` есть в разборе (`main.go:356`), в шапке нет. Узнаются флаги только
из отказа команды («для --accept mixed нужен --barrier <ключ> из шести
барьеров») либо из `-h` подкоманды. Поймано на нарезке цели DK-327
2026-08-14; на 2026-08-18 воспроизводится, `taskctl` без аргументов печатает
шапку без обоих флагов.

Обход дешёвый (второй заход после отказа), но подсказку читает агент на каждом
груминге и нарезке, и лишний заход стоит хода.

## Чего хотим

Шапка `add` и `set` в `usageText` называет `--accept agent|mixed|user` и
`--barrier <ключ>` с закрытым списком барьеров (глаза, доступ, необратимость,
секрет, согласие, событие). Тест сверяет шапку с набором флагов, объявленных
у подкоманды, чтобы следующее расхождение ловилось само.

## DoD

`taskctl` без аргументов и `taskctl help` печатают у `add` и `set` флаги
`--accept` и `--barrier` со списком ключей барьера. Тест на подсказку падает
на старом `usageText` (regcheck красный до фикса) и проходит после; тот же
тест сверяет флаги шапки с флагами `flag.FlagSet` подкоманды `add`.

## Ранг

`25+4+0+5+2 = 36`, P2.

- Серьёзность 25. Трение с дешёвым обходом: флаг узнаётся из отказа команды
  вторым заходом.
- Ценность 4. Регулярная операция: `add` зовётся на каждом груминге и каждой
  нарезке цели.
- Неопределённость 0. Рутина: строка справки и тест на неё.
- Поправка на баг +5. Подсказка отстала от кода после DK-298.
- Рычаг 2. Небольшая своя польза: агент не тратит ход на отказ.

Цена S: правка одной константы и один тест.

## Ход работы

Исправлена шапка `add` и `set` в usageText (tools/taskctl/main.go) с добавлением флагов `--accept agent|mixed|user` и `--barrier глаза|доступ|необратимость|секрет|согласие|событие` для `add`. Написаны три теста на соответствие usageText: регрессионный (шапка содержит флаги) и две проверки (все флаги в подкоманде упомянуты в справке). Тесты краснеют на main и проходят на текущем коде.

## Тесты

Три новых теста в tools/taskctl/main_test.go:

- TestUsageTextAcceptBarrier: регрессионный тест проверяет, что usageText содержит `--accept agent|mixed|user` и `--barrier` с перечислением ключей барьера для `add`, а также `--accept agent|mixed|user` для `set`.
- TestAddCommandFlags: проверяет, что все специфичные для `add` флаги (title, type, rank, cost, link, status, id, reason, accept, barrier) упомянуты в usageText.
- TestSetCommandFlags: проверяет, что все специфичные для `set` флаги (title, type, rank, cost, link, accept) упомянуты в usageText.

Прогон: `cd tools/taskctl && GOWORK=off go test ./...` показывает ok.
Краснота regcheck: `regcheck --base main --tests tools/taskctl/main_test.go -- bash -c "cd tools/taskctl && GOWORK=off go test -v -run 'TestUsageTextAcceptBarrier|TestAddCommandFlags|TestSetCommandFlags'"` показывает тесты краснеют на main и проходят на текущем коде.

## Сценарий проверки

Агентский сценарий на собранном бинаре:

1. `taskctl help` показывает справку с флагами `--accept agent|mixed|user` для `add` и `set`.
2. `taskctl help` показывает флаг `--barrier глаза|доступ|необратимость|секрет|согласие|событие` для `add`.
3. `taskctl add --help` не падает и показывает справку со всеми флагами.
