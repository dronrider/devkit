# DK-342: dashboard: состояние «доставлено агенту» в очереди исходящих и честная плашка чата

## Постановка

Третья строка разбивки LLD DK-136 (docs/lld/DK-136-live-chat.md, пункт 3):
дашборд показывает состояние «доставлено агенту» в очереди исходящих чата
цели и честную плашку. Почтальон DK-341 уже в main: отметки доставки лежат
в .devkit/goal-<ID>.mail (две строки на запись: время с сессией и
доставленная строка «Входящих» целиком). Состав, поведение плашки и тесты в
LLD, он решение и есть.

## Ход работы

- Исполнение: opus/medium по вердикту pick, 2026-08-15.
- Чтение отметок и правило живости легли своим файлом `tools/dashboard/mail.go`:
  предмет у них общий, почта цели, и в `messages.go` они соседствовали бы с
  разбором «Входящих», от которого не зависят.
- Живость витка дашборд считает сам, второй реализацией правила почтальона.
  Позвать `hooks/inbox.py` подпроцессом было бы дешевле по строкам, но у хука
  нет режима «скажи про цель», а заводить его ради одного читателя дороже
  полутора десятков строк на замок с метками. Цену расхождения держит
  `TestGoalLiveRuleMatchesPostman`: он сверяет порог, слово строки доставки и
  формат времени прямо по тексту `hooks/inbox.py`.
- Плашка получила третье состояние вместо двух, и признак ей нужен свой:
  живость доставки приходит с ручки сообщения полем `live`, а список работ
  (`liveWorks`) остался при своём деле, показывать работу на экране. Разводить
  их пришлось аккуратно: стенд DK-319 требует, чтобы цель, ведомая записью
  реестра или чужим окном, не звалась стоящей, и это требование в силе. Ответ
  такой: «цикл не идёт» по-прежнему судится работами, а минуты до доставки
  судятся живостью, и у цели с мёртвым циклом плашка возвращается к прежним
  словам про следующую рабочую итерацию.
- Доставка приходит без человека, поэтому открытый чат перечитывает «Входящие»
  сам раз в пятнадцать секунд. Отсчёт этот задел стенд очереди исходящих
  (`testdata/outbox_offline.mjs`): он считал запланированные таймеры глобально,
  и живая очередь первого сценария приносила туда свой. Очередь со сцены
  уходит своим `stop()`, проверка осталась прежней.
- Вычитка: 3 файла, 7 правок, 1 пометка, 2026-08-15.
- Ревью: субагент sonnet/high по вердикту pick (квота: week_all 77%, week_max 66%, снимок 38м назад, сдвига нет), 2026-08-15.

## Итог

У реплики в чате цели пропал разрыв между «ждёт витка» и «прочитано агентом»:
внесённая почтальоном в идущий виток строка подписывается «доставлено агенту»
со временем и сессией витка, и приходит это состояние без перезагрузки
страницы. Ручка `GET .../goals/{id}/message` отдаёт отметки полем `delivered`
и живость витка полем `live`; своей ручки каналу не понадобилось. Текст
плашки над полем ввода стал разным вместо одинакового для всех: у живого
витка в ней указаны минуты до доставки и отдельной фразой сказано про
поворот в работе, у цели с мёртвым циклом остаются прежние слова, а «цикл
цели не идёт» с кнопкой подъёма витка работает как работало (DK-319). Живой прогон на стенде показал ручку
целиком: без отметок `delivered` пуст, отметка почтальона доезжает со временем
и сессией, замок с живым `pid` поднимает `live`.

## Сценарий проверки (агентский)

Юниты закрывают разбор отметок, ручку и разметку клиента, но собранного
бинаря с настоящими `taskctl` и доской они не трогают, и живой шаг здесь
ровно про это: дашборд поднимается на своём доме, доска заводится настоящим
`taskctl init`, а отметку кладёт файл, как её кладёт почтальон. Оговорка:
настоящий почтальон в связке с настоящим браузером этим шагом не проверяется,
канал доставки закрыт живым прогоном DK-341, а экран на приёмке цели смотрит
человек с телефона. Чужие проекты и живой `~/.devkit` не трогаются:
стенд весь во временном каталоге со своим `HOME`.

```sh
# 1. Живая ручка: отметка доставки и живость витка на собранном бинаре.
export W=~/projects/devkit-dk-342 P=$(mktemp -d)
mkdir -p "$P/bin" "$P/projects/demo"
(cd "$W/tools/taskctl" && GOWORK=off go build -o "$P/bin/taskctl" .)
(cd "$W/tools/dashboard" && GOWORK=off go build -o "$P/bin/dashboard" .)
export PATH="$P/bin:$PATH" HOME="$P/home"
mkdir -p "$HOME/.devkit"
cd "$P/projects/demo" && git init -q . && git config user.email a@b && git config user.name a
taskctl init --prefix XR --name demo >/dev/null
taskctl add --title "Цель: живой прогон DK-342" --type task --rank "25+8+2+0+3" --cost XL --status in-progress
taskctl file XR-001 >/dev/null
printf '\n## Входящие\n\n- 2026-08-15 10:00, из дашборда: стой, не туда\n\n## Журнал\n\n- виток 1\n' \
  >> docs/tasks/XR-001.md
printf 'root = %s\nport = 7342\naddr = 127.0.0.1\ntoken = live-token\n' "$P/projects" \
  > "$HOME/.devkit/dashboard.local"
chmod 600 "$HOME/.devkit/dashboard.local"
("$P/bin/dashboard" serve > "$P/serve.log" 2>&1 &)
sleep 2
curl -s -c "$P/jar" -X POST -H 'Content-Type: application/json' \
  -d '{"token":"live-token"}' http://127.0.0.1:7342/api/login
export M=http://127.0.0.1:7342/api/projects/demo/goals/XR-001/message
curl -s -b "$P/jar" "$M"; echo
#    жду: строка лежит в pending, delivered пуст, live false.

printf '%s 8f2a1c30-1111-2222\n%s\n' "$(date +%Y-%m-%dT%H:%M:%S)" \
  "2026-08-15 10:00, из дашборда: стой, не туда" > .devkit/goal-XR-001.mail
curl -s -b "$P/jar" "$M"; echo
#    жду: delivered называет ту же строку со временем и сессией, а из pending
#    она не ушла: доставленное это не прочитанное.

mkdir -p .devkit/goal-XR-001.lock
sleep 300 & echo $! > .devkit/goal-XR-001.lock/pid
curl -s -b "$P/jar" "$M"; echo
#    жду: live true. Замок с живым pid это идущая оболочка, и плашка на таком
#    ответе обещает минуты до доставки.

pkill -f "$P/bin/dashboard serve"; pkill -f "sleep 300"; rm -rf "$P"

# 2. Клиент: очередь исходящих и плашка на игрушечном DOM.
(cd ~/projects/devkit-dk-342/tools/dashboard && node testdata/screen_keep.mjs static/app.js)
#    жду: строку про частичную перерисовку и ни одной строки отказа.

# 3. Ничего не сломано.
(cd ~/projects/devkit-dk-342/tools/dashboard && GOWORK=off go test ./... 2>&1 | tail -3)
#    жду: ok на модуле целиком, вместе со сквозным прогоном smoke.
```

Шаг 1 на коде `main` не проходит: полей `delivered` и `live` в ответе нет
вовсе, отметки там никто не читает. Шаг 2 там же падает первой проверкой
плашки: живому витку она обещает следующую рабочую итерацию.
