# DK-345: почта любой живой сессии, а не только витка цели

## Задача

Ящик писем и почтальон построены под цель: письма лежат в
`.devkit/goal-<ID>.mail`, `hooks/inbox.py` вносит их в контекст на ходе
инструмента, а `goal-run.py --ask` умеет ждать ответа (LLD DK-136). Реплика с
дашборда доезжает только до витка цели, а до исполнителя задачи и до грумера
черновика нет, и экран `/chat/<ID>` выдаётся только работам вида goal.

Нужен общий носитель писем с адресацией сессией, а не работой: у задачи чатов
бывает несколько, и письмо адресуется тому, кто его прочитает. Третьей копии
механики отметок, признака ожидания и замка рядом с ящиком цели и ящиком
черновика не заводить, иначе они разъедутся молча.

## DoD

- Адресованная сессии реплика доезжает своей сессии: письмо ложится строкой
  в ящик `.devkit/mail` дерева работы, почтальон `hooks/inbox.py` вносит его
  в контекст на завершённом ходе инструмента и забирает из ящика. Реплика без
  адресата доезжает любой сессии дерева, этим ответ припаркованной задаче
  (DK-400) достаётся пробуждённой сессии без правки почты.
- Замок ящика один с почтальоном (`flock` через `take_mail_lock`), отправка
  под занятым замком отказывает 503; отметок доставки нет, отсутствие строки
  и есть прочитанное, третьей копии механики отметок и ожидания нет.
- Ручка `POST /api/projects/{p}/sessions/{sid}/message` кладёт реплику,
  честно говорит idle по молчащему транскрипту и отказывает словами по чужому
  id сессии, удалённому дереву и сессии-цели; каталог `.devkit/mail` стоит
  в `.gitignore`.
- regcheck зелёный.

## Ход работы

- Разработка: подпроцесс glm-5.3/medium по вердикту pick (квота: объявления нет, корректор выключен), 2026-08-17 17:18-17:18.

Носитель выбран общий каталог `.devkit/mail` в дереве работы: ящик
`<имя>.inbox`, письма строками, адресат сессии в самой строке перед подписью
дашборда. Имя ящика живёт дольше сессии: `task-<ID>` для сессии с узнанной
задачей, `sess-<ID>` личный для остальных. Ящик не коммитится. Читает и
доставляет письма тот же почтальон `hooks/inbox.py` на завершённом ходе
инструмента, вторым проходом после целей: доставленная строка уходит из ящика
под тем же `flock` через общий `take_mail_lock`, признак ожидания
`<имя>.ask` тем же форматом штампа, общей оказалась и функция его разбора.
Третьей копии механики нет: отметок доставки у ящика вовсе не заводилось,
отсутствие строки и есть отметка, отдельный файл отметок рос бы вечно, потому
что читателя, забирающего строку своей записью, у ящика нет. Пишет строку
дашборд новой ручкой `POST /api/projects/{p}/sessions/{sid}/message`
(tools/dashboard/mailbox.go): сессия ищется по транскриптам, дерево берётся
из хвоста её каталога, ящик называется задачей сессии, запись идёт под тем же
замком ящика, повтором считается такая же лежащая строка, сессия-цель
отправляется к ручке цели, у протухшего транскрипта ответ честно говорит
«не идёт». Строка без адресата доезжает любой сессии дерева: этим ответ
припаркованной задаче (DK-400) достанется пробуждённой сессии без всякой
правки почты. Экраны чата задачи не трогал: UI это пункты 7-8 самой цели
DK-397, доставка работает без них.

Отвергнутые варианты:

- ящик на голом id сессии без ящика задачи: сессии одноразовы, письмо
  припаркованной задаче лежало бы мёртвым грузом, пока её не поднимут тем же
  ключом `--session-id`;
- письма в файле задачи `docs/tasks/<ID>.md`: дашборд пишет в основной
  чекаут, сессия-исполнитель работает в боковом дереве и увидела бы письмо
  только после слияния, да и правка файла на каждом ходе инструмента
  наплодила бы коммитов;
- файл отметок доставки у ящиков, как у цели: у отметки цели есть читатель
  (виток забирает строку записью «Входящих»), у ящика читателя нет, отметки
  росли бы вечно, а уборка была бы второй механикой поверх первой;
- подъём от `cwd` до ближайшего `.devkit` вместо границы `.git`: сессия
  бокового дерева задачи поднялась бы к основному чекауту и забрала чужую
  почту, `.git` у worktree это файл, и он честно меряет границу;
- поле ввода на экране сессии дашборда: экраны чата задачи перерабатываются
  пунктами 7-8 цели DK-397, строить ввод до них значило бы переделывать его
  следом.

Цена общего прохода: почтальон больше не выходит до разбора события по
пустому реестру целей, потому что ящики живут и без целей; разбор события и
обход каталога ящиков стоят доли миллисекунды.
