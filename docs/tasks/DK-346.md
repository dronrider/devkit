# DK-346: devkitctl: параллельный раннер питоновой сюиты, классы отдельными процессами

## Ход работы

- Исполнение: подпроцесс glm-5.2/high по вердикту pick (квота: объявления нет, корректор выключен), 2026-08-15.
- Раннер `tools/devkitctl/suite.py`: перечень классов тем же загрузчиком, что у
  discover, прогон класса своим процессом `python3 -m unittest -v модуль.Класс`,
  общая очередь с потолком воркеров, тяжёлые по числу тестов уходят первыми.
  Счёт читается из строки итога unittest, а не из подсчёта строк прогона:
  докстринг теста уезжает отдельной строкой и уносил бы «... ok» с имени.
- Сверка счёта с последовательным discover встроена в раннер: расхождение это
  код 1 с находкой, погибший без итога процесс считается нулём и ловится той
  же сверкой. Провалившийся класс печатается выводом целиком.
- Тесты раннера в `tools/devkitctl/suite_test.py` (12 тестов) на синтетическом
  каталоге с короткими модулями: живая сюита для проверки раннера тяжела.
  Связка проверена regcheck: тесты краснеют на main, зелёные на правке.
- Замеры на машине исполнителя (10 ядер, нагрузка чужими прогонами на части
  замеров, плато 8-16 воркеров): последовательный discover 430 с до правки и
  407 с с новыми тестами, раннер 490 тестов в 95 классах за 128-143 с при
  `-j16`, за 134-143 с при умолчательных 12. Счёт обеих прогонов 490,
  два прогона подряд зелёные. Коммит f6a84317 (код и тесты), a56063aa (дока).
- Порог 100 с на машине исполнителя не взят: стена упирается не в число
  воркеров (CPU занят 2,5-3 ядра из 10), а в файловую систему и системных
  демонов macOS (Xprotect, mds, fseventsd забирают столько же CPU, сколько
  сами тесты), а единоличный тяжёлый класс MachineContourTest растягивается с
  54 с в тишине до 118 с под нагрузкой. Вскрытие тяжёлых юнитов это соседний
  кандидат 3 цели, там же стоит ждать и порог.
- Ревью: подпроцесс glm-5.2/high по вердикту pick (квота: объявления нет, корректор выключен), 2026-08-15.

## Сценарий проверки

Агентский. Прогон идёт по выкаченной ревизии, счёт тестов сверяется с
последовательным discover: сверка встроена в сам раннер, расхождение или
погибший воркер это код 1 с находкой в выводе.

1. Прогон сюиты devkitctl раннером:

   ```
   cd tools/devkitctl && python3 suite.py; echo "exit=$?"
   ```

   Ожидание: `exit=0`, строка итога `Ran ... tests ... across ... classes` и
   последняя строка `OK`; строка счёта совпадает со счётом последовательного
   discover, который раннер считает сам и печатает расхождение отдельной
   находкой.
