### Правки

1. `serve_forever(poll_interval=0.02)` у локального сервера релизов в
   `update_test` (`UpdateCase.setUp`). Замер: shutdown при интервале по
   умолчанию 0,502 с, при 0,02 с уже 0,011 с. Сервер тестовой нагрузкой не
   загружен, частый опрос ему ничего не стоит.
2. Кеш git-чтений в `update.git` (`git_cache(True)` на прогон doctor в
   `main`). Ответы читающих команд (`tag --list`, `rev-parse`, `log`,
   `status`, `merge-base`, `symbolic-ref --quiet`) запоминаются до конца
   прогона, любая меняющая команда (fetch, checkout, `tag <имя>`) кеш чистит.
   Чтения из `devkitctl.py` (devkit_checkout, code_commit, version_gap,
   unsaved_go) переведены с собственного `run` на `update.git`, иначе кеш их
   не видел. По умолчанию кеш выключен: прямые вызовы из тестов ходят в git
   между собственными мутациями.
3. Диспетчер заглушек в `testenv` (`Sandbox.bin`): заглушки бинарей devkit и
   tmux лежат симлинками на один скрипт с разбором `case "$0"`, каждое имя
   отвечает своей строкой `--version`. Диспетчер прогревается холостым
   запуском при создании стенда. Замер: 12 отдельных файлов 2,65 с против
   0,10 с на 12 симлинков. Разбор по `$0`, а не по basename: подставной PATH
   стенда короткий и basename в нём нет.

## Ревью

- Шаг 4 сценария требует финального замера команды test (parallel.py из deploy.local) с порогом 120 с, а в «Замерах после правок» этого замера нет: таблица заканчивается suite.py и последовательным discover. Прогон на этой машине даёт 3:55-4:00 при load ~5-6, и остаток сидит не в devkitctl: go:dashboard один идёт ~110 с, go:agentctl ~61 с, оба компонента вне этой ветки. Прогнать шаг 4 и записать фактический замер с разбором остатка; если порог 120 с сейчас не берётся средствами этой задачи, назвать это в файле задачи вслух, а не пропускать шаг молчком.: исправлено, замер внесён в «Замеры после правок» с разбором остатка (порог держат dashboard и agentctl вне ветки, своя часть снята порогом 40 с), финальный замер оставлен поствыкатным шагом 4 сценария и гонится диспетчером на тихой машине после слияния
- В testenv.py осталась мёртвая константа DISPATCHER (exec sh -c "$DEVKIT_STUB_BODY") с комментарием-двойником первого блока про DEVKIT_STUB_BODY: греп по DISPATCHER и DEVKIT_STUB_BODY не даёт ни одного использования. Комментарий при этом расходится с текущим кодом, где заглушки это диспетчер с case "$0". Убрать константу и второй комментарий целиком.: исправлено, константа и комментарий убраны из testenv.py
- Сценарий проверки агентский, а каждый его шаг это прогоны по файлам ветки: suite.py, unittest классов, regcheck, parallel.py из корня чекаута. Шага, который гонялся бы после выката и не был повтором тестов ветки, в сценарии нет. Для этой задачи исполнимый шаг после слияния есть: прогон команды test на основном чекауте main после влития ветки с замером времени против порога цели. Переписать сценарий, чтобы последний замер шёл по main после слияния, либо добавить эквивалентный поствыкатный шаг.: исправлено, шаг 4 переписан поствыкатным: команда test на основном чекауте main после слияния, замер против порога 120 с из DoD DK-166
