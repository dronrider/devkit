# DK-362: dashboard: headless-запуск с доски не наблюдаем, чата нет в сессиях

## Что происходит

Реплика пользователя во «Входящие» цели DK-327, 2026-08-15 (доставлена
витку почтальоном DK-341): случайный запуск с дашборда перевёл DK-194 в In
progress, исполнитель ушёл в headless (tmux task-DK-194 через agentctl
exec), но работа не видна: чата нет в списке сессий, экрана агента с доски
тоже нет, найти можно только раскопками по транскриптам. Сценарий 2 цели
(«видеть, чем агент занят») на headless-запусках не закрыт: строка In
progress не подкреплена ничем наблюдаемым.

## Чего хотим

Headless-сессия, поднятая с доски через agentctl exec, видна как обычная:
разговор стоит в списке сессий задачи, экран агента открывается с доски
(чип «работает» ведёт на живой статус), и это держит тест. Разобрать, чем
headless-запуск через exec отличается для sessions.go от прежнего прямого
подъёма (каталог, cwd, session_id), и закрыть щель.

## DoD

- Запуск с доски через agentctl exec даёт разговор в списке сессий задачи и
  рабочий экран агента; тест воспроизводит headless-сессию (транскрипт в
  каталоге дерева задачи с cwd от exec) и падает на старом коде.
- Смок или стенд держит стык, regcheck зелёный.

## Ход работы

- Исполнение: субагент opus/medium по вердикту pick (квота: week_all 78%, week_max 67%, снимок 12м назад, сдвига нет), 2026-08-15.
- Исполнение: субагент opus/medium по вердикту pick (квота: week_all 78%, week_max 67%, снимок 28м назад, сдвига нет), 2026-08-15.
- Причина нашлась не в exec и не в cwd: рабочий каталог сессии ставит tmux
  (`new-session -c <корень проекта>`), exec его не трогает, и путь проекта у
  headless-запуска тот же самый. Расходится каталог журналов. Запуск с доски
  идёт на выбранной подписке, а её клиент поднимается со своим
  `CLAUDE_CONFIG_DIR` (пара окружения из машинного слоя). Транскрипт уезжает
  в `<home подписки>/projects`, тогда как `sessions.go` искал разговоры в одном
  `~/.claude/projects`. На машине это видно глазами: журнал headless-запуска
  DK-194 лежит в `~/.devkit/claude-glm/projects/-Users-rider-projects-devkit`.
- Правка по слоям. Каталог хозяйства подписки в машинном виде
  `agentctl harness --json` это поле `home` (развёрнутая тильда). Без него
  дашборду неоткуда узнать, куда клиент пишет журнал, а собирать пути самому
  ему нельзя: конфигурация состоит из трёх слоёв. Дашборд собирает корни
  журналов из своего `~/.claude` и хозяйства подписок (`transcriptRoots`).
  Обход каталогов идёт по всем корням, и по ним же ищется транскрипт для
  экрана агента.
- Тесты: регрессионный на список задачи и экран агента по headless-сессии в
  каталоге второй подписки (`TestSessionsSecondHarnessSeen`, транскрипт в
  формате живого запуска с `promptSource: sdk`), перечисление корней без
  двойников, поле `home` в машинном виде agentctl. Смок довели до конца стыка:
  клиент второй подписки пишет транскрипт в своё хозяйство, и шаг выбора
  подписки после запуска запрашивает список сессий задачи и ленту разговора.
- Вычитка: 3 файла, 9 правок, 0 пометок, 2026-08-15.
- Ревью: субагент sonnet/high по вердикту pick (квота: week_all 78%, week_max 67%, снимок 45м назад, протух, сдвига нет), 2026-08-15.

## Итог

Каталог журналов у второй подписки свой, и список сессий его теперь учитывает.
Каталог хозяйства подписки в машинном виде `agentctl harness --json` это поле
`home`. Дашборд складывает из него и своего `~/.claude` корни журналов и
обходит их все: список сессий задачи, экран агента по id разговора, работы из
транскриптов и вопрос груминга ходят одним и тем же перечнем корней. Разговор
headless-запуска с доски стоит в списке сессий своей задачи, и чип «работает»
ведёт на живую ленту. Стык держит смок: клиент второй подписки на стенде пишет
транскрипт в своё хозяйство, а шаг выбора подписки после запуска запрашивает
список сессий задачи и ленту разговора.

## Сценарий проверки

Сценарий агентский, живого шага не требует: стык от машинного вида agentctl до
ленты разговора проходит смок целиком, на живой машине его повторять нечем,
кроме второй подписки и настоящего запуска.

1. `cd tools/dashboard && GOWORK=off go test -run TestSessionsSecondHarnessSeen
   ./...` зелёный на слитой ветке; тест кладёт транскрипт headless-запуска в
   `projects` хозяйства второй подписки и ждёт его в списке сессий задачи и на
   экране агента.
2. `regcheck --base main --tests tools/dashboard/sessions_test.go -- sh -c 'cd
   tools/dashboard && GOWORK=off go test -run TestSessionsSecondHarnessSeen
   ./...'` подтверждает красноту на старом коде.
3. Полный модуль дашборда и agentctl зелёные (`GOWORK=off go test ./...` из
   обоих), смок проходит шаг «выбор подписки доезжает до команды» с припиской
   про виденный разговор.
4. Живой шаг, если под рукой вторая подписка: поднять задачу с доски на ней и
   открыть экран агента, разговор виден без раскопок по транскриптам.
