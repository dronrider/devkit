# DK-364: Назначение исполнителя с учётом остатков подписок

записан 2026-08-15

## Что происходит

Вердикт agentctl pick разворачивает ярус в харнес статически по маппингу
машинного слоя, остаток подписки назначения в решении не участвует: 15 августа
конвейер цели DK-327 продолжал назначать исполнителей на glm-code при пустом
пятичасовом окне и собирал отказы посреди витка.

## Чего хотим

Гейт перед назначением: сверять снимок квоты харнеса назначения, при пустом
окне уводить ступень на другой харнес либо ставить задачу в очередь до сброса
окна (время сброса берётся из снимка). Вторая подписка встаёт в тот же гейт
бюджета, которым agentctl budget держит витки цели по бакетам claude-code.
Пиковые часы z.ai (09:00-13:00 МСК, кредиты дороже) и курс кредитов при выборе
стороны это следующий слой, отдельной строкой при будущем грумминге.

## DoD

Прогон с подменённым снимком: окно glm пусто -> назначение ступени base уходит
на claude-code либо в очередь с временем сброса, и это видно в выводе pick и
run; окно живое -> назначение прежнее. Делается после DK-181, без снимка гейту
не на что опираться.
