# DK-375: devkitctl map: генератор карты проекта и индекса решений, сторож свежести, импорт в тонкий файл

## Что происходит

Сессии собирают карту проекта грепами: знания о том, где что лежит, разбросаны
по коду и докам, а вопроса «почему так» нет в одном месте. LLD DK-194 закрыл
разработку: карта генерится из кода и доки, ложится в контекст импортом из
тонкого файла харнеса, свежесть держит doctor.

Постановка и границы: docs/lld/DK-194-project-map.md, восемь решений. Реализация
идёт по нему, развилки закрыты в тексте, своих решений исполнитель не принимает.

## Что сделать

1. `describe.py` достаёт текст описания компонента (сегодня возвращает факт
   наличия), источник по приоритету из решения 2: модульная дока, первая строка
   README со срезом заголовка, строка состава из ARCHITECTURE.md. Первое
   предложение целиком, без обрезки.
2. Новый модуль `tools/devkitctl/codemap.py` с генератором карты: маркер
   `devkit:generated map body=<хеш>`, плоские строки `путь: описание`,
   сортировка по пути, индекс решений вторым разделом из заголовков «Решение N»
   в docs/lld/*.md (строки «DK-139.2 текст», сортировка по документу и номеру,
   архив задач не индексируется).
3. Подкоманда `devkitctl map -C <dir>`: сухой прогон в stdout, `--write` пишет
   docs/map.md.
4. Doctor: сверка карты в памяти с файлом на диске, три находки из решения 7
   (нет файла при живых компонентах, хеш разошёлся с телом, тело разошлось с
   деревом), все чинятся `--fix` перегенерацией.
5. `thin_text`: строка `@docs/map.md` последним импортом, только когда файл
   карты существует.
6. Той же задачей сгенерировать и закоммитить карту самого devkit, импорт
   в тонкий файл devkit, вес проверить `weigh`.
7. Тесты пирамидой по разделу «Тесты» LLD (строки 281-300), дока:
   `tools/devkitctl/README.md` (подкоманда map, находки доктора), README devkit
   раздел «Состав» после реализации.

## Сценарий проверки

Агентский, по DoD цели DK-297.

1. `python3 tools/devkitctl/devkitctl.py map` печатает карту с маркером
   `devkit:generated map body=`, плоскими строками компонентов и разделом
   «Решения по docs/lld»; строк в разделе карты 40-60 (DoD DK-194).
2. `python3 tools/devkitctl/devkitctl.py doctor` на приведённом в порядок
   devkit молчит про карту; после правки README компонента печатает находку
   свежести, `--fix` перегенерирует.
3. Индекс: каждая строка раздела решений держит документ и номер раздела.
4. Тонкий файл devkit кончается импортом `@docs/map.md`.
5. `python3 hooks/check-symbols.py docs/map.md tools/devkitctl/codemap.py`
   молчит.
6. Юниты: `cd tools/devkitctl && python3 -m pytest codemap_test.py` зелёные
   (или go-список модулей, если затронуты).
