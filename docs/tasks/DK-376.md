# DK-376: POC-замер карты на xr-proxy: пара типовых задач с картой и без, цифры расхода [после DK-375]

## Что происходит

Генератор карты (DK-375) слит и выкачен. Замер из DoD постановки DK-194 ещё не
проводился: генерализацию на другие проекты решают цифры, а не вкус. Протокол
лежит в docs/lld/DK-194-project-map.md, раздел «Протокол POC на xr-proxy»
(строки 249-269), исполнять его буквально.

## Что сделать

1. Ветка в xr-proxy: сгенерированная карта (сухой прогон `devkitctl map -C`
   из чекаута devkit, запись файла), строка импорта в тонкий файл xr-proxy.
   До замера проба с кодовым словом из карты в `claude -p`: карта доезжает
   в контекст, иначе замер меряет не карту, а дыру доставки.
2. Две пары задач одного типа и размера с бэклога xr-proxy (LLD или кодовые,
   не одна и та же дважды). Прогон A без карты, B с картой, контрольная пара
   зеркально: C с картой, D без. Порядок чередуется, модель и effort
   одинаковые во всех четырёх.
3. Расход меряется по журналам сессий (`devkitctl drain -C`) токенами:
   суммарный расход сессии как основная цифра и доля поисковых вызовов
   (grep, find, чтение файлов подряд) как объяснение механики.
4. Цифры ложатся в этот файл задачи. Критерий генерализации: в обеих парах
   экономия поиска перекрывает собственный вес карты. Решение читает
   пользователь, в цель DK-297 генерализация не входит.

## Сценарий проверки

Агентский.

1. Файл задачи держит четыре прогона с цифрами: путь журнала, токены
   сессии, доля поисковых вызовов.
2. Проба с кодовым словом зафиксирована: карта доезжала в контекст каждого
   прогона с картой.
3. Вывод по критерию сформулирован числами обеих пар.
