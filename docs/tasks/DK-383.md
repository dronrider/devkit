## Чего хотим

Грубая шкала приоритета разбора high/mid/low, на глаз, без чисел и привязки к
слагаемым RANKING: приоритет разбора не сводится к серьёзности будущей задачи,
идея с нулевой серьёзностью может заслуживать разбора раньше мелкого бага.
Ставится автором при записи (--prio) или любым проходом списка, маркировка не
дороже записи. Механика по образцу defer:

- taskctl draft prio <ID> high|mid|low со снятием через --clear; в файле
  черновика строка рядом с «записан»: «приоритет: высокий», русское слово в
  файле и печати, латинские имена в команде и в поле prio json, как у суффикса
  приёмки;
- сортировка в loadDrafts, один порядок для печати, json, хвоста list и
  дашборда: high, mid, low, затем немаркированные отдельной группой, отложенные
  после всех; внутри уровня по возрастанию ID, как на доске;
- перенос add --id и приписка draft attach выкидывают строку метки из файла:
  метаданные в файле задачи не дублируются (п. 3 правил доски), метка не
  переживает черновик;
- defer метку не трогает: отложенные стоят после всех независимо от метки,
  defer --clear возвращает черновик на место по метке;
- prio повторяет ensureWritten: первой записи в старый черновик строка
  «записан» ставится из ModTime до самой записи (решение LLD DK-129);
- парсер метки читает только шапку до «## », строка «приоритет:» в теле идеи
  меткой не ложится;
- справка, текст отказа draftTextGuard и карта подкоманд дополняются prio;
- дашборд рисует чип уровня в строке черновика (draftRow): порядок списка
  меняется, и перемена должна быть видна на экране, а экран черновиков это
  вход в грумминг (DK-328.2, DK-354.4);
- п. 5 RULES.board.md получает абзац про приоритет разбора с оговоркой
  коллизии: слово «приоритет» в п. 2 занято выводом из ранга, приоритет
  черновика это очередь разбора на глаз, живёт и умирает в накопителе;
- скилл board-groom доезжает: разбор начинается с верха списка с учётом меток.

Границы: черновики остаются одной кучей без секций и переходов, уровни не
статусы; авто-гниения метки по возрасту нет, возраст и так напечатан рядом;
немаркированный черновик нормальное состояние, как прочерк цены в бэклоге.
Разовая чистка накопителя (живость плюс простановка меток) идёт после этой
задачи и с оговоркой: путь add --id с неагентским видом приёмки и --link
затирает перенесённый файл (живой баг DK-329), чистка либо ждёт его закрытия,
либо обходит связку --link с неагентским видом.

## Сценарий проверки

Сценарий агентский: гоняется на синтетической доске во временном каталоге с
временным HOME, ничего на живой доске не трогает.

1. Собрать утилиту и завести доску: `cd tools/taskctl && go build -o /tmp/dk383/taskctl .`,
   затем в /tmp/dk383 `git init`, `HOME=/tmp/dk383 ./taskctl init --prefix XR --name demo`.
2. Записать четыре черновика `./taskctl draft "..."`, поставить метки
   `./taskctl draft prio XR-004 high`, `XR-003 mid`, `XR-002 low`, отложить
   `./taskctl draft defer XR-002 "причина"` и посмотреть `./taskctl draft list`.
   Ожидаемый итог: порядок XR-004, XR-003, XR-001, XR-002 (high, mid,
   немаркированный, отложенный с low), пометки в строках вида
   «XR-004 (сегодня, высокий): ...» и «XR-002 (сегодня, низкий, отложен ...): ...».
3. `./taskctl draft list --json` отдаёт поле "prio":"high"|"mid"|"low" у
   маркированных и не отдаёт его у немаркированного, порядок тот же, что у
   печати.
4. `./taskctl draft defer XR-002 --clear` возвращает черновик на место по
   метке: low встаёт после mid (XR-003) и до немаркированного XR-001.
   `./taskctl draft prio XR-002 --clear` снимает метку, и черновик уезжает в
   конец к немаркированным.
5. Отказы: `./taskctl draft prio XR-002 urgent` (уровень не из шкалы),
   `./taskctl draft prio XR-004 high --clear` (уровень при снятии),
   `./taskctl draft show` (текст отказа называет prio в списке подкоманд),
   `./taskctl draft prio` (форма команды).
6. Перенос: поставить метку, `./taskctl add --id <ID> --title ... --type task
   --rank "25+4+2+0+2" --accept agent`, файл docs/tasks/<ID>.md без строки
   «приоритет:»; приписка `./taskctl draft attach <ID> <TASK-ID>` выкидывает
   метку тем же правилом.
7. Тесты: `cd tools/taskctl && GOWORK=off go test ./...` и
   `cd tools/dashboard && GOWORK=off go test ./...` зелёные.
8. Дашборд: раздел «Черновики» рисует чип уровня русским словом в строке
   накопителя, порядок списка совпадает с taskctl. Проверено тестами
   TestDraftsSortedByPrio и TestStaticDraftsSection; глазами на живом
   накопителе после простановки меток.
