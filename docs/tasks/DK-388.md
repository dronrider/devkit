# DK-388: Цель: единые ворота заведения строки доски при любом входе

## Цель

Реализация решений LLD DK-133 (docs/lld/DK-133-entry-gates.md, приёмка
согласована 2026-08-17): у каждого из четырёх входов на доску стоят явные
ворота, а файл задачи и DoD строке даёт машинная опора на заведении, не на
взятии в работу.

DoD (агентски проверяемый):

- на синтетической доске во временном HOME `taskctl add --type bug` заводит
  `docs/tasks/<ID>.md` с заголовком `## DoD`, ссылка в ячейке строки ведёт на
  этот файл;
- `taskctl add --id <черновик>` отказывает, если тип `task` или `bug` и в
  переносимом файле нет заголовка `## DoD`;
- изменяющие команды (`move`, `dep add`, `set`) отказывают у стоящей строки без
  файла задачи, отказ называет `taskctl file <ID>`;
- строка нарезки цели (`--link`) получает файл задачи, ссылка на файл цели
  уходит в болванку файла;
- скиллы `board-groom`, `board-task`, `goal-loop`, `goal-start`, `goal-cut` и
  п. 5 `RULES.board.md` согласованы с рубежом на `add`: обязательный шаг
  `taskctl file` после `add` нигде не значится (проверка грепом);
- тесты модулей `tools/taskctl` и `internal` зелёные, `regcheck` зелёный.

## Бюджет

бюджет: week_all <= 20
бюджет: week_max <= 10
ярус: pro

Рамка условна: витки цикла едут подпиской glm-code, траты которой панель
квоты не видит (у харнеса секция [quota] пуста), и `gate: over` по этим
строкам не сработает. Строки включаются целиком, если цикл поднимется
харнесом claude-code после сброса бакетов.

## Задачи цели

Заводит нарезка первым витком. Состав-кандидат уже посчитан разделом «Нарезка
реализации» LLD DK-133: шесть строк, от абзаца п. 5 `RULES.board.md` до
механики `taskctl add` и машинных отказов, порядок и зависимости там же.
