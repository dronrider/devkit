# DK-394: taskctl add заводит файл задачи с пустым DoD, изменяющие команды без файла отказывают

## Ход работы

- Разработка: подпроцесс glm-5.3/medium по вердикту pick (потолок цели: pro, вердикт и так не выше; квота: объявления нет, корректор выключен), 2026-08-17 02:47-02:47.
- cmdAdd заводит docs/tasks/<ID>.md вместе со строкой: ячейку ссылки занимает
  файл, болванка task/bug (кроме строк-целей) несёт пустой «## DoD», а при
  --link ссылка на файл цели уходит в болванку строкой «Цель: ...» под
  заголовок. Оформление add --id отказывает до переноса, если у черновика
  task/bug нет «## DoD», и отказ называет причину.
- ensureTaskFile стал общим для add, file, review add и draft attach: болванка
  несёт DoD по типу строки, раздел «Приёмка» неагентского вида дописывается
  соседним заголовком, не перезаписывая его.
- move, dep add и set отказывают стоящей строке без файла задачи и называют
  taskctl file <ID>: машинная опора перехода для строк, заведённых до рубежа.
  Рубеж доски не тронут, изменяющие команды из линкованного worktree
  отказывают раньше, как и прежде.
- README tools/taskctl переписан под новое поведение add и file и под новые
  отказы; тестовая фикстура доски дополнена файлами строк, тесты старых строк
  снимают файл сами.
- Замечания ревью: дашборд приведён под новый контракт add (чекбокс файла
  снят с формы заведения, файл задачи едет в коммит создания строки
  безусловно, кнопка «Завести файл» на экране задачи осталась ремонтом дыры),
  прогон обоих модулей зелёный; шаг 5 сценария переформулирован без опоры
  на DK-391.
- Вычитка: 2 файла, 11 правок, 2 пометки, 2026-08-17.

## Сценарий проверки

1. Прогон тестов модуля: `cd tools/taskctl && GOWORK=off go test -count=1 .`
   заканчивается `ok`. Пункты DoD ниже закрыты тестами TestAddCreatesTaskFile
   (файл с «## DoD», ссылка в ячейке, --link в болванку),
   TestAddGoalRowSkipsDoD, TestAddDraftWithoutDoDRefused,
   TestMutatingCommandsNeedTaskFile.
2. Синтетическая доска во временном каталоге: `taskctl init --prefix TS`,
   затем `taskctl add --title "Баг" --type bug --rank "0+1+1+0+1" --accept
   agent`; в docs/tasks/<ID>.md стоит пустой «## DoD», ячейка строки ведёт на
   этот файл, а не на прочерк.
3. Та же доска: `taskctl draft "без дод"`, потом `taskctl add --id <ID>
   --title "Оформить" --type task --rank "0+1+1+0+1" --accept agent` отказывает
   с «у черновика ... нет заголовка "## DoD"».
4. У строки без файла (файл снят руками) `taskctl move <ID> in-progress`,
   `taskctl dep add` и `taskctl set` отказывают с «заведите его: taskctl file
   <ID>»; после `taskctl file <ID>` move проходит.
5. Греп согласованности: в `RULES.board.md` и скиллах груминга и нарезки цели
   (`kit/skills/board-groom/SKILL.md`, `kit/skills/goal-cut/SKILL.md`) нет
   обязательного шага `taskctl file` после `add`, а сам `taskctl file` назван
   только добиванием строк, заведённых до рубежа. Исключение это скилл
   board-task с его шагом взятия в работу: его пересмотр за открытой DK-391 и
   доезжает её слиянием, DK-394 на него не опирается.

## Исключения

- Исключение: regcheck (гоняется поверх слияния, а не в ветке задачи).

## Ревью

- Модуль tools/dashboard красный на ветке, а дифф его не трогает: тесты дашборда собирают taskctl из соседнего каталога (realTaskctlPath, tasks_test.go) и нового контракта add не знают. Падают пять: TestTaskCreateRowWithoutFile (add заводит файл всегда, тест держит старое «без чекбокса файла нет»), TestTaskEditAuthAndOrigin и TestTaskFileCreateAndEdit (фикстура создаёт файлы всем строкам, проверки «файла нет» и кнопка «Завести файл» потеряли предмет), TestDraftOutcomeTraces (add --id отказывает без «## DoD», а промоутер черновика в тесте DoD не дописывает), TestGoalTasksEmptyDistinct (у цели файл есть с минуты заведения, пустота «файла цели нет» недостижима и слова экрана разъехались с ожиданием). Той же веткой починить фикстуры и ожидания, текст формы «завести файл задачи по шаблону (taskctl file)» в static/app.js и места README дашборда, где файл задачи заводит кнопка: они описывают снятое поведение. Прогон: cd tools/dashboard && GOWORK=off go test -count=1 .: исправлено
- Ручка заведения строки коммитит не всё, что создала: handleTaskCreate (tools/dashboard/newtask.go) при снятом чекбоксе файла зовёт taskctl add без -m и собирает в commitDocs только docs/TASKS.md, а add с этой веткой заводит docs/tasks/<ID>.md всегда. Файл остаётся untracked, запушенная доска ссылается ячейкой на файл, которого в origin нет, рабочее дерево грязное. Воспроизведено на синтетической доске: add без -m, затем git add docs/TASKS.md && git commit -- docs/TASKS.md оставляет docs/tasks/ непрокоммиченным, в git status строка «?? docs/tasks/». Починить той же веткой: файл задачи берётся в коммит создания строки безусловно, и тест дашборда проверяет чистое дерево после create.: исправлено
- tools/taskctl/README.md, пункт про file: новая вставка склеилась с прежним хвостом, и строка 260 («отказ не срабатывает: файл уже стоит. Команда идемпотентна: у задачи, где уже есть и») вышла 86 символов при переносе файла 74-79. Переверстать абзац, чтобы строка легла в конвенцию файла.: исправлено
- Шаг 5 сценария заявляет, что grep -rn «taskctl file» kit/skills RULES.board.md выдаёт только добивание строк, заведённых до рубежа, но на ветке это не так: kit/skills/board-task/SKILL.md, шаг 3 процедуры взятия в работу, всё ещё несёт доктрину «Однострочному бэклогу файл не нужен, взятой в работу задаче нужен», противоречащую новому рубежу (RULES.board.md, п. 3: строка без файла это дыра). Пересмотр скилла за открытой DK-391, а DK-394 может дойти до Check раньше неё, и шаг не сойдётся с собственным ожиданием. Сузить формулировку шага: проверять отсутствие обязательного шага taskctl file после add, а про board-task назвать исключение со ссылкой на DK-391.: исправлено
- kit/skills/goal-start/SKILL.md, шаг 5 постановки цели, описывает снятый механизм: «Завести строку и файл» дано двумя командами (taskctl add, следом taskctl file <ID>), а абзац о заготовке приписывает заголовок команде file («заголовок ставит сама taskctl file»). С ветки файл цели кладёт сам add, вторая команда стала холостой (идемпотентное подтверждение), заголовок ставит add. Владельца у правки нет: DK-393 закрыта до нового контракта, DK-391 это зона board-task, в нарезке цели DK-388 отдельной строки под этот блок нет, а шаг 5 сценария зовёт board-task единственным исключением. Починить той же веткой: переписать шаг 5 goal-start под одну команду add с файлом от неё и поправить атрибуцию заголовка, либо назвать goal-start в шаге 5 вторым исключением с заведённым владельцем. Соседи проверены и не в претензии: board-team шаг 3 тень board-task и доедет с DK-391, board-batch зовёт file по пачке как добивание дорубежных строк (DK-048).: исправлено
- tools/dashboard/newtask.go, комментарий у склейки note в handleTaskCreate: «Провал коммита не затирает причину, по которой не завёлся файл: обе беды называются вместе». С ветки файл заводит сам add: его провал отдаётся ошибкой раньше, а единственный источник note до коммита это отказ writeAcceptReason. Комментарий объясняет живую склейку мёртвым случаем и отправляет читателя искать несуществующую ветку. Переписать под действительный источник: провал коммита не затирает причину приёмки, которая не записалась в раздел «Приёмка» файла задачи.: исправлено
