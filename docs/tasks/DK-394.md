# DK-394: taskctl add заводит файл задачи с пустым DoD, изменяющие команды без файла отказывают

## Ход работы

- Разработка: подпроцесс glm-5.3/medium по вердикту pick (потолок цели: pro, вердикт и так не выше; квота: объявления нет, корректор выключен), 2026-08-17 02:47-02:47.
- cmdAdd заводит docs/tasks/<ID>.md вместе со строкой: ячейку ссылки занимает
  файл, болванка task/bug (кроме строк-целей) несёт пустой «## DoD», а при
  --link ссылка на файл цели уходит в болванку строкой «Цель: ...» под
  заголовок. Оформление add --id отказывает до переноса, если у черновика
  task/bug нет «## DoD», и отказ называет причину.
- ensureTaskFile стал общим для add, file, review add и draft attach: болванка
  несёт DoD по типу строки, раздел «Приёмка» неагентского вида дописывается
  соседним заголовком, не перезаписывая его.
- move, dep add и set отказывают стоящей строке без файла задачи и называют
  taskctl file <ID>: машинная опора перехода для строк, заведённых до рубежа.
  Рубеж доски не тронут, изменяющие команды из линкованного worktree
  отказывают раньше, как и прежде.
- README tools/taskctl переписан под новое поведение add и file и под новые
  отказы; тестовая фикстура доски дополнена файлами строк, тесты старых строк
  снимают файл сами.
- Вычитка: 2 файла, 11 правок, 2 пометки, 2026-08-17.

## Сценарий проверки

1. Прогон тестов модуля: `cd tools/taskctl && GOWORK=off go test -count=1 .`
   заканчивается `ok`. Пункты DoD ниже закрыты тестами TestAddCreatesTaskFile
   (файл с «## DoD», ссылка в ячейке, --link в болванку),
   TestAddGoalRowSkipsDoD, TestAddDraftWithoutDoDRefused,
   TestMutatingCommandsNeedTaskFile.
2. Синтетическая доска во временном каталоге: `taskctl init --prefix TS`,
   затем `taskctl add --title "Баг" --type bug --rank "0+1+1+0+1" --accept
   agent`; в docs/tasks/<ID>.md стоит пустой «## DoD», ячейка строки ведёт на
   этот файл, а не на прочерк.
3. Та же доска: `taskctl draft "без дод"`, потом `taskctl add --id <ID>
   --title "Оформить" --type task --rank "0+1+1+0+1" --accept agent` отказывает
   с «у черновика ... нет заголовка "## DoD"».
4. У строки без файла (файл снят руками) `taskctl move <ID> in-progress`,
   `taskctl dep add` и `taskctl set` отказывают с «заведите его: taskctl file
   <ID>»; после `taskctl file <ID>` move проходит.
5. Греп согласованности: `grep -rn "taskctl file" kit/skills RULES.board.md`
   выдаёт только добивание строк, заведённых до рубежа, обязательного шага
   `taskctl file` после `add` нигде нет.

## Исключения

- Исключение: regcheck (гоняется поверх слияния, а не в ветке задачи).
