# DK-398: goal-start сверяет бюджет цели с остатком бакета до сброса

## Задача

Постановка цели задаёт бюджет в процентных пунктах бакетов квоты и снимает
снимок `agentctl`, но с остатком до сброса его не сверяет. Цель с бюджетом
`week_all <= 40` при остатке 49 пп формально влезает, хотя съедает почти весь
остаток машины, а предупреждения об этом нет ни на постановке, ни в цикле.
Человек узнаёт о том, что бакет выбран, на гейте бюджета посреди работы.

Скилл `goal-start` задаёт формат бюджета и снимок на постановке, сверки в нём
нет. Нужна одна: остаток бакета до сброса против бюджета цели, и когда старт
съедает почти весь остаток, постановка печатает предупреждение с датой
сброса. Отказом это не становится, решение остаётся за человеком.

## DoD

1. Прогон постановки на подставном снимке квоты, где бюджет цели больше остатка
   до сброса, печатает предупреждение с датой сброса; при достаточном остатке
   постановка проходит без предупреждения.
2. Правило записано в скилле постановки цели.
3. Прогон `test` из `.devkit/deploy.local` зелёный.

## Приёмка

Вид agent: сверка гоняется на подставном снимке квоты, эталон берётся из строки
вывода и кода возврата.

## Сценарий проверки

1. Тесная рамка предупреждает. Бюджет `week_all <= 40` при остатке 49 пунктов
   формально влезает, и это главный случай задачи.

```sh
GOWORK=off go -C tools/agentctl test -count=1 -run TestCmdFitWarnsOnTightBudget .
```

Тест проходит. Он сверяет первую строку `fit: tight`, числа «бюджет 40 пп из
остатка 49 пп» и дату сброса в той же строке.

2. Запаса хватает, и сверка молчит. Два бакета, оба с запасом.

```sh
GOWORK=off go -C tools/agentctl test -count=1 -run TestCmdFitQuietOnRoomyBudget .
```

Тест проходит. Ответ `fit: ok`, слова «съедает почти весь остаток» в выводе
нет, второй бакет посчитан своей строкой.

3. Сверять не с чем. Снимка нет вовсе, дата сброса позади, бакета бюджета в
   снимке не показалось.

```sh
GOWORK=off go -C tools/agentctl test -count=1 -run 'TestCmdFitWithoutSnapshot|TestCmdFitExpiredWindow|TestCmdFitMissingBucket' .
```

Все три проходят. Первые два ждут `fit: unknown` с причиной и зовом
`agentctl quota refresh`, третий ищет в строке «бакета week_max в снимке нет».

4. Порог и края разбора. Четыре пятых остатка это уже tight, раздел «Бюджет»
   без лимитов это отказ, протухший снимок считается, но зовёт переснять.

```sh
GOWORK=off go -C tools/agentctl test -count=1 -run 'TestFitTightBucket|TestCmdFitWithoutLimits|TestCmdFitStaleSnapshot' .
```

Все три проходят.

5. Команда зарегистрирована в main, путь цели берётся от корня доски, без
   `--goal` она отказывает, и в общей справке она есть.

```sh
GOWORK=off go -C tools/agentctl test -count=1 -run TestFitCLI .
```

Тест проходит.

6. Тест краснеет на старом коде.

```sh
GOWORK=off regcheck -C tools/agentctl --base df8881e5^ --tests tools/agentctl/fit_cli_test.go -- go test -count=1 -run TestFitCLI .
```

Утилита печатает «тест краснеет на df8881e5^ и проходит на текущем коде,
регрессия закрыта». База это коммит до правки. Остальные тесты зовут новые
символы, и база с ними не собирается, поэтому краснота снята прогоном через
CLI.
