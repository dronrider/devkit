# DK-405: Полка фона и потолки незакрытых деревьев и висящих вопросов

Цель: [docs/tasks/DK-395.md](docs/tasks/DK-395.md)

## Что происходит

Когда после ворот кандидатов нет, конвейер спит: списка работ, которые всегда
можно делать без человека (груминг накопителя, вычитка, карта, дожатие тестов),
нет. Без потолка незакрытых деревьев конвейер накопит хвостов, без потолка
висящих вопросов человек вернётся к простыне вопросов вместо пачки. Замер
в файле цели называет хвост дорогим: задача после ревью стоит две трети цены
целой, недопущение хвостов дороже умного выбора.

## Чего хотим

При пустых кандидатах конвейер берёт работу с полки фона, и это видно снаружи.
Потолок незакрытых деревьев и потолок висящих вопросов выбраны числом
в DK-400 и отбиваются внятным отказом с этим числом.

## DoD

На стенде с пустыми кандидатами конвейер называет работу с полки и выполняет
её; взятие задачи сверх потолка незакрытых деревьев и вопрос сверх потолка
висящих отбиваются отказом с числом потолка. Тесты зелёные, regcheck зелёный.

## Ранг

`25+5+1+0+4 = 35`, P2.

- Серьёзность 25 (Major). Простой слота при пустых кандидатах это трение,
  обход не брать ничего.
- Ценность 5. Улучшение второй очереди: живой слот при пустой доске.
- Неопределённость 1. Состав полки решает DK-400.
- Поправка на баг 0. Новая работа.
- Рычаг 4. Потолки берегут пропускную способность конвейера от хвостов.

## Сценарий проверки

Агентский, на временном репозитории со синтетической доской (префикс XR),
после выката. Эталон каждой машинной точки это код возврата и строки вывода,
команды зовутся так, как их описывает `tools/taskctl/README.md`.

1. Потолок висящих вопросов. Завести четыре задачи: три со строкой «Цель:»
   одного файла цели в файлах задач (кладёт `add --link`), четвёртую без
   связи с целью, и перевести все четыре в in-progress
   (`taskctl -C $R move <ID> in-progress`): из Backlog парковка падает
   раньше проверки потолка с отказом «ещё не в работе, блокировать нечего».
   Две задачи цели паркуются вопросом
   (`taskctl -C $R move <ID> blocked --reason "вопрос: ждём схему"`), третья
   та же команда падает с отказом «вопросов висит 2 из 2», называющим обе
   висящие строки. `DEVKIT_SLOT_QUESTIONS=3` пропускает ту же команду, вопрос
   задачи вне цели проходит и без перебития: потолок считается на цель.
2. Потолок незакрытых деревьев. В репозитории стенда завести ветки
   припаркованных строк: xr-301 с причиной «вопрос:», xr-302 с «окружение:»,
   xr-304 с внешним блокером. `DEVKIT_SLOT_TREES=0 taskctl -C $R slot`
   отказывает свежим строкам группой «потолок деревьев 0 исчерпан» и следом
   печатает «ждут разбора: XR-301 (вопрос), XR-302 (окружение), XR-304
   (блокер)»: отказ называет число и то, что разобрать. Припаркованная без
   ветки в разбор не попадает, осиротевшая строка в In progress проходит
   кандидатом: возврат к своей ветке дерева не заводит.
3. Полка фона. На стенде с целью, у которой после ворот нет кандидатов
   (`taskctl -C $R slot` печатает `slot: -`), поднять виток по скиллу
   `goal-loop`: при четырёх черновиках в `docs/tasks/drafts` строка «Журнала»
   называет взятую работу с признаком («груминг накопителя: черновиков 4»),
   при пустых признаках всех позиций пишется «кандидатов нет, полка пуста».
   Молчания не бывает ни в одном из исходов.

Ожидаемый итог: потолки отбиваются отказами с числом и разбором, полка видна
строкой «Журнала», обе половины покрыты тестами (`TestMoveQuestionCeiling`,
`TestMoveQuestionCeilingLinkForms`, `TestSlotTreeCeilingWaiters`) и прогон
стенда повторяет их вывод командами из README.

## Проверка

Прогон диспетчером цели DK-395 поверх выката, 2026-08-17, стенд с бинарем
из слитого main. Шаг 1: четыре строки цели переведены в работу, две
паркуются вопросом, третья получает отказ «вопросов висит 2 из 2 (XR-001,
XR-002)» кодом 1, `DEVKIT_SLOT_QUESTIONS=3` пропускает её, вопрос задачи
вне цели паркуется без перебития кодом 0. Шаг 2: с ветками xr-001, xr-002,
xr-004 и причинами «вопрос», «окружение», внешний блокер
`DEVKIT_SLOT_TREES=0 taskctl slot` отказывает единственному кандидату
строкой «потолок деревьев 0 исчерпан: XR-003» и печатает «ждут разбора:
XR-001 (вопрос), XR-002 (окружение), XR-004 (блокер)»; припаркованная без
ветки в разбор не попала, осиротевшая строка в In progress прошла
кандидатом. Разнобой форм записи цели проверен живьём: три формы ссылки
(XR-900, docs/tasks/XR-900.md, имя с .md) считаются одной целью.

Шаг 3 прогнан живым витком на стенд-цели XR-006: слот пуст, с полки взята
верхняя позиция, строка «Журнала» называет работу и признак («груминг
накопителя: черновиков 4, вопрос по XR-007..XR-009 задан»), DoD цели
сошёлся, цель закрыта витком сама. Граница второй половины шага: пустая
полка на стенде живьём недостижима, у голого репозитория `devkitctl
doctor` всегда держит находки и признак «здоровье каркаса» непуст; строка
«кандидатов нет, полка пуста» предписана текстом полки и правилом цели
(пустой «Журнал» это воронка), живого случая с пустыми признаками всех
позиций в цикле не случилось.

## Ревью

- Сценарий проверки, шаг 1: предусловие «в работе» названо только у двух задач из четырёх. Третья и четвёртая остаются в Backlog, а `move` в blocked из Backlog падает раньше потолка с отказом «ещё не в работе, блокировать нечего», и эталоны шага не воспроизводятся: третья не даёт «вопросов висит 2 из 2», четвёртая не проходит. Проверено на стенде. В шаге надо перевести в in-progress все четыре строки до первой парковки.: исправлено
- `taskGoalLink` в `tools/taskctl/ops.go` сопоставляет цели точным равенством сырой строки «Цель: ...», а `add --link` принимает цель в разных формах и нормализует только голый путь (`wrapLink`): при двух висящих вопросах цели XG-900 строка, заведённая с `--link XG-900` без `tasks/` и `.md`, кладёт в файл «Цель: XG-900», `parkedQuestions` её с целью не связывает, и третий вопрос той же цели паркуется мимо потолка. Проверено на стенде. Простыня вопросов, которую потолок держит, собирается тихо. Сравнивать цель по файлу ссылки (имя из скобок записи), добавив тест на разнобой формы.: исправлено
