# DK-407: Карта переходов работы плоскими строками со сторожем полноты

Цель: [docs/tasks/DK-395.md](docs/tasks/DK-395.md)

## Что происходит

Путь работы от идеи до архива нигде не нарисован: схема в README про доставку
правил, docs/map.md это карта компонентов и индекс решений, а связь между
шагами держит состояние доски, а не текст. Черновик DK-384 приписан в файл
цели, решение по нему принял DK-400: карта переходов живёт рядом с рубежом,
ручной docs/workflow.md плоскими строками со сторожем полноты
в `devkitctl doctor`.

## Чего хотим

Документ со схемой, где узлы это состояния работы (идея, черновик, строка,
ветка, ревью, слияние, очередь выката, приёмка, архив), а рёбра подписаны тем,
кто переход делает, скиллом или командой. Карта пишется руками, сторож
проверяет полноту по образцу сторожа docs/map.md: каждый скилл и каждый статус
доски упомянут, ссылки живые. С новыми понятиями DK-400 (рубеж, парковка,
пробуждение) карта согласована.

## DoD

docs/workflow.md держит карту переходов плоскими строками; сторож полноты
в `devkitctl doctor` ловит неупомянутый скилл и неупомянутый статус доски
на синтетическом прогоне; карта покрывает новый путь парковки и возврата
из решения 2 LLD DK-400. Тесты сторожа зелёные, regcheck зелёный.
