# DK-413: trackctl: адаптер Jira ходит только в API v3, на v2 не работает

записан 2026-08-17

## Что происходит

Базовый путь Jira зашит в адаптере константой `jiraAPI = "/rest/api/3"`
(`tools/trackctl/jira.go:19`). Выбрать версию нечем: ключа в контуре нет
(`tools/trackctl/contour.go:38`), флага у команд нет тоже. На Jira Server и
Data Center третьей версии REST нет вовсе, там живёт `/rest/api/2`. На такой
инсталляции все оси адаптера отказывают сразу: `show`, переход статуса,
исполнитель, ворклог, комментарий уходят в 404.

Контур на v2 у нас есть сегодня, и работа с тикетами там идёт руками через веб:
trackctl туда не ходит, а вся обвязка вокруг него (факты работы, ранг, сводка)
на этом контуре недоступна.

Симптом живого контура сверен прогоном (2026-08-18, Jira Server 10.3.18):
отсутствующий путь `/rest/api/3` отдаёт не 404, а 302 на веб-логин
(`login.jsp?permissionViolation`), и адаптер умирает не статусом, а разбором
HTML-страницы как JSON: Go-клиент превращает POST в GET на перенаправлении.
Внятный отказ по чужому формату ответа входит в объём наравне с текстом про
неизвестную версию.

Подмены цифры в константе мало, версия тянет за собой формат тел.

- Комментарий в v3 уезжает телом Atlassian Document Format
  (`jira.go:282`), в v2 то же поле принимает строку wiki-разметки.
- Исполнитель в v3 Cloud ставится по `accountId` (`jira.go:248`), а на
  Server и DC такого поля нет, там `name`. Без этого куска `take` разваливается
  на первом же вызове, то есть половинчатая поддержка версии не считается
  работой.
- Тесты адаптера прибиты к путям `/rest/api/3` строками стенда
  (`jira_test.go:154` и дальше), а таблица операций README описывает ручки той
  же цифрой (раздел «Адаптер jira»); примечание про `/rest/api/2` на Server и
  DC в README уже есть, но ключа контура за ним нет.

Аутентификация в объём не входит сознательно. Токен уезжает заголовком
`Bearer` (`jira.go:104`), и персональные токены в таком виде принимают все Jira
от 8.14. Инсталляция старше упрётся в это отдельным симптомом: 401 с текстом
трекера, который адаптер передаёт без изменений, и это лечится отдельной
строкой.

## Чего хотим

Версия API называется контуром, а не кодом: один ключ верхнего уровня в
`~/.devkit/tracker/<имя>.local` рядом с `base_url`. Умолчание оставляет
сегодняшнее поведение v3, чтобы стоящие контуры не требовали правки. Адаптер по
этому ключу собирает путь и выбирает формат тел, а команды остаются прежними:
снаружи разницы между контурами не видно.

Задача не предрешает, как раскладывается ветвление по коду: годится и
параметризация одного адаптера, и вторая запись в таблице адаптеров. Выбор
делает исполнитель, и он же отвечает за то, чтобы обе версии были покрыты
тестами, а не одна.

## DoD

- Версия Jira задаётся ключом контура, отсутствие ключа означает v3 и
  ничего не ломает у стоящих контуров.
- На контуре с v2 работают все оси адаптера: чтение тикета, переход статуса,
  исполнитель, ворклог, комментарий, ранг.
- Комментарий на v2 уходит строкой, на v3 остаётся телом ADF; исполнитель на
  v2 ставится по `name`, на v3 по `accountId`.
- Неизвестное значение ключа отбивается на чтении контура с внятным текстом, а
  не превращается в 404 посреди работы; ответ не-JSON (302 на веб-логин
  живого контура) тоже отдаётся внятным отказом, а не паникой разбора.
- Тесты гоняют обе версии: стенд отвечает по путям своей версии, тела
  сверяются по формату.
- README trackctl описывает ключ версии и разницу тел, а не одну третью версию.

## Ранг

Считается по `RANKING.md`, 50+7+3+0+2 = 62, это P1.

- Серьёзность 50: основной сценарий утилиты на контуре с v2 не работает вовсе,
  обход у пользователя есть, но болезненный, вести тикеты руками через веб.
- Ценность 7: закрытие возвращает контуру всю обвязку trackctl, ради которой
  утилита и заводилась.
- Неопределённость 3: подход понятен, но правка идёт через чужой API, чьи
  расхождения видны на живом прогоне, а не в исходниках.
- Поправка на баг 0: v2 никогда не работала, это новое поведение, а не регресс.
- Рычаг 2: адаптер становится годен и для чужих контуров, но чужую работу
  сейчас не поддерживает.

## Приёмка

- вид: agent

Шесть барьеров пройдены, ни один не устоял. «Глаза», «согласие» и «событие» к
предмету не относятся: итог не экран, не согласие с направлением и не ждёт
внешнего момента. «Доступ» и «секрет» снимаются обходами, стенд с ответами v2
поднимается на машине агента (он уже есть в тестах адаптера), а токен живого
контура агент получает через `secretctl exec`, не владея значением.
«Необратимость» снимается тем, что приёмка на живом контуре читает, а пишет на
стенд.
