# DK-418: Личный карман правил на машине рядом с генерённой глобальной точкой

## Что происходит

Наблюдение с чужой машины: у пользователя doctor выдал «~/.claude/CLAUDE.md
правлен руками, содержимое разошлось с хешем маркера: локальные добавления
перенести в RULES.local.md, файл убрать с дороги руками (mv ... .bak) и
повторить devkitctl doctor --fix». Он решил, что devkit хочет перезаписать
его основной CLAUDE.md.

Что на самом деле: check_global (tools/devkitctl/rules.py) держит для
глобальной точки харнеса эталон из шапки и одного импорта
@~/projects/devkit/RULES.core.md, и любую руками дописанную строку видит как
расхождение хеша. --fix файл нарочно не трогает, но находка висит навсегда,
пока пользователь не вынесет свои строки.

Дыра: вынести их некуда. RULES.local.md по RULES.md это файл про корп-контур
конкретного репозитория, подключается строкой в AGENTS.md проекта, а не
глобально. Личным правилам «на всю машину» (свой стиль ответов, привычки,
не связанные с devkit) devkit сегодня кармана не даёт: генерённая точка
везёт ровно один импорт, и файл харнеса, который по замыслу Claude Code
принадлежит пользователю, по факту забран devkit целиком. Текст находки при
этом отсылает в файл не того назначения.

Предлагаемое: генерённая точка везёт вторую строку импорта на личный файл
пользователя (например @~/.claude/CLAUDE.local.md), которого генератор не
трогает и не сверяет; клиент импорт в несуществующий путь молча пропускает,
так что пустой карман ничего не стоит. Текст находки «правлен руками»
отсылает туда, а не в RULES.local.md. Заодно проверить: имя файла на харнес
из профиля ([rules] user_file или подобное), а не зашитое; вес личного файла
считать в weigh; README раздел про глобальную точку и RULES.md пункт про
RULES.local.md поправить, чтобы два кармана не путались.

## Чего хотим

## Границы

Задача даёт карман и правит текст находки. Раскладка личных правил по машинам
(перенос между маками, синхронизация) в границы не входит.

## DoD

Генерённая глобальная точка везёт вторую строку импорта на личный файл
пользователя, имя которого приходит из профиля харнеса (секция `[rules]` рядом с
`global_file`), а не зашито в код. Личный файл генератор не создаёт, не сверяет и
не трогает `--fix`, а несуществующий путь клиент харнеса пропускает молча, так
что пустой карман ничего не стоит. Текст находки «правлен руками» отсылает в этот
карман, а не в `RULES.local.md` другого назначения. Вес личного файла считается
в `weigh`, README раздел про глобальную точку и пункт `RULES.md` про
`RULES.local.md` разведены так, что два кармана не путаются. Тест показывает
доктора чистым на машине, где личный файл есть, и на машине, где его нет.

## Ранг

`25+4+1+0+2 = 32`, P2.

- Серьёзность 25: трение с дешёвым обходом. Личные строки в глобальной точке
  живут и работают, `--fix` их не стирает, но доктор из-за них ругается каждым
  прогоном, и на чужой машине это прочли как «devkit хочет перезаписать мой
  CLAUDE.md».
- Ценность 4: доктор перестаёт шуметь у каждого, кто дописал себе строку, и
  находка «правлен руками» ведёт туда, где карман правда есть.
- Неопределённость 1: решение расписано до имени секции профиля и списка мест,
  которые правятся следом.
- Поправка на баг 0: карман заводится впервые, ничего не ломалось; текст находки
  чинится попутно.
- Рычаг 2: снимает шум доктора и разводит два файла с похожими именами, польза
  по одной теме.

Цена M: правка `tools/devkitctl/rules.py` и профилей харнесов с тестами, плюс два
раздела доки.

Вид приёмки agent: доктор на стенде отвечает кодом возврата и текстом находки.

## Что проверено на груминге

- Нехватка на месте: `check_global` в `tools/devkitctl/rules.py` держит эталон из
  шапки и одного импорта, текст находки на строках 816 и 916 отсылает в
  `RULES.local.md`.
- Опора в профиле есть: секция `[rules]` уже везёт `mode`, `file`, `import_line`
  и `global_file` (`kit/harness/claude-code.toml`), второму имени там место
  готово.
- Дублей нет: ближайший сосед DK-260 про профили прав сессии по контуру, предмет
  другой.
