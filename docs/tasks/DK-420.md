# DK-420: Дока запускатора окна второй подписки: порядок первого запуска с нуля

записан 2026-08-17

## Что происходит

Окно второй подписки поднимает `shipctl code <ID>` (DK-175, DK-192, DK-214),
и в `tools/shipctl/README.md` про него три раздела: «Окно на второй
подписке», «Копия на окно, а не на задачу», «Окружение живёт в директории,
а не в запуске». Пользователь, читая их 2026-08-17, не нашёл ответа на
вопрос «как поднять окно на новой машине с нуля»: разделы разбирают
устройство, а порядка первого запуска не дают. Проверено чтением
`tools/shipctl/README.md` (строки 108-231) и `tools/devkitctl/README.md`
(строки 870-895): сводного списка шагов нет ни там, ни там.

Что не так конкретно:

- порядок первого запуска разложен по трём местам и нигде не собран: ключ
  `home` секции `[glm-code]` в `~/.devkit/harness.local` (shipctl, абзац про
  машинный слой), болванка каталога конфига от `devkitctl doctor --fix` и
  находки про пустые ключи (devkitctl, раздел доктора), значения
  `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_MODEL` из кабинета
  подписки, потом `shipctl code <ID>`. Сводного «шаг 1, 2, 3, проверка
  `--dry-run` и `--probe`» нет;
- вводный абзац раздела «Окно на второй подписке» объясняет рычаг через
  `CLAUDE_CONFIG_DIR` и экспорт переменной перед каждым запуском, а раздел
  «Окружение живёт в директории» ниже говорит, что после DK-192 ключи лежат в
  самой копии в `.claude/settings.local.json` и окну переменная при запуске
  не нужна. Абзац остался от старой схемы, две картины спорят друг с другом
  (та же старая формулировка в шапке `tools/shipctl/editor.go:18`);
- откуда берётся имя поставщика (`glm`), путь копии `../<проект>-glm` и что
  такое профиль `kit/harness/glm-code.toml`, читатель узнаёт из корневого
  README и доки devkitctl, а не из доки запускатора.

Обход есть и дешёвый: собрать порядок из трёх мест самому либо спросить в
чате, что и случилось. На чужой машине без человека, знающего фичу, обход
уже не работает: без порядка запуска фича до пользователя не доезжает.

## Чего хотим

Раздел про окно второй подписки в `tools/shipctl/README.md` открывается
списком «первый запуск с нуля» на новой машине: заведение ключа `home` в
машинном слое, `devkitctl doctor --fix` за болванкой каталога, вписывание
значений из кабинета подписки, `shipctl code <ID>`, чем проверить
(`--dry-run`, `--probe`, находки доктора). Из списка на 100% понятно, что и
в каком порядке делать, а разбор устройства идёт после него. Вводный абзац
переписан под текущую схему: окружение живёт в директории копии,
`CLAUDE_CONFIG_DIR` упоминается только там, где он ещё участвует (машинный
слой, подпроцесс делегирования); та же правка в шапке `editor.go`. Раздел
доктора в `tools/devkitctl/README.md` ссылается на этот порядок, а не
дублирует его. Запуск без задачи не сюда: это DK-203, в списке на неё
отсылка, а вход без ID дописывается, когда она сделана.

## DoD

В `tools/shipctl/README.md` есть список первого запуска окна второй подписки
с нуля, по которому чужой контекст на временном `HOME` с синтетическим
машинным слоем доходит до успешного `shipctl code <ID> --dry-run` без
подглядывания в код и в другие доки; вводный абзац раздела и шапка
`editor.go` описывают текущую схему (окружение в директории копии), а раздел
доктора в devkitctl ссылается на список. Правка проходит вычитку
`proofread` и `check-symbols`.

## Приёмка

Вид agent. Барьер «глаза» (понятность текста) обходится прогоном чужого
контекста по списку на временном `HOME`: дошёл до `--dry-run` без подсказок
значит список полный, застрял значит место пробела названо шагом.

## Ранг

`25+5+1+0+2 = 33`, P2.

- Серьёзность 25 (Major). Заметное трение: первый запуск на новой машине
  требует собрать порядок из трёх мест или спросить знающего; обход дешёвый
  и очевидный, пока знающий рядом.
- Ценность 5. Ощутимое улучшение, которого просят: пользователь назвал пробел
  сам и требует стопроцентной понятности запуска.
- Неопределённость 1. Подход ясен (список шагов в начале раздела, правка
  вводного абзаца, ссылка из доктора), правка только в доке и одном
  комментарии, осталось сделать.
- Поправка на баг 0. Дефекта в коде нет, недостаёт доки.
- Рычаг 2. Небольшая своя польза: каждый следующий подъём окна на другой
  машине дешевле, вопрос в чат не уходит.
