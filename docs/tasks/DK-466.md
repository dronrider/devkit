# DK-466: Дашборд: истёкший логин чата виден состоянием и чинится перезапуском

## Что происходит

2026-08-21, POC разговора DK-397 (ветка poc-chat, экземпляр на 7131). Диалог
это сессия харнеса в tmux, и на реплику с дашборда сессия отвечает
«Login expired. Please run /login»: OAuth-токен харнеса истёк. Дашборд про
такой ответ знает только одно: titleJunk в tools/dashboard/chats.go не пускает
его в заголовок разговора.

Разговор встаёт, и с дашборда его не оживить: /login это интерактивный
OAuth-заход в терминале, кнопки или подсказки на экране чата нет. Пользователь
видит отказ без пути к починке, а смотрят POC в том числе с телефона, где
терминала машины нет вовсе.

Разбор того же дня: релогин в соседнем окне (vscode) живые сессии не оживил.
Свежий токен лёг в связку ключей, новый процесс логинится сразу, а поднятые
вчера chat-DK-397-1 и chat-DK-397-2 продолжали отвечать «Not logged in» и
«Login expired»: процесс держит старый токен в памяти и после чужого /login
сам не перечитывает. Вылечено снятием их tmux-сессий, продолжение поднял
штатный резюм дашборда.

## Чего хотим

Истёкший логин виден на дашборде явным состоянием чата, а не отказом в ленте,
и рядом лежит путь к починке: после релогина на машине дашборд сам
перезапускает застрявшую сессию резюмом, без захода в терминал.

## Развилки

Докуда вести пользователя: явная плашка «сессия разлогинена, зайдите на машину
и выполните /login» или починка с самого дашборда? Релогин в терминале кладёт
свежий токен в связку на всех, но живым сессиям он не помогает, им нужен
перезапуск процесса, а механика для него у дашборда уже есть: снять tmux и
поднять резюм. В POC-контуре ещё и фейковый HOME со связкой ключей симлинком.

### Агентская часть приёмки, 2026-08-29

Заход на экземпляре 7131 живым браузером: headless Chrome под управлением CDP,
раскладка меряется `getComputedStyle` и прямоугольником узла, а не свойством
`hidden`. Признак сервера читается своим замером, через API.

Подопытный разговор поднят на второй подписке, чтобы приёмка не тратила квоту
claude-code. Что сессия и правда пошла на GLM, видно четырьмя местами: подъём
ответил `{"model":"glm-5.3","tmux":"chat-4"}`, список чатов и шапка сессии дают
разговору `harness: glm-code`, транскрипт лёг в дом второй подписки
(`~/.devkit/claude-glm/projects/-Users-rider-projects-xr-proxy/`), а не в
`~/.claude/projects`, и сам агент на вопрос о модели ответил «Я работаю на
модели glm-5.3».

Здоровый разговор, плашки на экране нет:

```
{"hidden":true,"display":"none","visibility":"visible","w":0,"h":0,
 "text":"Сессия разлогинена. Агент отвечает служебной строкой про истёкший вход"}
```

Замер различает два состояния, а не смотрит на признак сервера. Из живых стилей
той же страницы снято ровно одно правило, добавленное правкой `0018e24e`
(`.cnote[hidden]{display:none}`), и на том же здоровом разговоре плашка встала
во весь рост:

```
снято правил: 1
{"hidden":true,"display":"flex","w":732,"h":74}
```

Разлогин поднимает плашку. Служебная строка подставлена в транскрипт записью
той же формы, какой её пишет клиент (роль `assistant`, текст
`Login expired. Please run /login`). Сервер:

```
список: login= 'сессия разлогинена'
лента:  assistant | logout= True | Login expired. Please run /login
```

Экран:

```
{"hidden":false,"display":"flex","visibility":"visible","w":732,"h":74}
```

Первый настоящий ответ гасит плашку, и она уходит с экрана. Ответ дописан в
транскрипт при открытой странице, страница не перезагружалась:

```
список: login= None
{"hidden":true,"display":"none","w":0,"h":0,"кнопка":true}
хвост ленты: продолжаю с того места, где остановился
```

Второй разлогин того же разговора плашку поднимает заново, состояние не
одноразовое: `{"hidden":false,"display":"flex","w":732,"h":74}`.

Кнопка «Перезапустить» на живой сессии. Нажата в браузере, из плашки. tmux
пересоздан (сессия `chat-4` от 09:06:35 снята, новая поднята в 09:13:49),
продолжение пришло резюмом в тот же транскрипт, и разговор ответил по делу:

```
user      | 06:13:49 | Разговор встал: у клиента истёк вход, процесс снят и поднят заново
assistant | 06:14:00 | Обрыва с потерями не случилось: проверка DK-466 была закончена до него
```

Плашка после этого погасла сама: `{"hidden":true,"display":"none","w":0,"h":0}`.
Резюм сохранил ID сессии, поэтому панель осталась на том же адресе
`#xr-proxy/chat/<id>` и подхватила пересозданный tmux; переезда на новый ID тут
не случилось, потому что резюм его не заводит.

Подопытный разговор снят, транскрипт и записи хранилища удалены.
