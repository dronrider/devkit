# DK-467: Маскировка токенов доктором рвёт экранирование и ломает settings.json

## Что происходит

doctor --fix заменяет литеральные токены в allow-правилах маской __TRACKED_VAR__. В правилах вида Bash(curl -H \"Authorization: Bearer <токен>\" ...) токен стоит перед экранированной кавычкой, и замена съедает обратную косую: остаётся __TRACKED_VAR__" без экранирования. Замечено 2026-08-21: после doctor --fix файл ~/.claude/settings.json перестал быть валидным JSON (семь таких мест), парс падал на char 4239.

Битый settings.json молча выключает настройки харнеса у новых сессий: хуки, разрешения, crossSessionInbound. Починено руками возвратом косой во все семь мест; окно поломки было около часа.

### Проверено грумингом 2026-08-25

Баг живой: подстановка `_FIX` в `tools/devkitctl/leak.py` собрана классом
`[^'\" ]+`, обратная косая в класс попадает, и на строке правила
`"Bash(curl -H \\"Authorization: Bearer glpat-XXXX\\" https://x)"` замена даёт
`Bearer __TRACKED_VAR__" https` без косой. Уязвимы четыре шаблона из пяти,
пятый (`xrReleasePublicKey='...'`) стоит в одинарных кавычках, которые JSON не
экранирует.

Развилка черновика закрыта: разбор JSON рядом уже прижит. `tools/devkitctl/perms.py`
читает те же настройки через `json.loads` и пишет их обратно целиком через
`json.dumps(..., indent=2)`, и переформатирование файла там названо осознанным
(комментариев JSON не держит). Значит маска ложится тем же путём: правило берётся
разобранной строкой списка `permissions.allow`, чинится в ней, и файл пишется
разбором, а не подстановкой по тексту.

Дублей нет: на доске задач про маску и течь литералов не стоит (DK-207 и DK-229
закрыты и лежат в архиве), в накопителе соседние записи про настройки харнеса
(DK-260, DK-442, DK-478, DK-527) про другой предмет.

Перепроверено 2026-09-11. `leak.py` с DK-229 не менялся, и баг на месте. Битый
settings.json доктор уже называет находкой проверки прав
(`tools/devkitctl/perms.py`, «настройки харнеса не разбираются»). Поэтому
отдельного сторожа валидности в задаче нет, выбор записан развилкой «объём».

## Чего хотим

Маска ставится через json-разбор строки правила, тест кормит доктору правило с экранированной кавычкой и сверяет валидность файла после --fix.

## Границы

как есть.

## DoD

`doctor --fix` на настройках, где allow-правило несёт токен перед экранированной
кавычкой, оставляет файл разбираемым как JSON. Правило остаётся с маской и целой
косой. Маска ставится в строках разобранного документа, и файл пишется разбором,
как в `perms.py`. Повторный `--fix` на прижитой маске файла не меняет.
Регрессионный тест падает на коде до правки и проходит после, краснота сверена
`regcheck`. Докстринг `leak.py` говорит, что `--fix` переписывает файл разбором
и форматирует его заново.

## Сценарий проверки

Агентский. Шаги гоняются из корня дерева, настройки харнеса не трогаются:
доктор работает на временном HOME.

1. Доктор чинит правило с экранированной кавычкой, и файл остаётся разбираемым JSON.

```sh
box=$(mktemp -d)
mkdir -p "$box/.claude"
python3 - "$box/.claude/settings.json" <<'PY'
import json, sys
rule = 'Bash(curl -H "Authorization: Bearer glpat-xxx" https://git/api)'
open(sys.argv[1], "w").write(
    json.dumps({"permissions": {"allow": [rule]}, "model": "opus"},
               ensure_ascii=False, indent=2) + "\n")
PY
HOME="$box" python3 tools/devkitctl/leak.py --fix
python3 -c 'import json,sys; d=json.load(open(sys.argv[1])); print(d["permissions"]["allow"][0]); print(d["model"])' "$box/.claude/settings.json"
HOME="$box" python3 tools/devkitctl/leak.py
rm -rf "$box"
```

Ожидание: строка «починено: ... литералы заменены маской __TRACKED_VAR__», дальше
правило `Bash(curl -H "Authorization: Bearer __TRACKED_VAR__" https://git/api)` с
целыми кавычками, строка `opus` от соседней настройки и на повторной сверке
«литеральных токенов и резервных копий нет». Разбор файла не падает, значит JSON
после `--fix` валиден.

2. Тесты модуля зелёные.

```sh
python3 -m unittest discover -s tools/devkitctl -t tools/devkitctl -p leak_test.py
```

Ожидание: `OK`, 11 тестов.
