# DK-472: Процедура записи чистого вердикта в board-ship и промтах ревьювера

## Что происходит

В разделе «Ревью» скилла `board-ship` (пп. 5-6, `SKILL.md:91-95`) сказано только
«строка на замечание, суть и исход», про вердикт без замечаний нет ничего.
Диспетчер читает процедуру и не находит, чем записать чистое ревью, поэтому
команда из DK-471 сама по себе останется невостребованной.

Строка вторая в плане [LLD DK-460](../lld/DK-460-review-gate.md), раздел «Что
меняется в строках», пункт 2.

## Чего хотим

Процедура называет запись вердикта шагом ревью, и ревьювер уходит с задачи,
оставив след при любом исходе.

## DoD

Раздел «Ревью» скилла `kit/skills/board-ship` и промты `kit/agents/review-*`
называют последним шагом ревьювера запись вердикта командой из DK-471, включая
чистый исход. Перечень подкоманд в `SKILL.md:92` дополнен той же командой.
Проверка стендом послушания, а не чтением глазами.

Строка ложится на те же файлы, что чужая DK-185 (точки вызова вычитки и формат
служебных записей, постановка в LLD DK-173). Предметы разные, поглощения нет,
но параллельно эти строки не едут: идущая второй подхватывает формулировки
первой.

## Ранг

`25+4+1+0+4 = 33`, P2.

- Серьёзность 25: команда есть, а процедура про неё молчит, шаг держится
  памятью того, кто читал LLD.

- Поправка на баг 0: шага в процедуре не было.
- Рычаг 4: без неё ворот DK-473 приходил бы на честную работу.

Пример: «конец: сессия» для board-ship или база без исходного упоминания review clean для review-medium.md. Выбранный вариант и причину нужно записать

## Сценарий проверки

1. Текст процедуры на месте в `board-ship/SKILL.md` и во всех четырёх
   промтах ревьювера:

```sh
grep -c "Последним шагом ревьювер" kit/skills/board-ship/SKILL.md
grep -c "Этим ревьювер" kit/agents/review-low.md kit/agents/review-medium.md kit/agents/review-high.md kit/agents/review-xhigh.md
```

Ожидание: первая команда печатает `1`, вторая печатает `<файл>:1` на каждый
из четырёх промтов.

2. Сценарий стенда `51-review-clean-verdict` разбирается без прогона
   моделей:

```sh
obeycheck --list --only 51-review-clean-verdict
```

Ожидание: одна строка с ID сценария, заголовком и предметом
(`kit/skills/board-ship/SKILL.md «Ревью»; kit/agents/review-medium.md
(конец: субагент)`), без спавна сессий.

3. `taskctl review clean` на синтетической доске во временном каталоге
   оставляет в файле задачи строку вердикта, реальный `docs/tasks/DK-472.md`
   не трогается:

```sh
S=$(mktemp -d) && mkdir -p "$S/docs/tasks" && cp docs/TASKS.md docs/TASKS-archive.md "$S/docs/" && taskctl -C "$S" review clean DK-472 "проверка процедуры чистого вердикта" && grep -n "Вердикт: без замечаний" "$S/docs/tasks/DK-472.md"
```

Ожидание: `taskctl` печатает «вердикт без замечаний записан», `grep` находит
строку `- Вердикт: без замечаний. проверка процедуры чистого вердикта` в
файле песочницы.
