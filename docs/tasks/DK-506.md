# DK-506: taskctl elapsed: минуты открытого этапа «разработка» против потолка захода

## Что происходит

LLD [DK-503](../lld/DK-503-exec-ceiling.md) (Решение 1) выбрал метрику
потолка захода: минуты с момента `Start` последнего этапа «разработка» в
записи `~/.devkit/runs/<ID>-<slug>.run`. `agentctl pick --record` пишет этот
момент (`pick.go:508`), а после DK-511 второй вызов делает это ещё раз
непосредственно перед спавном исполнителя, так что запись переживает старт
работы. Команды же, которая считала бы и печатала прошедшее время против
потолка, у `taskctl` нет: есть рубеж F (`progress`) и возраст строки доски
(`git blame`), а времени открытого этапа не считает ничего.

## Чего хотим

Команда `taskctl elapsed <ID>` печатает минуты с `Start` последнего этапа
«разработка» записи `.run` и сравнивает их с потолком (константа по
умолчанию 120 минут, переопределяется окружением
`DEVKIT_EXEC_CEILING_MINUTES`), по образцу из DK-503:

```
разработка открыта 46 минут назад (с 2026-08-24T13:55:00), потолок 120 минут: в пределах
разработка открыта 145 минут назад (с 2026-08-24T09:10:00), потолок 120 минут пройден: сдавай хвост
```

## DoD

- `internal/stage`: функция `Elapsed(rec Record, kind string, now time.Time)
  (time.Duration, bool)`, берущая `Start` последнего этапа с совпавшим
  `Kind`; тесты (этап есть и до потолка, этап есть и после потолка, этапа
  нет).
- `tools/taskctl`: подкоманда `elapsed <ID>`, потолок из константы с
  переопределением `DEVKIT_EXEC_CEILING_MINUTES`, обе ветки вывода («в
  пределах» / «пройден»), нештат без открытого этапа печатает «этап не
  открыт, потолок не проверить» и не падает (DK-503, раздел «Нештат и
  границы»); тесты на разбор аргументов и текст вывода.
- `tools/taskctl/README.md`: строка про `elapsed` в перечне подкоманд, рядом
  с `progress`.
- `go test ./...` зелёный.

## Ранг

`25+8+1+0+4 = 38`, P2.

- Серьёзность 25: заметное трение с известным дешёвым обходом (резать задачи
  мельче на грумминге), но обход не защищает от захода, разросшегося после
  старта (DK-503, «Задача и рамка»).
- Ценность 8: инструмент, который реально экономит квоту, а не абзац про
  экономию (DK-503, «Разбивка на задачи»): без него нечем измерить потолок.
- Неопределённость 1: подход выбран решением 1 целиком, имя команды, формула
  и формат вывода названы, реализация не встречает развилок.
- Поправка на баг 0: новая возможность, не регресс.
- Рычаг 4: делает дешевле каждый следующий длинный заход, правит механику
  диспетчера и исполнителей целиком.
