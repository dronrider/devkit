# DK-520: Метка уровня разбора обязательна при записи черновика

## Что происходит

Метка уровня разбора (`taskctl draft prio <ID> high|mid|low`) ставится
отдельной командой после записи, а скилл `board-draft` прямо говорит, что при
записи её не делают. Ставить её поручено грумингу, но груминг как правило
превращает черновик в задачу, и метка, которая должна была задавать очередь
разбора, теряет смысл: она появляется в тот момент, когда разбор уже идёт.
На 2026-08-25 из 81 черновика без метки 42, все записаны после 2026-08-17,
то есть после последнего сплошного прохода разметки.

## Чего хотим

Грубая оценка есть у каждого черновика с момента записи. `taskctl draft`
требует уровень явно (флаг `--prio high|mid|low`) и без него отказывает с
подсказкой; `draft list` не показывает группу немаркированных для новых
записей. Скилл `board-draft` учит ставить уровень на записи, а
`RULES.board.md` п. про накопитель и `board-groom` перестают называть
груминг местом первой разметки (`draft prio` остаётся для пересмотра).
Существующие 42 немаркированных черновика размечаются в той же задаче.

## DoD

- `taskctl draft` без `--prio` отказывает, с `--prio` кладёт строку
  «приоритет: ...» в шапку файла; тесты на оба исхода и на болванку из одного
  заголовка.
- Стенд дашборда и другие вызовы `taskctl draft` в devkit (grep по `kit/`,
  `tools/`, `hooks/`) передают уровень.
- `kit/skills/board-draft/SKILL.md`, `kit/skills/board-groom/SKILL.md`,
  `RULES.board.md`, `tools/taskctl/README.md` согласованы с новым порядком.
- `taskctl draft list` не содержит немаркированных черновиков.

## Ранг

Серьёзность 25: очередь разбора накопителя теряется, обход есть ручным
проходом разметки. Ценность 6: порядок груминга для 81 черновика. Неопределённость 1:
решение принято пользователем, открыты детали флага. Баг 0. Рычаг 2: груминг
заходит с верха списка и опирается на метку.
