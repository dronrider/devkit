# DK-527: Планы параллельных субагентов пачки пишутся в один файл и трутся

## Что происходит

Субагент ведёт план работ файлом в каталоге планов. Имя собирается из ID сессии
с хвостом sub, по этому адресу план и читает дашборд.

Диспетчер пачки поднимает субагентов пачкой, ID внешней сессии у них один, и
планы затирают друг друга. На витке цели DK-446 два исполнителя писали в один
файл. Один увёл своё в имя с ID задачи и пропал с экрана дашборда, такого имени
дашборд не знает. Исполнители DK-641 и DK-642 поймали то же самое, там
исполнитель просто перестал писать план.

## Чего хотим

Имя плана берёт ID задачи или ID субагента, дашборд собирает экран по маске.

## Границы

Формат файла плана и правило его ведения живут в DK-613. Здесь только адрес и
чтение по маске.

## Развилки

Чем разводить планы, когда сессия одна, а субагентов несколько.

## DoD

- У двух субагентов одной сессии адреса планов разные, чужой файл никто не
  перезаписывает.
- Дашборд показывает план каждого субагента пачки.
- Признак, по которому расходятся имена, назван и доступен субагенту из его
  окружения.
- Тесты. Два плана одной сессии на стенде дашборда, оба видны; старое имя
  `<ID>-sub.json` читается по-прежнему.

## Ранг

`25+6+2+5+2 = 40`, P2.

- Серьёзность 25: ход работы пачки не виден, обход дешёвый, спросить
  исполнителя.
- Ценность 6: пачка идёт каждый день, кольцо прогресса это её единственный
  вид снаружи.
- Неопределённость 2: подход назван, открыт источник признака субагента.
- Баг 5: планы трутся, запись работы теряется.
- Рычаг 2: чинит наблюдаемость своего конвейера.

## Ход работы

- Из черновика DK-527 «План работ субагентов пачки пишется в один файл и затирается»: записан 2026-08-25, оформлен 2026-09-01.
- Актуальность проверена чтением кода 2026-09-01. Правило плана называет адрес
  по ID сессии (`hooks/session-task.py:194`, `tools/dashboard/chats.go:1427`),
  признака субагента в адресе нет. DK-613 держит `<ID>-sub.json` в своём DoD, и
  без этой правки развод параллельных субагентов туда не попадёт.
- Приписаны черновики DK-648 и DK-639 о том же предмете.
- Разработка 2026-09-02. Признак назвал сам субагент: адрес стал
  `~/.devkit/plans/<ID сессии>-sub-<метка>.json`, метку исполнитель выбирает
  одним разом и держит до конца захода. Готовой переменной под это нет:
  `CLAUDE_CODE_SESSION_ID`, `CLAUDE_PID` и сокет сообщений у пачки общие, а свой
  PID шелла живёт одну команду. ID задачи в метку годится, но правило на него не
  опирается: у субагента разведки задачи нет вовсе. Правило переписано в четырёх
  определениях исполнителя (`kit/agents/exec-{low,medium,high,xhigh}.md`), чтение
  по маске легло в `tools/dashboard/sessions.go` (`subPlanFiles`, `subPlanMark`,
  `subPlans`, счёт в `planStamp`), пункты чужих планов метятся источником `sub`
  наравне с работами из журналов. Старый адрес без метки читается той же маской.

## Сценарий проверки

1. Поднять пачку из двух задач так, чтобы оба исполнителя шли субагентами одной
   сессии, и на середине их работы посмотреть `ls ~/.devkit/plans | grep -- -sub-`:
   лежат два файла с разными метками, у каждого свой список этапов.
2. Открыть в дашборде разговор диспетчера этой пачки. В списке кольца стоят
   этапы обоих исполнителей, каждый со своей меткой в тексте и пометкой
   «субагент», и по ним видно, кто из двоих на каком шаге. Плана, написанного
   поверх соседского, нет: закрыть шаг у одного исполнителя и убедиться, что
   пункты второго на экране не изменились.

## Проверка

Прогон стенда `obeycheck` не звался, и вот почему. По порогу скилла `prompt-test`
повод пограничный: процедура та же (пиши план файлом), сменился один аргумент,
адрес. Разницы между раскладками стенд тут не покажет: правило плана стоит в
обеих, и сценарий «напиши план» проходит на любой. Само же поведение, ради
которого правка затевалась, стенду недоступно: он поднимает сессию, а нужны два
субагента одной сессии сразу. Живой проверкой стал этот самый заход: исполнитель
DK-527 сам вёл план по новому адресу
`~/.devkit/plans/<ID сессии>-sub-DK-527.json`, файл читается дашбордом и лежит
рядом с планом внешней сессии, не трогая его. Остальное закрыто тестами и
шагами сценария выше.

## Из черновика DK-648 «План-файлы параллельных субагентов пишутся в один путь и трутся» (записан 2026-08-31)

### Черновик

#### Ситуация

Исполнители DK-641 и DK-642 шли параллельно субагентами одной сессии, и оба
при CLAUDE_CODE_CHILD_SESSION=1 получили один ID внешней сессии, а с ним один
план-файл ~/.devkit/plans/<ID>-sub.json. Планы перетирали друг друга, ход
работы по файлу нечитаем. Исполнитель обошёл тем, что перестал писать файл.
Хочется суффикса с собственным признаком субагента (PID, порядковый номер
спавна) или отдельного каталога на субагента, чтобы параллельная пачка вела
планы без столкновений.
