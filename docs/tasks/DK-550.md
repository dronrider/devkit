# DK-550: Сторож прозы считает машинные записи файла задачи наравне с прозой

Цель: [tasks/DK-446.md](tasks/DK-446.md)

## Что происходит

Сторож `hooks/check-prose.py` читает файл целиком и меряет двоеточие в
середине фразы по всему тексту. В файле задачи рядом с прозой лежат машинные
записи, и двоеточие в них стоит по формату.

```
- Разработка: субагент opus/high по вердикту pick (квота: week_all 42%...)
- Ревью: субагент sonnet/high по вердикту pick (квота: week_all 42%...)
- Неопределённость 1: место известно, открыт был только выбор по devkitRoot
```

Первые две строки пишет `taskctl` при переводе задачи, третья это формат
раздела «Ранг», где двоеточие делит оценку и причину. Человек их не писал и
переписать не может.

Мера цели по десяти текстам 2026-08-27 показала перекос числами. У DK-545
двоеточие вышло 17,6 на 1000 слов при пороге 10, а без машинных записей 7,1.
У DK-524 было 12,0, стало 7,4. У DK-546 и DK-530 перебор сохраняется и после
чистки, 11,6 и 11,0, и вот он настоящий.

Перекос систематический. Чем короче задача и длиннее «Ход работы», тем хуже
цифра при том же качестве прозы.

## Границы

Задача правит счёт сторожа. Пороги в `kit/prose.toml` она не двигает и текстов
не переписывает.

## Чего хотим

Сторож меряет прозу и пропускает машинные записи, как сборщик корпуса
пропускает служебные вставки. Список записей берётся из того, что пишут
`taskctl` и `shipctl`, плюс строки формата разделов «Ранг» и «Приёмка».

## Развилки

Список пропускаемых строк собран не из головы. Он взят из кода, который
правит файл задачи: `tools/taskctl`, `tools/shipctl`, `internal/stage`.

Раздел «Ход работы» пишет одно место в коде, `internal/stage.Lines`
(`internal/stage/stage.go:317`). Его зовёт `flushStages`
(`tools/taskctl/stage.go:23`) на каждом переводе статуса. Формат один на все
четыре вида этапа. Строка несёт дефис, метку с заглавной буквы, заметку, дату
и часы этапа, точку в конце. Метка это `Kind`: Разработка, Ревью, Снаружи,
Уточнение. Заметку для Разработки и Ревью строит `recordStage`
(`tools/agentctl/pick.go:504`). Заметку для Снаружи собирает `openOutside`
(`tools/taskctl/stage.go:48`). Заметку для Уточнения строит
`tools/taskctl/ask.go:87`. В список взяты все четыре метки, а в постановке
названы только Разработка и Ревью. Строку у всех четырёх видов этапа пишет
один и тот же код.

`shipctl` своих строк в файл задачи не пишет. Провал проверки и перевод
статуса он проводит внешним вызовом `taskctl`, командами `taskFailSet` и
`taskMove` (`tools/shipctl/ops.go`). Источник записи один.

Раздел «Ранг» размечен формой `TASKFORM.md`, строка 204. Первой строкой стоит
формула. Дальше идёт по строке на каждое из пяти слагаемых `RANKING.md`.
Слагаемые это Серьёзность, Ценность, Неопределённость, Поправка на баг,
Рычаг. Строка несёт дефис, слагаемое, число, причину через двоеточие.

Раздел «Приёмка» размечен `ACCEPTANCE.md`. Сам `taskctl` разбирает его теми
же регулярками. Строка барьера и строка обхода живут в `accept.go:47-52`,
это `acceptBarrierLineRe` и `acceptBypassRe`. Строка вида берётся из шаблона
в `tools/taskctl/ops.go:443`. Строка пересмотра вида это `revisionLineRe`
(`tools/taskctl/kinds.go:32`). Строка обхода несёт исход после двоеточия,
«годится» или «не годится», дальше причину. Строка барьера несёт ключ в
ёлочках и причину после двоеточия.

Скилл `proofread` велит дописывать в «Ход работы» строку «Вычитка». Формат
взят из `kit/skills/proofread/SKILL.md`. В список она не попала. Пишет её не
код, а сам исполнитель по инструкции скилла. Это обычная авторская запись,
не формат.

## DoD

1. Машинные записи файла задачи в счёт метрик не идут.
2. Список пропускаемых строк собран из того, что реально пишут утилиты.
   Источник назван в «Развилках».
3. Проза в тех же файлах считается по-прежнему. Тест держит оба конца на
   синтетическом файле: строка утилиты не считается, похожая на неё строка
   прозы считается.
4. Мера цели DK-446 перепрогнана по тем же десяти текстам, числа до и после
   лежат в разделе «Проверка».

## Ранг

`25+6+1+5+2 = 39`, P2.

- Серьёзность 25. Трение с дешёвым обходом. Мера считается руками, и так её
  уже посчитали.
- Ценность 6. Сторож стоит на записи каждого файла задачи.
- Неопределённость 1. Место известно, открыт состав списка.
- Поправка на баг 5. Сторож считал машинные записи с рождения, и заметили это
  только на мере цели.
- Рычаг 2. Замыкает пятый пункт DoD цели DK-446.

## Ход работы

- Вычитка: 1 файл, 2 правки, 2 пометки, 2026-08-27.

разошлись на несколько десятых. Архивные файлы после снимка получили новые
строки «Ход работы» и записи ревью. Фильтр вынес их из счёта, слов в файле
стало меньше. Обе задачи остаются кандидатами на правку самого текста.
