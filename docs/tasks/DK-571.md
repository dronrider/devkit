# DK-571: Фоновая команда мимо реестра сторожа: весть о её конце теряется

## Что происходит

Свод DK-519 (28.08): сторож регистрирует только субагентов, поднятых
инструментом Agent. Работа разряда shell, то есть фоновая команда вроде
shipctl merge, в реестр не попадает вовсе. Сессия, отдавшая слияние в фон,
ждёт вести, которой некому прийти. Так 26.08 встали DK-168 и DK-516: ветки
готовы, ревью пройдено, слияние не доехало.

Диспетчер стоит до смерти сессии, а задача выглядит идущей. Пойманы две задачи
за одну ночь, обе на последнем шаге.

## Чего хотим

Сессия узнаёт о конце фоновой команды так же, как о конце субагента, и не
засыпает в ожидании вести, которой не будет.

## Границы

Пробуждение самой сессии, которая кончила ход в ожидании, остаётся DK-691.
Там голова умирает вместе с ожиданием, а тут весть о конце команды приходить
некуда. Фоновая команда субагента теряется по своему признаку, это DK-683.

## Развилки

- Регистрировать ли фоновые команды тем же реестром, что субагентов, или
  запретить фоновый запуск долгих команд правилом. решает: исполнитель.
  решено исполнителем 2026-09-08: реестр. Запрет закрыт DK-678 для headless, а
  в живой сессии фон законен, и отбирать его там не за что. Разряд `shell`
  лёг в тот же реестр и в тот же журнал, что и субагент.
- Чем ловить конец команды, когда своего события у харнеса нет. решает:
  исполнитель. решено исполнителем 2026-09-08: перечнем работ сессии. Замер
  показал, что команда стоит в `background_tasks` события `Stop`, пока идёт, и
  пропадает оттуда, кончившись. Код возврата приезжает вестью
  `<task-notification>` в транскрипт, оттуда сторож его и читает.

## DoD

- Фоновая команда Bash попадает в журнал работ сторожа отдельным разрядом.
  Строка стоит при запуске и при конце, в обеих видны команда и код возврата.
- Сессия, отдавшая команду в фон и кончившая ход, будится после её конца тем же
  путём, что после конца субагента. Видно живым прогоном. Фоновый
  `shipctl merge` доезжает до слитой ветки без человека.
- Команда, умершая вместе с сессией, попадает в журнал строкой с разрядом и
  поводом, а не пропадает молча.
- Регрессионный тест на разряд `shell` в стороже падает на сегодняшнем коде и
  проходит на исправленном, краснота сверена прогоном `regcheck`.
- Разряд назван в `hooks/README.md` рядом с описанием сторожа.

## Разбор

Проверено грумингом 2026-09-01, чтобы исполнитель не проверял то же второй раз.

- Сторож ведёт работы одного разряда. В `hooks/agent-watch.py` заведён
  `SUBAGENT_JOB = "subagent"` (строка 101). Живые работы отбираются условием
  `j.kind == SUBAGENT_JOB` (строка 283), журнал пишется по событиям
  `hookio.AGENT_LAUNCHED` и `hookio.SUBAGENT_DONE`. Фоновая команда Bash не
  попадает в журнал ни строкой.
- Поле сузилось с 28.08. Вторая дорога черновика, запрет фонового запуска
  правилом, наполовину пройдена. DK-678 закрыта 01.09 и отбивает фоновый вызов
  в headless. Остались живая сессия, где фон законен, и субагент живой сессии.
- DK-691 в «Границах» оставляет реестр фоновых команд этой строке.

## Сценарий проверки

Шаги гоняются по порядку и держат общий стенд в `/tmp/dk571-stand`. Там лежат
хуки из родителя коммита правки, реестр каждый шаг берёт свой временный, а
живых сессий не поднимается ни одной. Событие харнеса шагам подаёт живой
образец из `hooks/testdata/claude-code/`. Каждый шаг это одна строка.

Первый шаг воспроизводит поломку. Сторож до правки читает ход `Bash` с фоновым
ответом и не пишет о нём ни строки.

```sh
d=/tmp/dk571-stand; r=$(git rev-parse --show-toplevel); rm -rf "$d"; mkdir -p "$d" && fix=$(git -C "$r" log --format=%H -S SHELL_JOB -- hooks/agent-watch.py | tail -1) && git -C "$r" archive "$fix^" hooks | tar -x -C "$d" && reg=$(mktemp -d) && DEVKIT_AGENT_WATCH_DIR="$reg" python3 "$d/hooks/agent-watch.py" --hook claude-code < "$r/hooks/testdata/claude-code/tool-done-bash-background.json"; echo "сторож из $fix^, строк в журнале: $(cat "$reg/agents.log" 2>/dev/null | wc -l | tr -d ' ')"
```

Ждём строку «строк в журнале: 0» с коммитом старого сторожа.

Второй шаг подаёт тот же образец нынешнему сторожу.

```sh
reg=$(mktemp -d) && DEVKIT_AGENT_WATCH_DIR="$reg" python3 hooks/agent-watch.py --hook claude-code < hooks/testdata/claude-code/tool-done-bash-background.json && cat "$reg/agents.log"
```

Ждём строку журнала с полями «разряд shell», «событие запуск» и командой
«sleep 8; echo готово».

Третий шаг играет потерянную весть. Команда кончилась, харнес больше не числит
её среди работ сессии, а в транскрипте про конец ничего нет.

```sh
d=$(mktemp -d) && python3 -c "import json,os,subprocess,sys; D='$d'; S=json.load(open('hooks/testdata/claude-code/tool-done-bash-background.json')); T=json.load(open('hooks/testdata/claude-code/turn-done.json')); T['session_id']=S['session_id']; T['transcript_path']=D+'/none.jsonl'; E=dict(os.environ,DEVKIT_AGENT_WATCH_DIR=D,DEVKIT_AGENT_WATCH_GRACE='0'); H=[sys.executable,'hooks/agent-watch.py','--hook','claude-code']; subprocess.run(H,input=json.dumps(S),text=True,env=E); print(subprocess.run(H,input=json.dumps(T),text=True,env=E,capture_output=True).stdout); print(open(D+'/agents.log').read())"
```

Ждём решение `block` со словами «фоновая команда» и «весть о ней до сессии не
дошла», а в журнале строки «событие конец» и «событие сдача» разряда shell.

Четвёртый шаг это самопроверка сторожа.

```sh
python3 -m unittest discover -s hooks -t hooks -p 'agent_watch_test.py' 2>&1 | tail -3
```

Ждём «Ran 36 tests» и «OK».

Пятый шаг смотрит доку. Разряд назван рядом с описанием сторожа.

```sh
grep -c "разряд" hooks/README.md
```

Ждём число не меньше четырёх.
