# DK-578: Отказ входа разбирается журналом: обновление связки против падений

## Что происходит

2026-08-29 вход истёк дважды за полчаса у диспетчерской сессии, оба раза с
ней падали её субагенты, и оба раза чинилось только ручным `/login` со
снятием процесса.

На машине держится около одиннадцати клиентов разом: рабочие окна, чат-сессии
дашборда и сессии POC-контура. Дом POC при этом делит настоящую связку ключей,
`~/.devkit/dashboard-poc/Library/Keychains` это симлинк на
`~/Library/Keychains`, и один токен обновляют много процессов сразу.

Гипотеза. Обновление токена ротирует его, и процесс, обновивший первым,
оставляет остальных с отозванным. Тогда частота отказов растёт с числом живых
клиентов, а не с возрастом входа.

Проверять надо наблюдением. Время обновления записи в связке сверяется с
временем отказов в журналах сессий. Смежное: DK-466 (плашка и перезапуск),
DK-577 (вход с телефона).

## Чего хотим

Следующий отказ входа разбирается по журналу. Видно, когда хранилище входа
обновилось, сколько клиентов жило на этот момент и какие сессии упали следом.
По этим парам гипотеза про ротацию общего токена подтверждается или снимается.

## Границы

Починка причины остаётся отдельной строкой. Чем разводить контуры по разным
входам, решается по вердикту журнала. Плашка истёкшего логина и
перезапуск сделаны в DK-466, вход с телефона в DK-577, обе закрыты.

## DoD

- Момент обновления входа виден машинно. Сторож пишет строку с временем правки
  хранилищ входа (связка `login.keychain-db`, файл `.claude/.credentials.json`,
  те же два в доме POC) и числом живых клиентов на этот момент.
- Отказ входа попадает в ту же ленту. Падение сессии с поводом про вход
  записывается строкой с сессией и временем.
- По ленте за сутки видно, совпадает ли отказ с чужим обновлением. Команда
  печатает пары «обновление, отказ» с разницей во времени.
- Регрессионный тест на разбор пары идёт по синтетической ленте, падает на
  сегодняшнем коде и проходит на исправленном, краснота сверена прогоном
  `regcheck`.
- Первый запуск и чтение ленты описаны в README того инструмента, который её
  несёт.
