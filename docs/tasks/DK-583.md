# DK-583: Корп-контур одним окном: ссылка .devkit в клоне, боковая директория на контур

## Что происходит

Обратная связь коллег из корп-контура, 2026-08-29. `devkitctl corp` кладёт
доску, файлы задач и `.devkit` в боковую директорию `../<проект>-local` (LLD
DK-074), а в клоне оставляет симлинк `.devkit/local` под `.git/info/exclude`
(DK-193). В VS Code эта папка из окна клона не видна: поиск уважает
`info/exclude`, панель git видит только репозиторий клона, файл по симлинку
открывается как внешний. Сессия Claude из клона доску видит только по
редиректу утилит.

На каждый корп-проект коллеги держат два окна VS Code, клон и `-local`, и
работа идёт с переключением между ними. У людей с workspace на десяток
проектов папок сбоку становится столько же, и раскладка путается.

Проверено по доке и issue Claude Code 2026-08-29, и это закрывает два обходных
пути: multi-root workspace расширение ведёт только по первому корню,
`CLAUDE.md` соседних корней не читает (issue 36949, 57243); обёртка процесса
`claudeCode.claudeProcessWrapper` cwd не выбирает, расширение присылает
рабочую директорию после старта и перекрывает `cd`. Обе дороги требуют
`--add-dir` руками и переменной
`CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD`, задокументированной только в
руководстве по большим кодовым базам.

## Чего хотим

Корп-проект открывается одним окном VS Code на клон, доска и файлы задач
лежат в нём как `.devkit/docs/...`, видны поиску, панели git и сессии Claude
без `--add-dir`, а в чужой индекс и историю ничего не едет. Боковых папок на
машине одна на контур, сколько бы проектов ни было.

## Развилки

Доска обязана лежать внутри cwd клона, иначе сессия и IDE её не видят.
Развилка: `.devkit` в дереве как хранилище под глобальным ignore (git clean
-xdf сносит доску, нужен обязательный пуш в личный remote, файлы едут в
архивы сборки, доводы DK-074 против) или `.devkit` как симлинк на
`<контур>-local/<проект>`, где боковая директория одна на контур со своим git
и remote (в дереве только ссылка, `git clean` сносит ссылку, чинит
`doctor --fix`). Предпочтение за симлинком. Проверить на живом VS Code: идёт
ли поиск через симлинк в папку под `info/exclude`, и не спасает ли тут
`.devkit/.gitignore` внутри цели вместо строки exclude; видит ли панель git
репозиторий боковой директории через симлинк. `devkitctl corp` тогда получает
`--local <путь>` с умолчанием на общую директорию контура, `findRoot` и
восстановление по соседним `*-local` пересматриваются.

Проверено 2026-08-29 на временных репозиториях, ripgrep 14 с `--hidden
--follow`, как зовёт его VS Code. Симлинк безопасен. `git add .` кладёт в
индекс только ссылку (mode 120000), содержимое боковой папки не утекает.
`git clean -xdf` сносит саму ссылку, файлы за ней целы. Но ripgrep и git
читают одни источники игнора (`info/exclude`, глобальный `excludesFile`,
`.gitignore` по пути обхода). Что прячет ссылку от git, то прячет её и от
поиска. Нынешняя строка `.devkit` в exclude и делает `.devkit/local`
невидимым поиску. Вложенный репозиторий вместо ссылки для поиска не лучше, а
с `git add .` и `clean` хуже (gitlink, отказ без коммита). Выходов два.
Первый, ссылка не игнорируется, в статусе клона висит `?? .devkit`, а от
случайного `git add .` стережёт `pre-commit` обёртка, проверка «обвязка в
корп-индексе» там уже есть. Второй, ссылка под exclude, а у коллег
`search.useIgnoreFiles=false`. Предпочтение за первым, правда в одном месте
и настройки редактора не трогаем.

## DoD

- `devkitctl corp` берёт путь боковой директории флагом `--local <путь>`; без
  флага путь общий на контур, `../<контур>-local/<проект>`, и скелет доски
  ложится подкаталогом в уже существующий репозиторий контура, а не заводит
  свой `git init`. Прежние клоны с `../<проект>-local` работают как раньше.
- В клоне лежит ссылка `.devkit -> <боковая>/<проект>` (доска, `docs/tasks/`,
  `.devkit/*.local` за ней), а строки `.devkit` в `.git/info/exclude` нет:
  поиск VS Code и сессия Claude из клона видят `.devkit/docs/TASKS.md`.
- `pre-commit` обёртка корп-клона отбивает коммит, в чьём индексе оказалась
  ссылка `.devkit` или тонкий файл контекста, и говорит, чем снять.
- `findRoot` утилит и восстановление по соседним `*-local` работают при общей
  директории контура; `doctor` видит пропавшую ссылку и чинит `--fix`.
- Проверка на временном клоне: `git add . && git commit` отбит хуком,
  `git clean -xdf` сносит ссылку, `doctor --fix` её возвращает, `rg --hidden
  --follow` из клона находит текст доски. Тесты на каждое из этого.
- CONNECT.md и README devkitctl описывают одно окно на проект и одну
  директорию на контур; в LLD DK-074 раздел отличий получает запись, почему
  ссылка в дереве и без exclude.
- Приёмка смешанная, барьер «глаза»: панель git VS Code и вид одного окна
  с доской в проводнике смотрит пользователь на живом корп-клоне.

## Сценарий проверки

Агентская часть гоняется на временном клоне под подставным HOME. Живые контуры
машины она не трогает. `$SC` это пустая временная директория.

```bash
export HOME=$SC/home
mkdir -p $SC/home $SC/projects && cd $SC/projects
git init -q corp-demo && cd corp-demo
git config user.name t && git config user.email t@t
echo readme > readme.md && git add . && git commit -qm init
devkitctl corp -C $SC/projects/corp-demo --prefix CD --contour acme
```

Ожидание: доска легла в `$SC/projects/acme-local/corp-demo/docs/TASKS.md`, а
репозиторий заведён на `$SC/projects/acme-local`. У самого проекта своего `.git`
нет. В клоне лежит ссылка `.devkit -> ../acme-local/corp-demo`.

```bash
head -1 $SC/projects/corp-demo/.devkit/docs/TASKS.md
git -C $SC/projects/corp-demo status --short
rg --hidden --follow --files-with-matches "префикс CD" $SC/projects/corp-demo
```

Ожидание: первая строка доски `# corp-demo: задачи (префикс CD)`. Статус клона
это ровно одна строка `?? .devkit`. `rg` печатает
`.../corp-demo/.devkit/docs/TASKS.md`.

```bash
cd $SC/projects/corp-demo && echo note > note.md && git add . && git commit -m "chore: правка"
```

Ожидание: коммит отбит. В выводе стоят «обвязка devkit в индексе корп-коммита»,
`.devkit` и подсказка `git rm --cached .devkit`.

```bash
git -C $SC/projects/corp-demo reset -q
git -C $SC/projects/corp-demo clean -xdfq
devkitctl doctor -C $SC/projects/corp-demo
devkitctl doctor --fix -C $SC/projects/corp-demo
head -1 $SC/projects/corp-demo/.devkit/docs/TASKS.md
```

Ожидание: `reset` снял отбитую ссылку из индекса, иначе `clean` её не тронет; `clean` снёс ссылку и тонкий файл, а доска за ней цела. Доктор говорит «нет ссылки
.devkit -> ../acme-local/corp-demo в клоне». После `--fix` в выводе стоит
«починено: ссылка .devkit», и доска снова открывается из клона.

Пользовательская часть, барьер «глаза». На живом корп-клоне открыть его одним
окном VS Code и посмотреть три вещи. Доска видна в проводнике по пути
`.devkit/docs/TASKS.md`, поиск по окну её находит, а панель git показывает
репозиторий боковой директории через ссылку.

Агентская часть прогнана 2026-08-29 после выката поезда, на временном клоне
под подставным HOME: раскладка, доска, поиск, страж коммита, `clean` и
`doctor --fix` сошлись с ожиданием. Две находки прогона ушли черновиками:
`doctor --fix` под чужим HOME перехватывает launchd-метку дашборда машины,
а `rg --follow` через ссылку `.devkit/devkit` уходит в само дерево devkit.
Пользовательская часть ждёт взгляда на живом корп-клоне.
