# DK-585: Возврат закрытой задачи в работу: команда reopen и поля в архиве

## Что происходит

У `taskctl` нет команды возврата из архива. Закрыли по ошибке либо всплыло
продолжение того же предмета, и сделать с этим ничего нельзя. Строка лежит в
`docs/TASKS-archive.md`, файл в `docs/tasks/archive/`, а `move` отвечает «нет
на доске». Руками доску править запрещает правило.

Обход есть, и он не бесплатный. Заводится новая строка, в архивный файл идёт
приписка со ссылкой. История задачи рвётся надвое, ранг считается заново,
коммиты первой половины ищутся по старому ID.

Живой случай 2026-08-29. DK-574 закрылась утром, к обеду выяснилось, что
починка сделана наполовину и вывод в файле неверен. Пользователь предложил
вернуть строку в работу, вернуть оказалось нечем, завели DK-584.

Обход по одному случаю терпимый, а по доске в целом нет. Со стороны доски
задача выглядит закрытой, работа по её предмету идёт под другим ID, и
посчитать, сколько задач возвращалось в работу, нечем. Машинного следа возврата
не остаётся. То же и с прозрачностью, связь двух половин выражена только фразой в
тексте.

Машинного возврата не сделать и поверх нынешнего архива. В архивной строке
лежат только ID, заголовок, тип, P, дата закрытия и ссылка на файл. Разбивки
ранга, цены и вида приёмки там нет.

### Проверено грумингом

Прогон на временном репозитории с синтетической доской 2026-08-29. Закрытой
строке `move` и `set` отвечают «нет на доске», `show` находит её в архиве, файл
лежит в `tasks/archive/2026/`. Возврата нет ни одной командой.

Состав архивной строки сверен по `docs/TASKS-archive.md`. Колонок шесть, ранга,
цены и вида приёмки среди них нет.

Дублей нет ни на доске, ни в архиве, ни в накопителе. Обход через новую строку
применялся три раза на 359 закрытых. Это DK-016 после DK-015, DK-487 доводкой
DK-470 и DK-584 после DK-574.

## Чего хотим

Заводится `taskctl reopen <ID> --reason "..."`. Строка возвращается на доску,
файл задачи переезжает из `docs/tasks/archive/<год>/` обратно в `docs/tasks/`,
запись из архивной таблицы снимается. Архивная таблица дополняется колонками
ранга, цены и вида приёмки, и возврат восстанавливает метаданные машинно. Факт
возврата остаётся видимым отметкой в файле задачи и в машинном виде, по ней
считается статистика возвратов.

## Развилки

Развилки, которые снимаются по ходу работы. Куда возвращается строка, в Backlog
или в In progress; как выглядит машинная отметка возврата, по которой считается
статистика; что происходит с датой закрытия, когда задачу закроют второй раз;
что делать с 359 уже закрытыми строками старого формата; как быть, если ID уже
уехал в поезд выката и по нему стоит отметка smoke.

## DoD

- `taskctl reopen <ID> --reason "..."` возвращает закрытую задачу на доску:
  строка встаёт в выбранный статус со своими рангом, ценой и видом приёмки,
  файл задачи переезжает из архива обратно, запись из архивной таблицы
  снимается.
- В архивной таблице есть колонки ранга, цены и вида приёмки; строки старого
  формата читаются без падения, и сказано, что с ними делает возврат.
- Факт возврата виден машинно: отметка в файле задачи и её счёт в сводке, по
  которой считается статистика вернувшихся в работу.
- В отказе сказано, что делать: возврат чужого ID, повторный возврат, ID с
  незакрытой отметкой выката.
- Тесты по пирамиде `test-standard`, включая прогон на синтетической доске.
- `tools/taskctl/README.md` и правила доски описывают команду и новые колонки.

### Решения реализации 2026-11-05

- Возврат идёт в Backlog. Ранг пересчитывается по текущей доске после
  восстановления разбивки, поправок, цены и вида приёмки из архива.
- Три новые колонки дописываются после прежних шести. Шапка расширяется при
  следующем закрытии, старые строки остаются без переписывания. Для возврата
  старой строки обязательны проверенные `--rank`, `--size`, `--accept`.
- Возвраты отмечаются строками в «Ходе работы» с датой, причиной, прежним
  закрытием и `<!-- taskctl:reopen -->`. Их число доступно в `show/list --json`
  в поле `reopen_count`; `reopen stats --json` даёт число задач и событий.
- Повторное закрытие получает новую дату. Прежняя остаётся в записи возврата.
  Проверки, ревью, выкат, журнал и спутники сохраняются. При непроверенном выкате
  перед возвратом нужны сценарий проверки и `shipctl smoke`.
- До окна проверок тесты и сборки не запускались. Окно машины было занято
  отдельным ревью DK-993; выполнены только gofmt и git diff --check. Прогоны
  не ставились в очередь.
