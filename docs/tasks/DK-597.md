# DK-597: review resolve --push отказывает на ветке без upstream

## Что происходит

Коммит с правкой docs/tasks на ветке обязан уезжать в origin сразу, и
исполнитель зовёт taskctl review resolve --push. На свежей ветке без
upstream ключ дергает голый git push, тот отказывает «no upstream»,
хотя сама обязанность пуша внутри команды уже есть. Обход есть, глобальный
push.autoSetupRemote true, но ждать его у каждой машины нельзя.

Ветка задачи заводится свежей, upstream у неё нет ни у кого. Значит отказ ловит
не одна машина, а всякий ревьювер на всякой новой ветке. Коммиты ревью остаются
локальными, и на XR-230 они вылезли конфликтом ребейза на дословных копиях.

## Чего хотим

Ключу достаточно звать push с установкой upstream (git push -u origin
HEAD или autoSetupRemote на время вызова).

## Развилки

Ставит ли команда upstream молча или говорит об этом строкой вывода.
- «Голос установки upstream»: Ставит ли команда upstream молча или говорит об этом строкой вывода
  - решает: исполнитель
  - рекомендация: говорить строкой: вывод и так печатает «запушено», а установка upstream меняет конфигурацию ветки, и молчаливая правка снаружи неотличима от обычного пуша
  - вариант: молча
  - вариант: строкой вывода
  - оставлена агентом 2026-09-17: строкой вывода: суффикс команды и так называет пуш, а поставленный upstream это правка конфигурации ветки, и о ней надо сказать
  - решено агентом 2026-09-17: строкой вывода: суффикс пуша дописывается словами «upstream поставлен», молчаливая правка конфигурации ветки снаружи неотличима от обычного пуша

## DoD

- `taskctl review resolve --push` и `review add --push` на свежей ветке без
  upstream проходят и ставят его сами.
- Тот же ход у остальных команд taskctl с `--push`, зовущих голый `git push`.
- Тест на временном репозитории с bare-origin. Ветка без upstream, вызов с
  `--push`, коммит в origin и upstream на месте.

## Ранг

`25+5+1+5+2 = 38`, P2.

- Серьёзность 25: трение с дешёвым обходом, `git push -u` руками один раз.
- Ценность 5: ревью в ветке идёт регулярно, а отказ ловится на первой же
  записи.
- Неопределённость 1: место правки и ход известны.
- Баг 5: команда обязана пушить и не пушит.
- Рычаг 2: расшивает свой поток ревью.

## Ход работы

- Из черновика DK-597 «review resolve --push не ставит upstream ветке и отказывает в пуш»: записан 2026-08-29, оформлен 2026-09-01.
- Актуальность проверена чтением кода 2026-09-01. `CommitOpts.apply`
  (`tools/taskctl/ops.go:274`) зовёт `git push` без ключей, upstream не ставит
  никто.
- Черновик DK-593 приписан сюда же: у ревьювера на ветке отбивался ручной пуш
  доски, и разбор упирается в тот же путь.
- Разработка: субагент opus/medium по вердикту pick (маппинг sonnet, корректор: профицит week_all, week_max; квота: week_all 28% профицит, week_max 44% профицит, снимок 16м назад), 2026-09-17 00:27-02:27.
- Правка легла одним местом. `CommitOpts.apply` зовёт `pushCommit`, тот смотрит
  upstream ветки и на свежей ветке пушит `git push -u origin HEAD`. Хвост
  сообщения команды дописывается словами «upstream ветки поставлен». На
  отделённой голове ставить нечего, там остаётся прежний пуш со своим отказом.
- Ключ `--push` у остальных команд taskctl идёт через ту же `apply`, отдельной
  правки им не понадобилось.
- Тесты легли в `tools/taskctl/commit_test.go`. Свежая ветка без upstream
  проходит и ставит его, ветке с готовым upstream достаётся прежний пуш. Краснота на
  старом коде проверена `regcheck`.

## Сценарий проверки

Агентский. Шаги гоняются из корня дерева, боевой origin не трогается, а пуш
идёт во временный bare-репозиторий. Каждый шаг идёт одной строкой: переменные
и heredoc между шагами обкатки не живут.

1. Старый код на тесте краснеет, новый проходит. Правка уже в main, поэтому
   старый код называется коммитом до неё, а тестовый файл ключом `--tests`:
   изменённых относительно main тестов автопоиск уже не видит.

```sh
regcheck -C tools/taskctl --base e201e1db~1 --tests tools/taskctl/commit_test.go -- go test -count=1 -run 'TestPushSetsUpstreamOnFreshBranch|TestPushKeepsExistingUpstream' .
```

Ждём строку «тест краснеет на e201e1db~1 и проходит на текущем коде, регрессия
закрыта».

2. Живой `review add --push` на свежей ветке без upstream. Во временном
   репозитории с bare-origin команда пушит коммит замечания, ставит upstream
   сама и говорит об этом хвостом вывода. `taskctl` шаг берёт из PATH, туда
   обкатка кладёт утилиты проверяемого дерева. Временный каталог уносит ловушка
   на выходе, и код возврата она не съедает.

#### Ситуация

На прогоне XR-230 ревьювер не мог пушить ветку: правило говорит «доска пушится сразу», а хук требует DEVKIT_PUSH_OK=1. Нужен разбор: пропускать пуш ветки задачи, когда в диффе только docs/tasks/, тем же рубежом, что и main.
