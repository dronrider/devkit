# DK-602: Мелочь в main без пуша запирает пуш доски всем сессиям

## Что происходит

Правило доски пускает однокоммитный багфикс с тестом прямо в main. Такая мелочь
уедет попутно со следующим выкатом. Хук pre-push пропускает пуш из сессии агента
только по чистому диапазону origin/main..main, где одна доска и никакого кода.

Доработка DK-584 в фазе Check легла в main коммитом f2f719a5 (7 файлов, 141
строка), доска следом закоммичена руками без --push. С этого момента каждый пуш
доски из любой сессии отбит. Мои чистые коммиты DK-428 ехали в одном диапазоне
с чужим кодом и ушли только через DEVKIT_PUSH_OK=1 руками. В автономном цикле
цели это стоп конвейера. Доска копится локально, сосед уходит вперёд, первый
пуш кончается конфликтом. При этом taskctl set -m --push с любым изменением
строки унёс бы тот же код без вопросов. Рубеж стережёт форму команды, содержимое
диапазона ему безразлично.

## Чего хотим

Два хода. Первый: мелочь коммитится и пушится одним движением командой shipctl
push, которая пропускает диапазон, где каждый код-коммит несёт ID задачи не из
Backlog; хук pre-push проверяет тот же критерий и голый код без ID отбивает
по-старому. Второй: taskctl lint или devkitctl doctor печатает находку «main
впереди origin на N коммитов с кодом» с именем коммита.

## Развилки

Как мелочь в main перестаёт запирать пуш доски и как это видно до отказа пуша.

## DoD

- Мелочь, легшая в main, пуш доски не запирает. Из сессии агента пуш чистого
  коммита доски проходит и при коде впереди origin.
- Голый код без ID задачи рубеж отбивает по-старому, тест на это есть.
- Отставание main от origin видно до отказа пуша. Находку печатает
  `taskctl lint` или `devkitctl doctor` с именем коммита.
- Тесты на временном репозитории с bare-origin: смешанный диапазон, чистая
  доска, голый код.

## Ранг

`50+7+2+0+3 = 62`, P1.

- Серьёзность 50: автономный цикл встаёт на человека, доска копится локально.
  Обход есть, но ручной, через DEVKIT_PUSH_OK.
- Ценность 7: пуш доски идёт у каждой сессии по десятку раз за заход.
- Неопределённость 2: гипотеза выбрала подход, открыты место критерия и форма
  находки.
- Баг 0: рубеж работает как задуман, случай стыка двух правил не разобран.
- Рычаг 3: расшивает пуш всем параллельным сессиям сразу.

## Сценарий проверки

Приёмка агентская. Критерий проверяется машиной агента на временном
bare-origin репозитории. Ни один из шести барьеров ACCEPTANCE.md к сценарию
не относится. Первый шаг воспроизводит исходную поломку. Пуш чистого коммита
доски отбивается, когда в диапазоне origin/main..main лежит код-коммит без
легитимного ID задачи. Второй шаг доказывает почин тем же способом. Тот же
код с легитимным ID (не из Backlog) диапазон пропускает.

1. Собрать `shipctl` из этого же коммита и завести сцену: рабочий репозиторий
   с доской (задача `DK-900` в In progress, чтобы её ID был легитимным не из
   Backlog), bare-origin и синхронизированный с ним main.

   ```sh
   rm -rf dk602scn && mkdir -p dk602scn/bin
   GOWORK=off go -C tools/shipctl build -o "$(pwd)/dk602scn/bin/shipctl" .
   mkdir -p dk602scn/board/docs/tasks
   git init -q -b main dk602scn/board
   git -C dk602scn/board config user.email t@t
   git -C dk602scn/board config user.name t
   printf '# devkit: задачи (префикс DK)\n\n## In progress\n\n| ID | Задача | Тип | P | R | Ссылка |\n|--------|--------|-----|---|---|--------|\n| DK-900 | Заготовка сценария DK-602 | task | P3 | 10 (0+5+0+0+5) | - |\n\n## Check\n\nНет.\n\n## Backlog\n\nНет.\n\n## Blocked\n\nНет.\n' > dk602scn/board/docs/TASKS.md
   git -C dk602scn/board add -A
   git -C dk602scn/board commit -qm init
   git init -q --bare dk602scn/origin.git
   git -C dk602scn/board remote add origin "$(pwd)/dk602scn/origin.git"
   git -C dk602scn/board push -qu origin main
   ```

   Итог: `git -C dk602scn/board rev-parse main` и `git -C dk602scn/board
   rev-parse origin/main` совпадают, сцена синхронизирована.

2. Воспроизвести поломку: код-коммит без ID задачи в subject, затем чистый
   коммит доски поверх него. Диапазон проверяется тем же критерием, каким
   `hooks/pre-push` зовёт `shipctl push --check-only`.

   ```sh
   printf 'правка без ID\n' > dk602scn/board/no_id.txt
   git -C dk602scn/board add -A
   git -C dk602scn/board commit -qm 'правка без ID задачи'
   printf '\n<!-- ход -->\n' >> dk602scn/board/docs/TASKS.md
   git -C dk602scn/board add -A
   git -C dk602scn/board commit -qm 'docs(tasks): DK-900 ход'
   dk602scn/bin/shipctl -C dk602scn/board push --check-only "$(git -C dk602scn/board rev-parse origin/main)" "$(git -C dk602scn/board rev-parse main)"; echo "код отказа: $?"
   ```

   Ожидание: команда пишет в stderr отказ со строкой «без ID задачи» и
   печатает «код отказа: 1». Пуш чистого коммита доски заперт код-коммитом
   без ID. Это та же поломка, что была в main до DK-602. На старом
   цельнодиапазонном `pre-push` этот же диапазон тоже отбился бы. Здесь это
   ожидаемое поведение, не регрессия.

3. Доказать почин: откатить сцену к origin/main и повторить тот же диапазон,
   но код-коммит несёт легитимный ID (`DK-900`, не из Backlog).

   ```sh
   git -C dk602scn/board reset -q --hard origin/main
   printf 'правка с ID\n' > dk602scn/board/with_id.txt
   git -C dk602scn/board add -A
   git -C dk602scn/board commit -qm 'fix: DK-900 мелкая правка мимо ship'
   printf '\n<!-- ход -->\n' >> dk602scn/board/docs/TASKS.md
   git -C dk602scn/board add -A
   git -C dk602scn/board commit -qm 'docs(tasks): DK-900 ход после правки'
   dk602scn/bin/shipctl -C dk602scn/board push --check-only "$(git -C dk602scn/board rev-parse origin/main)" "$(git -C dk602scn/board rev-parse main)"; echo "код выхода: $?"
   ```

   Ожидание: команда печатает «диапазон ...пропущен: доска либо код с ID
   задачи не из Backlog» и «код выхода: 0». Тот же по форме диапазон (код и
   доска поверх), но с легитимным ID, проходит. Мелочь, слитая в main мимо
   `ship`/`merge`, больше не запирает пуш доски.

4. Прогнать регрессионные тесты пакета:

   ```sh
   GOWORK=off go -C tools/shipctl test .
   ```

   Ожидание: `ok  	github.com/dronrider/devkit/tools/shipctl`.
