# DK-603: regcheck засчитывает падение сборки базы как красноту теста

## Что происходит

Базовый прогон под --inline переносит в копию main только тестовую часть
файла. Новые тесты зовут продакшн-символы, которых в базе нет (новая функция,
импорт, изменившаяся арность). База с новыми тестами не собирается с ошибками
E0425, E0433, E0061. regcheck засчитывает это как «тест краснеет на main» и
отчитывается успехом. На прогоне XR-202 так прошли ворота, и только ревьювер
своим прогоном выяснило, что один из двух новых тестов зелёный на старом коде:
ложная краснота заменила собой проверку.

### Разбор 2026-09-16

Актуальность: предмет на месте. Второй прогон в `tools/regcheck/check.go`
судит исход одним значением ошибки exec, то есть кодом выхода. Любой
ненулевой код печатается как «тест краснеет на базе». Разбора вывода
компилятора там нет. README в абзаце «Дописывание тестовой части в
конец базового файла» это признаёт и предлагает смотреть глазами. Правок
regcheck после записи черновика две, обе по DK-968 про временные деревья.
Исхода прогона они не касаются. Теста на падение сборки в `check_test.go` нет, все сценарии
гоняют `sh probe_test.sh` и grep.

Дыра не только у `--inline`. Тест, перенесённый флагом `--tests` целиком, тоже
зовёт новые символы и роняет сборку базы тем же исходом.

Дубли: на доске и в архиве строки с этим предметом нет. В накопителе лежат
DK-591 и DK-607. У первого команда тестов не нашлась в PATH, и пустой вывод
сошёл за красноту. У второго присваивание среды после `--` ушло в exec, и
команда не запустилась. Корень у трёх черновиков один. regcheck читает исход
прогона одним кодом выхода и не различает «тест упал», «не собралось» и «не
запустилось».

Стыки: `shipctl merge` (advice.go, regcheckGate) читает журнал `.devkit/log`.
Зелёным он считает только код 0. Отказ regcheck и сегодня выходит ненулевым
кодом, третий исход «не доказано» контракт ворот не меняет.

Второй вариант гипотезы (переносить на базу новые продакшн-символы) не
проходит. Инструменту пришлось бы отличать новое объявление от исправленной
логики в произвольном языке. Логику regcheck обязан оставить старой, а единого
критерия под такое разделение нет.

Условия: доступов, секретов, невозвратных шагов и чужих команд не нашла.
Компилятор в тесте не нужен. Сборку моделирует скрипт-заглушка с выводом
`error[E0425]` и кодом выхода 101.

## Чего хотим

Падение сборки базы должно считаться неубедительным исходом (отказ ворот).
Другой путь: regcheck переносит на базу и новые продакшн-символы, на которые
ссылаются тесты.

## DoD

- Базовый прогон, который не собрался или не запустился, regcheck не
  засчитывает краснотой. Утилита отказывает ненулевым кодом и называет
  причину: сборка или запуск. Рядом выжимка вывода и подсказка, что делать
  дальше. Выходов два: тест без новых символов либо запись в файле задачи,
  что regcheck здесь не применим. Так же отказ выходит у теста, перенесённого
  флагом `--tests` целиком, когда он роняет сборку базы.
- Тесты в `check_test.go` с заглушкой компилятора покрывают четыре кейса из
  развилки «кейсы». Тест на падение сборки падает на старом коде и проходит на
  новом. На старом коде утилита отчитывалась успехом.
- Коммит README с ветки `dk-603-readme` едет в задачу: «тестовый регион» в
  README стал «тестовой частью» файла.
- README: абзац «смотреть глазами» заменён описанием отказа и его причин.

## Сценарий проверки

Компилятор шагам не нужен. Сборку изображает скрипт-заглушка под именем
`cargo`. Без `fn helper` в `lib.rs` он печатает `error[E0425]` и выходит
со 101, с helper гоняет проверку и печатает итог `cargo test`. Каждая
строка блока это отдельный шаг обкатки, поэтому шаги начинаются с `cd`.

1. Синтетический репозиторий, тест зовёт функцию, которой в базе нет. Ожидание:
   код выхода 1, в выводе «не собралась», «error[E0425]» и подсказка про
   файл задачи. На старом коде тут печаталось «тест краснеет».

```sh
rm -rf "$HOME/dk603" && mkdir -p "$HOME/dk603/tests"
cd "$HOME/dk603" && git init -q -b main && git config user.email t@t && git config user.name t
cd "$HOME/dk603" && printf '#!/bin/sh\nif ! grep -q "fn helper" lib.rs; then echo "error[E0425]: cannot find function helper in this scope"; echo "error: could not compile probe (lib test) due to 1 previous error"; exit 101; fi\nif grep -q fixed lib.rs; then echo "test result: ok. 1 passed; 0 failed"; exit 0; fi\necho "test result: FAILED. 0 passed; 1 failed"; exit 101\n' > cargo && chmod +x cargo
cd "$HOME/dk603" && printf 'const CODE: &str = "bug";\n' > lib.rs && git add lib.rs && DEVKIT_NO_TESTS=1 git commit -qm seed
cd "$HOME/dk603" && printf 'const CODE: &str = "fixed";\nfn helper() {}\n\n#[cfg(test)]\nmod tests {\n    // helper()\n}\n' > lib.rs
cd "$HOME/dk603" && ! regcheck --inline lib.rs -- "$HOME/dk603/cargo" test && echo "отказ, код выхода 1"
```

2. Тот же репозиторий, helper уже есть в базе, тест на базе краснеет по-настоящему.
   Ожидание: «тест краснеет на HEAD», код выхода 0.

```sh
cd "$HOME/dk603" && printf 'const CODE: &str = "bug";\nfn helper() {}\n' > lib.rs && DEVKIT_NO_TESTS=1 git commit -qam helper
cd "$HOME/dk603" && printf 'const CODE: &str = "fixed";\nfn helper() {}\n\n#[cfg(test)]\nmod tests {\n    // helper()\n}\n' > lib.rs
cd "$HOME/dk603" && regcheck --inline lib.rs -- "$HOME/dk603/cargo" test
```

3. Тест перенесён флагом `--tests` целиком и зовёт helper, которого в базе нет.
   Ожидание: тот же отказ «не собралась», код выхода 1.

```sh
cd "$HOME/dk603" && git reset -q --hard HEAD~1 && printf 'const CODE: &str = "fixed";\nfn helper() {}\n' > lib.rs && printf '// helper()\n' > tests/probe.rs
cd "$HOME/dk603" && ! regcheck --tests tests/probe.rs -- "$HOME/dk603/cargo" test && echo "отказ, код выхода 1"
```
