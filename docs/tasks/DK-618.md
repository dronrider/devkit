# DK-618: Корпус прозы: поля «форма» и «тип» у фрагмента, ключ sample --form, формат блока

## Что происходит

Решение 3 LLD DK-606 (`docs/lld/DK-606-prose-structure.md`): у фрагмента поля «форма» (абзацы, список, таблица, шаги) и «тип», ключ `sample --form`, формулировка «Формата корпуса» сужена до блока без подзаголовков внутри, `HEAD_RE` не меняется. Тесты prose_test.py по видам источника остаются.

## Чего хотим

У фрагмента корпуса заводятся два поля. «Форма» описывает, чем блок стоит на
странице. Значений у неё четыре, это абзацы, список, таблица и шаги. Фрагмент
без поля читается абзацами, и 66 стоящих фрагментов остаются как есть. В «типе»
стоит слово пользователя о документе, словарь у него открытый.

Выборка получает ключ `--form`. Первым в наборе едет фрагмент названной формы,
остальные идут без фильтра. Формы, которой в корпусе нет, в наборе не
появляется. Про пропажу печатается строка в поток ошибок, а набор отдаётся
обычный. Шапкой фрагмента едут источник, тип, форма, роль и пометка.

«Формат корпуса» в скилле описывает теперь блок целиком. Слова «один или два
абзаца» оттуда ушли, подзаголовка в теле фрагмента не бывает. Раздел «Правка
готового текста» отсылал к отбору фрагмента глазами, теперь там стоит ключ.

## DoD

- `sample --genre readme --form список` ставит фрагмент этой формы первым, а
  когда такого фрагмента нет, печатает причину и отдаёт набор.
- Сторож корпуса проверяет три вещи. Форма из четырёх значений, тип у
  структурного фрагмента, тело без подзаголовков.
- `check-skills.py` краснеет, когда ключ формы пропал из текста скилла.

## Ранг

36 (25+6+1+0+2, S+2), P2.

- Серьёзность 25. Снесённую структуру страницы человек ловит глазами, обход
  дешёвый, правка откатывается.
- Ценность 6. Правка долгоживущего текста идёт каждый день.
- Неопределённость 1. В решении LLD названы формат, значения и ключ целиком.
- Поправка на баг 0. Задача не чинит регресс.
- Рычаг 2. Механика своего потока по одной теме.

## Сценарий проверки

Шаги гоняются из корня дерева. Первый берёт тесты корпуса, там разбор полей,
порядок набора по форме и сторож самого корпуса. Второй смотрит сторожа
скиллов, ключ формы обязан стоять в тексте `prose`. Третий кладёт во временный
корпус два фрагмента, таблицу и абзац, и берёт выборку по форме. Таблица едет
первой, а шапка везёт тип и форму. Четвёртый зовёт форму, которой в живом
корпусе нет, и на ней видно строку про пропажу в потоке ошибок.

```sh
python3 -m unittest discover -s kit/skills/prose -p prose_test.py -q
python3 kit/skills/check-skills.py
d=$(mktemp -d) && printf '# вход README\n\n## 1\nисточник: трекер, issues/1\nтип: справочник флагов\nформа: таблица\n\n| Ключ | Что делает |\n|---|---|\n| раз | первое |\n| два | второе |\n\n## 2\nисточник: трекер, issues/2\n\nОбычный абзац эталона, он лежит в корпусе без поля формы и читается абзацами.\n' > "$d/readme.md" && python3 kit/skills/prose/prose.py sample --corpus "$d" --form таблица --count 2 --seed 1
python3 kit/skills/prose/prose.py sample --genre task --form таблица --count 1 --seed 1
```

Ожидание: первый шаг печатает `OK`, второй `ok: скиллы, проверено 18`. Третий
печатает первым фрагмент с `тип: справочник флагов` и `форма: таблица`, вторым
абзацный. Четвёртый печатает в поток ошибок `формы «таблица» в корпусе нет у
жанра task, набор идёт без неё` и следом обычный фрагмент.
