# DK-629: README дашборда сверен с веткой, вычитан, вход новичка собран

## Что происходит

`tools/dashboard/README.md` прибавил в ветке POC цели DK-397 1090 строк и
потерял 109. Писалось это режимом POC, где вычитка отложена вместе с ревью.
Дока в дереве есть, а через `proofread` она не проходила ни разу.

Сверка с кодом тоже не делалась. Ручки, которых в README не нашлось: say,
status, shot, model, drop, login и wait, pulse, continue, goals и tasks. Часть
из них человек зовёт руками с чужой машины, и без описания у него остаётся
чтение исходников.

Вход новичка на этой странице разложен так же, как до POC. Черновик DK-423
описал беду ещё 2026-08-17. Первый запуск раскидан по четырём далёким разделам,
а первым идёт таблица флагов. Ядро правил ставит первый запуск шагами и
примерами раньше устройства.

## Чего хотим

README дашборда описывает то, что лежит в коде после слияния ветки. Первый
запуск собран одним разделом в начале страницы, шагами и примерами. Текст
прошёл вычитку скиллом `proofread`.

## Границы

README других утилит сюда не входят. Перенос разделов в `docs/` тоже. Страница
остаётся одна, меняются её порядок и полнота. Новых функций задача не добавляет,
недостающая ручка описывается или заводится строкой.

## Развилки

- Что делать с ручкой, которой в коде нет, а в описании она нужна. Кандидаты
  это строка на доске и абзац «пока нет» в самой доке.
- Насколько подробен вход. Ориентир это разбор DK-421 про правило входа и уже
  переписанные входы соседних утилит.

## DoD

Каждая ручка сервера и каждый флаг запуска, живущие в коде после слияния, есть
в README. Первый запуск стоит одним разделом раньше устройства. Прогон
`hooks/check-prose.py` по странице не даёт находок блокирующего порога, след
вычитки записан в «Ход работы».
