# DK-643: Сценарий без выката обкатывается в чистом окружении до перевода в Check

Цель: [tasks/DK-161.md](tasks/DK-161.md)

## Что происходит

Сценарий, выполнимый без выката, сегодня обкатывается там же, где шла работа,
в прогретом чекауте с живыми HOME и PATH. Дефекты окружения из-за этого
всплывают после слияния. Стенд самопроверки DK-138 падал в свежем worktree,
а в прогретом был зелёным, и находилось это уже прогоном DoD.

## Чего хотим

Сценарий без выката обкатывается в чистом окружении до перевода в Check.
Команда обкатки гоняет шаги сценария в дереве и окружении DK-641, кладёт вывод
в раздел «Проверка» и ставит отметку, а `taskctl move check` без отметки
отказывает и называет команду. Гасится пометкой-исключением по образцу трёх
нынешних ворот слияния (`advice.go`).

Пункт DoD 3 цели DK-161, вторая половина. После DK-641, кирпич дерева и
окружения общий.

## Развилки

- Где живёт команда. Кирпичи чистого прогона лежали у `shipctl` (DK-641), файл
  задачи и ворота перевода в Check у `taskctl`. Команда встала в `taskctl`.
  Обкатка читает и пишет файл задачи, а разбор его формы и запись отметки у
  `taskctl` уже есть. Дереву с окружением всё равно, кто их зовёт. Кирпичи
  переехали в `internal/freshtree`, оттуда их берут обе утилиты.
- Откуда команда берёт шаги. Проза сценария командой не считается: в обратных
  кавычках там ходят пути, имена файлов и куски объяснения. Шаги берутся из
  ограждённых блоков раздела «Сценарий проверки», остальное называется ключом
  `--step`.
- Кого ворота спрашивают. Отметку требуют у агентского вида, там каждый шаг
  выполним с машины агента. У `mixed` и `user` часть шагов держит человек, и
  машинной отметки с них не спрашивают.

## DoD

1. Команда обкатки гоняет шаги сценария в свежем дереве и собранном окружении,
   вывод ложится в раздел «Проверка» файла задачи, отметка ставится машинно.
2. `taskctl move check` без отметки отказывает и называет команду, гасится
   пометкой-исключением по образцу нынешних ворот.
3. `regcheck` и `obeycheck` зелёные, у правки своя пирамида тестов, стенд по
   prompt-test для правленых текстов.

## Сценарий проверки

Агентский. Шаги гоняются в свежем дереве самой обкаткой, синтетическая доска
живёт во временном HOME.

```sh
cd tools/taskctl && GOWORK=off go build -o "$HOME/taskctl" .
mkdir -p "$HOME/board" && cd "$HOME/board" && git init -q -b main . && git config user.email t@t && git config user.name t && "$HOME/taskctl" init --prefix SC --here && "$HOME/taskctl" add --title "Проба ворот обкатки" --type task --rank "25+4+2+0+2" --accept agent --status in-progress && printf '# SC-001\n\n## Сценарий проверки\n\nАгентский, шаг печатает строку.\n' > docs/tasks/SC-001.md && git add -A && git commit -qm init
cd "$HOME/board" && out=$("$HOME/taskctl" move SC-001 check 2>&1); echo "$out"; case "$out" in *"taskctl rehearse SC-001"*) echo ворота-отказали-и-назвали-команду;; *) exit 1;; esac
cd "$HOME/board" && "$HOME/taskctl" rehearse SC-001 --step "echo проба-шага" && grep -q "^- Обкатка:" docs/tasks/SC-001.md && grep -q "проба-шага" docs/tasks/SC-001.md && echo отметка-и-вывод-на-месте
cd "$HOME/board" && "$HOME/taskctl" move SC-001 check && echo строка-уехала-в-check
cd "$HOME/board" && "$HOME/taskctl" add --title "Проба исключения" --type task --rank "25+4+2+0+2" --accept agent --status in-progress && printf '# SC-002\n\n## Сценарий проверки\n\nАгентский, шаги гоняются на проде.\n\n## Ход работы\n\n- Исключение: обкатка (проверка идёт на проде)\n' > docs/tasks/SC-002.md && "$HOME/taskctl" move SC-002 check && echo исключение-погасило-ворота
```

Ожидание: первый `move` отказывает и называет `taskctl rehearse SC-001`, после
обкатки в файле задачи стоят отметка и вывод шага, второй `move` проходит, а
строка с пометкой-исключением проходит без обкатки вовсе.
