# DK-664: Сторожок цели идёт с голым PATH launchd, и разлив очереди падает

## Что происходит

~/.devkit/goal-watch.log на 2026-08-31 циклически пишет «taskctl не найден в
PATH» по трём корням: devkit, it-road-course, xr-proxy.

Надзор крутится вхолостую: парковки и переходы цели никто не будит, и цель
стоит, пока в лог не заглянут руками. Молчание не отличить от штатной работы.

## Чего хотим

Сторож находит taskctl из любого окружения запуска, а падение такого рода
видно снаружи, не только в логе.

## Развилки

Откуда сторожу брать PATH: зашить каталог бинарей при установке или тянуть
профиль пользователя при запуске.

Решение: зашить. `doctor --fix` считает PATH агента по машине (наличием
каталогов) тем же сборщиком, что у дашборда, `dashboard.agent_path`, и кладёт
готовую строку в `EnvironmentVariables` plist. Профиль пользователя (`.zshrc`
и подобные) launchd не читает вовсе, у него своя, отдельная от логина среда
запуска: тянуть его смысла нет. Зашитый срез вместо живого PATH сессии не
плывёт от прогона к прогону, и `doctor --fix` не переписывает агента заново
на каждом вызове (тот же довод уже стоит в docstring `dashboard.agent_path`
про дашборд).

## DoD

Launchd-агент сторожка получает PATH тем же сборщиком, что агент дашборда, и
разлив очереди из-под него доходит до конца. Доктор считает агента без PATH
находкой и переписывает plist по `--fix`, как переписывает показывающего не
туда. Тест держит каталог бинарей в PATH агента, краснота сверена прогоном
regcheck. Снаружи это видно журналом сторожка. Строки про ненайденный taskctl
уходят, на их месте печатается отчёт разлива.

## Ранг

`50+8+1+5+4 = 68`, P1.

- Серьёзность 50: надзор цели крутится вхолостую, парковки и переходы никто не
  будит, а очередь слияния стоит часами; обход есть, но ручной, звать разлив и
  читать журнал глазами.
- Ценность 8: на этом сторожке держатся автономный цикл цели и разлив очереди,
  и сейчас он молчит про собственную бесполезность.
- Неопределённость 1: подход взят у соседнего агента, осталось позвать тот же
  сборщик PATH.
- Поправка на баг +5: сторожок работал, пока его дети не пошли за утилитами.
- Рычаг 4: чинится носитель автономного цикла, от него дешевеет каждая
  следующая цель и каждая пачка.

Цена S, это раздел в plist, вызов готового сборщика и тест рядом. Вид приёмки
агентский. Агент подделывает дом, зовёт проверку носителя и читает plist, ни
один из шести барьеров не назван.

## Сценарий проверки

Агентский. Окружение подставное. Временный HOME (`$SC/home`) и подставной
каталог бинарей с одним файлом `dashboard` (`$SC/bin`) стоят своей записью,
живой PATH и живой launchd мимо. Якорь именно `dashboard`, тот же, что и в
самой правке. Причина в «Ходе работы»: `taskctl` тесты доски подделывают в
PATH проекта, и якорь на нём разъезжался бы со стендом. `watch.check()`
зовётся напрямую с `home`, `which` и `call` из стенда. Настоящего
launchd-агента поднимать незачем. Он делит имя `ru.devkit.goal-watch` с
агентом живой машины, и трогать его опасно.

```sh
export SC=$(mktemp -d)
mkdir -p "$SC/home" "$SC/bin"
printf '#!/bin/sh\n' > "$SC/bin/dashboard"
chmod +x "$SC/bin/dashboard"
python3 - <<'PY'
import os
import subprocess
import sys

sys.path.insert(0, os.path.join(os.getcwd(), "tools", "devkitctl"))
import watch

sc = os.environ["SC"]
home = os.path.join(sc, "home")
bindir = os.path.join(sc, "bin")
binary = os.path.join(bindir, "dashboard")


class Fake:
    def __call__(self, argv, **kw):
        return subprocess.CompletedProcess(argv, 0, "", None)


which = lambda name: binary
plist = os.path.join(home, "Library", "LaunchAgents", "%s.plist" % watch.LABEL)

# Агент положен как обычно, --fix на чистом месте.
f0, d0 = watch.check(fix=True, home=home, platform="darwin", which=which, call=Fake())
assert f0 == [] and d0, (f0, d0)

# Имитация плиста, положенного до DK-664: тот же агент, но без PATH.
with open(plist, encoding="utf-8") as fh:
    text = fh.read()
head, tail = text.split("  <key>EnvironmentVariables</key>\n", 1)
old = head + tail.split("  </dict>\n", 1)[1]
assert "<key>PATH</key>" not in old
with open(plist, "w", encoding="utf-8") as fh:
    fh.write(old)

# Шаг 1 (исходный баг DK-664): агент без PATH это находка доктора.
f1, d1 = watch.check(fix=False, home=home, platform="darwin", which=which, call=Fake())
print("находка:", f1)
assert len(f1) == 1 and "doctor --fix" in f1[0], f1

# Шаг 2: --fix переписывает plist, PATH снова несёт каталог бинарей.
f2, d2 = watch.check(fix=True, home=home, platform="darwin", which=which, call=Fake())
print("починено:", d2)
with open(plist, encoding="utf-8") as fh:
    text = fh.read()
has_env = "<key>EnvironmentVariables</key>" in text
has_path = ("<key>PATH</key><string>%s" % bindir) in text
print("EnvironmentVariables:", has_env, "PATH держит каталог бинарей:", has_path)
assert has_env and has_path

# Шаг 3: тем PATH, что теперь несёт plist, ребёнок тика находит shipctl, а
# разлив очереди не падает на «не найден в PATH» (DK-664).
agent_path = text.split("<key>PATH</key><string>", 1)[1].split("</string>", 1)[0]
os.environ["PATH"] = agent_path
open(os.path.join(bindir, "shipctl"), "w").close()
os.chmod(os.path.join(bindir, "shipctl"), 0o755)
found = watch.devkit_bin("shipctl")
print("shipctl из PATH plist-а:", found)
assert found == os.path.join(bindir, "shipctl"), found
PY
rm -rf "$SC"
```

Шаг 1 печатает `находка: [...]` со строкой, в которой стоит `doctor --fix`.
Старый plist без PATH это находка. Шаг 2 печатает `починено: [...]` с
непустым списком. Следом идёт строка `EnvironmentVariables: True PATH держит
каталог бинарей: True`. После `--fix` PATH снова несёт `$SC/bin`, каталог
подставных бинарей. Шаг 3 печатает `shipctl из PATH plist-а: .../bin/shipctl`,
путь до подставного файла. Ребёнок тика находит его тем PATH, что несёт
починенный plist, без разбора «shipctl нет ни в PATH». Код выхода нулевой,
`assert` в скрипте не сорвался ни разу.
