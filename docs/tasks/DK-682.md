# DK-682: Сводка tally слепа к архиву и читает чужие ID из прозы раздела

Цель: [tasks/DK-161.md](tasks/DK-161.md)

## Что происходит

Прогон DoD цели DK-161 позвал `agentctl tally --goal docs/tasks/DK-161.md` и
получил пустую сводку. Задачи цели закрыты, их файлы лежат в
`docs/tasks/archive/2026/`, а tally ищет только в `docs/tasks/` и говорит
«файла задачи нет: DK-641, DK-642, ...». Заодно в состав попали ID из прозы
раздела «Задачи цели» (DK-092, DK-503, DK-516, DK-158, DK-117, SC-001):
парсер собирает все упоминания, а не строки состава. Итог закрытой цели из-за
этого не называет, где время ушло, хотя записи этапов в архивных файлах есть.

## Чего хотим

`tally` находит файлы закрытых задач в архиве (глобом
`docs/tasks/archive/<год>/<ID>.md`, тем же путём, что уже считает `taskctl`
для закрытой задачи) и считает их этапы. Состав цели `tally` берёт из строк
состава раздела: пункта «- кандидат N, DK-NNN ...», которым виток нарезки
заводит строку доски, и вводного перечисления материализации «DK-NNN
(кандидат N), ...». Строку узнаёт метка «(кандидат N)» рядом с ID: в пункте
она стоит сразу после «кандидат N,», в перечислении сразу перед скобкой.
Прозаические упоминания и сверки этой меткой не отмечены, и в состав не
попадают. Сводка живой цели DK-161 после фикса называет времена по видам.

## DoD

1. На цели с закрытыми задачами tally печатает разбивку по видам с ненулевыми
   временами, хвост «файла задачи нет» пуст для задач из архива.
2. ID из прозы раздела (упоминания в скобках и сверках) в состав не попадают.
3. regcheck подтверждает красноту регрессионного теста, go test agentctl
   зелёный.

## Ранг

- Серьёзность 25: итог закрытой цели без времени, разбор «куда ушёл день»
  снова невозможен, работе цикла это не мешает.
- Ценность 6: та же ценность, что у DK-644, довершение до живого случая.
- Неопределённость 1: место известно, поиск в архиве есть у taskctl show.
- Баг +5: дефект найден прогоном DoD.
- Рычаг 2: вход DK-145 (прогресс цели).
