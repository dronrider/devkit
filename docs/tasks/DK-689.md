# DK-689: README taskctl не говорит, что обкатка режет блок сценария построчно

## Что происходит

Раздел про `rehearse` в README taskctl читается так, будто в блок `sh` кладут
скрипт: там сказано «шаги берутся из блоков раздела», а про то, что блок
режется по строкам, не сказано нигде. На деле `scenarioSteps` в
`tools/taskctl/rehearse.go` берёт шагом каждую непустую строку блока и гоняет
её своим прогоном в свежем дереве. Скрипт из десяти строк превращается в
десять шагов, переменные между ними не живут, и обкатка краснеет на пустом
месте.

Найдено на DK-471: сценарий из двух многострочных блоков дал 22 шага и 11
красных, а понять причину получилось только чтением `rehearse.go`.

## Чего хотим

Читатель README знает про построчную нарезку до первого прогона, а не после
красной обкатки.

## DoD

Абзац про `rehearse` в `tools/taskctl/README.md` говорит, что шагом становится
каждая непустая строка блока, а многострочный скрипт надо сводить в одну
строку. Рядом стоит рабочий пример строки со сборкой бинаря и песочной доской.
Отказ команды при красном прогоне называет число шагов, и по числу видно
нарезку, это стоит упомянуть.

## Ранг

`25+3+0+5+1 = 34`, P2.

- Серьёзность 25: заметное трение, обход есть (прочитать код), но нашли его
  тремя красными прогонами.
- Ценность 3: ждёт всякий, кто первый раз пишет сценарий с многошаговой
  командой.
- Неопределённость 0: правится дока, предмет назван.
- Поправка на баг 5: дока расходится с поведением.
- Рычаг 1: чужих задач не держит.
