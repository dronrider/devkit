# DK-690: Сторож прозы считает предложением строку команды в блоке кода

## Что происходит

`hooks/check-prose.py` меряет текст файла целиком, и строка команды внутри
ограждённого блока идёт у него за предложение. На DK-471 в файл задачи легла
однострочная команда обкатки из восьми звеньев через `&&`, и сторож выдал
«средняя длина предложения: 319,0 слов при пороге 23 (блокировка)», трижды на
трёх коммитах подряд. Прозы в этих коммитах было две фразы.

Такой замер не только шумит. Он прячет настоящую находку: цифры уезжают в
сотни, и по ним уже не видно, есть ли в тексте живой перекос.

## Чего хотим

Сторож меряет прозу и молчит про содержимое блоков кода.

## DoD

`hooks/check-prose.py` выкидывает из замера ограждённые блоки (три и больше
знака ` или ~, с языком и без) вместе с их содержимым. Тест на файл, где вся
длина набрана строкой команды в блоке: до правки сторож блокирует, после
молчит, краснота проверена `regcheck`. Поведение на обычной прозе не меняется,
это держит прежний набор тестов.

## Ранг

`25+3+0+5+1 = 34`, P2.

- Серьёзность 25: заметное трение, обход есть (пропустить предупреждение
  глазами), но оно приходит на каждый коммит с командой в тексте.
- Ценность 3: ждут все файлы задач со сценарием, где команда идёт одной
  строкой.
- Неопределённость 0: место названо, дизайн очевиден.
- Поправка на баг 5: сторож судит не то, что обещает.
- Рычаг 1: чужих задач не держит.
