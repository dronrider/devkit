# DK-719: Открытая форма черновика после груминга не становится формой задачи

## Что происходит

Сообщение пользователя 2026-09-02. В панели открыта форма черновика, и по
нему в этот момент идёт груминг. Груминг заводит строку доски, файл
переезжает из `docs/tasks/drafts/` в `docs/tasks/`. Ожидалось, что экран
сам перейдёт на форму заведённой задачи. Вышло иначе. Экран остаётся формой
черновика, поля пустеют, а в подписи стоит отказ «черновика DK-NNN в devkit
нет: файла не видно, грумминг мог уже завести по нему задачу». До формы
задачи человек добирается руками, через доску или правкой адреса.

Механика в асимметрии двух ручек. Ручка задачи знает про черновик. Когда
строки на доске нет, а файл в `drafts/` есть, сервер кладёт в отказ поле
`draft`, и экран задачи по нему уходит на форму черновика. Ручка черновика
(`handleDraft` в `tools/dashboard/drafts.go`) читает только файл в `drafts/`
и при его отсутствии отдаёт голый 404 с текстом. Доску она не спрашивает,
подсказки для перехода не даёт. Экран черновика (`renderDraft` в
`static/app.js`) отказ не разбирает и показывает текст как есть. Опрос
груминга держится, пока жива tmux-сессия груминга, и гаснет вместе с ней.
Проверка «файла черновика нет, а строка на доске есть» у сервера уже
написана. Ею закрывает разговор груминга `groomDone`, но ручке черновика
она не досталась.

## Чего хотим

Форма черновика, чей ID за время просмотра стал строкой доски, сама
переходит на форму этой задачи, как экран задачи уходит на черновик в
обратную сторону. Ручка черновика на пропавший файл сверяется с доской и
в отказе называет задачу. Экран черновика по этому слову меняет адрес и
перерисовывается формой задачи. Отказ с текстом остаётся только у ID,
которого нет ни в черновиках, ни на доске.

## DoD

Тест ручки. Черновика в `drafts/` нет, строка с тем же ID стоит на доске,
ответ несёт поле с ID задачи, симметрично `TestTaskOfDraftIDNamesDraft`.
Стенд экрана. Открытая форма черновика при таком ответе меняет адрес на
адрес задачи и рисует форму задачи, подписи с отказом нет. Тесты красные
на коде до правки и зелёные после, краснота проверена regcheck. Поведение
перехода вписано в `tools/dashboard/README.md` рядом с обратным переходом.

## Ранг

`25+4+1+5+2 = 37`, P2.

- Серьёзность 25. Экран показывает неверный отказ и теряет открытую запись.
  Обход дешёвый, задачу открывают с доски руками.
- Ценность 4. Груминг из формы черновика идёт каждый день, в накопителе
  больше сотни записей, и каждое оформление при открытой форме
  кончается этим отказом.
- Неопределённость 1. Причина названа, обратный переход уже написан и
  служит образцом.
- Поправка на баг 5. Сломанный переход, а не новое удобство.
- Рычаг 2. Своя польза по одной теме. Чинится стык экранов дашборда.

## Ход работы

- Сообщение пользователя 2026-09-02, строка заведена сразу, без черновика.

  Ручка черновика не сверяется с доской, экран черновика отказ не
  разбирает.
- Вычитка: 1 файл, 10 правок, 1 пометка, 2026-09-02.
