# DK-723: Разговор задачи в панели один, проходы складываются в него

## Что происходит

Правка DK-724 сузила предмет этой строки, и дальше речь только про остаток.
Конвейер задачи идёт одной живой сессией, проходы больше не плодят записей:
на непрерывный заход приходится одно окно и одна запись реестра. Вечер с
семью сессиями на DK-720 такой работой уже не повторяется.

Осталась склейка перезапусков. Остановы у живой головы прежние: потолок
проходов, воронка молчания, вышедший клиент, перезагрузка машины. После
каждого кнопка поднимает новую сессию со своим ID под тем же именем окна
task-<ID>, и в реестре снова копятся записи, теперь единицами вместо дюжины.
Список чатов ключует строку по ID сессии, chats.go правка DK-724 не трогала,
поэтому такие заходы по-прежнему видны отдельными строками с одинаковыми
заголовками.

Ниже исходная постановка, написанная до DK-724, она объясняет, откуда взялась
строка.

2026-09-02, DK-718 и DK-720. Конвейер задачи идёт проходами task-run.py.
Каждый проход это новый клиент со своим ID сессии. Реестр
~/.devkit/sessions.log за этот вечер держит по DK-720 семь сессий, по DK-718
три. Все они подняты под одним именем tmux, task-<ID>, с источником «заказ».
Список чатов дашборда собирается обходом транскриптов. На задачу приходится
столько строк, сколько было проходов, и заголовки у них одинаковые. Реплика
человека адресуется разговору task-DK-718 (DK-430.2), и берёт её только живой
проход.

Человек не знает, в какой чат заходить. Записи одной задачи не отличить друг
от друга по заголовку. Живая среди них одна, новейшая по времени, остальные
мёртвые. Работу по задаче не проследить в одном месте: вопрос агента, заданный
вторым проходом, лежит в одной записи, ответ третьего прохода в другой.
Историю приходится собирать по нескольким чатам. Когда проходы кончились, надо
ещё найти концы, чтобы продолжить работу. Чем длиннее задача, тем больше
мусора в списке.

## Чего хотим

В списке чатов у задачи одна запись. Лента её склеена из проходов подряд с
разделителем. Реплика человека уходит в живой проход, а когда проходы
кончились, работа продолжается из той же записи.

## Границы

Склеиваются проходы конвейера, то есть сессии с именем tmux `task-<ID>`
(ответ пользователя 2026-09-02). Разговор человека о задаче, поднятый с
дашборда именем `chat-<ID>-<n>`, остаётся своей строкой списка. В ленту
проходов он не втягивается. Кнопки строки задачи и чип этапа правит DK-716,
тут трогается список чатов и лента разговора.

Строка живёт до слияния DK-724. Та переводит конвейер на одну живую сессию, и
складывать тогда будет нечего. Проходов не станет. Снимается DK-723 по факту,
когда дорога доехала, а не по плану (ответ пользователя 2026-09-02).

## Развилки

Складывать записи по адресу разговора (tmux-имя task-<ID>) или по привязке к
задаче из реестра сессий. У цели лента одна и собирается из кусков ленты
сессий (DK-354.2), у задачи, видимо, тот же приём.

Закрыто исполнителем 2026-09-06.

- Ключ склейки это имя окна из реестра вместе с проектом. Привязка к задаче
  свела бы в одну строку конвейер, доводящий чат `chat-<ID>-<n>` и окно
  человека, а границы держат их врозь. Имя окна берётся целиком и не
  разбирается. Проект стоит в ключе рядом с именем, потому что имя
  переиспользуется между досками (живой случай `chat-DK-397-2`).
- Голова строки это заход, за которым закреплено имя. Мёртвый заход,
  говоривший последним, стоит в списке выше живого, и выбор по свежести отдал
  бы ему реплику человека.
- Прошлые заходы приклеиваются к ленте, доехавшей до начала своего
  транскрипта. Листание вверх само просит окно шире.
- Потолок склейки шесть заходов, столько же, сколько проходов держит
  конвейер. Дальше история открывается прошлым заходом по его ID.
- Слова про снятый разговор остаются. Имя окна занимает и живой клиент
  соседнего проекта, там склеивать нечего, а старый адрес прошлого захода
  панель переводит на голову.

## DoD

- В списке чатов у задачи одна строка на все проходы конвейера, а не строка на
  сессию; заголовок и время у неё от того захода, за которым закреплено имя
  окна. Свежесть головой не выбирается. Мёртвый заход говорит последним чаще
  живого, и строка ушла бы к нему вместе с репликой человека (правка по
  замечанию ревью 5).
- Лента этой строки склеена из транскриптов проходов по порядку, границы
  проходов видны разделителем. История задачи читается сверху вниз, без
  перехода в другой чат.
- Реплика человека из этой строки уходит в живой проход, как уходила по
  адресу task-<ID>. Живого прохода нет, работа продолжается из той же строки.
- Разговор `chat-<ID>-<n>` в склейку не попадает и остаётся отдельной строкой.
- Тесты: сборка списка из нескольких сессий одного имени tmux даёт одну
  строку, склейка ленты держит порядок проходов, адресация реплики находит
  живой проход при мёртвых соседях.
- Устройство склейки записано в docs/lld/DK-430-task-chat.md, поведение списка
  в tools/dashboard/README.md.
