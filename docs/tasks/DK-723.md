# DK-723: Разговор задачи в панели один, проходы складываются в него

## Что происходит

2026-09-02, DK-718 и DK-720. Конвейер задачи идёт проходами task-run.py, и
каждый проход это новый клиент со своим ID сессии. Реестр ~/.devkit/sessions.log
за этот вечер держит по DK-720 семь сессий, по DK-718 три, и все они подняты
под одним именем tmux, task-<ID>, с источником «заказ». Список чатов дашборда
собирается обходом транскриптов, поэтому на задачу приходится столько строк,
сколько было проходов, и заголовки у них одинаковые. Реплика человека при этом
адресуется разговору task-DK-718 (DK-430.2), и её берёт только живой проход.

Человек не знает, в какой чат заходить: записи одной задачи не отличить друг
от друга по заголовку, живая среди них одна, и она новейшая по времени, а
остальные мёртвые. Работу по задаче не проследить в одном месте: вопрос
агента, заданный вторым проходом, лежит в одной записи, ответ третьего прохода
в другой, и историю приходится собирать по нескольким чатам. Когда проходы
кончились, надо ещё найти концы, чтобы продолжить работу. Чем длиннее задача,
тем больше мусора в списке.

## Чего хотим

В списке чатов у задачи одна запись, лента её склеена из проходов подряд с
разделителем, реплика человека уходит в живой проход, а когда проходы
кончились, работа продолжается из той же записи.

## Границы

Склеиваются проходы конвейера, то есть сессии с именем tmux `task-<ID>`
(ответ пользователя 2026-09-02). Разговор человека о задаче, поднятый с
дашборда именем `chat-<ID>-<n>`, остаётся своей строкой списка и в ленту
проходов не втягивается. Кнопки строки задачи и чип этапа правит DK-716, тут
трогается список чатов и лента разговора.

## Развилки

Складывать записи по адресу разговора (tmux-имя task-<ID>) или по привязке к
задаче из реестра сессий. У цели лента одна и собирается из кусков ленты
сессий (DK-354.2), у задачи, видимо, тот же приём.

## DoD

- В списке чатов у задачи одна строка на все проходы конвейера, а не строка на
  сессию; заголовок и время у неё от самого свежего прохода.
- Лента этой строки склеена из транскриптов проходов по порядку, границы
  проходов видны разделителем, история задачи читается сверху вниз без
  перехода в другой чат.
- Реплика человека из этой строки уходит в живой проход, как уходила по адресу
  task-<ID>; когда живого прохода нет, из той же строки работа продолжается.
- Разговор `chat-<ID>-<n>` в склейку не попадает и остаётся отдельной строкой.
- Тесты: сборка списка из нескольких сессий одного имени tmux даёт одну
  строку, склейка ленты держит порядок проходов, адресация реплики находит
  живой проход при мёртвых соседях.
- Устройство склейки записано в docs/lld/DK-430-task-chat.md, поведение списка
  в tools/dashboard/README.md.

  регресс.
