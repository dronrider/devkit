# DK-758: Замечания чужого ревью копятся файлом и публикуются в MR по ключу publish

Цель: [lld/DK-756-foreign-review.md](lld/DK-756-foreign-review.md)

## Что происходит

Замечания к чужому MR уходят в треды как сложится разговор, человек не видит их до публикации, а режима «сначала покажи» нет. Решения 2, 3 и 4 LLD DK-756.

## Чего хотим

Файл `docs/tasks/<ID>.review.md` с блоками замечаний и четырьмя состояниями. `taskctl review draft <ID>` добавляет блок, `taskctl review publish <ID>` гонит одобренные в MR по командам `threads.md` с паузами и вписывает id тредов. Ключ `publish = confirm | auto` в `review.conf`, умолчание `confirm`. Раздел скилла `review` «Ревью чужой задачи» с порядком шагов, вопросом человеку последней репликой хода и парковкой «ждёт подтверждения». Чужая ветка не правится.

## DoD

- `draft` кладёт блок с файлом, строкой, меткой, текстом и состоянием «черновик», ручная правка файла разбирается.
- `publish` на заглушке API публикует только одобренные блоки, вписывает id тредов, держит паузу, при `auto` одобряет всё сам, при `confirm` отказывает без одобренных.
- Нечитаемый файл даёт отказ с именем блока.
- Раздел скилла написан, сторож скиллов знает про новый раздел, прогон `prompt-test` на стенде с заглушкой показывает вопрос человеку последней репликой и парковку.
- README taskctl и раздел «Конфиг» скилла знают ключ `publish`.

## Ранг

`25+8+3+0+4 = 40`, P2.

- Серьёзность 25. Публикация в чужой MR без взгляда человека это репутация в команде.
- Ценность 8. Сердце сценария, ради него он и затевался.
- Неопределённость 3. Формат файла и публикация решены, детали разбора ручной правки и пауз открыты.
- Поправка на баг 0.
- Рычаг 4. Ревью коллег идёт по одним правилам без ручной сборки тредов.

## Приёмка

- вид: mixed
- барьер «доступ»: публикация в живой GitLab требует токена корп-контура, стенд гоняет заглушку, живой MR проверяет человек.

## Ход работы

- Прогон стенда `prompt-test` на правку скилла отложен пользователем: раздел
  «Ревью чужой задачи» проверен сторожем скиллов и весом тела (15 937 из
  16 000 символов), послушание разделу проверяется отдельно.
- Разработка: субагент opus/high по вердикту pick (квота: week_all 28%, week_max 7% (панель разбивку не дала, цифра из кеша клиента возрастом 22ч 27м назад), снимок 32м назад, сдвига нет), 2026-09-03 16:14-16:14.

## Сценарий проверки

1. На стенде `taskctl review draft <ID>` дважды, файл с двумя блоками в состоянии «черновик».
2. `publish` при `confirm` без одобрения отказывает. Одобрить один блок, `publish`: у блока id треда, второй на месте.
3. `publish` при `auto` публикует оба блока опубликованы с паузой между вызовами заглушки.
4. Человек проверяет один живой MR корп-контура в режиме `confirm`, треды в MR совпадают с файлом.
