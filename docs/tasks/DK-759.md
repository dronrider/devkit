# DK-759: Тик опрашивает треды MR, будит второй круг и закрывает строку по судьбе MR

Цель: [lld/DK-756-foreign-review.md](lld/DK-756-foreign-review.md)

## Что происходит

После публикации замечаний ответы автора в тредах никто не смотрит, пока человек не попросит, а строка ревью висит, даже когда MR давно слит. Решения 5, 6, 7 и 8 LLD DK-756.

## Чего хотим

Тик `devkitctl watch` опрашивает треды MR у строк в парковке «ждёт автора» с шагом `poll` из `review.conf`, событие снимает парковку и будит живую сессию на второй круг, молчание дольше `silence` даёт уведомление человеку. Отказ автора на блокирующее даёт одно возражение фактом и стоп с парковкой «спор с автором». Слитый или закрытый MR закрывает строку молча, слитый с открытыми блокирующими шумит. Ворклог по ключу `worklog`.

## DoD

- Тик на заглушке API видит реплику автора, резолв треда и новый коммит, снимает парковку и ставит пометку «автор ответил»; пустая доска в сеть не ходит.
- Живая сессия задачи получает реплику тика и начинает второй круг; без сессии тик поднимает её дорогой дашборда; в окне без дашборда уведомление и пометка в `taskctl list`.
- Молчание дольше `silence` даёт одно уведомление и пометка строке, повторов на каждом тике нет.
- Отказ на `issue` после одного возражения даёт парковка «спор с автором» и уведомление с выжимкой; апрув при открытом блокирующем не ставится при любом `publish`.
- Слитый или закрытый MR закрывает строку с пометкой, блоки сняты, треды не тронуты; слитый с открытыми блокирующими даёт уведомление.
- `worklog = on` пишет время этапа «ревью» в тикет через заглушку, `off` не пишет.

4. Человек проверяет живой MR корп-контура, ответ коллеги в треде будит второй круг без реплики человека.
