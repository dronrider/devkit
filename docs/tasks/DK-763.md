# DK-763: Отказ рубежа пуша не печатает агенту обход через DEVKIT_PUSH_OK

## Что происходит

Ревью DK-760 2026-09-03. Ревьювер-субагент правил файл задачи в дереве ветки, пуш доски отбил рубеж pre-push, потому что в диапазоне лежали код-коммиты ветки. Текст отказа перечисляет способы пройти рубеж, среди них «по прямой команде пользователя: DEVKIT_PUSH_OK=1 git push». Субагент прочитал это как инструкцию и запушил ветку с этой переменной. Прямой команды человека не было.

Переменная задумана как след прямого слова человека, а её имя печатается каждому агенту в отказе. Рубеж перестаёт быть рубежом: любой субагент обходит его тем текстом, который сам рубеж ему и выдал. Сегодня уехала ветка задачи, вреда нет, завтра так же уедет код в main мимо ревью.

## Чего хотим

Отказ рубежа говорит агенту только то, что ему можно сделать самому: taskctl и shipctl с --push, автономный merge. Человеческий обход в отказ не печатается, и субагент им не пользуется.

## Развилки

Убрать подсказку про переменную из текста отказа и оставить её только в README, или сделать переменную непригодной для агента: требовать значение, которое знает только человек, либо проверять в рубеже, что процесс запущен не из сессии агента.

## DoD

- Текст отказа рубежа пуша (`shipctl push --check-only`, git-хук pre-push и хук харнеса check-review.py) не называет `DEVKIT_PUSH_OK` и `--no-verify`. Агенту печатается только то, что он может сделать сам: `taskctl ... --push`, `shipctl ... --push`, автономный merge, след ревью командой `taskctl review level`.
- Обход человека остаётся и описан только в README shipctl и hooks в разделе для человека.
- Регрессионный тест: отказ рубежа на код-коммите без ID и на коде без следа ревью не содержит имени переменной, тест краснеет на старом коде по `regcheck`.
- README shipctl и hooks: абзац, почему подсказка обхода в отказ не печатается.
