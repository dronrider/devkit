# DK-770: Хук режет связку cd с командой до классификатора, стоп на человека снят

## Что происходит

Автономная сессия встаёт на обычном поиске по коду, если команда начинается с
cd: путь после него классификатор авто-режима не определяет, поверх стоит
запрет на чтение, и решение остаётся за человеком. Права машинного контура тут
ни при чём, они разложены.

Всплыло на DK-724, где конвейер простоял двенадцать минут на
«cd ~/projects/devkit && grep -rn ...». К вечеру 2026-09-03 встали все чаты
разом: вопрос «Yes/No» на каждом ходу и у исполнителей задач, и у ревьюверов.

Разбор 2026-09-03 показал три слагаемых. Первое, сама связка «cd <каталог> &&
<чтение по относительному пути>»: классификатор не вычисляет, куда указывает
путь после cd, и так и говорит, «a directory that cannot be determined here».
Второе, deny-правила на Read в `~/.claude/settings.json`, четвёрка SECRET_DENY
из DK-228 (10 августа), которую раскладывает `devkitctl`: при запрете на чтение
и неизвестном адресате харнесс обязан спросить человека. Третье, обновление
Claude Code до 2.1.259 ночью 2026-09-03: в changelog «Fixed Bash Read() deny
rules not covering ... cd DIR && cat FILE compounds». До него связка с cd под
deny-правила не попадала, поэтому месяц всё молчало.

Прогоны headless-сессий в авто-режиме с флагом `--permission-prompts none`:
связка «cd ~/projects/devkit && grep ... tools/devkitctl/perms.py» требует
подтверждения, тот же grep по абсолютному пути проходит, относительный путь без
cd проходит, `git -C /Users/.../devkit log` проходит.

Стоп не лечится ни выбором проекта в шапке дашборда (гипотеза DK-714: на снимке
экрана cd идёт в worktree самого devkit и всё равно встаёт), ни allow-правилами
(команды составные и каждый раз другие), ни хуками devkit (они решения ask не
выдают). Снять deny-правила нельзя, это рубеж DK-207 против утечки секретов в
контекст. Правило прозой в RULES агенты выполняют не всегда: привычка писать
«cd && grep» сильнее одного абзаца, а промах стоит стопа конвейера до прихода
человека.

## Чего хотим

Хук devkit на PreToolUse Bash ловит «cd <каталог> && <команда>» и отвечает
отказом с подсказкой: cd отдельным вызовом либо абсолютный путь, `git -C`,
`cargo --manifest-path`. Хук раскладывает `devkitctl`, как остальные рубежи.
Пункт в `RULES.core.md` и строка в определениях exec-* и review-* закрепляют то
же словами. После этого headless-прогон связки с cd отвечает отказом хука, а не
запросом разрешения, и автономная задача доски проходит без остановок
permission_prompt в turns.log.

## Развилки

Как остановить связку раньше классификатора, чтобы агент получил внятную причину
и переписал команду сам, а вопрос до человека не дошёл. Взяты обе половины,
`hooks/check-cd-compound.py` на PreToolUse Bash и правило прозой. Одного правила
мало, привычка писать «cd && grep» сильнее абзаца, а промах стоит стопа. Одного
хука тоже мало, отказ обходится агенту в лишний ход, и правило гасит эти ходы
заранее.

Что считать связкой, решалось трижды. Первая редакция рубила любую вторую
команду за cd. Хук с ней встал в раскладку днём 3 сентября, и к вечеру
пользователь принёс обратное. Агенты встали уже на отказах рубежа: сборку и
прогон тестов после cd классификатор пропускает сам, а рубеж их резал. Вторая
редакция сузила рубеж по доке прав Claude Code. Третья взяла границу замером,
семь форм связки headless-прогонами в авто-режиме.

Замер и решил спор. Дока подтвердилась только про git после cd и про редирект
вывода в файл. Про читателей она молчит, и разбирать их пришлось живьём.
Классификатор спрашивает про `cd X && ls | head -2` и `cd X && ls hooks`.
Проходят `cd X && echo hi`, `cd X && python3 -c ...`, `cd X && go test
./tools/... | tail -1`, `cd X && make -n | head -1` и `cd X && cargo --version`.

Итог рубежа три вида. Команда чтения из списка READERS (cat, grep-семейство,
sed, awk, head, tail, ls, find, tree, du и соседи) режется, когда у неё
относительный путь в операнде. Листинг (ls, find, tree, du) режется и без
операнда, он читает cwd. Читатель stdin в трубе проходит, читатель с
абсолютными путями тоже. Второй вид это git после cd, третий это редирект
вывода в файл, кроме /dev/null. Остальное проходит: цена ложного отказа
считается на каждом ходу Bash, и она выше цены пропущенной связки.

Отказ ведёт готовой заменой первой строкой, а не одной причиной. Замена
собирается из самой команды. Cd убирается, относительные операнды и цель
редиректа получают префикс каталога, листинг без операнда получает каталог явно,
git получает `-C <каталог>`. Агент повторяет ход этой строкой и тратит на рубеж
один ход вместо разбора. Путём не считаются числа вроде `-n 5`, ключи find после
первого и глоб без слэша. Каталог с подстановкой (`cd $ROOT && cat a.txt`) в
путь не подставляется: значение переменной рубежу неизвестно. Подсказка тогда
советует одинокий cd отдельным вызовом.

Разделителем считаются `&&`, `||`, `;`, `|`, `&` и перевод строки, подшелл
`(cd X && ...)` и подстановка `$(cd X && ...)` разбираются наравне с началом
строки. Каталог после cd классификатор не вычисляет ни в одном из этих видов,
и разница между ними только в записи.

Одинокий `cd <путь>` проходит. Смена каталога отдельным вызовом законна, cwd у
Bash между вызовами сохраняется, и без такого выхода рубеж запретил бы работу в
чужом дереве вовсе. Хвостовой cd (`ls /tmp && cd /tmp`) тоже проходит, читать
по относительному пути после него нечего.

Команда разбирается токенами `shlex`, а не поиском подстроки. Слово cd внутри
кавычек это аргумент, и текст промпта у `claude -p '... cd ~/x && grep ...'`
рубеж пропускает. Тело heredoc снимается до разбора: без снятия записанный в
файл пример ловил бы сам себя. Взят надёжный минимум: cd за словом другой
конструкции (`do cd $d && ls` в цикле) проходит, и незакрытая кавычка тоже.

Прогон `obeycheck` по правке правил не заводился. Стенд сравнивает раскладки
правил, а держит рубеж хук, и при живом хуке обе раскладки дают один исход.
Польза абзаца в правилах тут не в исходе, а в сэкономленном ходе, и такой
разницы таблица стенда не показывает. Вместо стенда прогнан машинный сценарий
проверки: headless-сессия со связкой получает отказ хука, повторяет ход готовой
заменой и доводит дело сама.

## DoD

Headless-прогон `claude -p --permission-mode auto --permission-prompts none`
с командой «cd ~/projects/devkit && grep ... tools/devkitctl/perms.py» получает
отказ хука с подсказкой, а не запрос разрешения. `devkitctl doctor` видит хук
в раскладке и ставит его при нехватке. Правило про cd стоит в `RULES.core.md`
и в определениях агентов.
