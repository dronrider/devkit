# DK-770: Хук режет связку cd с командой до классификатора, стоп на человека снят

## Что происходит

Автономная сессия встаёт на обычном поиске по коду, если команда начинается с
cd: путь после него классификатор авто-режима не определяет, поверх стоит
запрет на чтение, и решение остаётся за человеком. Права машинного контура тут
ни при чём, они разложены.

Всплыло на DK-724, где конвейер простоял двенадцать минут на
«cd ~/projects/devkit && grep -rn ...». К вечеру 2026-09-03 встали все чаты
разом: вопрос «Yes/No» на каждом ходу и у исполнителей задач, и у ревьюверов.

Разбор 2026-09-03 показал три слагаемых. Первое, сама связка «cd <каталог> &&
<чтение по относительному пути>»: классификатор не вычисляет, куда указывает
путь после cd, и так и говорит, «a directory that cannot be determined here».
Второе, deny-правила на Read в `~/.claude/settings.json`, четвёрка SECRET_DENY
из DK-228 (10 августа), которую раскладывает `devkitctl`: при запрете на чтение
и неизвестном адресате харнесс обязан спросить человека. Третье, обновление
Claude Code до 2.1.259 ночью 2026-09-03: в changelog «Fixed Bash Read() deny
rules not covering ... cd DIR && cat FILE compounds». До него связка с cd под
deny-правила не попадала, поэтому месяц всё молчало.

Прогоны headless-сессий в авто-режиме с флагом `--permission-prompts none`:
связка «cd ~/projects/devkit && grep ... tools/devkitctl/perms.py» требует
подтверждения, тот же grep по абсолютному пути проходит, относительный путь без
cd проходит, `git -C /Users/.../devkit log` проходит.

Стоп не лечится ни выбором проекта в шапке дашборда (гипотеза DK-714: на снимке
экрана cd идёт в worktree самого devkit и всё равно встаёт), ни allow-правилами
(команды составные и каждый раз другие), ни хуками devkit (они решения ask не
выдают). Снять deny-правила нельзя, это рубеж DK-207 против утечки секретов в
контекст. Правило прозой в RULES агенты выполняют не всегда: привычка писать
«cd && grep» сильнее одного абзаца, а промах стоит стопа конвейера до прихода
человека.

## Чего хотим

Хук devkit на PreToolUse Bash ловит «cd <каталог> && <команда>» и отвечает
отказом с подсказкой: cd отдельным вызовом либо абсолютный путь, `git -C`,
`cargo --manifest-path`. Хук раскладывает `devkitctl`, как остальные рубежи.
Пункт в `RULES.core.md` и строка в определениях exec-* и review-* закрепляют то
же словами. После этого headless-прогон связки с cd отвечает отказом хука, а не
запросом разрешения, и автономная задача доски проходит без остановок
permission_prompt в turns.log.

## Развилки

Как остановить связку раньше классификатора, чтобы агент получил внятную причину
и переписал команду сам, а вопрос до человека не дошёл. Развилка: хук на
PreToolUse Bash, который отказывает с подсказкой, плюс правило прозой, либо
только правило прозой. Открыто, что считать связкой: cd с любой командой
или только с командой, у которой есть относительный путь-операнд; и как быть с
`cd` в подшелле и через `;`.

## DoD

Headless-прогон `claude -p --permission-mode auto --permission-prompts none`
с командой «cd ~/projects/devkit && grep ... tools/devkitctl/perms.py» получает
отказ хука с подсказкой, а не запрос разрешения. `devkitctl doctor` видит хук
в раскладке и ставит его при нехватке. Правило про cd стоит в `RULES.core.md`
и в определениях агентов.
