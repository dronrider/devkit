# DK-804: Ворота старта отказывают при открытой блокирующей развилке

Цель: [tasks/DK-565.md](tasks/DK-565.md)

## Что происходит

Раздел «Развилки» у файла задачи есть, и стоит он в форме
(`internal/taskform/taskform.go:26`). Пишется он прозой. Состояния у развилки
нет, автора решения нет, признака «держит старт» тоже нет.

Ветка заводится в обход этого текста. `cmdStart` смотрит на PATH taskctl, на
основной чекаут, на замок, на секцию доски и на корп-привязку
(`tools/shipctl/worktree.go:291`). Файл задачи он не открывает вовсе.
Исполнитель садится за код с нерешённой развилкой и решает её сам, а
расхождение всплывает на ревью.

Формат машинного перечня развилок даёт LLD DK-552, эта задача садится на его
решение.

## Чего хотим

`shipctl start` читает перечень развилок и отказывает, когда открыта
блокирующая. Отказ называет саму развилку прямо в строке. Закрытая
развилка ворот не держит, и ветка заводится обычным порядком. Дашборд
показывает открытые развилки рядом со статусом задачи.

## DoD

- `shipctl start DK-X` на задаче с открытой блокирующей развилкой печатает
  отказ с её именем.
- После закрытия развилки та же команда заводит ветку.
- Развилка, оставленная исполнителю, старта не держит.
- `taskctl close DK-X` при открытой блокирующей развилке отказывает тем же
  чтением перечня, что и старт, по решению 2 DK-552.
- Дашборд показывает открытые развилки задачи рядом со статусом.
- Тесты по стандарту, разбор в README shipctl.

## Сценарий проверки

Шаги гоняются из корня чекаута. Обкатка исполняет каждую строку блока своим
процессом, поэтому строки тут самодостаточны. Путь до корня подставляется в
каждую команду, а стенд третьего, четвёртого и пятого шагов собирается и
убирается внутри одной строки.

1. Общий отбор и слова отказа. Открытая человеческая развилка держит ворота,
   решённая и оставленная исполнителю не держат, а отказ несёт имя, вопрос,
   рекомендацию и обе команды снятия.

   ```sh
   GOWORK=off go -C "$(git rev-parse --show-toplevel)/internal" test ./taskform/... -count=1 -run "TestHoldingForks|TestForkGateNote" -v
   ```

   Ожидание: строка `PASS`, оба теста в списке `--- PASS`.

2. Ворота в трёх утилитах. Отказ старта, отказ закрытия и поле открытых
   развилок в строке задачи на дашборде.

   ```sh
   GOWORK=off go -C "$(git rev-parse --show-toplevel)/tools/shipctl" test . -count=1 -run "TestStartHeldByFork|TestStartPassesExecutorFork"
   GOWORK=off go -C "$(git rev-parse --show-toplevel)/tools/taskctl" test . -count=1 -run "TestCloseHeldByFork|TestCloseAnsweredForkPasses"
   GOWORK=off go -C "$(git rev-parse --show-toplevel)/tools/dashboard" test . -count=1 -run "TestTaskForksInRow"
   ```

   Ожидание: три строки `ok` с именами пакетов `shipctl`, `taskctl` и
   `dashboard`.

3. Живой отказ обоих ворот. Строка поднимает свой проект с доской из двух
   строк, заводит каждой человеческую развилку и зовёт обе команды.

   ```sh
   w="${TMPDIR:-/tmp}/dk804-stand-a"; rm -rf "$w"; mkdir -p "$w"; git -C "$w" init -q -b main; git -C "$w" config user.email t@t; git -C "$w" config user.name t; taskctl -C "$w" init --prefix XR --name проба; taskctl -C "$w" add --id XR-001 --title "Старт под развилкой" --rank 25+0+0+0+0 --accept user --barrier глаза; taskctl -C "$w" add --id XR-002 --title "Закрытие под развилкой" --rank 25+0+0+0+0 --accept user --barrier глаза; git -C "$w" add -A; git -C "$w" commit -qm стенд; taskctl -C "$w" decide XR-001 --ask доступ --hint "считать приватным" "токен положен в secretctl?"; taskctl -C "$w" decide XR-002 --ask публичность "релизы видны без токена?"; shipctl -C "$w" start XR-001; taskctl -C "$w" close XR-002; git -C "$w" status --short docs/TASKS.md; rm -rf "$w"; echo "стенд убран"
   ```

   Ожидание: `shipctl start` отказывает и называет «доступ» с вопросом про
   токен, `taskctl close` отказывает и называет «публичность», оба отказа несут
   команды `decide ... --by человек` и `decide ... --leave`. Доска стенда не
   тронута, `git status` по ней печатает пустую строку, последняя строка вывода
   это «стенд убран».

4. Ответ отпускает оба прохода. Тот же стенд, но развилки закрываются ответом
   до вызова команд.

   ```sh
   w="${TMPDIR:-/tmp}/dk804-stand-b"; rm -rf "$w" "$w"-xr-001; mkdir -p "$w"; git -C "$w" init -q -b main; git -C "$w" config user.email t@t; git -C "$w" config user.name t; taskctl -C "$w" init --prefix XR --name проба; taskctl -C "$w" add --id XR-001 --title "Старт под развилкой" --rank 25+0+0+0+0 --accept user --barrier глаза; taskctl -C "$w" add --id XR-002 --title "Закрытие под развилкой" --rank 25+0+0+0+0 --accept user --barrier глаза; git -C "$w" add -A; git -C "$w" commit -qm стенд; taskctl -C "$w" decide XR-001 --ask доступ "токен положен в secretctl?"; taskctl -C "$w" decide XR-002 --ask публичность "релизы видны без токена?"; taskctl -C "$w" decide XR-001 «доступ» --by человек "положил, имя xr-token"; taskctl -C "$w" decide XR-002 «публичность» --by человек "да, релизы публичные"; shipctl -C "$w" start XR-001; taskctl -C "$w" close XR-002; rm -rf "$w" "$w"-xr-001; echo "стенд убран"
   ```

   Ожидание: печать `decide` показывает у обеих развилок состояние «решена» со
   штампом автора и даты, `start` заводит ветку `xr-001` и переводит строку в
   In progress, `close` уносит XR-002 в архив. Предупреждение про разлив
   очереди у `close` законно, доска стенда после закрытия не закоммичена.

5. Развилка исполнителя и задача без перечня. Ни та, ни другая ворот не
   держат.

   ```sh
   w="${TMPDIR:-/tmp}/dk804-stand-c"; rm -rf "$w" "$w"-xr-003; mkdir -p "$w"; git -C "$w" init -q -b main; git -C "$w" config user.email t@t; git -C "$w" config user.name t; taskctl -C "$w" init --prefix XR --name проба; taskctl -C "$w" add --id XR-003 --title "Развилка исполнителя" --rank 25+0+0+0+0 --accept user --barrier глаза; taskctl -C "$w" add --id XR-004 --title "Задача без перечня" --rank 25+0+0+0+0 --accept user --barrier глаза; git -C "$w" add -A; git -C "$w" commit -qm стенд; taskctl -C "$w" decide XR-003 --ask поле --who исполнитель --hint "«решает»" "как звать поле?"; shipctl -C "$w" start XR-003; taskctl -C "$w" close XR-004; rm -rf "$w" "$w"-xr-003; echo "стенд убран"
   ```

   Ожидание: `decide` называет «поле» оставленной исполнителю, `start` заводит
   ветку `xr-003` при открытой развилке, `close` уносит XR-004 без перечня в
   архив, последняя строка вывода это «стенд убран».

6. Живой заход на файле этой задачи и дока. Развилка заводится, печатается
   состоянием, файл возвращается копией, снятой в той же строке. Копия тут
   надёжнее `git checkout`: он вернул бы файл к коммиту и унёс с ним
   незакоммиченное, в том числе запись самой обкатки.

   ```sh
   cp "$(git rev-parse --show-toplevel)/docs/tasks/DK-804.md" "${TMPDIR:-/tmp}/dk804-task.bak"; taskctl -C "$(git rev-parse --show-toplevel)" decide DK-804 --ask проба --hint "проба" "проба сценария?"; taskctl -C "$(git rev-parse --show-toplevel)" decide DK-804 --open; cp "${TMPDIR:-/tmp}/dk804-task.bak" "$(git rev-parse --show-toplevel)/docs/tasks/DK-804.md"; rm -f "${TMPDIR:-/tmp}/dk804-task.bak"; git -C "$(git rev-parse --show-toplevel)" diff --stat -- docs/tasks/DK-804.md; echo "файл возвращён"
   grep -n "Развилка держит старт" "$(git rev-parse --show-toplevel)/tools/shipctl/README.md"
   grep -n "Ворота старта и закрытия" "$(git rev-parse --show-toplevel)/tools/taskctl/README.md"
   ```

   Ожидание: `decide` заводит «пробу» и печатает её открытой, держащей старт,
   последняя строка первой команды это «файл возвращён», а `git diff --stat` по
   файлу печатает перед ней то же, что печатал до шага (на чистом дереве
   ничего). Оба `grep` печатают по строке с заголовком раздела README.
