# DK-804: Ворота старта отказывают при открытой блокирующей развилке

Цель: [tasks/DK-565.md](tasks/DK-565.md)

## Что происходит

Раздел «Развилки» у файла задачи есть, и стоит он в форме
(`internal/taskform/taskform.go:26`). Пишется он прозой. Состояния у развилки
нет, автора решения нет, признака «держит старт» тоже нет.

Ветка заводится в обход этого текста. `cmdStart` смотрит на PATH taskctl, на
основной чекаут, на замок, на секцию доски и на корп-привязку
(`tools/shipctl/worktree.go:291`). Файл задачи он не открывает вовсе.
Исполнитель садится за код с нерешённой развилкой и решает её сам, а
расхождение всплывает на ревью.

Формат машинного перечня развилок даёт LLD DK-552, эта задача садится на его
решение.

## Чего хотим

`shipctl start` читает перечень развилок и отказывает, когда открыта
блокирующая. Отказ называет саму развилку прямо в строке. Закрытая
развилка ворот не держит, и ветка заводится обычным порядком. Дашборд
показывает открытые развилки рядом со статусом задачи.

## DoD

- `shipctl start DK-X` на задаче с открытой блокирующей развилкой печатает
  отказ с её именем.
- После закрытия развилки та же команда заводит ветку.
- Развилка, оставленная исполнителю, старта не держит.
- `taskctl close DK-X` при открытой блокирующей развилке отказывает тем же
  чтением перечня, что и старт, по решению 2 DK-552.
- Дашборд показывает открытые развилки задачи рядом со статусом.
- Тесты по стандарту, разбор в README shipctl.

## Сценарий проверки

Шаги гоняются из корня чекаута. Стенд третьего шага это отдельный проект во
временном каталоге, живёт он до пятого шага и там же убирается. Шестой шаг
правит файл этой задачи и возвращает его гитом в том же блоке.

1. Общий отбор и слова отказа. Открытая человеческая развилка держит ворота,
   решённая и оставленная исполнителю не держат, а отказ несёт имя, вопрос,
   рекомендацию и обе команды снятия.

   ```sh
   GOWORK=off go -C "$(git rev-parse --show-toplevel)/internal" test ./taskform/... -count=1 -run "TestHoldingForks|TestForkGateNote" -v
   ```

   Ожидание: строка `PASS`, оба теста в списке `--- PASS`.

2. Ворота в трёх утилитах. Отказ старта, отказ закрытия и поле открытых
   развилок в строке задачи на дашборде.

   ```sh
   root="$(git rev-parse --show-toplevel)"
   GOWORK=off go -C "$root/tools/shipctl" test . -count=1 -run "TestStartHeldByFork|TestStartPassesExecutorFork"
   GOWORK=off go -C "$root/tools/taskctl" test . -count=1 -run "TestCloseHeldByFork|TestCloseAnsweredForkPasses"
   GOWORK=off go -C "$root/tools/dashboard" test . -count=1 -run "TestTaskForksInRow"
   ```

   Ожидание: три строки `ok` с именами пакетов `shipctl`, `taskctl` и
   `dashboard`.

3. Живой отказ обоих ворот. Стенд это свой проект с доской из четырёх строк.
   XR-001 и XR-002 получают человеческую развилку, XR-003 развилку
   исполнителя, XR-004 остаётся без перечня.

   ```sh
   work="${TMPDIR:-/tmp}/dk804-stand"; rm -rf "$work" "$work"-xr-001 "$work"-xr-003; mkdir -p "$work"
   git -C "$work" init -q -b main; git -C "$work" config user.email t@t; git -C "$work" config user.name t
   taskctl -C "$work" init --prefix XR --name проба
   taskctl -C "$work" add --id XR-001 --title "Старт под развилкой" --rank 25+0+0+0+0 --accept user --barrier глаза
   taskctl -C "$work" add --id XR-002 --title "Закрытие под развилкой" --rank 25+0+0+0+0 --accept user --barrier глаза
   taskctl -C "$work" add --id XR-003 --title "Развилка исполнителя" --rank 25+0+0+0+0 --accept user --barrier глаза
   taskctl -C "$work" add --id XR-004 --title "Задача без перечня" --rank 25+0+0+0+0 --accept user --barrier глаза
   git -C "$work" add -A; git -C "$work" commit -qm стенд
   taskctl -C "$work" decide XR-001 --ask доступ --hint "считать приватным" "токен положен в secretctl?"
   taskctl -C "$work" decide XR-002 --ask публичность "релизы видны без токена?"
   taskctl -C "$work" decide XR-003 --ask поле --who исполнитель --hint "«решает»" "как звать поле?"
   shipctl -C "$work" start XR-001
   taskctl -C "$work" close XR-002
   git -C "$work" status --short docs/TASKS.md
   ```

   Ожидание: `shipctl start` отказывает и называет «доступ» с вопросом про
   токен, `taskctl close` отказывает и называет «публичность», оба отказа несут
   команды `decide ... --by человек` и `decide ... --leave`. Доска стенда не
   тронута, последняя команда печатает пустую строку.

4. Ответ отпускает оба прохода. Развилки XR-001 и XR-002 закрываются ответом,
   и обе команды идут дальше.

   ```sh
   work="${TMPDIR:-/tmp}/dk804-stand"
   taskctl -C "$work" decide XR-001 «доступ» --by человек "положил, имя xr-token"
   taskctl -C "$work" decide XR-002 «публичность» --by человек "да, релизы публичные"
   shipctl -C "$work" start XR-001
   taskctl -C "$work" close XR-002
   ```

   Ожидание: печать `decide` показывает у обеих состояние «решена» со штампом
   автора и даты, `start` заводит ветку `xr-001` и переводит строку в
   In progress, `close` уносит XR-002 в архив. Предупреждение про разлив
   очереди у `close` законно, доска стенда после закрытия не закоммичена.

5. Развилка исполнителя и задача без перечня. Ни та, ни другая ворот не
   держат. Последняя команда убирает стенд.

   ```sh
   work="${TMPDIR:-/tmp}/dk804-stand"
   shipctl -C "$work" start XR-003
   taskctl -C "$work" close XR-004
   rm -rf "$work" "$work"-xr-001 "$work"-xr-003; ls -d "$work" 2>/dev/null; echo "стенд убран"
   ```

   Ожидание: `start` заводит ветку `xr-003` при открытой развилке «поле»,
   `close` уносит XR-004 в архив. Последняя строка вывода это «стенд убран», а
   пути стенда перед ней нет.

6. Живой заход на файле этой задачи и дока. Развилка заводится, печатается
   состоянием, файл возвращается гитом.

   ```sh
   root="$(git rev-parse --show-toplevel)"
   taskctl -C "$root" decide DK-804 --ask проба --hint "проба" "проба сценария?"
   taskctl -C "$root" decide DK-804 --open
   git -C "$root" checkout -- docs/tasks/DK-804.md
   git -C "$root" status --short docs/tasks/DK-804.md
   grep -n "Развилка держит старт" "$root/tools/shipctl/README.md"
   grep -n "Ворота старта и закрытия" "$root/tools/taskctl/README.md"
   ```

   Ожидание: `decide` заводит «пробу» и печатает её как открытую, держащую
   старт, `git status` по файлу пуст, оба `grep` печатают по строке с
   заголовком раздела.
