# DK-806: Дифф агентских файлов без сценария стенда отбивается на слиянии

Цель: [tasks/DK-565.md](tasks/DK-565.md)

## Что происходит

У слияния четверо ворот: regcheck, тесты, сценарий проверки и уровень ревью
(`tools/shipctl/ops.go:1004`). Правка текста, который читают агенты, проходит
их насквозь.

Опознавать такую правку доска уже умеет. `promptPath` в `tools/taskctl/gate.go`
знает `kit/skills/`, `kit/agents/`, `RULES*`, TASKFORM, RANKING и ACCEPTANCE, а
`promptHint` печатает на `move check` совет прогнать prompt-test. В коде рядом
прямо сказано, что отказа тут нет. Совет остаётся советом, и правка скилла
уезжает в main без единого прогона.

Правило прогона и его порог приходят из LLD DK-805, эта задача ставит по ним
ворота.

## Чего хотим

Ворота слияния отбивают дифф агентских файлов без сценария стенда и без следа
прогона. Пятые ворота встают рядом с четырьмя по образцу ворот теста. Гасятся
они той же пометкой-исключением, что и остальные. Подсказка `move check` из
DK-448 становится отказом на слиянии.

## DoD

- `shipctl merge DK-X` на ветке с правкой `kit/skills` без сценария печатает
  отказ и называет файл, из-за которого встал.
- Ветка с пометкой «- Исключение: стенд» в файле задачи проходит слияние.
- Ветка со сценарием и следом прогона проходит слияние.
- Список опознаваемых путей у ворот и у `promptHint` один на двоих.
- Тесты по стандарту, разбор в README shipctl.

- [возврат: реализация, 2026-09-06] блокирует: standCovered в tools/shipctl/advice.go:824 берёт отпечаток по предметам одного покрывающего сценария (obey.PrintFrom(read, s.subs)). Стенд же пишет отметку по объединению предметов всех сценариев прогона (tools/obeycheck/tasknote.go:176, runSubjects). Один прогон часто закрывает два сценария разом, --for принимает несколько путей. LLD DK-805 решение 2 приводит именно такую отметку, «сценарии 14-prose-sample, 15-mimicry-readme, зачтён». У неё отпечаток снят с объединения предметов обоих сценариев. Ворота же на каждый тронутый раздел берут отпечаток только своего сценария. Он с отметкой не совпадает. Гейт отвечает «отпечаток отметки не совпал с текстом дерева ветки», хотя прогон свежий и зачтён. Проверил живым прогоном: собрал ветку с двумя скиллами и двумя сценариями, положил зачтённую отметку с Print от union(subA,subB) и Scenarios: [20-a, 21-b]. cmdMerge отбил слияние этой ошибкой. Все 12 тестов TestStandGate* используют только односценарные отметки, баг они не ловят. Сейчас standCovered печатает предметы одного covering-сценария. Печать нужно считать по объединению предметов сценариев, названных в марке. Нужен новый тест на мультисценарную отметку.: исправлено, standCovered берёт отпечаток по объединению предметов сценариев, названных в самой отметке (markSubjects плюс общий obey.Union, куда переехал runSubjects стенда); тест TestStandGateMultiScenarioMark на отметку с двумя сценариями краснеет на прежнем коде по regcheck; разбор про объединение дописан в README shipctl
- [возврат: правила, 2026-09-06] не блокирует: базе шапки файла (headSection) и переименованию агентского файла (--no-renames разбирает его как удаление+добавление) нет отдельного теста в TestStandGate*: логика в touchedSections выглядит корректной при чтении (шапка существующего файла всегда база «старый», кроме случая целиком нового файла; переименование трактуется как новый файл с базой «пусто»), но эти ветки не проверены живым прогоном. Не блокирует, так как проверил вручную по коду.: исправлено, заведены TestStandGateHeadSection (правка шапки прежнего файла требует базу «старый») и TestStandGateRenamedFile (переехавший файл идёт новым, все его разделы с базой «пусто», сценарий перепривязан той же веткой)
- Вердикт: без замечаний. Второй круг, оба замечания отработаны и проверены живым прогоном. Блокирующее закрыто переносом объединения предметов в общий obey.Union и пересборкой standCovered от имён сценариев самой отметки (markSubjects). Откатил advice.go на дореформенную версию и подтвердил редноту: TestStandGateMultiScenarioMark падает ровно с той ошибкой, что называл в замечании, и зеленеет на текущем коде. Неблокирующее закрыто тестами TestStandGateHeadSection и TestStandGateRenamedFile. Оба уже проходили на дореформенном коде, это добавление покрытия. Отдельно проверил риск подмены отпечатка лишним или чужим именем сценария в поле «сценарии» отметки. markSubjects резолвит имена по дереву ветки и берёт объединение их текущих предметов. Отпечаток пересчитывается заново по текущему тексту, поэтому посторонним именем нельзя заставить старый или чужой прогон закрыть нужный раздел: совпадение остаётся привязано к текущему содержимому названных предметов. Прогнал живьём: TestStandGate* (15/15), internal/obey с TestUnion, полный self-check tools/devkitctl/parallel.py -j 3, 18 компонентов из 18 зелёные. Поправил сам мелочь.
