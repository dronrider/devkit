# DK-806: Дифф агентских файлов без сценария стенда отбивается на слиянии

Цель: [tasks/DK-565.md](tasks/DK-565.md)

## Что происходит

У слияния четверо ворот: regcheck, тесты, сценарий проверки и уровень ревью
(`tools/shipctl/ops.go:1004`). Правка текста, который читают агенты, проходит
их насквозь.

Опознавать такую правку доска уже умеет. `promptPath` в `tools/taskctl/gate.go`
знает `kit/skills/`, `kit/agents/`, `RULES*`, TASKFORM, RANKING и ACCEPTANCE, а
`promptHint` печатает на `move check` совет прогнать prompt-test. В коде рядом
прямо сказано, что отказа тут нет. Совет остаётся советом, и правка скилла
уезжает в main без единого прогона.

Правило прогона и его порог приходят из LLD DK-805, эта задача ставит по ним
ворота.

## Чего хотим

Ворота слияния отбивают дифф агентских файлов без сценария стенда и без следа
прогона. Пятые ворота встают рядом с четырьмя по образцу ворот теста. Гасятся
они той же пометкой-исключением, что и остальные. Подсказка `move check` из
DK-448 становится отказом на слиянии.

## DoD

- `shipctl merge DK-X` на ветке с правкой `kit/skills` без сценария печатает
  отказ и называет файл, из-за которого встал.

- Ветка со сценарием и следом прогона проходит слияние.
- Список опознаваемых путей у ворот и у `promptHint` один на двоих.
- Тесты по стандарту, разбор в README shipctl.

## Ревью

Уровень 3 до 08a9c34: неопределённость 1 из pick, триаж два «да»: путь пятых ворот критичен для DoD цели DK-565 (ложноотрицательный результат пропускает промпт-правку мимо стенда), диффом тронуты critical_paths tools/shipctl и tools/taskctl

- [возврат: реализация, 2026-09-06] блокирует: standCovered в tools/shipctl/advice.go:824 считает отпечаток отметки по предметам одного покрывающего сценария (obey.PrintFrom(read, s.subs)), а реальную отметку стенд пишет по объединению предметов ВСЕХ сценариев прогона (tools/obeycheck/tasknote.go:176, runSubjects). Прогон, который закрыл сразу два сценария на разные файлы одной командой (обычный путь при --for с несколькими путями, ровно так и показан в LLD DK-805 решение 2: «сценарии 14-prose-sample, 15-mimicry-readme, зачтён»), даёт отпечаток по объединению их предметов. Ворота же на каждый тронутый раздел берут отпечаток только своего сценария, и он с отметкой не совпадает: гейт всегда отвечает «отпечаток отметки не совпал с текстом дерева ветки», хотя прогон свежий и зачтён. Проверено живым прогоном: собрал ветку с двумя скиллами и двумя сценариями, положил зачтённую отметку с Print от union(subA,subB) и Scenarios: [20-a, 21-b], и cmdMerge отбил слияние этой ошибкой. Все 12 тестов TestStandGate* используют только односценарные отметки, поэтому баг не ловится. Починка: standCovered должен брать печать по объединению предметов ровно тех сценариев, что названы в марке, а не своего covering-сценария в одиночку; нужен новый тест на мультисценарную отметку.
- [возврат: правила, 2026-09-06] не блокирует: базе шапки файла (headSection) и переименованию агентского файла (--no-renames разбирает его как удаление+добавление) нет отдельного теста в TestStandGate*: логика в touchedSections выглядит корректной при чтении (шапка существующего файла всегда база «старый», кроме случая целиком нового файла; переименование трактуется как новый файл с базой «пусто»), но эти ветки не проверены живым прогоном. Не блокирует, так как проверил вручную по коду.
