# DK-807: Сценарий стенда судит вердиктом модели, калиброванным примерами

Цель: [tasks/DK-565.md](tasks/DK-565.md)

## Что происходит

Вкусовой класс правил стенд не проверяет. LLD DK-100 вывел его из-под проверки
сознательно. Мимикрия под стиль, англицизмы и канцелярит оцениваются вкусом, и
командой такое не меряется. Строки эти остаются в резиденте по умолчанию.

Судья-модель этот класс берёт. На прогоне 2026-08-17 слепой судья по критерию
на естественном языке сошёлся с эталоном, размеченным глазами, 6 раз из 6.
Условий три. Вердикт пишется последней строкой после разбора. Иначе sonnet
ставил ДА против собственной цитаты 16 раз из 20. Критерий формулируется
положительно, «найди в ответе X». Перед полным кругом судья калибруется на
размеченных примерах.

В стенде судьи как сущности нет. Секций у сценария три, модель проверке не
передаётся, в окружении клетки лежит `OBEY_TRANSCRIPT`, через который сценарий
зовёт судью сам. Рецепт записан прозой в скилле prompt-test, калибровочных
примеров нет нигде.

## Чего хотим

У сценария стенда есть судейская секция. Рядом с машинной проверкой лежит
критерий на естественном языке, стенд отдаёт транскрипт судье со свежим
контекстом и берёт вердикт кодом возврата. Калибровочные примеры едут в самом
сценарии. Сценарий идёт в зачёт после того, как судья сошёлся с ними.

У секции есть свой вход. Ключ `вход` это путь от корня проекта прогона либо
слово `ответ` умолчанием, а одна функция рядом с `phrase` достаёт реплики
ассистента из транскрипта. Судья слепой. В его контексте лежат критерий и
входной текст, примеры ему не показываются вовсе, а зовётся он из пустого HOME
и вне каталога проекта прогона. Модель разворачивается из яруса `mini`, ярус и
модель меняют флаги `--judge-tier` и `--judge-model`. Калибровка идёт до первой
сессии прогона, а при расхождении хотя бы на одном примере прогон
останавливается кодом 2.

Первый боевой сценарий берёт вкусовой класс. Номер 17 в постановке цели занят
`17-verify-runner`, сценарий заводится следующим свободным. Сценарий
`21-first-person-gender` переезжает со своего `claude -p` в sh-проверке на
судейскую секцию. Раздел «Судья-модель» в `prompt-test` сводится к правилу
положительного критерия и ссылке на README стенда. Живой замер «Мимикрии» на
паре с разделом и без него сюда не входит, он идёт первой строкой ревизии
DK-808.

## DoD

- Сценарий с судейской секцией краснеет на подставном ответе мимо стиля и
  зеленеет на ответе по стилю.
- Прогон печатает вердикт судьи вместе с его разбором.
- Сценарий с несошедшейся калибровкой в зачёт не идёт, и прогон говорит об
  этом прямо.
- Критерий и калибровочные примеры лежат в файле сценария.
- Ключ `вход` умолчанием берёт реплики ассистента из транскрипта, а путём файл
  проекта прогона.
- При расхождении судьи с примером прогон останавливается кодом 2 до первой
  сессии и называет сценарий и пример.
- Судья зовётся с яруса `mini`, а `--judge-tier` и `--judge-model` его меняют.
- `21-first-person-gender` работает секцией «Судья», своего вызова `claude -p`
  в нём не осталось.
- В разделе «Судья-модель» в `prompt-test` стоят правило положительного
  критерия и ссылка на README стенда.
- Тесты по стандарту, разбор в README obeycheck и в скилле prompt-test.
