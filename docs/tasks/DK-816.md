# DK-816: Строка цели несёт свой тип goal вместо префикса «Цель:» в заголовке

записан 2026-09-05
приоритет: средний

## Черновик

### Ситуация

Цель на доске заведена строкой типа task с ценой XL. Утилиты узнают её по слову «Цель:» в начале заголовка. Так решено в LLD DK-079, развилка «цель как строка доски против отдельной сущности». Довод там был про цену. Новый тип пришлось бы протащить через taskctl, agentctl и lint, а заголовок никто не парсил, и признак стоил ноль строк кода. Замечено 2026-09-05 при просмотре цели DK-713 на дашборде. В колонке типа у неё стоит task.

### Осложнение

Посылка «заголовок не парсит никто» не держится. Сегодня префикс «Цель:» проверяют двенадцать файлов без тестов. Три из них в taskctl (view.go, ops.go, retclass.go), девять в дашборде вместе с app.js. Скрытый тип уже есть. Живёт он строковым сравнением заголовка, размазанным по двум утилитам, и каждое новое место повторяет ту же проверку. Форма файла у цели тоже своя, taskctl add не кладёт ей DoD. Исключение «кроме строк-целей» в RULES.board.md и в коде выводится из заголовка вместо колонки типа. Переименование заголовка руками ломает признак молча. Строка перестаёт быть целью для утилит, и сторожа на это нет.

### Вопрос

Оставлять ли слово «Цель:» в заголовке как человеческий маркер при типе goal, или дашборд рисует маркер сам по типу? Как переводить стоящие строки-цели, миграцией в taskctl lint --fix или разовой правкой доски? Нужна ли типу goal своя ветка вердикта в agentctl pick, или вердикт «сначала разбить» по цене XL остаётся как есть?

### Гипотеза

В колонке типа у цели стоит goal. Команда taskctl add --type goal заводит файл цели по её форме без DoD. Утилиты и дашборд узнают цель по типу через одну функцию вместо дюжины сравнений префикса. Заголовок цели можно переименовать без потери признака.
