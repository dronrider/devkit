# DK-822: Дашборд поднимается одной строкой установки devkit

## Что происходит

Захотел дать коллеге попробовать дашборд на его маке и сверил 2026-09-05 по
исходникам, что даёт строка из `CONNECT.md` («клон плюс `devkitctl update
--pin`»). Дашборда после неё нет вовсе, и причина не в доводке, а в релизе:
`--pin` переводит клон на новейший тег и дальше работает его кодом, а в
тарболле `v0.12.0` от 2026-08-07 бинаря `dashboard` нет, как нет в `devkitctl`
тега и проверки `dashboard.check`. Владелец живёт со сборкой из `main`
через `devkitctl build`, поэтому пробела не видел.

Даже на теге с дашбордом строка не доводит его до входа. Конфиг
`~/.devkit/dashboard.local` никто не заводит, умолчания для `root` нет, и
экран отвечает «нет ни одной строки root»; доктор на первом прогоне про это
молчит нарочно (конфиг ещё не родился), а `--fix` строку `root` не пишет.
Токен рождается при первом старте демона, но нигде не печатается: про
`dashboard secret` и адрес `http://localhost:7112/login` новичку узнать
неоткуда. На чистом маке нет brew, а это единственный пакетник devkit, и
tmux с terminal-notifier уходят в «осталось сделать» без слова о том, что
ставить первым.

## Чего хотим

Коллега на чистом маке вставляет одну строку из `CONNECT.md` и в конце вывода
видит адрес входа и токен. Открывает адрес, вставляет токен и видит доску
devkit из своего клона: он лежит в корне, у него есть `docs/TASKS.md`, витрина
бесплатная. Свой проект добавляется `devkitctl new`, дашборд подхватывает его
без рестарта.

Для этого в devkit меняется четыре места:

- `dashboard.check` с `--fix` до взвода агента заводит `~/.devkit/dashboard.local`
  правами 600 со строкой `root`, равной родителю чекаута devkit. Клон по
  `CONNECT.md` лежит в `~/projects`, корень напрашивается сам; клон в другом
  месте даёт другой корень, а не пустой список. Существующий конфиг не
  трогается.
- Хвост `update` и `doctor --fix` печатает адрес входа. Токен печатается,
  когда родился на этом же прогоне: машина та же, и лишний шаг новичку это
  лишний вопрос. На обновлениях одна строка «дашборд поднят, адрес». Браузер
  сам не открывается: `update` гоняется и при обновлениях.
- «Осталось сделать» называет brew с командой установки, а не только
  пакеты, которых им нечем поставить. Сам brew не ставится: это тот же
  `curl | sh`, от которого devkit уходит.
- `CONNECT.md`, раздел «Один раз на машину», и README дашборда описывают
  этот ход: что печатает строка, куда идти, что заработает без Claude Code и
  tmux (доска, чаты), а что нет (запуск задач, разговор с агентом).

## Границы

- Релизный тег ставит человек, автоматика его не двигает (README, «Версии и
  доставка»). Задача готовит код, а тег с `tools/dashboard` в тарболле
  выпускается после её слияния; без тега строка для коллеги по-прежнему
  ставит `v0.12.0` без дашборда.
- Xcode Command Line Tools на чистом маке ставит сам первый `git`, строку
  после этого повторяют. Обходить это devkit не берётся.
- Второй сценарий пробы, показать коллеге дашборд владельца через
  браузерный вход, не годится: токен один на весь дашборд, отдать его
  значит отдать запуск задач за квоту владельца.
- Claude Code доктор по-прежнему не ставит; проверять его наличие и называть
  в «осталось сделать» можно, но это не предмет строки.

## Развилки

- Сценарий проверки гоняется на машине с живым дашбордом владельца: тот же
  порт 7112 и та же метка launchd `ru.devkit.dashboard`. Второй демон на том
  же порту не встанет, а `launchctl bootstrap` с той же меткой столкнётся с
  живым агентом. Исполнителю решить, как стенд разводит их: переопределение
  порта и метки в конфиге временного дома либо проверка раскладки без
  реального подъёма демона (плист и конфиг на диске, демон поднимает
  `dashboard serve` руками на свободном порту). Выбор записать здесь.

## DoD

- В свежем доме (временный `HOME`, чекаут devkit внутри) `doctor --fix` кладёт
  `dashboard.local` с `root` родителя чекаута и правами 600, `/healthz`
  отвечает без ошибок конфига и `projects` не меньше 1.
- Хвост `update`/`doctor --fix` содержит адрес входа; при рождении токена
  печатается и токен. Проверяется тестом стенда devkitctl.
- «Осталось сделать» без brew на машине называет brew с командой установки.
- `CONNECT.md` и README дашборда описывают первый запуск шагами.

## Ранг

25+5+1+0+2 = 33 (M+1 = 34), P2

- Серьёзность 25: ручная работа с дешёвым обходом, владелец ставит дашборд
  руками, коллеге можно дать инструкцию из шести шагов.
- Ценность 5: каждая новая машина devkit получает дашборд без рук, но
  операция редкая, не ежедневная.
- Неопределённость 1: подход выбран (корень от чекаута, печать токена, brew
  не ставим), открыты детали раскладки в `update` на теге.
- Поправка на баг 0: новой работы больше, чем дефекта.
- Рычаг 2: ускоряет подключение машин к дашборду, дешевле каждую задачу не
  делает.

## Сценарий проверки

Шаги гоняются с временным домом, чтобы не трогать живой дашборд владельца.

```sh
home=$(mktemp -d) && git clone -q /Users/rider/projects/devkit "$home/projects/devkit" \
  && HOME="$home" python3 "$home/projects/devkit/tools/devkitctl/devkitctl.py" doctor --fix 2>&1 | tail -5
```

Ожидание: в хвосте строка с `http://localhost:7112/login` и строка с токеном.

```sh
grep -c '^root = ' "$home/.devkit/dashboard.local"; stat -f %Lp "$home/.devkit/dashboard.local"
```

Ожидание: `1` и `600`.

```sh
HOME="$home" curl -fsS localhost:7112/healthz
```

Ожидание: JSON с `"errors":[]` и `"projects":1` (доска клона devkit). После
прогона агент дашборда временного дома снимается, каталог удаляется.
