# DK-832: Поиск чатов панели достаёт разговор по слову из его реплик

## Что происходит

6 сентября 2026 искал в панели дашборда разговор про накопление черновиков и
погашение долга. Набирал в поле поиска шапки списка слова из самого разговора.
Список отвечал «по запросу ничего не нашлось». Разговор нашёлся грепом по
транскриптам, файл
~/.claude/projects/-Users-rider-projects-devkit/ed82119c-0f1e-474c-b066-30568b3668d2.jsonl.
Заголовок у него «Добавить ранжирование черновиков по приоритетам». Слова
«долг» в заголовке нет. Отбор живёт в chatDropOpen
(tools/dashboard/static/app.js, строка 8350). Он сверяет запрос с
заголовком, ID сессии, задачами и именем проекта. Поле first сервер отдаёт,
строка списка его рисует. В отбор оно не входит.

Разговор помнят по тому, о чём в нём говорили. Заголовок слеплен из первой
фразы и этих слов обычно не несёт. Поиск отвечает пустотой на верный запрос.
Человек уходит гнать grep по ~/.claude/projects руками.

Рядом стоит горизонт. Набранный запрос снимает окно суток (`days=0`), но
потолок `chatAllLimit = 160` остаётся при нём (chats.go:696 и 1096). На машине
сейчас 3358 сессионных транскриптов, и поиск видит меньше пяти процентов из
них. Кнопки «показать раньше» при наборе запроса нет вовсе (app.js, условие
`if (!q && st.older && st.days && !loading)`). До разговора постарше не
дотянуться ни поиском, ни рукой.

### Проверено разбором

Отбор в `chatDropOpen` (app.js:8350) сверяет запрос с заголовком, ID сессии,
задачами и именем проекта, тела в нём нет. Находка воспроизводится сегодня.

Первый сосед снялся. Кнопка управляет только пустым запросом, набранный запрос
ищет по всей машине мимо неё. Так решила закрытая DK-726, и комментарий в коде
это прямо называет. Задача сюда не лезет.

Замер на машине 2026-09-08. Сессионных транскриптов 3358 на 590 Мб. Греп по 160
свежим отвечает за 0.73 с, по всей истории за 3.7 с. Индекс на этих числах себя
не окупает, и развилку «движок» решил этот замер.

Дублей нет: по доске, архиву и накопителю рядом стоят DK-726 (поиск мимо архива
и окна, закрыта) и DK-847 (состав списка), обе про другое.

## Чего хотим

Разговор находится в панели по любому слову, которое в нём звучало. Возраст
разговора и положение кнопки архива на выдачу не влияют.

## Границы

Задача меняет отбор строк списка и ничего кроме. Положение кнопки архива,
ступени окна суток, вид строки и порядок групп остаются как есть. Индекс тел на
машине не заводится ни в каком виде.

## Развилки

- «движок»: поиск по телу разговора идёт грепом по транскриптам в момент запроса или по индексу, который дашборд держит на машине?
  - решает: человек
  - рекомендация: греп по запросу без индекса: замер на машине 0.73 с по 160 свежим транскриптам и 3.7 с по всем 3358, индекс себя не окупает
  - решено человеком 2026-09-08: греп по транскриптам в момент запроса, индекса не заводим: замер 0.73 с по 160 свежим и 3.7 с по всей истории, хранилище себя не окупает
- «горизонт»: потолок chatAllLimit=160 при наборе запроса остаётся или поиск идёт по всем транскриптам машины?
  - решает: человек
  - рекомендация: поиск идёт мимо потолка 160 по всей истории машины: 3.7 с терпимо, надпись «ищем по всей машине...» в списке уже стоит
  - решено человеком 2026-09-08: поиск идёт мимо потолка 160, по всей истории машины, как сейчас идёт мимо окна суток
- «место»: поиск по телу живёт в том же выпадающем списке панели или отдельной ручкой рядом с ним?
  - решает: человек
  - рекомендация: тот же список панели: отбор уезжает на сервер, а поле поиска и строки выдачи остаются прежними, второму экрану учиться незачем
  - решено человеком 2026-09-08: поиск живёт в том же выпадающем списке панели, на сервер уезжает только отбор
- «тело»: телом разговора считаются реплики человека и агента или весь транскрипт вместе с выводом инструментов?
  - решает: человек
  - рекомендация: искать по репликам человека и агента, вывод инструментов и системные вставки мимо: иначе слово из чужого лога вытащит десяток лишних разговоров
  - решено человеком 2026-09-08: телом считаются реплики человека и агента, вывод инструментов и системные вставки мимо отбора

## DoD

Слово, звучавшее в разговоре, находит его в поиске панели. Заголовок этого
слова не несёт, разговор старше потолка 160, находка всё равно приходит. Отбор
идёт по репликам человека и агента, вывод инструментов в выдачу не попадает.
Стенд дашборда проверяет находку по телу и молчание на слово из чужого вывода.

## Ранг

`25+6+3+0+2 = 36`, P2, цена M, приёмка agent.

- Серьёзность 25: разговор из панели не пропал, обход есть и человек им уже
  пользовался, грепом по `~/.claude/projects` руками.
- Ценность 6: разговор ищут в панели каждый день, а помнят его по тому, о чём
  в нём говорили, и заголовок этих слов обычно не несёт.
- Неопределённость 3: подход после разбора выбран целиком. Правка идёт через
  границу сервера и клиента, отбор переезжает в Go новым ключом запроса. На
  такой границе `RANKING.md` держит пол 3.
- Поправка на баг 0: отбора тела раньше не было, это новое поведение, а не
  сломавшееся старое.
- Рычаг 2: своя польза по работе с панелью, чужую работу находка не затрагивает.

Приёмка agent. Итог виден на экране, а барьер «глаза» снимается стендом по
разметке и ручкой сервера, как у DK-726 (`testdata/poc_chatfind.mjs`). Доступа,
секрета, необратимого шага и внешнего события тут нет, согласия задача не
просит. Условий, посильных только человеку, не нашёл.
