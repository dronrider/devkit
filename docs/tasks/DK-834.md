# DK-834: Развилки задачи хранятся машинно: разбор перечня и команда taskctl decide

Цель: [tasks/DK-565.md](tasks/DK-565.md)

## Что происходит

Раздел «Развилки» у файла задачи стоит в форме
(`internal/taskform/taskform.go:26`), а пишется он прозой. Состояния у развилки
нет, автора решения нет, признака «держит старт» тоже нет. Прочесть такой
раздел кодом нечем.

Так уже вышло на DK-460. Три вопроса человеку легли в сценарий проверки
прозой, и там их не увидел никто, кроме читателя документа. Ворота старта
DK-804 и ворота закрытия садятся на этот же перечень. Читать им пока нечего, а
постановке нечем писать.

Формат перечня дало решение 1 LLD DK-552: голова развилки, четыре подстрочные
формы, три состояния из двух полей. Строка идёт в цели первой, за ней ворота и
скилл интервью.

## Чего хотим

Перечень развилок читается кодом. Разбор лежит в `internal/taskform` рядом с
`Exception` и `IsReviewLevel`, читают его `taskctl`, ворота `shipctl` и
дашборд. Второй копии регулярки нет ни у кого. Читается только тело раздела
«Развилки» мимо ограждённых блоков, и вывод команды, вложенный в «Проверку»,
развилок не заводит.

Пишет перечень команда `taskctl decide`. Она заводит развилку, закрывает её
сегодняшней датой, оставляет исполнителю и печатает состояния. Она сама ставит
штампы даты и автора. Ручная правка раздела остаётся законной, форма записана
в `TASKFORM.md`, а `taskctl lint` называет подстроку не по форме и повтор
имени.

При заведении наследной строки перенос больше не остаётся незамеченным.
`taskctl add --link` печатает открытые развилки файла цели, и тот, кто режет
цель, видит, что переносить.

## DoD

- `taskctl decide <ID> --ask «имя» "вопрос"` заводит открытую развилку, а
  повторный `--ask` на занятое имя отказывает и называет имя.
- `decide <ID> «имя» --by человек "ответ"` дописывает строку `решено человеком
  <дата>`, закрытие незаведённого имени отказывает.
- `decide <ID> --open` печатает только открытые, а развилку `решает:
  исполнитель` показывает оставленной.
- Запись команда находит по ID в черновике, файле задачи и файле цели, на
  архивный ID отказывает.
- Голова вида `- «имя»:` вне раздела «Развилки» и внутри ограждённого блока в
  перечень не идёт.
- `taskctl lint` называет подстроку не по форме, повтор имени и строку
  `оставлена` при `решает: человек`.
- `taskctl add --link` печатает открытые развилки файла цели, на который
  ссылается новая строка.
- Строка `TASKFORM.md` про «Развилки» переписана на форму, README `taskctl`
  получил раздел с первым запуском.
- Тесты по стандарту.

## Сценарий проверки

Шаги гоняются из корня чекаута. Третий правит файл этой задачи и возвращает его
гитом в том же блоке.

1. Разбор перечня в общем пакете. Четыре подстрочные формы, три состояния из
   двух полей, второе `решено` под той же головой, проза при развилке и голова
   внутри ограждённого блока.

   ```sh
   GOWORK=off go -C "$(git rev-parse --show-toplevel)/internal" test ./taskform/... -count=1 -run "TestForks" -v
   ```

   Ожидание: строка `PASS`, среди подтестов случай ограждённого блока и случай
   повторного `решено`.

2. Команда и печать переноса. Четыре входа `decide`, поиск записи по ID, отказы
   и открытые развилки цели на `add --link`.

   ```sh
   GOWORK=off go -C "$(git rev-parse --show-toplevel)/tools/taskctl" test . -count=1 -run "TestDecide|TestAddLink" -v
   ```

   Ожидание: строка `PASS`, среди подтестов отказ на повтор имени, отказ на
   незаведённое имя и отказ на архивный ID.

3. Живой заход на файле этой задачи. Развилка заводится, повторяется,
   закрывается и печатается, файл возвращается гитом.

   ```sh
   root="$(git rev-parse --show-toplevel)"; taskctl decide DK-834 --ask «проба» "проба сценария"; taskctl decide DK-834 --ask «проба» "второй раз"; taskctl decide DK-834 «проба» --by человек "закрыта прогоном"; taskctl decide DK-834 --open; git -C "$root" checkout -- docs/tasks/DK-834.md; git -C "$root" status --short docs/tasks/DK-834.md
   ```

   Ожидание: второй `--ask` отказывает и называет «пробу», после закрытия
   `--open` её не печатает, `git status` по файлу пуст.

4. Сторож формы и дока. Находки `lint` и место формы в двух страницах.

   ```sh
   root="$(git rev-parse --show-toplevel)"; taskctl lint; grep -n "решает: человек" "$root/TASKFORM.md"; grep -n "decide" "$root/tools/taskctl/README.md" | head -3
   ```

   Ожидание: `taskctl lint` не называет файлов задач цели DK-565, в
   `TASKFORM.md` стоит форма подстроки `решает`, в README `taskctl` есть раздел
   про `decide` с первым запуском.
