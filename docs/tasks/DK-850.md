# DK-850: Экран архивной задачи в дашборде: тот же состав, что у живой, только без правки

## Что происходит

Закрыл задачу и открыл её экран в дашборде, чтобы посмотреть, какие задачи она
держала, и взять их в работу. Зависимостей на экране нет. Кроме них у архивной
строки пропало почти всё: тип, приоритет, цена, связи с LLD, план агента,
полоса действий. Остались файл постановки, дата закрытия и кнопка разговора.

Где теряется, по разведке:

- `tools/dashboard/tasks.go`, `handleTask`: у закрытой строки ранний выход с
  пустыми `after` и `blocks`, `taskDeps` и `taskLinks` не зовутся вовсе.
- `tools/dashboard/goal.go`, `archiveRows`: из шести колонок архива читаются
  две (заголовок и дата), тип и приоритет выбрасываются, дальше в строку
  подставляются `task` и `-`.
- `tools/dashboard/static/app.js`, `renderTask`, ветка `row.closed`: собирает
  страницу с `has: {file, read, chat}`, карточка зависимостей и связи не
  рисуются, `return` обрывает план агента и журнал витка.
- `tools/taskctl/dep.go`, `cmdDepList` и `json.go`, `cmdDepListJSON`: отказ
  «нет на доске» для любого ID вне доски, хотя `depSides` уже считает, кого
  держит архивная строка (маркеры `[после X]` живут на доске и целят в архив).
- `tools/taskctl/ops.go`, `cmdClose`: суффикс `[после ...]` в архивную строку не
  переносится и вычищается из чужих строк. Направление «от кого зависела»
  после закрытия не восстановимо из текстов доски и архива.
- `tools/taskctl/view.go`, `cmdShow`: у архива две строки без зависимостей и
  без пути файла постановки, `show --json` без `blocks` и `file`.

## Чего хотим

Экран архивной задачи показывает всё, что показывает экран живой: строку с
типом, приоритетом, ценой и датой закрытия, зависимости в обе стороны, связи,
файл постановки, план агента и журнал, полосу действий без правящих кнопок.
Разница одна: править архивную строку нельзя, и экран говорит об этом словами
там, где у живой стоит карандаш.

## DoD

- `taskctl dep list <ID>` и `--json` отвечают по архивному ID: кого держит
  (строки доски с маркером на этот ID) и после кого шла, если известно.
- `taskctl show <ID>` для архива печатает зависимости и путь файла постановки,
  `show --json` отдаёт `blocks` и `file`.
- Ручка `GET /api/projects/{p}/tasks/{id}` для закрытой строки отдаёт `after`,
  `blocks`, `links` и полную строку архива (тип, P, дата, ссылка).
- Ветка `row.closed` в `renderTask` рисует карточку зависимостей, связи, план
  агента и журнал, полоса действий без кнопок правки, на месте карандаша
  пояснение «архив, правки нет».
- Направление «после кого» у архивной строки: либо `close` сохраняет суффикс в
  архивной строке, либо экран честно пишет, что для старых закрытий оно
  неизвестно. Развилку решает исполнитель и записывает исход здесь.
- Тесты: `runs_test.go` (экран закрытой задачи с `after`/`blocks`),
  `tasks_test.go` (разбор ветки `row.closed`), `dep_test.go` и `json_test.go`
  (dep list по архивному ID), `ops_test.go` (show для архива). Тест бага
  красный на старом коде через regcheck.
- README дашборда и taskctl: абзац про экран архивной задачи и dep list по
  архиву.

## Ранг

- Серьёзность 25: заметное трение, обход дешёвый: грепнуть доску по
  `[после <ID>]` или позвать `taskctl dep list` без ID.
- Ценность 6: операция после каждого закрытия, просят вслух.
- Неопределённость 3: подход ясен, развилка про хранение «после» в архиве.
- Баг +5: экран обещает задачу, а показывает обрубок.
- Рычаг 4: следующая работа берётся сразу с экрана закрытой, без обхода.
