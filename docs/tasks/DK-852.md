# DK-852: Голова разговора выглядит субагентом, и agentctl plan ей отказывает

## Что происходит

Дашборд поднимает задачу оболочкой task-run.py в tmux-сессии task-<ID>. Голова
разговора там одна. План она ведёт по адресу DEVKIT_TMUX без метки.

Разговор DK-614 открылся, и agentctl plan set отказал. Причина в отказе
названа так: «ты субагент (CLAUDE_CODE_CHILD_SESSION=1)». Переменную положил
не харнес. Сервер tmux на машине был поднят из дочерней сессии Claude. Его
глобальное окружение (tmux show-environment -g) держит CLAUDE_CODE_CHILD_SESSION=1
и чужой CLAUDE_CODE_SESSION_ID. Каждое новое окно tmux наследует обе пары, и
голова разговора выглядит субагентом. Руками это обходится, переменная снимается
в окружении самой команды.

### Замер

Метку кладёт сам клиент уже внутри окна, и снаружи её не снять. Показал это
прогон 2026-09-07 в живой сессии, поднятой дашбордом в окне
task-DK-852. Строка окна начинается с `/usr/bin/env -u ...` со всеми
одиннадцатью переменными `foreignVars` из `tools/dashboard/chats.go`. Соседи
метки по тому же списку, `CLAUDE_PROJECT_DIR` и `CLAUDE_ENV_FILE`, у сессии
пустые, хотя глобальное окружение сервера tmux держит их от чужой сессии
другого проекта. Чистка при подъёме отработала. А `CLAUDE_CODE_CHILD_SESSION=1`
у сессии всё равно стоит, и `CLAUDE_PID` с сокетом обмена стоят её собственные.

Второй прогон снял окружение с живого субагента этой же сессии. У субагента
`CLAUDE_CODE_CHILD_SESSION=1`, `CLAUDE_CODE_SESSION_ID` и `CLAUDE_PID` те же
самые, что у головы, до символа. Клиент 2.1.261 ставит метку обоим.
Различителя головы и субагента в окружении не осталось ни одного. Пару
`DEVKIT_PLAN_LABEL`, которую `agentctl plan` читает как метку субагента, в
devkit никто не кладёт, её только читают.

Отказ вдобавок говорит неправду про ID сессии, у головы он свой.

Третий замер, 2026-09-15, снял tmux с подозрения совсем. Клиент 2.1.263
запущен вне tmux печатным режимом, в окружении ни одной пары `CLAUDE_*` и
нет `TMUX`. В его Bash стоят `CLAUDE_CODE_CHILD_SESSION=1` и `CLAUDECODE=1`.
Метку кладёт клиент в окружение каждого вызова Bash, у головы и у субагента
одинаково. В окружении самого процесса `claude` её нет. Отказ по этой метке с
2026-09-06 по 2026-09-14 получили сто девятнадцать сессий, все на клиентах
2.1.261 и 2.1.263. Чат доски после отказа кладёт план с меткой, и кольцо в
шапке остаётся тёмным (черновик DK-991). Ту же переменную читает
`no_plan_applies()` в `hooks/plan-watch.py`. Сессию с меткой признак «плана
нет вовсе» (DK-978) не смотрит, и на этом клиенте он не срабатывает ни у
кого.

## Чего хотим

Ворота по `CLAUDE_CODE_CHILD_SESSION` снимаются. Планы пачки друг поверх друга,
ради чего ворота ставила DK-527, держит положительная метка. Субагент зовёт
план с `--label`, и требование метки живёт там, где субагент поднимается.

Той же строкой едет чистка окружения в подъёме головы `task-run.py`. Сейчас
`raise_head` копирует окружение целиком и снимает одну метку печатного режима.
Дорога `send-keys` в живой шелл идёт мимо чистки тем же порядком.

## Границы

Сторожок доктора на метки Claude в глобальном окружении сервера tmux в объём не
входит, его отрезали на разборе. Наследство оттуда снимает `dropForeign`
(DK-691).

Предмет соседней строки DK-683 задача не берёт. Её пункт про замер закрывает
раздел «Замер» выше, наследование `CLAUDE_CODE_CHILD_SESSION` в чужие сессии
проверено.

переменные перед запуском claude. Сама agentctl plan может при DEVKIT_TMUX без
метки считать сессию головой.

  - решено человеком 2026-09-07: снять ворота по CLAUDE_CODE_CHILD_SESSION: различителя в окружении нет, планы пачки держит положительная метка --label

  сессию по `CLAUDE_CODE_CHILD_SESSION` и снова ловит чат без плана на втором
  ходе (DK-978).

## Сценарий проверки

Машинные шаги гоняются из корня чекаута devkit, утилиты берутся из того же
дерева.

1. Голова разговора со своим ID сессии кладёт план, хотя метка субагента в
   окружении стоит. Прежде тут приходил отказ «ты субагент
   (CLAUDE_CODE_CHILD_SESSION=1)», и обходился он снятием метки через `env -u`.

```sh
CLAUDE_CODE_CHILD_SESSION=1 CLAUDE_CODE_SESSION_ID=dk852probe agentctl plan set "разведка" "правка с тестами"
```

Ожидание: команда печатает план сессии dk852probe с двумя пунктами и кончается
кодом 0, слова про субагента в выводе нет.

2. План лёг по имени сессии, файлом без метки.

```sh
ls "$HOME/.devkit/plans"
```

Ожидание: в каталоге лежит `dk852probe.json`.

3. Субагент зовёт план с меткой и пишет свой файл, а план головы остаётся на
   месте.

```sh
CLAUDE_CODE_CHILD_SESSION=1 CLAUDE_CODE_SESSION_ID=dk852probe agentctl plan set --label dk852 "работа субагента"
CLAUDE_CODE_SESSION_ID=dk852probe agentctl plan show
```

Ожидание: показ печатает план сессии dk852probe с двумя пунктами и следом план
субагента dk852 с одним.

4. Признак «плана нет вовсе» учитывает и сессию с меткой субагента в
   окружении. На втором ходу подряд с вызовами инструментов между отметками

   ходом без всякого обхода. Блок ниже намеренно стоит без языка. Обкатка
