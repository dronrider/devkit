# DK-859: Новый чат в освободившемся окне tmux склеивается с архивными заходами прежних жильцов

## Что происходит

2026-09-07 в 11:58 в дашборде завёл новый чат кнопкой «+» и написал первую
реплику. Сессию подняло в окне `chat-3`, запись выросла в сессию 51d590a4, и
панель встала на неё: сторона DK-851 отработала. Лента при этом открылась
чужой историей. Сверху стояли «заход 1 из 3, сессия 8b13a2c7» и «заход 2 из
3, сессия 491b4787», оба разговора давно в архиве, а своя реплика лежала в
самом низу. Для пользователя это выглядит как склейка нового чата с прежним
диалогом.

Имя `chat-3` до этого держали два разговора, 6 сентября и утром 7 сентября.
Свободные номера `chatNewName` (`chats.go`) раздаёт заново, как только окно
снято. Склейка заходов одного окна (DK-723, `chatpast.go`, `chatGlue` и
`chatPasses`) ключуется по проекту и имени окна и сводит в один разговор все
сессии, чья последняя запись реестра носит это имя. Архивность строк при этом
не проверяется, а окно, которое освобождалось между жильцами, считается тем
же самым. Побочно тем же способом к любому чату приклеится прежний жилец
любого переиспользованного номера.

## Чего хотим

Заход это продолжение того же разговора, а не всякий жилец имени. У чата,
поднятого в переиспользованном окне, список прошлых заходов пуст, а лента
начинается с его первой реплики. Архивные разговоры в заходы не попадают
никогда.

## Границы

Склейка DK-723 для конвейера задачи (окно `task-<ID>`, перезапуски одного
разговора) остаётся. Разница в том, освобождалось ли окно между записями:
момент подъёма лежит в памяти окна `tmux-<name>.json` полем `raised`, тот же
порог, что DK-851 ввела в `tmuxClaim`. Второй кандидат на правку это сама
раздача номеров: `chatNewName` мог бы не отдавать имя, по которому в реестре
есть записи неархивных разговоров, но это лечит симптом, а не склейку.

## DoD

Стенд по образцу `TestChatListGluesWindowPasses` в `chatpast_test.go`: две
записи реестра с окном `chat-3`, старая помечена архивом, tmux показывает
окно живым только у новой. Ожидание: у новой сессии `Past` пуст, лента
состоит из одной реплики без разделителя «заход 1 из 2». Тест красный на
нынешнем коде. Случай конвейера задачи (два захода одного `task-<ID>` без
освобождения окна) остаётся склеенным, и это держит существующий тест.

## Сценарий проверки

Шаги гоняются из корня чекаута main после слияния. Окружение это go на машине,
сеть и живой дашборд не нужны. Первый шаг показывает красноту стенда на коде до
правки: база берётся у родителя первого коммита задачи, тронувшего склейку.
Каждый шаг это одна строка.

```sh
cd tools/dashboard && GOWORK=off go test ./ -run 'TestChatListSplitsWindowTenants|TestChatListKeepsArchivedOutOfPasses|TestChatListGluesWindowPasses|TestChatListGlueHeadIsWindowHolder|TestChatFeedGluesPastPasses|TestChatTmuxNameBetweenOwnersIsNobodys'
```

Ожидание: строка `ok`, склейка заходов конвейера и порог имени живы вместе с
новыми стендами.

```sh
regcheck -C tools/dashboard --base "$(git log --reverse --format=%H --grep='DK-859' -- tools/dashboard/chatpast.go | head -1)^" --tests tools/dashboard/chatpast_test.go -- env GOWORK=off go test -run 'TestChatListSplitsWindowTenants|TestChatListKeepsArchivedOutOfPasses' .
```

Ожидание: строка «тест краснеет на ... и проходит на текущем коде, регрессия
закрыта».
