# DK-879: Служебный чат подписан задачей и ролью без haiku, чип не дублирует номер, полоса чипов уже

## Что происходит

Дашборд называет чаты лестницей titleFor в tools/dashboard/chats.go. Сначала берётся запись summary транскрипта, потом сохранённый заголовок в ~/.devkit/chats, потом эвристика titleTrim. Фоном идёт заказ у haiku отдельным процессом `claude -p --model haiku` из каталога ~/.devkit/titles.

Замер сделан 2026-09-09 по этой машине. Транскриптов с записью summary ноль из 3373, с записью ai-title 1743. Заказов haiku по dashboard.log с 1 сентября 308. Ещё 17 транскриптов заказа лежат в ~/.claude/projects под именами тестовых каталогов. Вызова titleAsk из go-тестов при разборе 2026-09-22 не нашлось, транскрипты под каталогами проб оставили ручные пробы дашборда, у `go test` таких вызовов нет.

Claude Code сам пишет запись `{"type":"ai-title","aiTitle":"..."}` сразу после первой реплики человека, до первого ответа модели. У интерактивных сессий она есть почти всегда. На подписке glm-code она тоже есть, и генерирует её endpoint подписки. У сессий печатного режима `-p` записи нет. Команда `/rename` и флаг `claude --name` пишут запись `custom-title`. Флаг проверен и в печатном режиме. Шапку читает readSessionHead в sessions.go, и чтение обрывается после Branch и First. До ai-title оно не доходит.

У других агентов та же развилка. OpenCode и Goose называют сессию своей дешёвой моделью на первой реплике. Codex CLI и Gemini CLI показывают первую реплику. Второй процесс поверх харнеса ради заголовка не поднимает никто.

### Проверка на разборе

Сверил 2026-09-22 на этой машине, клиент 2.1.263. В каталоге транскриптов devkit 548 файлов, записей `summary` ноль, `ai-title` в 429, `custom-title` в одном (проба `claude --name`). В dashboard.log с 10 августа 518 записей «назван haiku», среди них и чаты, поднятые самим дашбордом: заказ «Проведи груминг DK-920» haiku переименовал в «Проведи груминг черновика задачи DK-920», а прогон Check в «Запуск агентской проверки выкаченного кода». Флаг `-n, --name <name>` в справке клиента есть. Дашборд ни `ai-title`, ни `custom-title` не читает и `--name` не ставит (grep по tools/dashboard пустой).

Дополнение от 2026-09-22. У сессий, которые дашборд поднимает сам, предмет известен до первого токена: груминг, выполнение и продолжение задачи, цель, прогон Check. Имя таким чатам считается из ID и роли заказа без вопроса к модели. Тогда все заходы одной задачи подписаны одинаково, заголовок короткий и умещается в строку списка на смартфоне, а квота на украшение не тратится. Чат, поднятый рукой из терминала словами заказа («Выполни DK-5»), флага не получает и остаётся с именем из транскрипта. Узнавание по тексту подписало бы именем работы любой разговор со случайно совпавшими словами.

Замечания пользователя 2026-09-22 по примерам. Номер задачи в заголовке дублирует чип задачи той же строки, чип на смартфоне громоздкий и отнимает место у заголовка, а заголовок из одного слова роли без номера непонятен. Есть чаты с номером в заголовке и без чипа. Замер по живому списку из 79 чатов: у 14 строк номер в заголовке и чип, у 7 номер без чипа. Чип собирает ownTasks из касаний реестра (задачи, которых сессия касалась командами доски) плюс ID из имени дерева, а привязка запуска, которой дашборд сам поднял сессию под задачу (bindTask, tmux task-DK-972 и chat-DK-909-1), в чипы не едет: у сессии цели DK-909 и у мёртвой сессии выполнения DK-972 чипа нет при заголовке с номером.

Заголовок появляется с задержкой на подъём отдельного клиента, а заказов на заход списка по два. Каждый заказ жжёт токены подписки по умолчанию на украшение списка. Механика привязана к одному поставщику, и чат на glm-code называется haiku с claude-code. Заказы из тестов тратят квоту на каждом прогоне.

Обход 2026-09-22 нашёл три сборщика команды клиента: chatCmd для чатов, groomCmd для груминга и профиль `[head]` харнеса (internal/taskhead, kit/harness/*.toml) для конвейера задачи, прогона Check и второго круга ревью; флаг ложится во все три, а у профиля это новый ключ TOML. Чтение шапки транскрипта (readSessionHead) обрывается на первой реплике человека, а запись ai-title лежит после первого ответа модели, и дочитывать надо до неё. Порядок лестницы после правки: custom-title, ai-title, summary, эвристика первой реплики.

## Чего хотим

Чат в списке дашборда получает заголовок через секунды после первой реплики без отдельного процесса и без токенов дашборда. Сессии, поднятые дашбордом с известным предметом, названы до первого токена. Тем же именем они видны в окне терминала и в списке `claude --resume`. Заголовок чата второй подписки пишет её же модель. Тесты дашборда в живого клиента не ходят, и сторож этого стоит в самих тестах.

## Границы

Совместимость `--name` с `--resume` проверяется пробой на клиенте до правки продолжения: у резюма имя уже есть в транскрипте, и флаг там либо лишний, либо переписывает custom-title. Имя чата и заголовок строки доски это разные поля, регулярки по «Цель:» в app.js смотрят на строку доски и правкой не трогаются.

## DoD

Чат, поднятый дашбордом с известным предметом (груминг, выполнение, продолжение и закрытие задачи, прогон Check, цель), стоит в списке чатов под коротким именем из ID и роли с первой секунды, и то же имя видно в `claude --resume`. Свободный чат подписан записью custom-title или ai-title из транскрипта без отдельного процесса. Заказ у haiku, каталог ~/.devkit/titles, метка служебной сессии и фильтр titleSession сняты из кода, в dashboard.log записей «назван haiku» после выката нет. Тесты дашборда клиента не поднимают, и это проверяет сам тест. Чип задачи у строки, чей заголовок начинается с того же номера, не рисуется, а чат, поднятый дашбордом под задачу, несёт чип задачи до первой команды доски. Полоса чипов строки чата на смартфоне уплотнена так, что заголовок и полоса умещаются в две строки экрана шириной 360 px. README дашборда описывает лестницу заголовка и состав полосы чипов заново.
