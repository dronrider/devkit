# DK-888: go:dashboard тесты красные на main: talk_state пуст у чата без хода

## Что происходит

Находка при слиянии DK-880. Ветка DK-880 не трогает `tools/dashboard`, а
`shipctl merge` всё равно отказал: полный прогон `tools/devkitctl/parallel.py`
на свежем ребейзе на main красный по компоненту `go:dashboard`. Проверено
отдельно, вне ветки DK-880, прямо на HEAD main (`0c4119b0`), `git status` в
основном дереве чист:

```
$ cd tools/dashboard && GOWORK=off go test ./... -run \
  'TestRunStopInterruptsChatWork|TestBoardRowTalkStateWithoutWork|TestRowStaysBusyWhileSubagentWorks' -v
=== RUN   TestRunStopInterruptsChatWork
    runchat_test.go:119: строку не ведёт разговор с ходом: run="" busy=false
--- FAIL: TestRunStopInterruptsChatWork (0.01s)
=== RUN   TestBoardRowTalkStateWithoutWork
    runchat_test.go:329: строка молчит о живом разговоре: talk_state="" talk_chat=""
--- FAIL: TestBoardRowTalkStateWithoutWork (0.01s)
=== RUN   TestRowStaysBusyWhileSubagentWorks
    stopwait_test.go:153: строка с живой фоновой работой простаивает: state="" busy=false
    stopwait_test.go:156: признак работы строки "", ожидал "chat"
--- FAIL: TestRowStaysBusyWhileSubagentWorks (0.01s)
```

`go clean -testcache` перед прогоном находку не снимает. Последний коммит,
тронувший `runchat_test.go` и `stopwait_test.go`, это `cf75bbdc` (DK-716,
«замечания 13 и 14 закрыты, шаг сценария на шесть состояний окна»,
2026-09-06). Тесты ждут, что строка без активного хода, но с живым чатом или
фоновым субагентом, несёт признак `talk_state`/`busy`, а код отдаёт пустые
значения. Открытой задачи про эту красноту на доске не было.

## Чего хотим

`go test ./...` в `tools/dashboard` зелёный на main, и `shipctl merge` любой
задачи, не трогающей dashboard, снова проходит полный прогон без отказа по
чужому компоненту.
