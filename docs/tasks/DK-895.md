# DK-895: Правило автономии кроет любой маршрут выката, не только shipctl merge

## Что происходит

Пункт 8 раздела «Ветки, ревью и деплой» в RULES.board.md описывает автономию одним маршрутом. Задача готова, агент зовёт `shipctl merge`, merge пушит и катит выкат из конфига. Ядро RULES.core.md говорит «Push в origin делает пользователь. Ассистент останавливается на локальном коммите и ждёт явной команды». Что делать, когда команда пришла (`DEVKIT_PUSH_OK=1`, `shipctl push`), сказано только в полном тексте RULES.md, пункт 3 раздела «Git». В сессии XR-294 (2026-09-09) багфикс лёг в main без ветки, выкат нужен был не дефолтный, а релиз APK. Пользователь дважды написал «задеплоить всё», `autonomous = true` стоял в конфиге. Агент вернул четыре шага пользователю, из них три мог сделать сам, и после вопроса «почему сам не сделал» сделал их. `shipctl push` прошёл с первого раза, `release-apk.sh --dry-run` прошёл весь путь, релиз 0.111.0 залился на оба хаба.

Резидентное ядро перевешивает исключение, сказанное одной строкой в хвосте и раскрытое только в полном тексте. Это второй раз на той же развилке. В DK-205 диспетчер остановился перед merge при autonomous=true, разбор лёг в DK-191 и в память, и починка была точечной под `shipctl merge`. Теперь тот же провал повторился на соседних шагах, на пуше main и на релизе компонента по своему ключу. Каждый повтор стоит пользователю хода с упрёком и часа задержки выката.

## Чего хотим

Пункт 8 говорит, что при autonomous=true агенту доверен любой компонент и любой маршрут, включая багфикс в main без ветки и выкат по своему ключу компонента. Без ключа отказывает утилита (DK-894). Ядро в строке про push называет действие по команде. По явной команде пользователя пуш идёт через `shipctl push`, при автономии агент катит сам. Пользователю остаются только физические барьеры вроде проверки на устройстве. Стенд obeycheck держит сценарий с этой развилкой.

## Границы

- Промпты исполнителей `kit/agents/exec-*.md` не трогаются, они предмет DK-792.
- Механика выбора ключа выката у `shipctl` не трогается, она предмет DK-894.
- Условий, посильных только человеку, не нашёл. Правка текстовая, ни доступа,
  ни секрета, ни чужой команды ей не нужно, а формулировки утверждаются на
  ревью.

## DoD

- Пункт 8 раздела «Ветки, ревью и деплой» в `RULES.board.md` говорит про любой
  маршрут выката, а не про один `shipctl merge`. Названы багфикс, который лёг в
  main без ветки, и компонент, который катится своим ключом. При
  `autonomous = true` их катит агент сам, а пользователю остаются физические
  барьеры вроде проверки на устройстве.
- Строка про push в ядре `RULES.core.md` договорена до конца. По явной команде
  пуш идёт через `shipctl push`, при автономии агент катит без слова. Умолчание
  прежнее, и репозиторий без доски работает как раньше.
- Пункт 3 раздела «Git» в полном `RULES.md` говорит то же самое, что и ядро,
  без расхождения формулировок.
- В `tools/obeycheck/scenarios` стоит сценарий «autonomous и явное задеплой».
  Зелёный исход это вызов `shipctl push` и выкат, а возврат пользователю списка
  шагов красный. Сценарий не спорит с `04-no-push`, там ни доски, ни автономии
  нет.
- Прогон стенда по скиллу `prompt-test` лежит в файле задачи вместе с вердиктом.
