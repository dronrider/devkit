# DK-908: Тест свежести снимка квоты краснеет под нагрузкой параллельного прогона

## Что происходит

Находка при слиянии DK-860, 2026-09-10. Полный прогон `tools/devkitctl/parallel.py`
внутри `shipctl merge` отбил слияние по компоненту `go:agentctl`:

```
--- FAIL: TestQuotaStaleConfigured (10.05s)
    main_test.go:342: пятиминутный снимок без настройки должен быть свежим (<nil>):
        снимок .../TestQuotaStaleConfigured2556090958/001/.devkit/quota/claude-code.local
        снят 2026-09-10T15:54, возраст 6м
```

Тест кладёт снимок возрастом пять минут и ждёт, что порог свежести его пропустит.
Возраст меряется живым временем. Под параллельным прогоном девяти компонентов
разом заход провисел лишнюю минуту, и пятиминутный снимок дорос до шести минут.

Прогон того же теста в одиночку зелёный и на main, и в ветке задачи. Красноту
даёт только нагрузка.

Ложный отказ бьёт по воротам слияния: `shipctl merge` встаёт на первом провале и
не сшивает ветку, хотя правка ни при чём. Обход это повторный заход, но человек
об этом не знает и идёт разбирать чужой тест.

## Чего хотим

Прогон `parallel.py` под полной нагрузкой не даёт ложной красноты по свежести
снимка квоты.

## Границы

- Правка живёт в тесте. Порог свежести снимка в самой утилите остаётся прежним.
- Соседние тесты квоты не пересматриваются.

## DoD

Тест свежести снимка не зависит от того, сколько времени заход простоял в
очереди планировщика. Показано прогоном `parallel.py` целиком, краснота теста
показана `regcheck`.

## Ранг

`25+4+1+5+2 = 37`, P2.

- Серьёзность 25: ложный отказ ворот слияния, обход есть, это повторный заход.
- Ценность 4: доверие к воротам конвейера, отказ уводит разбираться в чужой код.
- Неопределённость 1: место известно, `tools/agentctl/main_test.go:342`.
- Поправка на баг 5: зелёный код объявлен красным, это дефект.
- Рычаг 2: следующие плавающие отказы конвейера гаснут вместе с этим.

## Сценарий проверки

Агентский. Тест краснеет под реальной нагрузкой на старом коде через
несколько десятков прогонов. Сценарий подставляет тот же исход напрямую.
Подпроцесс `run("quota")` под нагрузкой прочитывает время на минуту позже
записи, и снимок вместо «возраст 5м» показывает «возраст 6м» при том же
факте свежести. Шаг ниже накладывает эту подстановку на родительский коммит
(тест без правки DK-908) и на текущий коммит (тест с правкой) и сравнивает
исход.

- Исключение: regcheck (правка целиком лежит в самом тесте, старого кода под
  ней нет; краснота показана подменой снимка на родительском коммите, шаг 1)

1. Подмена и прогон на обоих состояниях теста:

```sh
root=$(git -C /Users/rider/projects/devkit rev-parse --show-toplevel); git -C "$root" show 9567256dc^:tools/agentctl/main_test.go > /tmp/dk908-old-main_test.go; cp "$root/tools/agentctl/main_test.go" /tmp/dk908-new-main_test.go; sed -i '' 's/-5 \* time.Minute/-6 * time.Minute/' /tmp/dk908-old-main_test.go; sed -i '' 's/-5 \* time.Minute/-6 * time.Minute/' /tmp/dk908-new-main_test.go; cp /tmp/dk908-old-main_test.go "$root/tools/agentctl/main_test.go"; GOWORK=off go -C "$root/tools/agentctl" test -run TestQuotaStaleConfigured -v -count=1 ./... > /tmp/dk908-old-out.txt 2>&1; old_rc=$?; cp /tmp/dk908-new-main_test.go "$root/tools/agentctl/main_test.go"; GOWORK=off go -C "$root/tools/agentctl" test -run TestQuotaStaleConfigured -v -count=1 ./... > /tmp/dk908-new-out.txt 2>&1; new_rc=$?; git -C "$root" checkout -- tools/agentctl/main_test.go; echo "родитель (rc=$old_rc):"; cat /tmp/dk908-old-out.txt; echo "текущий (rc=$new_rc):"; cat /tmp/dk908-new-out.txt; test "$old_rc" -ne 0 -a "$new_rc" -eq 0
```

   Родительский коммит краснеет по той же причине, что в находке. Сообщение
   содержит «возраст 6м», а тест ждёт ровно «возраст 5м». Текущий коммит
   остаётся зелёным при той же подмене.
2. `GOWORK=off go -C tools/agentctl test -count=1 ./...` без подмены зелёный
   целиком. Прогон сделан с очищенными переменными `DEVKIT_GOAL_SHELL` и
   `CLAUDE_CODE_CHILD_SESSION` окружения сессии. Без очистки краснеет
   `TestWatchRegisterNamesSessionAndCarrier`. Дефект вне предмета DK-908
   (утечка переменной цели в подпроцесс, известная отдельно).

## Из черновика DK-883 «TestQuotaStaleConfigured краснеет от возраста снимка на долгом прогоне» (записан 2026-09-09)

### Черновик

#### Ситуация

Полный прогон `python3 tools/devkitctl/parallel.py` на дереве DK-588,
2026-09-09. Компонент `go:agentctl` упал за 210 секунд:

```
--- FAIL: TestQuotaStaleConfigured (10.95s)
    main_test.go:342: пятиминутный снимок без настройки должен быть свежим (<nil>):
        снимок .../TestQuotaStaleConfigured1134754792/001/.devkit/quota/claude-code.local (харнес claude-code)
        снят 2026-09-09T13:01, возраст 6м
```

Повторный прогон одного этого теста (`go test -run TestQuotaStaleConfigured`)
проходит за 7 секунд. Тест кладёт снимок с меткой времени и ждёт, что тот
сойдёт за свежий. На загруженной машине между записью и проверкой набегает
больше пяти минут.

#### Осложнение

Первый провал валит весь прогон `parallel.py`, и шесть компонентов из
восемнадцати до прогона не доходят вовсе. Автор правки видит красноту, к его
диффу отношения не имеющую, и платит вторым полным прогоном.

#### Вопрос

Метку времени снимка в тесте брать сдвигом от `time.Now()` в момент проверки
или подменять часы утилиты?

#### Гипотеза

Прогон набора на загруженной машине краснеет только там, где сломан код.
