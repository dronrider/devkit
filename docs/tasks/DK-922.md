# DK-922: Ответ человека возвращает строку в работу, а сессию задачи поднимать некому

## Что происходит

2026-09-10, DK-914. Исполнитель задал вопрос «чужие коммиты» через
taskctl decide, и строка ушла в Blocked. Оболочка task-run.py по правилу
DK-400.2 погасила сессию task-DK-914 в 19:49 (дашборд: «прожила 1 ч 18 мин
и кончилась, следующая реплика поднимет продолжение резюмом»). Ответ человека
в 19:57 лёг в .devkit/chat/task-DK-914.in «без ведущей сессии». Тик сторожка
в 20:03 сделал move в in-progress («разбуждена ответом») и на этом кончил.
У задачи, запущенной рукой с дашборда, нет ни цели, ни пачки, ни планировщика.
В 21:07 и 21:23 чужие сессии пробовали адрес task-DK-914 и получали отказ
«разговор принадлежит не этой сессии». Тот же разбор был чатом в 19:59.

Человек отвечает на вопрос и ждёт, а строка стоит в in-progress с
непрочитанной репликой во входе, пока он сам не нажмёт «Запуск» заново.
Фраза дашборда про резюм по следующей реплике для припаркованной задачи
неверна. Повторяется каждый день у любой задачи, запущенной рукой и вставшей
вопросом.

### Проверено грумингом 2026-09-10

Предмет живой, обрыв цепочки прочитан в коде. Функция `wake`
(`tools/devkitctl/watch.py:1208`) поднимает строку по тику.
Она находит безадресный ответ во входе, вызывает `taskctl move <ID>
in-progress` с коммитом и пушем, снимает признак `.ask` и на этом заканчивает
работу. Так задумано решением DK-400.2. Комментарий там говорит, что строка
после `wake` становится кандидатом планировщика, а у задачи, поднятой рукой,
нет планировщика. Оболочка `task-run.py` к этому моменту уже вышла нулём по
стопу `wait_human` и снесла окно вместе с головой
(`kit/skills/board-task/task-run.py:858`, `:951`, `:978`). У неё нет режима
продолжения. Панель тоже никого не поднимает. Функция `handleTaskMessagePost`
(`tools/dashboard/chat.go:509`) записывает строку во вход и отвечает, что тик
вернёт задачу в работу.

Нужная развилка в проекте уже написана и работает вторым кругом чужого
ревью. Тик вызывает `dashboard round` (`watch.py:1115`), а `reviewRound`
(`tools/dashboard/round.go:31`) проверяет, жива ли сессия. Если окно есть,
реплика уходит клавишами, если окна нет, поднимается новая через
`startTaskSession`. Тем же путём страхует себя прогон сценария, `check_run` в
`watch.py:1346`. Целям подъём не нужен вовсе. Оболочка цикла не умирает на
вопросе, а сторожит признак сама (`kit/skills/goal-loop/goal-run.py:573`).

На доске нет дублей. Ближе всех цель DK-902. Её третий уровень («подъём это
новая голова, поднимает её команда `taskctl run <ID>` с лестницей носителей»)
накрывает этот случай, но цель стоит в Backlog нетронутой и не нарезана.
DK-898 про соседнюю поломку той же оболочки, DK-839 про вопрос из строки
Backlog, предмет у обеих другой. Условий, посильных только человеку, кроме
выбора исхода не нашёл. Машина своя, tmux и launchd на месте, autonomous
стоит.

## Чего хотим

Ответ человека на вопрос припаркованной задачи поднимает её сессию сам в
течение одного тика, и в чате видно продолжение без повторного «Запуска».

## Границы

## DoD

- Стенд стоит на временном репозитории с синтетической доской. Строка стоит в
  Blocked с разрядом «вопрос:», ответ ложится во вход, прогон тика поднимает
  окно задачи, и продолжение видно в ленте чата без нажатия «Запуска».
- Живой случай на этой машине. Человек ответил в панели, сессия поднялась,

  припаркованной строки либо переписана под то, что происходит на деле.

## Сценарий проверки

Команды гоняются из корня чекаута.

1. Стенд всей цепочки на временном репозитории. Строка стоит в Blocked с
   причиной «вопрос: ...», ответ человека лежит во входе разговора задачи,
   поверх этого идёт тик. Так выглядел случай DK-914, из которого выросла
   задача. Ждём одну строку итога. Строка вернулась в работу, признак ожидания
   снят, окно `task-DK-901` поднято с заказом продолжения и без признака hidden.
   Дом, доска, tmux и клиент тут временные, настоящие не трогаются.

```sh
python3 tools/devkitctl/testdata/poc_wakeraise.py
```

2. Половина тика. Пробуждение зовёт подъём после возврата строки, молчит без
   лежащего ответа и называет словами отказ подъёма и пропавший бинарь
   дашборда. Ждём `OK` и число прогнанных тестов.

```sh
cd tools/devkitctl && python3 -m unittest watch_test.WakeTest
```

3. Половина дашборда. Общая точка подъёма, ручка ответа задаче и слова смерти
   сессии задачи. Ждём `ok` пакета.

```sh
cd tools/dashboard && GOWORK=off go test ./... -run 'TestTaskWake|TestTaskMessageRaisesParkedRow|TestChatDeathWord'
```

4. Краснота обеих половин. Тесты обязаны падать на коде до правки. База названа
   коммитом задачи, потому что после слияния `--base main` даёт пустой дифф.
   Ждём по строке «регрессия закрыта» на каждый прогон.

```sh
regcheck --base 897c310a^ -C tools/devkitctl --tests tools/devkitctl/watch_test.py -- python3 -m unittest watch_test.WakeTest
GOWORK=off regcheck --base 8577e67f^ -C tools/dashboard --tests tools/dashboard/chat_test.go -- go test ./... -run TestTaskMessageRaisesParkedRow
```

5. Команда видна снаружи. Справка дашборда называет `wake` и говорит, кто её
   зовёт. Ждём строк справки про подъём сессии разбуженной задачи.

```sh
cd tools/dashboard && GOWORK=off go build -o /tmp/dk922-dashboard .
/tmp/dk922-dashboard 2>&1 | grep -A 6 "wake <ID>"
```
