# DK-931: Команда taskctl run поднимает голову задачи лестницей носителей

Цель: [tasks/DK-902.md](tasks/DK-902.md)

## Что происходит

2026-09-11, нарезка цели DK-902 чтением кода. Голову задачи сейчас поднимает
только дашборд. Функция `startTaskSession` (tools/dashboard/runs.go:406)
заводит tmux-сессию `task-<ID>` с оболочкой task-run.py. К ней ведут четыре
дороги: кнопка экрана, `dashboard wake`, `dashboard check` и
`dashboard round`. Тик сторожка тоже зовёт дашборд, и без него голову никак
не поднять.

Своего замка у task-run.py нет. От двойного старта защищает только
совпадение имени tmux-сессии: при живой сессии runs.go отвечает отказом 409.
При живом окне `taskWake` снимает парковку и в окно ничего не подаёт.
Реплику в живое окно подаёт только `resume_failed` в watch.py, и только
сессии с непустым полем tmux в реестре чатов. Поле пишет хук
`hooks/session-task.py` из переменной `DEVKIT_TMUX`, которую ставит дашборд.
Окно, открытое руками, получает в реестре прочерк.

Команда клиента прибита в коде дважды, в task-run.py:274 и в `clientCommand`
(runs.go:359). В профилях kit/harness ключей под неё нет.

## Чего хотим

`taskctl run <ID>` поднимает голову задачи и перебирает носителей по порядку.
Первым идёт живое окно tmux по задаче из реестра чатов, туда уходит реплика
«продолжай». Вторым идёт новое окно tmux с оболочкой task-run.py. Без tmux
голова поднимается headless через ту же оболочку. Последним идёт громкий зов
человеку, в тексте которого лежит готовая команда.

Команда берёт замок на ID задачи в ~/.devkit. Занятый замок даёт отказ с
отдельным кодом выхода, второй головы нет. Адрес поднятой сессии в реестр
пишет сама команда. Хук старта остаётся для сессий, поднятых рукой, и пишет
адрес любого окна tmux из `$TMUX` и `$TMUX_PANE`.

Команду клиента, резюм и признак конца хода команда берёт из профиля харнеса.
Ключи заводятся у claude-code и glm-code. Код запуска ложится в общий
go-модуль internal, и дашборд переходит на него строкой DK-935.

## Границы

Перевод дашборда, `close`, `merge` и тика на команду делают другие строки
цели, DK-932 и DK-935. Здесь сама команда, замок, ключи профиля и адрес окна в
реестре. Профиль под Codex в цель не входит.

## Развилки

- «замок»: как команда подъёма и тик делят замок от двойного старта?
  - решает: исполнитель
  - рекомендация: замок на ID задачи в ~/.devkit, тот же, что держит task-run.py: команда подъёма и тик берут его до старта головы, занятый замок это молчаливый отказ
- «лестница»: в каком порядке команда подъёма перебирает носителей?
  - решает: исполнитель
  - рекомендация: живое окно tmux по задаче, иначе новое окно tmux, иначе headless через task-run.py, иначе громкий зов человеку с готовой командой; без tmux лестница начинается с headless

## DoD

- `taskctl run <ID>` при живом окне задачи подаёт в него реплику и нового
  окна не заводит.
- Без живого окна команда заводит окно tmux с task-run.py. Без tmux она
  поднимает headless, а без клиента зовёт человека через notify.py строкой с
  готовой командой.
- Второй вызов при занятом замке кончается отказом, вторая голова не встаёт.
- Сессия, поднятая командой, лежит в реестре чатов с адресом окна. Окно,
  открытое руками внутри tmux, получает адрес через хук старта.
- Команда клиента и резюм берутся из профиля харнеса, в task-run.py прибитой
  строки клиента нет.
- Каждая ступень лестницы проверена тестом на подменных tmux и клиенте.

## Ранг

`50+8+3+0+4 = 65`, P1.

- Серьёзность 50: конвейер должен работать без человека, а мёртвую голову без
  дашборда поднимает человек руками. Сессию без поля tmux и headless тик не
  поднимает вовсе.
- Ценность 8: подъём нужен каждой ждущей задаче, ночью и в любой пачке.
- Неопределённость 3: команда пишется на go, оболочка на python, замок
  делится с тиком, лестница идёт через tmux.
- Поправка на баг 0: новая команда.
- Рычаг 4: на подъём опираются разряды парковки, взвод ребра и дашборд.

Цена M. Команда, замок, ключи профиля и адрес окна в хуке ложатся в одну
сессию, перенос дашборда вынесен в DK-935.
