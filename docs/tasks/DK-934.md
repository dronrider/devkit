# DK-934: Взведённая строка стартует сама по слиянию предпосылки, цепочка идёт уровнями

Цель: [tasks/DK-902.md](tasks/DK-902.md)

## Что происходит

2026-09-11, нарезка цели DK-902. Ребро «после» снимается только закрытием
предпосылки, и освобождённая строка ждёт в Backlog руки человека. LLD DK-933
решает устройство взвода. Эта строка несёт первый заезд черновика DK-721,
инструмент.

## Чего хотим

`taskctl` взводит строку на предпосылки и строит цепочку с уровнями одной
командой. Ребро стреляет по слиянию кода предпосылки. Выстрел идёт через хвост
обхода ждущих из DK-932, его зовут `shipctl merge`, `taskctl close` и тик
сторожка. Строку поднимает `taskctl run` из DK-931. Взвод виден в
`taskctl list` и `taskctl show`. Отказ подъёма из-за квоты или потолка
деревьев приходит уведомлением. Хранение, гашение и уровни берутся из решений
LLD DK-933.

## Границы

LLD заводит скилл цепочки в чате и диалог дашборда вне цели. Часовое условие
остаётся строкой DK-538 и встаёт на механизм после этой.

## DoD

- Взведённая строка стартует сама после слияния кода всех предпосылок. Строка
  уровня N стартует после всех строк уровня N-1.
- Возврат предпосылки из Check и откат гасят взвод так, как решила LLD DK-933.
- Взведённая строка отличается от заглохшей в `taskctl list`, сторожок её
  брошенной не считает.
- Тест на временном репозитории: цепочка из трёх строк на двух уровнях
  стартует по слияниям.

## Ранг

`50+8+3+0+4 = 65`, P1.

- Серьёзность 50: цепочка вне цели ждёт человека на каждом стыке.
- Ценность 8: машина работает ночью цепочкой без ручного подъёма.
- Неопределённость 3: правка идёт через taskctl, shipctl и python-сторожок,
  решения берутся из LLD.
- Поправка на баг 0: новая механика.
- Рычаг 4: на взвод встанут DK-538 и живой замер цели.

Цена M. Если LLD нарежет механику крупнее, недостающее дорезается строками
цели.
