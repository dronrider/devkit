# DK-938: Кнопка чата у цели открывает мёртвый груминг, реплика не доходит до «Входящих»

## Что происходит

2026-09-11, цель DK-902 поднята кнопкой «Выполнить» в дашборде. Оболочка
goal-run.py поднимает цикл с DEVKIT_HIDDEN=1 по решению DK-847 от 2026-09-07.
Хук старта пишет hidden: true в память диалога сессии 7eaa707c, её tmux
goal-DK-902. Панель чатов просит список ?all=1 без ключа hidden=1. Чат
цикла в список не попадает. Сервер с ключом hidden=1 отдаёт ему state: live.
Кнопка чата на форме задачи фильтрует видимые чаты по DK-902. Находится
один кандидат, вчерашняя сессия груминга ba1e0826 в tmux task-DK-902. У неё
заголовок «Разбор и груминг задачи DK-902» и state: dead.

Сверка с кодом при груминге, 2026-09-11. Фильтр скрытых стоит на сервере,
`tools/dashboard/chats.go:917`, и ключ `keep` его не обходит. Кнопка чата одна
на строку и форму, это `rowChatBtn` в `static/app.js:9486`. Форма передаёт ей
только ID задачи (`app.js:3896`). У строки цели пустое поле `run_chat`.
Работа из tmux цели собирается без сессии (`board.go:432-452`), goal-run.py
не ставит `DEVKIT_TMUX`, и имени окна в реестре нет. Поэтому выбор уходит в
поиск по ID среди видимых чатов (`app.js:7908-7914`). Даже адресный вход по
sid покажет живой чат мёртвым. В списке нет записи, и `chatWay` по умолчанию
берёт `dead` (`app.js:9643`).

Во «Входящие» цели панель сегодня не пишет вовсе. Ручка
`POST /goals/{id}/message` жива, но её вызов снят с фронтенда правкой DK-397
от 2026-08-19 (`3f6a27b2`). `goalMessageURL` с `makeOutbox` остались без
вызовов. README дашборда эту дорогу описывает («реплика уходит ручкой цели,
во «Входящие» её файла»). Это регресс. Реплика в живой чат цикла ушла бы
через `/say` и подняла бы резюм второго агента рядом с идущим витком.

Человек заходит в чат цели с формы и видит чужой заголовок. Над лентой стоит
красная плашка «разговор остановлен», а цикл в это время жив и пишет журнал.
Реплика из этого чата поднимет резюм мёртвой сессии груминга. Во «Входящие»
цели она не доедет, подхват chat-in.py её не увидит. Ответ на вопрос витка
теряется. У дашборда нет входа во «Входящие», а goal-run.py --say пишет
строку в журнал цикла.

## Чего хотим

Кнопка чата у строки и формы цели открывает живой чат цикла. У него свой
заголовок и зелёное состояние. Реплика из него доезжает во «Входящие».

## Границы

Решение DK-847 остаётся в силе, цикл цели из списка чатов не выходит. Условий,
посильных только человеку, не нашёл. Доступов и секретов правка не просит,
у неё нет выката наружу, правил другим строкам она не меняет.

## Развилки

не смотрит на признак hidden, а признак остаётся фильтром списка. По второй
цикл цели перестаёт прятаться вовсе, и решение DK-847 пересматривается для
целей. Первая дорога выглядит правильнее. Чистота списка сохраняется, а
адресный переход ведёт в живой чат.

## Сценарий проверки

Вид агентский. Каждый шаг идёт в свежем дереве с временным `HOME`, цель XR-100
и её виток синтетические, их заводят сами тесты. Вердикт шага это код возврата
команды.

1. Исходный баг на синтетической цели. Цель XR-100 идёт циклом в tmux
   `goal-XR-100`, её виток живой и скрыт из списка чатов, рядом лежит
   вчерашний груминг той же задачи. Браузерный стенд поднимает сервер
   дашборда и жмёт кнопку чата в строке доски и на форме цели. До правки обе
   кнопки открывали «Разбор и груминг задачи XR-100» с красной плашкой
   «разговор остановлен». В выводе ждём `--- PASS: TestBrowserGoalChatOpensLoop`
   и две строки `Title:Цикл цели XR-100: третий виток Busy:true Stop:false
   Green:true`. Без chrome тест печатает `--- SKIP`, и шаг краснеет. Браузер
   называет переменная `DASHBOARD_CHROME`.

```sh
cd tools/dashboard && GOWORK=off go test -count=1 -run '^TestBrowserGoalChatOpensLoop$' -v . 2>&1 | tee /dev/stderr | grep -c 'Title:Цикл цели XR-100: третий виток Busy:true Stop:false Green:true' | grep -qx 2
```
