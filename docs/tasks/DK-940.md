# DK-940: Команда chain строит цепочку уровнями

## Что происходит

2026-09-11, нарезка LLD DK-933, второй заезд черновика DK-721 вне цели DK-902.
После DK-934 цепочку ставят поштучно, `dep add` на каждое ребро и `arm` на
каждую строку. Просьба «после DK-A сделай DK-B и DK-C, потом DK-D» это четыре
ребра и три взвода.

## Чего хотим

Команда `taskctl chain` по решению 4 LLD DK-933. Уровни идут позиционными
аргументами, `--after` даёт рёбра первому уровню, `--dry-run` печатает план
уровнями и доску не пишет. Каждая строка проходит проверки `arm`, цикл
отбивает `reachable`. Запись идёт одним коммитом доски. Дока лежит в README
taskctl с примером просьбы из решения 4.

## DoD

- Тест на временном репозитории. `chain --after DK-A "DK-B DK-C" "DK-D"`
  кладёт на доску рёбра и взводы из решения 4, а `--dry-run` печатает те же
  уровни и доску не трогает.
- Цикл или строка, которой `arm` отказывает, дают отказ без записи на доску.
- README taskctl показывает пример просьбы и команду к ней.

Агентский. Шаги гоняются из корня дерева, в PATH стоит taskctl, собранный из
ветки; `taskctl rehearse DK-940` прогоняет их в свежем дереве каждый своим
шеллом.

```sh
cd tools/taskctl && GOWORK=off go test -count=1 -run 'TestChain|TestSplitChainIDs' ./...
```

Ожидается `ok github.com/dronrider/devkit/tools/taskctl`. Пять тестов кладут
сценарий решения 4 (два уровня, `--after`, взвод), первый уровень без
`--after`, отказ цикла без записи на доску и отказ ворот `arm` без записи на
доску.

```sh
cd tools/taskctl && GOWORK=off go build -o ../../taskctl-chain .
```

Ожидается код 0 и бинарь `taskctl-chain` в корне дерева, его берут следующие
три шага.


Ожидается план из трёх строк: `уровень 1: XR-002 [после XR-001] [взвод]`,
