# DK-942: Диалог цепочки на дашборде, список задач и номера уровней

## Что происходит

2026-09-11, нарезка LLD DK-933, третий заезд черновика DK-721 вне цели DK-902.
Карточка зависимостей на дашборде принимает один ID в поле ввода. Взвода она
не показывает, и цепочку с уровнями на ней не собрать.

## Чего хотим

В карточке вместо поля ввода список задач с поиском и переключатель
автозапуска, который зовёт `arm` и `arm --off`. Из списка доски открывается
диалог цепочки. Строки раскладываются по номерам уровней, предпросмотр идёт
через `chain --dry-run`, запись через `chain`. Три состояния взвода видны на
строке списка и в карточке, приходят они из `dep list --json`.

## DoD

- Цепочка из трёх строк на двух уровнях собирается диалогом и ложится на
  доску теми же рёбрами, что даёт `chain`.
- Переключатель ставит и снимает `[взвод]`, отказ `arm` виден в карточке с
  причиной.
- Проверка идёт тестом сервера дашборда на синтетической доске.

Шаг 2. Цепочка из трёх строк на двух уровнях. Предпросмотр печатает план
уровнями и не трогает доску, а при записи рёбра со взводом ложатся одним
коммитом.

```sh
set -eu
. ${TMPDIR:-/tmp}/dk942/env
cd "$proj"
before=$(git rev-parse HEAD)
curl -sS -b "$stand/jar" -X POST "$base/api/projects/demo/chain" \
  -H 'Content-Type: application/json' \
  -d '{"after":["XR-001"],"levels":[["XR-002","XR-003"],["XR-004"]],"dry_run":true}' \
  > "$stand/plan.json"
dry=$(git rev-parse HEAD)
curl -sS -b "$stand/jar" -X POST "$base/api/projects/demo/chain" \
  -H 'Content-Type: application/json' \
  -d '{"after":["XR-001"],"levels":[["XR-002","XR-003"],["XR-004"]]}' \
  > "$stand/write.json"
taskctl dep list XR-004 --json > "$stand/dep4.json"
git log -1 --pretty=format:%s > "$stand/subject.txt"
python3 - "$stand" "$before" "$dry" <<'EOF'
import json, sys
stand, before, dry = sys.argv[1], sys.argv[2], sys.argv[3]
plan = json.load(open(stand + "/plan.json"))["plan"]
dep4 = json.load(open(stand + "/dep4.json"))
for line in plan:
    print("план:", line)
print("предпросмотр доску не тронул:", before == dry)
print("хвост цепочки ждёт первый уровень:", dep4["after"] == ["XR-002", "XR-003"])
print("хвост цепочки взведён:", dep4.get("armed") is True)
print("состояние взвода:", dep4.get("arm", {}).get("state"))
print("subject коммита:", open(stand + "/subject.txt", encoding="utf-8").read().strip())
EOF
```

Ожидание: три строки плана, «уровень 1: XR-002 [после XR-001] [взвод]»,
«уровень 1: XR-003 [после XR-001] [взвод]» и «уровень 2: XR-004 [после XR-002,
XR-003] [взвод]». Дальше «предпросмотр доску не тронул: True», «хвост цепочки
ждёт первый уровень: True», «хвост цепочки взведён: True», «состояние взвода:
ждёт» и «subject коммита: docs(tasks): XR-002 цепочка с дашборда».

Шаг 4. Три состояния взвода и свободная строка приходят экрану полем `arm`. Ребро снимается
слиянием работы предпосылки, и состояние считается заново без правки доски.

```sh
set -eu
. ${TMPDIR:-/tmp}/dk942/env
cd "$proj"
mkdir -p x
printf 'package x\n' > x/code.go
git add x/code.go
git commit -qm "feat(x): XR-001 правка"
taskctl arm XR-003 --off > /dev/null
curl -sS -b "$stand/jar" "$base/api/projects/demo/tasks/XR-002" > "$stand/task2.json"

curl -sS -b "$stand/jar" "$base/api/projects/demo/board" > "$stand/board.json"
DEVKIT_SLOT_TREES=0 taskctl wake > "$stand/wake.out" 2>&1
curl -sS -b "$stand/jar" "$base/api/projects/demo/tasks/XR-002" > "$stand/task2-ref.json"
python3 - "$stand" <<'EOF'
import json, sys
stand = sys.argv[1]
task2 = json.load(open(stand + "/task2.json"))
task3 = json.load(open(stand + "/task3.json"))
board = json.load(open(stand + "/board.json"))["board"]
ref = json.load(open(stand + "/task2-ref.json"))
rows = {r["id"]: r for s in board["sections"] for r in s["rows"]}
print("карточка XR-002:", task2["armed"], task2.get("arm", {}).get("state"))
print("карточка XR-003:", task3["armed"], task3.get("arm", {}).get("state"))
print("строка доски XR-002:", rows["XR-002"].get("arm", {}).get("state"))
print("после обхода:", ref.get("arm", {}).get("state"))
print("причина отказа в пометке:", "отказ" in ref.get("arm", {}).get("note", ""))
EOF
```

Ожидание: «карточка XR-002: True готова» (рёбра сняты слиянием предпосылки),
«карточка XR-003: False рукой» (взвод снят, поднять некому кроме человека),
«строка доски XR-002: готова» (то же состояние в списке доски), «после обхода:
отказ» и «причина отказа в пометке: True». Обход запускается без ID, то есть
по всем ждущим. С названным ID он первым проверяет предполёт головы, а тут
нужен отказ ворот ёмкости. Потолок деревьев задан стенду через
`DEVKIT_SLOT_TREES`, и причина отказа ложится в `.devkit/arm/XR-002`.
