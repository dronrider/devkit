# DK-968: Упавший прогон оставляет временное дерево, и ёмкость занята

Цель: [tasks/DK-902.md](tasks/DK-902.md)

## Что происходит

Живой замер цели DK-902 двенадцатого сентября, второй затор подряд. Первый
сняла задача DK-967, и ворота пачки пропустили взведённую строку. Дальше
отказ пришёл от соседних ворот: «потолок деревьев 17 из 5».

Деревьев в списке восемнадцать, и одиннадцать из них временные. Семь оставил
`shipctl merge`, три `regcheck`, все лежат в каталоге временных файлов. Каталоги
на месте, git их prunable не считает, `git worktree prune` такую запись не
трогает.

Прогоны эти падали. Только за сегодняшнюю сессию тест со стенным потолком
времени (DK-764) трижды отбил слияние, и каждое падение оставило дерево. Рабочих
деревьев задач при этом пять, и четыре из них тоже брошены: dk-369, dk-466,
dk-470 и dk-605 стоят на строках Backlog.

Ворота `armGates` считают деревья через `liveTrees` (tools/taskctl/arm.go).
Счёт идёт по списку git без разбора, чьё дерево и живо ли оно.

## Чего хотим

Прогон убирает своё дерево и на падении. Слияние падает часто, это штатный
исход, и мусор после него копиться не должен.

Порядок разбора такой. Временное дерево прогона снимается тем, кто его завёл,
в том числе на аварийном выходе. Уже накопленный мусор снимает `devkitctl
doctor --fix` наравне с прочими находками. Дерево брошенной задачи, чья строка
лежит в Backlog, ёмкости не занимает. Тот же разбор действовал для окон tmux в
DK-967.

## DoD

- Упавшее слияние и упавший regcheck не оставляют дерева в списке git.
- Уборка снимает накопленные временные деревья и называет их числом.
- Ворота ёмкости не считают деревом задачу, чья строка лежит в Backlog или в
  архиве.
- Тест на временном репозитории: прогон, оборванный на середине, дерева не
  оставляет.

## Ранг

`50+7+2+5+3 = 67`, P1.

- Серьёзность 50: взведённая строка не стартует, конвейер стоит до руки
  человека. Обход ручной, снимать деревья через git worktree remove.
- Ценность 7: ночная цепочка не встаёт на воротах ёмкости.
- Неопределённость 2: уборка на аварийном выходе и место вызова.
- Поправка на баг +5: прогон должен убирать за собой и не убирает.
- Рычаг 3: тем же счётом деревьев живут слот и пачка.
