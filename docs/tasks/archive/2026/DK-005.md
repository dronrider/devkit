# DK-005: shipctl start: worktree на задачу, чтобы параллельные сессии не толкались в одном дереве

Наблюдение из проекта с доской: сессия по одной задаче видит в рабочем дереве
незакоммиченные правки параллельной сессии по другой. Пока чекаут общий, чужой
файл легко уезжает в посторонний коммит, а `git checkout` одной сессии рушит
контекст другой.

Решение: у каждой задачи своё рабочее дерево. `shipctl start <ID>` заводит
ветку задачи в git worktree рядом с проектом и переводит задачу в In progress;
`merge` находит ветку в worktree (из самого дерева или по ID с main), сливает
как раньше и убирает worktree. Основной чекаут остаётся на main под доску и
мелочь. Детали в `shipctl/README.md`, раздел «Worktree на задачу».

## DoD

- `shipctl start`: ветка по ID в `../<проект>-<id>`, перевод Backlog -> In
  progress через taskctl, повторный start отбивается, второй заход
  подхватывает уцелевшую ветку.
- `merge` работает из worktree и с main, читает замечания ревью с фичеветки,
  прибирает worktree; старый путь (ветка в общем чекауте) не меняется.
- `ship`/`revert`/`status` переносят работу в основное дерево при запуске из
  worktree.
- Тесты на все сценарии, дока (shipctl/README.md, RULES.board.md п. 1).

## Сценарий проверки (агентский)

Шаги выполняются с машины агента в любом клоне devkit, прод не трогают
(выкат devkit это пересборка локальных бинарей, шаг 5 её не запускает).

1. Пересобрать shipctl: `cd ~/projects/devkit/shipctl && go build -o ~/go/bin/shipctl .`; код возврата 0.
2. `cd ~/projects/devkit && shipctl status`: вывод содержит строку `ветка: main`.
3. Во временном git-репозитории с доской (`taskctl init --prefix T`, задача
   `taskctl add`) выполнить `shipctl start T-001 --slug demo`: код возврата 0,
   в выводе путь worktree `../<dir>-t-001`, `git -C ../<dir>-t-001 rev-parse
   --abbrev-ref HEAD` печатает `t-001-demo`, `taskctl list in-progress`
   показывает T-001.
4. Закоммитить в worktree правку с `T-001` в subject и выполнить
   `shipctl merge T-001 --test true`: код возврата 0, в выводе `worktree` и
   `убран`, директории worktree больше нет, правка в main.
5. `go test ./...` в `devkit/shipctl`: код возврата 0.

## Ход работы

- Реализация: worktree.go (start, поиск дерева по ветке, уборка), merge/ship/
  revert/status приводят корень к основному чекауту, подсказки regcheck и
  поезда считаются от ветки задачи, а не от HEAD.
- Незакоммиченное в worktree держит merge, untracked-черновики не валят
  слияние, но оставляют дерево на уборку руками.

## Ревью

- merge из worktree не сверяет ветку дерева с переданным ID, можно слить чужую ветку под чужой задачей (заодно ловится detached HEAD): исправлено
- осиротелая регистрация worktree (директорию снесли rm -rf) заводит start и merge в тупик, нет git worktree prune: исправлено
- подсказка при провале уборки предлагает git worktree remove без --force, который упадёт так же: исправлено
- провал taskctl move после создания worktree оставляет задачу в Backlog без подсказки, как дочинить: исправлено
- подхват уцелевшей ветки не работает при заданном --slug, молча заводится вторая ветка задачи: исправлено
- нет тестов на merge из чужого worktree и на осиротелую регистрацию: исправлено
- асимметрия: merge из основного чекаута на чужой фичеветке сливает текущую ветку под чужим ID, сверки branchOfTask там нет: исправлено
