# DK-008: shipctl start: worktree ветвится до коммита перевода, taskctl file в нём конфликтует с main при ребейзе

## Разбор

В cmdStart дерево задачи создавалось раньше, чем taskctl move коммитил
перевод в In progress: ветка ветвилась от main без коммита перевода, и
правка доски в worktree (taskctl file) на ребейзе при merge упиралась в
конфликт по строке задачи. Исправление переставляет перевод доски перед
git worktree add, ветка тогда сразу содержит коммит перевода.

## Сценарий проверки (агентский)

После выката (пересборка бинарей) прогнать во временной директории:

1. `git init -b main tmp && cd tmp`, `taskctl init --prefix XR`, закоммитить;
2. `taskctl add --title "проба" --type task --rank "0+5+0+0+5"`, закоммитить;
3. `shipctl start XR-001`;
4. сравнить `git rev-parse main` и `git -C ../tmp-xr-001 rev-parse HEAD`.

Ожидаемый итог: хеши совпадают, ветка задачи содержит коммит «XR-001 в
работу». На старом бинаре ветка отстаёт от main на этот коммит.
