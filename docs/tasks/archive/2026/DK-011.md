# DK-011: agentctl: effort в вердикте pick и применение через определения субагентов

Наблюдение пользователя: помимо модели у исполнения есть effort (reasoning
effort), правила его не затрагивают вовсе.

Фактура по Claude Code (июль 2026): у субагента effort задаётся полем
`effort` во frontmatter определения агента `.claude/agents/*.md`, уровни
low/medium/high/xhigh/max, от сессии не наследуется; в параметрах вызова
Agent tool его нет.

Набросок решения:

- pick выдаёт вердикт парой: вторая машинная строка `effort: ...` рядом с
  `model: ...` (мелочь S -> low, обычное -> high, LLD и грумминг -> xhigh);
- применяется через набор определений агентов-исполнителей с прибитым effort
  в frontmatter (модель передаётся параметром, effort берётся из
  определения); состав набора и где он живёт (devkit шаблоном, проект
  копией) решить при реализации;
- запись --record дополняется effort, README и п. 10 RULES.board.md
  обновляются той же веткой.

Зависимость по смыслу: если DK-009 введёт fable-ярус, наборы effort и
моделей согласовать в одной таблице маппинга.

## Ход работы

- Исполнение: субагент opus по вердикту pick, 2026-07-30.

Принятые развилки.

- Уровень sonnet-правила (цена S или M, неопределённость не выше 1) это
  `medium`. Обоснование то же, по которому там стоит sonnet: подход выбран при
  грумминге, исполнителю остаётся его применить, длинное размышление покупает
  не качество, а время и токены. Остальное по наброску: S без
  неопределённости `low`, обычная работа `high`, проектирование и грумминговые
  вердикты `xhigh`. Уровень `max` маппинг не выдаёт.
- Override симметричный, отдельной строкой «Эффорт» (значения от `low` до
  `max`, опечатка это жёсткая ошибка pick, как у модели). Оси независимые:
  каждая строка перебивает свою часть вердикта, незаданная берётся из обычного
  маппинга. Домен диктует то модель, то глубину размышления, то и другое
  сразу, связывать их одной строкой значило бы заставлять писать лишнее.
  Следствие, которое стоит помнить: override модели на грумминговом вердикте
  оставляет effort `xhigh`, и если исполнять задачу надо буднично, рядом
  ставится и вторая строка.
- Определения исполнителей живут в devkit, директория `agents/`, по файлу на
  уровень маппинга (`exec-low`, `exec-medium`, `exec-high`, `exec-xhigh`).
  Effort прибит во frontmatter, модель не прибита: её диспетчер передаёт
  параметром, поэтому одно определение обслуживает любую модель, иначе набор
  разросся бы матрицей моделей на уровни. Ставятся копией в `~/.claude/agents/`
  (доступны во всех проектах), сама установка это шаг пользователя.

## Сценарий проверки

Агентский: все шаги выполняются с машины агента, ничего не меняют, кроме
временной директории в `/tmp`. Проверяется на слитой main.

1. Тесты утилиты:

   ```sh
   cd ~/projects/devkit/agentctl && go test ./...
   ```

   Ожидается `ok  github.com/dronrider/devkit/agentctl`, код возврата 0.

2. Сборка и синтетическая доска. Ожидаемые уровни проверяются на ней, а не
   на живых задачах: живую строку перегруммят, и сценарий протухнет.

   ```sh
   cd ~/projects/devkit/agentctl && go build -o /tmp/agentctl-dk011 .
   mkdir -p /tmp/dk011/docs/tasks
   printf '%s\n' '# demo: задачи (префикс T)' '' '## Backlog' '' \
     '| ID | Задача | Тип | P | R | Цена | Ссылка |' '|---|---|---|---|---|---|---|' \
     '| T-001 | мелкая правка | task | P3 | 5 (0+3+0+0+2) | S | - |' \
     '| T-002 | обычная фича | task | P2 | 34 (25+4+1+0+4) | M | - |' \
     '| T-003 | фича посложнее | task | P2 | 35 (25+4+2+0+4) | L | - |' \
     '| T-004 | дизайн подсистемы | LLD | P1 | 30 (25+5+0+0+0) | L | - |' \
     > /tmp/dk011/docs/TASKS.md
   for id in T-001 T-002 T-003 T-004; do /tmp/agentctl-dk011 -C /tmp/dk011 pick $id | head -2; done
   ```

   Ожидаются пары `model: haiku` и `effort: low`, `model: sonnet` и
   `effort: medium`, `model: opus` и `effort: high`, `model: fable` и
   `effort: xhigh`, код возврата 0.

3. Живая доска отвечает тем же контрактом (значения зависят от текущих
   метаданных задачи и не фиксируются):

   ```sh
   /tmp/agentctl-dk011 -C ~/projects/devkit pick DK-012; echo "код $?"
   ```

   Три строки вывода, первые две начинаются с `model: ` и `effort: `, код 0.

4. Override эффорта (двоеточие подставляется аргументом printf, чтобы строка
   не сработала как override уже в этом файле):

   ```sh
   printf '# T-002\n\nЭффорт%s max\n' ':' > /tmp/dk011/docs/tasks/T-002.md
   /tmp/agentctl-dk011 -C /tmp/dk011 pick T-002
   ```

   Первые две строки `model: sonnet` (модель из маппинга) и `effort: max`,
   в третьей строке есть «effort задан override-строкой».

5. Опечатка в уровне валит вердикт:

   ```sh
   printf '# T-002\n\nЭффорт%s highest\n' ':' > /tmp/dk011/docs/tasks/T-002.md
   /tmp/agentctl-dk011 -C /tmp/dk011 pick T-002; echo "код $?"
   ```

   Ожидается сообщение про неизвестный effort и код 1.

6. Набор определений на месте, уровни прибиты, модель не прибита:

   ```sh
   ls ~/projects/devkit/agents/
   grep -h '^effort:' ~/projects/devkit/agents/*.md
   grep -l '^model:' ~/projects/devkit/agents/*.md; echo "код $?"
   ```

   Четыре файла `exec-low.md`, `exec-medium.md`, `exec-high.md`,
   `exec-xhigh.md`, по строке effort в каждом (`low`, `medium`, `high`,
   `xhigh`), а последний grep не печатает ничего и выходит с кодом 1: модели
   во frontmatter нет.

Уборка: `rm -rf /tmp/dk011 /tmp/agentctl-dk011`.
