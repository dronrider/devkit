# DK-015: agentctl: сдвиг лестницы моделей в pick (M к opus, sonnet не ниже high)

Пользователь пересмотрел политику маппинга: экономить effort на дешёвых моделях
бессмысленно (запросы sonnet стоят копейки, а риск потерять качество есть), и
средняя по размеру задача должна доставаться opus, а не sonnet. Дешёвые модели
остаются только на мелочи.

## Принятые решения

- Ось модели: haiku остаётся на S с неопределённостью ровно 0; sonnet сужается
  до S с неопределённостью 1; всё остальное исполнимое (M на любой
  неопределённости, S с 2-3, L) уходит в opus. Правила LLD, грумминга (>= 4) и
  XL не меняются.
- Ось effort: уровень по-прежнему считается от неопределённости, но вердикту с моделью
  sonnet уровень поднимается минимум до high. Пол применяется и когда sonnet
  пришёл override-строкой, а effort из маппинга; явный override эффорта пол не
  трогает. На haiku пол не распространяется: у Haiku 4.5 параметр effort в API
  не работает вовсе (проверено по референсу Claude API, июль 2026), его low
  остаётся формальным.
- Дока: таблицы маппинга в `agentctl/README.md` переписываются под новые
  правила, пол sonnet описывается отдельным абзацем оси effort.

## Сценарий проверки

Агентский. После выката (пересборка бинарей в PATH):

1. `cd ~/projects/devkit/agentctl && go test ./...` завершается кодом 0.
2. `agentctl pick DK-012` печатает первой строкой `model: opus` и второй
   `effort: medium` (task, цена M, неопределённость 1: раньше был sonnet).
3. `agentctl pick DK-015` печатает `model: sonnet` и `effort: high`
   (S с неопределённостью 1 с учётом пола; override эффорта в этом файле
   к моменту проверки снят, см. ход работы).

Шаги ничего не меняют, итог проверяется по коду возврата и строкам вывода.
