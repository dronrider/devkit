# DK-036: профиль харнеса и слои конфигурации: claude-code.toml описывает сегодняшнее поведение

Шаг 1 миграции из [DK-033](../../../lld/DK-033-universal-kit.md). Дизайн там, тут ход
работы и проверка.

## Ход работы

- Исполнение: субагент opus/medium по вердикту pick, 2026-08-01.
- Профиль `harness/claude-code.toml` описывает сегодняшний контур: детект по
  `CLAUDECODE=1`, правила импортом в `CLAUDE.md`, делегирование `native` с
  маппингом ярусов haiku/sonnet/opus/fable, хуки протокола claude-code со всеми
  четырьмя событиями, снимок квоты панелью `/usage`.
- Парсер подмножества TOML написан дважды: `agentctl/toml.go` на stdlib и
  `devkitctl/harness.py` на голом python3. Чтобы реализации не разъехались,
  тексты ошибок и канонический дамп у них общие, а входы лежат в
  `harness/testdata` с ожидаемым отчётом на файл; сверяются с ними обе стороны
  (`agentctl/harness_test.go` и `devkitctl/test.sh`). Проверено мутацией:
  правка одного слова в сообщении питоновской реализации красит самопроверку
  devkitctl.
- Валидация гоняется на каждой загрузке. Свод из дизайна плюс одна проверка
  сверх него (`required` обязан быть в `buckets`), отличия от дизайна собраны
  разделом «Отличия реализации от дизайна» в LLD.
- Слои и детект собраны в `agentctl/harness.go`, наружу их показывает
  `agentctl harness`. Машинного конфига нет, значит включён один claude-code с
  маппингом-предложением из профиля, то есть поведение сегодняшнее один в один.
- Пункт 20 скелета закреплён снимком: `agentctl/testdata/pick-verdicts.txt`
  снят с кода до правки (прогоном на копии main), а тест
  `TestPickVerdictsUnchanged` пересчитывает вердикты по фикстурной доске и
  сверяет побайтно.
- Секция `[quota]` профиля объявляет бакет `week_max`, имя из дизайна квоты;
  читатель снимка сегодня знает `week_fable`, псевдоним кладёт DK-038. До тех
  пор секцию не читает никто, кроме валидатора.
- Ревью: субагент sonnet/high по вердикту pick, 2026-08-01.
- По замечаниям ревью набор фикстур доведён до полного: на каждую ветку
  валидации (пять секций порознь, типы значений по секциям, каждый обязательный
  ключ, каждое значение режима, четыре яруса `spend_*` порознь и по
  обязательности, и по принадлежности бакетов) и на каждую границу подмножества
  в парсере лежит свой вход. Ветки, которых у общих фикстур быть не может
  (типы значений машинного и проектного слоёв, их читает только agentctl),
  закрыты Go-тестом. Проверено снятием проверок по одной: 56 мутаций, на каждой
  тесты краснеют.

## Сценарий проверки

Агентский: все шаги выполнимы с машины агента, итог проверяется выводом и кодом
возврата, окружение везде синтетическое (временный `HOME`, временная директория
профилей), живой контур шаги не трогают. Прогнан до перевода в Check на бинаре,
собранном из ветки; после выката те же команды идут через `agentctl` из PATH.

1. Активный харнес и чем он определён:

   ```sh
   cd ~/projects/devkit && agentctl harness
   ```

   Первая строка `харнес: claude-code (детект по переменной CLAUDECODE)` в
   сессии харнеса либо `харнес: claude-code (умолчание, машинного конфига нет)`
   вне её; дальше строка `маппинг ярусов: mini = haiku, base = sonnet, pro =
   opus, max = fable (предложение профиля, машина не настроена)`, строка
   `делегирование: native` с путём профиля и строка про снимок квоты. Код 0.

2. Машинный слой перебивает предложение профиля, имя без профиля выбрасывается
   предупреждением:

   ```sh
   h=$(mktemp -d) && mkdir -p "$h/.devkit"
   printf 'default = "claude-code"\nenabled = ["claude-code", "codex"]\n\n[claude-code]\nmini = "haiku"\nbase = "sonnet"\npro = "opus"\nmax = "opus"\n' > "$h/.devkit/harness.local"
   HOME="$h" agentctl harness -C ~/projects/devkit
   ```

   В маппинге `max = opus` с пометкой `(машинный конфиг)`, последней строкой
   `предупреждение: codex включён, а профиля .../harness/codex.toml нет,
   пропущен`. Код 0.

3. Ненастроенный контур говорит о себе, а не молчит:

   ```sh
   printf 'enabled = []\n' > "$h/.devkit/harness.local"
   HOME="$h" agentctl harness -C ~/projects/devkit
   ```

   Строки `харнес: не определён; ярусная часть вердикта работает, модель
   разворачивать нечем (model: -)` и `включены: никого`, дальше команда, чем это
   чинится. Код 0.

4. Битый профиль это отказ с именем файла и ключа, а не молча выключенная ось:

   ```sh
   d=$(mktemp -d) && mkdir -p "$d/harness"
   printf '[detect]\n\n[rules]\nmode = "import"\n\n[delegate]\nmode = "none"\n\n[hooks]\n\n[quota]\n' > "$d/harness/claude-code.toml"
   DEVKIT_HOME="$d" agentctl harness; echo "rc=$?"
   ```

   `ошибка: claude-code.toml: [rules] нет ключа file (при mode = "import")` и
   `rc=1`.

5. Вердикт pick не двинулся ничем (пункт 20 скелета), и обе реализации парсера
   читают общие фикстуры одинаково:

   ```sh
   cd ~/projects/devkit/agentctl && go test ./...
   sh ~/projects/devkit/devkitctl/test.sh
   ```

   `ok github.com/dronrider/devkit/agentctl` и `devkitctl в порядке`.

6. Доктор проверяет профили и на исправных молчит:

   ```sh
   python3 ~/projects/devkit/devkitctl/devkitctl.py doctor -C ~/projects/devkit | grep -c 'профиль харнеса'
   ```

   `0`.
