# DK-037: ярусы mini/base/pro/max в agentctl, третья строка вердикта tier

Шаг 2 миграции из [DK-033](../../../lld/DK-033-universal-kit.md). Дизайн там, раздел
«Ярусы и вердикт pick», тут ход работы и проверка.

## Ход работы

- Исполнение: субагент opus/medium по вердикту pick, 2026-08-01.
- Внутренние таблицы pick переписаны в ярусы без смены семантики: `pickTier`
  вместо `pickModel`, спуск роли ревьювера и его пол, пол effort (`floorBaseEffort`),
  корректор (`correctTier`) и лестница трат в `quota.go`. Лестница живёт одним
  списком `tierNames` в `harness.go`, отдельного списка моделей в корректоре
  больше нет.
- Порядок расчёта прежний, весь в ярусах: маппинг таблиц, override, корректор,
  роль ревьювера. Разворачивание яруса в модель добавлено последним шагом,
  маппингом активного харнеса из DK-036 (`resolveTierModels` поверх
  `mergeLayers` и `resolveHarness`).
- Вердикт получил третью машинную строку `tier`, первые две остались на местах.
  Развернуть ярус нечем, значит в `model` прочерк, а причина хвостом называет
  файл настройки; ярус и effort при этом полноценны.
- Override принимает и имя яруса, и старое имя модели: одна таблица
  псевдонимов, любое другое значение (включая конкретную модель инструмента)
  остаётся жёсткой ошибкой pick.
- Как сохранена доказательная сила снимка вердиктов. Переснять
  `testdata/pick-verdicts.txt` значило бы сверять код сам с собой, поэтому файл
  остался нетронутым, снятым ещё до ярусов, а `TestPickVerdictsUnchanged`
  прогоняет сегодняшний вывод через обратный перевод: строка `tier` снимается,
  слова ярусов разворачиваются в старые имена по таблице псевдонимов. Перевод
  механический и узкий, мимо него не проходит ничего, кроме самого
  переименования ступеней: сдвинься любая формулировка, порядок строк или сам
  вердикт, и сверка покраснеет. Сегодняшний вид вердикта при этом тоже
  закреплён, вторым снимком `testdata/pick-verdicts-tiers.txt`.
- Отличия от дизайна собраны разделом «Отличия реализации от дизайна» в LLD:
  pick не падает от битого профиля и ненайденной директории профилей, хвост про
  холостой сдвиг ставится только при известной модели, строка `--record` при
  неразвёрнутом ярусе несёт ярус.
- Бакеты квоты и их имена не тронуты, они едут в DK-038; ярусными стали только
  ключи таблицы трат.
- Мутационный прогон по изменённому коду: 17 мутаций (не тот ярус в правиле
  маппинга, сдвинутая граница грумминга, снятый пол ревьювера, пол effort на
  чужом ярусе, потерянный хвост причины, псевдоним на чужой ярус, снятая
  проверка неизвестного значения override, молчание про ненастроенный харнес,
  молчаливый холостой сдвиг, переставленные машинные строки, прочерк вместо
  яруса в записи, несдвигающий дефицит, чужой ярус в предупреждении дна,
  потерянный бакет верхнего яруса, пустая модель вместо прочерка,
  ненастроенный харнес за настроенный, и заодно первая мутация после добавления
  недостающего случая). На каждой падает хоть один тест.
- Ревью: субагент sonnet/high по вердикту pick, 2026-08-01.

## Сценарий проверки

Агентский: все шаги выполнимы с машины агента, итог проверяется выводом и кодом
возврата, окружение синтетическое (временный `HOME`, синтетическая доска,
профили из репозитория через `DEVKIT_HOME`), живой контур шаги не трогают.
Прогнан до перевода в Check на бинаре, собранном из ветки; после выката те же
команды идут через `agentctl` из PATH.

Общая заготовка для шагов 2-5:

```sh
b=$(mktemp -d) && mkdir -p "$b/docs/tasks"
printf '# t: задачи (префикс T)\n\n## In progress\n\n| ID | Задача | Тип | P | R | Цена | Ссылка |\n|---|---|---|---|---|---|---|\n| T-002 | фича | task | P2 | 34 (25+4+1+0+4) | M | - |\n' > "$b/docs/TASKS.md"
h=$(mktemp -d) && mkdir -p "$h/.devkit"
export DEVKIT_HOME=~/projects/devkit
```

1. Вердикт по живой доске несёт три машинные строки, третья это ярус:

   ```sh
   cd ~/projects/devkit && agentctl pick DK-037
   ```

   `model: opus`, `effort: medium`, `tier: pro`, дальше строка задачи. Код 0.

2. На настроенном контуре ярус разворачивается в модель:

   ```sh
   HOME="$h" agentctl pick T-002 -C "$b"
   ```

   `model: opus` и `tier: pro` (маппинг-предложение профиля claude-code,
   машинного конфига нет). Код 0.

3. Ненастроенный харнес даёт прочерк вместо модели, а ярус остаётся полным:

   ```sh
   printf 'default = "claude-code"\nenabled = ["claude-code"]\n' > "$h/.devkit/harness.local"
   HOME="$h" agentctl pick T-002 -C "$b"
   ```

   `model: -`, `effort: medium`, `tier: pro`, в причине хвост `харнес
   claude-code не настроен, маппинга ярусов нет; вписать секцию [claude-code] в
   $h/.devkit/harness.local`. Код 0.

4. Override принимает и ярус, и старое имя модели, а имя модели инструмента
   отвергает:

   ```sh
   rm "$h/.devkit/harness.local"
   printf '# T-002\n\nМодель: opus\n' > "$b/docs/tasks/T-002.md"
   HOME="$h" agentctl pick T-002 -C "$b" | head -3
   printf '# T-002\n\nМодель: base\n' > "$b/docs/tasks/T-002.md"
   HOME="$h" agentctl pick T-002 -C "$b" | head -3
   printf '# T-002\n\nМодель: claude-opus-4-6\n' > "$b/docs/tasks/T-002.md"
   HOME="$h" agentctl pick T-002 -C "$b"; echo "rc=$?"
   ```

   Псевдоним `opus` даёт `model: opus` с `tier: pro`, имя яруса `base` даёт
   `model: sonnet` с `tier: base`, имя модели инструмента это
   `ошибка: ... override-строка задаёт неизвестный ярус "claude-opus-4-6"` и
   `rc=1`.

5. Сложенные в одну модель соседние ярусы: сдвиг корректора модель не меняет, и
   вердикт говорит об этом вслух:

   ```sh
   rm -f "$b/docs/tasks/T-002.md"
   printf 'default = "claude-code"\nenabled = ["claude-code"]\n\n[claude-code]\nmini = "small"\nbase = "workhorse"\npro = "workhorse"\nmax = "big"\n' > "$h/.devkit/harness.local"
   printf 'taken = %s\nweek_all = 95%% сброс %s\n' "$(date +%Y-%m-%dT%H:%M)" "$(date -v+1d +%Y-%m-%dT%H:%M)" > "$h/.devkit/quota.local"
   HOME="$h" agentctl pick T-002 -C "$b"
   ```

   `model: workhorse` при `tier: base`, в причине `корректор: дефицит week_all,
   сдвиг pro -> base, модель та же`. Код 0.

6. Вердикты не двинулись ничем, кроме строки `tier` и имён ступеней (сверка со
   снимком, снятым до ярусов), и соседние утилиты целы:

   ```sh
   cd ~/projects/devkit/agentctl && go test ./...
   sh ~/projects/devkit/devkitctl/test.sh
   ```

   `ok github.com/dronrider/devkit/agentctl` и `devkitctl в порядке`.
