# DK-039: генерация файлов правил: AGENTS.md источник, тонкий CLAUDE.md, вклейка с маркерами

## Ход работы

- Исполнение: субагент opus/medium по вердикту pick, 2026-08-02.
- Ревью: субагент sonnet/high по вердикту pick, 2026-08-02.
- Генератор живёт отдельным модулем `devkitctl/rules.py` рядом с парсером
  профилей: доктор зовёт его проверкой, `--fix` тем же вызовом чинит, а
  `devkitctl new` генерит файлы последним шагом, когда доска уже заведена.
  Своего входа в генерацию нет, как и просил дизайн.
- Слои включённых харнесов читаются той же логикой, что в agentctl: машинный
  `~/.devkit/harness.local` включает, проектный сужает, конфига нет вовсе,
  значит включён claude-code.
- devkit переехал сам: `CLAUDE.md` стал `AGENTS.md`, а тонкий `CLAUDE.md`
  сгенерирован и закоммичен. Своё ядро devkit себе не импортирует (оно и есть
  этот репозиторий), поэтому в тонком файле стоят `@AGENTS.md` и
  `@RULES.board.md`.
- Отступления от дизайна выписаны в [LLD](../../../lld/DK-033-universal-kit.md),
  раздел «Отличия реализации от дизайна», строка DK-039: devkit как проект,
  импорт в рукописной части `AGENTS.md`, примеры маркеров в блоках кода,
  пустой список харнесов, битый профиль включённого харнеса, режим render и
  место вклейки.
- По замечанию ревью проектный слой перестал сужать молча: лишний ключ,
  секция, имя вне машинного списка и каждый суженный харнес называются
  находкой теми же словами, что у Go-стороны (`agentctl/harness.go`,
  `narrowByProject`). Один и тот же проектный конфиг обе реализации теперь и
  разбирают одинаково, и объясняют одинаково.
- Тесты: `devkitctl/test.sh` (юниты генератора прямо по модулю плюс сценарии
  доктора на временном HOME). По правкам прогнаны типовые мутации: игнор
  доски, снятая сверка хеша тела, импорты devkit при вклейке, несверяемый
  `src`, неудаляемый блок, отключённые находки про переезд, про две копии и
  про сужение слоёв, а по правке ревью ещё четыре, по одной на каждую строку
  разбора проектного слоя. На каждой падает хотя бы один шаг самопроверки.

## Сценарий проверки

Агентский: все шаги выполняются с машины агента, итог проверяется строками
вывода, живое дерево не меняется (`--fix` гоняется только на временном HOME и
синтетических проектах).

1. Самопроверка утилиты:

   ```sh
   sh ~/projects/devkit/devkitctl/test.sh
   ```

   Ожидается `devkitctl в порядке`.

2. Эталон для самого devkit виден командой и совпадает с тем, что лежит в
   репозитории:

   ```sh
   python3 ~/projects/devkit/devkitctl/rules.py ~/projects/devkit
   diff <(python3 ~/projects/devkit/devkitctl/rules.py ~/projects/devkit |
          sed -n '5,$p' | sed 's/^  //') ~/projects/devkit/CLAUDE.md
   ```

   Ожидается план и пустой diff:

   ```
   включены: claude-code (import)
   доска: есть
   вклейка правил: не нужна, все включённые понимают импорты
   CLAUDE.md (харнес claude-code):
     <!-- devkit:generated body=1fb804c4198d -->
     @AGENTS.md
     @RULES.board.md
   ```

3. Доктор по живому devkit не находит ничего про файлы правил:

   ```sh
   python3 ~/projects/devkit/devkitctl/devkitctl.py doctor -C ~/projects/devkit 2>&1 |
       grep -E 'AGENTS|CLAUDE|вклейка'
   ```

   Ожидается пустой вывод, код grep 1.

4. Чистое окружение: новый проект получает `AGENTS.md` из шаблона и
   сгенерированный тонкий файл, доктор по нему чист.

   ```sh
   tmp=$(mktemp -d); export HOME="$tmp/home"; mkdir -p "$HOME" "$tmp/newproj"
   git init -q "$tmp/newproj"
   python3 ~/projects/devkit/devkitctl/devkitctl.py new --prefix TT -C "$tmp/newproj"
   cat "$tmp/newproj/CLAUDE.md"
   python3 ~/projects/devkit/devkitctl/devkitctl.py doctor -C "$tmp/newproj" 2>&1 |
       grep -E 'AGENTS|CLAUDE|вклейка'
   ```

   Ожидается строка `CLAUDE.md сгенерирован для харнеса claude-code` в отчёте
   `new`, маркер `devkit:generated` первой строкой файла, три строки импорта
   (`@AGENTS.md` и два пути в devkit) и пустой вывод последнего grep.

5. Переезд проекта, подключённого по-старому: рукописный `CLAUDE.md` остаётся
   нетронутым, доктор подсказывает шаги, после `git mv` плюс `--fix` тонкий
   файл появляется.

   ```sh
   old="$tmp/oldproj"; mkdir -p "$old"; git init -q "$old"
   printf '# Старый проект\n\n@../devkit/RULES.md\n\nОсобенности.\n' > "$old/CLAUDE.md"
   python3 ~/projects/devkit/devkitctl/devkitctl.py doctor --fix -C "$old" 2>&1 |
       grep -E 'AGENTS|CLAUDE'
   git -C "$old" add -A && git -C "$old" mv CLAUDE.md AGENTS.md
   python3 ~/projects/devkit/devkitctl/devkitctl.py doctor --fix -C "$old" 2>&1 |
       grep -E 'AGENTS|CLAUDE'
   cat "$old/CLAUDE.md"
   ```

   Ожидается: на первом прогоне находка `нет AGENTS.md, а CLAUDE.md
   рукописный` с командой `git mv`, файл при этом не тронут и `AGENTS.md` не
   заведён; на втором `починено: CLAUDE.md сгенерирован для харнеса
   claude-code` плюс находка про оставшуюся в `AGENTS.md` строку импорта; в
   тонком файле маркер и `@AGENTS.md`.

6. Проектный слой сужает машинный список и говорит об этом (правка по
   замечанию ревью). На том же временном проекте:

   ```sh
   mkdir -p "$tmp/newproj/.devkit"
   printf 'enabled = ["ghost-tool"]\ndefault = "ghost-tool"\n\n[ghost-tool]\npro = "x"\n' \
       > "$tmp/newproj/.devkit/harness.local"
   python3 ~/projects/devkit/devkitctl/devkitctl.py doctor -C "$tmp/newproj" 2>&1 |
       grep -E 'сужен|не положен|не положена|включённых харнесов'
   ```

   Ожидаются четыре строки: ключ `default` проектному слою не положен, секция
   `[ghost-tool]` не положена, `ghost-tool` сужением не включить, `claude-code`
   сужен проектным слоем, плюс находка про пустой список включённых.

## Ревью

- enabled_harnesses в devkitctl/rules.py при сужении проектным .devkit/harness.local молчит там, где дизайн (DK-033, «Слои конфигурации») и агентовский agentctl/harness.go (narrowByProject) требуют находку: имя вне пересечения с машинным enabled отбрасывается без предупреждения, любой другой ключ или секция в проектном harness.local тоже проходят без находки. Проверено живым вызовом rules.enabled_harnesses с enabled = ["claude-code", "ghost-tool"] и лишним ключом/секцией: findings пуст. Не отражено и в разделе «Отличия реализации от дизайна».: исправлено, находки сужения проектным слоем сделаны как в Go-аналоге, тексты общие, покрыто самопроверкой
- devkitctl/README.md, вводный абзац (строки 3-4) не обновлён вместе с остальным файлом: называет CLAUDE.md шаблоном ручного подключения, хотя сам файл ниже (и код) теперь описывает AGENTS.md как шаблон, а CLAUDE.md стал генерённым тонким файлом. Минорная нестыковка, не блокирует, но дока не докручена полностью в той же правке.: исправлено, вводный абзац доки devkitctl переписан на AGENTS.md и генерённые файлы правил
