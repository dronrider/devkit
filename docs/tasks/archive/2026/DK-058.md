# DK-058: devkitctl doctor --fix не перекладывает разошедшееся определение агента, только называет cp: правка промптов не доезжает на машину сама

## Развилка: чья правка старше

`devkitctl/test.sh` держал случай «--fix не затирает правленое руками
определение» как есть, что и держало баг живым. Источник правды это devkit:
промпты агентов пишутся в репозитории и правятся ревью, ручная правка на
машине это либо старая копия, отставшая после `git pull`, либо локальный
эксперимент, который либо не нужен, либо должен был поехать коммитом в
devkit, а не остаться только на одной машине. Раз источник правды один,
`--fix` из основного чекаута переопределение переносит. Молчаливо не
затирает: отчёт называет файл и то, что он разошёлся, так что подмену видно
в выводе `doctor --fix`, даже если файл уже переписан. Защита `from_main`
(с worktree фичеветки на машину ничего не кладём) действует и здесь: из
worktree разошедшееся определение остаётся находкой с `cp`, как раньше.

## Сценарий проверки

Агентский целиком: временный `HOME` и временный проект, итог проверяется
grep и кодом возврата. Шаг 1 воспроизводит исходный баг: определение уже
разошлось на машине (так и было бы после ручной правки или после git pull
без `--fix`), и до этой задачи `doctor --fix` такое определение не трогал,
только называл находкой команду `cp`. Запускать с основного чекаута
(`cd ~/projects/devkit`), не из worktree задачи.

1. `sh devkitctl/test.sh` печатает «devkitctl в порядке», код возврата 0.

2. Разошедшееся определение на месте, `doctor --fix` его перекладывает и
   называет в отчёте:

```sh
h=$(mktemp -d); mkdir -p "$h/.claude/agents"
cp agents/exec-low.md "$h/.claude/agents/exec-low.md"
printf '\nручная правка на машине\n' >> "$h/.claude/agents/exec-low.md"
p=$(mktemp -d)
out=$(HOME="$h" python3 devkitctl/devkitctl.py doctor --fix -C "$p" 2>&1)
echo "$out" | grep -q 'починено:.*exec-low.md разошлось' && echo "ОТЧЁТ ЕСТЬ" || echo "ОТЧЁТА НЕТ"
diff -q "$h/.claude/agents/exec-low.md" agents/exec-low.md && echo "ПЕРЕЛОЖЕНО" || echo "НЕ ПЕРЕЛОЖЕНО (баг)"
```

   Ожидается «ОТЧЁТ ЕСТЬ» и «ПЕРЕЛОЖЕНО»: до правки второе было бы «НЕ
   ПЕРЕЛОЖЕНО», это и есть исходный баг.

3. Повторный `--fix` уже не находит расхождения (идемпотентность):

```sh
out2=$(HOME="$h" python3 devkitctl/devkitctl.py doctor --fix -C "$p" 2>&1)
echo "$out2" | grep -q 'exec-low' && echo "ЕСТЬ ЛИШНЯЯ НАХОДКА" || echo "ТИХО"
```

   Ожидается «ТИХО».

Обкатано до слияния на копии исправленного кода в временном каталоге,
подставленном под основной чекаут (`devkit_checkout` считает основным чекаутом
то, что не под worktree ветки задачи):

```
$ out=$(HOME="$h" python3 "$tmp/devkit/devkitctl/devkitctl.py" doctor --fix -C "$p" 2>&1)
$ echo "$out" | grep 'exec-low.md'
починено: определение агента $h/.claude/agents/exec-low.md разошлось с devkit, переложено из $tmp/devkit/agents/exec-low.md
$ diff "$h/.claude/agents/exec-low.md" agents/exec-low.md && echo "содержимое совпало с эталоном devkit"
содержимое совпало с эталоном devkit
$ out2=$(HOME="$h" python3 "$tmp/devkit/devkitctl/devkitctl.py" doctor --fix -C "$p" 2>&1)
$ echo "$out2" | grep 'exec-low' || echo "находок и починок про exec-low.md нет"
находок и починок про exec-low.md нет
```

Тем же способом на коде `main` (до правки) шаг 2 подтверждает исходный баг:
находка «определение агента ... разошлось с devkit; обновить: cp ...» вместо
починки, и файл после `--fix` так и остаётся со строкой «ручная правка на
машине».
