# DK-059: клик по уведомлению подменяет активное окно VS Code деревом задачи

Клик по баннеру от сессии, работающей в worktree задачи (например
`it-road-course-irc-75`), не открывал её окно, а переключал на это дерево то
окно, в котором пользователь сидел в тот момент (`devkit`). Окно при смене
папки перезагружается, и все работавшие в нём агенты умирают.

## Разбор корня

Цель перехода собирает `click_target` из [DK-047](DK-047.md):
рабочее дерево сессии уезжает отправителю как `-open vscode://file/<путь>`. В
журнале виден и конкретный случай:

```
2026-08-01T21:27:29 сессия 47b944b5 повод subagent_stop бэкенд terminal-notifier цель vscode://file/Users/rider/projects/it-road-course-irc-75 код возврата: 0
```

Такую ссылку редактор открывает в активном окне. Видно прямо в обработчике
протокола (`Visual Studio Code.app/Contents/Resources/app/out/main.js`,
`app#handleProtocolUrl()`): отдельное окно он заводит, только когда в запросе
стоит `windowId=_blank`, а иначе (`V && e.getWindowCount()===0`) лишь при
отсутствии окон вообще.

В DK-047 вопрос «поднимает существующее окно или заводит второе» проверялся на
дереве, которое уже открыто в окне, и там всё честно поднималось. Не
проверялся случай, когда окна с этим деревом нет ни одного, а для worktree
задачи он как раз обычный: сессия работает в дереве, которое пользователь
руками не открывал. Тогда редактору нечего поднимать, и он берёт под открытие
активное окно.

Цена ошибки несимметричная: в лучшем случае клик экономит переключение руками,
в худшем сносит окно вместе с идущей в нём работой.

## Правка

`hooks/notify.py`: к цели `vscode://file/<путь>` дописывается
`?windowId=_blank`. Поведение снято живьём на этой машине (имена окон брались
через `System Events`, потому что `code --status` показывает не все окна):

- дерево уже открыто в окне: окно поднимается, второго на то же дерево не
  заводится, остальные не трогаются;
- дерева нет ни в одном окне: открывается новое окно, ранее открытые остаются
  как были.

Обещание DK-047 (клик ведёт в окно позвавшей сессии) держится, а
разрушительная ветка закрыта.

## Дока

Раздел про клик в `hooks/README.md` говорит про параметр и про то, почему он
обязателен.

## Ход работы

- Правку делала сессия: однокоммитный багфикс с тестами идёт в main без ветки
  и без обязательного ревью (п. 1 и 2 раздела «Ветки, ревью и деплой»).
- Тесты: юниты `test_worktree_becomes_url`, `test_awkward_path_is_quoted` и
  новый `test_target_never_replaces_a_window` (цель любого дерева кончается
  параметром, и вопросительный знак в ней ровно один), прогон хука со стабом
  отправителя в `hooks/test.sh` проверяет и аргументы, и строку журнала.
- Регрессия подтверждена прогоном: тесты писались первыми и на старом коде
  падали тремя провалами (`AssertionError: ... != ...?windowId=_blank`), после
  правки прошли все 32.
- Мутации, на каждой краснеет хоть один тест: параметр снят с цели, параметр
  без `?`, параметр приклеен и к своему шаблону `DEVKIT_NOTIFY_OPEN`
  (краснеет `test_own_template`), цель мимо журнала (прогон в `hooks/test.sh`).

## Сценарий проверки

Агентский, кроме шага 4. Исходный баг воспроизводится объективно, но без
настоящей подмены окна: она уносит чужие сессии, ради чего задача и заведена.

1. Баг на старом коде. Цель собиралась без параметра, а такую ссылку редактор
   открывает в активном окне:

```sh
git show HEAD~1:hooks/notify.py > /tmp/notify-old.py
python3 -c "import importlib.util as u; s=u.spec_from_file_location('old','/tmp/notify-old.py'); m=u.module_from_spec(s); s.loader.exec_module(m); print(m.click_target({'CLAUDE_CODE_ENTRYPOINT':'claude-vscode'}, '/p/dk-059'))"
grep -c 'windowId=_blank' '/Applications/Visual Studio Code.app/Contents/Resources/app/out/main.js'
```

   Ожидается `('-open', 'vscode://file/p/dk-059')` без параметра и ненулевой
   счёт совпадений в обработчике протокола редактора.

2. Тесты: `python3 hooks/notify_test.py` завершается кодом 0 (32 теста),
   `sh hooks/test.sh` печатает «хуки в порядке», `sh devkitctl/test.sh`
   печатает «devkitctl в порядке».

3. Цель на сегодняшнем коде и то, что она уезжает отправителю:

```sh
python3 hooks/notify.py --self-test | grep 'клик по баннеру'
h=$(mktemp -d); d=$(mktemp -d)
printf '#!/bin/sh\nprintf "%%s\\n" "$*" > %s/args\n' "$d" > "$d/terminal-notifier"
chmod +x "$d/terminal-notifier"
printf '{"hook_event_name":"Notification","notification_type":"permission_prompt","session_id":"s1","cwd":"/p/devkit-dk-059","message":"проба"}' |
  HOME="$h" CLAUDE_CODE_ENTRYPOINT=claude-vscode DEVKIT_NOTIFY_BACKEND="$d/terminal-notifier" \
  python3 hooks/notify.py --hook claude-code
cat "$d/args"; grep -c 'цель vscode://file/p/devkit-dk-059?windowId=_blank' "$h/.devkit/notify.log"
```

   Ожидается цель с `?windowId=_blank` в самопроверке, в аргументах
   `-open vscode://file/p/devkit-dk-059?windowId=_blank`, в журнале одна такая
   строка.

4. Пользовательский шаг: дождаться настоящего баннера от сессии, которая
   работает в worktree задачи, и кликнуть по нему. Ожидается, что дерево
   задачи откроется своим окном (или поднимется уже открытое), а окно, в
   котором работали до клика, останется на своей папке и живым.

## Прогон после выката

Прогнан на основном чекауте 2026-08-01. Шаги 1-3 прошли, шаг 4 за
пользователем.

(дерево уже открыто, дерева нет ни в одном окне) снято живьём при разборе.
