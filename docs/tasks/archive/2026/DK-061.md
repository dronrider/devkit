# DK-061: клик по уведомлению открывает лишнее окно worktree вместо окна сессии

Продолжение [DK-059](DK-059.md). Там клик перестал сносить чужое
окно, но приходить стал не туда: баннер от субагента, работавшего в
`it-road-course-irc-75`, открывает отдельное окно на это дерево, а сессия всё
это время идёт в окне `it-road-course`, и пользователю нужно именно оно.

## Разбор корня

Цель перехода собиралась из `cwd` события. У события `SubagentStop` это `cwd`
субагента, а он уходит в worktree задачи, тогда как окно редактора осталось
на дереве, где сессию завели. Своего окна у worktree нет, поэтому редактор его
и открывает: до DK-059 подменой активного окна, после DK-059 отдельным окном.
Оба раза мимо работающей сессии.

Что окон worktree не бывает, видно по самим сессиям: в `~/.claude/projects/`
лежат только основные чекауты (`-Users-rider-projects-it-road-course`), папки
вида `...-irc-75` нет ни одной. Сессия всегда заводится в основном чекауте, а
в worktree уходит субагент.

Дерево сессии лежит в её транскрипте. Живое событие (снято дампом хука на
работающей сессии):

```json
{"session_id": "5acbbc0e...", "cwd": "/Users/rider/projects/it-road-course",
 "transcript_path": "/Users/rider/.claude/projects/-Users-rider-projects-it-road-course/5acbbc0e....jsonl",
 "agent_type": "review-high", "hook_event_name": "SubagentStop"}
```

Первые записи транскрипта служебные (`queue-operation`), дальше идёт запись с
`cwd` самой сессии. Раскодировать имя папки в `~/.claude/projects/` обратно в
путь нельзя однозначно (дефис там и разделитель, и часть имени: `it-road-course`),
а `cwd` из записи берётся как есть.

## Правка

`hooks/notify.py`: цель клика собирается из дерева сессии (`session_tree`), а
`cwd` события остаётся запасным путём, когда транскрипт не читается. Чтение
ограничено первыми 20 записями: транскрипт вырастает на десятки мегабайт, а
`cwd` лежит в начале или не лежит вовсе.

Заголовок показывает разом окно и задачу: `it-road-course (irc-75): субагент
отработал`. Одно только дерево задачи не говорит, куда смотреть, одно только
окно теряет задачу, над которой шла работа.

## Дока

Раздел про клик в `hooks/README.md` рассказывает, откуда берётся дерево
сессии и почему не из `cwd`; абзац про заголовок дополнен видом со скобками.

## Ход работы

- Правку делала сессия: багфикс с тестами идёт в main без ветки (п. 1 раздела
  «Ветки, ревью и деплой»).
- Форма события снята живьём: в хук временно добавлялся дамп события в файл,
  первое же настоящее `SubagentStop` от соседней сессии показало и
  `transcript_path`, и `agent_transcript_path`. Дамп убран.
- Тесты: юниты на `session_tree` (дерево задачи уступает дереву сессии, битый
  и отсутствующий транскрипт откатываются на `cwd`, предел чтения соблюдается)
  и на `session_label` (окно и задача, совпадение, дерево не из проекта),
  прогон в `hooks/test.sh` на событии с транскриптом проверяет заголовок и
  цель разом.
- Мутации, на каждой краснеет хоть один тест: цель снова из `cwd` события
  (прогон), транскрипт не читается (юниты и прогон), заголовок без окна сессии
  (юниты и прогон), снятый предел чтения (юнит), снятый `windowId=_blank`
  (юниты и прогон). Первая версия юнита на предел мутацию пропускала, потому
  что считала число записей из самой константы; ожидание переведено на своё
  число.

## Сценарий проверки

Агентский, кроме шага 4.

1. Баг на старом коде: цель бралась из `cwd` события, то есть из дерева
   задачи, а не из дерева сессии.

```sh
git show HEAD~1:hooks/notify.py > /tmp/notify-old.py
python3 - <<'PY'
import importlib.util as u, json, tempfile, os
s = u.spec_from_file_location('old', '/tmp/notify-old.py')
m = u.module_from_spec(s); s.loader.exec_module(m)
tr = os.path.join(tempfile.mkdtemp(), 't.jsonl')
open(tr, 'w').write('{"type":"user","cwd":"/p/it-road-course"}\n')
print(m.parse_event({"hook_event_name": "SubagentStop", "cwd": "/p/it-road-course-irc-75",
                     "transcript_path": tr, "last_assistant_message": "готово"})[1])
PY
```

   Ожидается заголовок `it-road-course-irc-75: субагент отработал`: старый
   разбор транскрипт не смотрит вовсе.

2. Тесты: `python3 hooks/notify_test.py` завершается кодом 0 (39 тестов),
   `sh hooks/test.sh` печатает «хуки в порядке», `sh devkitctl/test.sh`
   печатает «devkitctl в порядке».

3. Живое событие субагента из worktree ведёт в окно сессии. Транскрипт берётся
   настоящий, отправитель подставной, живой журнал не трогается:

```sh
h=$(mktemp -d); d=$(mktemp -d)
printf '#!/bin/sh\nprintf "%%s\\n" "$*" > %s/args\n' "$d" > "$d/terminal-notifier"
chmod +x "$d/terminal-notifier"
tr=$(ls -t ~/.claude/projects/-Users-rider-projects-it-road-course/*.jsonl | head -1)
python3 -c "
import json, sys
print(json.dumps({'hook_event_name': 'SubagentStop', 'session_id': 'live1',
                  'cwd': '/Users/rider/projects/it-road-course-irc-75',
                  'transcript_path': sys.argv[1], 'agent_type': 'exec-medium',
                  'last_assistant_message': 'задача закрыта'}))" "$tr" |
  HOME="$h" CLAUDE_CODE_ENTRYPOINT=claude-vscode DEVKIT_NOTIFY_BACKEND="$d/terminal-notifier" \
  python3 hooks/notify.py --hook claude-code
cat "$d/args"
```

   Ожидается `-title it-road-course (irc-75): субагент отработал` и
   `-open vscode://file/Users/rider/projects/it-road-course?windowId=_blank`,
   то есть цель ведёт в дерево сессии, а не в дерево задачи.

4. Пользовательский шаг: дождаться баннера от сессии, у которой субагент
   работает в worktree, и кликнуть. Ожидается переход в уже открытое окно этой
   сессии, без нового окна на дерево задачи.
