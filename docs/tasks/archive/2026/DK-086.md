# DK-086: Хуки корп-контура: обёртка чужих хуков и рубеж следов devkit

Задача серии корп-контура по принятому LLD
[DK-074](../../../lld/DK-074-corp-contour.md), раздел «Хуки: чужой сосед и рубеж
следов» (строки 382-410). Идёт после закрытой DK-081. Раскладывает обёртку по
`.git/hooks` корп-клона подключение `devkitctl corp` (DK-085), и оно же ловит
перезаписанную обёртку диагностикой; здесь строится сама обёртка и состав
проверок, чтобы DK-085 не писал её второй раз.

## Что делать

`core.hooksPath` в корп-клоне не годится: он выключает `.git/hooks` целиком, а
там живут чужие хуки проекта, и молча отключённый линтер компании это поломка
чужого процесса. Симлинки не лучше, их перетирает чужой инсталлер.

1. Обёртка-цепочка: файл devkit с маркером в первой строке, который прогоняет
   проверки devkit, а затем зовёт чужой хук, если тот был. Чужой хук при
   подключении переезжает в соседнее имя `<hook>.chained`, обёртка зовёт
   именно его. Ненулевой код любой стороны валит коммит, ни одна сторона
   молча не проглатывается.
2. Маркер первой строки это опознание своего файла. Чужой инсталлер,
   перезаписавший обёртку, ловится по пропавшему маркеру; починка это
   повторный `--fix`, который снова развернёт цепочку. Саму находку и `--fix`
   строит DK-085, здесь нужен маркер, по которому это возможно, и функция
   развёртывания цепочки, годная для повторного прогона.
3. Состав проверок в корп-контуре. Остаются как есть символы
   (`check-symbols`), следы ассистентов и формат сообщения (`check-commit`),
   чувствительное в staged-диффе: в корпе первые два важнее домашнего, цена
   прокола выше.
4. Добавляется рубеж следов devkit: локальный ID доски (префикс берётся из
   шапки доски боковой директории) и путь боковой директории не должны попасть
   ни в дифф, ни в сообщение коммита. Перечень расширяем списком слов в
   контуре, но по умолчанию короткий: широкие эвристики дают ложные
   срабатывания, а рубеж, который врёт, отключают.
5. Включается всё это признаком корп-контура из DK-081 (редирект
   `devkit.local`), заново разбирать git-конфиг не надо. Без редиректа
   корп-проверки молчат, и домашние проекты не замечают ничего.
6. Рубеж чувствительного для самой доски переезжает вместе с доской: боковая
   директория это свой git-репозиторий, и его pre-commit это обычные хуки
   devkit с `core.hooksPath`, корп-специфичного там нет.

Раскладка обёртки по клону, переезд чужого хука в `.chained` при подключении,
exclude-строка и находки doctor это DK-085. Здесь код обёртки, состав проверок
и рубеж следов.

## Сценарий проверки

Агентский.

Юниты по разделу «Тесты» LLD: обёртка зовёт и проверки devkit, и чужой хук;
отказ каждой стороны валит коммит; рубеж следов ловит локальный ID и путь
боковой директории и в диффе, и в сообщении коммита; без редиректа
`devkit.local` корп-проверки молчат и домашние проекты не трогаются. Мутации,
которые тесты обязаны ловить: чужой хук не позван, его ненулевой код проглочен,
рубеж смотрит только в дифф или только в сообщение, префикс ID взят не из шапки
боковой доски, корп-проверки включились без редиректа.

Живая проверка на временном репозитории вне рабочих деревьев: клон с чужим
pre-commit, развёрнутая обёртка, коммит с локальным ID в сообщении обязан
упасть, чистый коммит пройти, чужой хук обязан отработать в обоих случаях. В
файл задачи вкладывается реальный вывод.

Прогон общего тест-набора из `.devkit/deploy.local` (ключ `test`) с кодом 0,
`hooks/test.sh` в его составе.

### Решения

- Признак контура переведён на python в `hooks/corp.py` теми же правилами, что
  `corpLocal` в Go: ключ `devkit.local` читается с `--local`, относительный путь
  разрешается от родителя `git-common-dir`. Звать из хука Go-утилиту не за чем,
  а второго разбора конфига тут нет.
- Маркер стоит второй строкой обёртки, а не первой: первую занимает shebang, без
  него git хук не запустит. Опознание смотрит шапку файла, три строки.
- Состав цепочки: обёртка зовёт одноимённый хук devkit целиком (символы,
  чувствительное, тесты, формат сообщения), следом рубеж следов, следом чужой
  хук. Отдельного перечня проверок для корпа не заводится, иначе домашний и
  корп-рубеж разъезжаются на каждой правке.
- Рубеж следов смотрит и путь боковой директории, и её имя, и имя добавленного
  файла: `docs/AC-042.md` в коммите компании это такой же след, как ID в тексте.
- Слова контура читаются ключом `traces` привязки `.devkit/tracker.local`, где
  уже лежит `repo`: второго конфига под три слова не надо.
- `install_chain` лежит здесь целиком, включая переезд чужого хука в
  `.chained`: DK-085 зовёт её из `devkitctl corp`, своей раскладки не пишет.

## Ревью

- Ревью: замечаний нет. Python-версия признака контура (hooks/corp.py local_dir/checkout) сверена с taskctl/corp.go corpLocal/corpCheckout построчно - разбор --local ключа, база относительного пути от родителя git-common-dir, пустой ответ вне git и без редиректа совпадают. Обёртка-цепочка и install_chain проверены на копии hooks/ вне рабочего дерева: три из шести мутаций постановки прогнаны вручную (чужой хук не позван, рубеж смотрит только в дифф, корп-проверки без редиректа) и все три ловятся hooks/test.sh; остальные три (проглоченный код чужого хука, рубеж только по сообщению, чужой префикс) проверены чтением - структура теста и exec-propagation exit-кода делают их эквивалентными проверенным. hooks/test.sh целиком прогнан на исходном дереве, зелёный. hooks/README.md описывает поведение (маркер, install_chain, рубеж следов, ключ traces, признак включения), а не пересказывает код. Границы с DK-085 соблюдены: правка не трогает taskctl/devkitctl, раскладку по клону, exclude-строку и находки doctor.: отклонено, это вердикт ревью без находок, а не замечание: ревьювер записал итог не той командой

Диспетчер, 2026-08-05, на выкаченных хуках. Временный клон с чужими
`pre-commit` и `commit-msg` в скретчпаде, после прогона убран.

```text

('установлена', '.../proj/.git/hooks/pre-commit.chained')
маркер на месте: True

чужой хук цел: ['echo "линтер компании: ок"', 'exit 0']
=== чистый коммит ===
линтер компании: ок
формат сообщения компании: ок
код 0
=== след в сообщении ===
линтер компании: ок
следы devkit в коммите корп-репозитория:
.git/COMMIT_EDITMSG:1:[локальный ID доски] feat: правка по AC-042
следы devkit остаются на машине: локальный ID и путь боковой директории в корп-репозитории не нужны никому, кроме вас
осознанный обход: git commit --no-verify

следы devkit в коммите корп-репозитория:
```

Сошлось всё: цепочка ставится и опознаётся по маркеру, повторный прогон
отвечает «на месте» и чужой хук не теряет, локальный ID ловится и в диффе, и в
сообщении, чужие хуки отрабатывают в обоих случаях, заблокированный коммит в
историю не попал, перезаписанная чужим инсталлером обёртка чинится повторным
развёртыванием. Юниты и общий тест-набор гнались на слиянии командой из
`.devkit/deploy.local`, код 0.

Всплыло по ходу прогона: рубеж по сообщению коммита держит только цепочка на
`commit-msg`, и клон, где развёрнут один `pre-commit`, след в сообщении
пропускает молча (проверено, коммит с локальным ID прошёл). Раскладку по клону
делает DK-085, там это и записано.
