## Решения

- **Зелёность решает проверка, а не код возврата команды прогона.** Агент может
  выйти с ошибкой, сделав работу, и наоборот. Но зелёная проверка при упавшей
  команде называется отдельной строкой итога: так выглядит проверка на
  отрицание, зеленеющая на сессии, которой не было.
- **Проба перед полным проходом.** Нашлось живьём: во временном `HOME` харнес не
  авторизован, `claude -p` отвечает «Not logged in», и сценарий «правила не
  читались» выходит зелёным, потому что читать было некому. Одна пробная сессия
  до прохода ловит это за копейки, а не за сотню долларов. Чинится флагом
  `--home-seed`: это дерево, которое кладётся во временный HOME до раскладки
  правил (на macOS туда идут ключи из связки), разбор в README утилиты.
- **Раскладок ровно две, и они вход, а не начинка.** Стенд копирует дерево
  раскладки поверх синтетического проекта, поддиректория `home/` едет во
  временный HOME. Свои тесты гоняются на фикстурных раскладках, поданных как
  боевые, поэтому от генератора из DK-103 стенд не зависит вовсе.
- **Ярус в модель разворачивает `agentctl harness`.** Маппинг живёт в профиле
  харнеса, второго читателя профиля стенд не заводит; нет agentctl, значит
  модель называется флагом `--model`.
- **Конец прогона объявляется в файле сценария** (`конец: сессия`, `субагент`
  или `любой`), а не выводится флагом на всех разом: сценарий про сам спавн
  исполнителя субагентским концом бессмысленен.
- Проверки, которым нужен ход работы, а не итог (звался ли `taskctl show`,
  спавнился ли субагент), грепают транскрипт. Это самое хрупкое место стенда:
  формат потока живёт на стороне инструмента, и грепы калибруются по живым
  транскриптам первого полного прохода (DK-104).
- Живой прогон остаётся ручным шагом задач разреза и хуков. По ходу работы
  живьём прогнаны три сценария на дешёвом ярусе: механика, авторизация и цена
  сессии (около трёх центов на короткий сценарий) сошлись с расчётом дизайна.

## Сценарий проверки

Агентский. Гоняется на фикстурных раскладках и подложной модели, живых сессий не
поднимает, прода не касается. Команды из директории `obeycheck` чекаута devkit.

1. Тесты утилиты и сборка бинаря:

   ```sh
   go test ./... && go build -o /tmp/obeycheck .
   ```

   Ожидание: код 0, строка `ok  github.com/dronrider/devkit/obeycheck`.

2. Сценарии первой очереди читаются все десять:

   ```sh
   /tmp/obeycheck --list | wc -l
   ```

   Ожидание: `10`, а сам `--list` без `wc` печатает заголовки от «написать абзац
   документации» до «отдать задачу исполнителю».

3. Раскладка, где модель работает, против такой же: регрессии нет, код 0.

   ```sh
   /tmp/obeycheck --scenarios testdata/scenarios --only press -k 3 \
     --agent-cmd "sh $PWD/testdata/fake-agent.sh" \
     testdata/layouts/full testdata/layouts/core-green; echo "код: $?"
   ```

   Ожидание: строка таблицы `нажать кнопку` со счётом `3/3` в обеих колонках и
   вердиктом `держится`, итог «регрессий нет», `код: 0`.

4. Та же пара, где на второй раскладке модель бездельничает: регрессия и код 1.

   ```sh
   /tmp/obeycheck --scenarios testdata/scenarios --only press -k 3 \
     --agent-cmd "sh $PWD/testdata/fake-agent.sh" \
     testdata/layouts/full testdata/layouts/core; echo "код: $?"
   ```

   Ожидание: счёт `3/3` против `0/3` с вердиктом `регрессия`, итог «с
   регрессией 1, вынос не принимается», `код: 1`.

5. Красный на обеих раскладках это находка про правило, а не регрессия:

   ```sh
   /tmp/obeycheck --scenarios testdata/scenarios --only press -k 2 \
     --agent-cmd "sh $PWD/testdata/fake-agent.sh" \
     testdata/layouts/core testdata/layouts/core; echo "код: $?"
   ```

   Ожидание: вердикт `красный на обеих`, строка про находку про сами правила,
   `код: 0`.

6. Окружение прогона: временный HOME и синтетический проект, живой чекаут не
   тронут.

   ```sh
   rm -rf /tmp/obey-check
   /tmp/obeycheck --scenarios testdata/scenarios --only env -k 1 \
     --agent-cmd "sh $PWD/testdata/fake-agent.sh" \
     --work /tmp/obey-check --keep \
     testdata/layouts/full testdata/layouts/core; echo "код: $?"
   grep -c "^HOME=/private/tmp/obey-check" /tmp/obey-check/env-full-1/project/env.txt
   ls /tmp/obey-check/env-full-1/home/.claude/agents/exec-medium.md
   git -C .. status --porcelain docs/TASKS.md
   ```

   Ожидание: `код: 0` и вердикт «держится» (проверка сценария сама смотрит
   доску, код, хуки и фиктивный origin внутри прогона), `1` от grep,
   существующий файл определения субагента, пустой вывод `git status` по живой
   доске.

7. Проба ловит команду прогона, которая сессии не поднимает:

   ```sh
   /tmp/obeycheck --scenarios testdata/scenarios --only press -k 1 \
     --agent-cmd "sh $PWD/testdata/fake-agent.sh" \
     testdata/layouts/broken testdata/layouts/core; echo "код: $?"
   ```

   Ожидание: `код: 2` и строка «пробная сессия ... не отработала» со ссылкой на
   README и на флаг `--no-preflight`.

8. Прибрать за собой: `rm -rf /tmp/obey-check /tmp/obeycheck`.
