# DK-111: Цель: корп-контур по DK-074, конвейер поверх внешнего трекера

## Цель

Довести до конца серию корпоративного контура по принятому LLD
[DK-074](../../../lld/DK-074-corp-contour.md): семь задач DK-081..DK-087 закрыты в
архив вместе с доками из раздела «Затрагиваемая документация» LLD. После этого
корп-проект подключается командой `devkitctl corp`, доска живёт в боковой
директории, статусы, оценка и ворклоги уезжают в трекер через `trackctl`, а
слияние честно останавливается на границе MR.

DoD, агентский:

- `taskctl show DK-081`..`DK-087` показывают все семь задач в архиве;
- общий тест-набор из `.devkit/deploy.local` (ключ `test`) проходит с кодом 0;
- живой прогон на чистом окружении из раздела «Тесты» LLD проходит с кодом 0:
  временный «корп»-репозиторий с чужим pre-commit, подключение `devkitctl
  corp`, цикл задачи от `trackctl take` через `submit` до отказа `shipctl
  merge` с подсказкой MR на подложном адаптере; затем клон сносится,
  клонируется заново, повторный `devkitctl corp` восстанавливает обвязку
  (доска цела, второй прогон ничего не меняет).

DK-088 (LLD имитации человеческого темпа) в цель не входит: скоуп LLD выносит
её отдельным решением.

## Итог

Цель достигнута. Корп-проект подключается одной командой `devkitctl corp`,
доска живёт в боковой директории и в дерево клона не попадает, статусы, оценка
и ворклоги уезжают в трекер через `trackctl`, а слияние честно останавливается
на границе MR.

Сделано восемь задач вместо семи. Семь по разбивке LLD DK-074 (DK-081..DK-087,
все в архиве), восьмая DK-124 родилась из прогона самого DoD.

DoD прогнан целиком:

- `taskctl show DK-081`..`DK-087` показывают все семь задач в архиве;
- общий тест-набор из `.devkit/deploy.local` проходит с кодом 0;
- живой прогон на чистом окружении сошёлся: временный корп-репозиторий с
  чужими `pre-commit` и `commit-msg`, подключение `devkitctl corp`, цикл задачи
  от `shipctl start` с вызовом `trackctl take` через `submit` с ворклогами до
  отказа `shipctl merge` с подсказкой про MR; затем клон снесён, клонирован
  заново, и повторный `devkitctl corp` восстановил обвязку, не тронув доску.
  Прогон гонялся на двух связках префиксов сразу, чтобы решение DK-124 не
  держалось на их совпадении.

Потрачено 5 процентных пунктов бакета `week_all` из отпущенных 30 и 1 из 15 по
`week_max`. Бакеты общие с целью DK-109, шедшей параллельно.

Что стоит знать дальше. Два бага из восьми нашлись только живым прогоном на
по-настоящему подключённом проекте, и оба прошли мимо тестов: DK-087 заводила
дерево задачи без кода проекта, а рубеж следов из DK-086 валил каждый коммит по
конвенции компании. Общее у них то, что фикстуры тестов расходились с тем, что
раскладывает `devkitctl corp`, поэтому проверка серии, где утилиты собираются в
конвейер, стоит на живом стенде, а не на фикстурах. Открытой осталась мелочь
DK-123: `shipctl start` в корп-контуре советует `merge`, которого там нет.
