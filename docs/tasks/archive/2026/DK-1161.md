# DK-1161: Отметка обкатки не гаснет от коммита файла соседней задачи

## Что происходит

Ворота перевода в Check считают отметку обкатки свежей при одном условии.
После неё в ветку не должно приехать ничего, кроме файла самой этой задачи.
Правило живёт в internal/rehearsal, функция onlyTaskDocSince.

Для одиночной задачи это работает. Поезду из нескольких оно закрывает дорогу
насовсем. Запись обкатки ложится в файл своей задачи и коммитится, а для
соседней задачи этот коммит уже чужой. Обкатали первую, закоммитили, обкатали
вторую, закоммитили, и отметка первой протухла.

Замер 25 сентября на поезде из шести строк. После коммита записи DK-669 отметка
DK-1157 стояла на a057fd4addf0 при HEAD 355928bff4cf, то есть числилась
протухшей, хотя код задачи никто не трогал. Дважды подряд ворота отбивали
shipctl ship именно так.

Выкат при этом автоматический, разлив зовёт тик сторожка каждые пять минут. Он
упирается в эти же ворота и повторяет отказ бесконечно.

Просится одно из двух. Либо свежесть считать по коду задачи, а коммиты файлов
любых задач доски считать безобидными. Либо обкатывать весь состав разом одним
прогоном, с общей отметкой на поезд.

## Чего хотим

## DoD

Коммит, который трогает только файлы задач доски, отметку обкатки соседней
задачи не гасит. Коммит с кодом гасит её по-прежнему.

Поезд из нескольких обкатанных задач проходит ворота перевода в Check.

Тест ловит старое поведение: на коде до правки он красный.

## Ревью

Уровень 3 до 48b6030: до 48b6030e2: неопределённость 3 из вердикта agentctl pick (effort high), плюс критический путь: правка ворот обкатки, стоящих на каждом move check и merge

- [возврат: постановка, 2026-09-25] не блокирует: boardDoc в internal/rehearsal/rehearsal.go не покрывает docs/TASKS.md. Коммит стороннего сброса статуса соседней задачи по поезду (taskctl move/stage) обычно трогает docs/TASKS.md вместе со своим docs/tasks/<ID>.md (см. коммиты 89958fede, 10c5e71e9) и всё ещё погасит отметку между обкаткой и переводом в Check, если ляжет в это окно. Регресса нет, старый код был строже и наблюдаемый провал (DK-669 между DK-1157) чинит, но DoD «поезд проходит ворота» гарантирован не для всех раскладов интерливинга. Стоит либо явно сузить формулировку DoD до записей docs/tasks/*.md, либо завести приписку-долг на разбор docs/TASKS.md: исправлено, доска и архив доски вошли в boardDoc, покрыто TestFreshSurvivesBoardMove
- [возврат: правила, 2026-09-25] не блокирует: internal/rehearsal/rehearsal.go:78-79, onlyTaskDocSince держит параметр id и гасит предупреждение строкой «_ = id // ...». Go не требует такой заглушки для неиспользуемого параметра функции, она только сбивает с толку. Проще убрать id из сигнатуры (func onlyTaskDocSince(root, mark string) bool) и поправить единственный вызов в Fresh: исправлено, параметр id убран из сигнатуры
