# DK-1233: Полка ждущих держит признак ожидания закрытой задачи

## Что происходит

DK-892 закрыта 27 сентября и уехала в архив, а строка её два дня висела в блоке
«Ожидают ответа» на дашборде. Держал её файл признака
.devkit/chat/task-DK-892.ask, внутри стендовый вопрос «проба-один» и сессия
b31a733b-da4f-4cc3-9a8d-fab3f5545e91. Признак снимает только ответ через панель
(settleAsk), срока у него нет с DK-715. Проверка waitAlive в
tools/dashboard/waiting.go знает два случая, где ожидание гаснет. Первый это
разговор в архиве, второй это ответ человека в транскрипте. Записи чата у этой сессии нет вовсе
(~/.devkit/chats/<SID>.json отсутствует), chatStoreRead отдаёт пустую запись с
Archived false, и первый случай не срабатывает. Закрытие задачи waitAlive не
смотрит. Убрал руками, rm файла признака.

Разбор груминга сверил это по коду на сегодня. Признак всегда пишется в
основной чекаут (tools/taskctl/ask.go:190), и чужого дерева у него не бывает.
Второй проход полки, тот что обходит признаки без строки доски, зовёт ту же
waitAlive (tools/dashboard/waitshelf.go:81), поэтому оба потребителя чинятся
одной правкой. Уборку drop_asks зовёт только пробуждение припаркованной строки
(tools/devkitctl/watch.py:1337), а закрытая задача в Blocked не стоит и мимо
парковки проходит. Снятие признака ответом приехало с DK-1204, и на закрытие
развилки исполнителем оно не срабатывает намеренно
(TestDecideCloseByExecutorKeepsAsk).

Отвечать на такой вопрос некому. Сессия мертва, задача закрыта, чат в архиве.
Человек видит в полке строку, по которой ничего сделать нельзя, и из панели её
не убрать. Разобраться, откуда она берётся, стоило сессии с чтением
waiting.go и README дашборда. Полка при этом главный экран ожиданий, и мусор
в ней обесценивает счётчик кнопки.

## Чего хотим

Закрытая задача в полке ожиданий не появляется, сколько бы признаков от её
сессий ни осталось.

## Границы

Условий, посильных только человеку, не нашёл: доступов, секретов, шагов наружу и согласия правка не требует. Искал по коду признака (internal/chat, taskctl ask и decide, dashboard waiting и waitshelf), по сторожку devkitctl watch.py и по доке дашборда. Вид приёмки агентский, ни один из шести барьеров не встал: итог читается ручкой `/api/waiting` и тестами go, а закрытие задачи подделывается синтетической доской, на которой уже работает стенд smoke.
