# DK-140: переезд файлов devkit по новой раскладке с починкой путей на машинах

Задача цели [DK-135](../../DK-135.md), вторая в её нарезке. Решение принято в
[DK-139](DK-139.md), документ `docs/lld/DK-139-repo-layout.md`.

## Задача

Разложить репозиторий по правилу из раздела «Раскладка» `README.md`: семь
утилит уезжают в `tools/`, четыре каталога агентской сессии в `kit/`, `hooks/`
и `docs/` остаются, фикстура синтетического проекта `obeycheck/project/`
уезжает внутрь `testdata/`. Что двигается и какие пути правятся тем же
коммитом, перечислено в разделе «Переезд для DK-140» документа DK-139
семнадцатью пунктами, и работать надо по нему, а не по памяти.

Отдельно из тех пунктов, потому что мимо них проехать легче всего:

- перед началом освежить перечень грепом из документа (три шаблона: путь со
  слэшем, сегмент в кавычках, адрес модуля); греп находит файл, а не строку, и
  имени каталога из переменной не видит, так что перечень пунктов остаётся
  главным;
- переезд едет одним коммитом: между `git mv` и починкой путей дерево красное,
  а поезд задач такого не переживает;
- `docs/tasks/**` и `docs/lld/**` не правятся, они описывают состояние на
  момент решения; живая дока (`README.md`, `CONNECT.md`, README утилит,
  `RULES.md`, `RULES.board.md`) правится;
- раздел «Состав» `README.md` в этой задаче как раз правится: он должен
  описывать раскладку после переезда, это пункт 1 DoD цели. Оговорку в конце
  раздела «Раскладка» про то, что дерево правилу ещё не отвечает, снять в
  своей половине;
- пункт 17, обход подключённых проектов и машины через `devkitctl doctor
  --fix`: без него в тонких файлах проектов остаются мёртвые указатели на
  скиллы, а в `~/.claude/skills/` старые копии команд. Шаг ручной, список
  проектов собирается грепом по соседям чекаута.

Гитигнорнутый `.devkit/deploy.local` (команды выката и тестов со старыми
путями) в дереве задачи не виден и правится диспетчером перед слиянием, сюда
не лезть.

## Сценарий проверки

Агентский.

1. Дерево отвечает правилу: в корне только `tools/`, `kit/`, `hooks/`, `docs/`,
   два служебных каталога и файлы, названные разделом «Раскладка».
2. Прогоны, те же, что в CI: шесть `go test ./...`, `hooks/test.sh`,
   `tools/devkitctl/test.sh`, `kit/skills/test.sh`,
   `kit/skills/goal-loop/test.sh`, `check-exec-bit.py` и `check-symbols.py`.
3. `git log --follow` на переехавшем файле показывает историю до переезда.
4. Обход пункта 17 прогнан: указатели в тонком файле подключённого проекта
   перевыпущены на новые пути, копии скиллов в `~/.claude/skills/` несут новые
   команды. Тесты этого не показывают, они гоняют генератор на синтетике.
