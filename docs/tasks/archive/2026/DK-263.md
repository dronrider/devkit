# DK-263: Интерактивные сессии агентов видны в работах: живость по mtime транскрипта, включая окна боковых деревьев

записана 2026-08-11, вопрос пользователя при проверке цели DK-112

## Чего хотим

Дашборд узнаёт живые работы по tmux-сессиям и реестру целей, и интерактивное
окно агента (VSCode, вторая подписка GLM в боковом дереве devkit-glm)
невидимо: ни tmux, ни записи в реестре. Первый пункт цели «видно, над чем
агенты работают прямо сейчас» для таких окон не выполняется.

Источник живости есть: транскрипт идущей сессии дописывается каждым ходом.
Показать в работах проекта интерактивные сессии, чей транскрипт обновлялся
недавно (порог решить, минуты), с заголовком задачи по привязке DK-252,
подписью «интерактивная сессия» и без кнопки остановки (снимать нечего,
сессию ведёт человек в окне). Каталоги боковых деревьев (devkit-glm,
devkit-dk-NNN) уже входят в выборку сессий, работы из них относятся к
родному проекту. Порог и решение записать в LLD.

## Ранг

`25+6+2+0+1 = 34`, P2.

- Ценность 6. Прямой вопрос пользователя, дыра в первом пункте цели.
- Неопределённость 2. Источник ясен, развилки в пороге живости и виде

- Поправка на баг 0. Оба источника работ собраны как задумано.
- Рычаг 1. Живость сессий пригодится экрану «Агенты» (DK-256).

## Сценарий проверки

Агентский: фикстурная сессия со свежим mtime и привязкой к задаче видна в
работах с подписью и без кнопки остановки; протухшая по порогу не видна;
tmux-работы не задваиваются (сессия конвейера и его транскрипт это одна
работа). Живая проверка: окно соседней подписки с идущей работой появляется
в работах проекта devkit руками диспетчера.

## Ход работы

- Исполнение: субагент opus/medium по вердикту pick (квота: week_all 16%, week_max 17%, снимок 0м назад, сдвига нет), 2026-08-11.
- Порог живости двенадцать минут: ход бывает долгим (одиночный прогон в
  foreground харнес держит до десяти минут, вокруг него размышления и правка),
  пятнадцать держали бы закрытое окно живым четверть часа. Разбор в LLD.
- Третий источник работ собирается в `sessionWorks` рядом с разбором сессий, а
  `liveWorks` стал методом сервера: ему понадобились память процесса на шапки
  и часы, подменяемые в тестах.
- Задача интерактивной работы берётся привязкой DK-252, ID с чужим префиксом
  задачей проекта не считается. Дедупликация по задаче: tmux-работа поглощает
  интерактивную с тем же ID.
- Стоп такой работы это 409 словами, кнопки нет ни на карточке, ни на экране
  агента; переход в живой статус остался.
- По замечаниям ревью: вид интерактивной работы берётся со строки доски
  (`liveWorks` и `sessionWorks` получили ответ taskctl), и кнопка чата на
  экране агента открыта той же целью, что и на экране задачи. Дедуп двух окон
  одной задачи, чужой префикс и закрытая кнопка чата покрыты тестами, краснота
  проверена мутациями каждой из трёх строк.
- Ревью: субагент sonnet/high по вердикту pick (квота: week_all 16%, week_max 17%, снимок 0м назад, сдвига нет), 2026-08-11.

## Ревью

- Дедуп двух интерактивных окон на одной задаче без tmux не проверен тестом: в sessionWorks (tools/dashboard/sessions.go) после первого совпадения busy[task]=true второе окно молча пропускается (continue) - поведение верное, но если убрать строку busy[task]=true в этой ветке, весь go test ./... остаётся зелёным (проверил руками). Нужен тест на два транскрипта с одинаковым узнанным ID без участия tmux.: исправлено, тест TestLiveWorksSessionsSameTask: два свежих окна XR-002 без tmux дают одну работу, мутация снятой строки busy[task] краснеет
- Чужой префикс задачи не покрыт тестом: ветка 'task, note = "", foreignTaskNote' в sessionWorks (tools/dashboard/sessions.go) - если убрать её целиком (задача с чужим префиксом приписывается проекту как своя), go test ./... тоже остаётся зелёным (проверил руками). LLD и ход работы называют это поведение сознательным решением, а красноты на него нет ни у одной мутации. Нужен тест с транскриптом, чья задача узнана с ID не с доски проекта (другой префикс).: исправлено, тест TestLiveWorksSessionForeignTask: сессия с веткой чужого префикса остаётся работой с подписью и без ID, вырезание ветки краснеет
- Переход в чат у renderAgent (tools/dashboard/static/app.js) открывается условием work.via === "session" без проверки, что узнанная задача правда цель: renderTask рядом гейтит ту же кнопку через isGoal = /^Цель:/.test(row.title), а renderAgent - нет. Для интерактивной сессии на обычной задаче (например самой DK-263, type=task) кнопка "Чат с агентом" появится, renderChat подпишет её "goal-DK-263" (нечестно, это не цель), а отправка сообщения на бэкенде получит 400 "не цель" от handleGoalMessagePost. Сценарий проверки DK-263 называет переход в чат у узнанной задачи ожидаемым поведением, а для обычной задачи он ведёт в тупик.: исправлено, вид работы у интерактивной сессии берётся со строки доски, кнопка чата в renderAgent гейтится целью как в renderTask; тесты TestLiveWorksSessionsSameTask (kind goal у XR-100) и TestStaticInteractiveWork
