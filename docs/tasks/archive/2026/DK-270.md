# DK-270: dashboard: ручка message шьёт путь цели жёстко, журнал идёт по ссылке строки

записан 2026-08-11, оформлен 2026-08-12

## Что происходит

`goalFile` в `tools/dashboard/messages.go` собирает путь файла цели жёсткой
склейкой `docs/tasks/<ID>.md`, а `goalDocPath` в `tools/dashboard/journal.go`
сначала идёт по ссылке строки доски (разбор `linkPath` из DK-255) и лишь при
битой ссылке откатывается на обычное место. У цели, чья ссылка ведёт на живой
файл не на обычном месте, концы расходятся: сообщение из дашборда ляжет в
`docs/tasks/<ID>.md`, а виток и экран прочитают файл по ссылке; если файла на
обычном месте нет вовсе, ручка ответит 404 «класть сообщение некуда» при
журнале, который экран показывает. Сегодня расхождения нет: все цели доски
ссылаются на `tasks/<ID>.md`, дефект латентный, обход дешёвый, держать файл
цели на обычном месте.

## Чего хотим

Оба конца берут путь одним разбором: `goalFile` ходит через тот же
`goalDocPath`, жёсткой склейки пути в ручке message не остаётся.

## DoD

Сообщение цели, чья ссылка строки ведёт на файл не на обычном месте, ложится в
тот файл, который читают журнал и экран; держит это тест с нестандартной
ссылкой в строке доски.

## Ранг

`0+2+1+5+2 = 10`, P3.

- Серьёзность 0 (Minor). Дефект латентный: все нынешние цели ссылаются на
  обычное место, расхождения на живой доске нет, обход дешёвый и очевидный.
- Ценность 2. Небольшая страховка целостности чата целей: пользователь заметит
  только на цели с нестандартной ссылкой.
- Неопределённость 1. Подход назван в черновике, общий разбор уже есть
  (`goalDocPath`), осталось позвать его из второго конца.
- Поправка на баг 5. Несостыковка двух ручек это дефект, а не новая работа.
- Рычаг 2. Общий разбор ссылки убирает грабли у будущих правок чата целей
  (DK-136, DK-112).

## Сценарий проверки

Агентский: тест с нестандартной ссылкой строки доски (`goals/XR-100.md`)
кладёт POST-сообщение в файл по ссылке, обычное место `docs/tasks/<ID>.md`
остаётся нетронутым, `git add` берёт файл по ссылке, а GET журнала читает
строки из того же файла. regcheck подтверждает красноту теста на старом коде.

## Итог

Обе ручки чата целей берут путь файла цели одним разбором `goalDocPath`:
жёсткой склейки `docs/tasks/<ID>.md` в ручке message не осталось ни для
чтения, ни для коммита правки. Регресс закрыт тестом с нестандартной
ссылкой строки доски.

## Ревью

- Вердикт: без замечаний. Путь от симптома до правки: `goalFile`
  (`messages.go:151`) звал жёсткий `filepath.Join(found.Path, "docs",
  "tasks", id+".md")`, теперь зовёт `s.goalDocPath` (`journal.go:237`), тот
  же разбор, что у `handleGoalLog` (`journal.go:282`) и SSE-статуса цели
  (`goal.go:213`): все три ручки чата целей сошлись на одной функции.
  Вторая склейка, которую заявил исполнитель (`git add` отдельным
  `filepath.Join`), в диффе действительно убрана: `goalFile` возвращает
  `doc.rel` вторым путём, `handleGoalMessagePost` передаёт его в
  `commitDocs` как есть, свой `rel := filepath.ToSlash(filepath.Join(...))`
  удалён. Других звеньев, до которых баг мог достать, в коде нет: grep по
  `id+".md"` и `"tasks", id` находит только `newtask.go:28` (путь черновика,
  чужой домен) и саму `taskFileRel` (`tasks.go:181`), от которой
  `goalDocPath` и берёт значение по умолчанию, трогать её незачем.
  Поведение при битой ссылке согласовано: `goalDocPath` проверяет
  `isFile` на разрешённой ссылке и откатывается на `taskFileRel`, если файла
  там нет; `doc.seen` (тот же `isFile`, но уже на итоговом пути) даёт 404
  только когда файла нет ни по ссылке, ни на обычном месте, ровно как у
  старой проверки `isFile(path)`.
  Тест `TestMessageLandsAtLinkedGoalPath` воспроизводит исходный дефект по
  содержанию, не только пометкой: ссылка `goals/XR-100.md` нестандартная,
  сообщение проверяется в файле по ссылке, обычное место `docs/tasks/XR-100.md`
  проверяется на отсутствие, `git add` берёт файл по ссылке, GET журнала
  читает ту же строку, все четыре пункта сценария проверки закрыты.
  `GOWORK=off go test ./...` из `tools/dashboard` зелёный (90.1с).
  `regcheck -C tools/dashboard --base main -- sh -c 'cd tools/dashboard &&
  go test . -run TestMessageLandsAtLinkedGoalPath -v'` подтвердил красноту
  на main и зелень на правке. Файл задачи: «Ход работы», «Итог», «Сценарий
  проверки» на месте, стиль и символы (`check-symbols.py`) в порядке.
