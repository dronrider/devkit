# DK-289: dashboard: кнопка «Закрыть» поднимает сессию агента и молчит про это

записан 2026-08-13, оформлен нарезкой цели DK-327 2026-08-14

## Что происходит

Приёмка 2026-08-13: пользователь нажал «Закрыть» у DK-284, на экране ничего не
изменилось; через несколько секунд нажал второй раз и получил «на доске devkit
нет строки DK-284», хотя строка была видна, и пропала она только после ручного
обновления страницы. По журналу дашборда видно, что первое нажатие поднимает
tmux-сессию `task-DK-284` с заказом «Закрой DK-284» (`runPrompt` для секции
check, `tools/dashboard/runs.go`): сессия отработала, задача уехала в архив
коммитом 830d54c4, а экран об этом не узнал.

Три отдельные беды. Первая: для задачи, которую человек только что принял
глазами, закрытие идёт через headless-сессию агента, то есть через минуты
ожидания и трату квоты там, где хватило бы `taskctl close`; для агентского
сценария сессия оправдана, для пользовательского нет. Вторая: нажатие не даёт
отклика, поднятая работа не появляется на экране сама, и человек не знает, идёт
ли что-то. Третья: отказ второго нажатия говорит «нет строки» вместо «задача уже
закрыта, экран устарел», и это читается как поломка.

Вид приёмки читать теперь есть откуда: DK-298 завела суффикс заголовка строки
доски (`[приёмка: user]`, `[приёмка: mixed]`, агентский вид без суффикса), и
дашборд берёт его готовым.

## Чего хотим

Задача с пользовательской приёмкой закрывается с экрана напрямую и сразу, а
устаревший экран получает честный ответ вместо выдуманного.

## DoD

- Закрытие задачи с пользовательской приёмкой зовёт `taskctl close` напрямую, без
  headless-сессии. Вид берётся суффиксом строки доски, своего признака дашборд не
  заводит.
- Агентская приёмка остаётся за сессией: там закрытие это работа, а не
  подтверждение уже проверенного.
- Отказ на устаревшем экране называет настоящую причину («задача уже закрыта»)
  вместо выдуманной («на доске нет строки»).
- Смок сверяет вызов по фикстуре `taskctl` и по строке синтетической доски.
- Отклик на нажатие держит частичная перерисовка (DK-316), эта строка её
  использует, а своего обновления экрана не заводит. Подсказку кнопки и переход
  на экран работы держит DK-286.
- Поведение описано в README дашборда.

## Сценарий проверки

Сценарий агентский: он поднимает ту самую сессию, которой быть не должно, и
показывает, что вместо неё идёт одна команда.

1. `GOWORK=off go test ./...` из `tools/dashboard`: модуль зелёный целиком.
2. `regcheck --base main -- sh -c 'cd tools/dashboard && GOWORK=off go test -run
   "TestRunStartUserAcceptClosesWithoutSession|TestRunStartClosedRowNamesArchive|TestRunStartKeepsSessionBesidesUserCheck"
   ./...'` из корня репозитория: тесты краснеют на main, где нажатие поднимало
   tmux-сессию с заказом «Закрой XR-004», а закрытой задаче отвечали «на доске
   нет строки».
3. `dashboard smoke`: шаг «закрытие принятой задачи без витка» печатает слова
   утилиты про закрытие, отсутствие сессии и ответ второму нажатию; прогон
   доходит до `dashboard smoke: ok`.
4. `node testdata/screen_keep.mjs static/app.js` из `tools/dashboard`: слой
   отклика на нажатие (DK-316) цел, карточка ответа раскладку не двигает.

Ожидаемый итог: строка с пользовательской приёмкой уходит с доски по нажатию,
без tmux-сессии и без ожидания, а нажатие по уже закрытой задаче отвечает
закрытием, а не пропажей строки.

## Итог

Проверенная задача с пользовательской приёмкой закрывается прямо из ручки
запуска (`closeFromCheck` в `tools/dashboard/tasks.go`): сервер зовёт `taskctl
close`, коммитит и пушит доску с ID в subject, а в ответ отдаёт слова утилиты и
`kind` равный `close` вместо имени сессии. Вид приёмки приезжает полем `accept`
ответа `taskctl list --json`, куда утилита кладёт разобранный суффикс заголовка
строки (DK-298), своего признака дашборд не завёл. Мимо сессии уходит ровно
пользовательская приёмка в Check: смешанной и агентской закрытие ещё остаётся
работой, а пользовательская строка в Backlog поднимает конвейер, как и прежде.
В коммит закрытия едут оба конца переезда файла задачи, поэтому `commitDocs`
теперь зовёт `git add` только по тем путям, что есть на диске.

Строке, которой на доске уже нет, отказ называет настоящую причину (`rowGone`
там же): лежит ID в архиве проекта, ответ говорит про закрытую задачу и
устаревший экран, а не про пропавшую строку. Одними словами отвечают и нажатие,
и экран задачи, открытый по закрытому ID. Отклик на нажатие держит прежний слой
DK-316, своего обновления экрана правка не завела: строка уходит с доски тем же
обновлением, каким приходит ответ.
