# DK-297: Цель: сессия начинает с готовой карты проекта, а не собирает её грепами

## Цель

Знания о том, где что лежит, разбросаны по коду и докам, и каждая сессия
собирает их заново грепами и чтением, а вопрос «почему так» ищется археологией
по docs/lld/. Цель сводит три работы в один механизм: карту проекта из кода
(DK-194), индекс решений по docs/lld/ (приписка DK-293 в файле DK-194) и
сторожа полноты доки в doctor (DK-071). Порядок задан пересечением задач: сначала LLD DK-194, судьба DK-071 решается
в нём. Отдельной парой они не идут, иначе получаются два сторожа полноты с
разными картами.

DoD, агентски проверяемый:

- тонкий файл харнеса импортирует сгенерённую карту devkit, и карта
  укладывается в целевой размер из постановки DK-194 (40-60 строк);
- `devkitctl doctor` печатает находку на компоненте без описания и на карте,
  разошедшейся с деревом; на приведённом в порядок devkit находок ноль;
- индекс решений генерится из заголовков «Решение N» в docs/lld/*.md, и для
  каждого решения в нём указаны документ и раздел;
- POC-замер из постановки DK-194 проведён: пара типовых задач с картой и без.
  Сравнение расхода квоты записано цифрами в файле задачи замера. Решение о
  генерализации на другие проекты принимается по этим цифрам и в цель не
  входит.
