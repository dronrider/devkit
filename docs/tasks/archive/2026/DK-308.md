# DK-308: Цель: вид приёмки задачи назначается критериями и виден с доски

## Цель

Довести до работающего состояния решение LLD
[DK-292](../../../lld/DK-292-check-kind.md): вид приёмки задачи (агентский,
смешанный, пользовательский) назначается по критериям в момент заведения
строки, живёт машиночитаемо на доске, пересматривается по правилам и виден
всем, кто с доской работает. Сегодня вид выбирает исполнитель последним шагом
перед Check по одному предложению правил, до Check его никому не видно, и
очередь выката стоит часами.

DoD, проверяется командами:

1. `taskctl add` без `--accept` отказывает, `--accept user` и `--accept mixed`
   без `--barrier <ключ>` отказывают тоже, `--accept agent` заводит строку без
   суффикса.
2. `taskctl list` печатает вид приёмки под строками Backlog и In progress, а не
   только Check.
3. В корне лежит `ACCEPTANCE.md` с шестью барьерами и списком обходов против
   каждого, и на него ссылаются `RULES.board.md` и скиллы груминга, задачи,
   движения кода и цикла цели.
4. `taskctl move <ID> check` отказывает не агентскому виду без раздела
   «Приёмка» с перебором обходов, где строк ровно столько, сколько обходов у
   названного барьера.
5. Заведение задачи с дашборда шлёт вид и барьер, и после этой правки флаг
   `--accept` обязателен на всех трёх входах.
6. `shipctl merge` печатает после выката один следующий шаг вместо обеих веток
   сразу, а `taskctl batch` отбирает кандидатов в поезд по виду, а не на глаз.
7. Ни одной открытой строки доски без назначенного вида: `taskctl kinds`
   печатает сводку по видам и ноль строк без вида.

## Бюджет

бюджет: week_all <= 20
бюджет: week_max <= 15

Потолок яруса не задан: вердикт `agentctl pick` работает по каждой задаче как
обычно. Числа это верхняя граница трат машины за время цикла, а не счётчик
самой цели: бакеты общие, и параллельная сессия тратит те же проценты.

   отбирает кандидатов по виду и называет отсеянное («вид приёмки не

7. `taskctl kinds` печатает сводку: 87 строк в счёте, agent 81, mixed 3,
