# DK-323: Событие уведомителя несёт задачу и проект полем, а не догадкой ленты

записан 2026-08-13, оформлен нарезкой цели DK-327 2026-08-14

## Что происходит

Лента дашборда привязывает событие к задаче регуляркой по тексту баннера
(`notifyIDRe`, `tools/dashboard/notifications.go`): событие, в чьём тексте ID не
написан, остаётся без перехода к задаче, хотя повод почти всегда рождается внутри
работы над конкретной строкой. Проекта в событии нет вовсе, журнал
`~/.devkit/notify.log` один на все доски, и «Поднять виток» бьёт в открытый проект
наугад.

Поймано пользователем 2026-08-13: не все события ленты привязаны к задаче, хотя
по смыслу привязка есть у каждого.

## Чего хотим

Событие несёт задачу и проект полями, лента ведёт к задаче с любого события, а
событие, у которого задачи правда нет, помечено честно, а не выглядит оторванным.

## DoD

- `hooks/notify.py` и его потребители пишут ID задачи и проект отдельными полями
  события; разбором текста лента больше не занимается.
- Лента ведёт к задаче и к журналу агента с любого события, у которого поле
  заполнено; событие без задачи (авария контура, протухшая квота) помечено
  честно.
- «Поднять виток» бьёт в проект события, а не в открытый на экране.
- Старые строки журнала ленту не ломают: событие без полей читается по-прежнему.
- Смок: `hooks/notify.py` в стенде настоящий, ответ ручки уведомлений сверяется
  по полю, а не по разбору текста.
- Поведение описано в README дашборда и в докстринге `notify.py`.

## Ранг

`25+6+3+0+2 = 36`, P2.

- Серьёзность 25 (Major). Событие без перехода заставляет искать задачу глазами
  по доске. Обход дешёвый и очевидный: открыть доску и найти строку.
- Ценность 6. Восьмой сценарий цели DK-327: лента становится входом в работу, а
  не только сводкой о ней.
- Неопределённость 3. Правка едет через три границы: питоновский хук, сервер на
  go и клиент. Журнал общий на все доски машины, и совместимость со старыми
  строками решается на месте.
- Поправка на баг 0. Полей в событии не было никогда, это работа, которой не
  было, а не сломавшееся поведение.
- Рычаг 2. Своя польза: событие с проектом пригодится всякому, кто читает журнал
  уведомлений, но чужой работы этим не разблокировано.

## Итог

Событие уведомителя несёт задачу и проект своими полями, и лента дашборда
ведёт от события к строке доски по полю, а не по разбору текста.

- `hooks/notify.py`: поля в строке журнала, сборка их из рабочего дерева
  (`event_target`, `task_id`), ключи `--task` и `--project` у аргументного
  вызова. Поля едут и в строки пропусков (песочница, фокус, окно повтора):
  событие, до баннера не доехавшее, лента показывает, и от него есть куда
  вести.
- `tools/dashboard/notifications.go`: разбор полей, `project` в JSON события.
  Вылов ID из текста остался путём старых строк, у строки с полями прочерк
  значит честное «задачи нет».
- `tools/dashboard/static/app.js`: переход строится по полям события, любое
  событие с задачей ведёт к задаче и к журналу агента, а не только стоп;
  событие без задачи помечено словами.
- Потребители: `taskctl move`, `taskctl fail`, `goal-run.py`, `shipctl` на
  упавшем выкате, сторожок простоя `devkitctl watch` и стоп из дашборда зовут
  уведомитель с ключами. Без ключа
  событие потеряло бы задачу совсем: поле с прочерком старый вылов ID из
  текста уже не включает.

  уведомитель в `hooks/README.md`, упавший выкат в `tools/shipctl/README.md`,

## Сценарий проверки

Агентский, гоняется из дерева задачи.

1. Строка журнала несёт поля. `cd hooks && python3 -m unittest
   notify_test.TestTargetInTheJournal notify_test.TestEventTarget` зелёный:
   поля собираются из дерева, из ключей и честно пустеют там, где задачи нет.
2. Лента отдаёт поля наружу. `cd tools/dashboard && GOWORK=off go test -run
   'TestParseNotifyLine|TestNotificationsGiveTargetFields|TestStaticFeedGoesByEventFields' .`
   зелёный: новые строки читаются полями, старые по-прежнему текстом.
3. Цепочка от уведомителя до ручки жива целиком. `cd tools/dashboard &&
   GOWORK=off go test -run TestSmokePassesTheChain .` зелёный: в стенде
   настоящий `hooks/notify.py`, и шаг «уведомление о стопе в ленте» сверяет
   проект по полю ответа, а в тексте баннера проекта нет вовсе.
4. Потребители зовут с ключами. Зелёные: `cd tools/taskctl && GOWORK=off go
   test -run 'Notifies' .`, `cd tools/shipctl && GOWORK=off go test -run
   'Notif' .`, `cd kit/skills/goal-loop && python3 -m unittest goal_run_test`,
   `cd tools/devkitctl && python3 -m unittest watch_test`.
5. Ничего не сломано рядом: `cd hooks && python3 -m unittest discover -p
   '*_test.py'`, `cd tools/dashboard && GOWORK=off go test ./...`.
