# DK-353: dashboard: черновики свежими вниз, выбора сортировки нет

записан 2026-08-15, оформлен 2026-08-15

## Что происходит

Порядок накопителя задаёт `loadDrafts` (`tools/taskctl/draft.go`, строка 112):
записи сортируются по номеру ID по возрастанию, и свежая всегда оказывается
последней. Дашборд этот порядок не трогает: `handleDrafts`
(`tools/dashboard/drafts.go`, строка 47) зовёт `taskctl draft list --json`,
`draftsWithOrder` дописывает каждой записи заказ груминга и отдаёт список как
есть, а `renderDrafts` (`tools/dashboard/static/app.js`, около строки 3353)
рисует строки в порядке ответа.

На накопителе из трёх десятков записей это значит, что записанное с телефона
пять минут назад лежит в самом низу списка, и до него надо прокрутить весь
накопитель. Выбора порядка на экране нет вовсе: шапка карточки «Черновики»
несёт только счётчик записей.

## Чего хотим

Раздел `#проект/drafts` открывается свежими записями сверху, а в шапке
карточки стоит переключатель порядка. Порядка два: по дате записи и по
заголовку записи по алфавиту. «По имени» из черновика читается как заголовок,
потому что сортировка по ID совпала бы с датой: номера растут по времени
записи. Выбранный порядок переживает обновление страницы, как переживают его
отметки в `localStorage` у ленты и у отправленных реплик.

Порядок в самих утилитах не меняется: агент на груминге читает
`taskctl draft list` и хвост `taskctl list` пачкой, и возрастание ID там
остаётся. Данных для сортировки на клиенте хватает, ответ API несёт `id`,
`title`, `written` и `age_days` (`jsonDraft` в `tools/taskctl/json.go`), и
задача не заводит лишнего запроса на сервер.

Открытые детали, за которыми задача идёт с неопределённостью 2: где держится
выбор и чем сортируется запись без строки «записан». Выбор хранится в
`localStorage` или в адресе экрана: второе делает порядок ссылкой, но плодит
адреса одного раздела. У записи без строки «записан» поле `written` пустое, а
возраст посчитан от времени правки файла.

## DoD

- Раздел `#проект/drafts` при первом заходе показывает записи от свежих к
  старым: сегодняшняя стоит первой строкой.
- В шапке карточки «Черновики» стоит переключатель порядка с двумя значениями,
  по дате и по заголовку, и переключение перестраивает список без запроса на
  сервер.
- Выбранный порядок восстанавливается после обновления страницы.
- Переключатель влезает в ширину телефона и не выдавливает счётчик записей.
- Строка накопителя работает как прежде: касание ведёт на экран записи, кнопка
  «Провести груминг» поднимает сессию разбора.
- `taskctl draft list` и хвост `taskctl list` печатают прежний порядок по
  возрастанию ID.
- Тест на узкой ширине по стенду `testdata/board_narrow.js` держит порядок
  строк и раскладку шапки и падает на нынешнем коде.

## Ранг

`25+4+2+0+0 = 31`, P2.

- Серьёзность 25 (Major). Заметное трение на каждом заходе в накопитель:
  свежая запись прячется под три десятка старых. Обход дешёвый и очевидный:
  прокрутить список до конца.
- Ценность 4. Запись и разбор черновиков с телефона это ощутимая часть
  ценности дашборда, и порядок правит именно тот заход, ради которого раздел
  и заведён; при этом записи достижимы и сейчас.
- Неопределённость 2. Место правки известно и лежит целиком во фронте, ответ
  API уже несёт нужные поля; открыты хранение выбора и запись без даты.
- Поправка на баг 0. Утилита сознательно завела возрастание ID, доска и
  накопитель читаются в этом порядке; смена умолчания на экране это доработка.
- Рычаг 0. Дальше по коду ничего не разблокирует.

## Приёмка

Вид агентский. Барьер «глаза» снят обходами «headless-браузер с замером» и
«тест по разметке и стилям»: порядок строк это порядок узлов в DOM, а
переключатель проверяется кликом на том же стенде узкой ширины
(`testdata/board_narrow.js`), которым мерили доску на DK-285.
