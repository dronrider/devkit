# DK-374: Реплика в работающий заход: подхват получает адрес черновика [после DK-373]

## DoD

## Расхождение с решениями DK-430

2026-08-18, нарезка цели DK-397: подхват реплики адрес черновика получает не
своей правкой, а общим правилом адресности из решения 2 документа
`docs/lld/DK-430-task-chat.md`: вход принадлежит разговору, реплика сессии идёт
с адресатом, реплика разговору без него. Строка сводится к тому, чтобы черновик
завёл себе вход по общему правилу, отдельной механики отметок в ней нет.

## Проверка

2026-08-28, ветка POC `poc-chat`. Своей правки в строке не осталось. Предмет
сняли коммиты ветки, пока строка стояла в Backlog.

- `5c4a82c2` и `1fed2812` свели разговор записи к общему имени `task-<ID>` в
  `.devkit/chat`. Своего адреса, которому подхват учился бы отдельно, у записи
  больше нет. Повод был живой, случай DK-517.
- `dcb731a0` завёл правило хозяина. Безадресную строку разговора задачи берёт
  только сессия из реестра чатов либо работающая в боковом дереве задачи
  (`owns_chat` в `hooks/chat-in.py`). Сессию разбора дашборд поднимает с
  `DEVKIT_TASK=<ID>` (`launchEnv`), так что запись реестра у грумера есть.
- Отметок доставки у входа нет ни у задачи, ни у записи. Доставленная строка
  уходит из входа под тем же замком, которым пишется. Дока про это стоит в
  `hooks/README.md`, раздел «Вход разговора любой сессии», где грумер черновика
  назван прямо.

Живая проверка это шаг 5 прогона DK-373. Запись накопителя DK-551, сессия
разбора `aa74cd11-4453-4edf-be63-0d074edd9477`, поднята дашбордом. Реплика
