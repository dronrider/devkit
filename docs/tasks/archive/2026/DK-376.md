# DK-376: POC-замер карты на xr-proxy: пара типовых задач с картой и без, цифры расхода [после DK-375]

## Что происходит

Генератор карты (DK-375) слит и выкачен. Замер из DoD постановки DK-194 ещё не
проводился: генерализацию на другие проекты решают цифры, а не вкус. Протокол
лежит в docs/lld/DK-194-project-map.md, раздел «Протокол POC на xr-proxy»
(строки 249-269), исполнять его буквально.

## Что сделать

1. Ветка в xr-proxy: сгенерированная карта (сухой прогон `devkitctl map -C`
   из чекаута devkit, запись файла), строка импорта в тонкий файл xr-proxy.
   До замера проба с кодовым словом из карты в `claude -p`: карта доезжает
   в контекст, иначе замер меряет не карту, а дыру доставки.
2. Две пары задач одного типа и размера с бэклога xr-proxy (LLD или кодовые,
   не одна и та же дважды). Прогон A без карты, B с картой, контрольная пара
   зеркально: C с картой, D без. Порядок чередуется, модель и effort
   одинаковые во всех четырёх.
3. Расход меряется по журналам сессий (`devkitctl drain -C`) токенами:
   суммарный расход сессии как основная цифра и доля поисковых вызовов
   (grep, find, чтение файлов подряд) как объяснение механики.
4. Цифры ложатся в этот файл задачи. Критерий генерализации: в обеих парах
   экономия поиска перекрывает собственный вес карты. Решение читает
   пользователь, в цель DK-297 генерализация не входит.

## Сценарий проверки

Агентский.

1. Файл задачи держит четыре прогона с цифрами: путь журнала, токены
   сессии, доля поисковых вызовов.
2. Проба с кодовым словом зафиксирована: карта доезжала в контекст каждого
   прогона с картой.
3. Вывод по критерию сформулирован числами обеих пар.

### Вывод по критерию

Критерий генерализации: в обеих парах экономия поиска перекрывает
собственный вес карты.

**Пара 1 (A без карты против B с картой):**
- Экономия с картой: 31 998 - 22 256 = 9 742 токена
- Экономия перекрывает вес карты: 9 742 > 320, да, с большим запасом

**Пара 2 (C с картой против D без карты):**
- Экономия с картой: 37 810 - 151 058 = -113 248 токенов, с картой дороже
- Разгон обязан субагенту Explore, а не самой карте, но экономии нет и
  перекрытия нет

Итог: экономия есть только в одной паре из двух, критерий генерализации не
выполнен.

Карта остаётся внутренним механизмом самого devkit, генерализация на чужие
проекты отклонена по цифрам. Решение читает пользователь, в цель DK-297
генерализация не входит.

## Ревью

- Вес карты 5 678 токенов не подтверждается: файл карты на poc/map это 1 227 байт (21 строка), а живая дельта резидента из журналов самих прогонов даёт около 310 токенов (первые запросы B и C: cache_read 50 176 при input 2 714; A и D: 49 856 при 2 724, вся разница веток это карта и строка импорта). devkitctl weigh тут источник не годится: он меряет цену всей раскладки devkit, а не одного файла. Переснять вес карты (живой дельтой из журналов прогонов или пересчётом файла карты) и заново прогнать сравнение пары 1: с реальным весом пара 1 проходит с большим запасом, итог «критерий не выполнен» не меняется. Исправлено: вес переснят живой дельтой кэша (320 токенов), пара 1 пересчитана.
- Прогон C не полный: сессия b966f48f породила субагента Explore (журнал b966f48f-87ce-48c5-b609-7558518b205c/subagents/agent-a63eb51822ef82aaa.jsonl) на 111 910 токенов вход-выход против 39 148 головного потока, и этого расхода в таблице нет. devkitctl drain считает субагентские потоки (context.streams собирает их через rglob), то есть протокольная цифра «суммарный расход сессии» должна была их включить: с субагентом прогон C это 151 058 токенов, разрыв пары 2 растет. Дописать в таблицу строку субагента или его вклад в токены прогона C и пересчитать вывод пары 2. Исправлено: субагент включён в таблицу, C это 151 058 токенов, пара 2 пересчитана.
- Мелочи файла задачи. «poc/map с 10:12:11 до 15:54» против reflog: возврат на main в 10:15:54, потеряны часы. Задачи названы «кодовые», а на доске xr-proxy XR-061/062/066/067 имеют тип LLD (XR-061 при этом XL с рангом 19 против XR-062 L с рангом 13: пара 1 не одного размера). Поправить время, тип и дать честную оговорку про размер пары 1, раз протокол требует задач одного типа и размера. Исправлено: время 10:15:54, тип LLD, оговорка про размер пары 1.
