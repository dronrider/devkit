# DK-443: Рабочее состояние целей в .devkit не гитигнорнуто и висит в статусе

записан 2026-08-18, оформлен 2026-08-18

## Что происходит

Цикл цели держит рядом с проектом три вида рабочих файлов: журнал витков
`.devkit/goal-<ID>.log` (его пишет оболочка `goal-run`), ящик почты
`.devkit/goal-<ID>.mail` с замком `.mail.lock` рядом и замок оболочки
`.devkit/goal-<ID>.lock`. Гитигнорнут из соседей по каталогу был кто угодно:
журнал запусков, выводы cmdout, замок конвейера, ящики почты сессий, а вот
состояние целей нет. В рабочем дереве devkit накопилось четырнадцать таких
файлов от семи целей, и `git status` показывал их untracked наравне с
настоящей правкой.

Своя раскладка у этого уже была: машинные записи `.devkit` живут списком
`MACHINE_IGNORE_ENTRIES` в devkitctl, оттуда их берут и подключение нового
проекта, и находка доктора с починкой по `--fix`. Записи про цель в списке
не оказалось, поэтому руками её пришлось бы дописывать в каждом проекте,
который ведёт цели.

## DoD

`.devkit/goal-*` стоит в общем списке машинных записей: подключение нового
проекта раскладывает её вместе с cmdout и замком конвейера, доктор помечает
её отсутствие находкой и чинит по `--fix`, а в самом devkit журналы и ящики
целей из `git status` пропали.

## Ранг

`25+2+0+5+2 = 34`, P2.

- Серьёзность 25 (Major). Заметное трение: чужие файлы в каждом статусе,
  обход дешёвый и очевидный (смотреть мимо них).
- Ценность 2. Небольшое удобство: статус снова показывает только правку.
- Неопределённость 0. Рутина, место правки известно, список записей готов.
- Поправка на баг 5. Состояние машины оказалось в поле зрения гита там, где
  соседи по каталогу давно скрыты.
- Рычаг 2. Небольшая своя польза: чистый статус на каждой задаче цикла цели.

## Сценарий проверки

Агентский: правка целиком проверяется прогоном.

1. Тест `test_16_machine_ignore_paths` в `tools/devkitctl/devkitctl_test.py`
   сверяет и шаблон, и живые имена файлов цели; краснота на старом коде
   доказана прогоном `regcheck --tests tools/devkitctl/devkitctl_test.py --
   python3 tools/devkitctl/devkitctl_test.py -k machine_ignore`.

2. В самом devkit `devkitctl doctor` до правки давал находку
   «.devkit/goal-* не гитигнорнут», `--fix` её починил, а `git status` после
   этого чист от журналов и ящиков целей.

## Проверка

Прогон 2026-08-18 в рабочем дереве devkit.

1. Краснота регрессионного теста:

       $ regcheck --tests tools/devkitctl/devkitctl_test.py -- \
           python3 tools/devkitctl/devkitctl_test.py -k machine_ignore
       тест краснеет на HEAD и проходит на текущем коде, регрессия закрыта
       (тесты: tools/devkitctl/devkitctl_test.py)

2. Весь набор юнитов devkitctl:

       $ python3 tools/devkitctl/devkitctl_test.py
       Ran 115 tests in 146.015s
       OK

3. Доктор в devkit до правки:

       .devkit/goal-* не гитигнорнут: журнал витков и ящик цели замусорят
       status, добавить .devkit/goal-* в .gitignore

   и он же с `--fix`:

       починено: .gitignore: добавлен .devkit/goal-*
       обвязка в порядке

4. Накопленные файлы семи целей ушли из статуса, гит подтверждает каждый вид:

       $ git check-ignore -q .devkit/goal-DK-397.log
       $ git check-ignore -q .devkit/goal-DK-327.mail
       $ git check-ignore -q .devkit/goal-DK-327.mail.lock

   все три ответили кодом 0, `git status --short` показывает только доску и
   файл этой задачи.
