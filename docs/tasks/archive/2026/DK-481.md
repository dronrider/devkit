# DK-481: dashboard: живой демон не видит токен после secret --rotate

## Что происходит

Демон читает конфиг один раз на старте (`runServe` в `tools/dashboard/main.go`)
и дальше держит секрет в памяти: вход (`handleLogin`) и подпись кук
(`loggedIn`) сверяются с `s.cfg.Token`. Команда `dashboard secret --rotate`
пишет новый токен только в `~/.devkit/dashboard.local`, живому серверу об этом
ничего не приходит. В итоге вход по свежеотпечатанному токену получает 403, а
старые куки продолжают ходить, хотя по справке команды после ротации «все
выданные куки гаснут». Обход один: рестарт демона руками.

## Чего хотим

Живой демон сверяет вход и куки с тем токеном, который сейчас лежит в конфиге:
после `secret --rotate` новый токен пускает сразу, старые куки гаснут без
рестарта. Ошибка перечитывания конфига не роняет сервер и не открывает вход:
пока файл не читается, действует последний удачно прочитанный секрет, а причина
видна в журнале и /healthz.

## DoD

- Вход по токену, записанному в конфиг после старта демона, работает без
  рестарта.
- Кука, подписанная доротационным секретом, после ротации не пускает.
- Тесты на оба поведения, регрессионный падает на старом коде (regcheck).
- README dashboard упоминает, что ротация действует на живой демон.

## Ранг

- Серьёзность 25: ротация и первый вход при живом демоне ломаются, обход
  дешёвый и очевидный, рестарт.
- Ценность 2: небольшое удобство, ротация начинает действовать сразу.
- Неопределённость 1: подход ясен, перечитывать секрет из конфига по mtime,
  открыты только детали.
- Поправка на баг +5: поведение расходится с обещанием справки secret --rotate.
- Рычаг 2: небольшая своя польза, из обихода уходит ручной рестарт демона.

## Сценарий проверки

1. Собрать бинарь и поднять демон на временном `HOME`: `dashboard serve`
   слушает на своём порту, `dashboard secret` печатает выданный при первом
   старте токен.
2. `curl -X POST /api/login` с этим токеном отвечает `{"ok":true}` (200),
   кука сохраняется.
3. `dashboard secret --rotate` печатает новый токен, живой демон не
   перезапускается.
4. `curl -X POST /api/login` с новым токеном без рестарта демона отвечает
   `{"ok":true}` (200): на старом коде здесь 403 «токен не подошёл», потому
   что демон держал секрет в памяти со старта.
5. Запрос с кукой, полученной на шаге 2 (до ротации), к `/api/projects`
   отвечает 401: на старом коде кука продолжала бы пускать до рестарта.

## Проверка

Прогнан сценарий агентской части после выката (очередь непроверенного выката
занята задачей DK-481, отметка smoke ставится этим прогоном).

Демон поднят на бинаре `/Users/rider/go/bin/dashboard` (`taskctl` в PATH
машины резолвится первым в устаревшую копию `/Users/rider/.devkit/dashboard-poc/`.
`devkitctl doctor` уже даёт находку про эту тень, поэтому все вызовы шли
явным путём). Временный `HOME` со связкой ключей символьной ссылкой на
настоящий `~/Library/Keychains` (без неё поднимается диалог), конфиг
`.devkit/dashboard.local` со свободным портом 49633, права 600.

`shipctl smoke DK-481` поставлена.
