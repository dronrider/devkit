# DK-514: taskctl review: замечание с цитатой слова «исправлено» закрывается само

## Что происходит

Статус пункта раздела «Ревью» считается поиском подстроки по всему тексту
пункта (`tools/taskctl/review.go:27`, `strings.Contains(low, "исправлено")`),
а не по факту вызова `review resolve`. Замечание, которое само цитирует эту
фразу, считается закрытым с момента записи: `resolve` на него отказывает
словами «замечание N уже закрыто», а пояснения исполнителя в файл не
попадают.

Найдено на DK-503: замечание 18 цитировало прежний текст сценария со словами
«остаются закрытыми исходом «исправлено»», и цитата сработала ложным
триггером. Исполнитель дописал суффикс руками в формате самой команды.

Рядом стоит второе следствие того же устройства: ворота `shipctl merge`
считают открытые замечания тем же способом, значит замечание с цитатой
слияние не задержит.

## Чего хотим

Исход пункта живёт отдельно от его текста: цитата внутри замечания на статус
не влияет, `resolve` пишет исход и не отказывает, а ворота merge видят
незакрытое замечание незакрытым.

`25+2+1+5+2 = 35`, P2.

## Сценарий проверки

Агентский: задача про парсер внутреннего инструмента, проверкой служит
воспроизведение симптома на выкаченном taskctl и зелёные регрессионные тесты.
Первый шаг ставит исходный баг, а не показывает правку.

Воспроизвести симптом на выкаченном taskctl во временном корне: файл задачи с
единственным замечанием, буквально цитирующим слово исхода не на хвосте.

    mkdir -p /tmp/dk514t/docs/tasks && : > /tmp/dk514t/docs/TASKS.md
    cat > /tmp/dk514t/docs/tasks/XR-514T.md <<'EOF'
    # XR-514T

    ## Ревью

    - замечание цитирует текст сценария со словами «остаются закрытыми исходом «исправлено»»
    EOF
    taskctl -C /tmp/dk514t review show XR-514T
    taskctl -C /tmp/dk514t review resolve XR-514T 1 fixed

Ожидание: `review show` печатает замечание как `[открыто]`, а `review resolve`
проходит и дописывает исход в хвост строки (не отказывает словами «уже
закрыто»). На баге `show` печатал `[исправлено]` сразу после записи, а
`resolve` отказывал.

Регрессионные тесты зелёные и воспроизводят симптом (краснота на base доказана
прогоном `regcheck`):

    go test ./tools/taskctl/ -run TestReviewOutcomeQuotedWord -v
    go test ./tools/shipctl/ -run TestReviewNotesQuotedWord -v
