# DK-682: Сводка tally слепа к архиву и читает чужие ID из прозы раздела

Цель: [tasks/DK-161.md](../../tasks/DK-161.md)

## Что происходит

Прогон DoD цели DK-161 позвал `agentctl tally --goal docs/tasks/DK-161.md` и
получил пустую сводку. Задачи цели закрыты, их файлы лежат в
`docs/tasks/archive/2026/`, а tally ищет только в `docs/tasks/` и говорит
«файла задачи нет: DK-641, DK-642, ...». Заодно в состав попали ID из прозы
раздела «Задачи цели» (DK-092, DK-503, DK-516, DK-158, DK-117, SC-001):
парсер собирает все упоминания, а не строки состава. Итог закрытой цели из-за
этого не называет, где время ушло, хотя записи этапов в архивных файлах есть.

## Чего хотим

`tally` находит файлы закрытых задач в архиве (глобом
`docs/tasks/archive/<год>/<ID>.md`, тем же путём, что уже считает `taskctl`
для закрытой задачи) и считает их этапы. Состав цели `tally` берёт из строк
состава раздела: пункта «- кандидат N, DK-NNN ...», которым виток нарезки
заводит строку доски, и вводного перечисления материализации «DK-NNN
(кандидат N), ...». Строку узнаёт метка «(кандидат N)» рядом с ID: в пункте
она стоит сразу после «кандидат N,», в перечислении сразу перед скобкой.
Прозаические упоминания и сверки этой меткой не отмечены, и в состав не
попадают. Сводка живой цели DK-161 после фикса называет времена по видам.

## DoD

1. На цели с закрытыми задачами tally печатает разбивку по видам с ненулевыми
   временами, хвост «файла задачи нет» пуст для задач из архива.
2. ID из прозы раздела (упоминания в скобках и сверках) в состав не попадают.
3. regcheck подтверждает красноту регрессионного теста, go test agentctl
   зелёный.

## Ранг

  снова невозможен, работе цикла это не мешает.
- Ценность 6: та же ценность, что у DK-644, довершение до живого случая.
- Неопределённость 1: место известно, поиск в архиве есть у taskctl show.
- Баг +5: дефект найден прогоном DoD.
- Рычаг 2: вход DK-145 (прогресс цели).

## Ревью

- goalCandidateRe и goalMaterializedRe различают только запись DK-161 («- кандидат N, DK-NNN ...»), а строка, начинающаяся с «- », проходит исключительно через goalCandidateRe: continue после неё не даёт дойти до goalMaterializedRe. Живая цель DK-490 материализована по букве самого скилла goal-cut (номер кандидата заменён на ID без «кандидат N,» перед ним): «- DK-491 (task, M, R=61). ...», «- DK-492 (task, M, R=32). ...» и ещё пять строк с реальными ID на доске. На текущем коде «agentctl tally --goal docs/tasks/DK-490.md» печатает «раздел «Задачи цели» файла ... не называет ни одной задачи, складывать нечего», хотя семь ID стоят строками. Старый регексп ловил все семь (вместе с двумя лишними из прозы), новый не ловит ни одного: для этой цели фикс не лечит слепоту tally, а доводит её до нуля. Тот же провал у архивных DK-138 и DK-156, где материализованная строка вообще без слова «кандидат» («- DK-149 (LLD): ...», «1. DK-153, ...»). Нужно расширить распознавание строки состава хотя бы на форму без «кандидат N,» перед ID (документированную самим goal-cut), не заужая под единственный образец DK-161.: исправлено
- Задачи, заведённые по ходу цикла не кандидатом, а прямо строкой журнала (в самой DK-161 так закрыта DK-649, рядом DK-677 и DK-682), в раздел «Задачи цели» не попадают вовсе, и никакой паттерн там их не найдёт: goalTaskIDs читает только этот раздел. После фикса tally по-прежнему не досчитывает время, ушедшее на такие попутные задачи, и DoD 4 DK-161 («итог называет, где ушло время») этим не закрывается целиком. Это устройство раздела «Задачи цели», а не регексп DK-682, но стоит явно решить: рамка это или дыра DoD 4, и нужна ли отдельная задача на учёт попутных задач цели.: отклонено, рамка раздела правильная, tally читает «Задачи цели», а попутные задачи цели в раздел допишет диспетчер: это правило goal-loop, пропуск ведения, не правка DK-682
