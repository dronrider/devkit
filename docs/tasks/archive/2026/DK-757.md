# DK-757: trackctl review заводит строку ревью чужого тикета без касания тикета

Цель: [lld/DK-756-foreign-review.md](../../lld/DK-756-foreign-review.md)

## Что происходит

Просьба «проведи ревью задачи AB-123» в корп-контуре не имеет входа. `trackctl take` назначит чужой тикет на меня и передвинет статус, а без строки на боковой доске у ревью нет ни файла задачи, ни следа уровня. Решение 1 LLD DK-756.

## Чего хотим

`trackctl review <KEY>` заводит на боковой доске зеркальную строку ревью со ссылкой на тикет и MR, заголовком и описанием тикета в файле задачи, ценой и рангом по тикету. Тикет не трогается. Повторный вызов находит стоящую строку. `sync` строку ревью по статусу тикета не двигает.

## DoD

- `trackctl review AB-123` на адаптере-заглушке заводит строку с пометкой сценария в заголовке и файл задачи с постановкой из тикета и ссылкой на MR, найденный по ветке из шаблона контура.
- Исполнитель, статус и эстимейт тикета после команды те же, что до неё, тест это проверяет по журналу вызовов заглушки.
- Повторный вызов на тот же ключ дубля не заводит и называет стоящую строку.
- MR не найден или найден не один: отказ с просьбой дать ссылку, строка не заводится.
- `trackctl sync` строку ревью не двигает, тест с переходом тикета в конечный статус.
- README trackctl: команда в перечне и абзац про строку ревью.

## Ревью

Уровень 2 до 8c31ff6: стартовый уровень 2 от диспетчера, триаж: DoD-путь не ломает (новая изолированная команда), tools/trackctl вне critical_paths (нет доступов/данных/денег/секретов, не горячий путь).

- не блокирует: ранг строки ревью не переведён из тикета, а взят заготовкой ревью-работы (0+0+1+bug+2), причина в комментарии reviewRank - контракт адаптера даёт rank только на запись, читаемого числового приоритета нет. У take ранг тоже не читается из тикета, а идёт в обратную сторону, из уже заведённой groomed-строки в тикет, так что «как у take» для ранга буквально нереализуемо. Заготовка явно помечена в выводе командой поправить после грумминга, поведение проверено TestReviewRankBugCorrection, DoD конкретных значений ранга не требует: отклонено, у адаптера нет читаемого приоритета в тикете, rank это только запись; заготовка ранга явно помечена в выводе команды

## Сценарий проверки

1. На стенде с боковой доской и адаптером-заглушкой: `trackctl review AB-123`, ожидание строка на доске и файл задачи со ссылками на тикет и MR.
2. Повторить команду, ожидание строка та же, дубля нет.
3. Перевести тикет в конечный статус на заглушке, `trackctl sync`, ожидание строка ревью на месте.
