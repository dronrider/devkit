# DK-882: decide дописывает вариант ответа в заведённую развилку

## Что происходит

Варианты ответа перечень развилок получил позже самой команды. Записи, чей
вопрос заведён раньше, остались с одной рекомендацией. Блок `decide --chat`
печатает такой развилке единственный пункт, и выбирать человеку не из чего.
Дописать вариант было нечем: ключ `--option` работал только при `--ask`, а
повторное `--ask` на занятое имя отбивается своим отказом. Поймано грумингом
DK-796, где три человеческие развилки завелись до правки DK-864.

## Чего хотим

Вопрос, заведённый без вариантов, доводится до выбора там же, где он лежит, без
второго имени под тем же вопросом.

## DoD

Команда `taskctl decide <ID> «имя» --option "..."` дописывает вариант в
заведённую развилку. Вариант встаёт после рекомендации и прежних вариантов, но
раньше следов решения и передачи. Повтор записанного варианта пачку не отбивает,
команда называет его в ответе и второй раз в файл не кладёт. Решённая развилка
вариант не принимает. Тесты лежат рядом с остальными про `decide` и про формы
развилок. Абзац в README taskctl, раздел «Развилки записи».

## Ревью

Уровень 2 до d9f0572: неопределённость 0 по рангу, критичный путь tools/taskctl даёт одно да в триаже: живой путь по DoD прогнан, дифф прочитан по составу до d9f0572d

- [возврат: реализация, 2026-09-09] не блокирует: tools/taskctl/decide.go, decideOption (строки 40-79). Когда все переданные --option оказались дублями, doc остаётся неизменным, а decideOption всё равно возвращает успех; runDecide пишет тот же файл и зовёт p.Commit.apply. При вызове с --commit git commit упадёт на пустом диффе вместо информативного "уже были в перечне". Проверить: taskctl decide ID «имя» --option "уже записанный вариант" --commit "msg" на развилке, где этот вариант уже есть: исправлено, пачка из одних дублей файла не переписывает и на коммит не идёт, ответ говорит «дописывать нечего», тест TestDecideOptionAllDuplicates, краснота проверена прогоном на снятой правке decide.go

## Сценарий проверки

Шагов три, и каждый идёт своим прогоном в свежем дереве. Стенд поэтому живёт
одной строкой, переменная до следующего шага не доживает. Ключ `-C` у `go`
стоит первым, иначе он его не принимает. Утилиты обкатка
собирает сама, руками сборка нужна только при ручном прогоне
(`devkitctl.py build`).

```sh
GOWORK=off go -C internal/taskform test -count=1 ./...
GOWORK=off go -C tools/taskctl test -count=1 -run 'Decide|Chat|Fork' ./...
S=$(mktemp -d) && mkdir -p "$S/docs/tasks" && git -C "$S" init -q && taskctl -C "$S" init --prefix ST --name стенд && printf '# ST-001: стенд\n\n## Что происходит\n\nтекст\n' > "$S/docs/tasks/ST-001.md" && taskctl -C "$S" decide ST-001 --ask «область» --hint "только боковая директория контура" "любая вложенная доска или контур?" && taskctl -C "$S" decide ST-001 --chat && taskctl -C "$S" decide ST-001 «область» --option "правило по суффиксу пути" && taskctl -C "$S" decide ST-001 --chat && taskctl -C "$S" decide ST-001 «область» --option "правило по суффиксу пути" && taskctl -C "$S" decide ST-001 «область» --by человек "боковая директория контура" && ! taskctl -C "$S" decide ST-001 «область» --option "поздний вариант" && sed -n '/## Развилки/,$p' "$S/docs/tasks/ST-001.md"
```

Ожидаемое по шагам:

- обе сюиты зелёные, слова «cached» в выводе нет;
- первый `--chat` печатает развилке один пункт, рекомендацию;
- дописывание отвечает «дописано вариантов 1»;
- второй `--chat` печатает два пункта, рекомендованный первым номером;
- повтор того же варианта отвечает «дописывать нечего, уже были в перечне 1»;
- дописывание в решённую развилку кончается отказом «вариант ей уже не нужен»,
  и шаг ждёт этого отказа отрицанием;
- хвост файла показывает вариант между рекомендацией и строкой решения.
