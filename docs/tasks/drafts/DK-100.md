# DK-100: Дерево контекста: тонкий резидентный корень и правила по требованию

## Черновик

Дерево контекста: тонкий резидентный корень и правила по требованию

Разбор расхода за 5.07-3.08 (сессия про ccusage): 7,67 млрд токенов, $8 693 по
ставкам API. Чтение кеша это 96,5% объёма, но 54% денег ($4 717); ещё 26%
($2 264) съедает запись кеша на часовом TTL. Контекст на запрос: медиана 128k,
среднее 182k, p90 394k; запросы >=200k несут 61% объёма; сабагенты 30%.
Резидентная цепочка devkit (CLAUDE.md -> RULES.md + RULES.board.md + AGENTS.md
+ MEMORY.md) ~53k символов, ~20k токенов в каждом из 42k запросов месяца,
то есть ~0,85 млрд токенов только на постоянный хвост.

Идея: контекст должен грузиться деревом. Корень тонкий (критический список на
~30 строк плюс указатели), остальное по требованию: RULES.board.md уезжает в
скилл, который грузится при работе с доской; стилевые правила по возможности
переезжают в хуки-энфорсеры (check-symbols уже так работает), тогда прозу
можно не держать в резиденте. Вопрос «какая погода» не должен тянуть весь
проектный контекст.

Рычаги по убыванию эффекта:
1. Длина истории: жирные tool results (чтение файлов целиком, длинные выводы),
   длинные сессии без /clear. Дисциплина чтения (offset/limit, grep),
   Explore-агенты для разведки, /clear между задачами.
2. Тонкий корень (эта идея): срезает ~20k токенов с каждого запроса, оценочно
   сотни долларов в месяц. Пол не срезать: системный промпт харнесса и схемы
   тулов останутся.
3. Лестница моделей: чтение кеша на fable $1/M против $0.5 у opus и $0.3 у
   sonnet; fable-сессии дали $2.46k из $4.7k чтения кеша.

Осторожно: резать контекст на живой сессии нельзя, инвалидация префикса
превращает дешёвое чтение (0.1x) в дорогую запись (1.25-2x). Резать на
границах задач, не внутри. Часовой кеш при редких инвалидациях выгоден,
при частых становится главной статьёй, что уже видно по cw1h.

Замер и методика в сессии от 3.08, скрипты в скретчпаде (build.py).
