# DK-1004: Чат закрытой задачи не находится по её ID

записан 2026-09-15
приоритет: средний

## Черновик

### Ситуация

2026-09-15, сессия закрыла DK-852 в 04:01. Закрытие пишет в реестр «снята DK-852», а список чатов собирает подпись разговора задачами свёрткой `Touched` (`internal/sessions/sessions.go`), которая снятые задачи вычёркивает. В панели разговор этой сессии по «DK-852» не находится, кнопка чата у строки заводит новый.

### Осложнение

Права на строку снимать после закрытия надо, а память о том, что задачу делали в этом разговоре, стирается вместе с ними. Итоги закрытой задачи в её чате недоступны через строку и поиск, найти их можно только по заголовку разговора, который назван первой репликой и ID задачи не содержит.

### Вопрос

Разделить ли два смысла «снята»: рабочая свёртка `Works` снимает права, а `Touched` касание оставляет? Отвязка рукой с пустой задачей тогда остаётся полной.

### Гипотеза

Разговор, в котором задачу делали, находится по её ID и после закрытия строки; права на строку при этом сняты, как сейчас.

### Приписка 2026-09-16: тот же корень у черновика и у окна до записи хука

Черновик DK-603 найден поиском в шапке дашборда, на его экране нажата кнопка чата. Панель открылась в состоянии «новый чат», хотя разговор по DK-603 в списке сессий стоял живым. Второй сессии при этом не поднялось, в журнале дашборда чат по DK-603 поднят один раз, в 11:02:04.

Кнопка на строке доски получает от сервера адрес живой сессии полем `run_chat` или `talk_chat` (`tools/dashboard/tasks.go`, `boardRuns`) и открывает его напрямую. Экран черновика зовёт ту же кнопку с одним ID (`static/app.js`, `renderDraft` и `formPage`), потому что ручки черновиков этих полей не отдают. Панель тогда перебирает список чатов по полю `tasks`, а его сервер собирает той же свёрткой `Touched` (`tools/dashboard/chats.go`). Имя tmux-окна `chat-DK-603-1` в это поле не попадает.

Записи реестра у сессии в момент нажатия не было. Дашборд поднял tmux в 11:02:04, хук старта записал привязку к DK-603 в 11:05:50. Почти четыре минуты разговор в списке виден, а по ID черновика в поле `tasks` пуст, и кнопка открывает пустую панель. Доска в этом окне повела бы себя так же, `run_chat` считается по тем же записям.

Третий вход в ту же дыру пишет resume. В 11:23:04 в реестр легла запись с пустой задачей для той же сессии, а свёртка `Last` берёт задачу из последней записи, в том числе пустой (`internal/sessions/sessions.go`). После неё сессия для доски перестаёт быть работой по DK-603, и у строки пропадает `run_chat`. Панель находит разговор только через `Touched`, где пустая запись без «снята» пропускается.

Тестов на «кнопка чата черновика открывает существующий разговор» нет ни в Go, ни среди стендов `testdata/poc_chat*.mjs`. Стенд `poc_chattask.mjs` проверяет обратное: задача без своих диалогов открывает новый чат с её привязкой.

К вопросу выше добавляются два. Отдавать ли черновикам те же `run_chat` и `talk_chat`, что строкам доски. Учитывать ли имя tmux-окна с ID задачи в поле `tasks` до прихода записи хука.
