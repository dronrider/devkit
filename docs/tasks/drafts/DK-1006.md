# DK-1006: Сессия кончается по заказу, а взятая по ходу задача виснет в In progress

записан 2026-09-15
приоритет: средний

## Черновик

### Ситуация

2026-09-15, сессия «Выполни DK-852» взяла по ходу DK-998, слила её в main, закрыла DK-852 в 04:01 и ждала фоновую обкатку DK-998. Обкатка упала в 04:11 по потолку шага, последняя реплика сессии «жду завершения, дальше переведу в Check». Дальше тишина до 11:32, когда человек случайно открыл этот разговор. Семь часов строка DK-998 стояла в In progress без живой сессии, дашборд показывал `run=gone`.

### Осложнение

Конвейер встал на побочной задаче, и заметить это было нечем: подъёма нет, уведомления нет, строка найдена только через кнопку чата. Рядом с целью DK-902 про непрерывный конвейер.

### Вопрос

Кто подхватывает хвост: сессия перед концом обязана сдать побочные задачи (правило в board-task), сторож видит In progress без живой сессии и будит подъём, или «gone» в дашборде получает кнопку и автоподъём?

### Гипотеза

Строка In progress без живой сессии подхватывается в пределах тика без человека, а тишина после упавшей фоновой обкатки видна снаружи.
