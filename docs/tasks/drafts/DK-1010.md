# DK-1010: Коммиты доски из сессий задач подписаны автором stand, а не человеком

записан 2026-09-15
приоритет: средний

## Черновик

### Ситуация

С 2026-09-13 18:27 коммиты доски из сессий задач в tmux и из тиков сторожка идут с автором `stand <stand@local>`. В истории devkit таких 273 из последних 400. Коммиты из окна редактора подписаны именем пользователя. Первый коммит с таким автором лёг в 18:27 того же дня, сразу после прогона сценария проверки DK-942. Тот сценарий заводил временный HOME и репозиторий с `git config user.name stand`.

### Осложнение

Глобальный gitconfig пользователя в порядке. Локального user у клона devkit нет. У демона дашборда HOME штатный. Tmux-сервера в момент проверки не было, и посмотреть его окружение не вышло. В истории и на гитхабе автором ответов и решений стоит стенд. Строки «решено человеком» в файлах задач писал тот же автор.

### Вопрос

Откуда сессия задачи берёт имя stand и как вернуть в коммиты доски имя пользователя.

### Гипотеза

Имя приезжает окружением, в котором taskctl run и тик поднимают голову задачи, через task-run.py или обвязку tmux. Второй кандидат это конфиг из чужого HOME. Проверка: поднять голову любой задачи через taskctl run и напечатать `git var GIT_AUTHOR_IDENT` из её окна. Счёт авторов даёт `git -C ~/projects/devkit log --format='%an|%ae' -n 400 | sort | uniq -c`.
