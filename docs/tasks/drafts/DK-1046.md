# DK-1046: выкат падает, команда сборки не находит go в PATH

записан 2026-09-18
приоритет: высокий

## Черновик

### Ситуация

2026-09-18, выкат поезда DK-1043. `shipctl ship` упал строкой «go в PATH нет,
собирать нечем». Go на машине стоит в `/usr/local/go/bin`. Этого каталога нет
в PATH сессии. Нет его и в ключе `EnvironmentVariables` plist службы
`ru.devkit.dashboard`, откуда выкат поднимается тиком. С прописанным
`PATH=/usr/local/go/bin:$PATH` тот же `shipctl ship` прошёл с первого раза.

### Осложнение

Правка второго круга DK-1043 пролежала слитой на main с 10:16 до 11:14 и на
прод не попала. Тиковый `shipctl ship --drain` каждые пять минут молчал нулём.
Сценарий проверки этого тоже не поймал. Агентская часть гоняет тесты рабочего
дерева и прода не трогает. Приёмка успела отметить smoke на сборке без правки.

### Вопрос

Чинить PATH раскладкой devkit (подключение дописывает каталог Go в plist и в
профиль) или ловить нехватку Go находкой `devkitctl doctor`?

### Гипотеза

Выкат проходит без ручного PATH на любой машине, где Go стоит мимо
`/usr/local/bin`. Нехватку Go видно диагностикой заранее.

## Что дал разбор 2026-10-27

Обход и замер живой машины. Правки PATH выката после 2026-09-18 нет: DK-1271
(13.10) переписал генератор plist с обёрткой agentctl exec, DK-1373 (23.10)
добавил рабочий каталог, каталог Go никто не добавил. Строку печатает
`build_binaries` (tools/devkitctl/devkitctl.py:3307, `shutil.which("go")` по
PATH процесса), выкат зовёт её через `machine_build` (:3284). Окружение живой
службы проверено процессом: pid `dashboard serve` несёт тот же PATH, что
plist, без `/usr/local/go/bin`, сегодня выручает только homebrew-Go.

PATH служб собирает `agent_path` (tools/devkitctl/dashboard.py:195) из
констант SYSTEM_PATH, BREW_PATH и LOCAL_BIN (:190-192), в них go-каталога нет.
Сборщик один на дашборд и сторожок цели (DK-664, watch.py тем же сборщиком),
перевыпуск plist делает `doctor --fix`. Профиль оболочки раскладка не правит.
Доктор случай не ловит: `check_binaries` (devkitctl.py:1206) спрашивает PATH
сессии самого доктора, живое окружение службы это тема открытой DK-848.

Дубль: DK-1030 «Сессия, поднятая заново, не находит go в PATH» (2026-09-17),
приписка 2026-09-18 описывает этот же случай на выкате. Строк ни у кого нет,
оформляется DK-1046, DK-1030 приписывается к нему. В архиве тот же класс:
DK-664, DK-247.

## Развилки

- «кейсы»: какие пользовательские кейсы у DK-1046? рекомендую сбалансированный: кейсы (4) и (5) широкого лежат за границей записи, (4) это открытая DK-848
  - решает: человек
  - рекомендация: сбалансированный состав, 3 кейса: (1) выкат поезда на машине с Go в /usr/local/go/bin доезжает без ручного PATH; (2) сессия, поднятая сторожком цели заново, находит go тем же PATH сборщика; (3) devkitctl doctor --fix перевыпускает plist и PATH живой службы получает go-каталог
  - вариант: узкий состав, 1 кейс: (1) выкат поезда доезжает без ручного PATH
  - вариант: широкий состав, 5 кейсов: (1) выкат доезжает без ручного PATH; (2) поднятая сторожком сессия находит go; (3) doctor --fix перевыпускает plist с go-каталогом; (4) doctor заранее находит нехватку go в окружении службы; (5) поток обновления находит go при сборке на месте
- «источник go-каталога»: откуда agent_path берёт go-каталог машины?
  - решает: исполнитель
  - рекомендация: дописать /usr/local/go/bin константой в agent_path рядом с BREW_PATH: сборщик один на дашборд и сторожок цели, перевыпуск plist уже делает doctor --fix
  - вариант: искать go динамически при doctor --fix по which go и брать его каталог
  - источник: код tools/devkitctl/dashboard.py:190-192
- «профиль оболочки»: правит ли раскладка профиль оболочки рядом с plist?
  - решает: исполнитель
  - рекомендация: профиль не трогать: PATH нужен службам и тикам, интерактивная сессия несёт свои пути, правка профиля это правка чужого файла
  - вариант: дописать каталог Go и в профиль оболочки
  - источник: код tools/devkitctl/dashboard.py:238-256

## DoD

`agent_path` несёт go-каталог машины, `doctor --fix` перевыпускает plist
службы дашборда и PATH живого процесса получает его, тест держит константу
сборщика. Выкат на машине, где Go стоит в `/usr/local/go/bin`, доезжает без
ручного PATH.
