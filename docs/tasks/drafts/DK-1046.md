# DK-1046: выкат падает, команда сборки не находит go в PATH

записан 2026-09-18
приоритет: высокий

## Черновик

### Ситуация

2026-09-18, выкат поезда DK-1043. `shipctl ship` упал строкой «go в PATH нет:
собирать нечем, Go ставится пакетным менеджером (brew install go)», хотя Go на
машине стоит в `/usr/local/go/bin`. Этого каталога нет ни в PATH сессии, ни в
ключе `EnvironmentVariables` plist службы `ru.devkit.dashboard`, откуда выкат
поднимается тиком. С `PATH=/usr/local/go/bin:$PATH` тот же `shipctl ship`
прошёл с первого раза.

### Осложнение

Правка второго круга DK-1043 пролежала слитой на main с 10:16 до 11:14 и на
прод не попала. Тиковый `shipctl ship --drain` каждые пять минут молчал нулём,
а сценарий проверки этого не поймал: агентская часть гоняет тесты рабочего
дерева, и прод она не трогает. Приёмка успела отметить smoke на сборке без
правки.

### Вопрос

Чинить PATH раскладкой devkit (подключение дописывает каталог Go в plist и в
профиль) или требовать Go на PATH диагностикой `devkitctl doctor` с находкой?

### Гипотеза

Выкат с машины, где Go стоит не в `/usr/local/bin`, проходит без ручного PATH,
а нехватка Go видна до выката, а не падением деплоя.
