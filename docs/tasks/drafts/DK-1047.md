# DK-1047: поезд из двух задач не проходит ворота обкатки перед выкатом

записан 2026-09-18
приоритет: высокий

## Черновик

### Ситуация

2026-09-18, пачка DK-472, DK-396, DK-894. Все три слиты `shipctl merge --train`, `shipctl ship` отказал воротами перевода в Check: отметка обкатки каждой задачи стоит на коммите её ветки, а HEAD main после ребейза и слияния соседей другой. Переобкатка на main кладёт отметку в файл задачи, `ship` требует чистого дерева, а коммит отметки одной задачи гасит отметки остальных. Ворот `rehearsalGate` в tools/taskctl/gate.go прощает после обкатки только коммиты файла самой задачи (`onlyTaskDocSince`), файл задачи соседа для него уже «код, которого обкатка не видела».

### Осложнение

Поезд из двух и более задач штатно не выкатывается. Диспетчер ходит по кругу: обкатка, коммит, отказ по соседу. В этой пачке круг занял четыре захода `ship` и около получаса, вышли пометкой «- Исключение: обкатка» у двух задач из трёх, хотя обкатка у них зелёная. Так будет на каждой пачке, потому что отметка ветки после ребейза устаревает всегда.

### Вопрос

Прощать воротам коммиты, трогающие только docs/tasks/ и docs/TASKS.md, или ставить отметки всему составу самим `ship` одним заходом перед воротами?

### Гипотеза

Поезд из нескольких задач с зелёной обкаткой на main уезжает в Check одной командой `shipctl ship`, без пометок-исключений.
