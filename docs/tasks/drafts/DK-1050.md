# DK-1050: ревьювер правит строку вердикта под сторож прозы, слияние отказывает

записан 2026-09-18
приоритет: средний

## Черновик

### Ситуация

2026-09-18, DK-631. Ревьювер записал `taskctl review clean`, хук сторожа прозы на коммите пожаловался на двоеточия и длинные фразы в строке вердикта. Ревьювер переписал строку руками и убрал двоеточие из «Вердикт: без замечаний». `shipctl merge DK-631 --train` отказал словами «в ревью замечания без исхода», строку без машинного начала ворот прочитал открытым замечанием. Те же жалобы сторожа на строки ревью были на DK-396, DK-894 и DK-457, там машинное начало уцелело случайно.

### Осложнение

Два рубежа тянут строку в разные стороны. Сторож прозы требует перестроить фразу, ворота слияния требуют её машинный вид. Чинил диспетчер руками в ветке, слияние с тестами ушло на второй заход, это около десяти минут на задачу.

### Вопрос

Выводить машинные строки раздела «Ревью» из-под сторожа прозы либо учить `review clean` складывать перечень проверенного короткими фразами?

### Гипотеза

Строка, записанная `taskctl review`, проходит хук прозы без правки руками, и ворота слияния читают её всегда.
