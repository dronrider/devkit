# DK-1056: след стенда с цитатами судьи не проходит рубеж символов

записан 2026-09-19
приоритет: средний

## Черновик

### Ситуация

2026-09-18, DK-449. `obeycheck --task` пишет в раздел «Проверка» файла задачи разбор судьи дословно (поле `a.Judge`, tools/obeycheck/table.go), без нормализации символов. Модель-судья вставила в ответ длинные тире, хук символов на коммите отказал. Исполнитель заменил пять тире на двоеточие и запятую внутри цитат, ревью вернуло это блокирующим замечанием: правка машинного вывода и подмена тире двоеточием запрещены правилами.

### Осложнение

След прогона с судьёй штатно не закоммитить. Исполнитель либо правит машинный блок руками, либо снимает цитаты целиком и пересказывает их, и дословный разбор судьи в файле задачи теряется. Так будет на каждом сценарии с судейской секцией (LLD DK-805).

### Вопрос

Нормализовать символы ответа судьи на стороне утилиты при записи следа либо выводить блок цитат из-под рубежа символов?

### Гипотеза

След прогона с разбором судьи коммитится в том виде, в каком его записала утилита, без правки руками.
