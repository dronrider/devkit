# DK-1058: машинные строки файла задачи после вычитки сверяет утилита

записан 2026-09-19
приоритет: средний

## Черновик

### Ситуация

2026-09-18 и 19, DK-464. Вычитку по скиллу proofread учат не трогать машинные строки перечнем в тексте скилла. Перечень собирали три круга ревью подряд, и каждый круг находил форматы, которых в нём не было: строки «Выката», «равенство:» в развилках, «Стенд не зачтён:», «Возврат:», голову замечания с классом возврата, раздел «Журнал» файла цели, строки судьбы MR. На стенде вычитка с полным перечнем всё равно один раз из пяти тронула строку замечания в «Ревью».

### Осложнение

Перечень в промпте устаревает с каждой новой строкой, которую начинает писать taskctl, agentctl или shipctl, и держится вероятностно. Испорченная машинная строка находится поздно и дорого: ворота слияния читают её открытым замечанием либо не находят отметку (DK-1050, DK-460).

### Вопрос

Где живёт проверка: шагом самого скилла proofread после правки (дифф файла не задевает строк, которые разбирает код) либо хуком записи файла задачи? Источник форматов общий с разбором, internal/taskform.

### Гипотеза

Правка, задевшая машинную строку файла задачи, отбивается сразу и называет строку, а новый формат строки накрывается без правки текста скилла.
