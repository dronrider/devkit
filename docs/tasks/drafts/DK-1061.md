# DK-1061: шаг сценария обкатки двигает теги живого репозитория

записан 2026-09-19
приоритет: высокий

## Черновик

### Ситуация

2026-09-19, DK-1060. `taskctl rehearse` гоняет шаги сценария в свежем дереве, а оно делит git-ссылки с живым репозиторием, как любой worktree. Шаг исполнителя `git -C "$D" tag -f deployed HEAD` выполнился с пустой переменной: каждая строка блока sh это отдельный процесс, и значение из строки выше до неё не дожило. Пустой `-C` означает текущий каталог, то есть свежее дерево, и команда сдвинула настоящий тег `deployed` на коммит ветки задачи. Исполнитель заметил и вернул тег на значение из origin.

### Осложнение

Тег `deployed` держит окно выката: сдвинутый молча, он меняет состав следующего поезда и диапазон, по которому shipctl выбирает команды выката. Обкатка обещает чистое окружение (свежее дерево, временный HOME), а теги, ветки и конфиг репозитория у неё общие с живым. Та же ловушка у любого сценария, который трогает ссылки git.

### Вопрос

Гонять шаги в отдельном клоне вместо worktree либо оставить worktree и отбивать шаги, меняющие ссылки вне своего дерева?

### Гипотеза

Шаг сценария обкатки не может сдвинуть тег или ветку живого репозитория, какой бы командой он ни был.
