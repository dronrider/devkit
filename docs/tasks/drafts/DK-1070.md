# DK-1070: Парковка чужих файлов стэшем стирает правки соседней сессии

записан 2026-09-20
приоритет: высокий

## Черновик

### Ситуация

2026-09-19 в 23:53 сессия по DK-881 перед `shipctl ship` положила в стэш `dk881-session-foreign-park-ship` незакоммиченные файлы общего дерева main, среди них черновик DK-1069, который в ту же минуту правила моя сессия командами `taskctl decide`. После возврата в дереве осталась версия из стэша, а записи, сделанные между парковкой и возвратом, легли поверх откатившегося файла и частично пропали. Стэш при этом остался в списке, хотя субагент отчитался «no stash left behind». В README shipctl такой парковки нет, её сделала сама сессия.

### Осложнение

Две сессии одной машины в общем дереве теряют работу друг друга молча. Восстанавливать пришлось руками из стэша, а ответы человека в перечне развилок были записаны заново. Это тот же класс, что DK-1069 про две машины, только внутри одной.

### Вопрос

Запретить сессии трогать чужие незакоммиченные файлы (стэш, checkout, restore) хуком, или дать shipctl штатную парковку, которая кладёт файлы поверх свежих правок и ничего под ними не стирает. Как сессии узнать, что файл чужой.

### Гипотеза

Выкат и слияние в общем дереве не трогают незакоммиченные файлы других сессий, а попытка припарковать чужое отбивается с именем сессии-владельца.
