# DK-1092: Конфликт доски при pull --rebase разбирается руками в каждой сессии

записан 2026-09-21
приоритет: высокий

## Черновик

### Ситуация

DK-881 разобрала 11 конфликтов `docs/TASKS.md` и архива, DK-1032 13 и написала свой питон-скрипт на пятнадцать шагов ребейза. 19 сентября 00:26 `taskctl list --json` дважды отказал на `<<<<<<< HEAD` в TASKS.md. Конфликт каждый раз однотипный: обе стороны дописали строку в журнал, либо одна закрыла строку, а другая её сдвинула. Ловушка «обе стороны при закрытии» живёт в памяти сессий.

### Осложнение

Около 25 ходов на сессию, доска на время нечитаема утилитой, риск стереть чужую строку или воскресить закрытую.

### Гипотеза

Доска и архив сливаются механически по ID строки: утилита (драйвер слияния git или шаг внутри `shipctl push` и `merge`) оставляет обе новые строки, а закрытую одной стороной убирает. Сессия конфликта доски не видит.
