# DK-1118: plan done без номера не находит идущий пункт после step соседнего

записан 2026-09-21
приоритет: низкий

## Черновик

### Ситуация

Исполнитель DK-972, 2026-09-21: после agentctl plan step на следующий пункт вызов agentctl plan done --label DK-972 без номера отвечает «идущего пункта в плане нет», хотя предыдущий пункт стоял начатым и не был закрыт.

### Осложнение

Закрытые пункты приходится называть номером, а порядок «step следующего, потом done предыдущего» ломает удобную форму без аргумента. Скилл work-plan про это молчит.

### Вопрос

Закрывать по done без номера последний начатый пункт, даже если позже начат другой, или запретить второй step при незакрытом идущем и сказать об этом в подсказке?

### Гипотеза

step второго пункта при незакрытом первом это ошибка с подсказкой «закрой пункт N», а done без номера остаётся однозначным.
