# DK-1121: Команды груминга не делают чат работой задачи, кнопка запуска остаётся

записан 2026-09-22
приоритет: средний

## Черновик

### Ситуация

2026-09-22, груминг DK-879 из свободного чата дашборда (chat-5). После `taskctl set DK-879` реестр `~/.devkit/sessions.log` получил строку с источником «работа», и строка доски пришла с полями run: chat, run_busy: true. Вместо кнопки «Выполнить» у строки стоял «Стоп». Перечень touchCmds в tools/taskctl/touch.go считает работой add, move, close, ask, fail, set, file, review, dep и progress. Комментарий к taskChats в tools/dashboard/chats.go говорит обратное: груминг, привязка рукой и разговор о задаче строку не присваивают. Привязку снял ручкой POST /api/projects/{p}/sessions/{sid}/task с пустой задачей, после этого поля run у строки пропали.

### Осложнение

Каждый груминг из чата зовёт add и set, и разговор становится работой над строкой. Пока чат жив, у строки «Стоп» вместо запуска, и кнопкой конвейер не поднять. После смерти чата кнопка становится «Продолжить» и ведёт в разговор разбора, а не поднимает исполнителя. Такое случается на каждой задаче, оформленной из чата, а не с экрана черновика.

### Вопрос

Какие команды остаются работой: move в In progress, ask, fail, review и этапы agentctl stage, а add, set, file, dep и progress уходят из перечня? Нужна ли запись «снята» на add --id, чтобы старые чаты разбора отпустили строки без руки?

### Гипотеза

Задача, оформленная или поправленная из чата, стоит в Backlog с кнопкой «Выполнить», а чат разбора в списке чатов остаётся разговором о задаче без признака работы.
