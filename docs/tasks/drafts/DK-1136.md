# DK-1136: go:dashboard: TempDir cleanup гонка валит прогон под GOMAXPROCS=1

записан 2026-09-23
приоритет: средний

## Черновик

### Ситуация

Три подряд живых прогона `python3 tools/devkitctl/parallel.py` упали на
`go:dashboard`. Код новый, из DK-1123 (доля по числу живых воркеров). Оба раза
тесты одни и те же: TestChatListGluesWindowPasses и
TestChatListShowsQuotaWait, testing.go:1464, TempDir RemoveAll cleanup:
unlinkat ...: directory not empty. Стена до провала 508-514 с. Потолок из
DK-1122 - 1560 с, раздутия стены нет. Провал при этом повторился 3 из 3 раз.

Диагностика: те же два теста в изоляции (-run, count=8) зелёные. Зелёные и под
GOMAXPROCS=1, и на умолчании. Гонка не в самих тестах поодиночке. Она
всплывает только при прогоне всего пакета целиком, где много параллельных
сабтестов делят машину. DK-1122 раунд 2 видел ту же гонку один раз, на -j5,
без всякого GOMAXPROCS - до DK-1123 доля компонентам вообще не назначалась.
Похоже, GOMAXPROCS=1 делает эту гонку систематической. Доля
компонента первого залпа в DK-1123 статична навсегда, домешать её после
старта процесса нельзя.

DK-1123 эту гонку не чинит. Блокирующее замечание её ревью закрыто разбором и
живым замером стены, а сама гонка лежит вне двух названных замечаний. Годится
строкой под цель DK-1084, в семейство тестов, которые красят чужие слияния.
Годится и отдельным bug на два выхода: тест сам починить (дождаться
watcher или goroutine перед cleanup), либо признать, что go:dashboard нельзя
гонять с GOMAXPROCS=1.
