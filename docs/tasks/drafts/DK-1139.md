## Ситуация

2026-09-23, исполнитель DK-1124 в дереве задачи собрался закоммитить правку и
позвал `DEVKIT_NO_TESTS=1 git commit ...`. Разрешение харнеса ловит буквальное
начало строки «git commit». Префикс переменной окружения перед командой его
рвёт, и вызов уходит на подтверждение человеку. В заходе без окна подтвердить
нечем. Работа встаёт на ровном месте.

Тот же разрыв ждёт всякую команду, которой в devkit положено ехать с
переменной впереди. Ближайший сосед это `GOWORK=off go test`. Без переменной
цепляется чужой go.work, а с переменной правило разрешения на `go test` команду
уже не узнаёт.

## Осложнение

Исполнитель обошёлся без переменной, и обход стоил ему отдельной работы.
Разрешение читает строку целиком, и префикс для него это другая команда.

## Чего хотелось бы

Разрешение узнаёт команду за префиксом переменных окружения. Второй способ:
devkit подсказывает агенту свой порядок задания переменной, при котором правило
команду видит.
