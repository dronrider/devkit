# DK-1172: Определение исполнителя велит класть план литеральным переносом

записан 2026-09-26
приоритет: средний

## Черновик

## Черновик

### Ситуация

2026-09-26, исполнитель DK-1169. Форму плана определения `kit/agents/exec-*.md` показывают строкой `agentctl plan set --label <ID задачи> "<этап>\n<этап>\n<этап>"`. В оболочке внутри двойных кавычек эти два знака переносом не становятся. Проба на живой команде это подтвердила. Вызов с тремя этапами через литеральный перенос кладёт один пункт с обратным слешем внутри. Команда ждёт настоящих переносов, её справка так и говорит, пункт с переносами строк это список.

### Осложнение

Исполнитель, повторивший форму из своего определения дословно, получает план из одного пункта. Ни команда, ни рубеж об этом не говорят, увидеть можно только глазами в выводе. Исполнитель DK-1169 обошла подстановкой `printf` и ключом `--force`, потому что `set` поверх несовпавшего плана отказывает.

### Вопрос

Чинить определения агентов или саму команду? Команда могла бы разворачивать литеральный перенос сама, но тогда пункт с обратным слешем в тексте его потеряет. Форма из отдельных аргументов, как у диспетчера, в определении тоже возможна.

### Гипотеза

Определения исполнителей кладут план тем же способом, что и диспетчер, пунктами отдельными аргументами. Литеральных переносов в промптах не остаётся.
