# DK-1192: ворота тестов слияния не узнают node-стенд в каталоге testdata

записан 2026-09-26
приоритет: средний

## Черновик

### Ситуация

Замечено 2026-09-26 на слиянии форвард-фикса DK-892. Правка тронула `tools/dashboard/static/app.js`, тесты к ней легли в `tools/dashboard/testdata/poc_askpick.mjs` и `poc_askwake.mjs`: это node-стенд поддельного DOM, его гоняет go-тест `TestStaticAskPicksInReply`, краснота на прежней редакции подтверждена regcheck. `shipctl merge` отказал: «в диффе ветки против main нет тестовых файлов». Предикат `isTestFile` в `tools/shipctl/advice.go` знает суффиксы `_test.go`, `_test.py`, `_test.sh`, `_test.rs`, префикс `test_` и каталоги `tests/` у Rust и `src/test` у JVM, каталог `testdata` и файлы `.mjs` ему неизвестны.

### Осложнение

Правка панели дашборда, где вся проверка живёт в node-стенде, каждый раз упирается в ворота, и автор гасит их пометкой «Исключение: тесты», хотя тесты есть и красные на старом коде. Пометка обесценивается: по ней не отличить честную правку от бестестовой.

### Вопрос

Считать тестом любой файл под `testdata/`, только стенды `.mjs` под ним, или сверять по go-файлу, который читает эти данные?

### Гипотеза

Ветка, чьи тесты лежат в стенде под `testdata/`, проходит ворота тестов без пометки исключения.
