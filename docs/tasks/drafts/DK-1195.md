# DK-1195: Модуль за порогом размера режется по предмету, тест едет за своим файлом

записан 2026-09-27
приоритет: средний

## Черновик

### Ситуация

2026-09-27, разбор развилки исполнителя DK-1194 об имени файла теста. Якорь STYLEGUIDE («Раскладка тестов») просит `<модуль>_test.go` рядом с модулем. В пакете tools/dashboard из 82 файлов тестов 38 названы по предмету без одноимённого модуля (chatdeath_test.go, chatbusy_test.go, chatblank_test.go). Модули при этом огромны: chats.go 4323 строки, sessions.go 3438, smoke.go 2373, tasks.go 1386. Порог размера модуля в STYLEGUIDE и ARCHITECTURE не записан, есть только граница sh в сотую строку (DK-139.2).

### Осложнение

Тесты по предмету выросли как обход нечитаемого одного файла тестов на огромный модуль. Записанное правило и код расходятся, исполнитель по ядру правил останавливается на развилке к человеку, конвейер ждёт. Человек решил 2026-09-27: DK-1194 идёт строго по якорю, а корень чинится правилом о размере.

### Вопрос

Порог строк на файл go и python, за которым модуль режется на файлы одного пакета по предмету. Считать ли порогом находку доктора или только правилом стиля. Судьба 38 тестов по предмету: переезд к своим файлам после нарезки модулей той же задачей или отдельной.

### Гипотеза

STYLEGUIDE несёт порог размера файла и правило нарезки по предмету внутри пакета, тест лежит рядом со своим файлом под именем `<файл>_test.go`, доктор называет файлы за порогом находкой. Нарезка chats.go и sessions.go идёт своей задачей после утверждения порога.
