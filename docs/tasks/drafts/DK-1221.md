# DK-1221: Причина закрытого замечания ревью правится командой taskctl review

записан 2026-09-27
приоритет: низкий

## Черновик

### Ситуация

2026-09-26, TL-014 на доске проекта dozor. Исполнитель закрыл замечание командой `taskctl review resolve TL-014 1 fixed --reason "..."` и по невнимательности набрал причину транслитом. Повторный `resolve` отказал: «замечание 1 уже закрыто». Строка резолва машинная, её разбирает код доски, и хук check-machine-lines отбивает любую правку руками. Ревьювер второго круга проверил `taskctl review --help`: команд level, add, clean, resolve, show, stats и команд чужого ревью хватает, а правки текста существующей записи нет.

### Осложнение

Транслит остался в файле задачи навсегда, и это не тот язык, на котором ведётся задача. Тот же тупик ждёт любую опечатку в причине: единственный обход это правка машинной строки в обход хука, которую правила запрещают.

### Вопрос

Отдельная команда `review reword <ID> <N> "причина"` для закрытого замечания, или `resolve` с флагом `--amend`, который переписывает причину при том же исходе?

### Гипотеза

Причина закрытого замечания правится одной командой утилиты с сохранением номера, исхода и структуры строки, и хук машинных строк такую правку принимает.
