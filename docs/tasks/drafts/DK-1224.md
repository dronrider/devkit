# DK-1224: Страница шлёт запросы первого ряда уже из фона

записан 2026-09-28
приоритет: средний

## Черновик

### Ситуация

Разбуженный возвратом круг проверяет видимость на входе в `step`, а до `fetch`
доходит после ухода вкладки в фон. Между проверкой и вызовом лежит await внутри
`run`, и под голодом event loop он растягивается за сотню миллисекунд.

Замер молчания скрытой вкладки поймал это фактом на десяти ядрах под load 28-46,
«после второго ухода 4 при круге ухода 5 и верхнем круге 5». Один красный прогон
из 28 на итоговом коде DK-1184, там же разбор.

Трафика тут немного, но инвариант DK-986 «скрытая вкладка ничего не спрашивает»
ломается, и этот же красный прогон способен отбить слияние. Смотреть в сторону
проверки видимости перед самим запросом, а не только на входе в круг. Держать в
уме сторонние вызовы api из потока уведомлений, `boardEcho` зовёт доску по
событию, и глухая отмена всякого чтения из фона задела бы его.
