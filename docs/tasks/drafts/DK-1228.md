# DK-1228: Тик поднимает оболочку цели при живом чате, который ждёт субагента

записан 2026-09-29
приоритет: высокий

## Черновик

### Ситуация

Цель DK-1084 по решению человека 2026-09-28 ведёт сессия живого чата cb85dc0e. Запись реестра `~/.devkit/goals` стоит с carrier = chat. Ночью 2026-09-29 тик `devkitctl watch` дважды поднял оболочку goal-run той же цели, в 00:02 и в 01:45. Строка сторожка в 01:45:25 звучит так.

```
простой 48м, носитель мёртв: сессии cb85dc0e на машине нет; цикл поднят оболочкой, попытка 1 из 3
```

Сессия при этом жила. С 00:41 до 01:46 у неё шёл субагент-исполнитель DK-1218 (agents.log, работа a4fbcba245979b1bd), рядом висели два фоновых ожидания в Bash. В 01:46:15 она сама позвала `taskctl review show`. Живость в `session_alive` из watch.py меряется свежестью транскрипта сессии, порог SESSION_LIVE 12 минут. Пока диспетчер ждёт субагента или долгий Bash, транскрипт родительской сессии не пишется. За час такого ожидания сессия становится «мёртвой». Простой цели тик берёт по строкам журнала цикла. Чат на долгой работе исполнителя их не кладёт, и оба порога сходятся на одном ожидании.

### Осложнение

У живой цели появляется второй носитель. Виток оболочки первым шагом зовёт гейт бюджета, а тот перезаписывает запись реестра сессией витка (черновик DK-1226). Виток, который это знает, тратит заход на разбор и гасит себя стоп-маркером. Стоп идёт с уведомлением человеку ночью. Оба ночных витка кончились так, по одному уведомлению каждый. Попыток у тика три, и при следующем долгом исполнителе подъём повторится. Работу чата виток не перебил, потому что прочитал реестр раньше гейта.

### Вопрос

Чем мерить живость сессии, которая ждёт субагента. Кандидатов четыре. Свежесть транскриптов её субагентов в каталоге сессии. Живые записи её работ в agents.log без события «конец». Фоновые выводы `tasks/*.output` под каталогом сессии. Сам процесс claude, найденный по реестру чатов. Второй вопрос отдельный. Стоит ли считать простой цели ещё и по этапам задач цели (`agentctl stage`), помимо строк журнала цикла.

### Гипотеза

Тик не поднимает оболочку, пока сессия чата, записанная носителем цели, ведёт субагента или держит фоновую работу. В журнале сторожка такая цель называется «носитель жив, ждёт субагента».
