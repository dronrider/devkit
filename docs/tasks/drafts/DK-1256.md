# DK-1256: Дверь чата цели не узнаёт цикл, поднятый руками ключом --foreground

записан 2026-09-30
приоритет: средний

## Черновик

### Ситуация

Признак идущего цикла у двери чата цели стоит на работе с видом tmux.
Функция goalShell в static/app.js спрашивает kind goal, via tmux и пустой
признак подъёма дашбордом. Так узнаётся оболочка goal-run в своей
tmux-сессии goal-<ID>.

Цикл, поднятый человеком из терминала ключом --foreground, своего окна не
заводит. В works он приходит другой дорогой, из реестра целей, с видом
registry. Сессию витка там называет тот же замок оболочки, место
откомментировано в board.go:531. Вид registry дверь не берёт, и при мёртвом
между ходами витке она уходит дорогой задачи. Человек получает вторую сессию
рядом с идущим циклом.

Ущерб узкий. Кнопку запуска держит своя проверка замка lockAlive, и второй
цикл она рядом не поднимает. Страдает одна дверь чата и только в редкой
раскладке: цикл ведут руками из терминала, а разговаривать с ним идут через
дашборд. Ревью DK-1009 назвало это остаточным и третьего круга по нему гнать
не стало.

Чинится расширением признака: вид registry с непустой сессией витка это та же
идущая оболочка. Проверить стендом poc_goalchat.mjs пятым случаем.
