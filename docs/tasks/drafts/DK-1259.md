# DK-1259: Тик зовёт shipctl merge на строку in-progress каждые пять минут

записан 2026-09-30
приоритет: средний

## Черновик

### Ситуация

Ситуация: у DK-1072 в «Ходе работы» с 23:41 до 00:17 легло пятнадцать строк «Слияние: shipctl merge» с шагом в пять минут, а строка доски показала «этап: слияние, круг 62». Ветка задачи при этом была пуста или в разработке, сливать было нечего.
Осложнение: запись этапа ложится в файл задачи в основном чекауте, и на живой строке она хоронит настоящие этапы под шумом; в чекауте остался файл .devkit/merge-queue.json.lock.
Вопрос: кто зовёт merge по тику на строку, которая не в Check и не в очереди выката, и почему зов оставляет этап в ходе работы, ничего не слив?
Гипотеза: разлив очереди (ship --drain на тике devkitctl watch) берёт строку по устаревшему состоянию очереди слияния, а хук записи этапов пишет «слияние» на любой запуск shipctl merge, не сверяясь с исходом.
