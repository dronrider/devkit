# DK-1263: agentctl: съёмка квоты протекает tmux-сессиями при гибели по потолку

записан 2026-10-01
приоритет: высокий

## Черновик

### Ситуация

Тик devkitctl watch зовёт agentctl quota refresh --all --if-stale каждые ~10 минут. Съёмка поднимает одноразовую tmux-сессию agentctl-usage-<pid> с клиентом claude. После снимка панели /usage сессию убивает отложенный kill-session. Если съёмка виснет, тик снимает agentctl жёстким сигналом по потолку времени. Отложенный kill-session при этом не выполняется, и сессия с клиентом остаётся жить.

Живой случай 01.10.2026. Сессии копились с вечера 30.09 каждые ~10 минут. К тринадцати часам накопилось 82 штуки, каждая держит ~250 МБ, вместе 19.7 ГБ из 32 ГБ. Свободной памяти оставалось ~100 МБ, машина ушла в своп. Голод вешал следующую съёмку, и ком накатывался сам.

Признак повтора простой. В tmux ls опять растут agentctl-usage-*, а свежих строк agentctl quota в .devkit/log нет. Висящая съёмка не дописывает свою строку журнала.

Фикс видится в вычистке осиротевших сессий перед подъёмом новой. Имя agentctl-usage-<pid> отличает живого владельца от мёртвого. Другой путь это перенос убийства сессии туда, где оно переживает смерть самого agentctl.
