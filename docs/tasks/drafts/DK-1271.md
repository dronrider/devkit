# DK-1271: дашборд молча поднимает чат мимо харнеса при сбое подспроса раскладки

записан 2026-10-01
приоритет: средний

## Черновик

### Ситуация

Пользователь поднял из дашборда новый чат с моделью второй подписки
(glm-5.3). Подспрос раскладки харнесов в тот момент вернул пустоту, дашборд
опаздывал за экраном, в логе подряд идут строки про не поспевший опрос досок.
Запуск чата (chatCmd, tools/dashboard/chats.go) при пустой раскладке собирает
команду без agentctl exec, то есть без каталога конфигурации подписки. Клиент
поднялся на дефолтном профиле первой подписки с истёкшим входом и на каждую
реплику ответил «Login expired». Сторож чата увидел «нужен вход» и открыл
окно авторизации выключенной подписки.

### Осложнение

Пустой ответ раскладки не запоминается (harnesses.go, harnessTTL), в спокойную
минуту запуск работает. Оттого сбой редкий и не ловится повтором, а урон
настоящий. Чат чужой подписки молчит login-ошибкой, человек видит отказ там,
где ждал ответ модели.

### Вопрос

Как должен вести себя запуск чата при пустой раскладке. Отказаться с внятной
ошибкой, подождать свежего ответа или взять дефолтный харнес машины. Отдельно
стоит решить, должен ли сторож «нужен вход» смотреть, чья подписка просит
вход, прежде чем открывать окно авторизации.
