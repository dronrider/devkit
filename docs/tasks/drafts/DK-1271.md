# DK-1271: дашборд поднимает чат подписки мимо её окружения, если serve перезапущен без харнеса

записан 2026-10-01
приоритет: высокий

## Черновик

### Ситуация

Машинная подписка по умолчанию это glm, её каталог конфигурации живёт в
харнесе. Запуск чата (chatCmd, tools/dashboard/chats.go) для харнеса по
умолчанию не заворачивает клиента в agentctl exec и рассчитывает на пары
окружения, унаследованные от самого serve. Два вечера подряд новые чаты
поднимались голым клиентом на профиле первой подписки с истёкшим входом,
отвечали «Login expired», и сторож чата открывал окно авторизации выключенной
подписки. Причиной был перезапуск serve без харнес-окружения.

С 02.10 serve держит launchd-агент ru.devkit.dashboard, и поломка стала
структурной. Генератор агента (plist_text, tools/devkitctl/dashboard.py)
кладёт в ProgramArguments только бинар с serve и PATH, без харнес-пар. Каждый
рестарт агента поднимает serve голым, сколько бы раз его ни оборачивали руками.
Сегодня plist вручную обёрнут в agentctl exec --harness glm-code, и ломается
обёртка при первой же перегенерации агента.

### Осложнение

Запуск без обвязки выглядит штатным и в спокойную минуту не отличается
ничем, пока serve несёт окружение харнеса. Чаты, поднятые раньше, продолжают
работать и маскируют поломку, а ловится она только по последствиям в чужом
чате. Ручная правка plist это лекарство до первого devkitctl, который
перегенерит агента по своему шаблону.

### Вопрос

Должен ли запуск чата подписки по умолчанию идти той же обвязкой agentctl
exec, что и чужой подписке, чтобы путь не зависел от окружения serve. Или
serve обязан проверять на старте пары окружения харнеса и отказываться
подниматься без них. Генератору launchd-агента нужен тот же ответ, иначе
ручная обёртка живёт до перегенерации. Отдельно стоит решить, должен ли
сторож «нужен вход» смотреть, чья подписка просит вход, прежде чем открывать
окно авторизации.
