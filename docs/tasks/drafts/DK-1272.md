# DK-1272: гибридная лестница ярусов получает верх у routerai

записан 2026-10-01
приоритет: высокий

## Черновик

### Ситуация

Разговор 2026-10-01, нужен провайдер верхних ярусов лестницы моделей. Каталог routerai.ru разобран через публичный /api/v1/models, в нём 538 моделей. Поддержка Anthropic-совместимого /v1/messages подтверждена документацией. API отвечает с машины без VPN.

Цены за 1M вход/выход/кеш в рублях. У claude-sonnet-5.5 это 217/1086/21.7, у claude-opus-5.5 будет 434/2173/21.7.

Бесплатного текстового яруса нет. Нулевая цена стоит у 40 моделей, и почти все они медиа-генерация или реранкеры. Единственная текстовая stealth/space-bunny-alpha анонимна и нестабильна. Доступность моделей от баланса не зависит. При пустом балансе платный вызов падает с ошибкой 402.

Смок 2026-10-01 прошёл, ключ лежит в secretctl под именем routerai-token. Все четыре ступени лестницы ответили в формате Anthropic Messages с заголовком Authorization Bearer. Base URL для харнеса это https://routerai.ru/api, клиент докладывает /v1/messages сам. Развилка про base URL из «Вопроса» снята этим смоком. Размышляющие модели отдают блоки thinking и text, бюджет max_tokens в 16 токенов размышление съедает целиком.

### Осложнение

Лестница glm-code уже гетерогенная, это поправил обход груминга. В машинном слое стоит pro = "claude-code:opus", но действующей подписки claude-code нет, и появится ли она, неизвестно. Опираться на это назначение нельзя. Вырожден ярус max, в glm-code.toml он сложен в glm-5.3. Ревью дизайна и приёмка LLD сидят на base-модели. У подписки z.ai моделей выше нет.

Факты обхода 2026-10-01, чтобы исполнитель не проверял их второй раз. Секция [quota] в профиле обязательна по наличию, но может стоять пустой, это штатно выключенный корректор (validateProfile, harness.go 305). Для платного баланса есть готовая механика budget_based с бюджетом в машинной секции (DK-033), но скрипт съёмщика в профиль кладётся только после живой проверки эндпоинта, прецедент DK-181. У доктора болванка второй подписки прибита к имени glm-code (ALT_SUB_HARNESS, devkitctl.py 519), без складывания алиасов DK-751 субагент в сессии routerai уйдёт на алиас первой лестницы. Токен харнеса лежит в settings.json его каталога по образцу z.ai, механики секрета в профиле нет. Соседние строки: контроль трат это территория DK-365 и её ребёнка DK-182, предупреждение раньше отказа это DK-501, задача ссылается на них и не дублирует.

Детект профиля routerai обязан стоять пустым. Клиент тот же claude, детект дал бы пересечение с claude-code, и харнес выбирает только явный DEVKIT_HARNESS от run и exec. Сам routerai встаёт в enabled машинного слоя, это калитка раскладки правил, хуков и скиллов. Дока DK-090 и README devkitctl пишут про вторую подписку в единственном числе, третьему харнесу нужна правка на множественное, она в скоупе задачи.

### Вопрос

Первая развилка это точный base URL профиля, с /v1 или без, её решает живой смок. Вторая про секцию [quota]: у сервиса нет квотных окон, оплата идёт с баланса. Третья про кандидата на pro, claude-sonnet-5.5 или gpt-6.1-sol с кешем вдвое дешевле. Качество спорных мест проверяется стендом prompt-test.

### Гипотеза

Routerai встаёт третьей самостоятельной подпиской со своей полной лестницей ярусов, предмет закрыт человеком 2026-10-01. Профиль собирается из каталога сервиса: mini это deepseek-v4-flash за 5.2 руб, base это glm-5.3 из того же каталога, не из подписки z.ai, pro это claude-sonnet-5.5, max это claude-opus-5.5. Кандидатов верха подтверждает стенд prompt-test. Сессия на routerai живёт целиком на токенах сервиса, пересечений с лестницами glm-code и claude-code нет, они остаются как есть. По умолчанию машина остаётся на glm-code, routerai выбирается явно. Входное условие одно, ключ routerai в secretctl под именем routerai-token.
