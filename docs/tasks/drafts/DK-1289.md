# DK-1289: доктор принимает конфиг свежести квоты за старый снимок

записан 2026-10-02
приоритет: средний

## Черновик

### Ситуация

Порог свежести снимков живёт в ~/.devkit/quota.local, его читает quotaconf.
По тому же пути раньше лежал одиночный снимок квоты, пока снимки не переехали
в директорию quota по файлу на харнес. Находка check_quota в devkitctl
смотрит только на существование файла. Рядом с quota/<харнес>.local она
зовёт quota.local старым снимком и советует убрать его руками. 02.10 файл на
машине пользователя держал строку stale = 10, поставленную под DK-1285, и
доктор советовал удалить живую настройку.

### Осложнение

На машине без quota/<харнес>.local доктор с --fix не советует, а делает:
legacy.replace(moved) переименовывает конфиг в снимок харнеса, настройка
свежести теряется молча. Агент в авто-режиме, прогнавший доктора, выполнит
совет rm без сомнений. Временной защитой на машине пользователя файл закрыт
флагом uchg, флаг снимается руками и мешает правке настройки.

### Вопрос

Доктор обязан отличать конфиг от снимка. Снимок узнаётся разбором содержимого
парсером снимка, конфиг это строки настроек вроде stale. Либо конфиг уезжает
на своё имя, а старый путь остаётся только легаси-снимком. Совет rm про файл,
в котором живая настройка, печататься не должен.

### Гипотеза

Находка разбирает содержимое quota.local перед советом. Строки настроек
quotaconf исключают файл из легаси-снимков целиком, разбор снимка в нём
пишется отдельной находкой с точным именем проблемы. Переименование конфига
на своё имя закрывает коллизию насовсем, но требует переезда настройки на
машинах, его выбирает развилка на груминге.

### Связи

- DK-1285: настройка stale, ради которой файл живёт
- DK-090: раскладка харнесов доктором
