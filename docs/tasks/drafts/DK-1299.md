# DK-1299: съёмщик квоты claude-code поднимает клиента на чужой подписке

записан 2026-10-05
приоритет: средний

## Черновик

### Ситуация

05.10.2026, `agentctl quota refresh` из окна конвейера task-DK-1292 (харнес glm).
Отказ «панель /usage не подала ни одного знакомого слова за 45s», снимок остался
от 30.09. Кадр панели лежит в /Users/rider/.devkit/quota/claude-code.pane.txt.
Клиент на кадре это glm-5.3 с биллингом API (заголовок «API Usage Billing»),
поднялся на конфиге второй подписки. snapUsagePanel (tools/agentctl/usage.go:540)
зовёт голый `claude` из PATH в одноразовой tmux-сессии. Окружение харнеса клиенту
не раскладывается. Каталог подъёма panelDir выбирает по профилю, а
CLAUDE_CONFIG_DIR достаётся сессии от того, кто позвал.

### Осложнение

Снимок claude-code не обновляется. Корректор вердиктов видит протухшие проценты
и не поднимает ярус («вверх корректор не двинет»). Вердикты pick едут по кешу
возрастом в дни. На машине, где окна в основном glm, съём ломается каждый раз.

### Вопрос

Раскладывать окружение самому съёмщику по профилю из quotaSpec или поднимать
клиента через agentctl exec --harness, где пары окружения уже кладутся?

### Гипотеза

`agentctl quota refresh` из любого окна снимает панель той подписки, чьё имя
названо в команде, и слов «протух» в вердикте больше нет.
