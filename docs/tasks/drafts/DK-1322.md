# DK-1322: исход очереди слияний доводится до исполнителя

записан 2026-10-08
приоритет: высокий

## Черновик

### Ситуация

Файл .devkit/merge-queue.json восемь октября держит семь снятых строк. DK-1072 стоит снятой с 30 сентября, причина «конфликт ребейза, разводить руками». DK-1286 и DK-1301 сняты после трёх повторов, краснота вне диффа go:obeycheck и go:dashboard. DK-1292 снята 5 октября с текстом «разработки не было, ветка без коммитов, запущу исполнителя». Неготовые строки наклейки не оставляют вовсе. Разлив каждый тик печатает причину неготовности в хвост отчёта и идёт дальше. В очередь строку возвращает только ручной запуск shipctl queue --free.

### Осложнение

Снятая строка ждёт рук без срока, старейшая восемь дней. Обещание «запущу исполнителя» из текста снятия нигде не исполняется. Автор получает уведомление о снятии, но задания починить ветку не получает, и строка остаётся мёртвым грузом.

### Вопрос

Куда уходит исход. Поручение в файл задачи, заказ через taskctl ask, подъём исполнителя на ветку? Конфликт ребейза механика не разведёт, его сразу человеку или дежурному агенту?

### Гипотеза

Каждый исход разлива, который не слияние и не временный повтор, в течение одного тика становится поручением исполнителю. Строка не стоит снятой дольше дня без разбора, и очередь не повторяет один отказ бесконечно.
