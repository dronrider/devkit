# DK-1345: check-symbols отбивает длинное тире в машинных строках замечаний ревью

записан 2026-10-10
приоритет: средний

## Черновик

### Ситуация

Препятствие из работы над DK-1324: коммит файлов задачи с добавленными строками замечаний падал на длинном тире в самих строках, их пишет taskctl review add, штатной перезаписи тире в taskctl нет. Исполнитель обошёл рубеж коммитом через git commit --no-verify на двух docs(tasks)-коммитах, само тире не переписывал.

Что мешает: машинные строки замечаний и уровней ревью сами несут длинное тире, рубеж символов их отбивает, и каждый коммит файла задачи с таким замечанием требует обхода хуком --no-verify, который глушит и остальные проверки. Дальше по конвейеру таких строк только больше.

Гипотеза: тире переписывается в момент записи строки (taskctl review add и соседние команды пишут дефис вместо тире), либо check-symbols учит машинные строки и не судит их состав. Решить на месте: хватит ли перезаписи в taskctl, чтобы рубеж не трогать.
