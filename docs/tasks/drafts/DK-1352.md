# DK-1352: plan set отбивает перезапись своего плана как чужой заход

записан 2026-10-11
приоритет: средний

## Черновик

### Ситуация

План сессии лежит в ~/.devkit/plans и перекладывается командой agentctl plan set. Совпавшие пункты нового набора сохраняют свои состояния, а planCarry переносит отметки с прошлого захода.

### Осложнение

Набор без ни одного совпадения получает отказ «это чужой заход» и требует ключа --force. Отказ одинаков для чужого файла и для своей же правки, где пункты переписаны новыми словами. Переложить план с --force можно, но ключ гасит защиту и от настоящего чужого захода. 2026-10-11 в DK-1349 отказ пришёл на плане, переписанном после сжатия контекста. Сворачивание пунктов с литеральными \n записано отдельно в DK-1336, и та же поломка ещё видна в plan show одним пунктом «Чтение скилла и пар\nПроход по файлам\nСлед вычитки».

### Вопрос

Чем отличить свою правку плана новыми словами от чужого захода?

### Гипотеза

plan set от той же метки сессии перекладывает план без --force, а ключ остаётся для чужого набора.
