## Ситуация

Доработка DK-1349 шла веткой в рабочем дереве рядом с проектом, дерево завёл shipctl start. Заход исполнителя длился больше двух часов, рядом в том же репозитории работала другая сессия доски.

## Осложнение

Дважды посреди захода дерево и ветка исчезали: git worktree list их не показывал, ref ветки пропадал. git worktree remove никто из захода не запускал. Субагент восстанавливал дерево руками через git worktree add -b и терял незакоммиченное чтение. Кто сносит дерево, неизвестно. Под подозрением чистка за чужим слиянием и общий обход git worktree.

## Вопрос

Что сносит рабочее дерево задачи посреди работы, и как удержать его до конца захода?

## Гипотеза

Дерево сносит shipctl merge чужой задачи либо git worktree prune за фоновой работой git. Лечится сторожем живости дерева или держанием его в исключениях prune.
