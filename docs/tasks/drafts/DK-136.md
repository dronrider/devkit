# DK-136: Двусторонний чат с идущей сессией агента: писать в живой процесс и читать его ответ. Витки поднимаются claude -p (goal-run.sh), у неинтерактивного процесса входа нет, вывод буферизуется до конца сессии, а tmux-сессия принадлежит оболочке goal-run, не агенту, так что send-keys шлёт команды оболочке. Отложено на грумминге цели DK-112 (2026-08-05): переписка там решена через состояние на диске, которое подхватывает следующий виток, и для wait-human этого хватает. Живой чат нужен там, где ответ требуется прямо в идущей работе, без стопа витка. Разбирать надо механику: интерактивный клиент в своей tmux-сессии с чтением панели и send-keys (хрупко на перерисовке TUI и промптах разрешений, трогает сердце автономного режима), headless с потоковым вводом, либо что-то ещё. Смежно с DK-117 (след хода витка по ходу, а не по концу).
