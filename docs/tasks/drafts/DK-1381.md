# DK-1381: отказ decide --ask не называет ключ дописывания вариантов

записан 2026-10-14
приоритет: средний

## Черновик

### Ситуация

Развилка в файле задачи уже заведена строками раздела «Развилки», и агент
дописывает ей варианты ключом `--option` (tools/taskctl/decide.go,
decideOption). Живой случай 14.10 в DK-1379: развилка «снятие» пришла из
постановки без вариантов, `decide --ask` на неё отказал словами «уже
заведена», а подсказка `--hint` с именем развилки тоже отказала.

### Осложнение

Ни один из отказов не называет ключ `--option`, и путь дописывания вариантов
в существующую развилку приходится искать в исходниках. Без вариантов вопрос
человеку уезжает без галочек и без номеров для ответа.

### Вопрос

Должен ли отказ `--ask` по существующей развилке называть команду
дописывания вариантов?

### Гипотеза

Отказу достаточно дописать форму `decide <ID> «имя» --option "вариант"`, пока
варианты не спросили человеком.
