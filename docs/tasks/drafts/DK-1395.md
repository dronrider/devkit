## Ситуация

Очередь слияний (shipctl queue --drain) отказывает ветку строкой «в рабочем дереве незакоммиченное по файлам задачи, сначала закоммить:» (shipctl/ops.go:335). queueTry кладёт в отчёт только первую строку отказа (queue.go: skip = firstLine), поэтому список файлов из cmdoutFrame до очереди не доезжает.

## Осложнение

Для неслитой ветки taskTouchedPaths не находит коммитов задачи в main, сужение чистоты вырождается в полную чистоту main (это задокументировано в ops.go:300). Грязь при этом обычно чужая: соседняя сессия держит в общем чекауте незакоммиченную правку своей строки доски, и стоит вся очередь. Виновника по сообщению не назвать: список файлов потерян, а формулировка «по файлам задачи» зовёт коммитить того, кто ветку и так держит чистой.

## Вопрос

Как довести до очереди имя чужого грязного файла (или хоть факт, что грязь вне диффа ветки), не ломая однострочный формат причин в отчёте тика?

## Гипотеза

Пропускать список файлов отдельной строкой заметки (как делает note нагрузочного отказа), а формулировку сузить: грязь вне файлов ветки, ждёт коммита соседа. Проверка на стенде очереди из заглушек.
