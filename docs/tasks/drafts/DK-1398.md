# DK-1398: Очередь после флейка оставляет ветку с протухшей отметкой

записан 2026-10-17
приоритет: высокий

## Черновик

### Ситуация

Ситуация

Конвейер слияния идёт по порядку: ворота свежести обкатки, перебаза на main, тесты. Нагрузочный флейк на тестах кладёт ветку в хвост очереди уже перебазированной, а отметка обкатки в файле задачи продолжает указывать на дерево до перебазы. Каждый следующий заход ворота свежести видят между отметкой и HEAD всю переехавшую историю main и отказывают «после прогона в ветку приехал код», хотя этот код привёз сам конвейер своим же ребейзом.

Осложнение

Цикл не размыкается сам. Отказ ворот свежести не тратит повторов ветки (счётчик стоит на 1 из 3 с вечера), до тестов дело больше не доходит, ветка молчит в очереди бессрочно. Живой случай ночи 17.10: dk-1359 между отметкой и HEAD 28 коммитов, dk-828 32, в обоих чужой код main. Соседняя DK-1390 тем временем снята 3 из 3 нагрузочными падениями и до слияния не доехала. Итог: после каждого флейка ветке нужна ручная перебаза и переобкатка, на шумной машине это каждая ночь.

Вопрос

Кто обновляет отметку после перебазы, которую сделал сам конвейер: свежесть после ребейза считает годной, конвейер переставляет отметку сам, или обкатка прогоняется заново на перебазированном дереве?

Гипотеза

Судить свежесть содержимым, а не линией коммитов: обкатка зелёная на дереве T, дифф ветки к текущему main совпадает с диффом на дереве T, значит перебаза ничего в задачу не привезла и отметка жива. Настоящий новый код в собственных коммитах ветки дифф меняет и отметку протухает как раньше. Проверка на стенде очереди из заглушек вместе с ручной перебазой как обходным путём.
