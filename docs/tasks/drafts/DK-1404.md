# DK-1404: regcheck бракует путь теста от -C и валится на go.work второго прогона

записан 2026-10-17
приоритет: средний

## Черновик

### Ситуация

при прогоне регрессионного теста из дерева задачи (DK-1399) путь тестового
файла передан относительно -C, regcheck ответил «тестовый файл chat_test.go
не найден в рабочем дереве», принят оказался только путь от корня
репозитория в --tests. Второй прогон по internal/chat упал на «directory
prefix . does not contain modules», хотя README решением называет один -C;
обошёл env GOWORK=off в команде теста.

Вопрос: неужели оба рубежа должны обходиться руками, или regcheck примет
относительный путь и приглушит go.work сам. Гипотеза: путь теста стоит
резолвить от корня дерева -C, а go.work отключать на время второго прогона.
