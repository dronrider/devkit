# DK-1410: утилиты devkit теряют repo-local core.sshCommand и падают на fetch

записан 2026-10-18
приоритет: средний

## Черновик

### Ситуация

Ситуация: доступ репозитория devkit в origin едет на отдельном ключе и отдельном known_hosts, названных локальным core.sshCommand. Обёртка gitrun утилит ставит свою переменную GIT_SSH_COMMAND и перекрывает настройку репозитория.
Осложнение: с вечера 17 октября taskctl push и shipctl fetch отказывают с «Host key verification failed», хотя тот же git из шелла проходит. Виноват не доступ, а потерянные опции ssh.
Вопрос: должна ли обёртка gitrun начинать с core.sshCommand репозитория, а не с голого ssh.
Гипотеза: gitrun читает core.sshCommand корня и подставляет её базой, наследование переменной из окружения остаётся приоритетнее.
