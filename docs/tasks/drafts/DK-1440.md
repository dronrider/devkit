# DK-1440: plan done читает файл задачи из чекаута сессии, а не из дерева задачи

записан 2026-10-24
приоритет: средний

## Черновик

### Ситуация

Ситуация. У DK-1438 (LLD, дерево /Users/rider/projects/devkit-dk-1438) ревьювер записал раздел «Ревью» в файл задачи в дереве ветки и попробовал закрыть этапы плана «сценарий» и «ревью». agentctl plan done отказал. planTraceCtx в tools/agentctl/planbuild.go читает docs/tasks/<ID>.md из дерева вызова команды, а конвейерная сессия живёт в чекауте main, где этих разделов до слияния нет. scenarioGate в tools/shipctl/advice.go читает тот же файл в дереве ветки, поэтому проверка слияния раздел видит, а проверка этапа плана нет.

Осложнение. По правилам ревью закрывается до слияния, а здесь этапы плана закрываются только после слияния, когда разделы приедут в main. Ревьювер потратил часть хода на поиск причины (60 ходов) и порекомендовал завести строку доски. То же повторится на каждой LLD-задаче с деревом.

Вопрос. Откуда проверке этапа плана брать файл задачи: из дерева задачи, как у проверки слияния, из ветки git-заметкой на HEAD или из чекаута сессии с закрытием этапов после слияния. Если менять место чтения, надо ли выровнять его у обеих проверок сразу.
