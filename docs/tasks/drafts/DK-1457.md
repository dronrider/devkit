# DK-1457: review level из основного чекаута пишет уровень с sha чужого дерева

записан 2026-10-25
приоритет: средний

## Черновик

### Ситуация

25.10.2026 ревьювер DK-1455 (круг 1) вызвал taskctl review level из основного
чекаута при неслитой ветке задачи. Команда молча записала строку уровня в
копию файла задачи с sha HEAD основного дерева («до 118b7bc»), хотя ревью
шло по ветке с sha 8a1dc90. Та же команда review add на том же входе
отказывает и требует дерево задачи. Причина в коде: cmdReviewLevel берёт
headSha(reviewCodeDir(root, start)), в не-корп репо это корень основного
чекаута.

### Осложнение

Ошибочная строка уровня расходится с деревом ревью, а ворота слияния читают
уровень вместе с sha. Штатного способа задать sha у команды нет, и ревьюверу
пришлось править руками: снимать строку из основного чекаута и класть
правильную в ветку отдельным коммитом. Каждый ревьювер, позвавший level не
из дерева задачи, оставляет за собой ложный след.

### Вопрос

Симметрия с add: level из основного чекаута при неслитой ветке отказывает
тем же текстом, или команда принимает явный sha ключом?

### Гипотеза

Пользователь хочет симметрию проверок level и add: без дерева задачи level
отказывает и называет правильный вход. Ручная правка строки уровня не
нужна вовсе.
