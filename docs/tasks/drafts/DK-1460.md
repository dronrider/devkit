# DK-1460: Эскалация дежурному пишет в файл задачи без коммита и блокирует слияние

записан 2026-10-25
приоритет: средний

## Черновик

### Ситуация

Ситуация: 2026-10-24 и 25, DK-489. Тик devkitctl watch звал shipctl merge каждые пять минут, попытки отказывали на занятой очереди, каждая оставляла след, а эскалации дежурному дописывали строки в раздел «Ход работы» файла задачи в основном чекауте. Записи оставались незакоммиченными.

Осложнение: merge отказывает на грязном файле задачи («в рабочем дереве незакоммиченное по файлам задачи, сначала закоммить»), retry не может пройти, исход выглядит неизвестным, дежурный разбирает и коммитит журнал руками. То же копится у DK-1432: строка эскалации лежит незакоммиченной прямо сейчас.

Вопрос: кто и когда коммитит журнальные записи неудач и эскалаций в файле задачи основного чекаута?

Гипотеза: записи этапа и эскалаций ложатся коммитом доски сразу за записью, либо merge поглощает журнальную грязь файла своей задачи; тогда retry не блокируется собственным следом.

Дополнение 26.10.2026: механизм подтвердился в полный рост. Слияние DK-489
дошло до круга 474: каждый отказ дописывал эскалацию в файл задачи, грязная
строка отбивала следующий круг по вороту дерева, и цикл жил сам. Журнал
уходил коммитом трижды за сутки (дважды дежурным утром, затем разбором в
14:12), и только после чистого коммита круг перестал отбиваться по дереву.
