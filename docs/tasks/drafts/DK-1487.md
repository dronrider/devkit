# DK-1487: Круг слияния умирает от сетевой флюктуры без второй попытки

записан 2026-10-27
приоритет: средний

## Черновик

записан 2026-10-27

## Черновик

### Ситуация

2026-10-27 круг слияния DK-1464 весь день спотыкается о сеть: git ls-remote и git fetch в syncDeployTag падают с «Could not resolve hostname github.com», след в .devkit/cmdout (11:02, 13:41, 13:47, 13:54, 14:25, 14:27), и каждый отказ уезжает эскалацией дежурному. В соседние минуты интерактивная сессия до origin достучится: сеть машины ложится окнами, а не насовсем.

### Осложнение

Круг умирает с первой сетевой неудачи, второй попытки в shipctl нет. Короткий миг DNS оборачивается кругом впустую, эскалацией и разбором дежурного, хотя через минуту тот же круг проходит. Состояние тега deployed при отказе ls-remote по построению остаётся неизвестным, и дежурный разбирает его вручную каждый раз заново.

### Вопрос

Держать ли вторую попытку сетевых команд круга (ls-remote, fetch, push) с короткой паузой внутри shipctl, или хватит нынешнего повтора круга раз в пять минут, а эскалацию научить называть сетевой отказ своими словами?

### Гипотеза

Пара попыток с паузой в несколько секунд переживает короткий миг DNS и снимает большую часть эскалаций; длинный провал всё же эскалирует, и тогда в тексте отказа должно стоять «сеть», чтобы дежурный не искал порчу там, где миг.

## DoD

Короткий миг сетевой флюктуры не роняет круг слияния и не эскалирует дежурному; при исчерпании попыток отказ называет сеть словами.
