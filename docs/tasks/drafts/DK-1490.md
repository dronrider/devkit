# DK-1490: check-tree-write держит устаревшую карту дерева после снятия очередью

записан 2026-10-27
приоритет: низкий

## Черновик

### Ситуация

На DK-1465 очередь слияний сняла рабочее дерево задачи, исполнитель после этого дописывал разбор в архив основного чекаута.

### Осложнение

Рубеж check-tree-write.py продолжал считать дерево задачи живым по устаревшей карте и отбивал допись разбора в архив; исполнитель отказался от дописки и увёз разбор строкой отчёта.

### Вопрос

Перечитывает ли рубеж карту деревьев на каждом срабатывании, и где её обновление при снятии очередью?

### Гипотеза

Карта перечитывается на каждом срабатывании хука, снятое дерево перестаёт опекаться сразу.
