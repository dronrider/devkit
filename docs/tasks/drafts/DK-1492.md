## Ситуация

В задаче WB-002 проекта watch-bot исполнитель прогнал вычитку доки
субагентом general-purpose. Определения proofread в наборе агентов для его
спавна не оказалось. Хук спавна записал этап как «разработка», вид этапа он
берёт из определения агента.

## Осложнение

Этап «вычитка» ложится в запись задачи только спавном по определению
proofread. Руками его agentctl stage не ставит. Ворота agentctl plan done
пункта «вычитка» не закрываются. Работа сделана и закоммичена, а след
прогона остался без метки этапа.

## Вопрос

Как записывать этап вычитки, когда субагент поднят не по определению
proofread? Можно научить хук спавна распознавать роль по тексту задания.
Можно добить набор агентов определением proofread для всех харнесов. Можно
дать agentctl stage явную команду записи чужого прогона.

## Гипотеза

Дешевле всего добить набор агентов определением proofread и проверить, что
хук спавна ставит по нему этап «вычитка». Распознавание роли по тексту
задания хрупко. Отдельная команда stage дублирует то, что хук делает сам.
