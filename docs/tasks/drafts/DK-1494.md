# DK-1494: Ворота вычитки недостижимы в харнесе без определения proofread

записан 2026-10-28
приоритет: средний

## Черновик

### Ситуация

Ситуация: у DK-1468 этап вычитки в agentctl plan done упёрся в отсутствие записи этапа в ~/.devkit/runs; запись кладёт хук спавна субагента по определению proofread, а в харнесе claude-glm такого определения нет.

Осложнение: ручная отметка agentctl stage запрещена кодом stageWriters, остаётся авторская строка этапа в файле задачи, ворота проходят мимо журнала. Соседняя DK-1489 о том же хуке, но с другой стороны: хук пишет proofread этапом разработки. Попутно agentctl plan done без -C слеп к файлу задачи ветки и требует звать с -C из дерева.

Вопрос: чья забота дать харнесу работающее определение proofread, генератора харнеса, doctor или правил, и ослаблять ли ворота до записи в файле задачи?

Гипотеза: определение proofread положено генерировать при подключении харнеса тем же механизмом, что и exec/review; пока его нет, ворота принимают строку этапа из файла задачи как эквивалент.
