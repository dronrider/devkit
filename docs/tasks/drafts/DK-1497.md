# DK-1497: review clean пишет SHA боковой доски вместо дерева кода

записан 2026-11-02
приоритет: средний

## Черновик

### Ситуация

При ревью ветки с боковой доской taskctl -C <дерево кода> review level берёт правильный HEAD кода. Следующий taskctl -C <то же дерево> review clean записывает в каноническую голову вердикта HEAD репозитория доски. Расхождение воспроизведено 2026-11-02 и проверено через git rev-parse HEAD обоих репозиториев.

В tools/taskctl/review.go функция cmdReviewClean вызывает headSha(root), где root после перенаправления указывает на доску. cmdReviewLevel также получает начальный путь вызова start.

### Осложнение

Чистый вердикт привязывается к другому репозиторию. Проверка повторного круга через cleanVerdictSameCode сравнивает SHA из канонической головы, поэтому текстовое пояснение с правильным SHA не исправляет машинную привязку. Пользователь получает формально записанное ревью с неверным адресом кода.

### Вопрос

Как передавать исходное дерево кода в clean и сравнение повторного круга, сохранив работу обычной доски и git-заметок без доски?

### Гипотеза

В боковом контуре review clean использует HEAD проверенного дерева кода, как review level. Повторный круг сравнивает код в том же репозитории. Желаемый результат предложен агентом после воспроизведения.

## Контекст обсуждения

Пользователь просил ревью ветки проекта. Ошибка обнаружена при сохранении результата; реализацию taskctl в этом заходе не меняли. В записи исходной задачи явно отмечены неверная служебная привязка и правильный SHA кода.
