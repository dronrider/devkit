# DK-1509: obeycheck в свежем дереве задачи не находит профиль харнеса

записан 2026-10-30
приоритет: средний

## Черновик

### Ситуация
30.10.2026 в дереве задачи dk-1442 исполнитель гнал стенд obeycheck (сценарий 69). Стенд отказал словами «нет профиля харнеса kit/harness/glm-code-2.toml». Профиль лежит в основном чекауте незакоммиченным машинным файлом. Свежий git worktree его не получает.
### Осложнение
Стенды сценариев по правилам гоняются в дереве задачи. Отказ повторяется на каждой задаче, чей сценарий задевает obeycheck. При закрытии DK-1442 обошлись копированием профиля руками, в коммиты оно не входит.
### Вопрос
Как профиль машинного харнеса должен попадать в свежее дерево задачи. Варианты. Искать его в общем каталоге гита, тянуть из основного чекаута или давать стенду флаг с путём.
### Гипотеза
obeycheck ищет профиль только по корню дерева. Общий каталог гита лежит рядом с основным чекаутом. Поиск сначала в корне дерева, потом в общем каталоге гита снимает обход без коммита машинного файла.
