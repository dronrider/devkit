# DK-1519: regcheck на ветке ищет базу в main и ломается о перенос теста

записан 2026-10-30
приоритет: средний

## Черновик

### Ситуация

Ревьювер DK-1226 доказывал красноту regcheck-прогонами на границах коммитов ветки: правка и тест в одном пакете, тестовый файл переносился из другого пакета, и sessions.SessionLive в базе main не существует. Автопоиск базы regcheck берёт main, сборка теста падает с undefined, краснота не доказывается; обход это явные --base на коммитах самой ветки. Случай в DK-1226 2026-10-30.
На всякой ветке, где правка с тестом приезжает переносом через пакеты, ревьювер руками ищет границы коммитов, автопоиск бесполезен.
Должен ли regcheck сам откатываться к базе «коммит перед правкой внутри ветки», когда сборка теста в main падает?
Гипотеза: сначала пробовать main, при ошибке сборки брать первый коммит правки из истории ветки и подсказывать найденную базу ревьюверу.
