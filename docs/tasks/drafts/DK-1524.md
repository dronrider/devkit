# DK-1524: Квитанция снятия черновика называет временный ID
замок: unlocked
источник: thought
тип: task

записан 2026-10-31
приоритет: средний

## Черновик

### Ситуация

На независимой приёмке DK-1522 30 октября 2026 года замечена неверная
квитанция исхода `drop`. Сравнение установленного taskctl f274f52611f6
с тестовой сборкой исходников e3955990794f воспроизвело ту же ошибку.
В каждом временном проекте созданы TR-001 и соседний TR-002. Для TR-001
принята карточка p1 с исходом `drop`. Ответ содержит `source: TR-001`,
но текст результата сообщает: «TR-003 удалён как протухший».

### Осложнение

TR-003 существовал только во временной проекции. Исходный TR-001 сохранён
в истории; соседний TR-002 и доска не изменились. Неверный ID сохраняется
в карточке и квитанции, точный повтор возвращает его с `repeated=true`.
По сообщению нельзя понять, какую запись сняли и сохранился ли исходный
текст. Данных об удалении настоящей соседней записи нет.

### Вопрос

Как формировать результат операции по исходной записи, не перенося в него
ID временной проекции? Нужно проверить остальные исходы карточек на тот же
перенос. Исправление старых сохранённых квитанций с пользователем не обсуждали.

### Гипотеза

Агент предполагает, что квитанция называет исходный черновик и его фактическое
состояние. Если текст остался в истории, сообщение прямо говорит об этом.

## Контекст обсуждения

Причина подтверждена сравнительным CLI-стендом. `stageOutcome` создаёт
проекцию исходной записи с очередным ID и передаёт её в `cmdDraftDrop`.
Возвращённый текст сохраняется в `stagedResult.Text`, затем в `result`
и `receipts` исходной записи. В проверенных ответах поля `source`, `proposal`,
`revision`, `outcome`, `reason` и `paths` верны; ошибочен текст `result`.
Исполнитель исходов не менялся между сравниваемыми ревизиями. Это отдельная
находка, пять исходных исправлений DK-1522 проверены независимо.

Для повтора создать два черновика. Для первого сохранить
карточку `drop`, показать её через `draft proposals ask`, принять
через `draft proposals answer` по показанному снимку и прочитать точный
повтор. Сверить оба файла, доску и список истории до и после операции.

Полные входы и выводы сравнительного прогона сохранены в
`/tmp/dk1522-codex/installed-acceptance/triage/compare.py`,
`triage/baseline/commands.json`, `triage/installed/commands.json`
и соответствующих `result.json`. Обе версии назвали временный TR-003,
изменился только TR-001.
