# DK-1526: Эскалация слияния теряет перечень незакоммиченных файлов

записан 2026-10-31
приоритет: средний

## Черновик

### Ситуация

Ситуация: тик devkitctl watch зовёт shipctl queue --drain и при повторе
отказа пишет в «Ход работы» строку «эскалация дежурному: слияние: ...».
Отказы чистоты у shipctl многострочные: за первой строкой идёт рамка
cmdout с перечнем файлов.

Осложнение: в эскалацию уходит только первая строка (firstLine в queueTry,
tools/shipctl/queue.go), перечень отрезается. Утром 31.10 строка DK-1523
приехала дежурному как «незакоммиченное, сначала закоммить:» с пустотой
после двоеточия: по такой строке причина не читается, разбор возможен
только повтором слияния руками. Рядом вторая потеря: отказ класса
«ворота готовности» в память отказов тика не попадает вовсе, снаружи
его видно только строками «Слияние» в пакете этапа.

Вопрос: как эскалации нести отказ целиком, чтобы дежурный разбирал его
без прогона слияния?

Гипотеза: в pipeline_incidents (tools/devkitctl/watch.py) брать не первую
строку, а весь текст отказа либо прикладывать к строке путь рамки cmdout.
Чем проверить себя: воспроизвести отказ на черновой ветке (грязный файл
задачи в копии окна) и убедиться, что строка эскалации называет файл.
