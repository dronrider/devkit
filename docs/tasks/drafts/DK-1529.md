# DK-1529: Полный прогон тестов из сессии задачи падает в agentctl на guard записи

записан 2026-10-31

## Черновик

### Ситуация

Полный прогон слияния DK-1417 в ночь на 31.10 упал на сюите go:agentctl: восемь тестов exec (exec_test.go, hookgap_test.go) остановились словами «DK-1417: файл материала отсутствует, запуск остановлен». Оболочка задачи держит в окружении DEVKIT_TASK=DK-1417, agentctl exec читает её и требует запись с этим ID в docs/tasks текущего корня, а тесты гоняют exec в синтетических деревьях, где такой записи нет. Тесты, задающие свою переменную (XR-1), проходят, ждущие чистого окружения падают.

### Осложнение

Слияние из сессии, привязанной к задаче, требует чистить переменную руками (env -u DEVKIT_TASK), чего документация не говорит. Прогон из окна человека или тика проходит чисто, и дефект выглядит плавающим.

### Вопрос

Где резать утечку: санитить переменную в тестах exec, не требовать запись в exec вне явного вызова или чистить окружение в обвязке прогона?

### Гипотеза

Дешевле санитить переменную в самих тестах exec: там она либо задаётся явно, либо мешает; прогон конвейера перестаёт зависеть от того, из чьего окна его позвали.
