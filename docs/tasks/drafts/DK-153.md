# DK-153: Цикл цели в чате молча встаёт: зависшее ожидание фона и обрыв API

записан 2026-08-06

## Черновик

Цикл цели в чате молча встаёт: зависшее ожидание фона и обрыв API

Инцидент 2026-08-06, чат «Выполни цель XR-266» (xr-proxy). Виток ждал выкат
XR-262: shipctl merge ушёл в фон по таймауту 600 с и завис на кросс-сборке,
потому что Docker Desktop не был запущен. Сессия кончила ход словами «жду
завершения выката» и стояла без дела 2.6 часа (04:48 -> 07:24 UTC), затем ещё
3.7 часа (07:34 -> 11:16 UTC), оба раза до прихода пользователя с вопросом.

Уведомления о фоне не приходили, потому что сторожа сами висли: until-цикл
ждал маркеров в пустом файле вывода (tail копит вывод до конца процесса),
второй until ждал смерти процесса, который не умирал, а перевзведённый после
Monitor цикл на docker info завис вместе с демоном (timeout на маке нет).
Единственный не молчащий механизм, Monitor с таймаутом, сработал честно, но
перевзвели его самодельным циклом.

Слои причины:
- shipctl merge/ship виснет молча, когда Docker не поднят: ни префлайта, ни
  предела ожидания, ни вывода. По правилу «молчание неотличимо от штатной
  работы» это дыра самого конвейера.
- у витка нет запасного будильника: ход, кончившийся ожиданием фона, ничем не
  ограничен по времени, и зависший сторож снаружи неотличим от вставшего цикла.
- вторая независимая причина стопа: «API Error: Connection closed
  mid-response» убивает ход, и в живом чате цикл никто не перезапускает
  (goal-run ловит аварию только headless-витка). Поймано живьём в сессии
  devkit 2026-08-06.

Кандидаты починки:
- префлайт Docker в shipctl перед деплоем с быстрым отказом и внятным текстом;
- процедура ожидания в скиллах: только Monitor с таймаутом и перевзвод им же,
  запрет самодельных until на командах, которые сами могут виснуть;
- сторожок вставшего цикла: цель In progress без движения дольше порога
  означает громкий зов пользователя; накрыл бы и обрыв API.
