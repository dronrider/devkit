# DK-1536: Согласование дизайна при разработке UI

записан 2026-10-31
приоритет: высокий

## Черновик

### Ситуация
Сейчас разработка и доработка фичей с UI составляющей идёт практически всегда вслепую. Задача берётся в работу с описанием дизайна на словах, предварительная подготовка макета не производится. 

### Осложнение
Агент делает UI на свой вкус и это зачастую полностью расходится с ожиданиями пользователя. Помимо этого ошибка в UX часто оборачивается тем, что фича работает неправильно и помимо фронта сам пользовательский флоу построен неверно и для того чтобы довести её требуется существенные переработки.
Это влечёт не только потерю времени но и существенный перерасход подписки.

### Вопрос
Где подключать требование проведения дизайна? В скилле board-task или например в скилле board-groom чтобы требование проработки дизайна попадало сразу в задачу? По идее задача с UI без макета не может быть взята в работу, а значит проработка дизайна это часть груминга черновика или задачи. Иначе задача не сможет быть взята автономно и потребуется вмешательство пользователя. 
Как определять исключения из правил когда нужно предположим цвет кнопки поправить? Как определять делать дизайн или нет в таких случаях?
В каком формате готовить дизайн пользователю? Агенты разные и их инструментарий тоже. Например у claude есть свой design и у ChatGPT тоже свой функциона, а у GLM такого может не быть. Нужен понятный стандарт, которого могут придерживаться модели.

### Гипотеза
При создании задачи или груминга черновика агент проверяет наличие UI составляющей и если она присутствует проводит отдельную фазу проработки дизайна и согласования его с пользователем. Без согласованного дизайна взятие задачи в работу блокируется механически, то есть мы сначала отмечаем раздел с Проектированием UI и если он есть, но не заполнен на уровне харнеса запрещаем брать задачу. Исключения составляют какие-то мелочи не требующие отдельно проктировать дизайн или если пользователь сам явно подтвердил ,что дизайн не нужен.
