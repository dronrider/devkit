# DK-1548: review level штампует sha головы не того чекаута

записан 2026-11-01
приоритет: высокий

## Черновик

### Ситуация

На круге ревью DK-1545 штамп `taskctl review level` ставился из основного чекаута. В штамп ложился sha головы основного чекаута вместо дерева ревью. Обходили вызовом из дерева задачи через `taskctl -C`.

### Осложнение

Ворота слияния сверяют след ревью с деревом задачи. Штамп с чужим sha валит ворота или пропускает непроверенный код. Ревью из основного чекаута наступает на это каждый раз.

### Вопрос

Должен ли штамп брать sha дерева ревью сам и отказывать ли вызову вне дерева?

### Гипотеза

Штамп всегда несёт sha дерева, из которого шло ревью. Вызов из основного чекаута отказывает и называет дерево задачи.

## Контекст обсуждения

Нашёл исполнитель DK-1545 при сдаче 2026-11-01. Обход применён в этом круге. Связь с DK-1339, там sha ломается ребейзом, здесь чужим чекаутом.
