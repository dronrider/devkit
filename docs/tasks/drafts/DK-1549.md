# DK-1549: привязка дерева задачи переживает удаление дерева

записан 2026-11-01
приоритет: высокий

## Черновик

### Ситуация

После слияния DK-1545 дерево задачи удалено. Хук hooks/tree-mark.py продолжал держать привязку чекаута к удалённому дереву. Правки основного чекаута после `shipctl merge` получали отказ DK-1072 с путём в несуществующее дерево.

### Осложнение

Основной чекаут блокируется для правок после каждого слияния. Обход требует правок через субагентов без привязки. Работать главным заходом становится нельзя.

### Вопрос

Кто снимает привязку при исчезновении дерева, хук или merge?

### Гипотеза

Привязка проверяет существование дерева и отцепляется молча. Правки основного чекаута идут свободно после слияния.

## Контекст обсуждения

Нашёл исполнитель DK-1545 при сдаче 2026-11-01. Обход применён в этом круге. Похоже на DK-1357, там дерево исчезает под живым заходом, здесь привязка живёт дольше дерева.
