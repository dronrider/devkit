# DK-1571: Обёртки clitx-тестов текут в PATH соседних тестов под нагрузкой

записан 2026-11-03

## Черновик

### Ситуация

2026-11-03 при load average 14 и выше краснели три теста
tools/taskctl/clitx_test.go: TestCLIBoardGuardDoesNotCallGitUnderLock,
TestCLISpendRejectsEditDuringCalculation,
TestCLIMoveRejectsEditDuringBranchGate. Все три падали фаталом про дедлок.
При load ниже 6 те же тесты зелёные. Из краснот следовали снятия строк с
очереди слияния с формулировкой «краснота вне диффа: go:taskctl».
DK-1546 снималась три раза.

### Осложнение

Проверка дедлока выводится из истечения срока. Вокруг цепочки стоит
context.WithTimeout на 6-8 секунд, и в бюджет должны уместиться холодный
старт внешнего бинаря, несколько git-подпроцессов и вложенный запуск
taskctl со своим холодным стартом. Под нагрузкой цена одного запуска
процесса растёт в 3-5 раз. Замер записан в комментарии
internal/merged/warm_test.go:12-15 со ссылкой на DK-1168. В
TestCLIBoardGuardDoesNotCallGitUnderLock вложенные запуски умножаются:
обёртка срабатывает на каждый git rev-parse внешнего процесса.

Версию заголовка про утечку PATH обход по коду снял. t.Setenv
восстанавливает прежнее значение по концу теста, тесты в пакете
последовательные, чужие bindir между тестами не накапливаются. Захват не
того бинаря красил бы безотносительно нагрузки.

### Вопрос

Как отвязать проверку дедлока в clitx-тестах от стенных часов.

### Гипотеза

Детект по факту вместо срока. Вложенный процесс отработал, замок
освобождён. Прецеденты в проекте есть. TestExpectHoldsGitSpawns держит
потолок в запусках git (internal/merged/warm_test.go:68-72). Стенд подъёма
ждёт факта передачи, своего потолка секунд у него нет
(tools/taskctl/run_test.go, комментарий у стабов headless). Потолки на
компиляцию go run остаются бюджетами сборки, детекторами дедлока они не
служат.

## Пользовательские сценарии

### СЦ-1

Ситуация: очередь слияния гоняет полный прогон go:taskctl на загруженной
машине, рядом идут точечные прогоны и сборки других задач.

Действие: обкатка или проверка запускает clitx-тесты при load 14 и выше.

Результат: три теста дедлока зелёные в трёх прогонах подряд, снятий
«краснота вне диффа: go:taskctl» нет.

Польза: очередь слияния не снимает строки ложно и не ждёт тишины машины.

Рекомендация: единственный сценарий, других составов с разным наблюдаемым
результатом нет.

Ограничение: прогоны для проверки идут на той же машине рядом с полным
прогоном сюиты. Тишина машины ничего не доказывает.

Источник: вывод из примера, снятия DK-1546 из очереди слияния 2026-11-02.

### Условия

Условий, посильных только человеку, не нашёл. Искал в доступах, внешних
службах, невозвратных шагах и смене правил другим строкам: правка живёт в
тестах своего репозитория, нагрузку для проверки воспроизводит полный
прогон сюиты на той же машине.

## Развилки

- «детект»: как отвязать проверку дедлока от стенных часов
  - решает: исполнитель
  - рекомендация: детект дедлока по факту: вложенный отработал и замок освобождён; прецеденты TestExpectHoldsGitSpawns и стенд headless, потолки компиляции остаются бюджетами сборки
  - источник: код tools/taskctl/clitx_test.go (сроки на строках 91, 173, 304, 551), internal/merged/warm_test.go:68-72, tools/taskctl/run_test.go
