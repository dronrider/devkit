# DK-1572: Ворота этапов плана слепы к дереву задачи

записан 2026-11-03
приоритет: средний

## Черновик

### Ситуация

Работа идёт в дереве задачи (shipctl start), а план сессии нередко ведётся из основного чекаута: диспетчер держит план сам, а исполнитель закрывает свои пункты, откуда его пускает замок задачи. Следы этапов расходятся по местам: regcheck пишет журнал в .devkit/log дерева, вычитка оставляет строку в «Ходе работы» файла задачи дерева, отметки хук спавна кладёт в ~/.devkit/runs.

### Осложнение

2026-11-03 на DK-919 диспетчер не закрыл пункт regcheck, пока вслепую не нашёл флаг -C у agentctl: зелёный прогон лежал в журнале дерева, а ворота читали корень сессии. Исполнитель в тот же день не закрыл пункт вычитки: прозаическая строка «- Вычитка: ...» в «Ходе работы» дерева записью этапа не считается, а хук спавна пометил субагента вычитки этапом «разработка», потому что подъём шёл чужим определением. Отказ ворот в обоих случаях советует переделать работу и не называет лечение.

### Вопрос

Ворота сами находят дерево задачи по её ветке, или отказ обязан называть флаг -C? И какая запись законна для вычитки, которую вёл субагент исполнителя?

### Гипотеза

Отказ ворот называет лечение одной строкой, как отказы shipctl называют команду парковки, а вычитка, поднятая исполнителем по определению proofread, оставляет машинную запись этапа тем же хуком спавна.

## DoD

Пункт плана с прогоном в дереве задачи закрывается без ручного подбора флага, а вычитка субагентом исполнителя оставляет запись этапа.
