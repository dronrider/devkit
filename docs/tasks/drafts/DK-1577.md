# DK-1577: дежурный поднимается по уже снятому отказу конвейера

записан 2026-11-03
приоритет: средний

## Черновик

### Ситуация

2026-11-03, DK-1570. Слияние отказывало пять раз, с 16:46 до 17:10. В файле задачи ветки не было раздела «Сценарий проверки». Тик записал эскалацию дежурному в 17:03:55, коммит 03eb1e728.

Дальше конвейер закрыл отказ сам. Сценарий приехал коммитом 6f9350264 в 17:11:23. Обкатка зелёная в 17:14:50, коммит e91aad96b. В 17:15:35 конвейер поднял ревьювера, журнал этапов лежит в ~/.devkit/runs/DK-1570-Users-rider-projects-devkit.run.

Голова дежурного встала лишь в 17:21. Подъёму мешал замок задачи, его держал конвейер. Журнал .devkit/log пишет «чужой заход по DK-1570: exec-high (18adf49b), голова не поднимается», последний отворот в 17:15:54. Заказ дежурному собрали из записи, и через десять минут после снятия отказа он всё ещё называл отсутствующий сценарий.

### Осложнение

Сессия дежурного тратится на отказ, которого уже нет. Подпись в ~/.devkit/watch.duty держит попытку без исхода. Контракт дежурного знает два исхода, вопрос человеку либо черновик. Без исхода тик поднимет дежурного ещё дважды. На потолке попыток он добьёт подпись громким зовом, и человек получит шум про снятую проблему.

Лаг подъёма закономерен. Голова дежурного стоит за замком задачи. Замок занят, пока конвейер работает над строкой. Отказ, закрытый за время ожидания, приходит к дежурному уже снятым.

### Вопрос

Где сверять свежесть отказа. Один путь, перезапуск условия записи перед подъёмом; ворота проверяют наличие раздела в ветке дёшево. Второй путь, третий исход дежурного «конвейер закрыл сам» по образцу инцидентов (RESUME_MARK в tools/devkitctl/duty.py); подпись по нему закрывает тик.

### Гипотеза

Отказ, снятый конвейером до подъёма дежурного, перестаёт тратить его сессии и не добивается громким зовом человеку. Исход пока ждёт только агент, дежурный слой; пользователь его не обсуждал.

## Контекст обсуждения

Наблюдение и разбор вёл дежурный агент по эскалации слияния DK-1570, сессия 2026-11-03. Артефакты снятия лежат в ветке. Коммит 6f9350264 принёс сценарий, e91aad96b зелёную обкатку. Ревью идёт с 17:15:35, после него очередь слияния повторит подход сама.

Механика сегодня такая. Заказ дежурному собирается из текста записи, duty_order в tools/devkitctl/duty.py. Сверки условия с живой веткой на подъёме нет. У инцидентов конвейера (DK-1415) исход «возобновление» уже есть, строка «- Возобновление:» в «Ходе работы», и исполняет её тик. У записей из файлов задач такого исхода нет.

Рядом нашлась вторая щель. Подпись отказа несёт счётчик минут, и перезапись с новым счётчиком проходит новой подписью. Сегодня «сессия молчит 172 минуты» и «179 минут» из одной тишины заняли две записи с отдельными попытками в ~/.devkit/watch.duty. SESSION_TAIL снимает с подписи только хвост сессии. Граница одинаковых отказов DK-1115 перезапись не узнаёт.
