# DK-1602: Прогоны тестов обходят общий слот при подмене HOME

записан 2026-11-05
приоритет: высокий

## Черновик

### Ситуация

2026-11-05 при `shipctl merge DK-1589 --train` полный прогон шёл через
freshtree с временным HOME. Диспетчер зафиксировал PID shipctl 53847 и
parallel.py 54554. С 02:37:53 до 02:39:13 рядом выполнялись адресные проверки
DK-1601 через установленный `devkitctl test`. Они сразу получили бюджет
машины и не ждали полного слота. Полные команды, длительности, результаты
и объяснение пересечения сохранены в `/private/tmp/dk1601-codex-result.md`.

В коде `tools/devkitctl/parallel.py` общий каталог задан как
`SLOT_DIR = os.path.expanduser(os.path.join("~", ".devkit", "parallel-slots"))`.
`FULL_RUN_SLOTS = 1`. Функция `internal/freshtree.Env` намеренно подменяет
HOME для изоляции проверок. В результате полный и адресный прогоны одного
пользователя на одной машине занимают разные файлы слота. Это подтверждено
чтением кода и совпавшими временами живых прогонов, новый опыт не запускался.

### Осложнение

Штатные команды обходят общий предел нагрузки без явного отключения
ограничения. Каждый прогон может запросить весь бюджет той же машины.
Изолированное окружение слияния отделяет не только данные тестов, но и
учёт занятого CPU. Зелёные результаты DK-1601 остаются действительными;
они не доказывают строгую сериализацию или нагрузочный DoD DK-1589.

### Вопрос

Как выбирать один ресурс для прогонов одной физической машины независимо
от подмены HOME, проекта и пользователя ОС? Требуется определить установку
каталога, права доступа, видимого владельца, срок ожидания и диагностику
недоступного общего ресурса. Общий путь внутри настоящего дома одного
пользователя закроет наблюдавшийся случай, но оставит независимые бюджеты
разных пользователей ОС. Выбор конкретного размещения и механизма пока
не согласован.

### Гипотеза

Предлагаемый агентом исход: штатные прогоны одной машины учитывают общий
бюджет и видят занятость независимо от временного HOME и рабочего дерева.
Изоляция тестовых данных сохраняется. Разделение бюджета на короткие и
полные проверки остаётся отдельным решением DK-1355.

## Контекст обсуждения

По поручению диспетчера запись фиксирует дефект, найденный при завершении
очереди, без исправления кода и новых тестовых запусков.

Проверены пересечения. Сценарий №049 в `docs/concurrency-queue.md` и
черновик DK-1355 описывают короткий прогон, ожидающий уже занятый общий
слот. Здесь общий слот фактически разошёлся на два из-за HOME. DK-1367
описывает зависание MachineContourTest рядом с чужой сюитой, а DK-498
наследование внешних указателей чекаута и конфига. Ни одна из этих карточек
не содержит текущего случая.

Сценарий №153 уже требует общего ресурса для разных пользователей одной
машины; его носитель пока указан как «Новая задача». Эту запись следует
использовать как один носитель №153 с новым воспроизведением для временного
HOME. Вторую карточку только для того же общего ресурса заводить не нужно.

### Предложенный концепт

Агент предлагает отделить пространство изоляции тестовых данных от
пространства учёта машинного ресурса. Идентичность проекта для второго
пространства не подходит: разные проекты конкурируют за те же CPU.
Настоящий пользователь ОС также не обозначает весь ресурс машины.
Конкретный каталог или сервис, способ раскладки прав и поведение при
недоступности ресурса остаются на груминг; пользователь их не утверждал.
