# DK-1603: decide пишет развилку в одноимённый черновик вместо живой задачи

записан 2026-11-05
приоритет: высокий

## Черновик

### Ситуация

5 ноября при разборе долга DK-993 команда `taskctl decide DK-799 --ask попутно` дописала вопрос в `docs/tasks/drafts/DK-799.md`. Живая задача `docs/tasks/DK-799.md` имеет другой предмет. Команда завершилась успешно и напечатала «черновик»; на самой задаче вопроса не оказалось.

В `tools/taskctl/decide.go` функция `decideRecord` сначала выбирает существующий черновик по пути `draftRel`, затем проверяет `taskFilePath`. Совпадение ID не считается неоднозначностью. Воспроизведение и оба заголовка сохранены в `/private/tmp/dk1589-993-installed-proofread.md`. Ошибочная новая развилка была отменена до публикации; прежний текст черновика и решения человека сохранены. Для сдачи оставлена одна развилка в DK-976.

Нужно определить явный выбор носителя при совпадающих ID. Без явного выбора команда должна сообщать о неоднозначности до записи. Проверка на синтетическом проекте создаёт задачу и черновик с одним ID и разными предметами. Затем выполняет обычную команду и сверяет содержимое обоих файлов, адрес записи в результате и отсутствие частичной записи при отказе. Реальные задачи и ответы человека в тест не входят.
