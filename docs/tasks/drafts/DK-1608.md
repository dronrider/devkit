# DK-1608: Слияние падает при копировании временного Python-кеша

записан 2026-11-05
приоритет: средний

## Черновик

### Ситуация

На выкате DK-1564 2026-11-05 команда `shipctl merge DK-1564 --push --no-wait` запустила штатный общий прогон в свежем дереве 58a8e6ece92f. В `CacheKeepHomesTest.setUpClass` вызов `Sandbox()` упал на `shutil.copytree`: временный файл `hooks/__pycache__/check_board_files_test.cpython-314.pyc.4399446512` исчез во время копирования. Полный вывод сохранялся в `.devkit/cmdout/20261105T150933-test/out` дерева задачи. После слияния рабочее дерево удалено, доступного полного лога нет.

### Осложнение

Из-за сбоя окружения слияние остановилось до выката. Прогон выполнил 1313 тестов вместо ожидаемых 1322 и завершился с ошибкой. Код задачи не менял тестовый раннер и создание песочниц.

### Вопрос

Как исключить гонку между созданием Python-кеша и копированием исходников в песочницы? Решение с пользователем не обсуждали.

### Гипотеза

Агент ожидает, что параллельный общий прогон создаёт песочницы без случайных падений на временных файлах кеша.

## Контекст обсуждения

Повторный `PYTHONDONTWRITEBYTECODE=1 shipctl merge DK-1564 --push --no-wait` прошёл со штатным набором тестов, после чего исправление выкатилось. Это обход на один запуск, конфиг и код раннера не менялись. Сохранить запрет записи байткода либо исключить кеши из копирования предложит следующий разбор; пользователь способ не выбирал.
