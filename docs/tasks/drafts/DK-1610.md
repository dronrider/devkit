# DK-1610: слияние DK-1605 стоит без сценария проверки

записан 2026-11-06
приоритет: средний

## Черновик

### Ситуация

2026-11-06 очередь слияний отказала DK-1605 (ранг 66, P1, блокер проверки
цели DK-1253): ворота слияния не находят раздел «Сценарий проверки» в
docs/tasks/DK-1605.md, ни в main, ни в ветке dk-1605 (вершина 03ec6cc55,
ревью круга 2 без замечаний). Отказ уехал эскалацией дежурному агенту.
Тик очереди сейчас отказывает ещё раньше: в основном дереве лежит
незакоммиченная запись самой эскалации по файлу задачи.

### Осложнение

Без раздела shipctl merge не переведёт задачу в Check и не выкатит её: по
RULES.board.md («Трекинг задач» п. 6) сценарий обязателен до перевода в
Check, и проверять выкат после слияния будет нечем. Задача стоит первой в
очереди слияний, строка не двигалась сутки, за ней ждёт выката поезд.

### Вопрос

Открытых вопросов нет: пометка «- Исключение: сценарий (причина)» не
подходит, правка кодовая (fix(dashboard) в ветке) и по DoD имеет
собственную проверку отдельной сессией на установленном бинаре.

### Гипотеза

Конвейер задачи дописывает агентский сценарий из шагов воспроизведения
раздела «Что происходит», закоммичивает запись эскалации, повторяет
слияние, поезд уходит в Check и выкат. Исход требует конвейер по правилам
доски, пользователь ждёт выката.

## Контекст обсуждения

Материал для сценария уже собран в файле задачи. Воспроизведение:
синтетический профиль XR-010, после возобновления через say живое окно
chat-XR-010-1, обычный POST /tasks/XR-010/continue вернул way=resume и окно
chat-XR-010-2, оба процесса работали с одним --resume SID. Подтверждение
сохранено в /private/tmp/dk1433-final-run/proof/G2-duplicate-FAIL.json,
разбор кода в /private/tmp/dk1253-g2-continue-diagnosis.md. Ожидаемый итог
по DoD: остаётся один живой процесс того же SID и окна, контрольная реплика
приходит только ему. DoD также требует поведенческий regcheck (красный на
старой версии) и прогон отдельной сессией на установленном бинаре с
настоящими tmux-окнами и квитациями; образец раздела у задачи DK-1433. Вид
приёмки строки агентский, и ворота слияния сверх раздела спросят отметку
обкатки: taskctl rehearse DK-1605 в свежем дереве с временным HOME, вывод
ложится в раздел «Проверка». Эскалация записана дежурным агентом без прав
на правки: дописка раздела и повтор слияния остаются за исполнителем
DK-1605, черновик фиксирует блокировку поезда для разбора.
