# DK-1621: эскалация дежурного грязнит доску и держит очередь слияний

записан 2026-11-06
приоритет: средний

## Черновик

### Ситуация

2026-11-06 тик дописывает в файлы задач строки «эскалация дежурному: слияние: ...» и не коммитит их. Проверено на главном чекауте: `git status --short docs/` даёт `M docs/tasks/DK-1605.md`, `M docs/tasks/DK-1606.md`, у каждой по две-три добавленные строки одного и того же отказа, плюс свой хвост был у `DK-1570.md`. Записи у DK-1570 я закоммитил, после этого тик добавил новые строки соседям.

`shipctl queue --drain` отвечает «очередь слияний пуста: готовых веток нет» и называет причиной у всех строк «в рабочем дереве незакоммиченное по файлам задачи, сначала закоммить:». Состав поезда берёт файлы соседних строк, поэтому чистая DK-1570 получает отказ по чужим файлам.

### Осложнение

Запись эскалации сама делает дерево грязным, грязь отбивает слияние, следующий тик дописывает ещё две такие же строки. Круг замыкается: очередь не разливает ни одну строку, файлы растут, а исходный отказ (нет раздела «Сценарий проверки») так и не чинится. Строка DK-1570 с зелёными тестами и принятым ревью второй час стоит в очереди без собственной причины.

### Вопрос

Кто коммитит запись эскалации: тик сразу после записи либо сессия строки? И должен ли ворот чистоты поезда считать файлы чужих строк своей грязью? Не обсуждали.

### Гипотеза

Записи эскалации уезжают на доску сразу и не держат слияние соседей, а строка с зелёными тестами не ждёт чужого сценария.
