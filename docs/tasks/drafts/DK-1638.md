# DK-1638: Повреждённая запись мешает читать всё согласование накопителя

записан 2026-11-06
приоритет: средний

## Черновик

### Ситуация

При ревью срочной DK-1623 обнаружено ограничение общего ответа GET /api/projects/{p}/drafts/prepared. Он использует taskctl draft prepared adopt без ID. Если readPrepared одной записи возвращает ошибку, весь вызов завершается отказом. Новый интеграционный тест воспроизводит это на битом prepared-файле.

### Осложнение

Накопитель не показывает подготовленные задачи здоровых записей до исправления повреждённой записи. Прежде отдельные запросы сохраняли доступ к остальным карточкам. Ошибка не скрывается, отдельный экран здоровой записи остаётся доступен. Срочная правка убирает лавину из 466 запросов; это ограничение вынесено отдельно.

### Вопрос

Как отделить чтение состава от закрепления номеров и сохранить доступ к здоровым записям при частичном отказе? Нужен явный перечень непрочитанных записей в общем ответе и понятная ошибка в интерфейсе без молчаливого пропуска.

### Гипотеза

В ответе на один общий запрос доступны карточки и перечень записей с ошибками. Повреждённая запись не мешает отображать остальное согласование. Закрепление номеров и подтверждение сохраняют необходимые гарантии транзакции.
