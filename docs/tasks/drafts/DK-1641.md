# DK-1641: убитый прогон делегирования оставляет открытый этап разработки

записан 2026-11-06
приоритет: средний

## Черновик

### Ситуация

2026-11-05 в 14:44 я запустил `agentctl run DK-1570` и через 20 секунд снял его по таймауту: проба маршрута делегирования. Прогон оставил в `/Users/rider/.devkit/runs/DK-1570-Users-rider-projects-devkit.run` открытую запись `этап = разработка | 2026-11-05T14:44:25 | подпроцесс deepseek-v4-pro/high | ... |` без времени закрытия. Дальше шли настоящие прогоны: две записи разработки закрыты (14:45-14:53 и 14:54-19:49), вычитка, ревью и два слияния закрыты.

2026-11-06 сторож увидел текущим этапом ту открытую разработку и прислал дежурному «этап «разработка», сессия молчит 125 минут, подъём не помог 3 раз подряд». Строка при этом давно сдана: код круга 3 в ветке, голова f0bfd260c, ревью принято, тесты дашборда зелёные.

### Осложнение

Открытая запись держит строку в глазах сторожа как идущую разработку. Подъём за подъёмом пишет в ветку коммиты «строка поднята», голова уезжает вперёд, а уровень ревью привязан к голове. Строка с готовым кодом получает эскалации дежурному и лишние коммиты, и разбор каждый раз упирается в запись, которой соответствует давно убитый процесс.

### Вопрос

Закрывать запись этапа по факту смерти процесса (pid прогона в записи) либо ставить срок жизни открытому этапу и снимать его тиком? Не обсуждали.

### Гипотеза

Убитый прогон не оставляет за собой открытый этап, и сторож не поднимает строку ради процесса, которого нет.
