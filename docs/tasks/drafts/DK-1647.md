# DK-1647: Фикстуры dashboard вызывают установленные утилиты после потери кэша

записан 2026-11-08
приоритет: средний

## Черновик

### Ситуация

8 ноября в штатном полном прогоне DK-1646 прошли 17 из 18 компонентов. Dashboard завершился с ошибкой после исчезновения общего файла dashboard-test-shim. В [server_test.go](../../../tools/dashboard/server_test.go) его путь сохраняется через sync.Once. После удаления файла новые фикстуры получают сломанные ссылки, а поиск в PATH доходит до установленных утилит.

### Осложнение

В исходном отказе dashboard прочитал реальные профили вместо подставных и вызвал установленный taskctl. Проверка общего переходника в том же прогоне сообщила, что его файл отсутствует. Ошибки стенда остановили штатное слияние и потребовали отдельного разбора окружения.

### Вопрос

Как должны вести себя фикстуры при исчезновении общего переходника во время прогона? Нужны восстановление файла или явная ошибка до обращения к настоящим утилитам? Решение пока не выбрано.

### Гипотеза

Агент предлагает следующий исход. При потере общего переходника тесты сохраняют изоляцию и не обращаются к установленным утилитам и реальным профилям. Пользователь этот исход отдельно не формулировал.

## Контекст обсуждения

Агент подтвердил цепочку отдельной синтетической пробой с точной копией scriptShim и writeScript из исходника. Сначала работала подставная команда. Затем удалялся только свой переходник в отдельном временном каталоге. Следующая фикстура получала битую ссылку, а поиск в PATH выбирал вторую подставную команду, изображавшую установленную утилиту. В новых пробах не было обращений к реальным профилям. Подробный локальный след сохранен в [диагностике](/private/tmp/DK1646-dashboard-env-diagnosis.md).

В момент исходного отказа macOS dirhelper чистил старые временные файлы. По данным агента, это вероятная причина исчезновения. Прямой unlink переходника не доказан. Для продолжения штатного прогона диспетчер выбрал собственный свежий TMPDIR на время запуска. Этот обход сохраняет все проверки, но хрупкость общего кэша остается.

### Предложенный концепт

Восстановление исчезнувшего переходника и явный отказ до запуска настоящих утилит названы агентом как варианты для отдельного разбора. Пользователь их не выбирал. Подробности решения, ранг и план реализации пока не определены.
