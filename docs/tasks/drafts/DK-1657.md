# DK-1657: Regcheck с -C в модуль-подкаталог подхватывает чужой go.work

записан 2026-11-08
приоритет: средний

## Черновик

### Ситуация

Ситуация: при ревью DK-1334 2026-11-08 regcheck с -C tools/shipctl и -C tools/devkitctl падал с «current directory is contained in a module that is not one of the workspace modules listed in go.work», хотя usage утилиты заявляет обход go.work для модулей-подкаталогов (DK-367). Регчек находит go.work выше по дереву каталогов, чем корень репозитория.

Осложнение: обход одной переменной GOWORK=off закрывает оба прогона, но заявленный в usage режим с -C из коробки не работает, и обход надо помнить вручную.

Вопрос: почему -C не включает заявленный DK-367 обход go.work и где регчек ищет go.work при смене каталога.

Гипотеза: регчек определяет корень модуля по текущему каталогу и берёт первый go.work вверх по дереву без остановки на границе репозитория; лечится либо остановкой поиска на границе репозитория, либо явным GOWORK=off для модулей-подкаталогов.
