# DK-1667: Дежурный поднимается по живому конвейеру и зря бьёт потолок

записан 2026-11-09
приоритет: средний

## Черновик

### Ситуация

Слияние DK-1663 09.11.2026 отворачивалось с 16:40 до 17:06 на незакоммиченной
правке файла задачи в worktree: исполнитель нёс правку вычитки к коммиту.
Работу вела сессия припаркованной DK-1650, замок был у DK-1650, у DK-1663
замка не было, и для цикла головы у задачи не было. Подъём конвейера в те же
минуты отворачивался «чужой заход», то есть процесс исполнителя был виден.
Инцидент слияния (INC-20261109-5) за 13 минут поднял дежурного трижды (16:52,
16:59, 17:05), двое дежурных ушли с кодом 0 без исхода. В 17:06 исполнитель
закоммитил правку сам, worktree стал чист, очередь слияния продолжила ход.

### Осложнение

У дежурного нет исхода для самоустранённого отказа: вопрос паркует живую
задачу, черновик требует отдельного предмета, запись «Возобновление» инцидент
не закрывает и легла бы в файл задачи на main поверх идущей ветки. Подпись с
тремя попытками на ближайшем тике без головы бьёт громким зовом «дежурный не
оставил исхода», хотя отказ устранил сам исполнитель. Живого исполнителя из
чужой припаркованной сессии цикл не признаёт и считает попытки дальше.

### Вопрос

Признавать живой работой по задаче сессию припаркованной задачи (замок
родителя, этап в реестре сессий) и не поднимать дежурного, пока она идёт,
либо завести исход «устранено исполнителем» без черновика и громкого зова?

### Гипотеза

Дежурный молчит при живой работе по задаче, кто бы её ни вёл, а потолок
остаётся для действительно пропавших разборов.
