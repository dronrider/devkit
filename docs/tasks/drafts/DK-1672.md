# DK-1672: Повтор DK-1392: слияния бьют в одну правку сотни раз без потолка

записан 2026-11-09
приоритет: высокий

## Черновик

### Ситуация

Цифра: DK-993 набрал 611 попыток слияния за три с половиной дня шагом в пять минут; инциденты недели по слиянию: DK-1471 376 обнаружений, DK-1605 127, DK-1570 85, DK-1606 77; отворот shipctl merge 89% вызовов недели.
Пример: INC-20261107-18, «в рабочем дереве незакоммиченное по файлам задачи, сначала закоммить», 376 обнаружений об одну и ту же правку.
Мера: потолок попыток и шумный отказ очереди по стоящей DK-1392, довод ущерба к DK-1105; повтор поднимает серьёзность внутри полосы.

### Осложнение

Потолок повторов из DK-1218 считает только чужую красноту: счёт растёт в одной ветке разбора отказа, а предполётный отворот и нераспознанная ошибка слияния попадают в хвост разбора без счёта (shipctl/queue.go:688-692), и наклейка preflight между тиками никого не останавливает. Отказ ворот свежести повторов тоже не тратит, это заметил черновик DK-1398. Звон дежурному после второго одинакового отказа уже стоит (DK-1436), но инцидент продолжает копить счётчик обнаружений на каждом тике, сами попытки тоже продолжаются. INC-20261107-18 собрал 376 обнаружений об одну правку.

### Вопрос

Какие классы отворотов считают повтор и чем очередь заявляет о снятой ветке; дежурному нужен один закрытый отказ вместо растущего счётчика.

### Гипотеза

Считать повтор у всякого отворота, который не ждёт события. После трёх одинаковых причин на одной правке очередь снимает ветку наклейкой с поручением, инцидент дежурного закрывается исходом «потолок попыток». Смена причины начинает счёт заново, новый коммит в ветке возвращает её в очередь и обнуляет счёт.

## Пользовательские сценарии

### СЦ-1

Ситуация: ветка стоит в очереди слияний с отворотом вне кода ветки, например незакоммиченной правкой в дереве задачи, сторож тикает очередь каждые пять минут.
Действие: очередь встречает третий одинаковый отворот подряд.
Результат: ветка снимается с очереди с поручением разобраться и вернуть, тик перестаёт заказывать слияние по ней.
Польза: сотни бессмысленных попыток и растущий счётчик обнаружений исчезают, очередь не жжёт прогоны об одну правку.
Рекомендация: включаем, это слово пользователя из меры записи про потолок попыток.
Ограничение: при смене слов отворота счёт начинается заново, потолок не снимает ветку по суматохе разных причин.
Источник: слово пользователя (мера записи), INC-20261107-18, черновик DK-1392.

### СЦ-2

Ситуация: исполнитель устранил причину отворота и закоммитил правку в ветку.
Действие: очередь видит новый коммит за пределами файлов доски.
Результат: снятая ветка возвращается в очередь сама, счёт повторов начинается с нуля.
Польза: потолок не замуровывает ветку, чинить и возвращать можно без ручных команд.
Рекомендация: включаем. Без возврата потолок превращал бы снятие в тупик, а путь уже стоит у снятий чужой красноты.
Ограничение: ручной возврат shipctl queue --free обнуляет счёт так же.
Источник: необходимое следствие СЦ-1, инвариант очереди из README shipctl про возврат после нового коммита.

### СЦ-3

Ситуация: ветка снята по потолку повторов, у дежурного живёт инцидент с этим отворотом.
Действие: очередь снимает ветку и объявляет причину снятия.
Результат: инцидент закрывается исходом «потолок попыток», счётчик обнаружений перестаёт расти, исполнителю уходит поручение.
Польза: ущерб виден одним закрытым отказом, дежурный не перечитывает сотню одинаковых строк.
Рекомендация: включаем, это слово пользователя из меры записи про шумный отказ.
Ограничение: новый зов не заводится, звон второго одинакового отказа стоит с DK-1436.
Источник: слово пользователя (мера записи), словарь исходов hooks/incidents.py.

## Дерево решений

- СЦ-1: очередь перестаёт долбить стоящую причину.
  - Продуктовые показатели: попыток слияния на одну стоячую причину не больше трёх; счётчик обнаружений инцидента не растёт после снятия; остальные ветки очереди едут дальше. Проверка: стенд очереди из заглушек, тики имитируются повторными вызовами drain. Источник требования: мера записи, инциденты недели.
  - Развилка «классы счёта» (решает исполнитель): какие отвороты считают повтор. Рекомендация: все, кроме ждущих события вроде занятого замка, ожидания предпосылки и ожидания regcheck. Ждущие кончаются сами, счёт повторов превращал бы их в снятия. Проверка: стенд с отворотом каждого класса.
  - Развилка «шум снятия» (решает исполнитель): чем очередь заявляет снятие. Рекомендация: тем же механизмом, что у чужой красноты. Наклейка снятия с поручением, запись в файл задачи, исход «потолок попыток» у инцидента, новый канал не заводится.
- СЦ-2: возврат после починки.
  - Продуктовый показатель: возвращённая ветка получает свежий счёт и доезжает слиянием. Проверка: коммит в дереве задачи после снятия на стенде.
  - Решение задано инвариантом DK-1218: возврат новым коммитом и командой queue --free, обе дороги обнуляют счёт.
- СЦ-3: инцидент закрывается исходом.
  - Продуктовый показатель: в журнале один инцидент с исходом «потолок попыток», счётчик остановился. Проверка: синтетический журнал инцидентов на стенде.
- Общие ограничения: с DK-1650 плоскости не пересекаются, там отбор кандидатов, здесь разметка исходов отворотов, граница записана в самой DK-1650. Текст жалобы остаётся у DK-1395, доставка Held-поручения у DK-1394, карантин красноты прогонов у DK-1393.
