# DK-1677: Автоматическое закрытие опережает независимую проверку

записан 2026-11-09
приоритет: высокий

## Черновик

### Ситуация

9 ноября 2026 года в текущей сессии агентская задача с документацией прошла ревью и обкатку. После `taskctl move <ID> check` и `taskctl debt-done <ID>` сторож автоматически закрыл задачу. Записи `agentctl stage <ID> проверка` ещё не было. Фактический ID участника разработки был указан в файле задачи.

README taskctl описывает действующее поведение: `taskctl close` без записи прогона проходит без предупреждения. Это нужно для принятия человеком. При автоматическом закрытии условие не различается.

### Осложнение

Задача может попасть в архив до независимого прогона сценария. При отсутствии хуков спавна возможна ложная приёмка без подтверждения проверки отдельной сессией.

### Вопрос

Как различать автоматическое закрытие и явное принятие человеком, сохранив возможность последнего без записи агентского прогона?

### Гипотеза

Ожидается, что автоматическое закрытие агентской задачи дождётся независимой проверки и фактической записи о ней либо явного принятия человеком. Способ реализации не выбран.
