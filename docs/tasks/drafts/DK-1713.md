# DK-1713: Codex показывает ожидание реплики до завершения основного хода

записан 2026-11-14
приоритет: средний

## Черновик

### Ситуация

На приёмке DK-1711 14 ноября 2026 года груминг DK-1536 работал через app-server на Sol и вызывал субагентов. API status вернул busy=false и idle=true, пока основной ход продолжал выполнять команды. В ленте были ответы дочерних агентов. Собственный rollout основного разговора после этого дополнялся инструментами и завершился событием task_complete только в 18:08:12 по Москве.

### Осложнение

Панель сообщает ожидание реплики во время продолжающейся работы. Пользователь может принять ответ субагента за итог груминга и отправить повторный заказ. Груминг успешно подготовил результат и вопрос согласования; запуск не блокируется.

### Вопрос

Нужно проверить принадлежность уведомлений turn/completed к основному и дочерним разговорам. В tools/dashboard/appchat.go функция appNote сбрасывает busy для каждого turn/completed и не разбирает threadId. Связь наблюдаемой ошибки с этим обработчиком пока гипотеза; отдельного воспроизведения пакетами RPC не было.

### Гипотеза

Агент ожидает, что индикатор будет отражать основной ход до его завершения. Завершение дочернего агента не должно переводить основной разговор в ожидание реплики.

## Контекст обсуждения

Находка записана отдельно после восстановления запуска DK-1536. Пользователь ограничил работу завершением подключения профиля и отложил дальнейшее развитие прототипа. Исправление индикатора в текущую правку не включалось. Техническую гипотезу предложил агент; пользователь способ исправления не выбирал.
