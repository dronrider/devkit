# DK-1721: Обычный стоп чата не прерывает повторные запросы после ошибки API

записан 2026-11-17
приоритет: средний

## Черновик

### Ситуация

17 ноября 2026 при диагностике DK-1720 старый чат DK-1570 ожидал повторного запроса после ответа 429 [1113] о недостаточном балансе. В окне клиента были строки API error, Retrying и attempt 2/300. POST ручки /stop с пустым телом вернул way idle и сообщение «ход не идёт: прерывать нечего, сессия жива и ждёт следующей реплики».

### Осложнение

На повторном снимке окна были видны продолжающиеся запросы и напоминание в состоянии queued. В транскрипте появился следующий api-request. После обычного стопа клиент мог возобновить ошибочно начатый ход при восстановлении API.

### Вопрос

Как распознавать ожидание повторного API-запроса при остановке хода? Требуется воспроизведение на синтетическом окне, включая idle, API retry, ожидание ответа человека и меню клиента. Обычная остановка не должна посылать клавишу в чужое меню или снимать весь разговор.

### Гипотеза

По предположению агента, обычный стоп должен прекращать повторные запросы текущего хода и показывать фактическое состояние. Пользователь отдельно поведение стопа не обсуждал.

## Контекст обсуждения

При инциденте использован штатный обход /stop с drop:true. Он снял ошибочно разбуженную сессию. Отсутствие панели и native registry подтверждено, ответов assistant после служебного запуска не было. История сохранена. Этот дефект не входит в исправление маршрутизации первой реплики DK-1720.
