# DK-1733: Обычный чат Codex не может читать и менять доску devkit

записан 2026-11-18
приоритет: высокий

## Черновик

### Ситуация

18 ноября 2026 в новом обычном чате дашборда с подпиской Codex агент
попытался зарегистрировать обнаруженный баг. Даже taskctl list --safe
и taskctl draft list --safe завершились ошибкой состояния доски при chmod
каталога транзакций .git/devkit/draft-tx. Регистрация не состоялась.

Нить Codex 01a1f008-a8e6-7f20-b40c-acad5a9c909b, ключ чата
as70a61dc7-f82a-4c3e-bc95-f729fc7b19f2. В журнале
~/.codex/sessions/2026/11/18/rollout-2026-11-18T22-01-06-01a1f008-a8e6-7f20-b40c-acad5a9c909b.jsonl
строка 8 содержит approval_policy=never. Проект доступен на запись,
.git только на чтение, ~/.devkit/plans вне разрешённых каталогов записи.
Команды и отказ записаны в строках 44 и 47.

В текущем расследовании ошибка повторилась на taskctl draft list --json.
Каталог транзакций принадлежит текущему пользователю с правами 0700.
Штатный повтор команды через require_escalated успешно прочитал накопитель.
Запись плана agentctl также потребовала расширенного доступа.
Это подтверждает ограничение песочницы. Неисправность обычных файловых прав
владельца не подтверждена.

### Осложнение

Агент обычного чата не может проверить состояние доски и сохранить находку.
Правило репозитория требует остановиться до правок при недоступном состоянии
доски. Политика never не позволяет запросить нужный доступ в том же чате.
Также нельзя положить план работ штатной командой agentctl.

### Вопрос

Как поддержать регистрацию находок и ведение плана из обычного чата при
согласованной политике доступа? Проверить необходимые каталоги записи,
побочные записи команд чтения и возможность штатного рабочего запуска.
Решение о расширении политики обычных чатов пока не принято.

### Гипотеза

Пользователь ожидает, что чат сможет проверить доску и зарегистрировать баг.
Если для работы требуется иной режим, ограничение и способ продолжения
должны быть понятны в интерфейсе. Агент предлагает учесть также запись
плана работ.

## Контекст обсуждения

README дашборда, раздел «Первый запуск Codex», сохраняет never для обычных
чатов. on-request с auto_review отдельно разрешены для груминга и рабочих
запусков задач. DK-1724 восстановила рабочий режим продолжения чата
незакрытой задачи, поднятой кнопкой «Выполнить»; новый обычный чат в её
границы не входит. Этот разбор не разрешает молча расширять права всех
обычных чатов. Изменений исходников и конфигурации в расследовании нет.

## Пользовательские сценарии

### СЦ-1

Ситуация: пользователь начинает любой чат Codex или продолжает сохранённый.
Действие: поручает проверить доску, зарегистрировать находку и вести план.
Результат: необходимые запросы доступа проходят автоматическую проверку;
при одобрении команды выполняются, при отказе видна причина ограничения.
Польза: способ создания чата не мешает выполнению одного и того же поручения.
Рекомендация: включить по прямому выбору пользователя.
Ограничение: проектовая песочница и отдельная проверка дополнительных прав.
Источник: решение пользователя 18 ноября в двух развилках DK-1733.

## Дерево решений

- СЦ-1: все новые и возобновлённые чаты получают одну политику доступа.
  - Пользователь отверг различия по кнопке запуска и отдельный выбор режима.
  - Обычная запись ограничена прежней workspace-write; постоянные разрешения
    за её границами не расширяются. Чтение и запросы эскалации описываются
    согласно фактическому механизму, без обещания полной изоляции.
  - Подмена или отсутствие подтверждённых полей политики приводят к отказу
    до отправки хода. Используется уже существующий путь рабочего запуска.
  - Прежние нити возобновляются с новой политикой и прежней историей.
  - Владение задачей проверяется отдельно от прав; дубли владельцев запрещены.
- Обход подтвердил поддержку sandbox mode/config у thread start/resume
  локальной схемой установленного Codex и реализацией рабочего пути.
  Пробы вне проекта и с отказом проверяют сохранение границ.
  Неподтверждённые настройки writableRoots не добавляются.
- Условий, посильных только человеку, после сохранённого выбора не найдено.
