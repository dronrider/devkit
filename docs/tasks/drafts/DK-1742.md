# DK-1742: Взятие задачи коммитит доску без существующего файла постановки

записан 2026-11-20
приоритет: средний

## Черновик

### Ситуация

Источник: выполнение DK-1741, 2026-11-20. Команда `taskctl move DK-1741 in-progress -m ... --push` успешно создала и отправила коммит `38200f858`. В него вошёл только `docs/TASKS.md`. Существовавший незатреканный файл `docs/tasks/DK-1741.md` в коммит не попал.

### Осложнение

После `shipctl start` дерево задачи было создано без постановки. Проверка `taskctl guard DK-1741` запретила старт работы. Доска уже показывала задачу взятой, но исполнитель не мог начать её по штатному пути.

### Вопрос

На каком шаге проверять наличие постановки в коммите и как связывать её сохранение с переводом задачи в работу? Решение ещё не обсуждалось.

### Гипотеза

Предложение агента, пока не согласовано. После успешного взятия задачи с пушем исполнитель открывает дерево с доступной постановкой и проходит guard. Если материала в истории нет, проблема обнаруживается до отправки коммита взятия.

## Контекст обсуждения

Диспетчер сохранил постановку отдельным коммитом main `07f39f7ca` и отправил его в origin. Исполнитель перенёс этот коммит через cherry-pick. Так работа получила недостающий материал.

В прежней постановке также были запрещённые символы. Это отдельное обстоятельство; предмет черновика состоит в пропуске существующего файла при коммите взятия задачи.
