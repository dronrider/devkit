# DK-1743: Штатное делегирование Codex прерывается до разработки

записан 2026-11-20
приоритет: средний

## Черновик

### Ситуация

Источник: выполнение DK-1741, 2026-11-20. Запуск через native collaboration spawn не вызывал `hooks/agent-watch.py`, поэтому запись этапа DK-1741 оставалась пустой. Отдельная вычитка с меткой `DK-1741-proofread` получила автоматически развёрнутый шаблон bug с этапами всей разработки. Команда `agentctl plan done` требовала этап «разработка» при закрытии собственных пунктов вычитки.

В профиле codex предусмотрен путь `[delegate] mode=cli`. Команда `agentctl run DK-1741 --workdir /Users/rider/projects/devkit-dk-1741` запустила `gpt-6.1-sol` с effort `high`. Процесс `codex exec` работал с sandbox `workspace-write` и approval `never`. Он не смог записать `~/.devkit/plans` и `main/.git/devkit/draft-tx`, после чего завершился до правок кода. Журнал сохранён в `/private/tmp/DK-1741-exec.log`.

### Осложнение

При native-запуске реальное участие агента не учитывается через хук, а отдельный план вычитки требует чужие этапы. Предусмотренный профилем CLI-запуск останавливается на записи служебных данных до разработки. Для продолжения исполнения пришлось вернуться к native-инструменту и отдельно сохранить правдивый след обоих путей в задаче.

### Вопрос

Какой путь делегирования должен поддерживаться для этого харнеса? Как учитывать реальных участников native-запуска и вести отдельные планы ролей? Как обеспечить штатную запись нужных служебных данных при CLI-запуске? Эти решения ещё не согласованы.

### Гипотеза

Предложение агента, пока не согласовано. Для Codex доступен согласованный путь делегирования, при котором исполнитель начинает разработку, сохраняет служебные данные и учитывается как реальный участник задачи. План отдельной вычитки отражает её собственную работу и закрывается по её результатам.

## Контекст обсуждения

Native-инструмент поддерживает `require_escalated` через auto_review. Поэтому исполнение DK-1741 продолжили native с правдивой записью обоих путей в файле задачи. Настройки харнеса и permissions не меняли. В этом черновике сохраняется препятствие для будущего разбора; способ исправления пока не выбран.
