# DK-192: Слияние из окна запускатора убивает окно: shipctl merge убирает worktree, в котором живёт сессия vscode. Корень это склейка жизни директории с жизнью задачи: дерево на задачу верно для одноразовых субагентов, а DK-175 отдал его долгоживущему интерактивному окну. Ход: копия на окно вместо копии на задачу. Вечный worktree ../devkit-glm, ветки задач переключаются внутри, merge вместо удаления дерева переводит копию на detached HEAD слитого коммита и освобождает ветку. Подписка привязывается к директории (.claude/settings.local.json из машинного слоя, в gitignore), а не к переменной запуска; code без -n, чтобы окно было одно; поставщик виден в заголовке окна. Наблюдение с живого случая IRC-097.

записан 2026-08-08

## Черновик

Живой случай IRC-097: сессия окна запускатора позвала `shipctl merge`, merge по
дизайну убрал worktree и ветку, а окно vscode жило ровно в этом дереве. Рабочий
каталог исчез из-под живого окна, расширение claude упало (ReferenceError про
native binary, настоящая причина это удалённый cwd), окно дохлое, в джамплисте
vscode остался мёртвый путь.

Корень не в merge, а в склейке жизни директории с жизнью задачи. Дерево на
задачу проектировалось под субагентов: диспетчер сидит в основном чекауте,
деревья одноразовые, merge зовётся из main, и самоуборка там нужное свойство.
DK-175 переиспользовал ту же механику под интерактивное окно, у которого
жизненный цикл другой: окно переживает задачу. Палиативы (предупреждение при
cwd внутри удаляемого дерева, ключ --keep-tree, правило «слияние из окна не
звать» в доке) лечат симптом и держатся на дисциплине, склейку они не рвут.

Ход: копия на окно вместо копии на задачу. `shipctl code` заводит вечный
worktree `../devkit-glm` (имя от каталога конфига подписки, `git worktree add
--detach`) один раз и дальше всегда открывает его; ветка задачи заводится тем
же путём, что в start, и переключается внутри копии. Merge как и сейчас идёт в
основном чекауте, но вместо removeWorktree переводит копию на detached HEAD
слитого коммита, после чего ветка ни в одном дереве не занята и `git branch -d`
проходит. Окно живёт, cwd на месте, под ногами слитое состояние main, следующая
задача берётся из того же окна. Субагенты batch не трогаются: у них остаются
одноразовые деревья с текущей уборкой, окна там нет.

Требования к окну. Окружение привязывается к директории, а не к способу
запуска: окно, открытое из дока или «Open Recent», теряет экспортированный
`CLAUDE_CONFIG_DIR` и молча уходит на дорогую подписку, поэтому при заведении
копии в неё кладётся `.claude/settings.local.json` с ключами ANTHROPIC_BASE_URL,
ANTHROPIC_AUTH_TOKEN, ANTHROPIC_MODEL из машинного слоя
`~/.devkit/claude-glm/settings.json`; файл в gitignore, расхождение с машинным
слоем ловит doctor с починкой через --fix. Окно одно: `code` без `-n`, повторный
вызов фокусирует живое окно, а не плодит дубли. Поставщик виден в заголовке:
имя директории уже говорит `devkit-glm`, явный ярус это `window.title` вида
«[GLM] devkit» в `.vscode/settings.json` копии, тоже гитигнорнутом.
`CLAUDE_CONFIG_DIR` перестаёт быть несущим, класс ошибок «переменную забыли»
исчезает целиком.

Развилки исполнителю: чистота копии при переключении задач (черновики прошлой
задачи это отказ с перечнем файлов, а не молчаливый перенос в новую ветку);
ревьювер на занятой ветке (второе окно берёт её только detached, разбор
«дерево задачи занято» в board-team переписывается под копии окон); уборка
старых деревьев `devkit-dk-<id>` от интерактивных запусков (один раз руками
либо находка доктора); дока запускатора и board-ship под новый жизненный цикл.
