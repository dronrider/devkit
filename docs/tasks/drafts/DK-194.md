# DK-194: Карта проектов: генерённая из кода карта уровня модулей для контекста сессий

записан 2026-08-09

## Черновик

Карта проектов: генерённая из кода карта уровня модулей для контекста сессий

Агент в начале задачи тратит квоту на поиски не в том направлении: знания о
том, где что лежит, разбросаны по коду и докам. Идея: devkit собирает карту
проекта сам и кладёт её в контекст каждой сессии.

Границы решения, к которым пришли в обсуждении:
- карта генерится из кода, а не пишется руками: адаптеры на экосистему
  (cargo metadata, go list -json ./..., модули python, fallback на дерево
  для скриптовых каталогов);
- однострочные описания модулей берутся из doc-комментариев уровня модуля
  (//! в Rust, package comment в Go, докстринг в Python); отсутствие
  описания это находка doctor;
- уровень функций и сигнатур в карту не тянуть: он протухает и раздувает
  контекст, а добывается по запросу через LSP;
- свежесть держит doctor (сверка карты с деревом), --fix перегенерит;
- доставка в контекст через тонкий файл харнеса, который devkitctl уже
  генерит; целевой размер карты 40-60 строк.

Обязательное условие: до генерализации на все проекты POC на xr-proxy с
замером на цифрах. Пара типовых задач с картой и без, сравнить расход
квоты; замер ложится сценарием проверки, генерализация только если цифры
подтвердили экономию. Новый инструмент или подкоманда devkitctl: решение
про место и формат принимается в LLD.
