# DK-195: Символьный доступ к коду через LSP (MCP-сервер Serena) вместо grep

записан 2026-08-09
приоритет: средний

## Черновик

Символьный доступ к коду через LSP (MCP-сервер Serena) вместо grep

Символьные вопросы (кто зовёт функцию, сигнатуры большого файла, поиск
использований при рефакторинге) агент сейчас решает грепом: ложные
срабатывания на одноимённых методах и чтение больших файлов целиком.
LSP держит живой индекс и отвечает списком сигнатур вместо кусков текста.

Границы решения, к которым пришли в обсуждении:
- Serena регистрируется один раз в user scope (claude mcp add -s user) и
  действует на все проекты; сама поднимает rust-analyzer или gopls по
  языку проекта;
- набор инструментов урезать (find_symbol, find_referencing_symbols,
  get_symbols_overview), иначе схемы MCP съедят экономию контекста;
- роль devkit тонкая: doctor проверяет регистрацию сервера и наличие
  бинаря, как с хуками; своим кодом Serena не оборачивать, при поломке
  замена (mcp-language-server) втыкается в ту же розетку;
- строчка в правилах: символьные вопросы исполнитель задаёт LSP, а не
  грепу; на скриптах и конфигах остаётся grep;
- оговорка: холодный старт rust-analyzer на больших проектах десятки
  секунд, для коротких задач low-исполнителей накладные расходы могут
  съесть выигрыш.

Обязательное условие: POC на xr-proxy с замером на цифрах до включения в
правила. Пара типовых символьных задач с Serena и без, сравнить расход
квоты и время; замер ложится сценарием проверки, генерализация только
если цифры подтвердили экономию.
