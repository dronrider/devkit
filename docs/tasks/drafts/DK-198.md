# DK-198: goal-run через Agent SDK вместо разбора вывода claude -p

записан 2026-08-09

## Черновик

goal-run через Agent SDK вместо разбора вывода claude -p

Оболочка витков цели поднимает claude -p и судит о ходе по текстовому
выводу; тем же способом меряет резидент devkitctl weigh. Разбор чужого
текста это самое хрупкое место цикла: формат вывода не контракт и
меняется релизами харнеса. Claude Agent SDK даёт то же самое
программно: события сессии стримом, структурированный итог, хуки и
управление контекстом, а заодно открывает живой ход витка (смежные
черновики DK-117 и DK-136 упираются ровно в это).

Трейд-офф с правилом «ноль внешних зависимостей»: goal-run не уезжает
с машины и зовётся путём из чекаута, так что зависимость локальна и
голую машину потребителя не трогает. Открытые вопросы к груммингу:
- python или typescript вариант SDK и чем он ставится (кандидат
  doctor --fix рядом с tmux и terminal-notifier);
- переводить ли weigh тем же ходом или он остаётся на claude -p как
  замер именно текстового пути;
- деградация без SDK: цикл должен уметь работать по-старому, пока
  пакет не встал.
