## Черновик

Тест до реализации для новой функциональности (правка test-standard)

Сейчас скилл test-standard отпускает новую функциональность без красного
прогона: старого кода с багом нет, и красноту заменяют мутации. Но у
LLM-исполнителя есть характерный отказ, который мутации ловят поздно: тест,
зелёный и без фичи, то есть проверяющий существующее поведение или ничего.
Порядок «сначала тест, прогон, падение, потом реализация» отсекает это за один
прогон и заодно даёт проектирующее давление: интерфейс, написанный сначала со
стороны вызывающего, получается удобнее.

Состав правки:
- kit/skills/test-standard/SKILL.md, раздел «Тест на новую функциональность»:
  шаг про порядок (тест до реализации, прогон, падение) и оговорка про слабую
  красноту, когда тест падает сборкой из-за отсутствующей функции: такая
  краснота доказывает лишь, что тест зовёт новый код, мутации остаются.
- RULES.md, раздел «Тесты обязательны»: пункт с разбором, почему порядок важен
  именно для агента (пустой зелёный тест).
- tools/regcheck/README.md: заметка, что --base main годится и для красноты
  фичевого теста, с той же оговоркой.
- RULES.core.md не трогать: ядро уже говорит «правка едет вместе с тестами»,
  рубеж держат хук и regcheck.

Мелкий такт red-green-refactor по одному ассерту не брать: агент пишет код
крупными кусками, дробить его это церемония без выигрыша.
