# DK-272: Грумминг на обкатанных практиках: слои проверок, красные карточки и независимые критики

записан 2026-08-11

## Черновик

Грумминг на обкатанных практиках: слои проверок, красные карточки и независимые критики

Разбор 2026-08-11 на живом примере DK-136 показал четыре дыры процедуры
грумминга (LLD DK-129, скилл board-groom):

- вопросы пользователю привязаны только к слагаемым ранга, вопросов по сути
  задачи не рождается (сценарий проверки оставлен исполнителю, спрашивать не
  из чего);
- границ принятия и отклонения нет: что ни ответь, черновик едет строкой на
  доску, ответ двигает позицию, а не судьбу;
- ответ пользователя может менять предмет задачи (на DK-136 фраза про
  недоступность VSCode сдвинула предмет к управлению извне), а шага сверки
  предмета и DoD после ответов нет;
- каденции нет: накопитель в 25 черновиков без единого разобранного, заходы
  по настроению.

Чинить опорой на обкатанные практики, повёрнутые под агентную специфику
(грумер и автор один человек, роли играют субагенты, дорогое строго по
триггерам, квота бережётся).

Человеческий слой:

- INVEST + Definition of Ready: нынешние трое ворот достроить предпосылками
  (Independent, инвариант зависимости из RANKING.md уже есть, на воротах не
  спрашивается) и размером (Small: цена XL на воротах означает «сначала
  нарезать», ножи по SPIDR, а не оформить как есть).
- Example Mapping как формат разбора: мини-карта в файле задачи (2-4 правила,
  по паре примеров на правило), красные карточки уходят пользователю пачкой
  вопросов, зелёные становятся сценарием проверки в форме Given/When/Then.
- Pre-mortem для крупного, Ritual Dissent при готовом решении в черновике
  (половина накопителя записана решением вперёд проблемы).

Агентный слой:

- Ambiguity detection дешёвым фильтром каждому черновику, один вызов: слова
  без меры («быстро», «удобно»), скрытые допущения, недостающие негативные
  сценарии, конфликт с прошлыми решениями (греп по docs/lld и архиву доски,
  смежно с DK-201).
- Сверка черновика против правил как шаг ворот: черновик без «чем видно
  снаружи» ловится об правило «Фича доезжает до пользователя» механически.
- Независимый критик как одна ось, а не три практики: скептик для обычной
  задачи, pre-mortem для L/XL и сердцевины (автономный режим, выкат, доска),
  спор двух агентов с арбитром только для LLD с настоящей развилкой. Критик
  спавнится субагентом со свежим контекстом, не в сессии грумера.
- Страховка от сикофантии и от её близнеца: квоты «найди минимум N проблем»
  не ставить, находка обязана опираться на проверяемый факт (строка
  черновика, греп, прогон, пункт правил), «проблем нет» законен при
  перечислении проверенного. Арбитр красных карточек человек.

Сквозные границы:

- красных карточек больше трёх, значит строки нет: defer до ответов либо тип
  LLD;
- рядом с каждым вопросом пользователю называется ставка: что решает ответ
  (полосу серьёзности, судьбу черновика, DoD);
- пятиминутный taskctl draft ритуалом не обрастает: все слои живут на
  грумминге, вход записи мысли не трогается;
- каденция: находка в taskctl list или doctor про черновик старше недели,
  долг виден, а не вспоминается.

Куда правка: LLD DK-129 и скилл board-groom, находка возраста накопителя в
taskctl или doctor. Вероятный тип LLD: решений по маршрутизации и цене слоёв
несколько, и они спорные.
