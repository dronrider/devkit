# DK-275: Пользовательский Check держит очередь выката часами, при том что задачи с агентским сценарием закрываются за минуты: DK-272 держала очередь около девяти часов (ночь), DK-232 около семи, DK-223 около пяти, и каждый раз стояли несвязанные задачи. Два процессных кандидата на грумминг, оба поверх снятия блокировки слияний (черновик DK-274). Первый: двухступенчатый Check, очередь держится до прогона агентской части сценария после выката, а не до закрытия пользователем; приёмка глазами остаётся в Check и очередь не держит, по образцу уже принятого «приёмка с замечаниями очередь не держит», где непроверенный глазами код тоже остаётся на проде. Меняет смысл инварианта «непроверенный выкат один»: непроверенным считается выкат без прогнанного smoke, а не незакрытая задача; риск в том, что поломку, видимую только глазами, найдут после следующих выкатов, revert по ID задачи при этом остаётся. Второй: планирование окнами, taskctl batch и диспетчер отделяют задачи с пользовательским сценарием, катят их последним выкатом перед известным окном проверок и копят пачкой, чтобы один заход пользователя закрывал несколько; чисто процессная правка без изменения кода очереди.

## Черновик

Пользовательский Check держит очередь выката часами, при том что задачи с агентским сценарием закрываются за минуты: DK-272 держала очередь около девяти часов (ночь), DK-232 около семи, DK-223 около пяти, и каждый раз стояли несвязанные задачи. Два процессных кандидата на грумминг, оба поверх снятия блокировки слияний (черновик DK-274). Первый: двухступенчатый Check, очередь держится до прогона агентской части сценария после выката, а не до закрытия пользователем; приёмка глазами остаётся в Check и очередь не держит, по образцу уже принятого «приёмка с замечаниями очередь не держит», где непроверенный глазами код тоже остаётся на проде. Меняет смысл инварианта «непроверенный выкат один»: непроверенным считается выкат без прогнанного smoke, а не незакрытая задача; риск в том, что поломку, видимую только глазами, найдут после следующих выкатов, revert по ID задачи при этом остаётся. Второй: планирование окнами, taskctl batch и диспетчер отделяют задачи с пользовательским сценарием, катят их последним выкатом перед известным окном проверок и копят пачкой, чтобы один заход пользователя закрывал несколько; чисто процессная правка без изменения кода очереди.
