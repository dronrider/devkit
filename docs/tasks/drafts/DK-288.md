## Черновик

shipctl считает задачу осиротевшей по упоминанию её ID в чужом коммите: codeCommits (tools/shipctl/ops.go) ищет ID словом в subject, поэтому коммит соседней задачи «docs: DK-278 раскладка машинных файлов .devkit в README, пробел DoD №6 цели DK-137 снят» (1dbcac91, трогает tools/devkitctl/README.md, то есть не docs-only) записался в код задачи DK-137. DK-137 стоит в Check, и merge любой другой задачи отбивается словами «код в окне выката, а задача не в In progress: DK-137 в check». Поймано 2026-08-13 на слиянии DK-287: слияние встало до тех пор, пока чужую цель не закроют, при том что её собственного кода в окне нет. Кандидат: владельцем коммита считать первый ID в subject (правило доски ставит ID задачи в начало), а прочие упоминания в тексте не брать; либо сверять с записью раздела «Выкат» файла задачи, которая уже есть у codeCommits вторым источником.
