# DK-289: Кнопка «Закрыть» на дашборде поднимает сессию агента и молчит про это. Приёмка 2026-08-13: пользователь нажал «Закрыть» у DK-284, на экране ничего не изменилось; через несколько секунд нажал второй раз и получил «на доске devkit нет строки DK-284», хотя строка была видна, и пропала она только после ручного обновления страницы. По журналу дашборда видно, что первое нажатие поднимает tmux-сессию task-DK-284 с заказом «Закрой DK-284» (runPrompt для секции check, tools/dashboard/runs.go): сессия отработала, задача уехала в архив коммитом 830d54c4, а экран об этом не узнал. Три отдельные беды. Первая: для задачи, которую человек только что принял глазами, закрытие идёт через headless-сессию агента, то есть через минуты ожидания и трату квоты там, где хватило бы taskctl close; для агентского сценария сессия оправдана, для пользовательского нет. Вторая: нажатие не даёт отклика, поднятая работа не появляется на экране сама, и человек не знает, идёт ли что-то. Третья: отказ второго нажатия говорит «нет строки» вместо «задача уже закрыта, экран устарел», и это читается как поломка. Родственно DK-286 про непонятность кнопок запуска.
