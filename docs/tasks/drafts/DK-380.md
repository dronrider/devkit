dashboard: go-сюита тянет стену прогона команды test, 110-254 с на тест. По итогам цели DK-166 компонент go:dashboard остался самым тяжёлым звеном параллельного раннера: 254 с под общим прогоном (parallel.py, вся стена равна ему), 110-147 с в одиночку. ## Приписка 2026-08-28

Дело дошло до отказа. Под четырьмя работающими исполнителями компонент
go:dashboard разогнался до 605 секунд и упёрся в десятиминутный потолок
`go test`, прогон упал паникой «test timed out». Вместе с ним упало слияние
чужой задачи DK-366, где правился текст скилла вычитки: ворот готовности
гоняет весь набор.

То есть сюита дашборда теперь не только держит стену, она ещё и роняет
конвейер на занятой машине. Второй разряд починки к тем, что уже записаны
выше: пакету нужен свой потолок в вызове прогона, иначе разгрузка сюиты
остаётся гонкой с нагрузкой машины.
