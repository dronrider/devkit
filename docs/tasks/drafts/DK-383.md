# DK-383: Приоритет груминга накопителя: три уровня на глаз для черновиков drafts. Боль: накопитель дорос до 38 файлов, груммить всё подряд не хочется, а выбирать нечем. RANKING.md на черновик не ложится: слагаемые ранга оценивают задачу, которой ещё нет, ценность и рычаг считаются по кандидату решения, неопределённость у всех черновиков высокая по определению и различающего слагаемого нет. Ранг строки доски отвечает на вопрос «что исполнять», черновику нужен ответ на «что разбирать следующим», это другая ось. Решение: отдельная грубая шкала high/mid/low без чисел и без привязки к слагаемым RANKING, ставится на глаз автором при записи или любым проходом списка. Три уровня ставятся за секунду: маркировка не должна стоить дороже записи, иначе рухнет низкий порог черновиков. Не полосы серьёзности RANKING: приоритет разбора не сводится к серьёзности будущей задачи, идея с нулевой серьёзностью (структурированные отчёты, DK-199) может заслуживать разбора раньше мелкого бага, потому что открывает большую работу, а мелкий баг не гниёт. Механика по образцу defer: taskctl draft prio <ID> high|mid|low со снятием через --clear, опция --prio у самой записи; в файле черновика строка рядом с «записан»: «приоритет: высокий», русское слово в файле и печати, латинские имена в команде как у флагов; без даты постановки, возраст файла и так напечатан, переоценка это перезапись метки. draft list сортирует high, mid, low, затем немаркированные отдельной группой, отложенные вниз; внутри уровня по возрастанию ID как на доске; пометка в строке вида «DK-176 (9 дней, высокий)», её же несёт хвост taskctl list, --json получает поле prio. defer стирает метку: отложенный вне очереди по определению, второй приоритет ему не нужен. Метка не переживает черновик: при оформлении в строку ранг ставится заново по RANKING, переносить нечего. Скилл board-groom доезжает: разбор начинается с верха списка с учётом меток. Границы решения: черновики остаются одной кучей без секций и переходов, уровни не статусы; авто-гниения метки по возрасту нет, возраст и так напечатан рядом; немаркированный черновик нормальное состояние, как прочерк цены в бэклоге, а не долг; дашборд не трогаем. Состав правки: taskctl (команда, парсинг, сортировка, печать, json, справка, тесты в объёме defer), абзац про черновики в п. 5 RULES.board.md, правка скилла board-groom. Порядок внедрения: код раньше разовой чистки накопителя, иначе 38 меток придётся класть правкой файлов руками; проход по накопителю совмещает проверку живости (часть черновиков уже разрешилась сама и уйдёт в drop) и простановку меток единым жестом на свежем draft prio.
