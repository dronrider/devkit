# DK-395: Конвейер не встаёт на вопросе человека: парковка задачи, рубеж машинным состоянием и планировщик, который решает, что делать в освободившемся слоте

записан 2026-08-17
приоритет: высокий

## Черновик

Конвейер не встаёт на вопросе человека: парковка задачи, рубеж машинным состоянием и планировщик, который решает, что делать в освободившемся слоте

Сегодня вопрос человеку гасит всю петлю: `wait-human` это маркер витка цели, и
оболочка останавливает цикл на любом маркере кроме `continue`
(`kit/skills/goal-loop/goal-run.py`, MARKERS и STOP_KEY). Человек уехал на
выходные, и конвейер стоит целиком, хотя из четырёх штатных поводов
`wait-human` три относятся к одной задаче, а не к цели.

Замысел. Вопрос принадлежит задаче, а не циклу. Агент, упёршийся в трудность,
инициирует вопрос с адресом задачи, задача паркуется, а конвейер получает не
стоп, а повод выбрать работу заново: подождать заданный таймаут (человек может
быть за клавиатурой), потом посмотреть на своё состояние (сколько задач в
работе, что стоит на доске, что из этого не связано с ждущими ответа) и решить,
брать ли новую задачу или заняться подготовительной работой вроде груминга
накопителя. Ответ приходит когда придёт и возвращает в оборот свою задачу, а не
размораживает всё скопом.

Возврат при этом не автоматический. Ответ это повод принять решение заново:
конвейер детерминированно смотрит на состояние задачи и на состояние бэклога и
выбирает между «доделать» и «встать в очередь». Задача, у которой остались
тесты, доделывается без остановки; задача, брошенная в середине разработки при
полном бэклоге, ждёт своей очереди на общих основаниях. Привилегии перед доской
у припаркованной нет, частичный задел это довод в её пользу, а не пропуск без
очереди.

## Что уже есть и переиспользуется

- Парковка механически существует: `taskctl move <ID> blocked "причина"`, в
  тестах живут ровно такие случаи («ждём ответ хостера», «ждём железо»).
- Зависимости на месте: `taskctl dep add`, и `dep.go` не пускает в работу
  задачу с незакрытой предпосылкой.
- Вопрос с таймаутом написан: `goal-run --ask` кричит уведомителем, держит ящик
  признаком с внутренним сроком, опрашивает «Входящие» и по истечении срока
  возвращается без ответа, не залипая. Не хватает того, чтобы на это время
  конвейер уходил работать, а не спал в опросе.
- Ящик и почтальон (`hooks/inbox.py`), лента и чат дашборда.
- Потолок пачки по квоте (`agentctl budget`), отбор кандидатов
  (`taskctl batch`), поезд и очередь слияния (LLD DK-306).
- Этапы задачи с видом деятельности и временем начала лежат в
  `~/.devkit/runs/<ID>-<slug>.run`, среди видов есть `уточнение` с текстом
  вопроса, и дашборд их читает.

## Чего нет

1. Состояния «ждёт ответа» с пробуждением. `Blocked` терминальный: никто не
   следит за приходом ответа и не поднимает строку обратно. Нужна машинная
   причина, связь с вопросом и тик, который возвращает задачу в кандидаты;
   тикать умеет `devkitctl watch`.
2. Адреса у вопроса. Он живёт в ленте и ящике цели, поля задачи у него нет,
   поэтому ни разбудить именно её, ни отсечь её зависимые, ни собрать висящие
   вопросы в пачку нечем.
3. Достигнутого рубежа. Запись `.run` отвечает, чем задача занята, а решение
   «доделать или отложить» требует ответа, что уже готово: код написан, тесты
   зелёные, ревью пройдено, слито, выкачено. Плюс пакет этапов стирается на
   смене статуса, уезжая прозой в «Ход работы».
4. Полки работ для простоя. `taskctl batch` отвечает только на вопрос, какие
   задачи брать. Списка того, что всегда можно делать без человека (груминг
   накопителя до вопроса, вычитка, карта, дожатие тестов), нет.
5. Потолка незакрытых деревьев и потолка висящих вопросов. Без первого
   конвейер накопит хвостов, без второго человек вернётся к простыне вопросов
   вместо пачки.
6. Правил возврата к остывшей задаче: ребейз на уехавший main, свежий
   исполнитель, ответ человека в постановку.

## Формула выбора

Ранг не трогается: `RANKING.md` отказывается делить важность на трудозатраты
сознательно, и это про вопрос «что важнее вообще». Планировщик отвечает на
другой вопрос, «что делать в этом слоте сейчас», и цена там законна (раздел
«Цена исполнения» это прямо называет). Считается внутри полосы P, иначе дешёвый
P3 выдернет наверх P0 и сломается инвариант плюс-минус одной полосы.

Три слоя, не смешивать. Ворота булевы (незакрытая предпосылка, неопределённость
выше 1, нет цены, висящий вопрос без ответа, нет квоты на нужный ярус, дерево
или файлы заняты, выбран потолок деревьев, человек недоступен и путь упирается
в приёмку вида user). Счёт числом для прошедших ворота. Полка фона, когда после
ворот кандидатов нет.

    score = R / W,  внутри своей полосы P
    W = C * (1 - F) + V

R это ранг строки, C цена в пунктах, F доля пройденного пути, V плата за
возврат к остывшей задаче. Плата нужна потому, что припаркованная задача
дорожает сама: свежему исполнителю входить в контекст, ветку ребейзить на
уехавший main (`git rev-list main ^branch --count` считает расхождение машинно).

## Замер по 147 закрытым задачам

Маркерные коммиты доски дают секундные метки переходов («в работу», «замечания
ревью», «коммиты слияния», «в Check», «закрыта»). Активное время считается с
вырезкой простоев дольше 90 минут. Медиана активного времени задачи 56 минут.

| Фаза | Доля средняя | Доля медианная | Минут (медиана) |
|---|---|---|---|
| вход и основной код | 35.0% | 34.7% | 15.2 |
| доводка кода и тестов | 20.7% | 19.6% | 7.7 |
| ревью, слияние, выкат | 33.3% | 29.5% | 13.9 |
| приёмка | 11.0% | 4.1% | 1.4 |

Первую строку нельзя читать как чистую цену входа в контекст: первый коммит
кода несёт 69% всех строк задачи (медиана по 130 задачам), то есть до него
пишется основная работа. Честная формулировка: 35% времени уходит на всё, что
случается до первого коммита.

Доли по цене почти не расходятся (вход у S 36%, у M 35%, у L 27%), а сама цена
слабо предсказывает время: S медиана 47 минут, M 58, L 69. Отношение S к M это
0.81, тогда как курс квоты из `goal-cut` даёт 0.375. Расхождение не ошибка:
курс меряет расход токенов, замер меряет занятость слота. Ресурса два, и делить
надо на тот, который дефицитен.

Приёмка двухголовая: медиана 1.4 минуты (агентские сценарии), но 17 задач из
148 простояли в Check дольше часа, максимум 12.2 часа. Кругов ревью с
замечаниями: у 50 задач один, у 8 два, у 3 три.

Плата за возврат замерена прямо. Нашлось 9 задач с двумя заходами (возврат из
Check обратно в работу): второй заход стоит 52% первого (медиана 36.9 минуты
против 71), при том что делалась там правка по замечанию, а не задача заново. У
двух задач с паузой в 8-10 часов (DK-087, DK-284) возврат вышел дороже, вплоть
до случая, где второй заход дороже первого. Девять точек это не закон, но
направление видно: чем дольше задача стыла, тем дороже возврат.

Отсюда числа.

| Рубеж | F |
|---|---|
| строка заведена, дерево есть | 0.00 |
| первый коммит кода лёг | 0.35 |
| код и тесты готовы | 0.56 |
| ревью пройдено, слито, выкачено | 0.89 |
| приёмка пройдена | 1.00 |

Промежуточных узлов между ревью и выкатом нет сознательно: слияние с выкатом
занимают 0.1 минуты медианы. Все пять рубежей наблюдаемы машинно, и это важнее
стройности таблицы.

Цена C: курс квоты (S 0.75, M 2, L 5.5 пункта) при дефиците подписки и время
слота (S 0.8, M 1.0, L 1.2) при дефиците параллелизма.

Плата за возврат: `V = C * min(0.3 + 0.02 * h, 0.55)`, где h часы простоя. Даёт
0.35 при паузе в час и 0.46 при паузе в восемь.

Проверка на живых строках. DK-331, свежая S с рангом 42: `W = 0.8`, score 52.
Припаркованная M с рангом 40 после ревью (F 0.89), простоявшая сутки:
`W = 0.11 + 0.55 = 0.66`, score 61, доделываем. Она же, остановленная в
середине кода (F 0.45) после часа простоя: `W = 0.55 + 0.35 = 0.90`, score 44,
уступает свежей S и встаёт в очередь.

Неприятный вывод из чисел: хвост дорог. Задача после ревью с остатком в 11%
работы стоит две трети цены целой задачи, потому что повторный вход съедает
0.55. Значит главный выигрыш даёт не умный выбор между хвостом и новой задачей,
а недопущение хвостов: жёсткий потолок незакрытых деревьев и правило доезжать
до ближайшего рубежа перед парковкой стоят больше самой формулы. Формула нужна,
чтобы решение было объяснимым и одинаковым.

## Границы замера

Доли посчитаны по времени, а не по токенам, и для второго ресурса они могут
лежать иначе: ревью гоняет модель high, вход читает много файлов. Прямой счёт
по журналам сессий это черновики DK-377, DK-378 и DK-209; когда они закроются,
таблицу F стоит пересчитать в токенах и сравнить. Скрипт замера вложен ниже,
чтобы пересчёт был командой, а не разовой работой.

- DK-396 держит вторую половину того же разбора: чем меньше поводов звать
  человека после старта, тем реже конвейеру приходится парковать задачи.

## Что решать дизайном

Развилок столько, что предмет тянет на LLD с видом приёмки user по барьеру
«согласие»: где живёт рубеж и кто его двигает, как устроена парковка и
пробуждение, кто считает формулу (утилита или сессия), из чего собрана полка
фона, каковы потолки деревьев и висящих вопросов, что остаётся от `wait-human`
в `goal-loop`. Порядок реализации виден так: рубеж машинно, затем парковка с
пробуждением, затем планировщик, затем полка фона с потолками, затем отвязка
`wait-human` от стопа цикла.

## Скрипт замера

Считает таблицу фаз и плату за возврат по git-истории проекта. Гоняется из
корня репозитория, ничего не пишет.

```python
#!/usr/bin/env python3
"""Фазы конвейера по git-истории: доли рубежей и цена повторного захода."""
import re
import statistics
import subprocess
from collections import defaultdict

GAP = 90 * 60  # разрыв между коммитами задачи, дальше которого это простой
BOARD = re.compile(r"^docs\(tasks\)|^docs\(board\)")

log = subprocess.run(["git", "log", "--pretty=format:%at|%s"],
                     capture_output=True, text=True, check=True).stdout.splitlines()
byid = defaultdict(list)
for line in reversed(log):
    ts, subj = line.split("|", 1)
    for tid in set(re.findall(r"DK-\d+", subj)):
        byid[tid].append((int(ts), subj))


def marks(commits, pattern, tid):
    rx = re.compile(tid + r"[.\d]* " + pattern)
    return [ts for ts, subj in commits if rx.search(subj)]


def active(commits, a, b):
    """Активные секунды между метками: простои длиннее GAP не считаются."""
    pts = [ts for ts, _ in commits if a <= ts <= b]
    if len(pts) < 2:
        return min(max(b - a, 0), GAP)
    return sum(pts[i] - pts[i - 1] for i in range(1, len(pts))
               if pts[i] - pts[i - 1] <= GAP)


KEYS = ("вход", "код и тесты", "ревью, слияние, выкат", "приёмка")
shares, phases, totals = defaultdict(list), defaultdict(list), []
first_lap, second_lap = [], []
for tid, commits in byid.items():
    starts = marks(commits, "в работу", tid)
    checks = marks(commits, "в Check", tid)
    closed = marks(commits, "закрыта", tid)
    if not (starts and checks and closed):
        continue
    t0, tcheck, tclose = starts[0], checks[0], closed[0]
    if len(checks) > 1:  # повторный заход: цена возврата к остывшей задаче
        first_lap.append(active(commits, t0, checks[0]))
        second_lap.append(active(commits, checks[0], checks[1]))
    if not t0 < tcheck <= tclose:
        continue
    code = sorted(ts for ts, s in commits if t0 <= ts <= tcheck and not BOARD.match(s))
    if not code:
        continue
    rev = marks(commits, "замечания ревью", tid)
    dev_end = max([ts for ts in code if ts <= rev[0]] or [code[0]]) if rev else code[-1]
    p = {"вход": active(commits, t0, code[0]),
         "код и тесты": active(commits, code[0], dev_end),
         "ревью, слияние, выкат": active(commits, dev_end, tcheck),
         "приёмка": active(commits, tcheck, tclose)}
    total = sum(p.values())
    if total < 60:
        continue
    totals.append(total)
    for k, v in p.items():
        phases[k].append(v)
        shares[k].append(v / total)

print("задач в выборке: %d, медиана активного времени %.0f мин\n"
      % (len(totals), statistics.median(totals) / 60))
acc = 0.0
for k in KEYS:
    acc += statistics.mean(shares[k])
    print("%-24s доля ср %5.1f%%  мед %5.1f%%  минут мед %5.1f  рубеж F %.2f"
          % (k, statistics.mean(shares[k]) * 100, statistics.median(shares[k]) * 100,
             statistics.median(phases[k]) / 60, acc))
print("\nповторных заходов: %d, второй заход к первому: %.2f"
      % (len(second_lap), statistics.median(second_lap) / statistics.median(first_lap)))
```
