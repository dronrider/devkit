# DK-418: Глобальная точка правил ~/.claude/CLAUDE.md присвоена devkit целиком: личным добавлениям пользователя места нет

записан 2026-08-17
приоритет: средний

## Черновик

Глобальная точка правил ~/.claude/CLAUDE.md присвоена devkit целиком: личным добавлениям пользователя места нет

Наблюдение с чужой машины: у пользователя doctor выдал «~/.claude/CLAUDE.md
правлен руками, содержимое разошлось с хешем маркера: локальные добавления
перенести в RULES.local.md, файл убрать с дороги руками (mv ... .bak) и
повторить devkitctl doctor --fix». Он решил, что devkit хочет перезаписать
его основной CLAUDE.md.

Что на самом деле: check_global (tools/devkitctl/rules.py) держит для
глобальной точки харнеса эталон из шапки и одного импорта
@~/projects/devkit/RULES.core.md, и любую руками дописанную строку видит как
расхождение хеша. --fix файл нарочно не трогает, но находка висит навсегда,
пока пользователь не вынесет свои строки.

Дыра: вынести их некуда. RULES.local.md по RULES.md это файл про корп-контур
конкретного репозитория, подключается строкой в AGENTS.md проекта, а не
глобально. Личным правилам «на всю машину» (свой стиль ответов, привычки,
не связанные с devkit) devkit сегодня кармана не даёт: генерённая точка
везёт ровно один импорт, и файл харнеса, который по замыслу Claude Code
принадлежит пользователю, по факту забран devkit целиком. Текст находки при
этом отсылает в файл не того назначения.

Предлагаемое: генерённая точка везёт вторую строку импорта на личный файл
пользователя (например @~/.claude/CLAUDE.local.md), которого генератор не
трогает и не сверяет; клиент импорт в несуществующий путь молча пропускает,
так что пустой карман ничего не стоит. Текст находки «правлен руками»
отсылает туда, а не в RULES.local.md. Заодно проверить: имя файла на харнес
из профиля ([rules] user_file или подобное), а не зашитое; вес личного файла
считать в weigh; README раздел про глобальную точку и RULES.md пункт про
RULES.local.md поправить, чтобы два кармана не путались.
