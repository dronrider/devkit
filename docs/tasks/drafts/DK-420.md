# DK-420: Дока запускатора окна второй подписки не даёт порядка первого запуска с нуля

записан 2026-08-17

## Черновик

Дока запускатора окна второй подписки не даёт порядка первого запуска с нуля

Наблюдение пользователя 2026-08-17: в tools/shipctl/README.md есть разделы
«Окно на второй подписке», «Копия на окно, а не на задачу» и «Окружение
живёт в директории, а не в запуске», но по ним не понятно, как поднять окно
второй подписки на новой машине одной цепочкой команд. Читатель ищет «какую
переменную задать и чем запустить», а получает разбор устройства.

Что не так конкретно:

- порядок первого запуска разложен по трём местам и нигде не собран: ключ
  home секции [glm-code] в ~/.devkit/harness.local (shipctl/README.md, абзац
  про машинный слой), болванка каталога конфига от devkitctl doctor --fix и
  находки про пустые ключи (devkitctl/README.md, раздел доктора), значения
  ANTHROPIC_BASE_URL, ANTHROPIC_AUTH_TOKEN, ANTHROPIC_MODEL из кабинета
  подписки, потом shipctl code <ID>. Сводного «с нуля до открытого окна:
  шаг 1, 2, 3, проверка --dry-run и --probe» нет;
- вводный абзац раздела «Окно на второй подписке» объясняет рычаг через
  CLAUDE_CONFIG_DIR и экспорт переменной перед запуском, а раздел ниже
  говорит, что после DK-192 ключи лежат в самой копии в
  .claude/settings.local.json и окну переменная при запуске не нужна. Абзац
  остался от старой схемы, и две картины спорят друг с другом;
- откуда берётся имя поставщика (glm) и путь копии ../<проект>-glm, и что
  за файл kit/harness/glm-code.toml, читатель узнаёт из корневого README и
  devkitctl, а не из доки запускатора.

Чего хотим: в доке shipctl раздел про окно второй подписки открывается
списком «первый запуск с нуля» на новой машине (заведение машинного слоя,
doctor --fix, вписывание значений, shipctl code, чем проверить), из
которого на 100% понятно, что и в каком порядке делать, а разбор устройства
идёт после. Вводный абзац переписать под текущую схему (окружение в
директории копии, CLAUDE_CONFIG_DIR только там, где он ещё участвует).
Раздел доктора в devkitctl/README.md сослаться на этот порядок, а не
дублировать. Запуск без задачи не сюда: это DK-203, в доке дать на неё
отсылку или дописать вход без ID, когда она сделана.
