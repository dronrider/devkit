# DK-427: Вход в README trackctl: первый запуск, предусловие и вывод команд

записан 2026-08-17
приоритет: средний

## Черновик

### Ситуация

README trackctl сверен с правилом входа (RULES.md, п. 2 раздела
«Документация изменений», DK-421) 18.08.2026, поводом был вопрос про то, где
читать про корп-контур и смену статуса тикета. Первый раздел файла это
«Команды» (строка 21), перечень синопсисов вида `take <KEY>`. Предусловие
первого вызова, то есть контур `~/.devkit/tracker/<имя>.local` с адресом и
таблицей статусов, привязка `.devkit/tracker.local` и токен в переменной
окружения, лежит в разделе «Конфиг» на строке 188. Вывода команд в файле нет
ни одного: `trackctl status` упомянут прозой трижды, но что он печатает, не
показано. Единственный настоящий ключ тикета во всём тексте это `ABC-12` в
прозе строки 38, остальное плейсхолдеры. Сторож `devkitctl doctor` на этом
молчит: `entry.py` сверяет имя первого заголовка по списку, а «Команды» в
списке есть.

### Осложнение

Читатель, впервые открывший корп-контур, до первой команды по README не
доходит: он зовёт `trackctl issue`, получает отказ про ненастроенный контур и
идёт искать конфиг в конец файла либо в CONNECT.md. Отработала команда или
нет, по README тоже не понять, потому что успешного вывода `take` и `submit`
не показано, а на границе статуса это как раз то, что нужно сверить.
Собирается порядок работы сейчас из трёх мест: CONNECT.md, середина README и
код адаптера.

### Вопрос

Откуда брать вывод команд, если живого инстанса под рукой нет. Образцы в
`testdata/jira/` собраны из публичной документации Cloud v3, живьём проверено
только чтение по v2 на Server (DK-413), и сочинённый вывод в доке хуже
отсутствующего. Второй вопрос про сторожа: расширять ли `entry.py`, чтобы
раздел «Команды» первым не проходил там, где вход не написан, или это
остаётся барьером «глаза» из ACCEPTANCE.md.

### Гипотеза

Читатель с подключённым по CONNECT.md корп-проектом доходит от README
trackctl до первого настоящего перехода тикета, ни разу не заглянув в код и в
конец файла.
