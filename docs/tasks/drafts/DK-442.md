# DK-442: hooks/notify.py это два инструмента в одном файле, и второй попал в hooks/ по букве правила DK-139, а не по смыслу (разбор в черновике про правило языка того же дня). Хук-режим (--hook на Notification, Stop, SubagentStop, UserPromptSubmit) это законный вход харнеса. Аргументный режим (notify.py [--quiet] [--reason] [--task] [--project] заголовок текст) это CLI, который зовут уже собранные утилиты: tools/taskctl/notify.go, tools/shipctl/notify.go и tools/dashboard/runs.go держат по копии искателя пути hooks/notify.py (DEVKIT_HOME, корень, ../devkit, ~/projects/devkit), а лента дашборда (tools/dashboard/notifications.go) парсит журнал ~/.devkit/notify.log по словарю полей, записанному в python (log в notify.py). Формат журнала и правила поводов живут в двух языках, три go-утилиты зависят от чекаута devkit по фиксированному пути, и «до сборки» у аргументного режима не бывает: зовущий уже собран. Что сделать по образцу решения о почтальоне (LLD DK-430, решение 3): ядро уведомителя (выбор бэкенда, троттлинг, отметка ожидания, песочница, фокус окна, журнал с его словарём полей) переезжает в go пакетом internal/notify, команда в PATH (рабочее имя taskctl notify либо своя утилита, решает LLD или ревью по правилу «имя директории это имя команды») берёт оба входа: аргументный для утилит и --hook <протокол> для харнеса, доктор пишет её в settings.json по имени; taskctl, shipctl и дашборд зовут пакет напрямую, три искателя пути и notifyScript уходят; лента дашборда читает журнал через тот же пакет, а не по словарю-копии. Таблица протоколов hookio.py у остальных хуков остаётся: они законно живут в python. hooks/notify.py уходит целиком, вместе с notify_test.py и упоминаниями в README hooks и devkitctl. Наблюдаемость: бинарь не в PATH ловит доктор той же проверкой, что у остальных утилит; --self-test сохраняется. Цена: 825 строк python со своими тестами, три go-утилиты и дашборд; заводить после почтальона (DK-432), чтобы второй переезд шёл по обкатанной дороге internal/mail.
