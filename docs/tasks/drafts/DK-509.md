# DK-509: check-symbols --stdin не щадит testdata: коммит живого снимка отбит

записан 2026-08-24
приоритет: высокий

## Черновик

### Ситуация

Ситуация. check-symbols.py исключает из проверки файлы testdata: позиционный
режим и режим --hook зовут is_testdata(), и живые снимки событий харнеса
(hooks/testdata/claude-code/*.json) проходят с любыми символами, какие в них
попали от настоящего API.

Осложнение. Режим --stdin, которым скрипт зовёт pre-commit хук, is_testdata()
не применяет. На DK-172 это отбило коммит нового снимка turn-failed.json: в
тексте настоящей ошибки API стоит длинное тире, снимок обязан лежать как снят,
и обойти пришлось git commit --no-verify. Обход снимает проверку со всего
коммита разом, а не с одного файла, так что цена находки выше, чем кажется.

Вопрос. Почему исключение живёт в двух режимах из трёх: это недосмотр при
заведении --stdin или у режима хука были причины проверять всё подряд?

Гипотеза. Недосмотр, чинится переносом того же вызова is_testdata() в ветку
--stdin, с тестом на снимок из testdata, который до правки коммит отбивает.
