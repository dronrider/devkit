# DK-518: Хук check-reread отклоняет Read: файл читался в другой сессии

записан 2026-08-25
приоритет: высокий

## Черновик

### Ситуация

2026-08-24, ревью DK-181: ревьювер вызвал Read файла, hook check-reread
вернул отказ «файл уже прочитан в этой сессии», хотя в сессии ревьювера
файл до того не читали. Обход, найденный на месте: чтение другого файла.

### Осложнение

След чтений утёк между сессиями: новая сессия получает отказ за чужие
чтения, и ревьювер обходит хук косвенным чтением. На чужом прогоне это
выглядит как запрет на работу с файлом в новой сессии.

### Вопрос

Где check-reread хранит след прочитанных файлов и по какому ключу
привязывает его к сессии: почему одна сессия видит чтения другой?

### Гипотеза

Чтения разных сессий не пересекаются, и Read в новой сессии проходит
без отказа.
