# DK-541: Сторож прозы считает двоеточия строк ранга и бьёт по форме файла задачи

записан 2026-08-26

## Черновик

### Ситуация

check-prose режет текст на предложения, снимая маркер списка (LIST_RE в
hooks/check-prose.py:107), а сам пункт считает обычной фразой. Разделы «Ранг» и
«Приёмка» файла задачи состоят из строк вида «Серьёзность 25: причина» и
«- вид: agent», и такую форму диктует TASKFORM.md. Замер 2026-08-26 по
docs/tasks/*.md: блокировку «двоеточие в середине фразы» бьют 46 файлов из 98.

### Осложнение

Сторож наказывает за форму, которую проект требует сам. Автор файла задачи
видит блокировку, которую нечем снять: убрать двоеточие из строки ранга значит
сломать форму, а оставить значит коммитить с красным хуком. Красный хук,
который все привыкают проходить насквозь, перестаёт держать рубеж и там, где
проза действительно сбилась на шаблон.

### Вопрос

Считать ли строку списка с двоеточием после короткого зачина отдельным видом
текста и выводить её из метрики целиком, или же выводить из счёта именно
разделы «Ранг» и «Приёмка» по имени заголовка. Первое переносимо на другие
проекты, второе знает про devkit и его форму.

### Гипотеза

Метрика двоеточий считается по прозе, а не по спискам вида «зачин: причина», и
файл задачи с каноническими разделами хук проходит молча. Пороги при этом не
двигаются: замер по тому же корпусу должен показать, что на настоящей агентской
прозе сторож ловит столько же, сколько ловил.
