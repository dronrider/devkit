# DK-567: Правка правил и скиллов едет с прогоном стенда, как правка кода с тестом

записан 2026-08-28
приоритет: высокий

## Черновик

### Ситуация

Ядро правил, скиллы и определения субагентов правятся вычиткой. Скилл
prompt-test зовётся по порогу повода и по желанию сессии, а obeycheck
гоняется руками. Правка кода без тестов считается незакрытой, и это держат
хук check-tests и ворота слияния. Для текста, который читают агенты, такого
рубежа нет.

### Осложнение

Строка ядра, которая ничего не меняет в поведении, живёт в контексте
каждой сессии годами, и никто её не найдёт. Правка скилла, которая ухудшила
послушание, замечается по чужим сессиям спустя недели. Цена резидента
растёт без цифры, что за неё куплено.

### Вопрос

Сколько стоит прогон на пункт и какой порог красноты считать регрессией.
Гонять на каждый коммит или на слияние задачи, которая трогает файлы
агентов. Как хранить сценарии, чтобы они лежали рядом с пунктом правила.

### Гипотеза

У каждого пункта ядра и у каждого скилла есть сценарий obeycheck рядом.
Дифф по файлам, которые читают агенты, без сценария в диффе отбивается
теми же воротами, что правка кода без теста. Прогон на слиянии сравнивает
послушание с базой и краснеет при просадке. Пункт, без которого послушание
не падает, показывается находкой doctor как кандидат на удаление.
