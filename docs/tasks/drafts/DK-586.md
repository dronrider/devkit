# DK-586: Маска doctor --fix съедает бэкслеш и бьёт settings.json

записан 2026-08-29

## Черновик

### Ситуация

2026-08-28 devkitctl doctor --fix заменил литеральные токены в allow-правилах
~/.claude/settings.json маской __TRACKED_VAR__. В правилах вида
Bash(curl -H \"Authorization: Bearer <токен>\" ...) замена захватила
экранирующий бэкслеш закрывающей кавычки: \" превратилась в ", строка JSON
оборвалась. Побилось шесть правил (Bearer у Jira, PRIVATE-TOKEN у GitLab),
файл перестал парситься. Замечено 2026-08-29: claude на старте показывал
диалог Settings Error вместо строки ввода, из-за чего agentctl quota refresh
не мог снять панель /usage и отказывал «не отрисовал строку ввода за 20s».

### Осложнение

Битый settings.json выключает все настройки файла целиком (клиент его
пропускает), а снимок квоты молча протухает: корректор pick теряет сдвиг
вверх, и это видно только по хвосту «снимок протух» в вердиктах. Чинить
пришлось руками, восстанавливая бэкслеши по месту.

### Вопрос

Резать маску по границе токена (не трогая соседний бэкслеш) или после замены
валидировать JSON и откатывать правку с находкой вместо записи битого файла?
Годятся оба, второе страхует и от других огрехов замены.

### Гипотеза

doctor --fix после маскировки оставляет settings.json валидным JSON, а тест
гоняет замену на правиле с экранированными кавычками.
