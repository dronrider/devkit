# DK-586: Маска doctor --fix съедает бэкслеш и бьёт settings.json

записан 2026-08-29

## Черновик

### Ситуация

2026-08-28 devkitctl doctor --fix заменил литеральные токены в allow-правилах
~/.claude/settings.json маской __TRACKED_VAR__. В правилах вида
Bash(curl -H \"Authorization: Bearer <токен>\" ...) замена захватила и
экранирующий бэкслеш закрывающей кавычки. \" превратилась в ", и строка JSON
оборвалась. Побилось шесть правил (Bearer у Jira, PRIVATE-TOKEN у GitLab),
файл перестал парситься. Замечено 2026-08-29 по цепочке. Свежий claude
показывал на старте диалог Settings Error вместо строки ввода. Из-за этого
agentctl quota refresh не мог снять панель /usage и отказывал со словами
«не отрисовал строку ввода за 20s».

### Осложнение

Битый settings.json выключает все настройки файла целиком, клиент его
пропускает. Снимок квоты при этом молча протухает. Корректор pick теряет
сдвиг вверх, и видно это только по хвосту «снимок протух» в вердиктах.
Чинить пришлось руками, восстанавливая бэкслеши по месту.

### Вопрос

Резать маску по границе токена, не трогая соседний бэкслеш? Или после замены
валидировать JSON и при провале откатывать правку с находкой? Годятся оба,
второе страхует и от других огрехов замены.

### Гипотеза

doctor --fix после маскировки оставляет settings.json валидным JSON, а тест
гоняет замену на правиле с экранированными кавычками.
