# DK-601: Разбивку по моделям брать из кеша клиента, а не с экрана панели

записан 2026-08-29
приоритет: высокий

## Черновик

### Ситуация

Ситуация. Снимок квоты снимается разбором панели /usage в одноразовой
tmux-сессии (DK-010, DK-574, DK-584). Разбивку по моделям панель показывает не
всегда, и DK-584 научил снимок честно помечать её отсутствие.

Осложнение. Разбор DK-584 нашёл, откуда панель берёт цифры. Клиент кладёт ответ
эндпоинта в ~/.claude.json, ключ cachedUsageUtilization. Там limits[] с
weekly_all и weekly_scoped по моделям (Fable), проценты, даты сброса и
fetchedAtMs момента удачного запроса. Долгоживущая панель рисует именно этот
кеш. Свежий клиент съёмщика его не предпочитает. Он берёт общий бакет из
заголовков своих ответов, а разбивку теряет и пишет Per-model breakdown
unavailable. Отсюда расхождение, которое пользователь видел 2026-08-29. На его
экране Fable 10%, а в снимке той же минуты разбивки нет. 29 августа с 17:50 до
18:40 удачного запроса на машине не случилось ни одного, при этом снимок
освежается не чаще раза в 45 минут, то есть частота обращений тут ни при чём.

Вопрос. Не пора ли читать cachedUsageUtilization напрямую вместо разбора
нарисованного текста.

Гипотеза. Читать. Это машинный JSON того же происхождения, что цифры на экране,
без tmux, без клиента в подпроцессе и без разбора разметки, которая меняется с
каждой версией. Открытая развилка одна и важная. У кеша свой возраст
(fetchedAtMs), и момент снятия снимка обязан идти от него. Свежий taken над
старыми цифрами это та же молчащая ложь, от которой уходила DK-584. Панель при
этом остаётся запасным путём для харнесов без такого кеша.
