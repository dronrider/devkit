# DK-602: Мелочь в main без пуша запирает пуш доски всем сессиям

записан 2026-08-29
приоритет: высокий

## Черновик

### Ситуация

Ситуация. Правило доски пускает однокоммитный багфикс с тестом прямо в main и обещает, что такая мелочь уедет попутно со следующим выкатом. Хук pre-push пропускает пуш из сессии агента только по чистому диапазону origin/main..main: одна доска, без кода.

Осложнение. Доработка DK-584 в фазе Check легла в main коммитом f2f719a5 (7 файлов, 141 строка), доска следом закоммичена руками без --push. С этого момента каждый пуш доски из любой сессии отбит: мои чистые коммиты DK-428 ехали в одном диапазоне с чужим кодом. Ушло только через DEVKIT_PUSH_OK=1 руками. В автономном цикле цели это стоп конвейера: доска копится локально, сосед уходит вперёд, первый пуш кончается конфликтом. При этом taskctl set -m --push с любым изменением строки унёс бы тот же код без вопросов, так что рубеж стережёт форму команды, а не содержимое.

Вопрос. Как мелочь в main перестаёт запирать пуш доски и как это видно до отказа пуша.

Гипотеза. Два хода. Первый: мелочь коммитится и пушится одним движением командой shipctl push, которая пропускает диапазон, где каждый код-коммит несёт ID задачи не из Backlog; хук pre-push проверяет тот же критерий и голый код без ID отбивает по-старому. Второй: taskctl lint или devkitctl doctor печатает находку «main впереди origin на N коммитов с кодом» с именем коммита.
