# DK-604: pre-commit судит наличие тестов по имени файла, а не по региону

записан 2026-08-29

## Черновик

### Ситуация

Рубеж «правка кода без единого теста» на прогоне XR-202 сработал дважды
мимо цели. Коммит с правкой только док-комментария в трекаемом конфиге
отвергнут как код без тестов; коммит, целиком лежащий внутри модуля
#[cfg(test)] того же файла, отвергнут по тому же признаку, потому что
рубеж смотрит на имя файла, а не на регион правки. Оба обхода ручные:
перенос комментария в коммит с тестами и явное DEVKIT_NO_TESTS=1.

Тот же признак у ворот слияния: `shipctl merge XR-189` 2026-09-05 отбит с
«в диффе ветки против main нет тестовых файлов», хотя дифф несёт девять
`#[test]` в модуле `#[cfg(test)]` файла `xr-share/src/sync_cmd.rs`
(testsGate и isTestFile в tools/shipctl/advice.go судят по имени файла и
каталогу tests/). Обход штатный, пометка «Исключение: тесты» в файле задачи,
но пометка врёт по смыслу: тесты есть, ворот их не видит. Для Rust с
инлайновыми юнитами это каждая вторая ветка.

### Гипотеза

Рубежу нужен разбор региона: правка внутри #[cfg(test)] это и есть тест,
а правка комментариев и докстрингов не считается кодом.
