# DK-615: DK-503: диспетчер меряет продолжаемого субагента токенами, а не часами

записан 2026-08-30
приоритет: средний

## Черновик

### Ситуация

LLD DK-503 (решение 1) меряет срок жизни исполнителя временем с открытия этапа «разработка» через taskctl elapsed (DK-506 закрыта), доводка до exec-* и скиллов стоит в DK-511 и DK-507. Параллельно дашборд везёт приписку rotateRule: диспетчер меняет субагента, чей контекст перевалил порог exec_rotate_tokens (~/.devkit/harness.local) по subagent_tokens в уведомлениях. Разобрано 30.08, пользователь согласился на две меры по ролям.

### Осложнение

В чате диспетчер держит субагента через SendMessage и досыпает ему куски по ходу разговора; между кусками субагент простаивает, часы этапа идут, и на рубеже свежий по контексту исполнитель сдаёт хвост, хотя работал минуты. Мера по времени честна только для одиночного вызова без пауз. Снять rotateRule сейчас нельзя: другой работающей ротации нет.

### Вопрос

Куда переезжает порог из harness.local дашборда: ключ конфига devkit рядом с agentctl budget или строка RULES.board? Как диспетчер просит хвост у субагента перед сменой: репликой или это шаг exec-*?

### Гипотеза

В решении 1 LLD и в абзаце DK-507 стоят две меры: исполнитель в одиночном вызове меряет себя временем, диспетчер продолжаемого субагента меряет токенами по уведомлениям; сдача хвоста в «Ход работы» и подъём следующего через pick одни на обе. Порог живёт в конфиге devkit, приписка дашборда уходит.
