# DK-616: Реплика панели в tmux-сессию идёт через send-keys, сокет вне tmux

записан 2026-08-30
приоритет: средний

## Черновик

### Ситуация

Доставка реплики из панели дашборда (POC-дерево, chats.go около 2040) идёт тремя дорогами: сокет клиента первым (рамка «сообщение от другой сессии», from-name=dashboard), tmux send-keys запасным, вход .devkit/chat при ожидании taskctl ask. Из-за рамки заказу понадобилось channelRule («это человек, отвечай на вы текстом в ленту»); грумер DK-509 и чат 93828026 отвечали человеку в третьем лице. По документации (проверено 30.08) рамку сокета сменить нельзя, а без рамки и с побудкой сессии текст приходит только через tty (send-keys) или Remote Control.

### Осложнение

Все сессии, которые поднимает дашборд, живут в tmux, и для них рамки можно не иметь вовсе, а правило послушания подпирает выбранный порядок дорог. Сессии не из tmux (vscode, терминал человека) без сокета не слышны, и там рамка остаётся.

### Вопрос

Как отличить в момент доставки клиент на диалоге разрешений и замороженный терминал (send-keys глотается без эха), чтобы не ронять реплику молча; панель уже метит дорогу в chatSayDone.

### Гипотеза

Для tmux-сессий реплика человека приходит как его собственный ввод, без рамки и без правила; для остальных сокет с подписью, о которой devkit говорит соглашением в board-chat (подпись человека, а не имя приложения). Стенд: реплика в спящую сессию, в сессию на диалоге разрешений, в замороженный терминал.
