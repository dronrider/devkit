# DK-650: Ранг в форме задачи расходится со списком у задач с хвостом поправок

записан 2026-08-31
приоритет: высокий

## Черновик

### Ситуация

2026-08-31, разбор DK-643: список показывает ранг 64, форма задачи 38.
Разведка кода: taskctl list --json отдаёт хвост целиком (r, r_own,
adjustments; tools/taskctl/json.go:28-46), а boardRow дашборда
(tools/dashboard/tasks.go:35-91) объявляет только r и r_parts, поправки
выбрасываются на декодировании. Карточка ранга формы (static/app.js:3863)
рисует сумму пяти слагаемых и итог строки не использует. В карточке
«Связи» рода «от цели» нет (tools/dashboard/lld.go:183-189), выйти из
формы на задачу-источник подтяжки нечем.

### Осложнение

Пользователь видит два противоречащих числа у одной задачи (64 в списке,
38 в форме) без объяснения, и проверить наследование ранга из формы
нельзя: источник подтяжки ищется грепом по доске. Подсказка ячейки списка
(app.js:766-767) перечисляет слагаемые с суммой 38 под подписью «Ранг 64»
и тоже разницу не объясняет.

### Вопрос

Хватит ли карточке ранга строки вида «38 + M+1, подтянуто до 64 от
DK-565» с кликабельным ID, или подтяжку показывать и родом «от цели» в
карточке связей? Смоук-доска (smoke.go:77-85) вся из строк без хвоста,
поэтому расхождение прогонами не ловилось; нужен ряд с поправками.

### Гипотеза

Форма задачи показывает тот же итог, что список, с разбивкой на свои
слагаемые, бонус за цену и подтяжку, а ID источника подтяжки открывает
его форму одним кликом.
