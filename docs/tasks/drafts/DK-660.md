# DK-660: уборка чата груминга в архив снимает tmux-сессию нового чата задачи

записан 2026-08-31
приоритет: высокий

## Черновик

### Ситуация

2026-08-31, журнал ~/.devkit/agents.log. Груминг DK-652 шёл в tmux-сессии
task-DK-652. Запуск конвейера задачи в 16:50:20 снял остаток груминга и поднял
исполнителя в сессии с тем же именем task-DK-652. В 16:52:08 groomSweep убрал
чат груминга в архив, а chatArchive (tools/dashboard/chats.go) снял tmux-сессию
по имени из последней привязки архивируемого чата. Имя к этому моменту держал
уже конвейер.

### Осложнение

Исполнитель DK-652 погиб на середине хода, сразу после shipctl start. Чат
задачи полтора часа стоял без ведущей сессии, реплика «Продолжай работу»
лежала во входе недоставленной. Под удар попадает каждый запуск задачи следом
за грумингом той же задачи: между запуском и приходом groomSweep минуты.

### Вопрос

Сверять принадлежность перед kill, то есть последнюю запись реестра по этому
tmux против архивируемого чата, или развести имена tmux-сессий груминга и
конвейера?

### Гипотеза

Уборка в архив снимает только сессию, которая всё ещё ведёт архивируемый чат.
Чужая сессия под тем же именем продолжает работу.
