## Ситуация

По задаче XR-220 в xr-proxy прогонял regcheck по инлайн-файлу xr-android-jni/src/lib.rs. В тестах файла есть вызов parse_selection("{") со скобкой внутри строкового литерала, и эвристика подсчёта скобок, ищущая конец блока #[cfg(test)] mod, ответила «не нашёл закрывающую скобку блока mod, начатого на строке 1898» на корректно закрытом коде. README regcheck ограничение признаёт.

## Осложнение

База без маркеров тем же больна, то есть регрессионный тест по такому файлу инлайн-функцией не прогнать в принципе, а тестовые данные со скобками в репозитории законны. Исполнитель обходился выносом инварианта в tests/ на время прогона с возвратом назад, и такой обход легко забыть вернуть.

## Вопрос

Как подсчёту скобок в эвристике отличить код от строкового литерала: полный лексер или минимальной правки хватает?

## Гипотеза

Минимальной правкой хватает пропуска содержимого строковых, символьных и сырых литералов при подсчёте скобок; полноценный синтаксический разбор для эвристики избыточен.
