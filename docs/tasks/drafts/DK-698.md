# DK-698: shipctl start отводит ветку от названной базы

записан 2026-09-01
приоритет: высокий

## Черновик

### Ситуация

`shipctl start` отводит ветку задачи от главной ветки репозитория. Имя её
ищет `mainBranch` в `tools/shipctl/ops.go:115`, перебором ровно двух вариантов,
`main` и `master`. Другой базы у команды нет, флага тоже.

### Осложнение

В корп-контуре задача приходит привязанной к релизу. Живой случай такой.
Правка по CAP-2400 должна была отвестись от `Release-26.2.0`. Сканирование
SSDLC идёт по релизному образу, и до него правка из master не доедет.
Выразить это командой было нечем, и ветка ушла руками через
`git worktree add`, мимо всей обвязки `start`. Без имени по шаблону `branch`,
без дерева рядом с корп-клоном, без `trackctl take`.

Ручной отвод принёс и вторую беду. Точкой отвода в такой команде естественно
пишется `origin/Release-26.2.0`, а от remote-tracking ссылки git по умолчанию
(`branch.autoSetupMerge`) проставляет ветке upstream на эту же ссылку. Дальше
Sync из редактора отправил фичевую ветку прямо в релизную. Сам `start` в эту
яму не падает. `mainBranch` возвращает локальное имя, а от локальной ветки
автопривязки не бывает.

### Вопрос

Чем назвать базу отвода. Ключом `shipctl start <ID> --base <ветка>`,
умолчанием из привязки трекера или и тем и другим?

### Гипотеза

Ключ `--base` плюс умолчание для корп-контура. Релизная ветка тикета у трекера
есть, брать её оттуда дешевле, чем спрашивать каждый раз. Отвод от
remote-tracking ссылки идёт с `--no-track`. Иначе `--base` принесёт ту же
подмену upstream, что и ручной git.
