# DK-699: Пуш ветки в удалённую с другим именем отбивается рубежом

записан 2026-09-01
приоритет: средний

## Черновик

### Ситуация

Пуш в origin devkit стережёт хук `pre-push`: он отбивает пуш, запущенный из
сессии агента, а разрешение утилиты выдают переменной `DEVKIT_PUSH_OK=1`
(`tools/shipctl/README.md`, «Разрешение на пуш»). Ссылку, в которую идёт пуш,
хук не читает.

### Осложнение

Живой случай прошёл мимо рубежа целиком. Ветка `CAP-2400` имела upstream
`origin/Release-26.2.0`, и Sync из редактора отправил её туда. Пушил человек,
так что по праву пуша всё законно. Голый `git push` из терминала такой пуш бы
отбил сам, потому что при `push.default=simple` git отказывается пушить, когда
имя upstream не совпадает с именем ветки. Редактор пушит прямо в upstream и
этой защиты не касается. Коммит фичевой ветки сел в релизную без MR, и ни хук
devkit, ни утилита этого не заметили.

### Вопрос

Ставить проверку адреса в тот же `pre-push` или чинить только причину и не
давать заводить ветку с чужим upstream?

### Гипотеза

Проверка в `pre-push`. Расхождение имени локальной ссылки с именем удалённой
отбивается отказом с подсказкой. Причину чинит DK-698, но она закрывает
только ветки, заведённые через `shipctl start`, а руками ветки будут заводить
всегда.
Обход для намеренного случая нужен явный, вроде переменной рядом с
`DEVKIT_PUSH_OK`.
