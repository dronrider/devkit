# DK-705: run уводит делегата claude-code в раскладку раздавшего окна

записан 2026-09-01
приоритет: средний

## Черновик

### Ситуация

Ситуация
01.09.2026 делегирование DK-691 из сессии второй подписки (вердикт via:
claude-code) подняло подпроцесс claude с унаследованными CLAUDE_CONFIG_DIR
её каталога, ANTHROPIC_BASE_URL и ANTHROPIC_DEFAULT_OPUS_MODEL. Клиент
ответил предупреждением про глм-модель в каталоге моделей: opus из вердикта
развернулся в модель второй подписки, и делегат работал бы чужим эндпоинтом.

Осложнение
У claude-code.toml в секции [delegate] пар окружения нет вовсе, комментарий
исходит из того, что каталог у команды домашний. Это верно, пока раздающая
сессия сама на claude-code, а из окна второй подписки наследование привозит
её раскладку. Обратное направление закрыто: glm-code.toml кладёт делегату
CLAUDE_CONFIG_DIR своего домашнего каталога явной парой.

Вопрос
Где резать наследование: run снимает харнес-переменные раздавшего с любого
подпроцесса или профиль назначения объявляет явные пары на каждый случай.

Гипотеза
run снимает с подпроцесса харнес-переменные раздавшего (CLAUDE_CONFIG_DIR,
ANTHROPIC_MODEL, ANTHROPIC_BASE_URL, ANTHROPIC_AUTH_TOKEN и родню) всегда,
а пары из env профиля назначения кладёт после. Тогда профиль без пар получает
чистый домашний каталог, и дорога из второй подписки в claude-code работает
без правки профилей.
