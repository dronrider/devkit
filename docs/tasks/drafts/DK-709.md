# DK-709: дашборд пушит доску своим git push мимо предела и разрешения

записан 2026-09-02
приоритет: средний

## Черновик

### Ситуация

DK-697 завела пакет `internal/gitrun`: он закрывает интерактивный запрос учётки, ставит сетевым командам git предел времени и выдаёт хуку `pre-push` разрешение `DEVKIT_PUSH_OK=1`. На него переведены обе утилиты, которые пушат доску, `taskctl` и `shipctl`. Дашборд остался в стороне, у него свой `git push` в `tools/dashboard/board.go` под `CommitContext`. Замечено чтением кода при разборе DK-697, 2026-09-02.

### Осложнение

Насмерть он не виснет, свой предел и `WaitDelay` там стоят. Расходится другое. Список переменных окружения у дашборда собирается отдельно, и закрытие интерактивного запроса ему придётся дописывать руками при каждой правке. Разрешения `DEVKIT_PUSH_OK` он не выдаёт вовсе, так что пуш доски из дашборда живёт по другим правилам, чем тот же пуш из `taskctl`. Две копии одного решения расходятся молча, и следующая правка `gitrun` до дашборда не доедет.

### Вопрос

Переводить дашборд на `gitrun` целиком или вынести из пакета одно окружение, а запуск оставить дашборду со своим контекстом?

### Гипотеза

Пуш доски работает одинаково, откуда бы его ни позвали, и правка правил пуша делается в одном месте.
