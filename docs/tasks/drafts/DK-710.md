# DK-710: сторож прозы считает метрики по строкам, которые пишут утилиты

записан 2026-09-02
приоритет: средний

## Черновик

### Ситуация

На двух коммитах файла задачи DK-697 хук прозы выдал предупреждение по диффу. Первый раз средняя длина предложения 34,8 при пороге 23, второй раз двоеточие в середине фразы 26,0 на 1000 слов при пороге 19. Добавленные строки там были почти сплошь машинные. Три строки раздела «Ревью» пишет `taskctl review resolve`, по одной физической строке на замечание. Семь однострочных команд стоят в сценарии проверки. Блок «Проверки» печатает обкатка. По всему файлу метрики при этом укладываются во все шесть порогов. Замечено 2026-09-02.

### Осложнение

Переписать эти строки нельзя. На физической строке резолюции держится ворот слияния, на строках сценария держится прогон обкатки. Автор правки читает предупреждение и идёт искать свою прозу. Виновата машинная, и найти он ничего не может. Сторож на таком файле выдаёт предупреждение всегда, и цена ему падает. Следующее предупреждение, уже про живой текст, пролистают вместе с этим.

### Вопрос

Резать машинные строки по разметке раздела, по автору строки или считать дифф только по абзацам?

### Гипотеза

Предупреждение сторожа приходит на текст, который писал человек или агент, и молчит на строках, напечатанных утилитой.
