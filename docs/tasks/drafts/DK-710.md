# DK-710: сторож прозы считает метрики по строкам, которые пишут утилиты

записан 2026-09-02
приоритет: средний

## Черновик

### Ситуация

На двух коммитах файла задачи DK-697 хук прозы выдал предупреждение по диффу: сначала средняя длина предложения 34,8 при пороге 23, потом двоеточие в середине фразы 26,0 на 1000 слов при пороге 19. В добавленных строках там лежали три строки раздела «Ревью», которые пишет `taskctl review resolve` одной физической строкой на замечание, семь однострочных команд сценария проверки и блок «Проверки», напечатанный обкаткой. По всему файлу метрики при этом укладываются во все шесть порогов. Замечено 2026-09-02.

### Осложнение

Переписать эти строки нельзя. На физической строке резолюции держится ворот слияния, на строках сценария держится прогон обкатки. Автор правки читает предупреждение, идёт искать свою прозу и не находит её, потому что виновата машинная. Сторож на таком файле кричит всегда, и цена ему падает: следующее предупреждение, уже про живой текст, пролистают вместе с этим.

### Вопрос

Резать машинные строки по разметке раздела, по автору строки или считать дифф только по абзацам?

### Гипотеза

Предупреждение сторожа приходит на текст, который писал человек или агент, и молчит на строках, напечатанных утилитой.
