# DK-714: Новый чат панели выбирает проект в форме, есть вариант без проекта

записан 2026-09-02
приоритет: средний

## Черновик

### Ситуация

Разбор в сессии 2026-09-02 по коду `tools/dashboard/static/app.js`. Проект разговора панель берёт из адреса вкладки вида `<проект>/chat/<адрес>`. Существующий чат привязан к проекту записью реестра, и смена проекта в левой колонке его не трогает. Новый чат, чат задачи и общий чат доски рождаются в проекте из адреса. На «Главной» и в разделе «Агенты» проекта в адресе нет, и кнопка чата в шапке подставляет последний запомненный проект либо первый в списке (`currentProject`, `shownProject`). В шапке панели стоит задача, имени проекта там нет.

Подтверждение 2026-09-03 из авто-режима. При активном xr-proxy подняты chat-34 (про дашборд devkit) и chat-35, оба в авто-режиме, и turns.log показал по четыре остановки permission_prompt у каждого, все на командах, которые заходят в `~/projects/devkit`, `~/.devkit` и в чужие окна tmux при дереве xr-proxy. Хуки devkit решения ask не выдают, allow-правила не помогают: команды составные и каждый раз другие. Пока активным был devkit, те же команды проходили без вопросов.

### Осложнение

Человек не видит, в каком каталоге поднимется сессия по первой реплике. С «Главной» разговор уходит в проект, выбранный когда-то раньше, и агент читает чужие AGENTS.md и память. Заметно это уже по ответу агента, а сменить проект живой сессии нельзя, каталог задан при старте. Место в шапке панели кончилось. На телефоне в выпадающем списке чатов не помещается даже название разговора, и ещё один переключатель там не встанет.

Чат про один проект, поднятый с экрана другого, встаёт вопросом «Yes/No» почти на каждом ходу и без человека не двигается: классификатор авто-режима судит выход за дерево сессии, и дополнительные каталоги из настроек этого не снимают. Один активный проект в шапке диктует дерево всем новым чатам разом, и работа над двумя проектами в панели требует переключать шапку перед каждым новым чатом.

Уточнение 2026-09-03 после разбора DK-770. Остановки авто-режима вызывает не
выход за дерево сессии, а связка «cd <каталог> && <чтение по относительному
пути>» при deny-правилах Read из DK-228: Claude Code 2.1.259 (обновление ночью
2026-09-03) стал применять их к таким связкам, и классификатор не вычисляет
каталог после cd. Стоп воспроизводится и внутри своего проекта, выбор проекта
в форме его не снимает; чинит хук DK-770. Здесь остаётся сам предмет: выбор
проекта нового чата и запись «без проекта».

### Вопрос

Как назвать и где держать машинную запись «без проекта». Все ручки чата живут под `/api/projects/{p}/`, и проще всего завести в списке проектов запись с зарезервированным именем, путём в домашний каталог, без доски и префикса, скрытую с главной и из счётчиков. Обход транскриптов берёт каталог проекта вместе с каталогами, продолжающими его имя дефисом. Для домашнего каталога это все проекты машины разом, и машинной записи нужно точное совпадение каталога. Вход реплик такой сессии ляжет в `~/.devkit/chat` рядом с реестром, это стоит записать в доку дашборда.

### Гипотеза

У нового чата до первой реплики над полем ввода стоит строка «Проект» с меню из проектов левой колонки и пунктом «без проекта». По умолчанию в ней проект с экрана, откуда открыта панель, а с «Главной» и из «Агентов» сразу «без проекта». Сессия без проекта поднимается из домашнего каталога с глобальным CLAUDE.md и своей памятью, доски у неё нет. Строка выбора уходит вместе с первой репликой, шапка панели и выпадающий список не меняются.

Чат про devkit, заведённый с экрана xr-proxy с выбором проекта в форме, идёт в авто-режиме без вопросов классификатора на командах внутри devkit.
