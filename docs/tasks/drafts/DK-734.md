# DK-734: Корп-схема без ключа тикета оставляет коммиты кода без ID задачи

записан 2026-09-03
приоритет: средний

## Черновик

### Ситуация

Проект cozyphi подключён к devkit по корп-схеме: доска в боковой директории
cozyphi-local, в клоне редирект devkit.local. Трекера у проекта нет: в
.devkit/tracker.local есть repo, нет key и contour, origin это GitHub, а не
корп-хост из RULES.local.md. На задаче CP-001 2026-09-03 хук check-traces.py
отбил коммит кода с ID CP-001 в subject как след доски в корп-репозитории, и
исполнитель оставил subject без ID.

### Осложнение

RULES.board.core требует ID задачи в subject каждого коммита кода: по нему
shipctl merge, revert и состав поезда находят коммиты, а калитка shipctl push
(DK-602) отбивает код-коммит без ID. В корп-схеме ID подменяет ключ тикета, но
без трекера подменять его нечем, и задача ходит без опознавательного знака в
истории. shipctl start об этом предупредил строкой, а хук отбил коммит, то есть
два инструмента тянут в разные стороны.

### Вопрос

Считать ли корп-схему без ключа тикета законной раскладкой (домашний проект с
доской в боковой директории), и чем тогда метить коммиты кода: локальным ID,
как дома, или ничем, отключив зависимые от ID ворота?

### Гипотеза

У раскладки «доска сбоку, трекера нет» есть названный режим: ID доски в subject
разрешён, check-traces молчит, а shipctl merge, revert и push работают как в
домашнем проекте.
