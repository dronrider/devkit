# DK-736: check-commit.py не знает префикс docs, когда его нет в последней сотне

записан 2026-09-03
приоритет: низкий

## Черновик

### Ситуация

Хук check-commit.py берёт набор префиксов из последних ста коммитов проекта.
На задаче CP-001 2026-09-03 в клоне cozyphi коммит docs(claude): ... отбит как
неизвестный тип, хотя docs(tui), docs(plan) и docs(changelog) в истории есть,
глубже сотни. Исполнитель обошёл хук ключом --no-verify на одном коммите.

### Осложнение

Стандартный префикс conventional commits считается чужим из-за окна выборки, и
агент либо пишет доку под чужим префиксом, либо гасит хук. Каждый обход хука
это дырка, через которую проходит и настоящая ошибка.

### Вопрос

Расширять окно (вся история или 500 коммитов) или держать базовый набор
conventional commits (feat, fix, docs, test, chore, refactor, style, perf, ci,
build) поверх выборки?

### Гипотеза

Префикс из базового набора conventional commits проходит хук всегда, а выборка
из истории только добавляет проектные.
