# DK-750: выбор модели в чате панели не доезжает до сессии второй подписки

записан 2026-09-03
приоритет: высокий

## Черновик

### Ситуация

Пикер модели чата хранит выбор в памяти диалога (~/.devkit/chats/<sid>.json),
но сборщик команды chatCmd (tools/dashboard/chats.go:1548) для подписки не по
умолчанию не ставит --model вовсе, только --permission-mode auto. Модель сессии
берётся из ANTHROPIC_MODEL профиля второй подписки
(~/.devkit/claude-glm/settings.json), сейчас это glm-5.3. Тот же недострой в
groomCmd (tools/dashboard/drafts.go:484). Упущение закреплено тестом
TestChatCmdSecondHarnessOmitsModel (tools/dashboard/chat_test.go:789) и пунктом
README дашборда, мотив в комментарии: предупреждение unrecognized_model в панели
времён DK-269. Проба 2026-09-03: agentctl exec --harness glm-code -- claude -p
... --model glm-5.3-flash отвечает и выходит нулём; unrecognized_model это
жалоба клиента на незнание окна контекста модели, сессия поднимается.

### Осложнение

Ярус mini виден в пикере, но пути до клиента не имеет: сколько ни выбирай
glm-5.3-flash, чат идёт на glm-5.3. Замечено на живой работе: все сессии второй
подписки шли на glm-5.3 при выбранном в панели flash.

### Вопрос

Как снять предупреждение и вернуть честное окно контекста: modelOverrides или
behavesAs в настройках клиента, CLAUDE_CODE_MAX_CONTEXT_TOKENS, либо принять
предупреждение как есть. Отдельная развилка: смена модели живого чата второй
подписки заблокирована в UI, рамка devkit-remodel работает только для подписки
по умолчанию; тащить ли её в эту же задачу.

### Гипотеза

Новый чат панели поднимается на модели выбранного яруса, и поле модели в
транскрипте сессии совпадает с выбором пикера.
