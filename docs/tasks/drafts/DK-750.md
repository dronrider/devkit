# DK-750: выбор модели в чате панели не доезжает до сессии второй подписки

записан 2026-09-03
приоритет: высокий

## Черновик

### Ситуация

Пикер модели чата хранит выбор в памяти диалога, файл ~/.devkit/chats/<sid>.json.
Сборщик команды chatCmd для подписки не по умолчанию не ставит --model. Ставится
только --permission-mode auto, tools/dashboard/chats.go:1548. Модель сессии
берётся из ANTHROPIC_MODEL профиля второй подписки, сейчас это glm-5.3. Тот же
недострой живёт в groomCmd, tools/dashboard/drafts.go:484.

Упущение закреплено тестом TestChatCmdSecondHarnessOmitsModel и пунктом README
дашборда. Причина в комментарии названа. Предупреждение unrecognized_model
видели в панели времён DK-269.

Проба 2026-09-03 дала другое. Команда agentctl exec --harness glm-code -- claude
-p ... --model glm-5.3-flash ответила и вышла нулём. unrecognized_model оказался
жалобой клиента на незнание окна контекста модели. Сессия поднимается.

### Осложнение

Ярус mini показан в пикере. Дороги до клиента у него нет. Все живые сессии
второй подписки шли на glm-5.3 при выбранном в панели flash.

### Вопрос

Как снять предупреждение и вернуть честное окно контекста. Вариантов несколько.
Клиенту можно объявить модель через modelOverrides или behavesAs. Можно задать
CLAUDE_CODE_MAX_CONTEXT_TOKENS. Можно смириться с предупреждением.

Вторая развилка рядом. Смена модели живого чата второй подписки заблокирована
в UI. Рамка devkit-remodel работает только у подписки по умолчанию. Тащить ли
её в ту же задачу.

### Гипотеза

Новый чат панели поднимается на модели выбранного яруса. Поле модели в
транскрипте сессии совпадает с выбором пикера.
