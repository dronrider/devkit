# DK-752: Рубеж ревью судит пуш по репозиторию сессии вместо репозитория пуша

записан 2026-09-03
приоритет: высокий

## Черновик

### Ситуация

Пуш доски из боковой директории корп-контура отбит хуком `check-review.py`.
В тексте отказа стоит диапазон HEAD..HEAD с вершиной клона кода, хотя команда
шла из репозитория доски. Поймано 2026-09-03 на задаче проекта cap_autotests,
отказ дословно `fatal: Invalid revision range 1a15b048..1a15b048`.

### Осложнение

Коммит доски по правилу уходит в origin сразу и без просьбы, а рубеж его не
пускает и советует ревью, которого коммиту доски не нужно. Обход остаётся один,
ставить `DEVKIT_PUSH_OK=1` в каждую команду, то есть подписывать разрешение
пользователя там, где пользователь ничего не разрешал. В корп-контуре доска
лежит боковым репозиторием всегда, и под рубеж попадает каждый её пуш.

Рядом вылезло второе. Разбор команды не отличает текста от команды, поэтому
черновик про этот же рубеж не записывался, пока имя команды стояло в теле
heredoc.

### Вопрос

Брать репозиторий из рабочей директории того куска команды, где стоит вынос
кода наружу (с учётом `cd` и `git -C`), или звать `shipctl push --check-only`
с явным путём? Отдельно, как отличать команду от текста, который она несёт на
вход.

### Гипотеза

Рубеж судит репозиторий, в который идёт вынос, и коммит доски из боковой
директории уходит без `DEVKIT_PUSH_OK`.
