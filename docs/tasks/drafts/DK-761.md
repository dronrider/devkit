# DK-761: пропавший проект в ~/go.work валит go-команды в каталоге devkit

записан 2026-09-03
приоритет: средний

## Черновик

### Ситуация

2026-09-03, прогон тестов задачи DK-751 из корня ~/projects/devkit: go test
ушёл ошибкой про модуль вместо результата. В ~/go.work перечислены
./projects/devkit-poc-chat/tools/dashboard, ./projects/gows/projects/UCS-TOOLS/moaigate
и ./projects/wal, каталога devkit-poc-chat на диске нет. Сам devkit в go.work
не входит, файл лежит на уровень выше проекта и подхватывается любой
go-командой из него. Обход в обвязке стоит, команды тестов проекта ходят
с GOWORK=off.

### Осложнение

Свежая сессия без знания про GOWORK=off принимает чужой файл за поломку
тестов самой задачи и тратит круг на разбор. Каждая новая задача платит эту
минуту заново.

### Вопрос

Чистить мёртвые use-записи вручную или научить devkitctl doctor находить
записи без каталога?

### Гипотеза

go-команды из корня devkit работают без обёртки GOWORK=off.
