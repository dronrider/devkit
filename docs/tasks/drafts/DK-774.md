# DK-774: ship проверяет ворота приёмки до деплоя, не после

записан 2026-09-03
приоритет: высокий

## Черновик

### Ситуация

2026-09-03 18:51 тик сторожка разлил поезд с DK-758. Деплой прошёл, тег deployed уехал, дашборд перезапустился. Перевод доски отказал. Из журнала сторожка (`~/.devkit/goal-watch.log`):

    выкат прошёл, но доска не переведена: taskctl move: DK-758: у барьера «доступ» обходов 4, а перебор в «Приёмка» имеет строк 0

Ворота приёмки задачи `cmdShip` спрашивает после команды деплоя, в блоке перевода строк.

### Осложнение

Код DK-758 на проде, строка в In progress, в разделе «Выкат» файла задачи нет записи о выкате. Поезд после сдвига тега пуст, повторный разлив ничего не делает. Строку восстанавливают руками. Сессия DK-758 и человек узнали об этом через два часа, из разбора журнала.

### Вопрос

Отказывать всему поезду на одной сломанной задаче или катить остальные? Отказ целиком проще, состав ждёт починки файла. Дописать запись о выкате до move, чтобы отказ ворот оставлял след в файле.

### Гипотеза

Ворота приёмки каждой задачи состава проверяются до команды деплоя, вместе с чистотой дерева. Сломанные ворота отбивают ship до того, как что-то уехало на прод.
