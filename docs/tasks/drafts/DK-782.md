# DK-782: Упавший merge оставляет временные деревья, shipctl status их перечисляет

записан 2026-09-03
приоритет: низкий

## Черновик

### Ситуация

После серии упавших прогонов `shipctl merge DK-770` (тесты красные по нагрузке) и нескольких `regcheck` в `git worktree list` осталось десять detached-деревьев в системном временном каталоге: семь `shipctl-merge-*/tree`, три `regcheck-*/old`, одно `tmp.*/tree`. Каталоги на диске живые, 2026-09-03 23:35. `shipctl status` печатает каждое строкой «worktree: detached, задачи в работе нет».

### Осложнение

Каждое дерево это полный чекаут devkit на диске и строка шума в `shipctl status`. Копятся они тем быстрее, чем чаще merge падает. Удачный merge своё дерево убирает, упавший оставляет.

### Вопрос

Кто убирает дерево при провале. Либо сам merge и regcheck в ветке отказа (defer с `git worktree remove --force`), либо тик `devkitctl watch` подметает старые временные деревья по возрасту.

### Гипотеза

Провальный исход merge и regcheck снимает своё временное дерево так же, как удачный, а `shipctl status` не показывает деревья из системного временного каталога. Тест стенда: merge с красными тестами не оставляет записи в `git worktree list`.
