# DK-788: След regcheck сгорает от ребейза, который делает сам shipctl merge

записан 2026-09-04
приоритет: средний

## Черновик

### Ситуация

Ворот слияния у задачи типа bug спрашивает зелёный regcheck за время жизни
ветки. В DK-784 прогон был зелёным. Дальше shipctl merge пошёл ребейзом на main,
ребейз наткнулся на конфликт и откатился. После ручной пересборки ветки тот
же merge отбился словами «нет зелёного regcheck за время жизни ветки».
Коммит стал другим, а след остался при старом.

Merge отбивает по regcheck после того, как сам переписал ветку. Прогон
приходится повторять без единой правки кода. Стоит он недёшево, старое
дерево собирается заново и тесты идут дважды.

Вопрос: чем помечать прогон, чтобы ребейз его не гасил.

Гипотеза. Считать след по содержимому тестовых файлов и правки, тем же
отпечатком, каким обкатка сверяет сценарий. Ребейз содержимого не меняет.
Повторный прогон тогда нужен после настоящей правки.
