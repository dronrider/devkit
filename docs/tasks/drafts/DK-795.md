# DK-795: шаблон ветки корп-привязки с точкой даёт имя, которое git не примет

записан 2026-09-04
приоритет: средний

## Черновик

### Ситуация

Замечено при подключении корп-проекта authn 2026-09-04. В `.devkit/tracker.local`
лежит шаблон имени ветки, разворачивает его `corpBranchName`
(`tools/shipctl/corp.go:202`). Хвост подставляется на `{slug}`, а висящий
разделитель срезается одной строкой, `strings.TrimRight(out, "-")`. Обрезка
знает только дефис, потому что дефис стоит в шаблоне по умолчанию.

У authn в origin 132 ветки, и разделитель у них точка. Имён вида
`CAP-1630.oidc_metrics` там 43 против 5 через дефис. Шаблон `{key}.{slug}` для этого
проекта и надо ставить, но `shipctl start` без `--slug` соберёт по нему имя
`CAP-2929.`, а git ссылку с точкой на конце не создаёт.

### Осложнение

Привязку с любым разделителем, кроме дефиса, заводить нельзя. Заход без хвоста
падает на создании ветки. Обходится это тем, что `--slug` передают каждый раз
руками, и забытый флаг роняет `shipctl start` в середине захода. Поэтому в
authn шаблон оставлен умолчательным, и имена веток расходятся с конвенцией
команды.

### Вопрос

Срезать любой разделитель шаблона (последний символ перед `{slug}`) или
выкидывать пустой хвост вместе с ним ещё на подстановке?

### Гипотеза

Шаблон привязки с любым разделителем собирает годное имя ветки и без хвоста.
