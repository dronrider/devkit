# DK-802: check-sensitive считает секретом присваивание переменной token в Rust

записан 2026-09-05
приоритет: средний

## Черновик

### Ситуация

Отчёт исполнителя XR-189 (xr-proxy, 2026-09-04): хук `hooks/check-sensitive.py`
отбил коммит `xr-share/src/sync_cmd.rs` на двух присваиваниях переменной
`token`: справа стоят вызовы `to_string()` у той же переменной и `clone()` у
поля `session.token`. Метка хука «секрет со значением». Значения там нет,
справа идентификатор и вызов метода. Исполнитель обошёл `--no-verify`.
Повтор 2026-09-05 на коммите этого же черновика в devkit: хук отбил цитату
тех двух строк в markdown с той же меткой, пришлось пересказать их словами.

### Осложнение

Обход `--no-verify` снимает все рубежи коммита разом, а не один: вместе с
ложным срабатыванием мимо проехали check-tests и check-symbols. Рабочий код с
переменной token в Rust это любой клиент с Basic или Bearer, ложная тревога
будет на каждой такой правке и приучает нажимать обход не глядя.

### Вопрос

Где граница: литерал в кавычках справа от `=` это кандидат в секреты, а
идентификатор, вызов метода и поле структуры нет.

### Гипотеза

Хук отбивает только присваивание литералом (строка в кавычках, base64 или
hex нужной длины), а присваивание выражением без литерала пропускает; в
справке хука есть свой ключ обхода, чтобы не тянуться к `--no-verify`.
