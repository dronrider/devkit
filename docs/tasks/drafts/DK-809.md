# DK-809: ID удалённого черновика достаётся новой задаче, история путается

записан 2026-09-05
приоритет: средний

## Черновик

### Ситуация

На витке цели DK-565 2026-09-05 команда taskctl add выдала ID DK-801 задаче про
класс причины возврата. Тем же утром DK-801 был черновиком про sha в review
level: заведён коммитом a7c87eaaa, приписан к DK-753 коммитом 5e71d69c0 и удалён.
taskctl id выдаёт первый свободный ID и в историю коммитов не смотрит.

### Осложнение

По правилу доски ID в subject коммита это способ найти коммиты задачи, revert и
состав поезда. После переиспользования git log --grep DK-801 отдаёт вперемешку
коммиты черновика и коммиты новой задачи. Разбор отката читает чужую работу.
Случается это на каждом груминге, где черновик приписан к строке или удалён.

### Вопрос

Считать ли занятыми ID, встречавшиеся в истории коммитов доски, или хранить
занятые отдельным списком в самой доске.

### Гипотеза

Выданный однажды ID второй задаче не достаётся, и git log по ID отдаёт коммиты
одной работы.
