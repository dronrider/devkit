# DK-816: Строка цели несёт свой тип goal вместо префикса «Цель:» в заголовке

записан 2026-09-05
приоритет: средний

## Черновик

### Ситуация

Цель на доске заведена строкой типа task с ценой XL, а узнаётся по слову «Цель:» в начале заголовка. Так решено в LLD DK-079 (развилка «цель как строка доски против отдельной сущности»): новый тип пришлось бы протащить через taskctl, agentctl и lint, а заголовок не парсит никто, поэтому признак стоит ноль строк кода. Замечено 2026-09-05 при просмотре цели DK-713 на дашборде: в колонке типа у неё стоит task.

### Осложнение

Посылка «заголовок не парсит никто» не держится. Сегодня префикс «Цель:» проверяют двенадцать файлов без тестов: три в taskctl (view.go, ops.go, retclass.go) и девять в дашборде вместе с app.js. Скрытый тип уже есть, только живёт строковым сравнением заголовка, размазанным по двум утилитам, и каждое новое место повторяет ту же проверку. Форма файла у цели тоже своя (taskctl add не кладёт ей DoD), и исключение «кроме строк-целей» в RULES.board.md и коде выводится из заголовка, а не из колонки типа. Переименование заголовка руками ломает признак молча: строка перестаёт быть целью для утилит, а сторожа, который бы это отбил, нет.

### Вопрос

Оставлять ли слово «Цель:» в заголовке как человеческий маркер при типе goal, или тип его вытесняет и дашборд рисует маркер сам? Как переводить стоящие строки-цели: миграцией в taskctl lint --fix или разовой правкой доски? Нужен ли goal в agentctl pick отдельной веткой вердикта, или вердикт «сначала разбить» по цене XL остаётся как есть?

### Гипотеза

В колонке типа у цели стоит goal, taskctl add --type goal заводит файл цели по её форме без DoD, а утилиты и дашборд узнают цель по типу через одну функцию вместо дюжины сравнений префикса. Заголовок цели можно переименовать, не потеряв признак.
