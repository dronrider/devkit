# DK-819: пульс дашборда читает весь каталог записей ради одной задачи

записан 2026-09-05
приоритет: средний

## Черновик

### Ситуация

5 сентября 2026, профиль ручки GET /api/projects/devkit/pulse?task=DK-716 на
боевых данных: 64% времени в taskStages -> stage.List, которая глобит
~/.devkit/runs/*.run и открывает каждый файл, чтобы отфильтровать записи по
root, хотя нужна одна запись, а её путь известен через stage.Path. Ещё 19% в
chatEntriesFrom: на каждый из 80 транскриптов зовётся s.binds(), то есть
читается и разбирается весь реестр сессий (chats.go:860), хотя тот же реестр
уже прочитан в recs строкой выше. liveStages для доски читает каталог тем же
List на каждый запрос доски и экрана задачи.

### Осложнение

Клиент дёргает pulse каждые 5 с с каждого открытого экрана задачи, доску и
экран задачи тоже кругами. При чистом каталоге pulse отвечает 0,2-0,8 с, при
разросшемся секунду и больше, демон ест до 85% CPU на пустом месте.

### Вопрос

Хватит ли taskStages одного stage.Load по stage.Path, или запись задачи может
лежать под другим корнем (боковое дерево)? Держать ли liveStages кэш по mtime
каталога?

### Гипотеза

pulse и доска не открывают файлов, не относящихся к запрошенной задаче или
проекту, и время ответа pulse не зависит от числа записей в ~/.devkit/runs.
