# DK-819: пульс дашборда читает весь каталог записей ради одной задачи

записан 2026-09-05
приоритет: средний

## Черновик

### Ситуация

5 сентября 2026 снял профиль ручки GET /api/projects/devkit/pulse?task=DK-716
на боевых данных. 64% времени сидит в taskStages, а там в stage.List. Она
глобит ~/.devkit/runs/*.run и открывает каждый файл, а после отсеивает записи
по root. Нужна при этом одна запись, и путь к ней даёт stage.Path. Ещё 19%
уходит в chatEntriesFrom. Там на каждый из 80 транскриптов зовётся s.binds(),
и весь реестр сессий читается и разбирается заново (chats.go:860). Тот же
реестр уже лежит в recs строкой выше. liveStages для доски читает каталог тем
же List на каждый запрос доски и экрана задачи.

### Осложнение

Клиент дёргает pulse каждые 5 с с каждого открытого экрана задачи. Доска и экран
задачи тоже перечитываются кругами. При чистом каталоге pulse отвечает
0,2-0,8 с. При разросшемся каталоге ответ занимает секунду и больше, а демон
ест до 85% CPU.

### Вопрос

Хватит ли taskStages одного stage.Load по stage.Path? Запись задачи может
лежать под другим корнем, например у бокового дерева. Держать ли liveStages
кэш по mtime каталога?

### Гипотеза

pulse и доска открывают только файлы запрошенной задачи или проекта. Время
ответа pulse не зависит от числа записей в ~/.devkit/runs.
