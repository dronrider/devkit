# DK-820: Самопроверка правит боевой файл задачи в основном чекауте

записан 2026-09-05
приоритет: высокий

## Черновик

### Ситуация

Компонент board-task в раннере самопроверки гоняет живой taskctl rehearse против настоящего docs/tasks/DK-696.md в основном чекауте, а не против своей песочницы. После прогона в чекауте остаётся незакоммиченная правка вида «Обкатка не зачтена, 60 красных из 66 шагов»: обкатка шла в чужих условиях и, конечно, не сошлась.

Всплыло на DK-716, исполнитель откатил правку руками и сам чинить не стал, чужого предмета не трогая. Опасность тут не в самой строке, а в том, что прогон самопроверки пишет в боевые файлы: он идёт при каждом слиянии, и его след ловится случайно, когда кто-то смотрит git status.

Разобрать надо, чем гонять живой круг обкатки. У соседних компонентов раннера песочница своя, временный проект во временном доме, и board-task должен идти тем же путём, а не по живой доске.
