# DK-830: Каркас файла задачи от taskctl file уезжает коммитом move

записан 2026-09-06
приоритет: средний

## Черновик

### Ситуация

Задача XR-198 в xr-proxy, 2026-09-06. У строки, заведённой до правила про
файл задачи, файла не было. Порядок был `agentctl pick --record` (отказ:
файла нет), `taskctl file XR-198` (файл создан), `taskctl move XR-198
in-progress -m ... --push`. Коммит move унёс только `docs/TASKS.md`, а
`docs/tasks/XR-198.md` остался untracked. Дальше `shipctl start XR-198`
завёл дерево задачи от этого коммита, и файла задачи в дереве не оказалось,
а `agentctl pick --record -C <дерево>` снова отказал «файла задачи нет».

### Осложнение

Исполнитель обходит руками: `git add` и коммит доски в основном чекауте,
затем `rebase` ветки задачи. Без обхода дерево задачи стартует без файла, и
все команды, которым файл нужен (pick --record, review, move), отказывают из
дерева. Та же грабля записана в памяти сессий как известная, значит
повторяется.

### Вопрос

Должен ли `taskctl file` сам добавлять каркас в индекс (или коммитить его
коммитом доски), либо `move` при коммите брать все untracked файлы
`docs/tasks/<ID>.md` своей задачи?

### Гипотеза

После `taskctl file <ID>` и `taskctl move <ID> ... -m --push` файл задачи
лежит в том же коммите, что и строка доски, и дерево `shipctl start`
стартует с ним.
