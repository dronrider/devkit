# DK-832: Поиск чатов панели не находит разговор по слову из самого разговора

записан 2026-09-06
приоритет: высокий

## Черновик

### Ситуация

6 сентября 2026 искал в панели дашборда разговор про накопление черновиков и
погашение долга. Набирал в поле поиска шапки списка слова из самого разговора.
Список отвечал «по запросу ничего не нашлось». Разговор нашёлся грепом по
транскриптам, файл
~/.claude/projects/-Users-rider-projects-devkit/ed82119c-0f1e-474c-b066-30568b3668d2.jsonl.
Заголовок у него «Добавить ранжирование черновиков по приоритетам». Слова
«долг» в заголовке нет. Отбор живёт в chatDropOpen
(tools/dashboard/static/app.js, строки 8218-8224). Он сверяет запрос с
заголовком, ID сессии, задачами и именем проекта. Поле first сервер отдаёт,
строка списка его рисует. В отбор оно не входит.

### Осложнение

Разговор помнят по тому, о чём в нём говорили. Заголовок слеплен из первой
фразы и этих слов обычно не несёт. Поиск отвечает пустотой на верный запрос.
Человек уходит гнать grep по ~/.claude/projects руками.

Рядом стоят два соседа. Пустой запрос режет архивные положением кнопки
(chatArchShown, app.js:7652). Набранный запрос ищет по всем, включая архивные.
Одно множество ведёт себя до и после первого нажатия по-разному. Второй сосед
это горизонт. chatEntriesFrom читает шапки не глубже chatAllLimit = 160
транскриптов (chats.go:675 и 829). На живой машине это примерно две недели.
Кнопки «показать раньше» при наборе запроса нет вовсе (app.js, условие
`if (!q && st.older && st.days && !loading)`). До разговора постарше не
дотянуться ни поиском, ни рукой.

### Вопрос

Чем искать по телу разговора. Держать индекс на машине или читать транскрипты
по запросу. Что делать с горизонтом 160. Двигать потолок или пустить поиск
отдельной ручкой мимо списка.

### Гипотеза

Разговор находится в панели по любому слову, которое в нём звучало. Возраст
разговора и положение кнопки архива на выдачу не влияют.

## Развилки

- «движок»: поиск по телу разговора идёт грепом по транскриптам в момент запроса или по индексу, который дашборд держит на машине?
  - решает: человек
  - рекомендация: греп по запросу без индекса: замер на машине 0.73 с по 160 свежим транскриптам и 3.7 с по всем 3358, индекс себя не окупает
- «горизонт»: потолок chatAllLimit=160 при наборе запроса остаётся или поиск идёт по всем транскриптам машины?
  - решает: человек
  - рекомендация: поиск идёт мимо потолка 160 по всей истории машины: 3.7 с терпимо, надпись «ищем по всей машине...» в списке уже стоит
- «место»: поиск по телу живёт в том же выпадающем списке панели или отдельной ручкой рядом с ним?
  - решает: человек
  - рекомендация: тот же список панели: отбор уезжает на сервер, а поле поиска и строки выдачи остаются прежними, второму экрану учиться незачем
- «тело»: телом разговора считаются реплики человека и агента или весь транскрипт вместе с выводом инструментов?
  - решает: человек
  - рекомендация: искать по репликам человека и агента, вывод инструментов и системные вставки мимо: иначе слово из чужого лога вытащит десяток лишних разговоров
