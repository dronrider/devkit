# DK-833: Дашборд заказывает заголовок чата у haiku, хотя он есть в транскрипте

записан 2026-09-06
приоритет: средний

## Черновик

### Ситуация

6 сентября 2026, на разборе того, почему разговор не ищется по заголовку.
readSessionHead (tools/dashboard/sessions.go:441) берёт заголовок харнеса из
записи с полем type = "summary". Claude Code 2.1.261 такой записи больше не
пишет. В каталоге ~/.claude/projects/-Users-rider-projects-devkit записей
type = "summary" ноль на 500 транскриптов. Строка вида
{"type":"ai-title","aiTitle":"..."} лежит в 361 файле. В транскрипте ed82119c
харнес назвал разговор «Ранкинг для черновиков в devkit». Дашборд этого имени
не видит.

### Осложнение

head.Summary остаётся пустым всегда. titleFor (chats.go:3645) уходит по
лестнице дальше. Сперва идёт эвристика первого предложения на месте, потом
фоновый заказ имени у haiku (titleOrder, не больше titleAskLimit заказов на
заход списка). Готовое имя лежит в том же файле даром. Панель платит за него
квотой. Имя появляется к следующему открытию списка. На ed82119c обе версии
видны рядом. Харнес назвал разговор «Ранкинг для черновиков в devkit», haiku
назвал «Добавить ранжирование черновиков по приоритетам».

### Вопрос

Читать ai-title вместо summary или наравне с ним. Кто старше, если в файле
окажутся оба. Ключ формата у харнеса свой и меняется без предупреждения.
Отсюда второй вопрос. Ставить ли сторожа, который заметит следующую смену.

### Гипотеза

Заголовок разговора берётся из транскрипта сразу. Он совпадает с тем именем,
которое показывает сам клиент. Haiku зовётся только там, где имени в файле нет.
