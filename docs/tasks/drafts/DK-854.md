# DK-854: Отметка прогона стенда ложится в файл задачи по cwd, а не по дереву

записан 2026-09-07
приоритет: средний

## Черновик

### Ситуация
Прогон с ключом `--task` пишет отметку в файл задачи того дерева, где стоит
текущий каталог, и ключ `--devkit` на адрес следа не влияет. Поймано
2026-09-07 на круге доработки DK-808: первый прогон положил отметку в файл
задачи основного чекаута вместо дерева ветки, потому что каталог субагента
между вызовами сбрасывается.
### Осложнение
След уезжает в чужое дерево незаметно: команда отвечает успехом, отметка
выглядит целой, а в ветке её нет, и ворота слияния потом отказывают по
отсутствию следа. Правится это возвратом чужого файла к HEAD и повторным
прогоном, то есть десятками минут и деньгами за сессии.
### Вопрос
Брать адрес файла задачи из того же ключа, что и дерево прогона, или отказывать,
когда каталог и дерево разошлись?
### Гипотеза
Отметка ложится в файл задачи того дерева, которое гонялось, откуда бы команду
ни позвали.
