# DK-858: Грязная сборка уезжает в PATH машины, а рубеж стоит только у update

записан 2026-09-07
приоритет: средний

## Черновик

### Ситуация
Суффикс `-dirty` вешает `git describe --dirty` в `tools/devkitctl/build.py:64`,
а рубеж на незакоммиченные отслеживаемые файлы стоит рядом, но у соседа:
его держит `devkitctl update` (`tools/devkitctl/update.py:692`). Сам
`devkitctl build` дерево не смотрит и молча кладёт бинарь с `-dirty` туда,
откуда его берут все сессии машины и launchd-агенты.
### Осложнение
Такую сборку не с чем сверить. По чистой версии находится коммит, и
расхождение бинаря с деревом видно глазами; за `-dirty` не стоит ничего, и
вопрос «из какого кода собрано то, что сейчас работает» остаётся без ответа.
Отбить грязное дерево у `build` тем же способом, что у `update`, нельзя:
сборка руками из рабочего дерева это нормальный ход разработки, ей бинарь из
незакоммиченного кода и нужен. Различать надо не грязь, а назначение сборки:
проба на своей машине против бинаря, который встаёт в PATH и переживает сессию.
### Проверка
Замечено 2026-09-06 на боевой службе дашборда, разбором черновика DK-848.
Сегодня уже не воспроизводится: живая служба отвечает чистой версией
`v0.12.0-5497-g819b376ab`, её переставил очередной выкат. Дорога, по которой
`-dirty` попадает в PATH, при этом осталась нетронутой.
