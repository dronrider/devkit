# DK-866: obeycheck на занятом каталоге прогона падает чужой ошибкой git

записан 2026-09-08
приоритет: низкий

## Черновик

### Ситуация

Каталог прогона стенда называется флагом `--work`, и стенд заводит там
заготовку проекта, для чего зовёт `git init`.

### Осложнение

Каталог, в котором прогон уже был, стенд принимает молча и падает позже
строкой «git commit: exit status 1, nothing to commit». Функция `seedRepo`
зовёт `git init` поверх готового репозитория. Про занятость каталога в
сообщении нет ни слова, и повторный прогон читается как поломка сценария.
Наступил на это исполнитель DK-861 и обошёл свежим каталогом на каждый прогон.

### Вопрос

Отбивать занятый каталог на входе внятной строкой или чистить его самому, раз
содержимое заготовки стенд и так кладёт целиком.

### Гипотеза

Отбивать на входе и называть каталог, а чистку прятать за отдельным флагом.
Молчаливое удаление чужого каталога опаснее лишней строки отказа.
