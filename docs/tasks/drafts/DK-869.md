# DK-869: obeycheck --task пишет след в основное дерево, а не в чекаут --devkit

записан 2026-09-08
приоритет: средний

## Черновик

### Ситуация

Прогон стенда зовётся из дерева задачи, чекаут называется ключом `--devkit`, а
след прогона стенд кладёт в файл задачи сам по ключу `--task`.

### Осложнение

Файл задачи стенд ищет от текущего каталога, а не от `--devkit`. Прогон DK-861
из дерева `devkit-dk-861` записал след в `docs/tasks/DK-861.md` основного
чекаута, где лежит main и доска. Исполнитель заметил чужую правку в основном
дереве, откатил её и перенёс блок следа руками. Незамеченная, она уехала бы в
коммит доски вместе с чем-то посторонним.

### Вопрос

Брать ли корень для файла задачи из `--devkit`, отказывать ли при расхождении
текущего каталога с чекаутом или писать след только рядом с прогоном.

### Гипотеза

Корень надо брать из `--devkit`, раз ключ уже назван. Прогон из чужого каталога
это обычное дело, и молчаливая запись в соседний чекаут опаснее отказа.
