# DK-878: runsguard валит полный прогон следом чужой сессии

записан 2026-09-08
приоритет: средний

## Черновик

### Ситуация

Замечено 2026-09-08 исполнителем DK-571. Полный прогон
`GOWORK=off python3 tools/devkitctl/parallel.py` упал на компоненте
`go:taskctl` строкой «прогон оставил след в настоящем /Users/rider/.devkit/runs:
DK-847-Users-rider-projects-devkit.run», хотя правка тестов таких файлов не
пишет. Файл в 19:53 положила живая соседняя сессия, ревью DK-847 в основном
дереве. Сторож считает своим следом любой новый файл настоящего каталога.

### Осложнение

Пачка задач идёт параллельно по несколько сессий, и полный прогон рядом с живой
сессией краснеет у любого, кто его позвал. Исполнитель видит красное на чужой
работе и перепроверяет свою правку. На DK-571 это стоило повторного прогона и
одиночного `go test ./...` в `tools/taskctl` сверху.

### Вопрос

Снимать ли слепок каталога до прогона и сверять разницу или узнавать свой след
по имени, где стоит ID прогоняемой задачи.

### Гипотеза

Полный прогон остаётся зелёным рядом с живыми сессиями, а свой след в настоящем
каталоге сторож ловит по-прежнему.
