# DK-879: заголовок чата берётся из транскрипта харнеса, а не заказом у haiku

записан 2026-09-09
приоритет: средний

## Черновик

### Ситуация

Дашборд называет чаты лестницей titleFor в tools/dashboard/chats.go: запись summary транскрипта, сохранённый заголовок в ~/.devkit/chats, эвристика titleTrim, и фоном заказ у haiku отдельным процессом `claude -p --model haiku` из каталога ~/.devkit/titles. Замер 2026-09-09 по этой машине: транскриптов с записью summary ноль из 3373, с записью ai-title 1743; заказов haiku по dashboard.log с 1 сентября 308, ещё 17 транскриптов заказа лежат в ~/.claude/projects под именами тестовых каталогов, то есть тесты дашборда ходят в живого клиента.

Claude Code сам пишет запись `{"type":"ai-title","aiTitle":"..."}` сразу после первой реплики человека, до первого ответа модели, у интерактивных сессий почти всегда; на подписке glm-code она тоже есть, генерирует её endpoint подписки. У сессий печатного режима `-p` записи нет. Команда `/rename` и флаг `claude --name` пишут запись `custom-title`, флаг проверен и в печатном режиме. Шапку читает readSessionHead в sessions.go, и чтение обрывается после Branch и First, раньше, чем встречается ai-title.

У других агентов та же развилка: OpenCode и Goose называют сессию своей дешёвой моделью на первой реплике, Codex CLI и Gemini CLI показывают первую реплику. Второй процесс поверх харнеса ради заголовка не поднимает никто.

### Осложнение

Заголовок появляется с задержкой на подъём отдельного клиента и очередь заказов по два на заход списка, каждый заказ жжёт токены подписки по умолчанию на украшение списка, а механика привязана к одному поставщику: чат на glm-code называется haiku с claude-code. Заказы из тестов тратят квоту на каждом прогоне.

### Вопрос

Порядок лестницы: custom-title раньше ai-title, дальше summary, сохранённый заголовок, эвристика. Какие точки запуска в chatCmd получают флаг `--name`: запуск задачи, груминг, цель, прогон Check. Убирать ли заказ haiku целиком вместе с titleDir, меткой [devkit-title] и фильтрами служебных сессий или оставить за ключом конфига.

### Гипотеза

Чат в списке дашборда получает заголовок через секунды после первой реплики без отдельного процесса и без токенов дашборда; сессии, поднятые дашбордом с известным предметом, названы до первого токена и тем же именем видны в окне терминала и в списке `claude --resume`; заголовок чата второй подписки пишет её же модель; тесты дашборда в живого клиента не ходят.
