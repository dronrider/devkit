# DK-885: Правка задачи оседает в коммите чужой задачи при работе в общем дереве

записан 2026-09-09
приоритет: средний

## Черновик

### Ситуация

Замечено 2026-09-09 на прогоне сценария DK-571. Проверяющий позвал
`shipctl smoke DK-571` в основном чекауте, где рядом работала сессия DK-588.
Команда упёрлась в «cannot lock ref HEAD», а однострочная отметка «smoke
прогнан, 2026-09-09» осела внутри чужого коммита 9570da54 с заголовком
«DK-588 сценарий с пометкой исключения обкатки».

### Осложнение

ID задачи в subject держит связь коммита с задачей, по ней ищут состав поезда,
откат и историю правки. Отметка дошла верно, а найти её коммитом DK-571 уже
нельзя. Пачка задач идёт в общем дереве по несколько сессий разом, и такое
слипание повторится на любой команде, которая коммитит доску.

### Вопрос

Брать ли утилитам доски свой замок на коммит доски или коммитить только явно
названные пути с проверкой чужого индекса перед add.

### Гипотеза

Отметка задачи уезжает своим коммитом с её ID в subject, сколько бы сессий ни
работало в одном дереве.
