# DK-887: Сторож прозы меряет перечень развилок как прозу и краснеет ложно

записан 2026-09-09
приоритет: высокий

## Черновик

### Ситуация

Сторож check-prose.py знает машинные строки файла задачи и прозой их не
считает. Список лежит в TOP_LEVEL_MACHINE_RES: ход работы, ранг, выкат,
приёмка.

Перечень развилок, который пишет taskctl decide, в этот список не попал. Поля
одной развилки («рекомендация:», «вариант:», «решено человеком») склеиваются в
одно длинное предложение без точек. Слово из середины вопроса засчитывается
концовкой-обобщением. На DK-396 сторож показал «абзац кончается обобщением:
20,0 % при пороге 6», а тот же файл без раздела «Развилки» даёт 0,0 %.
Развилки теперь есть у каждой постановки, и краснота приедет на каждой.

Чинить регуляркой строк перечня в TOP_LEVEL_MACHINE_RES или разбирать раздел
целиком, как раздел машинной записи? Первое дешевле и ложится рядом с
пятью готовыми регулярками. Тест берёт файл задачи с развилками и требует
молчания сторожа.

Нашлось вычиткой прозы на груминге DK-396.
