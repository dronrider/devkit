# DK-895: Правило автономии кроет любой маршрут выката, не только shipctl merge

записан 2026-09-10
приоритет: высокий

## Черновик

### Ситуация

Пункт 8 раздела «Ветки, ревью и деплой» в RULES.board.md описывает автономию одним маршрутом. Задача готова, агент зовёт `shipctl merge`, merge пушит и катит выкат из конфига. Ядро RULES.core.md говорит «Push в origin делает пользователь. Ассистент останавливается на локальном коммите и ждёт явной команды», а что делать, когда команда пришла (`DEVKIT_PUSH_OK=1`, `shipctl push`), сказано только в полном тексте RULES.md, пункт 3 раздела «Git». В сессии XR-294 (2026-09-09) багфикс лёг в main без ветки, выкат нужен был не дефолтный, а релиз APK. Пользователь дважды написал «задеплоить всё», `autonomous = true` стоял в конфиге. Агент вернул четыре шага пользователю, из них три мог сделать сам, и после вопроса «почему сам не сделал» сделал их: `shipctl push` прошёл с первого раза, `release-apk.sh --dry-run` прошёл весь путь, релиз 0.111.0 залился на оба хаба.

### Осложнение

Резидентное ядро перевешивает исключение, сказанное одной строкой в хвосте и раскрытое только в полном тексте. Это второй раз на той же развилке. В DK-205 диспетчер остановился перед merge при autonomous=true, разбор лёг в DK-191 и в память, и починка была точечной под `shipctl merge`. Теперь тот же провал повторился на соседних шагах, на пуше main и на релизе компонента по своему ключу. Каждый повтор стоит пользователю хода с упрёком и часа задержки выката.

### Вопрос

Хватит ли правки текста двух правил или нужен сторож? Сторожем может быть сценарий стенда obeycheck «autonomous плюс явное задеплой», где ожидаемый исход это вызов `shipctl push`. Надо ли вообще держать в ядре фразу «ждёт явной команды», если проекты с доской почти все автономные.

### Гипотеза

Пункт 8 говорит, что при autonomous=true агенту доверен любой компонент и любой маршрут, включая багфикс в main без ветки и выкат по своему ключу компонента, а без ключа отказывает утилита (DK-894). Ядро в строке про push называет действие по команде. По явной команде пользователя пуш идёт через `shipctl push`, при автономии агент катит сам, а пользователю остаются только физические барьеры вроде проверки на устройстве. Стенд obeycheck держит сценарий с этой развилкой.
