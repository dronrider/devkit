# DK-925: taskctl draft выдал черновику ID занятой строки доски

записан 2026-09-10
приоритет: высокий

## Черновик

### Ситуация

2026-09-10. Коммит 274b403b в 18:45 оформил DK-916 из черновика и завёл строку
DK-917 «Развилка знает родителя» с файлом docs/tasks/DK-917.md. Коммит
0f7b382d в 18:51 записал черновик docs/tasks/drafts/DK-917.md про мимикрию
тем же ID. Оба файла лежали рядом до 2026-09-10 вечера, `taskctl show DK-917`
печатал строку доски, `taskctl draft list` печатал черновик.

### Осложнение

Черновик с занятым ID нельзя оформить: `taskctl add --id DK-917` упрётся в
строку, а `draft attach` и `draft drop` не различают, о ком речь. Разбор
такого черновика уходит в ручную пересадку под новый ID, что и сделано с
черновиком про мимикрию (DK-924).

### Вопрос

Откуда взялся занятый ID. Кандидаты: `taskctl id` смотрит доску и накопитель,
но не файлы docs/tasks/ без строки; сессия, писавшая черновик, работала на
отставшем чекауте devkit (черновик из корп-проекта пишется через симлинк
kit). Отличить их можно по журналу сессии, записавшей 0f7b382d. Черновик DK-918
отмечает, что коммиты доски с DK-917 пришли с другой машины, и это довод
за отставший чекаут.

### Гипотеза

`taskctl draft` и `taskctl add` отказывают, когда ID занят строкой доски,
архивом, файлом задачи или черновиком, и печатают, чем именно. Перед выдачей
ID утилита сверяется с origin, если чекаут отстал.
