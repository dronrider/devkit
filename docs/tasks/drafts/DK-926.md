# DK-926: прогон parallel.py при восьми воркерах роняет компонент hooks

записан 2026-09-11
приоритет: средний

## Черновик

### Ситуация

2026-09-11, прогон тестов по ходу DK-922 в дереве задачи. Команда
`python3 tools/devkitctl/parallel.py` с потолком по умолчанию (-j 8) валила
компонент `hooks` разными тестами от захода к заходу: сперва
`notify_test.TestHookFocusProcess.test_session_window_in_focus_keeps_quiet`,
следом `quota_refresh_test.TestQuotaRefresh.test_snapshot_is_taken_and_logged`.
Та же сюита в одиночку (763 теста) зелёная, и прогон с `-j 4` тоже зелёный,
18 из 18 компонентов.

### Осложнение

Красный прогон при живом коде читается как поломка правки, и исполнитель с
ревьювером тратят заход на разбор чужой красноты. Обход это гонять с `-j 4`,
то есть терять минуты на каждом прогоне, и знать про обход неоткуда: команда
из конфига выката его не содержит.

### Вопрос

Чинить сами тесты (они меряют время и ждут процессы под нагрузкой) или
опустить потолок воркеров для компонента `hooks`?

### Гипотеза

Полный прогон с потолком по умолчанию зелёный на живом коде, и краснота снова
означает поломку правки.
