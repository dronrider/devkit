# DK-927: класс замечания ревью правится только переписыванием файла руками

записан 2026-09-11
приоритет: низкий

## Черновик

### Ситуация

2026-09-11, ревью DK-922. Ревьювер позвал `taskctl review add` и вписал
`--class реализация` не флагом, а внутрь текста замечания, и класс уехал
словами в первую строку записи. У `taskctl review` для своей задачи есть
только `add`, `resolve`, `clean` и `show`, команды на правку записи или снятие
замечания нет: `drop` живёт в журнале чужого MR.

### Осложнение

Класс возврата считает `taskctl review stats`, и такое замечание в счёт не
попадает, то есть статистика причин возврата врёт тем чаще, чем чаще
ошибается вызов. Починить можно только правкой файла задачи руками, а это
ровно то, от чего доску закрыли утилитой.

### Вопрос

Заводить правку записи отдельной командой или дать `add` перезапись
замечания по номеру?

### Гипотеза

Ошибочно записанное замечание правится командой, и класс возврата доезжает до
`review stats`.
