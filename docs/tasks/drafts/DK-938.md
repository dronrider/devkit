# DK-938: Кнопка чата у цели открывает мёртвый чат груминга вместо чата цикла

записан 2026-09-11
приоритет: высокий

## Черновик

### Ситуация

2026-09-11, цель DK-902 поднята кнопкой «Выполнить» в дашборде. Оболочка
goal-run.py поднимает цикл с DEVKIT_HIDDEN=1 по решению DK-847 от 2026-09-07.
Хук старта пишет hidden: true в память диалога сессии 7eaa707c, её tmux
goal-DK-902. Панель чатов просит список ?all=1 без ключа hidden=1. Чат
цикла в список не попадает. Сервер с ключом hidden=1 отдаёт ему state: live.
Кнопка чата на форме задачи фильтрует видимые чаты по DK-902. Находится
один кандидат, вчерашняя сессия груминга ba1e0826 в tmux task-DK-902. У неё
заголовок «Разбор и груминг задачи DK-902» и state: dead.

### Осложнение

Человек заходит в чат цели с формы и видит чужой заголовок. Над лентой стоит
красная плашка «разговор остановлен», а цикл в это время жив и пишет журнал.
Реплика из этого чата поднимет резюм мёртвой сессии груминга. Во «Входящие»
цели она не доедет, подхват chat-in.py её не увидит. Ответ на вопрос витка
теряется. Рабочий вход остаётся один, команда goal-run.py --say.

### Вопрос

Развилка из двух дорог. По первой адресный вход с формы задачи и со строки цели
не смотрит на признак hidden, а признак остаётся фильтром списка. По второй
цикл цели перестаёт прятаться вовсе, и решение DK-847 пересматривается для
целей. Первая дорога выглядит правильнее. Чистота списка сохраняется, а
адресный переход ведёт в живой чат.

### Гипотеза

Кнопка чата у строки и формы цели открывает живой чат цикла. У него свой
заголовок и зелёное состояние. Реплика из него доезжает во «Входящие».
