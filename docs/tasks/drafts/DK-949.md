# DK-949: obeycheck --task пишет след в основной чекаут вместо дерева задачи

записан 2026-09-12
приоритет: средний

## Черновик

### Ситуация

Ключ `--task` ищет файл задачи от текущей директории. Сначала
`git rev-parse --show-toplevel`, дальше `docs/tasks/<ID>.md` от найденного корня
(tools/obeycheck/tasknote.go:37). Переменную `DEVKIT_HOME` он не смотрит, флага
`-C` у него нет.

### Осложнение

У субагента рабочий каталог сбрасывается между вызовами Bash, и каждый вызов
стенда стартует из основного чекаута. Поэтому на DK-947 три прогона записали
след в `docs/tasks/DK-947.md` основного чекаута вместо файла в дереве задачи.
Исполнитель возвращал основной чекаут командой `git checkout --` и звал стенд
одной строкой вместе с `cd`, то есть ровно той связкой, которую правила
запрещают. Молча испорченный основной чекаут это ещё и грязное дерево под
слияние.

### Вопрос

Чем чинить адрес следа. Своим ключом каталога (`-C <дерево>`) или чтением
`DEVKIT_HOME`, как это делают остальные утилиты. Отдельно стоит решить, не
отбивать ли запись вовсе, когда найденный корень оказался не деревом задачи.

### Гипотеза

Ключ `-C` рядом с отказом на несовпадение. Стенд, позванный из чужого дерева,
тогда скажет об этом вслух и файла в основном чекауте не тронет.
