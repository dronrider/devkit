# DK-974: Парковка вопросом при готовой рекомендации встаёт вместо обхода

записан 2026-09-13
приоритет: высокий

## Черновик

### Ситуация

DK-941 дважды встала вопросом «разрез board-task». 2026-09-12 23:54 исполнитель спросил человека тремя вариантами без рекомендации. Ответ сторожа веса лежал в коде: «резать скилл надвое». 2026-09-13 10:36 человек ответил сомнением про отдельный скилл. Новая голова согласилась, нашла четвёртый вариант, назвала его рекомендацией и в 10:39 припарковала строку тем же вопросом снова. Правило уже есть: interview, «Кто спрашивает», развилка с одной уверенной рекомендацией уходит исполнителю без вопроса. Обвязка выката стоит с autonomous = true. Умолчание decide --ask без --who ставит «решает: человек».

### Осложнение

Цель DK-902 стояла с 23:54 до утра при живой квоте, строка ушла в blocked с ответом, который машина уже знала. Каждая такая парковка это ночь простоя и реплика человека, которой могло не быть.

### Вопрос

Где ставить обход: в decide --ask, который отбивает «решает: человек» при рекомендации, или в парковке, которая при autonomous = true закрывает развилку «по рекомендации» сама и идёт дальше, оставляя человеку уведомление и право переиграть? Менять ли умолчание --who на исполнителя?

### Гипотеза

В автономном режиме исполнитель не встаёт на развилке с рекомендацией. Он закрывает её рекомендацией, пишет в след задачи и шлёт человеку уведомление. Человек может переиграть ответом в чат. Вопрос без рекомендации команда отбивает.
