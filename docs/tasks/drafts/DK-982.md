# DK-982: Сторож прозы считает предложением командную строку из блока sh

записан 2026-09-13
приоритет: средний

## Черновик

### Ситуация

2026-09-13, работа по DK-966. Хук check-prose дважды отбил коммит файла задачи
docs/tasks/DK-966.md, ругаясь на длину предложения. Предложением он посчитал
однострочную команду шага сценария проверки внутри блока с языком sh: там сотни
символов без точки. Прогон по всему файлу (python3 hooks/check-prose.py
docs/tasks/DK-966.md) при этом показывает норму, 18,9 слов на предложение при
пороге 23. Ловится это и на правке через инструмент редактирования, где хук
видит изолированный кусок диффа и парность блоков кода в нём разорвана.

### Осложнение

Сценарий проверки по правилам доски держит команды шагов в блоке sh, и такой
блок есть у каждой агентской задачи. Автор на отказе хука начинает править
живой текст под сторожа либо перестраивать команду, а команда правится только
в одну сторону: она обязана гоняться дословно. Один и тот же файл при этом
проходит проверку целиком и не проходит по куску.

### Вопрос

Считать ли блоки кода по сторонам события записи, как это уже сделано для счёта
разметки страницы (DK-606.4), или хук должен видеть файл целиком, а не кусок
диффа.

### Гипотеза

Команды внутри блоков кода сторож прозы не читает вовсе, и отказ хука означает
настоящую находку в прозе.
