# DK-989: Ворот обкатки протухает от чужих коммитов доски на живом main

записан 2026-09-14
приоритет: средний

## Черновик

### Ситуация

2026-09-14, DK-793. Слияние прошло, а перевод в Check отбился: отметка обкатки стояла на коммите ветки, а HEAD main уехал ребейзом. Повторил обкатку на main, она заняла пять минут, и за это время соседняя сессия положила в main два коммита доски DK-826. Ворот `move check` (tools/taskctl/gate.go, onlyTaskDocSince) пропускает после отметки только правки файла самой задачи. Чужой коммит доски для него равен коду, которого обкатка не видела. Прошёл с третьего круга, когда пять минут никто не коммитил.

### Осложнение

На main с несколькими сессиями коммиты доски идут каждые несколько минут, а обкатка с go-тестами длится дольше. Гонка выигрывается случайно, каждый проигрыш стоит ещё пяти минут прогона на том же коде. Ворот ловит движение HEAD. Код, который сценарий проверяет, в это время стоит на месте. Ту же природу у ворот regcheck разбирает DK-987.

### Вопрос

Считать «приехавшим кодом» только коммиты, тронувшие что-то вне docs/tasks и docs/TASKS*.md? Или сверять отметку с деревом файлов сценария по предмету из шапки?

### Гипотеза

Ворот сравнивает отметку с HEAD через список тронутых путей и пропускает коммиты, которые правили только доску и файлы задач, любые ID. Обкатка на живом main перестаёт зависеть от чужих сессий.
