# DK-997: стенд пишет зелёный след при нуле сессий

записан 2026-09-15
приоритет: средний

## Черновик

### Ситуация

2026-09-15, прогон стенда на DK-996 из дерева задачи. Команда `obeycheck --task DK-996 --for kit/skills/work-plan/SKILL.md -k 3 --base старый` без `--end субагент`. Все три сценария помечены «конец: субагент», и таблица вышла с прочерками: «пропущен, конец субагент», «всего 0 сессий». Итог напечатан как «сценариев 3, все зачтены», а в «Проверку» файла задачи лёг след «Стенд: ... k 3, сценарии , зачтён» с пустым перечнем сценариев.

### Осложнение

Ворота слияния читают след и пропускают правку промпта, которой стенд не мерил ни одной сессией. Отличить такой след от настоящего можно только глазами по прочеркам в таблице. Вдобавок стенд, зная из шапки сценария, что конец субагентский, не подсказывает флаг `--end субагент`.

### Вопрос

Нужен ли при нуле сессий отказ кодом 2 или достаточно не писать след и предупредить? Стоит ли стенду самому брать конец из шапки, когда все отобранные сценарии одного конца?

### Гипотеза

Прогон без единой сессии кончается ошибкой с подсказкой флага конца, след в файл задачи не ложится.
