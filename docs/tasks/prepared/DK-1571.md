## Что происходит

При load average 14 и выше три clitx-теста tools/taskctl краснеют фаталом
про дедлок: TestCLIBoardGuardDoesNotCallGitUnderLock,
TestCLISpendRejectsEditDuringCalculation,
TestCLIMoveRejectsEditDuringBranchGate. При load ниже 6 те же тесты
зелёные. Очередь слияния снимает строки с формулировкой «краснота вне
диффа: go:taskctl», DK-1546 снималась три раза за сутки.

Корень в проверке дедлока, которая выводится из истечения срока. Вокруг
цепочки стоит context.WithTimeout на 6-8 секунд. В бюджет должны уместиться
холодный старт внешнего бинаря, несколько git-подпроцессов и вложенный
запуск taskctl со своим холодным стартом. Под нагрузкой цена одного запуска
растёт в 3-5 раз (замер DK-1168, комментарий
internal/merged/warm_test.go:12-15). В TestCLIBoardGuardDoesNotCallGitUnderLock
вложенные запуски умножаются, обёртка срабатывает на каждый git rev-parse
внешнего процесса.

## Чего хотим

Проверка дедлока отвязана от стенных часов. Тест детектирует факт:
вложенный процесс отработал, замок освобождён. Прецеденты в проекте есть.
TestExpectHoldsGitSpawns держит потолок в запусках git
(internal/merged/warm_test.go:68-72). Стенд headless ждёт факта передачи
(tools/taskctl/run_test.go). Потолки на компиляцию go run остаются
бюджетами сборки.

## DoD

Новый тест держит инвариант: обёртка с искусственной задержкой выше
прежнего потолка 6 секунд не роняет проверку дедлока. Три названных теста
зелёные в трёх прогонах подряд рядом с полным прогоном сюиты, который
держит машину в load 14 и выше.
