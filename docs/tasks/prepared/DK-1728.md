## Уточнение из DK-1728 от 2026-11-18

18 ноября в чате DK-1570 отвеченные вопросы от 5 ноября снова показаны
в конце ленты. Решения сохранены. По исходной диагностике активного ask
нет ни у задачи, ни у рабочего разговора, файлов ожидания также нет.

Установлен клиентский путь воспроизведения. В tools/dashboard/static/app.js
askPickWire проходит по confirmed-записям pick.history даже при пустом ask.
askPickQuestion при отсутствии исходной реплики в загруженной части истории
создаёт запасной блок через feed.append. Подтверждённые отметки disabled;
повторная отправка этим наблюдением не доказана.

На синтетическом DOM с текущим app.js проверены три состояния:

- Исходная реплика отсутствует, активного ask нет. Создан один старый блок
  в конце ленты; выбранный ответ сохранён. Повторная перерисовка оставляет
  один блок.
- Исходная реплика доступна. Запасного блока нет, выбранные отметки стоят
  у исходного вопроса.
- Исходная реплика отсутствует, есть новый активный ask. Созданы два блока;
  новый доступен для ответа, старый недоступен и стоит последним.

Во всех случаях localStorage с историей ответов не меняется. Проба использует
poc_dom.mjs; она не проверяет браузер и данные пользователя. Команда пробы:
node /tmp/dk1728-probe.mjs. Существенные результаты сохранены здесь, наличие
временного файла для реализации не требуется. Штатный poc_askpick.mjs проходит,
но не покрывает отсутствие исходной реплики у confirmed history.

Это уточнение третьего пункта DoD DK-1607. После частичной загрузки истории,
повторного входа, обновления страницы и переключения рабочего разговора
старый вопрос должен оставаться в истории на своём месте. Его отсутствие
в загруженной части не создаёт новый действующий блок в конце ленты.
После загрузки исходной реплики виден прежний выбранный ответ. Настоящий
новый вопрос остаётся доступен, включая действующий запасной блок при
отсутствующей либо частично совпавшей исходной реплике.

Исправление сохраняет историю ответов и текст пользователя. Старые ответы
не переотправляются, рабочий исполнитель не останавливается. Проверки
выполняются в синтетическом разговоре, без действий в живом DK-1570.
Новая форма представления истории этим уточнением не выбирается.
DK-1537 уже требует отметки у исходного вопроса; DK-1665 касалась серверного
ожидания, тогда как эта клиентская проба воспроизводится при пустом ask.

Ранг, цена, приёмка и остальные пункты DoD DK-1607 сохраняются.
