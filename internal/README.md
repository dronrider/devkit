# internal: общий go-модуль каркаса утилит

Библиотека, а не команда: пакеты отсюда импортируют утилиты из `tools/`
через relative replace в своих go.mod, и ни один из них не зовётся по имени.
Заведён DK-237, когда замер показал, что копии каркасных функций уже
разошлись; разбор и граница модуля в
[LLD DK-237](../docs/lld/DK-237-shared-go-module.md).

- `frame` - выжимка вывода команды по формату LLD DK-137: `Capture` пишет
  полный вывод файлом в `.devkit/cmdout/`, `Summarize` собирает сводку,
  `Clean` чистит устаревшее. Порог выжимки живёт тут же.
- `accept` - разбор вида приёмки задачи по суффиксу заголовка строки доски
  (LLD DK-292), общий для taskctl и процедур ревью.
- `stage` - живое состояние этапа работы над задачей (DK-338): словарь видов
  деятельности, запись `~/.devkit/runs/<ID>-<slug>.run` за пределами
  репозитория, разбор её и сборка пакета строк для раздела «Ход работы».
  `agentctl` и `taskctl` пишут запись, `dashboard` читает её.
- `chat` - носитель живого разговора (LLD DK-430, DK-715): входы `.devkit/chat`
  рабочего дерева, строка с адресатом и без него, замок, признак ожидания
  `.ask` со сроком либо меткой «без срока», ждущей сессией и пачкой вопросов.
  Реплики пишет `dashboard`, признак пишет писатель `taskctl ask`, а зовёт его
  хук `hooks/ask-panel.py` на вопросе AskUserQuestion. Снимает признак ответ
  (`dashboard`), а разносит реплики по ходам подхват `hooks/chat-in.py`, и
  разбор строки у них один.
- `sessions` - чтение реестра чатов задачи `~/.devkit/sessions.log` (LLD
  DK-430, решение 1): какая сессия ведёт задачу, чем привязана и где лежит её
  транскрипт. Пишут реестр хук старта и ручка привязки, читают `dashboard`
  (экран) и `taskctl ask` (адрес признака).
- `taskform` - машинная часть формы файла задачи из `TASKFORM.md`: имена и
  порядок разделов, маска ограждённых блоков и вставка раздела на его место
  по форме, а с ними разбор пометки-исключения и отметки обкатки. Читают
  `taskctl` (болванка, «Приёмка», lint, ворота move check), `stage` (пакет
  этапов в «Ход работы») и `shipctl` («Выкат», ворота слияния): отсутствующий
  раздел встаёт по форме, а не в хвост файла.
- `gitrun` - вызов git за утилиты доски (DK-697): запрос учётки закрыт,
  разговор с удалённым репозиторием идёт с пределом времени, а по пределу
  умирает вся группа процессов вместе с помощником учётки. Предел по умолчанию
  тридцать секунд, поднимается переменной `DEVKIT_GIT_TIMEOUT`. `RunContext`
  получает повод оборвать разговор ещё и снаружи, через контекст. Зовут `taskctl`
  и `shipctl`, у обоих пуш доски раньше вставал на связке ключей навсегда.
- `kvconf` - разбор плоских конфигов `.devkit`: строка `ключ = значение`,
  решётка под комментарий, снятая внешняя пара кавычек. Читают им обвязку
  выката `deploy.local` (`deployconf`) и бюджеты с режимом публикации ревью
  `review.conf` (`taskctl review publish`), а копия разошлась бы с оригиналом
  на первой же правке.
- `freshtree` - одноразовое дерево на нужном коммите и окружение прогона без
  следов дома сессии (DK-641, DK-643): временный `HOME`, урезанный `PATH`,
  унесённые переменные харнеса. Зовут `shipctl merge` (тесты перед слиянием) и
  `taskctl rehearse` (обкатка сценария), и прячут дефекты «зелено у
  исполнителя, красно на чужой машине» они одинаково.
