# Долг у диффа

Долговая строка проигрывает живой задаче по рангу и лежит на доске месяцами.
Запас на 2026-08-30: 72 стенда дашборда без драйвера, 34 места с выводом
подпроцесса на экране, невычитанный README, непокрытая отметка работы в двух
утилитах. Очередь по рангу до них не доходит.

Берёт такую строку не очередь, а исполнитель, который только что правил те же
файлы. Экономия тут одна и вполне конкретная. Тот же контекст, те же файлы
прочитаны, та же механика в голове. Своей ветки, своих проверок и своего хвоста
приёмки долг при этом не теряет.

Долг это строка, после которой пользователь снаружи ничего не замечает, а код,
тесты или дока становятся честнее. Метка стоит суффиксом заголовка `[долг]`,
ставит её груминг ключом `--debt` у `taskctl add` либо отдельная команда
`taskctl debt <ID>`. Механику разбирает `tools/taskctl/README.md`, раздел
«Метка технического долга».

## Первый запуск

Заход занимает три команды и живёт внутри сдачи основной задачи.

1. Взять файлы своего диффа. Ветка задачи уже с коммитами, база это `main`.

   ```bash
   git -C <дерево задачи> diff --name-only main...HEAD
   ```

2. Взять запас долга. Фильтр печатает только помеченные строки, Backlog целиком.

   ```bash
   taskctl list backlog --debt
   ```

3. Посмотреть кандидатов, чьи файлы пересеклись с диффом. У строки доски поля с
   файлами нет, и названы они в заголовке и в файле задачи.

   ```bash
   taskctl show <ID долга>
   ```

Пересечение нашлось и цена S, эта строка идёт следующей работой.
`taskctl move <ID долга> in-progress` и дальше обычным порядком `board-task` и
`board-ship`. Пустое пересечение кончает заход, и в сдаче о нём не пишут.

## Когда скилл зовётся

Момент один, сдача основной задачи в Check. Раньше сдачи дифф неполон, а по
неполному диффу пересечение считается наугад. Зовёт скилл сам исполнитель,
сразу за сценарием проверки и до отчёта диспетчеру.

Заход не обязателен ничем. Пустой запас долга, пустое пересечение или уже
взятая на этой сдаче строка это конец захода без всяких последствий для
основной задачи.

## Кто двигает строку

Строку долга двигает сам исполнитель, и место это единственное, где он берёт
следующую работу без диспетчера: кольцо задачи велит сдать хвост и вернуться, а
следующего поднять повторным `agentctl pick` (DK-503.2). Экономия живёт как раз
в этом обходе, поэтому модель долгу заново не выбирается: строку ведёт тот же
исполнитель со своей моделью, а размер держит потолок в одну строку на сдачу.
Не взял, значит назвал в отчёте одной строкой. Строка тогда остаётся в Backlog,
и дальше работа идёт обычным кольцом.

В пачке и в цикле цели момент тот же, сдача основной задачи исполнителем, а не
шаг диспетчера. Диспетчер, который берёт следующую работу, видит строку долга
уже в In progress за тем же исполнителем и второй раз её не поднимает.

## Мера пересечения

Считается пересечение по файлам, а не по компоненту карты. В `docs/map.md`
дашборд стоит одним компонентом, и главный пример долга такой мерой не
различается.

- Общий файл это пересечение. Дифф тронул `tools/dashboard/tasks.go`, строка
  долга названа про тот же файл.
- Общий каталог это пересечение, когда каталог назван у строки прямо, вроде
  «стенды `tools/dashboard`» или «вывод подпроцесса в `tools/shipctl`».
- Общий корень верхнего уровня (`tools/`, `kit/`, `docs/`) пересечением не
  считается. Под ним лежит весь репозиторий.

Файлы строки долга стоят в двух местах, в заголовке строки и в файле задачи
`docs/tasks/<ID>.md`.

## Цена S идёт без вопроса

S берётся молча, одна строка на сдачу. Два долга подряд превратили бы сдачу в
отдельную смену.

Дальше долг идёт ровно так же, как любая задача доски. Своя ветка, свой
сценарий проверки, свой чужой прогон, свой след ревью. Слияние в общий коммит с
основной задачей запрещено. Владельцем коммита `shipctl` считает первый ID в
subject, и второй номер не попадает ни в поезд, ни в откат.

В цикле цели такая строка считается в бюджет цели наравне с остальными. Маркер
`wait-human` скилл не ставит, долг не повод уровня цели.

## Цена M и выше уходит развилкой

Долг дороже S исполнителя не держит. Вопрос заводится развилкой «попутно» на
самой строке долга.

```bash
taskctl decide <ID долга> --ask «попутно» --hint "рекомендация и довод" \
  --option "взять следующей задачей" --option "оставить в Backlog" \
  "брать ли <ID долга> следующей задачей после <ID основной>?"
```

Открытая развилка со значением «решает: человек» держит старт только этой
строки. Основная задача и цель идут дальше, а исполнитель называет развилку в
сдаче одной строкой и возвращается диспетчеру. После ответа строку берёт
ближайший свободный исполнитель обычной очередью, и тем же исполнителем она
быть уже не обязана.

## Чего скилл не делает

- Не правит долг внутри чужой ветки. Правка, уехавшая вместе с основной
  задачей, на доске не отличается от нетронутой.
- Не пишет два ID в subject коммита.
- Не заводит своей арифметики ранга. Готовый ранг с бонусом за дешевизну
  берётся как есть, поднимает долг только пересечение файлов.
- Не размечает беклог по ходу. Метку ставит груминг при заведении строки, а
  разметка стоящего запаса это отдельная работа с приёмкой пользователя.
- Не ставит `wait-human` и не паркует основную задачу.
