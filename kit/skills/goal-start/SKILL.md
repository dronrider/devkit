# Постановка цели

Цель это длинная работа, которую пользователь задаёт один раз целиком, а дальше
её ведёт цикл витков: режет цель на задачи доски, исполняет их обычным
конвейером, ревьюит, выкатывает и отчитывается по завершению. Правила, из
которых режим выведен, лежат в `RULES.board.md` (п. 10 раздела «Ветки, ревью и
деплой»), разбор решений в `docs/lld/DK-079-autonomous-loop.md` репозитория
devkit.

Постановка это единственный интерактивный шаг режима, и она описана здесь.
Витки идут по скиллу `goal-loop`, и к постановке они не возвращаются: всё, что
виток о цели знает, он читает из её файла.

Отдельной сущности под цель на доске нет. Цель это обычная строка (тип `task`,
цена XL) плюс её файл задачи, он же файл цели; задачи цели заводятся обычными
строками со ссылкой на этот файл, как серия задач ссылается на LLD.

## Порядок

1. Условия старта. Проект с доской и `autonomous = true` в гитигнорнутом
   `.devkit/deploy.local`. Флага нет или он `false` значит отказ с причиной:
   при `autonomous = false` слияние не пушит и не катит, и цикл проверял бы
   агентские сценарии против старого прода, считая задачи выкаченными. Флаг
   ставит пользователь, скилл его не поднимает.
2. Диалог, вопросы одной пачкой, а не по одному:
   - что считать целью и по какому DoD она достигнута. DoD выпытывается до
     агентски проверяемого («команда печатает такую строку»), потому что
     проверять его будет цикл, а не глаз. Не выходит агентский, годится
     пользовательский, но тогда цикл на нём остановится и позовёт человека;
   - сколько цель стоит: потолок по каждому бакету квоты в процентных пунктах;
   - каким ярусом моделей ограничиться, если ограничивать.
3. Заголовок строки начинается со слова «Цель:», дальше короткая формулировка в
   стиле доски. По этому слову цель видно в `taskctl list` и грепом, машинного
   признака у неё нет.
4. Ранг вслух, по пяти слагаемым `RANKING.md`, как у любой задачи. Цена всегда
   XL: по шкале это «серия задач, такую дешевле разбить, чем оценивать
   целиком», то есть ровно то, чем цель и является.
5. Завести строку и файл:

   ```bash
   taskctl add --title "Цель: ..." --type task --rank "а+б+в+г+д" --cost XL
   taskctl file <ID>
   ```

   Строка остаётся в Backlog, ссылка на файл цели встаёт сама. В работу цель
   переводит первый виток, а не постановка: заведённая с вечера цель не должна
   выглядеть работающей до запуска цикла.
6. Заполнить файл цели по разделам ниже. Пустых заголовков не оставлять: раздел,
   которому нечего сказать сейчас, всё равно называет, чем он наполнится
   («Задачи цели: заводит нарезка первым витком»).
7. Коммит доски с пушем, флагами самой команды (`-m "docs(tasks): ..."` и
   `--push`), как положено любой правке `docs/tasks/`. Файл цели это состояние
   цикла, и после пуша оно видно с другой машины.
8. Сказать пользователю ID цели, её бюджет и то, чем цель дальше ведётся: цель
   ведут витки по скиллу `goal-loop`, и первый из них поднимается не
   постановкой, а отдельно, фразой «продолжай цель <ID>» в чате или оболочкой
   `goal-run` из того же скилла. Сама по себе заведённая цель не работает, и это
   надо сказать прямо, иначе она молча стоит и выглядит идущей.

## Разделы файла цели

Заголовок файла и раздел «Ход работы» остаются от обычной задачи, к ним
добавляются пять разделов, и цикл читает состояние только из них.

- «Цель»: постановка пользователя и DoD достижения, по возможности агентски
  проверяемый (команда и ожидаемый результат, а не «стало лучше»);
- «Бюджет»: машинно-читаемые строки лимитов, формат ниже;
- «Задачи цели»: список ID с судьбой, растёт по ходу нарезки и находок;
- «Журнал»: строка на виток (дата, что сделано, чем виток кончился) и строки
  снимков квоты, по которым считается расход;
- «Итог»: отчёт по завершению, пишется последним витком.

Заготовка файла (заголовок ставит сама `taskctl file`, строку «Исполнение» в
«Ход работы» допишет `agentctl pick --record`):

```markdown
# <ID>: Цель: ...

## Цель

Постановка пользователя. DoD: ...

## Бюджет

бюджет: week_all <= 25
бюджет: week_max <= 10
ярус: pro

## Задачи цели

Заводит нарезка первым витком.

## Журнал

## Итог
```

## Бюджет и потолок яруса

Цена цели меряется в процентных пунктах недельных бакетов квоты, а не в токенах
и не в деньгах: честных данных на машине только два бакета панели, и живут они
снимком, который освежает `agentctl quota refresh`. Строка на бакет, имена те
же, что в снимке (`week_all`, `week_max`), незнакомый бакет это ошибка
постановки, а не молчаливый пропуск.

```text
бюджет: week_all <= 25
бюджет: week_max <= 10
ярус: pro
```

Мера честна ровно настолько, насколько бакеты принадлежат цели. Бакеты общие на
машину, и параллельная чужая сессия тратит тот же `week_all`, так что число это
верхняя граница трат машины за время цикла, а не точный счётчик цели. Проговорить
это пользователю на постановке, а не изображать точность.

Строка «ярус» задаёт потолок моделей (`mini`, `base`, `pro`, `max`) и
необязательна: без неё вердикт `agentctl pick` работает как обычно. Потолок
режет вердикт последним шагом, сильнее override в файле задачи: бюджетную рамку
пользователь задал на всю цель, и задача внутри цели её не переопределяет.
Стопом превышение не делается, потолок задан с открытыми глазами про потерю
качества. Единственное исключение это нарезка и разбивка: ниже `pro` их не
режет никакой потолок, иначе дешёвая модель нарежет цель плохо и весь бюджет
уедет на переделку.

Числа выпытываются у пользователя, скилл их не назначает и не поднимает по ходу.
Исчерпание бюджета это стоп с отчётом, добавку даёт только пользователь, правкой
раздела «Бюджет» и повторным запуском цикла.

## Где постановка упирается

- `autonomous = false` или доски в проекте нет. Отказ с причиной на шаге 1,
  цель не заводится: цикл, который сливает в локальный main и не катит, хуже
  отсутствия цикла.
- DoD не формулируется. Цель не заводится, пока не ясно, чем она кончается:
  цикл без DoD не умеет выйти маркером «достигнуто» и будет жечь бюджет до
  потолка.
- Пользователь бюджета не называет («сколько нужно»). Числа всё равно нужны, и
  предложить их можно самому, но утверждает их пользователь: назначенная себе
  цена это уже не его граница.
- Цель на самом деле список готовых задач. Цикл не нужен, такое везёт
  `board-batch` своим вторым входом.
- Доска правится только в основном чекауте: из линкованного worktree `add` и
  `file` отказывают сами.
