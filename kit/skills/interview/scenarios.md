# Текстовый выбор сценариев

Подробности первого раунда `interview`. До команд ниже выполнить чтение
записи, фильтр вопросов и подготовку карточек из `SKILL.md`, раздел
«Первый раунд: сценарии».

## Создание и ответ

До сохранения снимка `--chat` и `--given` нужны готовые карточки всех ID.
В разделе `## Пользовательские сценарии` под каждым `### СЦ-N` заполнить
отдельные строки `Ситуация:`, `Действие:`, `Результат:`, `Польза:`,
`Рекомендация:`, `Ограничение:` и `Источник:` с непустым значением.
Регистр подписей не влияет на разбор. Карточка кончается следующим
заголовком. Поле из чужой карточки, другого раздела или ограждённого
примера не заполняет пропуск. Команда называет ID/поле и отказывает
раньше записи снимка, решения и изменения ожидания. Подготовительный
открытый список можно создать и читать без карточек.

Новый список заводится явным режимом `--scenarios`. У каждого сценария
своя строка варианта, рекомендованный набор с доводом стоит отдельно.

```sh
taskctl decide DK-119 --ask «сценарии» --scenarios --hint 'СЦ-1, СЦ-3: нужны отдельный выбор и продолжение' --option 'СЦ-1 (слово пользователя): выбрать сценарии' --option 'СЦ-2 (вывод из примера): собрать пример' --option 'СЦ-3 (предложение агента): продолжить после перерыва' 'какие сценарии включаем?'
taskctl decide DK-119 «сценарии» --chat
```

Вопрос и карточки идут из вывода команды знак в знак. Рекомендация в голове
не становится отдельным вариантом и не закрывает выбор. Вместе с блоком
сохраняется ключ `снимок сценариев: sc1-<sha256>`. Ответ передаётся с ключом
именно показанного блока, включая ответ по ID. Последний известный ключ
не подставляется вместо потерянного; сначала сверяется, на какой блок
отвечал человек.

```sh
taskctl decide DK-119 «сценарии» --snapshot 'sc1-<ключ показанного блока>' --answer 'сценарии 1, 3'
```

Полный набор заменяет выбор. `минус 2` снимает сценарий, `плюс СЦ-2`
включает известный, `плюс "свой сценарий, с запятой"` добавляет свой.
Правка берёт полный набор из той же строки, иначе текущий выбор; до первого
ответа основой служит показанный рекомендованный набор. `по рекомендации`
считается ответом человека. Слова, пробелы и пунктуация передаются дословно.
Неразобранные слова возвращаются агенту. При таком ответе список автоматически
не закрывается.
При своём сценарии сначала сохраняются слова и выбор человека, затем агент
дополняет карточку перед следующим `--chat`. До самого ответа будущая
карточка нового ID не требуется. Новое существенное условие сверяется с человеком.

Повтор той же пары ключа и точного текста возвращает сохранённый результат
без записи и нового ID. После более позднего выбора или пересмотра старый
ответ устаревает, даже если состав вернулся к прежнему. При отказе на снимок
показать конкретное расхождение прежнего и нынешнего блока, сверить выбор
и получить свежий блок командой `--chat`. Ошибка не повод пересказать ответ
так, чтобы утилита его приняла.

Явное `ничего` или снятие всех сохраняет отказ, отменяет прежний состав
и оставляет выбор открытым для пересмотра границ. Агент выясняет новый
состав либо прекращение работы. Пустая строка ошибочна. После отказа
правкам нужна явная основа, полный набор или `по рекомендации`.

## Заданный состав и продолжение

Прямо заданный состав переносится без нового вопроса. Карточки подготовлены
до `--given`, их поля проверяются по разделу «Создание и ответ». При создании списка
передать выбранные ID ключом `--given`, а исходные слова человека или ссылку
на принятое решение ключом `--said`.

```sh
taskctl decide DK-119 --ask «сценарии» --scenarios --hint 'СЦ-1: путь прямо задан' --option 'СЦ-1 (слово пользователя): считать None нулём' --given 'СЦ-1' --said 'из записи: total считает None нулём' 'какие сценарии включаем?'
```

Агентское предложение основанием `--said` не служит. Решённый старый состав
не переписывается автоматически, открытый принимает первый ответ прежним
способом. При новом разговоре его смысл переносится с явным соответствием
ID; неизменный состав повторно не согласуется.

После пересмотра выполнить напоминание CLI и сверить зависимые решения
по содержанию. Под затронутой головой после последнего решения дописать
`требует сверки ГГГГ-ММ-ДД: <что изменилось и что проверить>`. Подтверждение
прежнего ответа и новый ответ сохраняются обычной более поздней строкой
`решено`. Человеческий ответ берётся у человека; внутреннее решение
остаётся исполнителю. Связи и дерево здесь не создаются. Возобновление
с `--open` показывает текущие ID, открытый остаток и пометки сверки.
