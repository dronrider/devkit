# План работ сессии

Снаружи сессия видна одним планом. Дашборд рисует по нему деления кольца в
шапке разговора и блок «План агента» на экране задачи. Без плана человек
смотрит в молчащее окно и не знает, на каком шаге заход и жив ли он вообще.

План живёт файлом `~/.devkit/plans/<ID сессии>.json`, а пишет и читает его
`agentctl plan`. Формат, имя файла и три состояния пункта держит утилита.
Руками JSON не собирается и файл не правится, иначе план каждой сессии выходит
своего вида. Устройство команды и её флаги лежат в
`tools/agentctl/README.md`, раздел «План работ сессии».

## Порог повода

План ведётся там, где работа длиннее одного хода. Это задача доски, виток
цели, груминг черновика, разбор или правка по просьбе человека в несколько
шагов. Один вопрос с одним ответом плана не просит.

## Ритм

1. До первого шага работы положить план целиком. Пункты это этапы задачи
   словами, по которым человек поймёт, что происходит. Пять-десять штук,
   строкой в семьдесят знаков.

   ```bash
   agentctl plan set "дерево задачи
   скилл work-plan
   команда agentctl plan с тестами
   дока и прогон тестов
   коммиты"
   ```

2. Начиная пункт, отметить его идущим. Прежний идущий команда закроет сама.

   ```bash
   agentctl plan step "команда agentctl plan"
   ```

   Пункт называется куском текста либо номером с единицы. Кусок, под который
   подходят два пункта, команда отбивает и просит номер.

3. Кончив работу не тем пунктом, который шёл, закрыть его отдельно.

   ```bash
   agentctl plan done 3
   ```

4. Поменялся состав работы, значит план кладётся заново тем же `set`.
   Появившийся по ходу этап это новый план.

5. Перед возвратом или концом хода закрыть сделанное. План, брошенный на
   середине, снаружи неотличим от сессии, которая встала.

Посмотреть, что видно снаружи, можно тем же инструментом. Команда печатает
план сессии и планы её субагентов.

```bash
agentctl plan show
```

## Адрес файла

Адрес считает сама команда, и знать его наизусть незачем. Порядок такой.

- ID сессии берётся из `CLAUDE_CODE_SESSION_ID`.
- Пустую переменную (контур второй подписки) подпирает `DEVKIT_TMUX`, имя
  tmux-сессии из заказа поднявшего.
- Нет ни того, ни другого, и команда отказывает, зовя флаг `--sid`.
  Искать своё имя по `printenv` и каталогу планов не надо.

## Субагент

У субагента `CLAUDE_CODE_CHILD_SESSION=1`, а `CLAUDE_CODE_SESSION_ID` ему
достаётся от внешней сессии, и файл по этому имени принадлежит ей. Свой план
субагент ведёт с меткой, файлом `<ID сессии>-sub-<метка>.json`.

```bash
agentctl plan set --label dk613 "разведка
правка с тестами
коммит"
```

Метку субагент выбирает себе сам одним разом и держит до конца захода. Годится
ID задачи, годится короткое слово. У субагентов одной пачки ID сессии общий, и
без метки они писали план друг поверх друга (DK-527). Метка приезжает и парой
окружения `DEVKIT_PLAN_LABEL`, когда её положил поднявший. Без метки команда
отказывает и чужого плана не трогает.

## Инструмент TodoWrite

Файла он не заменяет. У сессии в обход разрешений его нет вовсе, у части
подписок нет тоже, а дашборд читает файл. Есть TodoWrite в наборе, веди его вдобавок,
теми же пунктами.
