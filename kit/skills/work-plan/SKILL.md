# План работ сессии

Снаружи сессия видна планом. Дашборд рисует по нему кольцо разговора и блок
«План агента» на экране задачи. План живёт файлом
`~/.devkit/plans/<ID сессии>.json`, пишет и читает его `agentctl plan`, руками
JSON не собирается. Флаги команды лежат в `tools/agentctl/README.md`.

## Порог повода

План ведётся там, где работа длиннее одного хода. Один вопрос с одним ответом
плана не просит, а два хода это уже план, и два пункта в нём не мало.

## Пункт

Пункт это проверяемый результат этапа. Пишется «тест на clamp красный на
старом коде» вместо «тесты». По тексту пункта при закрытии видно, сделан он
или нет. Когда так не пишется, этап делится, пока не напишется, а пункт с
критерием дальше не дробится. Строка до семидесяти знаков, пунктов столько,
сколько этапов.

Порядок пунктов это порядок исполнения. Разведка, проба и вопрос человеку
стоят раньше пунктов, которые зависят от ответа. Пункт, снимаемый без ущерба
задаче, начинается словами «по возможности».

## Ритм

1. Первым ходом, до чтения задачи, положить план целиком грубыми этапами.
   Кольцо оживает сразу, уточнение придёт после разведки.

   ```bash
   agentctl plan set "разведка по коду
   правка с тестами
   коммит"
   ```

2. После разведки переложить план тем же `set` пунктами с критерием. Перед
   этим назвать себе три самые вероятные причины провала плана. Каждая
   становится ранним пунктом либо критерием в тексте пункта. Отметки
   совпавших по тексту пунктов команда переносит.

   ```bash
   agentctl plan set "тест на clamp красный на старом коде
   clamp режет верх, тест зелёный
   абзац про clamp в README
   коммит с ID задачи
   по возможности: тест на lo больше hi"
   ```

3. Начиная пункт, отметить его идущим, прежний идущий команда закроет сама.
   Пункт зовётся куском текста либо номером.

   ```bash
   agentctl plan step "режет верх"
   ```

4. Закрывать пункт, когда критерий из его текста выполнен и это видно: тест
   прошёл, файл лежит, коммит есть. Заодно сверить остаток плана с узнанным,
   разошедшийся переложить `set`. Пункт не сошёлся, тогда один повтор, затем
   деление через `set`, затем вопрос человеку, а пункт при этом остаётся
   идущим.

   ```bash
   agentctl plan done 3
   ```

5. Состав меняется через `set` тем же ходом. Снятый пункт не попадает в новый
   набор, а закрывать его нельзя, он не сделан. Своей волей агент делит
   пункт, меняет порядок и снимает пункт «по возможности». Снять остальное,
   добавить этап вне предмета задачи или переложить план под новую просьбу
   можно только со слов человека, а находка вне предмета уходит черновиком.
   Причина перекладки говорится в реплике одной фразой.

6. После сжатия контекста первый вызов это `plan show`. План это память о том,
   где заход. Что не влезло в текст пункта, пишется в файл задачи.

   ```bash
   agentctl plan show
   ```

7. Перед возвратом или концом хода закрыть сделанное. Брошенный план снаружи
   неотличим от вставшей сессии.

## Адрес файла

Адрес считает команда: ID сессии из `CLAUDE_CODE_SESSION_ID`, пустую
переменную подпирает `DEVKIT_TMUX`, а без обоих команда требует флаг `--sid`.
Искать своё имя по `printenv` и каталогу планов не надо.

## Субагент

У субагента `CLAUDE_CODE_CHILD_SESSION=1`, а `CLAUDE_CODE_SESSION_ID` достаётся
от внешней сессии. Свой план субагент ведёт с меткой, файлом
`<ID сессии>-sub-<метка>.json`.

```bash
agentctl plan set --label dk613 "разведка
правка с тестами
коммит"
```

Метку субагент выбирает один раз, ID задачи или короткое слово, а поднявший
кладёт её парой окружения `DEVKIT_PLAN_LABEL`. Без метки команда отказывает:
у пачки ID сессии общий, и планы легли бы друг поверх друга.

## Инструмент TodoWrite

Файла он не заменяет, дашборд читает файл. Есть TodoWrite в наборе, веди его
вдобавок, теми же пунктами.
