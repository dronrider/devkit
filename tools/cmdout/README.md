# cmdout: длинный вывод команд файлом, агенту выжимка

Бинарь-обёртка над `internal/frame` для агентских сессий: когда вывод команды
способен перевалить за экран (тесты, сборка, слияние, выкат, `git diff` без
опций), полный вывод пишется файлом в `.devkit/cmdout/<timestamp>-<slug>/out`
репозитория, а в стандартный вывод уходит выжимка. Ниже порога (4K символов
или 100 строк) выжимка не строится, агент получает полный вывод как есть, и
обёртка ведёт себя прозрачно. Правило, по которому обёртку зовут, лежит в
RULES.md, раздел «Длинные прогоны под обёрткой»; формат выжимки и порог
разобраны в [LLD DK-137](../../docs/lld/DK-137-cmdout-wrapper.md), модуль
общего каркаса в [LLD DK-237](../../docs/lld/DK-237-shared-go-module.md).

Ставится в PATH релизом devkit, как taskctl:

```
python3 ~/projects/devkit/tools/devkitctl/devkitctl.py update
```

## Запуск

```
cmdout <команда ...>
cmdout clean [--days N] [--dry-run]
```

Команда ставится как есть, без разделителя `--`. Имя каталога вывода (slug)
берётся от первой лексемы команды: «git diff» даёт «git». Код возврата cmdout
совпадает с кодом возврата команды, поэтому обёртка встаёт в конвейеры и
скрипты проверки без поправок на себя.

Подкоманда `clean` удаляет каталоги `.devkit/cmdout` старше порога возраста
(по умолчанию 7 дней, перекрывается `--days`). Порог и правило живут в
`internal/frame`, как и порог выжимки, чтобы чистка и запись не разъехались.
`--dry-run` печатает пути каталогов под удаление, не трогая файлы. Doctor
зовёт clean подпроцессом и порог ему не дублируется: на сухом прогоне он
видит, что cmdout счёл устаревшим.

Инструменту, встраивающему обёртку в себя, бинарь не нужен: он зовёт
`frame.Capture`/`frame.Summarize` напрямую, без вызова подпроцесса.
