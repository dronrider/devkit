# dashboard: веб-дашборд агентской разработки

Go-сервер с вшитой статикой: доска и текущие работы проектов с любого
устройства пользователя. Первый срез цели DK-112, решения приняты в
[LLD](../../docs/lld/DK-112-dashboard.md): считает всё сервер, клиент только
рисует; источник правды это доска и утилиты, своей базы нет; правок доски в
этом срезе нет, доска на чтение.

Инструмент общий, живёт в devkit и едет готовым бинарём в его релизе, как
`taskctl` и соседи: ставит его в PATH `devkitctl update` (или `build` из
исходников). Держит процесс launchd-агент `ru.devkit.dashboard` с KeepAlive,
его кладёт и поднимает `devkitctl doctor --fix`; тот же доктор проверяет, что
агент поднят и `/healthz` отвечает без ошибок конфига. Замену собственного
бинаря выкатом демон замечает сам по иноде, доживает начатые ответы и
выходит, а KeepAlive поднимает уже новый: правка доезжает до работающего
процесса командой deploy, без правки обвязки.

## Команды

```
serve [--static <dir>]      поднять сервер; --static читает статику с диска
                            вместо вшитой, правка видна по F5 без пересборки
secret [--rotate]           напечатать токен входа; --rotate заменяет секрет,
                            и все выданные куки разом мертвы
```

## Конфиг

`~/.devkit/dashboard.local`, формат «`key = value`, `#` комментарий», тот же,
что у `.devkit/deploy.local`. Права 600, потому что в файле секрет входа;
файл с правами шире сервер не берёт. Незнакомый ключ это ошибка старта, а не
молчаливый пропуск.

```
# корней несколько, по строке на каждый
root = ~/projects
root = ~/work
addr = 0.0.0.0
port = 7112
token = <секрет входа, рождается сам при первом старте>
```

Умолчания: порт 7112 (по номеру цели), `addr` слушает все интерфейсы (доступ
решает канал, вход решает секрет). Умолчания для `root` нет: пустой список
корней сервер называет в `/healthz` и журнале, а не подставляет что-то молча.

Проект узнаётся как у devkitctl, по `docs/TASKS.md`: проектом считается сам
корень или его прямой подкаталог с доской, глубже обход не идёт. Боковые
деревья задач отсеиваются признаком линкованного worktree (расхождение
`git rev-parse --git-dir` и `--git-common-dir`). Совпадение имён проектов из
разных корней это ошибка конфига: оба выпадают из списка и называются в
`/healthz`, а не молча берётся первый попавшийся.

## Вход

Единый секрет-токен и подписанная кука (разбор развилки в LLD). Секрет
рождается на машине при первом старте `serve` и живёт строкой `token` в
конфиге; по сети он не ездит. На устройство токен переносится руками один
раз: печатает его `dashboard secret`, вставляется он на странице `/login` и
живёт в менеджере паролей. Сервер сверяет токен константным временем и
ставит куку HttpOnly SameSite=Lax на 30 дней: значение это срок действия с
подписью HMAC-SHA256 от секрета, состояния сессий на сервере нет, и рестарт
демона никого не разлогинивает.

Утечка лечится ротацией: `dashboard secret --rotate` заменяет секрет, подпись
всех выданных кук перестаёт сходиться, токен вводится заново. Перебор токена
гасится секундной паузой после провала входа и строкой в журнале. CSRF закрыт
SameSite=Lax и сверкой Origin на изменяющих методах, XSS тем, что тексты
досок рисуются текстом, а CSP запрещает инлайн и внешние источники.

Без входа не отдаётся ни одна строка данных: API отвечает 401, страницы
уводят на `/login`. Открыты только сам `/login` с его обвязкой и `/healthz`.
TLS сервер не заводит: канал это решение выката, а не архитектуры.

## API

Все ручки под `/api`, JSON, вход кукой. Доску сервер берёт подпроцессом
`taskctl list --json`, своего разбора markdown у него нет. Ищется taskctl
сначала рядом с бинарём самого дашборда (под launchd PATH системный, а
утилиты devkit лежат одним каталогом), потом по PATH; не нашёлся нигде, это
названная ошибка в `/healthz` и в каждом ответе доски, потому что тихая
деградация неотличима от «задач нет».

- `POST /api/login` (`{"token": "..."}`) и `POST /api/logout`;
- `GET /api/projects`: проекты по конфигу корней: имя, путь, счётчики секций
  и живые работы: tmux-сессии `goal-*`/`task-*`, привязанные префиксом ID
  доски, плюс цели из реестра `~/.devkit/goals`, привязанные корнем (цикл,
  ведущийся снаружи, без tmux-сессии). Ненайденный tmux называется в
  `/healthz`, в списке проектов и в ответе доски, а не отдаёт молча пустые
  работы; tmux без единой сессии (его сервер не живёт, `ls` отвечает
  ненулевым кодом) это штатно пустой список без ошибки;
- `GET /api/projects/{p}/board`: доска проекта как её отдал
  `taskctl list --json`, рядом живые работы;
- `GET /healthz`: без входа; `ok`, версия (по её смене выкат проверяется
  машинно), аптайм, число проектов и ошибки конфига.

## Экран доски

Вшитая статика (`static/`, `go:embed`): рукописные HTML, CSS и ES-модули без
сборки и внешних зависимостей, наружу сервер не ходит ни за одним байтом,
шрифты IBM Plex берутся через системные фолбэки. Вёрстка по макету DK-216
(«01 Доска» в Claude Design): на ноутбуке боковая колонка с проектами и
разделами, на телефоне нижние вкладки и переключатель проекта в шапке.
Разделы «Агенты» и «Лента» стоят заглушками до своих срезов серии. Доска
перечитывается по фокусу окна, постоянного опроса нет.

## Наблюдаемость

Журнал `~/.devkit/dashboard.log`: старты и остановки, входы и провалы входа,
ошибки чтения досок. Чтения в журнал не пишутся, иначе опрос открытых
экранов зарастил бы его за день. Молчание различимо: пустая доска, пустой
список проектов и недоступная утилита это разные ответы API с причиной, а не
одинаковый пустой экран.
