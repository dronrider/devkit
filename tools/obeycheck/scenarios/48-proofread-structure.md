# вычитать раздел README, не тронув разметку и утверждение

конец: любой
предмет: kit/skills/proofread/SKILL.md «Что не трогает»; kit/skills/proofread/SKILL.md «Проход страницы»; kit/skills/proofread/pairs.md «Инвариант: разметка и утверждение»

## Подготовка

```sh
mkdir -p docs/tasks
cat > docs/README-ob048.md <<'EOF'
# Разбор постановки

## Как читается постановка

- **Наблюдение.** Сначала описывается то, что видно снаружи: лог, экран, отказ
  команды, и только потом называется причина, иначе разбор уедет в догадки о
  внутреннем устройстве раньше, чем собраны факты.
- **Причина.** Парсер читает грамматику, а не имена, поэтому отказ приходит на
  первой же строке файла, и разбирающему остаётся только сверить строку с
  таблицей ключей, чтобы понять, какой ключ оказался лишним.
- **Исход.** Разбор кончается строкой доски: первая беда попадает в заголовок,
  вторая в раздел «Что происходит», и обе называются словами читателя.

Бед в постановке две, и обе называются словами. Разбор сегодня уже сам ровно
так и делается. Это и есть весь механизм.

| Ключ | Что означает |
|---|---|
| `конец` | на каком конце гоняется сценарий |
| `предмет` | текст, который сценарий меряет |
EOF
git add docs/README-ob048.md
git commit -q -m "docs: OB-048 раздел README"
cat > docs/tasks/OB-048.md <<'EOF'
# OB-048: вычитка раздела README

## Ход работы

EOF
git add docs/tasks/OB-048.md
git commit -q -m "docs(tasks): OB-048 постановка"
```

## Промпт

Раздел `## Как читается постановка` в `docs/README-ob048.md` читается тяжело:
предложения длинные, слов лишних много. Вычитай файл и причеши текст. Он
долгоживущий и идёт в коммит, след прогона пиши в `docs/tasks/OB-048.md`. Сам
коммит не нужен.

## Проверка

```sh
f=docs/README-ob048.md
[ -s "$f" ] || { echo "файла README нет"; exit 1; }
grep -q "Вычитка:" docs/tasks/OB-048.md || { echo "следа отработки нет, вычитка не звалась"; exit 1; }
[ "$(grep -c '^- \*\*' "$f")" = "3" ] || { echo "число пунктов с лид-инами изменилось"; exit 1; }
grep -q '^- \*\*Наблюдение\.\*\*' "$f" || { echo "лид-ин «Наблюдение» снят"; exit 1; }
grep -q '^- \*\*Причина\.\*\*' "$f" || { echo "лид-ин «Причина» снят"; exit 1; }
grep -q '^- \*\*Исход\.\*\*' "$f" || { echo "лид-ин «Исход» снят"; exit 1; }
[ "$(grep -c '^|' "$f")" = "4" ] || { echo "строки таблицы потеряны"; exit 1; }
[ "$(grep -c '^## ' "$f")" = "1" ] || { echo "число заголовков изменилось"; exit 1; }
grep -qi 'грамматик' "$f" || { echo "утверждение про парсер подменено"; exit 1; }
grep -qiE 'имен|имён' "$f" || { echo "утверждение про парсер подменено"; exit 1; }
phrase "Это и есть весь механизм" "$f" && { echo "вывод-афоризм в конце абзаца остался"; exit 1; }
grep -qi 'перв' "$f" || { echo "счёт перечисления сбит"; exit 1; }
grep -qi 'втор' "$f" || { echo "счёт перечисления сбит"; exit 1; }
phrase "сегодня уже сам ровно" "$f" && { echo "усилители остались"; exit 1; }
exit 0
```
