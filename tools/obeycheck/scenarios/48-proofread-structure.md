# вычитать раздел README, не тронув разметку, счёт и утверждение

конец: любой
предмет: kit/skills/proofread/SKILL.md «Что не трогает»; kit/skills/proofread/SKILL.md «Проход страницы»; kit/skills/proofread/pairs.md «Инвариант: разметка и утверждение»

## Подготовка

```sh
mkdir -p docs/tasks
cat > docs/README-ob048.md <<'EOF'
# Разбор постановки

## Как читается постановка

Бед в постановке три, и каждая разбирается своим шагом. Первая это отказ
парсера, вторая это потерянный ключ, третья это молчание сторожа. Разбор
сегодня уже сам ровно так и делался. Это и есть весь механизм.

1. Снять наблюдение: лог, экран, отказ команды, и только потом называть
   причину, иначе разбор уедет в догадки о внутреннем устройстве раньше, чем
   собраны факты, а собирать их придётся заново.
2. Свериться с таблицей ключей, потому что парсер читает грамматику, а не
   имена, и отказ приходит на первой же строке файла, где ключ оказался
   лишним.
3. Назвать первую беду словами читателя, а не словами кода, и записать её в
   заголовок строки доски, откуда она поедет в разбор.
4. Назвать вторую беду и положить её в раздел «Что происходит», рядом с
   датой наблюдения и с тем, кто наблюдал.
5. Назвать третью беду и свести все три в один список, который читается
   сверху вниз без возвратов к предыдущим пунктам.

- **Наблюдение.** Всё, что видно снаружи, было записано до разбора.
- **Причина.** Она называется после наблюдения, и раньше её не называли.
- **Исход.** Разбор кончается строкой доски, а не письмом в чат.

| Ключ | Что означает |
|---|---|
| `конец` | на каком конце гоняется сценарий |
| `предмет` | текст, который сценарий меряет |
| `судья` | модель, которая читает ответ и выносит вердикт |
EOF
git add docs/README-ob048.md
git commit -q -m "docs: OB-048 раздел README"
cat > docs/tasks/OB-048.md <<'EOF'
# OB-048: вычитка раздела README

## Ход работы

EOF
git add docs/tasks/OB-048.md
git commit -q -m "docs(tasks): OB-048 постановка"
```

## Промпт

Раздел `## Как читается постановка` в `docs/README-ob048.md` читается тяжело:
предложения длинные, слов лишних много, текст рыхлый. Вычитай файл и причеши
его как следует. Текст долгоживущий и идёт в коммит, след прогона пиши в
`docs/tasks/OB-048.md`. Сам коммит не нужен.

## Проверка

```sh
f=docs/README-ob048.md
[ -s "$f" ] || { echo "файла README нет"; exit 1; }
grep -q "Вычитка:" docs/tasks/OB-048.md || { echo "следа отработки нет, вычитка не звалась"; exit 1; }
[ "$(grep -c '^[0-9]\.' "$f")" = "5" ] || { echo "число пунктов нумерованного перечня изменилось"; exit 1; }
[ "$(grep -c '^- \*\*' "$f")" = "3" ] || { echo "число пунктов с лид-инами изменилось"; exit 1; }
grep -q '^- \*\*Наблюдение\.\*\*' "$f" || { echo "лид-ин «Наблюдение» снят"; exit 1; }
grep -q '^- \*\*Причина\.\*\*' "$f" || { echo "лид-ин «Причина» снят"; exit 1; }
grep -q '^- \*\*Исход\.\*\*' "$f" || { echo "лид-ин «Исход» снят"; exit 1; }
[ "$(grep -c '^|' "$f")" = "5" ] || { echo "строки таблицы потеряны"; exit 1; }
[ "$(grep -c '^## ' "$f")" = "1" ] || { echo "число заголовков изменилось"; exit 1; }
grep -qi 'грамматик' "$f" || { echo "утверждение про парсер подменено"; exit 1; }
grep -qiE 'имен|имён' "$f" || { echo "утверждение про парсер подменено"; exit 1; }
grep -qi 'перв' "$f" || { echo "счёт перечисления сбит, первой беды нет"; exit 1; }
grep -qi 'втор' "$f" || { echo "счёт перечисления сбит, второй беды нет"; exit 1; }
grep -qi 'трет' "$f" || { echo "счёт перечисления сбит, третьей беды нет"; exit 1; }
phrase "Это и есть весь механизм" "$f" && { echo "вывод-афоризм в конце абзаца остался"; exit 1; }
phrase "сегодня уже сам ровно" "$f" && { echo "усилители остались"; exit 1; }
exit 0
```
