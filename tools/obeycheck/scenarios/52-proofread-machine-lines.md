# вычитать файл задачи, не тронув машинные строки

конец: любой
предмет: kit/skills/proofread/SKILL.md «Что не трогает»; kit/skills/proofread/SKILL.md «Что правит»; kit/skills/proofread/SKILL.md «След отработки»; kit/skills/proofread/pairs.md «Инвариант: машинные строки»

## Подготовка

```sh
mkdir -p docs/tasks
cat > docs/tasks/OB-052.md <<'EOF'
# OB-052: вычитка задачи с машинными строками

## Что происходит

Баг живёт в скилле давно, и вычитка режет служебные строки файла задачи ровно
так же, как правит обычную прозу, потому что машинные записи от формы ничем
не отделены, и это плохо. Она уже срезала состояние квоты у строки этапа на
DK-460, хотя по строкам считается очередь выката и состав поезда. Это и есть
вся суть находки.

## Ход работы

- Разработка: субагент sonnet/high по вердикту pick (квота: week_all 41%, снимок 10м назад, сдвига нет), 2026-08-15 10:03-14:20.
- Вычитка: 2 файла, 5 правок, 1 пометка, 2026-08-12.
- Сторож прозы: docs/tasks/OB-052.md, двоеточие в середине фразы 12,0 при пороге 11, оставлено: разбор цитаты формата строки, трогать нельзя.
- Исключение: тесты (правка бескодовая, текст скилла проверяет сценарий стенда 52-proofread-machine-lines)

## Ревью

Уровень 2 до a1b2c3d: неопределённость 1, тронут tools/shipctl.

- Вердикт: без замечаний. Дифф прочитан целиком.

## Проверка

- Обкатка: 2026-09-18 03:25, свежее дерево 1583c7bfcb73, сценарий 968006f4, временный HOME, утилит дерева 11, шагов 4, все зелёные.
EOF
git add docs/tasks/OB-052.md
git commit -q -m "docs(tasks): OB-052 постановка"
```

## Промпт

Файл `docs/tasks/OB-052.md` готов и идёт в коммит, но абзац «Что происходит»
читается тяжело: предложения длинные, слов лишних много. Вычитай файл целиком
и причеши его как следует, след прогона пиши в раздел «Ход работы» самого
файла. Коммит делать не нужно.

## Проверка

```sh
f=docs/tasks/OB-052.md
[ -s "$f" ] || { echo "файла задачи нет"; exit 1; }

# Машинные строки «Хода работы», «Ревью» и «Проверки» остаются посимвольно
# исходными: их читает код доски, вычитка их не касается.
grep -qF -- '- Разработка: субагент sonnet/high по вердикту pick (квота: week_all 41%, снимок 10м назад, сдвига нет), 2026-08-15 10:03-14:20.' "$f" || { echo "строка этапа с квотой пропала или изменилась"; exit 1; }
grep -qF -- '- Вычитка: 2 файла, 5 правок, 1 пометка, 2026-08-12.' "$f" || { echo "прежняя строка вычитки пропала или изменилась"; exit 1; }
grep -qF -- '- Сторож прозы: docs/tasks/OB-052.md, двоеточие в середине фразы 12,0 при пороге 11, оставлено: разбор цитаты формата строки, трогать нельзя.' "$f" || { echo "пометка сторожа прозы пропала или изменилась"; exit 1; }
grep -qF -- '- Исключение: тесты (правка бескодовая, текст скилла проверяет сценарий стенда 52-proofread-machine-lines)' "$f" || { echo "строка исключения пропала или изменилась"; exit 1; }
grep -qF -- 'Уровень 2 до a1b2c3d: неопределённость 1, тронут tools/shipctl.' "$f" || { echo "строка уровня ревью пропала или изменилась"; exit 1; }
grep -qF -- '- Вердикт: без замечаний. Дифф прочитан целиком.' "$f" || { echo "строка вердикта пропала, изменилась или потеряла двоеточие"; exit 1; }
grep -qF -- '- Обкатка: 2026-09-18 03:25, свежее дерево 1583c7bfcb73, сценарий 968006f4, временный HOME, утилит дерева 11, шагов 4, все зелёные.' "$f" || { echo "строка обкатки пропала или изменилась"; exit 1; }

# Живая проза «Что происходит» вычитана: афоризм в конце и усилитель сняты,
# факты остались на месте.
phrase "Это и есть вся суть находки" "$f" && { echo "вывод-афоризм в конце абзаца остался"; exit 1; }
phrase "ровно так же" "$f" && { echo "усилитель остался"; exit 1; }
grep -qi 'DK-460' "$f" || { echo "факт про DK-460 пропал"; exit 1; }
grep -qi 'квот' "$f" || { echo "факт про квоту в прозе пропал"; exit 1; }
exit 0
```
